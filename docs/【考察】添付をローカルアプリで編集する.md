# 【考察】添付をローカルアプリで編集する

> 2026-09-07。ユーザー:「サーバー上のCADファイルや画像ファイルなどをローカルのアプリで
> 編集する方法を考察してください。ブラウザでファイルをクリックするとローカルのアプリが
> 立ち上がり、Ctrl＋Sで上書き保存されるような使い方をワンノートでしています」。
>
> 関連: [【考察】添付ファイルの表示と操作.md](【考察】添付ファイルの表示と操作.md)（表示・
> コンテキストメニュー）／[要件定義書.md](要件定義書.md) §5（保存した画像の編集）。
> **結論は §6**——WebDAV を第一候補とし、まず読み取り専用で試す。
> **§6a 試用の結果**——HTTPとしては動くが、Windows から使うには HTTPS が要る（実測）。
> **§6b HTTPS化**——実装済み。**§6c エクスプローラから読める**。
> **§6d DXF・RPCD で中身の一致とシーク読みを確認**——残るは実物のCADで開くことだけ。

## 1. 何が欲しいのか

ワンノートの体験を分解すると、**4つの動作が繋がっている**ことが分かります。

```
①クリック → ②ローカルのアプリが開く → ③Ctrl+S → ④サーバー側が新しくなる
```

いま w-cms にあるのは①と、②の半分（ダウンロード）だけです。**③と④が無い**——
ダウンロードしたファイルはブラウザの保存先にあり、編集しても誰も見ていません。
人が手で再アップロードすれば繋がりますが、それは「Ctrl+S」ではありません。

**AutoCAD・SolidWorks・画像編集ソフトのどれでも**同じ形で動く必要があります。
拡張子ごとに違う仕掛けを作ると、対応表を永久に育てることになります。

### 1.1 編集するのは**自社のファイル**——メール由来のものではない

ユーザー:「ワンノートを見てもらえばわかりますが、編集するCADファイルは弊社の物です。
メール由来のものではありません」（2026-09-07）。

**この区別が、この文書でいちばん大事な線です。** 添付には出自の違う2種類があります。

| | 出自 | 例 | 書き換えてよいか |
|---|---|---|---|
| **届いたもの** | 通信記録（メール・FAX）の添付 | 客先支給の図面PDF・DXF | **駄目**——届いた事実の証拠。書き換えたら「何を受け取ったか」が消える |
| **自社のもの** | 人が部品ページへ置いたファイル | CAM用DXF・自社作図・注記した画像 | **よい**——作った人が直すのが仕事 |

実データがこの2種類をはっきり分けています。DXF 911件のうち **896件は自社のCAM用**
（表題欄なし）で、**取り込み口を通っていません**。客先から届くDXFは11件で、
そちらは通信記録の添付です（[作業引き継ぎ.md](作業引き継ぎ.md) の「DXFは2種類ある」）。

**線の引き方も、既にある原則そのまま**です——「**記録は動かしません**」
（[【考察】通信記録処理.md](【考察】通信記録処理.md) §3.2）。通信箱の下にある添付は
記録なので読み取り専用、部品ページなどに人が置いたファイルは編集可。
**置き場所が権限を決める**ので、ファイルごとの印は要りません。

## 2. 取りうる道は4つ

### A. WebDAV——サーバーをネットワークドライブとして見せる

Windows のエクスプローラで「ネットワークドライブの割り当て」をすると、
`\\localhost@8080\DavWWWRoot\...` のようなパスでファイルが見えます。**そこから開いた
ファイルは、アプリにとって普通のファイル**なので、Ctrl+S が素直に効きます。

- **①②③④が全部つながります。** 特別な仕掛けはブラウザ側にも要りません。
- **実装の材料は既にあります**——`golang.org/x/net/webdav` は**いま使っている依存の中**
  （`x/net` は HTML パースで既に直接依存）。**新しいモジュールはゼロ**で、開発方針の
  「外部依存の最小化」に抵触しません。
- 認証は**HTTPの世界の話**なので、セッションCookieではなく Basic か Digest になります。

**Windows のWebDAVクライアントには既知の癖があります**（実装前に確かめること）:

| 癖 | 影響 | 逃げ道 |
|---|---|---|
| 平文HTTPでの Basic 認証を既定で拒否 | ログインできない | HTTPS にする（本番は要る）／レジストリ `BasicAuthLevel`（＝各PCの設定・避けたい） |
| 既定の最大ファイルサイズが 50MB | 大きなCADが開けない | レジストリ `FileSizeLimitInBytes`（同上） |
| `WebClient` サービスが止まっていることがある | 割り当てできない | サービスを自動起動に |
| 認証が切れると無言で失敗する | 保存できたように見えて消える | **要検証**（いちばん怖い） |

### B. カスタムURLスキーム＋常駐ヘルパー（`w-cms://edit?...`）

各PCに小さなヘルパーを入れ、`w-cms://` を登録します。ブラウザでクリックすると
ヘルパーが起動し、①一時フォルダへ落とし、②既定のアプリで開き、③ファイルの変更を
見張って（`fsnotify` 相当）、④変わったらサーバーへ PUT する。

Confluence・Nextcloud・Jira の「デスクトップアプリで編集」はこの形です。

- **狙った体験にいちばん近い**。認証も w-cms のセッションを引き継げます。
- **各PCへインストールが要ります**（レジストリ登録つき）。ヘルパーは Go で書けるので
  モジュールは増えませんが、**配布するものが1つ増えます**。
- **攻撃面が増えます**——`w-cms://` はどのWebページからでも叩けるので、ヘルパーは
  **URLのホストを検証し、使い捨ての鍵を要求する**必要があります。ここを間違えると
  「任意のサイトが社内ファイルを書き換えられる口」になります。

### C. File System Access API（ブラウザだけで完結）

Chromium 系なら `showSaveFilePicker` でローカルのファイルハンドルを得て、
**ブラウザから書き戻せます**。

- **ローカルのアプリを起動できません**。②が無いので、この案だけでは輪が閉じません。
- 「w-cms が保存先を覚えていて、人がアプリで保存したあとブラウザで『取り込む』を押す」
  という**半自動**にはなります。Ctrl+S ではない。

### D. いまのまま（ダウンロード → 手で再アップロード）

- 追加の仕掛けはゼロ。**回数が少ないうちはこれで足ります**。
- 図面の修正が日常なら、確実に摩耗します。

## 3. w-cms 側で先に決めることが3つある

道を選ぶ前に、**どの道を選んでも必要になる**決定が3つあります。ここが未決のまま
実装すると、静かに壊れる形になります。

### 3.1 添付には版が無い

ページ本文には版があります（`versions/`・リバートできる）。**添付には版がありません。**
上書き保存を許すと、**前のCADファイルは消えます**——編集ミスも、間違ったファイルを
開いたことも、取り返せません。

既存の決定は「編集結果は**別ファイル保存（原本残置）**が本命」（
[【考察】添付ファイルの表示と操作.md](【考察】添付ファイルの表示と操作.md) §3）でした。
これは画像の加工（回転・切り抜き）についての判断で、**CADの継続的な修正とは性質が違います**
——別ファイルにすると `X026-001_v2.dxf` `..._v3.dxf` が増え、**どれが最新か分からなく
なる問題**（旧版を子ページへ移した理由そのもの）が添付の側で再発します。

なお **§1.1 の線引きで「原本残置」は別の形で守られます**——届いたファイルはそもそも
書き換えられないので、**原本は通信記録の側に必ず残ります**。ここで版を積むのは
自社の作業ファイルについてで、失われるのは「自分の前回の作業」です。

選べる形は3つ:

| | 上書き | 版を積む | 別ファイル |
|---|---|---|---|
| 最新がどれか | 明らか | 明らか | **分からなくなる** |
| 前へ戻せる | **戻せない** | 戻せる | 戻せる |
| 置き場 | `files/<ID>.dxf` | `files/versions/<ID>/<時刻>.dxf` | `files/<別ID>.dxf` |

**「上書き＋版を積む」が本文と同じ形**で、いちばん筋が通っています。ページ本文が
そうしているのだから、添付だけ違う原理にする理由がありません。

### 3.2 誰かが同時に開いたら

ページには編集ロックがあります。**添付にはありません。** 2人が同じDXFを開いて
両方が Ctrl+S すると、**後の保存が前を黙って消します**。

WebDAV には `LOCK` があり（`x/net/webdav` も実装しています）、Windows は
Office ファイルでこれを使います。**CADアプリが LOCK を送るかは分かりません**——
実装前に実物で確かめる必要があります。送らないなら、w-cms 側で
「開いた人・時刻」を記録して**警告する**（止めない）のが現実的です。

### 3.3 上書きされたあと、派生をどうするか

**§1.1 の線引きで、この心配はほとんど消えます。** 解析（図面番号・図面名称の抽出、
`✓ 図面` の印）が掛かるのは**届いたファイル**で、それは読み取り専用だからです。
自社のCAM用DXFは取り込み口を通らず、解析もされていません。

残るのは**更新時刻**です。添付を書き換えてもページの本文は変わらないので、いまの
仕組みでは「いつ直したか」がどこにも出ません。**「添付が変わったらページを触ったことに
する」**（更新時刻を進める）だけは要ります——子ページの並びや「最近の更新」が、
実際の作業とずれるためです。

## 4. 名前の問題——`19ux.dxf` が開く

添付の保存名は**生成ID**です（`19ux.pdf`）。元の名前は本文のリンク文字と
`download` 属性が運んでいます。

WebDAV でフォルダとして見せるとき、**アプリのタイトルバーに `19ux.dxf` と出ます**。
CADの図面名としては役に立ちません。

逃げ道は「WebDAV の見せかけの名前を、元のファイル名にする」——`x/net/webdav` の
`FileSystem` は自前で実装できるので、**`ページID/元の名前.dxf` で見せて、実体は
`files/19ux.dxf` へ繋ぐ**ことができます。ただし**元の名前は本文の中にある**ので、
WebDAV の一覧を出すたびに本文を読むことになります（重い・要検討）。

## 5. どこまでを w-cms が持つべきか

**ローカルアプリの起動は、ブラウザにはできません**（できたら攻撃です）。だから
②を実現する主体は必ず「OSに登録された何か」——ネットワークドライブ（A）か、
インストールしたヘルパー（B）です。**w-cms が単体で完結させる道はありません。**

その前提で、A と B の違いは**どこに複雑さを置くか**です。

- **A は OS の機能に乗る。** w-cms 側は WebDAV を喋るだけで、癖は Windows のもの。
  癖が出たときに直せるのは Microsoft だけ、という弱みがあります。
- **B は自分で全部持つ。** 癖は自分のもので、直せます。代わりに**配る・入れる・
  更新する**が発生し、攻撃面も自分で守ることになります。

## 6. 結論——A（WebDAV）から。ただし読み取り専用で試す

**順序が肝**です。いきなり書き込みを許すと、§3 の3つが未決のまま「消えた」が起きます。

1. **読み取り専用の WebDAV を出す**（`x/net/webdav`・新しい依存ゼロ）。
   ページの添付フォルダをドライブとして見せ、**CADアプリから開けるか**を実物で確かめる。
   ここで Windows の癖（サイズ上限・認証・サービス）が全部出ます。**出させるのが目的**です。
2. 開けたら、**§1.1 の線引きを先に実装する**——通信箱の下の添付は読み取り専用、
   それ以外は書き込み可。**置き場所で決まる**ので、ファイルごとの印は要りません。
3. **§3.1（版）を決めてから**書き込みを許す。「上書き＋版を積む」を推す。
4. §3.2（同時編集）は、まず**警告だけ**。CADアプリが `LOCK` を送るかを見てから決める。
5. §3.3（更新時刻）は書き込みと**同時に**入れる。

**Bは、Aが Windows の癖で使い物にならなかったときの控え**にします。先に作らないのは、
配布物が増える判断を「Aが駄目だった」と確かめる前にしたくないためです。

**Cは採りません**——②が無いので、この話の要求を満たしません。

## 6a. 試用の結果（2026-09-07・実装して測った）

読み取り専用の WebDAV を実装し（`internal/cms/webdav.go`・`WCMS_DAV=1` で開く）、
**実データで試しました**。

**HTTPとしては完全に動いています**（`curl`）:

```
PROPFIND /dav/010256/   → 207 一覧に添付6件
GET      /dav/010256/5jl9.pdf → 200 158,526バイト application/pdf
PUT      （書き込み）    → 403
認証なし                → 401 ＋ WWW-Authenticate: Basic
```

**ところが Windows のエクスプローラからは繋がりません。** `net use` は
「システムエラー 67（ネットワーク名が見つかりません）」で失敗します。

**サーバー側の記録が原因を1行で示しました**:

```
WebDAV OPTIONS /dav/010256 auth=false     ← 要求はこれ1つきり
```

Windows は**認証情報を付けずに1回だけ**問い合わせ、401 を受け取ったところで
**諦めています**。`BasicAuthLevel=1`（既定）は「平文HTTPでは Basic を送らない」という
設定で、**送らないまま失敗し、しかも認証の失敗としては報告されません**——
「ネットワーク名が見つかりません」と出るので、原因にたどり着きにくい形です。

この機械での実測値:

| | 値 | 意味 |
|---|---|---|
| `WebClient` サービス | Running（スタートアップは手動） | 動いてはいる |
| `BasicAuthLevel` | **1**（＝SSLのみ） | **これが原因**。平文HTTPでは Basic を送らない |
| `FileSizeLimitInBytes` | **50,000,000**（約47.7MB） | 大きなCADはこの先で詰まる |

### 逃げ道は事実上ひとつ——HTTPS

- **Digest 認証は使えません。** Digest はサーバー側に `MD5(利用者:realm:合言葉)` が
  必要ですが、w-cms が持っているのは **argon2id のハッシュ**だけです。合言葉から
  別の形をもう1つ保存しない限り成立しません——**保存すべきではない**ので、この道は塞がっています。
- **レジストリ（`BasicAuthLevel=2`）は各PCの設定**なので、配る運用になります。
  「WebDAVはインストール不要」という利点が消えるうえ、**その端末の平文Basicを
  w-cms 以外に対しても許すこと**になります。勧めません。
- **HTTPS にすれば素直に通ります。** もともと本番では要るものなので、
  **WebDAV は「HTTPS化の先にある機能」**と位置づけるのが正しい。

## 6b. HTTPS化（2026-09-07・同日に実装）

`-gencert` で自己署名の証明書を作り、`WCMS_TLS_CERT` / `WCMS_TLS_KEY` を置くと
**:8443 で HTTPS 待ち受け**になります（`cmd/w-cms/tls.go`）。

**HTTPS では全部動きます**（`curl`）:

```
PROPFIND https://localhost:8443/dav/010256/   → 207
GET      …/5jl9.pdf                           → 200（158,526バイト）
ログイン（Secure Cookie を既定の有効のまま）    → 302 ＋ authenticated:true
```

**Windows の壁は、進みましたがまだ残っています。**

| | 平文HTTP | HTTPS（証明書は未信頼） |
|---|---|---|
| `net use` の結果 | エラー **67**（ネットワーク名が見つかりません） | エラー **1244**（認証されていない） |
| サーバーに届いた要求 | `OPTIONS` 1回（認証情報なし） | **ゼロ** |

**エラーの種類が変わったことが手掛かり**です。67 は「そもそも辿り着けない」、
1244 は「認証の段で断られた」——`BasicAuthLevel` の壁は越え、**証明書を信頼して
いないところで止まっている**と読めます。

残る一手は**各PCで証明書を信頼させること**で、これは**管理者権限とUIの確認**が要ります
（自動では通せません）:

```powershell
# PowerShell を「管理者として実行」して、この1行を貼る（改行で分けない）
Import-Certificate -FilePath "C:\...\w-cms\data\tls\cert.pem" -CertStoreLocation Cert:\LocalMachine\Root
```

> **1行で書くこと。** バッククォートの継続（PowerShell）も `^`（cmd.exe）も、
> 貼り付け先によっては通りません。ここは1回きりの操作なので、長くても1行が確実です。

**`BasicAuthLevel` を変えるのとの違い**は、緩める範囲です。レジストリ変更は
**その端末の平文Basicを w-cms 以外に対しても許します**が、証明書の信頼は
**その1枚を信じるだけ**です。1台1回で、あとは普通に使えます。

### 6c. 信頼させたら通りました（2026-09-07・実測）

証明書を `LocalMachine\Root` へ入れたあと、**エクスプローラから割り当てられました**。

```
net use * https://localhost:8443/dav/010256 /user:a a
  → Drive Z: is now connected.

Z: の一覧          5jl9.pdf 158,526 / b49d.eml 1,893,152 / hik0.step 481,941 …
Z: の 5jl9.pdf     読める（先頭は %PDF-）
Z: への書き込み     拒否（読み取り専用が効いている）
```

**エラーの道筋は 67 →（HTTPS化）→ 1244 →（証明書の信頼）→ 成功**でした。
`BasicAuthLevel` は**触っていません**——HTTPS にすれば当てはまらない設定なので、
最後まで残った原因は「証明書を信頼していないこと」1つでした。

**指紋を照らし合わせること。** `-gencert` を走らせるたびに別の証明書ができるので、
**信頼させたものと、サーバーが出しているものが同じか**を確かめてから試すこと
（1度これで食い違わせました）:

```powershell
Get-ChildItem Cert:\LocalMachine\Root | Where-Object { $_.Subject -like "*w-cms*" } | Select-Object Thumbprint
```

### 6d. DXF・RPCD で確かめました（2026-09-07）

ユーザー:「STEPではなくRPCDを使ってるんですが、DXFあたりでテストしてください」。
**RPCD は Radan の形式**で、添付の許可拡張子には元から入っています（`.rpcd`・`.dxf`・
`.dwg`・`.step` すべて許可）。

いまの実データ（実メール100通）には **DXF も RPCD も1件もありません**——添付は
eml/pdf/png/step/zip/xlsx だけです。**客先から届くDXFは11件しかなく、自社のCAM用が
896件**（§1.1）という内訳を思えば当然で、**編集したいファイルはまだ w-cms に入って
いない**ということでもあります。そこで最小の R12 ASCII DXF を作り、部品ページへ
アップロードして通しました。

| 確かめたこと | 結果 |
|---|---|
| ドライブに見えるか | `fglh.dxf` 416バイト・`nyvp.rpcd` 31バイト——両方見える |
| **中身が変わらないか** | SHA256 が**完全一致**（`889A082E…`） |
| **アプリと同じ読み方ができるか** | 開く → `Seek(0,Begin)` → 部分読み → `Seek(-5,End)` → 末尾 `EOF` を取得。**できた** |
| 書き込みは断るか | 拒否。**断ったあとも中身は無傷**（ハッシュ不変） |

3行目が肝です。**CADは大きなファイルを「開いて・飛んで・部分的に読む」**ので、
ここが通らなければ実用になりません。WebDAV 越しでも普通のファイルとして扱えています。

**残るのは「実物のCADアプリで開けるか」だけ**になりました——ここから先は
Radan / SolidWorks を持っている側でないと確かめられません。

### まだ確かめていないこと

- **実物のCADアプリ（Radan・SolidWorks）がネットワークドライブ上のファイルを
  直接開けるか**（一時ファイルを同じフォルダに作る作りのアプリは、WebDAV上で遅い・

## 7. 決定ログ

| 日付 | 決定 | 理由 |
|---|---|---|
| 2026-09-07 | **WebDAV（A）を第一候補とし、読み取り専用から試す** | ①〜④が繋がる唯一の低コスト路。`x/net/webdav` は既存依存の中にあり、モジュールが増えない。書き込みを後回しにするのは §3 の3つが未決のため |
| 2026-09-07 | **書き込みは自社のファイルだけ。通信箱の下の添付は読み取り専用** | ユーザー:「編集するCADファイルは弊社の物です。メール由来のものではありません」。届いたものは**届いた事実の証拠**で、書き換えると何を受け取ったかが消える。「記録は動かしません」の添付版。**置き場所で決まる**のでファイルごとの印は要らない |
| 2026-09-07 | **添付の上書きを許すなら「版を積む」**（推奨・未確定） | 本文が版を持つのに添付だけ持たないと、CADの修正が取り返せない。別ファイル案は「どれが最新か分からない」を添付側で再発させる。届いたファイルの原本は、そもそも書き換えられないので通信記録の側に残る |
| 2026-09-07 | ヘルパーアプリ（B）は**Aが駄目だったときの控え** | 配布物と攻撃面が増える判断を、Aの不足を確かめる前にしない |
| 2026-09-07 | **読み取り専用の WebDAV を実装**（`WCMS_DAV=1` で開く・既定は閉じる） | HTTPとしては動くことを実データで確認（§6a）。既定で閉じるのは、平文HTTPでの Basic が要求のたびに合言葉を流すため |
| 2026-09-07 | **HTTPS を実装**（`-gencert` ＋ `WCMS_TLS_CERT`/`WCMS_TLS_KEY`・:8443） | WebDAV のために要り、かつ本番にもともと要るもの。自己署名＋各PCで信頼、を第一の形にした——`BasicAuthLevel` を変えるのと違い、**緩めるのはその1枚だけ** |
| 2026-09-07 | **HTTPS＋証明書の信頼で、エクスプローラから読めた**（§6c） | 67→1244→成功。`BasicAuthLevel` は触っていない——原因は最後まで証明書の信頼だった |
