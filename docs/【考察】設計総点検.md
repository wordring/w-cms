## 0. 総評

**骨格は健全で、破れていたのは末端でした。** 3層の語彙モデル・一方向依存（htmldoc がドメインを知らない）・
サニタイズの二層化・決定ログの文化は、いずれも文書が主張するとおり実装として成立していました。文書と実装の
乖離を探しに行って、**見つかったのは文書の誤りではなく文書が触れていない領域**（メソッドガード・キャッシュ
ヘッダ・派生索引の認可）ばかりだった、というのが結論です。一方で **「黙って壊れる」経路が想定より多い**こと
が分かりました——「見える文字がすべて」の代償が、告知機構で十分に補われていません。

## 1. この調査から得た教訓

個別の指摘は対処か判断で片付きますが、下の8点は残ります。

1. **未検証の指摘は、着手前に必ず反証してから使う。** 全件を反証側から検証して**原文のまま通った指摘は
   1件もありませんでした**（判定が覆ったもの7件、成立するが範囲・深刻度・原因の訂正が要るもの10件、
   残りは新規発見）。誇張・因果の取り違え・深刻度の付け間違いが体系的に混じるので、**指摘を読んで
   そのままコードを直すと、存在しない欠陥を「修正」してしまう**。
   > 実例——「保存2本のロック検証がフェイルオープン」→ `u == nil` は `RequirePageWrite` とルート表の
   > `RequireAuth` で二重に到達不能＝**不成立**。「`robots.txt` が `.` を含むパスで404」→ **因果が誤り**で
   > そもそもハンドラ未登録。「`/api/load` がヒューリスティックキャッシュされうる」→ 検証子が無く再利用
   > されないので**起きない**（実害は `/data/` だけ）。「往復契約テストに語彙形式が無い」→ **結論が誤り**で、
   > `save_sanitize_test.go` が3形式にバイト一致の往復契約を与えている（残る課題は12形式中8形式が未カバー）。
2. **テストは「値」だけでなく「配線」も固定する。** [csp_test.go](../internal/auth/csp_test.go) が固定して
   いたのはポリシー文字列だけで `main.go` の組み込みは見ておらず、**`CSPProtect` を丸ごと外しても緑**
   でした。`buildHandler()` を切り出して [route_guard_test.go](../cmd/w-cms/route_guard_test.go) が
   ルートごとの保護レベルと CSRF・CSP の**配線**を固定するようにしたのは、この発見によります
   （配線を変異させてテストが落ちることを確認済み）。
3. **E2E だけが守っている不変条件がある。** `serializeChildren` の `.vocab-chrome` 除外には Go テストが
   無く、破れを検出できるのは E2E だけでした。E2E がリポジトリ外にあることの本当の重さは
   「レビュー不能」より**この一点**で、`e2e/` の取り込みはそのために優先しています。
4. **正本と索引がズレたら、認可は索引に従う。** `GetPerms` も `EffectivePublic` の親チェーンも読むのは
   `cms.db`（派生）であってサイドカー（正本）ではありません。「サイドカーが壊れて `parent_id` を失う」は
   データ整合の問題ではなく、**そのまま公開範囲の問題**になります（データモデルと安全性の2体が独立に
   同じ結節点を指しました）。
5. **サニタイズの後にHTMLを足す関数が3つある**（`RenderComputedViews`・`RenderAnchors`・
   `RenderPageShell`）。それぞれが自前でエスケープ責任を負っており、規律が破れた時点で保存型XSSです
   （[本文サニタイズ設計.md](本文サニタイズ設計.md) §2 の二層の**外側**）。
6. **`.vocab-chrome` の不変条件は「型」ではなく「規律」。** 本文DOMを走査する箇所は**29ある**のに明示除外は
   4つだけで、残りは「クロームが入れ子」「クロームが `data-type` を持たない」という現時点の偶然に
   依存しています。レジストリへ `View: true` を1件足すと5箇所が一斉に誤爆します。
7. **手で書いた写像は、実装と同じ速度で陳腐化する。** コードリファレンスは行数主張30件中16件が誤り、
   `app.js` を指す `file:line` は7件中6件が誤り、殻の `id` 参照は7件すべてが `w-` 未追随でした。
   **一方で腐っていなかったのは**依存の向き・ミドルウェア入れ子・ルート表・サニタイズ二層・不変条件・
   テスト地図——**構造は生き、座標は死ぬ**。文書を畳んだ判断はこの非対称に基づきます。
8. **「黙って壊れる」を告知で補うと決めたなら、告知の網羅を測る。** 改名の告知は3類型のうち1つしか拾って
   おらず、`section[data-type]` のタイポは完全に無症状、部材手配が読む `部品番号` は Go コードに直書き
   された**日本語の魔法文字列**でレジストリにもエディタ補助にも現れませんでした（どちらも対処済み）。

### 2.1 採らなかったもの

- **`tags` へ `{Field:"part-id", Label:"部品番号"}` を1行足す**（当初の最優先案）→ **採れない**。`tags` は
  自由語なので列として宣言すると、担当者しか書いていないページでも「部品番号が無い」と鳴り、**全ページで
  誤検知**になります。代わりに「部材表があり、タグを実際に使っており、それでも鍵が引けない」ときだけ
  報告する形（レジストリ宣言 `RequiresTag`）にしました。
- **テンプレート判定をサイドカー属性 `template_root` へ昇格し、右レールにトグルを出す** → **取り消し**
  （2026-08-21 に一度は決定したが着手前に中止）。**h1（ページ名）で決まるまま**とし、置き場を改名すると
  配下が丸ごと②索引・③計算から出入りする（告知は出ない）リスクは**受け入れます**。**決定とその根拠
  （ユーザーの言葉）の正本は [【考察】ページテンプレート.md](【考察】ページテンプレート.md) §9**、
  受け入れたリスクは同 §3.3。なお「テンプレートという名前を設定で変えられる方が良いかもしれない」は**未決**。

### 2.2 起動時のDB再構築の決着（実測値の正本）

`3e5d506` が入れた「起動時にスキーマのずれを見つけたらファイルから全再構築する」処理
（[main.go](../cmd/w-cms/main.go)）について所要時間を実測し、ユーザーの判断を得ました。

**実測**: **1500ページ = 7.0秒**／**3000ページ = 15.8秒**。**1ページあたり約5ミリ秒でページ数に比例**し、
本文の分量には比例しません（同じ1500ページで本文を4倍にしても7.4秒）。再構築が終わるまでサーバーは
受け付けを始めません。**心配していたほど長くはありませんでした。**
**ユーザーの判断**: **1日以内で終わるなら、ファイルから作り直す方式で行く**。外挿すると100万ページで
約1時間半——楽観値で実際はもっと掛かりますが、いずれにせよ1日以内なので**方式は維持**します。

**残る穴（未対処）**: 再構築が途中で止まると（強制終了・停電）、**次の起動は何事もなく成功し、取り込めなかった
ページは開いても「ありません」のまま**になります。`RebuildIfEmpty`（[sync.go](../internal/cms/sync.go)）は
`pages` が**空かどうか**しか見ないため、途中まで入ったDBは「再構築済み」と見分けが付きません（スキーマずれの
経路も同じで、DROP と CREATE を終えた時点でずれは消えるので2回目以降は走りません）。ユーザーは下の3点に同意
済みで、**やることは決まっていて未実装**です——①再構築を**始めた印**を残す ②起動時にその印が残っていたら
**必ずやり直す** ③終わったら**件数と所要時間**を記録に残す。

> → **3点とも 2026-08-22 に実装済み**（2026-09-22 確認。この段落は §3 の外にあったので 09-14 の点検から
> 漏れていた）。`RebuildIfEmpty` は **`RebuildIfNeeded`** に改名され、`pages` が空かどうかより先に
> `rebuildUnfinished()`（`started_at` があり `finished_at` が無い行）を見てやり直します。印は
> `markRebuildStarted`／`markRebuildFinished(pages, durationMS)` が DB の状態表に書きます
> （[sync.go](../internal/cms/sync.go)）。
