# 【考察】発注書のPDF発行

> **検討中・実装は着手直前**（2026-09-21）。⚠ **外部依存を1つ増やす判断**を含むので、
> 理由と代案を残します。
>
> 一言でいうと: **PDF発行は MUST。だから依存を1つ入れる。いちばんの難所はフォント。**

---

## 0. なぜ要るのか

ユーザー（2026-09-21）:

> **PDFを発行出来ることはMUSTです。** 発注書はPDFで送付し**7年保存**する必要があるそう
> です。PDFにするのは**改ざん防止**なんだそうです。

そして送り方も:

> ボタンを押したら印刷出来たいです。**メールで発注を増やしたい**ですが、**FAXで発注も
> 残っています**。メールに添付して送付やFAXサーバーで送信で来たいです。

⚠ **どの経路も「PDFという1つのファイル」を作れることが前提**です（印刷・メール添付・
FAX送信）。ブラウザの「PDFに保存」では**人の手が毎回挟まり、自動送信に繋がりません**。

### ⚠ ただし「PDFだから改ざんされない」ではありません

**PDF そのものは普通に編集できます。** 電子帳簿保存法が求めているのは（筆者の理解では）
**訂正・削除の履歴が残ること**／**事務処理規程を定めて運用すること**／**タイムスタンプ**の
いずれかで、**ファイル形式ではありません**。

⚠ **これは税理士に確かめてほしい**ことです（筆者の理解が古い・不正確かもしれません）。
もし「履歴が残ること」が要件なら——**w-cms は本文の版と監査記録を既に持っています**。

⚠ **PDFを作ること自体は要件として動きません**（相手へ送る形式として必要）。念のため。

**7年保存**は w-cms には素直です——**出したPDFを発注書ページの添付として残せば**、
ページごと残ります。

## 1. 依存を1つ増やす（ユーザー承認済み）

プロジェクト内で事前に承認された重大なライブラリ」）に当たります。SQLiteドライバ・
argon2id・`x/net/html` と同じ扱いです。⚠ **承認は 2026-09-21 にユーザーから**。

### 選んだもの: `github.com/signintech/gopdf`

| 比べたもの | 判断 |
|---|---|
| **`signintech/gopdf`** ← 採用 | **MIT**・依存1つ（`gofpdi`）・**2026-09-12 更新**・⚠ **TTF埋め込みが本業**（作者が日本語のために作った） |
| `jung-kurt/gofpdf` | ⚠ **作者が開発終了を宣言**（後継が `go-pdf/fpdf`） |
| `go-pdf/fpdf` | 生きているが、**日本語の埋め込みに一手間**かかる |

⚠ **日本語が要件の中心**なので `gopdf` が素直です。

## 2. ⚠ いちばんの難所はフォント

**日本語のPDFはフォントを埋め込まないと読めません。** そして**どのフォントを同梱できるか**が
ライセンスの問題になります——**w-cms は MIT で公開**されており、世界中の誰かが使う前提です。

### 実測（2026-09-21）

| フォント | 結果 |
|---|---|
| `NotoSansJP-VF.ttf` | ✓ **通りました**（⚠ 可変フォントだが読めた） |
| `meiryo.ttc` / `msgothic.ttc` | ✗ **読めません**——⚠ **`.ttc` はコレクション形式**で、gopdf は単体TTFしか受けません |

⚠ **「エラーが出なかった＝正しく出た」ではありません。** 作ったPDFの `ToUnicode` を
読み返して、**`発注書　株式会社みなと商店　御中　鉄STPG370EG φ27.2` が一字一句戻る**ことを
確かめています。**中身で確かめること**（2026-09-21 朝に印刷で同じ失敗をしたばかり）。

### Noto Sans JP は **SIL Open Font License**（フォント自身の `name` 表から確認）

⚠ **同梱して再配布できます**。ただし **9.2MB**——リポジトリに入れると小さくない重さです。

### ⚠ 未決: 同梱するか、設定で指すか

| 案 | 良い点 | ⚠ 代償 |
|---|---|---|
| **A: 同梱**（`assets/fonts/`） | どの環境でもそのまま動く | ⚠ リポジトリが **9.2MB** 増える |
| **B: 設定で指す**（`pdf_font`） | 重くならない | ⚠ **設定しないとPDFが出ない**（Gemini キーと同じ形の「設定待ち」） |
| **C: 両方**（既定は同梱・設定で差し替え可） | 運用者が社名ロゴ入りの書体に替えられる | 実装が少し増える |

**筆者の推しは B → 必要になったら A へ。** ⚠ 理由は、**いま同梱しても職場と自宅の2台には
既に Windows のフォントがある**ので、9.2MB を払う相手がまだ居ないからです。
⚠ **他社へ配るときには A が要ります**——そのときに入れれば間に合います。

⚠ **設定にするなら、無いときの断り方はGeminiキーと同じ形**にすること
（「サーバーに ◯◯ が設定されていません」と画面に出し、**起動は止めない**）。

## 3. 作るもの（順番）

1. **発注書ページ**（`自社の発注書`・明細は実物7枚に合わせた1形式 ← `681bb66` で済み）
2. **PDFにする口**——ページからPDFを作り、**添付として同じページへ保存**する
   （⚠ 7年保存がこれで済む。ファイルはページと一緒に残る）
3. **印刷**——⚠ **PDFがあれば印刷は「そのPDFを開く」で済みます**。受注残表で作った
   `@media print` の仕掛けは**画面の表**のためのもので、**発注書は紙の体裁が要る**ので
   PDF側で組むほうが素直です。
4. **メール添付**——w-cms は SMTP を持っているので、**2でできたPDFを添付するだけ**。
5. **FAX** ——⚠ **FAXサーバーが動いてから**（機械は購入済み・未稼働）。送るのは
   PDFか画像なので、2ができていれば繋がります。

⚠ **2がすべての前提**です。3〜5は2の上に乗るだけなので、**2を先に、確かめてから**。

## 4. ⚠ 罠（先に書いておく）

- ⚠ **`.ttc` は読めません**（Windows の meiryo・msgothic はこれ）。設定で指させるなら、
  **`.ttf` だけ受ける**と断ること——`.ttc` を指されて「読めません」だけ出ると理由が分かりません。
- ⚠ **可変フォント（VF）は通りましたが、太さは選べていません**。太字が要るなら、
  **別のフォントファイル**を指すことになります（`gopdf` は `SetFont` の style で太さを
  選べますが、VFの軸を動かす機能はありません）。
- ⚠ **金額の桁区切りと右寄せ**は自分で組むことになります（実物は `122,580` のように
  区切っています）。`gopdf` に表を組む機能はありません——**線と文字を自分で置きます**。
- ⚠ **発注書No. の採番**が要ります。実物は `44`・`33`・`87` のような連番でした。
  ⚠ **ページIDで代用しない**こと——相手に渡す番号なので、**欠番や飛びが説明できる**必要が
  あります（ページIDは他の用途で飛びます）。

## 6. 発注書が複数枚になるとき（2026-09-23・考察）

> ユーザー:「発注書PDFは複数枚になる場合があります。この場合、発注書ページはどのように
> なるべきか考察してください。私は、**複数ページのPDFにすればよい**と思いますが、
> **発注書番号はどうすべきか**考える必要があります。」

### 6.1 いまの形（測った事実）

- **PDF は既に複数ページになります**（2026-09-23・0a8）——明細が紙の下からはみ出したら
  `AddPage()` して**表の見出しだけ**刷り直す（`pdfTable`）。
- ⚠ **2枚目以降には、発注書番号・宛名・差出人・「何枚目か」が無い。** 1枚目の頭にだけ
  題・`御中`・差出人・ヘッダ4項目（発注書番号・発注日・納期・納品場所）を刷る。
  合計は**表の直後**（＝最後の紙）に1回。
- **発注書番号はページ番号そのもの**（6桁・`our_order_new.go`。別に採番しない・09-21 決定）。
  紙には `発注書番号： 000138` と1枚目に出る。
- **1発注書＝1ページ＝1PDF**——添付は `発注書 <日時>.pdf` の1本で、作り直すと
  `file-view` のマーカーが差し替わる（`placeOrderPDFView`）。
- ⚠ **実物7枚はすべて1枚もの**でした（`w-cms用見本`・材料2・加工2・塗装2・鍍金1）。
  **複数枚の実物はまだ見ていません。** 発注書 No. は7枚とも空欄。

### 6.2 「複数ページのPDF」で足りる——器は変えない

ユーザーの案のとおりでよいと考えます。理由は**紙の枚数はレイアウトの都合**で、
**注文の同一性ではない**からです。

| 変えないもの | なぜ |
|---|---|
| **発注書ページは1枚** | 1枚＝1社（09-22）。相手にとっても1回の注文 |
| **発注書番号は1つ** | 番号は**文書**に付く。枚数は**紙**に付く。相手が問い合わせる番号が枚数で増えてはいけない |
| **PDF は1本** | 添付・`file-view`・メール添付・7年保存の単位が揃う。分けると「2枚目だけ送り忘れ」が起きる |
| **`状態` は行に付く** | 何枚目に刷られたかは行の事情に関係ない |
| **合計は最後に1回** | 途中の紙に小計を出すと**取り消した行を刷らない**規則と食い合う（紙の小計と本文の和がずれる） |

⚠ **別の道を採らない理由**も書いておきます:

- **紙ごとに枝番（`000138-1`・`000138-2`）**——索引の `発注書番号` タグは1つなので、
  枝番は**紙にしか存在しない番号**になる。相手が枝番で問い合わせてきたとき、こちらは
  6桁で引くので**枝番を捨てて読む**ことになり、持つ意味が無い。
- **紙ごとに発注書ページを分ける**——同じ仕入先への1回の注文が2ページに割れ、
  合計・送信・取消の印が**2か所**になる。1枚＝1社と衝突。
- **1ページに複数のPDF**——「どれが正本か」が生まれる。

### 6.3 ⚠ 決めるべきは「2枚目以降の紙に何を刷るか」

FAX の現実は**紙が1枚ずつ届く**ことです——順番が入れ替わる・1枚だけ欠ける・
別の発注書の紙と混ざる。2枚目以降にいま何も刷っていないのは、その紙が**どの注文の
何枚目か、相手に分からない**ということです。

| 刷るもの | 場所 | なぜ |
|---|---|---|
| **発注書番号** | 全部の紙の頭 | 混ざった紙を1つの注文に戻す鍵 |
| **`n / N`**（何枚目／全何枚） | 全部の紙 | ⚠ **`N` が無いと欠けた紙に気づけない**（「2/3」を見て初めて3枚目を探す） |
| **宛名（`御中`）** | 全部の紙の頭 | 別の会社の紙と混ざらない |
| **表の見出し** | 全部の紙（既にある） | 列の名前が無いと数字が読めない |
| 差出人 | 1枚目だけでよい | 番号と宛名があれば足りる。2枚目以降は**明細の場所を空けたい** |
| **合計金額** | 最後の紙だけ | 6.2 のとおり |
| 「次頁へ続く」 | 最後以外の紙の足元 | 最後の紙だと思って読み終える事故を防ぐ |

⚠ **`n / N` は gopdf で書けます**——全部描き終えてから `GetNumberOfPages()` で N を取り、
`SetPage(i)` で各紙へ戻って刷る（`gopdf.go` にどちらも在る）。**2回描く必要はありません。**

⚠ **紙の区切りで明細行を割らない**は既にそうなっています（行の高さを見て `AddPage`）。
実物にあった**装置名だけの見出し行**（`〇〇用` 等・未実装）を入れるなら、
**見出し行を紙の最後の行にしない**規則が要ります。

### 6.4 発注書番号の形は、ここでは変えない

「番号をどうすべきか」の答えは **6.2 のとおり「1つのまま」**です。ただし、複数枚を
きっかけに番号の**形**（6桁のページ番号）を見直す必要は無いか、も考えました:

- 実物は7枚とも **No. 空欄**——相手は番号を要求していない。番号は**こちらが引くため**のもの。
- ページ番号は**一意・不変・振り直し不要**で、しかも `/000138` で開ける。**これに勝る番号は無い。**
- ⚠ 日付や連番を含む番号（`250923-01`）にすると、**採番の口と索引の鍵が2つ**になる
  （09-21 に「別に採番しない」と決めた理由そのもの）。

**結論: 番号は変えない。変えるのは2枚目以降の紙に刷る内容だけ。**

### 6.5 ⚠ 実物を見てから決めること

複数枚の実物は**まだ1枚もありません**。想像で器を決めないため、**6.3 のうち番号・`n / N`・
宛名・「次頁へ続く」までを実装**し、次は**本当に2枚になった発注書が出てから**
（差出人を2枚目にも要るか・小計を途中に出したいか）を見て決めるのが順当です。
**実装は数十行**（`pdfTable` の改ページの枝と、描き終えた後の `SetPage` ループ）。
