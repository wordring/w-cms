# 【考察】消すと壊れるページと表

> 2026-10-22 利用者:「見積もりページは削除しても作り直せば大丈夫ですか？」
> 2026-10-22 利用者:「消すと壊れるページや表を探して文書にしてください。できる限りそのようなページや表を無くしたいです」

ページや表を消すと、ほかの所が黙って変わったり、働かなくなったりすることがあります。
この文書では、それがどこで起きるかを、職場のデータとコードで調べて並べます（2026-10-22 夜）。
そのうえで、そういう所を減らす案を出します。どれを作るかは、利用者が決めます（§6）。

## 1. きっかけ

2026-10-22 夜、利用者が試しに作った見積書ページ2枚（/001746・/001748）を消しました。
このときは、壊れたものはありませんでした。

- 2枚とも送付日が無かったので、案件残表は変わりませんでした。
- ほかのページの本文から、2枚を指している所はありませんでした。
- 2枚の単価は、加工製品ページの「🧾 受注・見積の単価」から消えました（表示のたびに探し直すため）。

ただ、送った見積書だったら、見積依頼の案件が案件残表に戻り、紙の見積番号と w-cms の番号が合わなくなります。
同じことが、ほかの書類やページでも起きます。

## 2. いまの守り

ページを消す API（`DeletePageAPIHandler`・`internal/cms/handler_delete.go`）は、次のときだけ断ります。

- トップページ。
- 書く権限が無い。
- 道具がロックを握っている。
- 子ページがある（「子ページが N 件あります。先に移動するか削除してください。」）。

消したページは、ごみ箱（`data/trash`）へ移ります。中身は残りますが、戻す画面はありません（手で戻して DB を作り直す）。

消したあとに見える印は、次の2つです。

- 参照の型（`ref`）のタグや表のセルが、もう無いページを指していると、薄赤になり「参照先のページ … が見つかりません」と出ます（`internal/cms/ref_render.go`）。
- ファイル表示が、もう無いファイルを指していると、「… のファイルが見つかりません」と出ます（`internal/cms/file_view.go`）。

**ほかのページから指されているかは、消す前に見ていません。** 指されていても、黙って消えます。

## 3. 消すと壊れるもの

5つの種類があります。

### 3.1 ほかのページから番号で指されているページ

本文の中には、ほかのページの番号を書いた所があります。
参照の型のタグ（`受信元`・`弊社品番`・`案件`・`製造`・`親ページID`・`連絡帳`・`○○担当` など。`config/settings.json` の `vocabulary` で `type: ref` の語）と、同じ語を見出しにした表の列、ファイル表示（`data-ref`）、本文のリンクです。

職場のデータで数えると、次のとおりです（テンプレートの下は除く）。**いま、切れている参照は0件です。**

| 指される種類 | 誰が指すか | 件数 | 消すと |
|---|---|---|---|
| 通信記録 | ほかの通信記録の `親ページID` | 526 | メールの前後がたどれなくなる |
| 通信記録 | 加工製品・案件・業者見積書の `受信元` | 144 | どのメールから来たかが分からなくなる |
| 通信記録 | 案件ページ（47）・加工製品（28）・装置（7）・業者見積書（5）のファイル表示 | 87 | ⚠ **案件ページの原本の発注書と、加工製品ページの図面が消える**（ファイルは、メールの添付として通信記録に置いたまま、ほかのページから見せているため） |
| 加工製品 | 加工製品自身と見積計算書の `弊社品番` タグ | 390 | 見積計算書がどの品物のものか分からなくなる |
| 加工製品 | 案件明細表・納品明細表・部材見積依頼明細表・見積明細表・製造明細表・部材発注明細表の `弊社品番` | 516 | 案件残表で品物が薄赤になる。必要な部材・見積の単価・🧾 の一覧が数えられなくなる |
| 案件ページ（顧客発注書） | 納品明細表・製造明細表・部材発注明細表などの `案件` | 242 | 納品書や部材発注書の行が、どの注文のものか分からなくなる |
| 製造ページ | 部材発注明細表・見積依頼部材表の `製造` | 2 | 書類が製造ページの「この製造の書類」から外れる |
| 加工製品の旧版 | 改訂明細表のリンク | 8 | 古い版の図面へ行けなくなる |
| 連絡帳の人・組織 | `○○担当`・`連絡帳` のタグ | 2 | 紙の差出人・署名が出なくなる |

数え方は、本文のタグ・キャプションのある表の見出し・ファイル表示・`<a href="/NNNNNN">` を読み、6桁の番号が今あるページを指すかを確かめました（道具は使い捨て。リポジトリには入れていない）。

### 3.2 数えるもとになっている書類

次の書類は、ほかのページから番号で指されてはいません。
その代わり、w-cms が書類を数えて、案件や部材の状態を決めています。
消すと、**薄赤も出ずに状態が戻ります。**

| 書類 | 何を数えているか | 消すと |
|---|---|---|
| 納品書 | 案件明細の出荷済数量 | 納めた数が減り、案件残表に戻る。請求書を作るときの数も変わる |
| 部材発注書 | 部材の手配済みの数 | 同じ部材が、まだ発注していないものとして、もう一度並ぶ（二重に発注するおそれ） |
| 見積書（送付日・送付不要のあるもの） | 見積依頼の案件の「見積を出した」 | 見積依頼の案件が案件残表に戻る。案件明細表の「前の見積の単価」が消える |
| 見積計算書 | 加工製品の見積表 | 見積書に写す単価と、赤字の警告のもとが変わる |
| 請求書 | 請求書の発行 | 請求したことが消える |
| 製造ページ | 製造明細表の行（製造中の数） | 製造中だった数が、製造待ちにも戻らずに案件残表へ戻る。作った書類の `製造` は薄赤になる |

### 3.3 番号がページ番号の書類

次の書類は、書類の番号がページ番号そのものです。

- 見積書（見積番号）・部材見積依頼書（部材見積依頼番号）・部材発注書（部材発注書番号）・納品書（納品書番号）・請求書（請求書番号）。

消して作り直すと、番号が変わります。
もう送った紙があると、相手の手元の番号と w-cms の番号が合わなくなります。

### 3.4 題や種類で探すページ

w-cms は、次のページを題で探します。消すと、そのページを使う働きが止まります。

- トップ直下の置き場: 通信箱・案件・製造・製造台帳・記録・連絡帳。
  消すと、メールの取り込み・整理・書類づくりなどが「置き場が見つからない」で止まります。
  ふだんは子ページがあるので、§2 の守りで消せません。空のときだけ消せます。
- テンプレートの根（`テンプレート`）の下の、機械が使うテンプレート（約15枚）:
  案件ページ・加工製品・見積計算書・見積書・部材見積依頼書・部材見積依頼の返事・部材発注書・納品書・請求書・製造ページ・通信記録（受信メール・送信メール・手入力）・連絡帳の組織・連絡帳の人。
  テンプレートは子ページを持たないことが多いので、**いまは消せます。**
  消すと、そのページを作るボタンが 409「テンプレート「…」がありません」で止まります。
- 連絡帳の自社のページ: 紙の会社の情報・署名・請求書の登録番号のもとです。

### 3.5 消すと働きが消える表・列・節

w-cms は、表をキャプションで、列を見出しの文字で、節を見出しの文字で探します。
そのため、表を消す・キャプションを変える・列の見出しを変えると、消したのと同じになります。

- 案件ページの **案件明細表** と、その列（`弊社品番`・`数量`・`状態`・`製造待ち`・`製造完了` など）。
  消すと、その案件が案件残表から消えます。列が無いと、ボタンが「… の列がこのページの案件明細表にありません」で止まります。
- 製造ページの **製造明細表**（見出し「作業開始」の下）と、作業の見出し。
- 加工製品ページの部材の表（材料表・外注加工表・購入部品表・支給部品表）と **見積表**。
  消すと、必要な部材と見積の単価が数えられなくなります。
- 書類の明細の表（見積明細表・部材発注明細表・納品明細表 など）。消すと、§3.2 の数えるもとが消えます。
- 本文の印: 通信記録の「記録の箱」（✉️ 返信・整理・🤖 解析が出る所）、置き場に挿したビューの印（案件残表・製造待ち など）。
  消すと、その部品が出なくなります（エラーは出ません）。
- テンプレートの中の表と節。消すと、そのテンプレートからページを作るときに「テンプレート「…」に表「…」がありません」で止まります。

## 4. 考えたこと

ページどうしが番号で指し合うのは、w-cms の作りの中心です（参照の型のタグ・ファイル表示）。
だから、指されるページを無くすことはできません。

目指すのは、**消して黙って壊れることを無くす**ことだと考えます。そのために、次の3つを組み合わせます。

1. 消す前に知らせる・断る（何が壊れるかを、消す人が見られるようにする）。
2. 消さなくて済む道を用意する（取消・作り直し）。
3. 消しても戻せるようにする（ごみ箱から戻す）。

ほかのページに頼らずに済む所は、頼らない形に変えます（§5 の案C）。

## 5. 無くす案

効き目の大きい順に並べます。コアか拡張かは、[開発方針.md](../開発方針.md) §0 の線で分けました。

### 案A 消す前に、そのページを指している所を見せる（コア）

- 参照の型のタグと表の列は、もう索引（`page_tags`・`vocab_index`）に入っています。ファイル表示の `data-ref` も本文にあります。
  消すページの番号を指すものを、索引から数えられます。
- 子ページと同じように、指されていれば断り、「このページを指しているページ」の一覧を見せます。
  一覧から、指している側を先に直すか、それでも消すかを選べるようにします（「それでも消す」を残すかは問い1）。
- 効く所: §3.1 の全部。業務の言葉は要らないので、コアに置けます。

### 案B 送った・発行した書類は、消さずに「取消」にする（拡張）

- 送付日・送付不要のある見積書、PDF を作った納品書・請求書、送った部材発注書は、消すのを断ります。
- 代わりに、取消の印（タグ）を付けます。取消の書類は、§3.2 の数えから外します。紙の番号も残ります。
- 部材発注書の明細には、もう行ごとの `取消` があります。同じ考えを書類1枚の単位に広げます。
- 効く所: §3.2・§3.3。

### 案C 原本と図面のファイルを、使うページへ写す（拡張）

- いまは、案件ページの原本の発注書（47件）・加工製品ページの図面（28件）・装置のページ（7件）・業者見積書（5件）が、通信記録の添付を指しています。
- 解析や整理でページを作るときに、ファイルをそのページへ写し、ファイル表示を自分のページを指す形にします。今ある87件も、道具で写します。
- そうすると、通信記録を消しても、案件ページの原本や加工製品ページの図面は消えません。
- 写すとファイルが2つになり、データが増えます（同じ中身を2か所に持つ）。
- 効く所: §3.1 のいちばん危ない行。案A があれば断れるので、案A の次でもよいです。

### 案D 置き場と、使っているテンプレートは消せない（コア）

- 登録された置き場（トップ直下の題）と、登録されたテンプレートの題のページは、削除を断ります。
- コアは、置き場とテンプレートの名簿（`RegisterRequiredPage`・`RegisterPageTemplate`）を、もう持っています。
- 効く所: §3.4。

### 案E ごみ箱から戻す画面（コア）

- いまは、ごみ箱から戻すのは手作業です（フォルダを戻して DB を作り直す）。
- 管理画面に、ごみ箱の一覧と「戻す」を置きます。戻すと、索引にも入り直します。
- 間違えて消しても、すぐ戻せます。§3 の全部に効きます。

### 案F 表・列・節を消したら知らせる（拡張・あと回し）

- 機械が使う表と列が、いつもあるはずのページ（案件ページの案件明細表 など）で見つからないときに、ページの上に ⚠ を出します。
- テンプレートから足し直すボタンも考えられます。
- 効く所: §3.5。表の作りは人が直すこともあるので、どこまで守るかは使いながら決めます。

## 6. 問い（利用者に決めてほしいこと）

- 問い1: 案A で、指されているページは**断る**か、一覧を見せたうえで**それでも消せる**ようにするか。
  筆者の勧めは「管理者だけ、それでも消せる」です（試しのデータを片付けるときに困らないため）。
- 問い2: 案B の「消せない書類」の線を、送ったとき（送付日・PDF）にするか、作ったときからにするか。
  筆者の勧めは「送った・発行したときから」です（作っただけの書類は、作り直しで済むため）。
- 問い3: 作る順。筆者の勧めは、案A → 案D → 案B → 案E → 案C → 案F です。
  案A と案D はコアの小さな変更で、§3.1・§3.4 をまとめて守れます。

## 7. 作ったもの

### 7.1 取り消しで空になった製造ページをごみ箱へ（2026-10-23）

> 2026-10-23 利用者:「製造明細表でチェックボックスをチェックし取り消しボタンを押すとその案件は製造フォルダへ戻ります。その時に、明細表が空になり、リンクが無いなど可能な状態であれば、ページを消すことは出来ますか？」
> 2026-10-23 利用者:「その条件で、取り消しで製造明細表が空になった製造ページを自動でごみ箱へ移す形を作ってください。」

製造明細表の「↩ 取り消し」（`/api/mfg/back`）で最後の行を外したとき、次の全部が揃えば、製造ページをごみ箱へ移します（`ext/toho/mfg_drop.go`）。

1. まだ「製造」の下にある（記録へ移した製造は、もともと取り消せない）。
2. 製造明細表にデータの行が1つも無い。
3. 子ページが無い。添付ファイルが無い。
4. ほかのページから指されていない（書類の `製造` の列・タグなど）。
5. 人が書いたものが無い。本文が、いまのテンプレートから同じ製造番号・客先・始めた日で組んだ空の製造ページと同じ形です。
   見出し・文・字のある表の行・リンク・画像・ファイル表示などの印を比べます。字下げ・`<br>`・空の段落・空の表の行は見ません。
   テンプレートを作ったあとで直した場合も「違う」と見て、残します（安全な側）。

- 1つでも欠ければ残し、画面がその理由を出します（「…がこの製造ページを指しているので、この製造ページは残しました」など）。
- 移したときは、画面が「製造」の置き場へ移ります。ごみ箱にあるので、戻せます。監査には `mfg.drop` を残します。
- 4 のために、コアに `cms.PagesReferringTo`（`internal/cms/referrers.go`）を作りました。参照の型のタグと表のセルの索引から、そのページを指しているほかのページを引きます。§5 の案A の芯です（まだ、ふつうの「ページを消す」には使っていません）。
- 見張りの試験は `ext/toho/mfg_drop_test.go`（指されているときと書き足したときの守りを、それぞれわざと外すと落ちることを確かめた）と、E2E `e2e/verify-mfg-wait.js` の ⑤ です。
