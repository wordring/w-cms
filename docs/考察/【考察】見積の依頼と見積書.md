## 1. いま在るもの（使い回せる部品）

| 部品 | どこ | 見積で使えるか |
|---|---|---|
| 必要部材表 → 発注部材表 → 発注書ページ（1枚1社・テンプレートから） | `ext/toho`（unordered・order_draft・our_order_new） | **業者への依頼**の流れの型そのもの |
| 発注書の PDF（12pt・改ページ・資料を綴じる） | `order_pdf.go`・`order_docs.go` | 依頼書・見積書の紙に使える（題と欄が違うだけ） |
| メールの送る欄の「用件」（返信・新規・発注書） | `ext/comm/compose.go`・`order_mail.go` | 用件「見積依頼」「見積書」を足すだけで送れる（控えは通信箱） |
| 🤖解析（PDF・Excel・メール本文 → 受注ページ） | `analyze_pdf.go`・`analyze_mail.go` | **貰った見積書**（PDF）を読んで単価を書き起こすのに使える |
| 見積計算表の確定単価 | `estimate.go` | **顧客への見積書**の単価の元 |
| 最新単価（材料表の右）・出所の順位 | `material_price.go` | 貰った見積を「順位2（言われた値段）」として足す |
| 加工製品の区分「見積」 | 整理・加工製品の一覧 | 見積の段階の品物を見分ける |

**「見積計算表」は原価の内訳で、見積書ではありません**（`vocab.go` の注意書き）。
見積書は、**別の紙・別のページ**です。

### 2.0 1回の見積を「見積ページ」に——2026-10-01 夜の整理（正本は【要求】見積 §6）

> **この節のその後**: ⚠ **2026-10-02 に変わりました。**
>
> - 業者へ出すものは**見積依頼**と呼び、置き場はトップ直下の**「見積依頼」**です。
>   「見積」は、弊社が顧客へ出す見積もりだけです。
> - 見積依頼ページは、業者ごとに1枚です（§2.0b）。
> - 下は当時の記録です（見出しの【要求】見積 §6 は、【要求】見積依頼へ移しました）。

利用者の整理は、次のとおりです。

- 依頼を出すのは2通りです。
  - **① 既にある部材の価格を知るため**
  - **② 顧客からの見積依頼に答えるため**（「プロセスとしては、受注に似てますね」）
- 同じ品物を何度も見積もり直すので、「加工製品ページには記録できない」とのことです。
  そこで、**見積ページ**を作って記録します。
- 置き場は、**トップ直下の「見積」**です。業者への依頼も、ここへ入れます。
  下の §4 の 10-01 昼の決定（発注のくくり）を変えました。

受注・発注に写すと:

```
受注フォルダ                         見積フォルダ（トップ直下）
  受注ページ（顧客の発注書）            見積ページ（1回の見積の記録）……① 価格調査 ／ ② 顧客の見積依頼
    受注明細                              見積の明細（品物＝加工製品か手書き・数量／ロット）
発注フォルダ                               必要な部材（加工製品の表 × 数量・無ければ手で）
  必要部材表 → 発注部材表                  → 見積依頼の部材表（発注部材表に当たる・業者を選ぶ）
  発注書（1枚1社）                         ├ 見積依頼書（1枚1社・相見積もりは同じ行を何社へも）── 返事（手書きの FAX・PDF）を 🤖解析
                                           └ 見積書（顧客へ・②のとき・確定単価から）
```

- **② の始まり**は、受注と同じ形です。
  - 依頼のメールに表があれば、🤖 で読みます（受注ページを作るのと同じ仕組みです）。
  - 図面の束なら、図面から**見積の加工製品ページ**（区分「見積」）を作り、必要な部材を書き込みます（手で）。
  - 加工製品ページが無くても、手で部材の表を書いて依頼できます。
- **① の始まり**は、「発注フォルダの表に当たる表を見積フォルダに」です。
  加工製品の品番などから、部材を見積ページへ集めます。
- **見積依頼書の紙**は、見本の欄に、**業者が単価を書き込む欄**を足します。
  - 見本は Word で、4社へ同じ紙を出しています（＝相見積もり）。
  - 返事は、紙に手書きで来ます。
  - 外注加工の依頼には、**図面を綴じます**（発注書の外注加工の資料と同じ仕組みです）。
  - 回答期限は足しません。
- 顧客への見積書（§3・10-01 に実装）は、`見積／年／月` の直下に作っています。
  見積ページの子へ移す形は、見積ページを作るときに合わせます。

**次に決めること**:

- 見積ページの形（タグ・見積の明細の列・必要な部材の出し方）
- ① で部材を集める入口（品番から・🔎 材料を探すから・手で）
- 見積依頼の部材表を見積ページの中に置くか、見積フォルダのトップに置くか
- 返事の取り込み（🤖 で単価を読む先）。
  見積依頼書の子の「貰った見積」か、見積依頼書そのものへ書き込むか

### 2.0a 見積ページの骨組み（筆者の案・2026-10-02 朝——⚠ **同じ日に §2.0b へ変わった**・記録として残す）

```
見積（トップ直下）／年／月
  見積ページ「見積 ○○」……1回の見積の記録
    ① タグ   … 見積の種類（価格調査／顧客の見積依頼）・客先（顧客の依頼のとき）・見積日・
                受信元（依頼のメール）・状態（見積中／受注／失注）
    ② 見積品目     … 見積もる品物（受注明細に当たる）

    ③ 必要な部材   … 鏡（必要部材表に当たる）——②の品物 × 加工製品の材料・購入部品・外注加工の表
```

- **顧客の見積依頼（§2.0 の ②）**は、受注と同じ始まりです。

  ④に手で書く（または品番から集める）ところから始めます。

**問い1（返事待ち）: ⑤ 見積依頼の部材表をどこに置くか**

- **A. 見積ページの中**（筆者の勧め）
  - 良いところ: 1回の見積の記録が1枚にまとまります。
    どの業者へ何を聞いたかが、そのページで分かります。依頼書〔子〕ともつながります。
  - ただし、別々の見積ページの部材を、同じ業者へ1枚でまとめて聞けません。
- **B. 見積フォルダのトップに1つ**（発注部材表と同じ形）
  - 良いところ: 複数の見積の部材を、業者ごとに1枚にまとめられます。
  - ただし、依頼書の行が「どの見積のためか」を持つ必要があり、記録が2か所に分かれます。

決め手は、材料屋・加工屋への見積依頼を、
**1件の見積ごとに出すことが多いか、いくつかの見積をまとめて出すことが多いか**です。

このあと聞く順: ①のタグ → ②の列 → ③④の部材の出し方（①で部材を集める入口を含む）→ 返事の取り込みの先 → 見積書を見積ページの子へ。

「①のタグ」「②の列」「③④」は、上の図の番号です。
「①で部材を集める入口」の①は、依頼の種類の①（価格調査）です。

## 3. 顧客へ見積書を出す（出す見積）

### 3.1 流れ（案）

```
顧客から見積の依頼（メール・図面）
   ↓ 🤖解析 → 加工製品ページ（区分「見積」）
加工製品ページの見積計算表を人が埋める（塗装あり・なし、ロットごとに表を分けてよい）→ 確定単価
   ↓ 「見積書を作る」——客先・品物（加工製品）・条件（ロット・塗装）を選ぶ
見積書ページ（見積／年／月）── 見積明細に確定単価を写す（その時点の値で凍結）── PDF・メールで送る（用件「見積書」）
   ↓ 顧客から注文が来たら
受注ページ（受注明細の行が見積書を指す）——見積書は「受注」、来なければ「失注」
```

- **見積書の明細の単価は写して凍結**します
  （[【考察】表の集計の一般化.md](【考察】表の集計の一般化.md) §4.4）。
  - 出した紙の値は、あとで見積計算表を直しても、変わってはいけません。
  - 見積書ページが原本で、PDF が出した紙の写しです。
- **1つの品物に条件違いの行**（10個・塗装あり／50個・塗装なし）を並べられます。
  見積計算表が複数あるのと対応します。
- **受注とのつながり**
  - 受注明細の行に `見積`（見積書ページ）の列を持つか、見積書の明細に `受注` を持つか。
  - 受注の 🤖解析で、「同じ客先・同じ品番の、まだ受注になっていない見積書」があれば、単価を突き合わせます
    （見積と違う単価で注文が来たら ⚠）。
- **受注・失注の印**は、見積書ページのタグです（`状態：見積中／受注／失注`）。
- 見積の横断比較（「あの部品は前いくらで出したか」。【要求】見積 §1）は、
  見積書の明細を品番・加工製品で引けば出せます（表の写し）。
