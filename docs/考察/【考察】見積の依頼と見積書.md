# 【考察】見積の依頼と見積書

> 2026-10-01。利用者:「業者へ見積の依頼と、顧客へ見積書の発行を考えましょう」。
>
> 見積には向きが2つあります——**業者へ依頼して貰う見積**（原価の予定・相見積もり）と、**顧客へ出す見積書**（売上の予定）。
> 決まっていることは [【要求】見積.md](../拡張/東邦/【要求】見積.md) §2（見積は器＝紙のページが要る・「見積DB」は要らない・
> 発注明細に混ぜない・価格の出所の順位）と、[【考察】製造という軸.md](【考察】製造という軸.md) §7i・§7k。この文書は、
> **すでにある発注の仕組みに沿って、2つの流れをどう作るか**を考えます。

## 1. いま在るもの（使い回せる部品）

| 部品 | どこ | 見積で使えるか |
|---|---|---|
| 必要部材表 → 発注部材表 → 発注書ページ（1枚1社・テンプレートから） | `ext/toho`（unordered・order_draft・our_order_new） | **業者への依頼**の流れの型そのもの |
| 発注書の PDF（12pt・改ページ・資料を綴じる） | `order_pdf.go`・`order_docs.go` | 依頼書・見積書の紙に使える（題と欄が違うだけ） |
| メールの送る欄の「用件」（返信・新規・発注書） | `ext/comm/compose.go`・`order_mail.go` | 用件「見積依頼」「見積書」を足すだけで送れる（控えは通信箱） |
| 🤖解析（PDF・Excel・メール本文 → 受注ページ） | `analyze_pdf.go`・`analyze_mail.go` | **貰った見積書**（PDF）を読んで単価を書き起こすのに使える |
| 見積計算表の確定単価 | `estimate.go` | **顧客への見積書**の単価の元 |
| 最新単価（材料表の右）・出所の順位 | `material_price.go` | 貰った見積を「順位2（言われた値段）」として足す |
| 加工製品の区分「見積」 | 整理・加工製品の一覧 | 見積の段階の品物を見分ける |

⚠ **「見積計算表」は原価の内訳で、見積書ではありません**（`vocab.go` の注意書き）——見積書は**別の紙・別のページ**です。

## 2. 業者へ見積を依頼する（貰う見積）

### 2.0 1回の見積を「見積ページ」に——2026-10-01 夜の整理（正本は【要求】見積 §6）

> ⚠ **2026-10-02 に変わった**——業者へ出すものは**見積依頼**と呼び、置き場はトップ直下の**「見積依頼」**（「見積」は弊社が顧客へ
> 出す見積もりだけ）・見積依頼ページは業者ごとに1枚（§2.0b）。下は当時の記録（§6 は【要求】見積依頼へ移した）。

利用者の整理: 依頼を出すのは2通り——**① 既にある部材の価格を知るため**と、**② 顧客からの見積依頼に答えるため**（「プロセスと
しては、受注に似てますね」）。同じ品物を何度も見積もり直すので「加工製品ページには記録できない」→ **見積ページ**を作って記録する。
置き場は**トップ直下の「見積」**（業者への依頼もここへ——下の §4 の 10-01 昼の決定〔発注のくくり〕を変えた）。

受注・発注に写すと:

```
受注フォルダ                         見積フォルダ（トップ直下）
  受注ページ（顧客の発注書）            見積ページ（1回の見積の記録）……① 価格調査 ／ ② 顧客の見積依頼
    受注明細                              見積の明細（品物＝加工製品か手書き・数量／ロット）
発注フォルダ                               必要な部材（加工製品の表 × 数量・無ければ手で）
  必要部材表 → 発注部材表                  → 見積依頼の部材表（発注部材表に当たる・業者を選ぶ）
  発注書（1枚1社）                         ├ 見積依頼書（1枚1社・相見積もりは同じ行を何社へも）── 返事（手書きの FAX・PDF）を 🤖解析
                                           └ 見積書（顧客へ・②のとき・確定単価から）
```

- **② の始まり**は受注と同じ形——依頼のメールに表があれば 🤖 で読む（受注ページを作るのと同じ口）／図面の束なら、図面から
  **見積の加工製品ページ**（区分「見積」）を作り、必要な部材を書き込む（手で）。加工製品ページが無くても、手で部材の表を書いて依頼できる。
- **① の始まり**は「発注フォルダの表に当たる表を見積フォルダに」——加工製品の品番などから、部材を見積ページへ集める。
- **見積依頼書の紙**は見本（Word・4社へ同じ紙＝相見積もり）の欄に、**業者が単価を書き込む欄**を足す（返事は紙に手書きで来る）。
  外注加工の依頼には**図面を綴じる**（発注書の外注加工の資料と同じ仕組み）。回答期限は足さない。
- ⚠ 顧客への見積書（§3・10-01 に実装）は `見積／年／月` の直下に作っている——見積ページの子へ移す形は、見積ページを作るときに合わせる。

**次に決めること**: 見積ページの形（タグ・見積の明細の列・必要な部材の出し方）／① で部材を集める口（品番から・🔎 材料を探すから・
手で）／見積依頼の部材表を見積ページの中に置くか、見積フォルダのトップに置くか／返事の取り込み（🤖 で単価を読む先——見積依頼書の
子の「貰った見積」か、見積依頼書そのものへ書き込むか）。

### 2.0a 見積ページの骨組み（筆者の案・2026-10-02 朝——⚠ **同じ日に §2.0b へ変わった**・記録として残す）

受注・発注にそのまま写した形です。

```
見積（トップ直下）／年／月
  見積ページ「見積 ○○」……1回の見積の記録
    ① タグ   … 見積の種類（価格調査／顧客の見積依頼）・客先（顧客の依頼のとき）・見積日・
                受信元（依頼のメール）・状態（見積中／受注／失注）
    ② 見積品目     … 見積もる品物（受注明細に当たる）
                     弊社品番（加工製品）・品番・品名・数量（ロット）・条件（塗装の有無など）・備考
    ③ 必要な部材   … 鏡（必要部材表に当たる）——②の品物 × 加工製品の材料・購入部品・外注加工の表
    ④ 手書きの部材 … 加工製品ページが無い品物の部材を手で書く（臨時部材表に当たる）
    ⑤ 見積依頼の部材表 … ③④から行を選び、業者ごとに分ける（発注部材表に当たる）→「見積依頼書を作る」
    子ページ: 見積依頼書（1枚1社・相見積もりは同じ行を何社へも）・見積書（顧客へ）
```

- ② 顧客の見積依頼は受注と同じ始まり——依頼のメールに表があれば 🤖 で②を作り、図面の束なら加工製品ページ（区分「見積」）を
  作ってから②に並べる。① 価格調査は②が空でもよく、④に手で書く（または品番から集める）ところから。

**問い1（返事待ち）: ⑤ 見積依頼の部材表をどこに置くか**——
**A. 見積ページの中**（筆者の勧め——1回の見積の記録が1枚にまとまり、どの業者へ何を聞いたかがそのページで分かる・依頼書〔子〕とも
つながる。ただし別々の見積ページの部材を同じ業者へ1枚でまとめて聞けない）／
**B. 見積フォルダのトップに1つ**（発注部材表と同じ形——複数の見積の部材を業者ごとに1枚にまとめられる。ただし依頼書の行が
「どの見積のためか」を持つ必要があり、記録が2か所に分かれる）。
決め手は、材料屋・加工屋への見積依頼を**1件の見積ごとに出すことが多いか、いくつかの見積をまとめて出すことが多いか**。
このあと聞く順: ①のタグ → ②の列 → ③④の部材の出し方（①で部材を集める口を含む）→ 返事の取り込みの先 → 見積書を見積ページの子へ。

### 2.0b 発注と同じ形に——見積依頼フォルダの表から、業者ごとの見積依頼ページを作る（2026-10-02 昼——⚠ **同じ日の夕に §2.0c へ変わった**・記録として残す）

問い1への利用者の答え:「見積依頼の必要部材表は発注の場合と同じように見積フォルダに置き、そこから各見積もりページを作成して
いきます。加工製品ページの区分に見積があるので新規見積もりは収集可能なはずです。再見積もりの場合、弊社品番を入力することになる
でしょう。加工製品が無くても必要部材を追加できるのは発注と同じです。」

続けて**言葉を分けた**（利用者:「弊社の見積もりを見積もり、業者への見積依頼の場合、見積依頼と明確に言葉を分けます」「見積依頼の
フォルダはトップ直下の見積依頼に変更します。弊社の見積もりをトップ直下の見積にします」）——**見積**＝弊社が顧客へ出す見積もり
（トップ直下の「見積」・見積計算表・見積書）、**見積依頼**＝業者へ出すもの（トップ直下の「見積依頼」）。上の答えの「見積フォルダ」
「見積もりページ」は、この区別では「見積依頼フォルダ」「見積依頼ページ」に当たる。§2.0（10-01 夜）の「業者への依頼も『見積』へ」も
これで変わった。

```
発注フォルダ（いま）                          見積依頼フォルダ（トップ直下「見積依頼」）
  受注残（受注明細 × 受注数）                     区分「見積」の加工製品（自動）＋「見積依頼する品物」の表（弊社品番・ロット・備考）
  必要部材表（鏡・受注残 × 材料表）               見積依頼の必要部材表（鏡・品物 × 材料・購入部品・外注加工の表 × ロット）
  臨時部材表（手で・弊社品番の無い部材）          見積依頼の臨時部材表（手で・加工製品が無くても）
  発注部材表 →「発注書を作る」                    見積依頼部材表 →「見積依頼ページを作る」
  発注書（1枚1社・発注／年／月）                  見積依頼ページ（1枚1社・紙は「見積依頼書」・返事の単価もここ）
  手配済み → 必要部材表から外れる                 依頼済み → 見積依頼の必要部材表から外れる
```

決まったこと（10-02・利用者の答え）:

- **見積依頼ページは業者ごとに1枚**（発注書と同じ）——ページの名前は「見積依頼ページ」、印刷する紙は「見積依頼書」、発注部材表に
  当たる表は「見積依頼部材表」。§2.0a の「見積ページ＝1回の見積の記録・依頼書はその子」は採らなかった——「同じ品物を何度も見積もり
  直す記録」は、業者ごとの見積依頼ページが時期ごとに積もることで残る。
- 部材が見積依頼の必要部材表から外れるのは**見積依頼を出したとき**。
- 再見積依頼の弊社品番は**「見積依頼する品物」の表**へ——列は**弊社品番・ロット・備考**（ロットが空なら見積計算表のロット・書けば
  その数・品名や品番は加工製品ページから引いて必要部材表に出すので書かない）。
- 「見積依頼する品物」の行は、その行の部材が**全部**見積依頼部材表（または見積依頼ページ）へ移ったら**機械が消す**（臨時部材表と同じ）。
  途中のあいだは残る。依頼を戻すと行も戻る。表に残るのは「まだ依頼していないもの」だけ。
- 区分「見積」から集める数は**見積計算表のロット** × 部材の数量（見積計算表がロットごとに何枚もあれば、同じ部材がロットの数だけ
  行になる・見積計算表が無ければ1個分）。筆者の勧め（1個分で集めて依頼の部材表で直す）は採らなかった。
- 顧客への見積書（§3・10-01 に実装）は別の流れのまま（`見積／年／月` の直下・見積計算表の確定単価から）。

筆者の前提（問いの説明で示した・反対は無かった）: **依頼済みは行ごとに数える**——見積依頼部材表と見積依頼ページの行は「どの
『見積依頼する品物』の行から来たか」を覚え、その行のぶんだけを引く。区分「見積」の品物は加工製品ページごとに数える。品物
（弊社品番）ごとに数えると、半年前の見積依頼ページが残っているだけで再見積依頼の部材が最初から「依頼済み」に見えてしまう。

⚠ 実装で気をつけること: 読めるのは縦の形（「ロット」の行）の見積計算表だけ——列にロットを並べた形（約20枚）と「移行中」の
見積計算表は読めない（§4 の ⚠ いま と同じ）。「見積依頼する品物」の行を消すのは、機械が本文を書き換えることになるので
編集中の関門が要る（`editlock`）。

**次に決めること**: 区分「見積」の品物が一度見積依頼したあとまた並ぶことはあるか（再見積依頼は「見積依頼する品物」へ、で足りるか）／
依頼元で「見積依頼する品物」の行をどう見分けるか（明細は決まった——見積依頼明細＝発注明細と同じ列＋状態・返事の単価は単価の列／置き場は **`見積依頼／年／月`**——10-02 利用者:「見積依頼／年／月 でよいです。」・タグは決まった——【要求】見積依頼 §2）／見積依頼書の紙（見本＋単価の欄・外注加工の図面を
綴じる）とメールで送る／返事の取り込み（🤖 で単価を見積依頼ページへ）／貰った単価を見積計算表・最新単価（順位2）へどう渡すか。

### 2.0c 見積依頼必要部材表に3つの入口から入れ、重複は赤くして人が外す（2026-10-02 夕・正本は【要求】見積依頼 §2）

§2.0b の「依頼済みを行ごとに数える」を説明していたところ（4月に聞いた品物を10月にまた聞くと、4月の見積依頼が「依頼済み」に
数えられて並ばない——どう見分けるか）、利用者が流れを組み直した:

> 「まず、見積もりを依頼する部材は見積依頼必要部材表に入ります。ここに入れるには、１.臨時部材表に書き込む。2.再見積依頼フォームの
> 弊社品番テキストボックスに書き込みボタンを押す。すると、その品番にある必要部材を自動的に収集します。3．受注フォルダの受注残表を
> 読み込み収集する。見積依頼が発注と異なるのは、ロットが同じ品物を重複して依頼する必要が無いことです。とはいえ、重複の道は残して
> おくべきでしょう。そこで重複するものは見積依頼必要部材表に入れるが重複とわかるように背景を赤くします。そして消すことが出来るように
> するのです。人間が判断して必要なければ消します。」（全文は【要求】見積依頼 §2）

```
見積依頼の臨時部材表（手で）──┐
再見積依頼フォーム（弊社品番）──┼→ 見積依頼必要部材表 ──（選ぶ・入れる先）→ 見積依頼部材表 ──（差出人・仕入先）→ 見積依頼書ページ
受注残表（選んだものだけ）──────┘    重複（同じもの・同じロットが表の中に2つ）は赤・「不要」で外す       （業者ごとに1枚・見積依頼／年／月）
```

- **機械は依頼済みを数えない**——入れたものは全部並び、重複は赤くするだけ。人が見て外す。§2.0b で悩んだ「行をどう見分けるか」
  （整理番号・弊社品番＋ロット・書き出し）は、この形では要らない。重複を見るのは**見積依頼必要部材表の中だけ**（前に出した見積依頼書
  ページとは比べない——利用者:「見積依頼必要部材表に同時に同じもので同じロットが出ていたらに赤くしておけば十分」）。
- 外すのはチェックボックスを借りた「不要」ボタン（利用者:「チェックボックスがあるので、ちょっとお借りして、不要ボタンを押せば
  不要にして良いのでは？」）。
- **見積依頼必要部材表は、発注の必要部材表（表示するたびに計算する鏡）と違い、入口のボタンが行を書き込む表**になる見込み——
  ボタンで集めたものを人が消せるので（筆者の解釈・作るときに確かめる）。
- 「見積依頼する品物」の表・全部依頼したら機械が行を消す・依頼元の列は要らなくなった。見積依頼明細は発注明細と同じく「受注」の列を
  持つ（受注残表から集めた部材に入る）。
- 区分「見積」の加工製品（顧客から見積もりを頼まれた品物）から集める入口は**後で作る**（利用者:「顧客からの見積もりはまた後で
  作りましょう」）。⚠ 同じ日の昼に決めた「一度見積依頼したら並ばない」「辞退は依頼済みに数えない」は、数えない形になったので
  そのとき考え直す。
- 業者ごとのページの名前は**見積依頼書ページ**（昼の「見積依頼ページ」から——発注書ページと揃う）。

⚠ 作るときに気をつけること: 赤は色だけでは足りない（赤緑色覚——引き継ぎの罠「薄赤と薄緑は色だけでは足りない」）——行頭に ⚠ を
付ける。重複は「同じもの」の見分け方（材料なら材質・形状・寸法、購入部品なら品番・品名、外注加工なら弊社品番と加工内容）と
「同じロット」（数量）で決める——発注の手配の鍵（`種類` の列）と同じ考えで揃える。

**次に決めること**（【要求】見積依頼 §4）: 集める数（再見積依頼フォームは見積計算表のロットでよいか・受注残表からは受注残の数量か
手配した分を引くか）／受注残表の「選ぶ」はどこで／臨時部材表の行の入り方／「不要」で外した行を記録するか／紙と送り方／返事の取り込み
／貰った単価の行き先。

### 2.1 流れ（案）（2026-10-01 昼の案——置き場は 2.0 で変わった）

```
必要部材表（または加工製品の外注加工の表）
   ↓ 行を選んで「見積を依頼する」
見積依頼の表（発注部材表と同じ列・人が足し引き）
   ↓ 「見積依頼書を作る」——1枚1社。相見積もりなら同じ行で業者ごとに1枚ずつ
見積依頼ページ（見積／依頼／年／月）── PDF・メールで送る（用件「見積依頼」）
   ↓ 業者から見積書が届く（メール・PDF）
受信メールの「🤖 解析」→ 貰った見積のページ（依頼ページの子）に単価が入る
   ↓ 相見積もりを並べて人が業者を決める
発注部材表へ（単価つき）→ 発注書
```

- **依頼のページは1枚1社**（発注書と同じ）——返事を待つ・催促する・届いた見積と突き合わせる単位が業者だからです。相見積もりは
  「同じ行を複数の業者へ」——依頼の表から業者ごとに1枚ずつ作る（行は同じ・宛先だけ違う）。
- **貰った見積の明細は、発注明細と同じ列で別の形式**（`見積明細`・【要求】見積 §2「形式を分け、列の宣言は共有する」）。
  `受注` の列（どの受注のための部材か）も同じく持てる。
- **貰った単価は最新単価の出所「順位2（言われた値段）」**に入れる——買った値段（順位1）が無ければ、日付と業者つきで出す。
  ⚠ 相見積もりは1つの材料に複数社が並ぶので、**「最新」1つに畳まず、業者ごとに並べる**（買ってもいない会社の値段が最新単価を
  上書きしないように）。
- **依頼したのに返事が無い**を見える形に——発注フォルダの「未発注の発注書」と同じく、「返事待ちの見積依頼」を数える鏡。

### 2.2 決めること

1. **依頼の起点**——必要部材表から（受注のある材料）か、加工製品ページの外注加工・購入部品の表から（受注の前の見積の段階）か、
   両方か。受注前（顧客へ見積書を出すため）の依頼が多いなら、加工製品ページから出せる必要があります。
2. **依頼書の紙**——いまの依頼はメール本文だけか、紙（PDF）も付けるか。紙なら欄（宛先・依頼日・回答期限・数量・図面を綴じる）。
3. **貰った見積の取り込み**——PDF を 🤖解析で読むか（受注と同じ仕組み）、人が表に打つか。
4. **単価の扱い**——ロット違い（10個なら○円・50個なら○円）が多いなら、明細に `ロット` の列が要る。

## 3. 顧客へ見積書を出す（出す見積）

### 3.1 流れ（案）

```
顧客から見積の依頼（メール・図面）
   ↓ 🤖解析 → 加工製品ページ（区分「見積」）
加工製品ページの見積計算表を人が埋める（塗装あり・なし、ロットごとに表を分けてよい）→ 確定単価
   ↓ 「見積書を作る」——客先・品物（加工製品）・条件（ロット・塗装）を選ぶ
見積書ページ（見積／年／月）── 見積明細に確定単価を写す（その時点の値で凍結）── PDF・メールで送る（用件「見積書」）
   ↓ 顧客から注文が来たら
受注ページ（受注明細の行が見積書を指す）——見積書は「受注」、来なければ「失注」
```

- **見積書の明細の単価は写して凍結**します（[【考察】表の集計の一般化.md](【考察】表の集計の一般化.md) §4.4）——出した紙の値は、
  あとで見積計算表を直しても変わってはいけない。見積書ページが原本で、PDF が出した紙の写し。
- **1つの品物に条件違いの行**（10個・塗装あり／50個・塗装なし）を並べられる——見積計算表が複数あるのと対応。
- **受注とのつながり**——受注明細の行に `見積`（見積書ページ）の列を持つか、見積書の明細に `受注` を持つか。受注の 🤖解析で
  「同じ客先・同じ品番の、まだ受注になっていない見積書」があれば単価を突き合わせる（見積と違う単価で注文が来たら ⚠）。
- **受注・失注の印**は見積書ページのタグ（`状態：見積中／受注／失注`）。見積の横断比較（「あの部品は前いくらで出したか」——
  【要求】見積 §1）は、見積書の明細を品番・加工製品で引けば出せる（表の写し）。

### 3.2 決めること

1. **見積書の紙の欄**——いま出している見積書（Excel など）の見本があれば、それに合わせます（発注書はデスクトップの見本から
   作りました——`w-cms\見本\` に見積書のフォルダを作って置いてもらえると助かります）。宛名・見積番号・見積日・有効期限・納期・
   支払条件・明細（品名・数量・単価・金額）・小計・消費税・合計・備考（塗装の有無など）。
2. **見積番号**——発注書と同じく**ページ番号**でよいか。
3. **有効期限**——決まった日数（30日など）か、毎回書くか。
4. **見積計算表が無い品物**（受注前に図面が無い・ざっくり出す）——見積書に直接単価を書けるか（書けるようにする案）。
5. **受注・失注**を誰がいつ付けるか——受注の 🤖解析で自動で「受注」にしてよいか。
