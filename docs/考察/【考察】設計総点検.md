## 0. 総評

**骨格は健全で、破れていたのは末端でした。**

次の4つは、いずれも文書が主張するとおりに、実装として成立していました。

- 3層の語彙モデル
- 一方向依存（htmldoc がドメインを知らない）。
  本文の HTML を扱う部品が、業務の中身（ドメイン）を知らずに済んでいる、ということです。
- サニタイズの二層化
- 決定ログの文化

文書と実装の乖離（食い違い）を探しに行きました。
しかし、**見つかったのは文書の誤りではなく文書が触れていない領域**ばかりでした
（メソッドガード・キャッシュヘッダ・派生索引の認可）。これが結論です。

- メソッドガードは、状態を変える口を、決まった要求の種類（POST など）に限る守りです。
- キャッシュヘッダは、応答を使い回してよいかを、ブラウザなどに伝える情報です。

一方で、**「黙って壊れる」経路が想定より多い**ことが分かりました。
「見える文字がすべて」の代償が、告知機構（壊れたことを人に知らせる仕組み）で十分に補われていません。

## 1. この調査から得た教訓

個別の指摘は、対処か判断で片付きます。しかし、下の8点は残ります。

1. **未検証の指摘は、着手前に必ず反証してから使う。**

   全件を反証側から検証したところ、**原文のまま通った指摘は1件もありませんでした**。

   - 判定が覆ったもの: 7件
   - 成立するが、範囲・深刻度・原因の訂正が要るもの: 10件
   - 残りは新規発見

   誇張・因果の取り違え・深刻度の付け間違いが、体系的に混じります。
   だから、**指摘を読んでそのままコードを直すと、存在しない欠陥を「修正」してしまう**ことになります。

   > 実例:
   >
   > - 「保存2本のロック検証がフェイルオープン」
   >   → `u == nil` は、`RequirePageWrite` とルート表の `RequireAuth` で二重に到達不能です。つまり**不成立**でした。
   >   フェイルオープンは、迷ったときに「通す」側へ倒れてしまうことです。
   > - 「`robots.txt` が `.` を含むパスで404」
   >   → **因果が誤り**でした。そもそもハンドラが未登録でした。
   > - 「`/api/load` がヒューリスティックキャッシュされうる」
   >   → 検証子が無く、再利用されないので**起きません**（実害は `/data/` だけ）。
   >   ヒューリスティックキャッシュは、指示が無いときに、ブラウザが自分の判断で応答を使い回すことです。
   > - 「往復契約テストに語彙形式が無い」
   >   → **結論が誤り**でした。`save_sanitize_test.go` が、3形式にバイト一致の往復契約を与えています
   >   （残る課題は、12形式中8形式が未カバーであること）。
   >   往復契約は、保存して読み直しても元と同じになる、という約束です。

2. **テストは「値」だけでなく「配線」も固定する。**

   「配線」は、その守りが実際に通り道へ組み込まれていることです。
   CSRF 対策と CSP は、どちらもブラウザ越しの攻撃に対する守りです。

   - [csp_test.go](../../internal/auth/csp_test.go) が固定していたのは、ポリシー文字列だけでした。
     `main.go` の組み込みは見ていませんでした。
   - そのため、**`CSPProtect` を丸ごと外しても緑**（試験が通る状態）でした。
   - この発見から、`buildHandler()` を切り出しました。
     [route_guard_test.go](../../cmd/w-cms/route_guard_test.go) が、ルートごとの保護レベルと、CSRF・CSP の**配線**を固定します。
   - 配線を変異させて（わざと壊して）、テストが落ちることを確認済みです。

3. **E2E だけが守っている不変条件がある。**

   不変条件は、いつも成り立っていなければならない決まりのことです。

   - `serializeChildren` の `.vocab-chrome` 除外には、Go テストがありませんでした。
     破れを検出できるのは、E2E だけでした。
   - E2E がリポジトリ外にあることの本当の重さは、「レビュー不能」より**この一点**です。
     `e2e/` の取り込みは、そのために優先しています。

4. **正本と索引がズレたら、認可は索引に従う。**

   - `GetPerms` も、`EffectivePublic` の親チェーン（親をたどる鎖）も、読むのは `cms.db`（派生）です。
     サイドカー（正本）ではありません。
   - だから、「サイドカーが壊れて `parent_id` を失う」は、データ整合の問題ではなく、
     **そのまま公開範囲の問題**になります。
   - データモデルを調べた1体と、安全性を調べた1体が、独立に同じ結節点を指しました。

5. **サニタイズの後にHTMLを足す関数が3つある**（`RenderComputedViews`・`RenderAnchors`・`RenderPageShell`）。

   （→ 3つは、調査の時点の数です。いまは `RenderReferenceLinks`（`internal/cms/ref_render.go`）が加わって、4つです。）

   - それぞれが、自前でエスケープ（文字を無害な形に直すこと）の責任を負っています。
   - 規律が破れた時点で、保存型XSSです
     （保存された本文に仕込まれたスクリプトが、開いた人のブラウザで動いてしまう攻撃）。
   - ここは、[本文サニタイズ設計.md](../旧文書/本文サニタイズ設計.md) §2 の二層の**外側**です。

6. **`.vocab-chrome` の不変条件は「型」ではなく「規律」。**

   - 本文DOMを走査する箇所は**29ある**のに、明示除外は4つだけです。
   - 残りは、「クロームが入れ子」「クロームが `data-type` を持たない」という、現時点の偶然に依存しています。
   - レジストリへ `View: true` を1件足すと、5箇所が一斉に誤爆します。

7. **手で書いた写像は、実装と同じ速度で陳腐化する。**

   - コードリファレンスは、行数主張30件中16件が誤りでした。
   - `app.js` を指す `file:line` は、7件中6件が誤りでした。
   - 殻の `id` 参照は、7件すべてが `w-` 未追随でした。

   **一方で腐っていなかったのは**、依存の向き・ミドルウェア入れ子・ルート表・サニタイズ二層・不変条件・テスト地図です。
   **構造は生き、座標は死ぬ**。文書を畳んだ判断は、この非対称に基づきます。

8. **「黙って壊れる」を告知で補うと決めたなら、告知の網羅を測る。**

   改名の告知は、3類型のうち1つしか拾っていませんでした。
   `section[data-type]` のタイポ（打ち間違い）は、完全に無症状でした。
   部材手配が読む `部品番号` は、Go コードに直書きされた**日本語の魔法文字列**で、
   レジストリにもエディタ補助にも現れませんでした（どちらも対処済み）。

### 2.2 起動時のDB再構築の決着（実測値の正本）

方式は維持と決まりました。「残る穴」の3点も、2026-08-22 に実装済みです（この節の最後の注記）。

`3e5d506` が入れた処理について、所要時間を実測し、利用者の判断を得ました。
その処理は、「起動時にスキーマのずれを見つけたらファイルから全再構築する」というものです
（[main.go](../../cmd/w-cms/main.go)）。スキーマは、DB の表の作りのことです。

**実測**:

- **1500ページ = 7.0秒**／**3000ページ = 15.8秒**。
- **1ページあたり約5ミリ秒でページ数に比例**します。
  本文の分量には比例しません（同じ1500ページで本文を4倍にしても、7.4秒でした）。
- 再構築が終わるまで、サーバーは受け付けを始めません。
- **心配していたほど長くはありませんでした。**

**利用者の判断**: **1日以内で終わるなら、ファイルから作り直す方式で行く**。

外挿すると（測った値を先へ延ばして見積もると）、100万ページで約1時間半です。
これは楽観値で、実際はもっと掛かります。
いずれにせよ1日以内なので、**方式は維持**します。

**残る穴（未対処）**:

再構築が途中で止まると（強制終了・停電）、
**次の起動は何事もなく成功し、取り込めなかったページは開いても「ありません」のまま**になります。

- `RebuildIfEmpty`（[sync.go](../../internal/cms/sync.go)）は、`pages` が**空かどうか**しか見ません。

利用者は下の3点に同意済みで、**やることは決まっていて未実装**です。

1. 再構築を**始めた印**を残す
2. 起動時にその印が残っていたら、**必ずやり直す**
3. 終わったら、**件数と所要時間**を記録に残す
