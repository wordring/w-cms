- **外注加工の `資料` 列**（ref）は、「加工業者に渡す資料」の置き場として宣言済みです。

  - 加工図面を加工製品ページに貼って、ここから指す設計です。

- **図面ブロック**の `受信元`（顧客から届いた図面PDF）・`対応DXF` は、タグで引けます。

1. **発注の表に列が足りません。**

2. **元の表に置き場が足りません。**

## 3. 案——「種類ごとに、どの列をどこから運ぶか」を設定に書く（利用者の案）

東邦の設定（`config/settings.json` の `extensions.toho`）に、**種類ごとの運び方**を書きます。

```json
"order_kinds": [
  { "kind": "材料", "from": "材料", "key": ["材質", "形状", "寸法"],
    "columns": { "材質": "材質", "形状": "形状", "寸法": "寸法", "数量": "個数" } },
  { "kind": "外注加工", "from": "外注加工", "key": ["加工内容"],
    "columns": { "品番": "@品番|@図面番号", "品名": "@図面名称", "加工内容": "加工内容",
                 "表面": "表面", "支給": "支給", "資料": "資料", "数量": "個数" } },
  { "kind": "購入部品", "from": "購入部品", "key": ["品名"],
    "columns": { "品名": "品名", "仕様": "仕様", "数量": "個数" } },
  { "kind": "支給部品", "from": "支給部品", "key": ["品名"],
    "columns": { "品名": "品名", "仕様": "仕様", "数量": "個数" } }
]
```

設定の読み方です。

- `columns` は、**左が発注部材表・発注明細の見出し**、**右が元の表の見出し**です。
  - `@名前` は、加工製品ページのタグです。
  - `|` は、「無ければ次」です。
  - `数量` は、元の個数×受注数です（いまと同じ）。
- `key` は、**手配済みを数える鍵**です。
  同じ値が発注書の行にあれば、「もう手配した」と数えます。
- **発注の表の列は、全種類の左側の和集合**です。
  - 【要求】の「すべての項目の集合」と同じです。紙では、空の列が消えます（実装済み）。
  - 発注書は、テンプレートの表を埋めます（テンプレート駆動 D）。
    だから、**テンプレートに無い列は値があれば右端へ足されます**。
  - 列の並びは、テンプレートで決められます。
- 種類は、**どの表から来たか**で決まります。だから、途中で落とさずに運びます。
  発注の表に `種類` の列を持つか、運ぶ値に添えるかは、§6 の問いです。
- **置き場所は拡張**です（東邦の業務の規則・開発方針 §0）。
  - コアは、「設定から語を読む」口と、表を埋める道具（`PageDraft.FillTable`）を貸すだけです。
  - 表の種類の登録をコードから出す方向（DBの日本語化 4-5）とも、向きが同じです。

**利点**: 種類を足す・列を足すのが、**設定の1行**で済みます。
運用者が足せます（複数運用者の前提）。

**難点**:

- 設定が「表の見出しの言葉」に依存します。
  見出しを改名したら、設定も直す必要があります（保存のときの告知で知らせられます）。
- 手配済みの鍵を種類ごとに持つので、**鍵を変えると、既存の発注書と結ばれなくなります**。

## 4. 外注加工で図面を添付するとき（利用者の問い）

**おすすめ: 加工製品ページの外注加工の表の `資料` 列に「渡す図面」を書いておき、発注書を送るときにそれを
添付の候補として並べる**ことです（毎回探して選ばなくてよく、人が外せます）。

| 送り方 | 図面の渡し方 |
|---|---|
| メール | 発注書PDF＋`資料` が指すファイル（PDF・DXF）を添付。送信欄に候補を並べ、人が外せる |
| FAX・手渡し | **図面PDFを発注書PDFの後ろのページに綴じる**（gopdf の `ImportPage`）。⚠ DXF は紙にできないので、FAX では渡せないと画面で言う |

- **`資料` が空なら、図面ブロックの `受信元`（顧客の図面PDF）・`対応DXF` を候補に出します。**
  - ただし、**顧客の図面をそのまま外注先へ渡してよいか**（守秘・版の取り違え）は、利用者の判断です（§6）。
  - 弊社で描き直した加工図（展開DXF など）を渡すなら、`資料` に書きます。
- 運ぶ道: 必要部材表 → 発注部材表 → 発注明細に、`資料` の列（ref）を持たせます
  （§3 の設定で「資料」を運びます）。
  発注書ページの送信欄は、発注明細の `資料` を集めて候補にします。
- 足りない部品は、次の4つです。
  - ① 参照→保存名の公開の口（コア）
  - ② 送信欄の候補の一覧（`order_send.go`・`app.js`）
  - ③ PDFの綴じ込み（`order_pdf.go`・`recover`）
  - ④ 25MB の上限と、図面の置き場の読み権限（通信箱のページを外注担当が読めるか）

## 12. 外注加工の資料のブロック（2026-09-28 夕・決定・実装）

> 2026-09-28 利用者（§6a の返事）:「加工製品のページに、外注加工ごとに資料のブロック（開いたり閉じたりできる）を用意して、そこに

番号（`弊社品番-番号`）が決まったので、形を決めます。

**いまある部品**（調べた事実）:

- 本文は、`<details>`／`<summary>` を持てます。**開閉は、JS 無しで動きます。**
  - サニタイザ（本文から危ない要素を落とす処理）が許しています。
  - エディタの保存も、同じ許可リスト〔`/api/tag-schema`〕から組むので、`open` まで残ります。
  - `<summary>` の中で字を打つ書き心地は、まだ画面で確かめていません。
- ファイルは、本文に **ファイル表示の印** `<section data-type="file-view" data-ref="000223-fhea">` で置けます。
  指す先は、**別のページの添付でもかまいません**。
  顧客の図面は通信記録のページに届いていて、加工製品ページはそれを指しています。
- メールの送信口（`/api/mail/send`）は、**読めるページの添付なら何ページからでも**付けられます
  （`{page_id, file}`・合計25MBまで）。写し直しは要りません。
- PDF の部品（gopdf）は、**既にあるPDFのページを取り込めます**（`ImportPage`・承認済みの gofpdi）。画像も置けます。
- 発注明細の行は、`弊社品番` と `番号` を持ちます（§11）。
  だから、**行から加工製品ページの資料へ辿れます**。新しい列は要りません。

**案**:

1. **ブロックの形**: `<details open><summary>資料 1</summary> …ファイル表示の印… </details>`。
   - **名乗りは summary の言葉**です（表が caption で名乗るのと同じ・見えている言葉が機能）。
     「資料 1」の **1 が外注加工の表の `番号`** です。
   - 加工製品テンプレートに「資料 1」を1つ置きます。足すときは、スラッシュメニュー「外注加工の資料」を使います。
   - 中に置くのは、ファイル表示の印（添付をこのページに上げる・通信記録の図面を指す）と、自由な文です。
2. **拾うもの**: 発注書の取り消していない外注加工の行ごとに、`弊社品番` のページの「資料 <番号>」のブロックの中の
   ファイル表示の印が指す添付です。
   **送る人が読めない添付は、拾いません**（理由は出します）。
3. **メール**: 送信欄に候補を並べ、**全部チェックした状態**で出します（人が外せます）。
   発注書のPDFと一緒に送ります。
4. **FAX・印刷**: 「📄 PDFを作る」とは別に、「**📠 FAX・印刷用（資料を綴じる）**」を置きます。
   発注書のうしろに、資料のPDFのページと画像を綴じた1本を作ります。
   - ⚠ **発注書のPDF（7年保存の正本）には綴じません**（出した注文の紙を太らせないためです）。
   - ⚠ **紙にできない形式**（DXF・CAD・Excel・ZIP）は綴じられないので、**「メールでだけ渡せます」と画面で言います**。
   - ⚠ 取り込めないPDF（暗号化など）は、飛ばして理由を出します
     （gofpdi は落ちることがあるので、守りを入れます）。
5. **外注加工の表の `資料` 列は外します**。
   ブロックと列で同じことを2か所に書くと、食い違うからです。

**聞くこと**:

- ① ブロックを番号で結ぶ（「資料 1」）でよいか
- ② FAX・印刷用は発注書と別の1本でよいか
- ③ `資料` 列を外してよいか

→ ✅ **3つとも案のとおり**（同日・利用者の選択）。

**実装（同日）**:
