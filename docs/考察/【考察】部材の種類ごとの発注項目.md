## 1. いま（2026-09-27 夜に調べた事実）

### 1.1 元の表（加工製品ページ）と、発注の表

| 表 | 列 |
|---|---|
| 材料 | 材質・形状・寸法・個数・備考・区分 |
| 外注加工 | 加工内容・支給・個数・推奨業者・資料（ref）・備考・区分 |
| 購入部品 | 品名・仕様・個数・備考・区分 |
| 支給部品 | 品名・仕様・個数・備考・区分 |
| **発注部材表・発注明細**（同じ12列・`orderItemColumns()`） | 弊社品番・品番・品名・材質・形状・寸法・表面・数量・単位・単価・備考・状態 |

- 【要求】発注フォルダ:「部材の種類によって発注明細に必要な項目は変わりますが、**表はすべての項目の集合**
  となります。PDFを作成するときに空の項目を消す」——**実装済み**（`readOrderDoc` が、どの行にも値の無い列を
  刷らない。`金額` だけは計算列なので常に刷る）。
- ⚠ 加工製品ページのテンプレートの外注加工の表には `推奨業者` の列がありません（登録には在る）。

### 1.2 必要部材表 → 発注部材表 → 発注書で運ばれるもの

| 種類 | 運ばれる | 落ちる |
|---|---|---|
| 材料 | 材質・形状・寸法・数量・参考単価 | — |
| 購入部品 | 品名・数量 | 仕様・推奨業者・備考 |
| 外注加工 | 品名＝**加工内容**・数量 | **何の部品か**（品番・図面名称）・支給・**資料**・推奨業者・備考 |
| 支給部品 | —（必要部材表に出していない） | — |

- 運ぶ値は固定です（必要部材表の行の属性 `unorderedRowAttrs`→画面の `lineOf`→`/api/our-order/draft`→
  発注書を作るとき `draftLinesOf`→`ourOrderLine`）。**種類（材料・購入部品・外注加工）も途中で落ちます**——
  発注書の行が外注加工かどうかは、行からは分かりません。
- 手配済みを数える鍵は、材料なら材質・形状・寸法、それ以外は**品名**（`orderedByProduct`・`draftedQty`）。
  外注加工の品名を「図面名称」に変えると、この鍵も変える必要があります。

### 1.3 図面を相手へ渡す部品

- **メールの口**（`/api/mail/send`）は、**複数の添付・別ページのファイル・`.dxf`**（設定 `attachment_extensions`）を
  受け付けます（送る人がそのページを読めること・合計25MB）。控えにも添付へのリンクが残ります。
- ⚠ **発注書の送信画面は、添付を発注書PDF 1本に固定しています**（`order_send.go`・`app.js` の `sendMail`）。
  人が添付を足す欄はありません（通信記録の「✉️ 返信」には、ページの添付を選ぶ欄があります）。
- **FAX・手渡しは印を付けるだけ**です（FAXサーバーはまだ無い）。
- **外注加工の `資料` 列**（ref）は「加工業者に渡す資料」の置き場として宣言済み——**値は添付への参照**
  （`ページID-ブロックID`）で、加工図面を加工製品ページに貼って、ここから指す設計です。**読むコードはまだ無い**。
- **図面ブロック**の `受信元`（顧客から届いた図面PDF）・`対応DXF` はタグで引けます——ただし指す先は
  **通信箱の記録ページ**の添付です（加工製品ページではない）。
- **発注書PDFの後ろに図面PDFを綴じる口**は既にあります——gopdf の `ImportPage`／`ImportPagesFromSource`
  （依存の gofpdi は承認済み・いまは使っていない）。⚠ 読めないPDFで `panic` するので `recover` が要ります。
- ⚠ 参照（`ページID-添付ID`）を保存名（`<ID>.<拡張子>`）へ解く口は、コアの中にあって公開されていません。

### 1.4 ついでに見つけた食い違い（未対応）

  あります（実物の材料2枚は単価も合計も空欄）」「0とは別」と食い違い。
- **メールで送るたびにPDFを作り直しています**——【要求】「送るのは表示している最新のPDF（送る直前に作り直さない）」
  と食い違い（作業引き継ぎ 0a10 の「再送とキャンセル」の残りと同じ話）。

## 2. 問題の形——3か所で合っていない

1. **発注の表に列が足りない**——加工内容・仕様・支給・資料（表面は在る）。
2. **元の表に置き場が足りない**——**塗装の色**を加工製品ページのどこに書くか（外注加工の表に色の列が無い）。
   テンプレートの外注加工の表には推奨業者も無い。
3. **運ぶ道が種類を知らない**——種類ごとに運ぶ値が違うのに、道は1本の固定の組で、種類も落ちる。

## 3. 案——「種類ごとに、どの列をどこから運ぶか」を設定に書く（利用者の案）

東邦の設定（`config/settings.json` の `extensions.toho`）に、**種類ごとの運び方**を書きます。

```json
"order_kinds": [
  { "kind": "材料", "from": "材料", "key": ["材質", "形状", "寸法"],
    "columns": { "材質": "材質", "形状": "形状", "寸法": "寸法", "数量": "個数" } },
  { "kind": "外注加工", "from": "外注加工", "key": ["加工内容"],
    "columns": { "品番": "@品番|@図面番号", "品名": "@図面名称", "加工内容": "加工内容",
                 "表面": "表面", "支給": "支給", "資料": "資料", "数量": "個数" } },
  { "kind": "購入部品", "from": "購入部品", "key": ["品名"],
    "columns": { "品名": "品名", "仕様": "仕様", "数量": "個数" } },
  { "kind": "支給部品", "from": "支給部品", "key": ["品名"],
    "columns": { "品名": "品名", "仕様": "仕様", "数量": "個数" } }
]
```

- `columns` の**左が発注部材表・発注明細の見出し**、**右が元の表の見出し**（`@名前` は加工製品ページのタグ・
  `|` は「無ければ次」）。`数量` は元の個数×受注数（いまと同じ）。
- `key` は**手配済みを数える鍵**——同じ値が発注書の行にあれば「もう手配した」。
- **発注の表の列は、全種類の左側の和集合**です——【要求】の「すべての項目の集合」と同じで、紙では空の列が消える
  （実装済み）。発注書はテンプレートの表を埋めるので（テンプレート駆動 D）、**テンプレートに無い列は値があれば
  右端へ足されます**——列の並びはテンプレートで決められます。
- 種類は**どの表から来たか**で決まるので、途中で落とさずに運びます（発注の表に `種類` の列を持つか、
  運ぶ値に添えるか——§6 の問い）。
- **置き場所は拡張**（東邦の業務の規則・開発方針 §0）。コアは「設定から語を読む」口と、表を埋める道具
  （`PageDraft.FillTable`）を貸すだけ。表の種類の登録をコードから出す方向（DBの日本語化 4-5）とも向きが同じ。

**利点**: 種類を足す・列を足すのが**設定の1行**で済む（運用者が足せる——複数運用者の前提）。
**難点**: 設定が「表の見出しの言葉」に依存する——見出しを改名したら設定も直す必要がある（保存のときの
告知で知らせられる）。手配済みの鍵を種類ごとに持つので、**鍵を変えると既存の発注書と結ばれなくなる**。

## 4. 外注加工で図面を添付するとき（利用者の問い）

**おすすめ: 加工製品ページの外注加工の表の `資料` 列に「渡す図面」を書いておき、発注書を送るときにそれを
添付の候補として並べる**（毎回探して選ばなくてよい・人が外せる）。

| 送り方 | 図面の渡し方 |
|---|---|
| メール | 発注書PDF＋`資料` が指すファイル（PDF・DXF）を添付。送信欄に候補を並べ、人が外せる |
| FAX・手渡し | **図面PDFを発注書PDFの後ろのページに綴じる**（gopdf の `ImportPage`）。⚠ DXF は紙にできないので、FAX では渡せないと画面で言う |

- **`資料` が空なら、図面ブロックの `受信元`（顧客の図面PDF）・`対応DXF` を候補に出す**——ただし**顧客の図面を
  そのまま外注先へ渡してよいか**（守秘・版の取り違え）は利用者の判断（§6）。弊社で描き直した加工図（展開DXF など）を
  渡すなら `資料` に書く。
- 運ぶ道: 必要部材表 → 発注部材表 → 発注明細に `資料` の列（ref）を持たせる（§3 の設定で「資料」を運ぶ）。
  発注書ページの送信欄は、発注明細の `資料` を集めて候補にする。
- 足りない部品: ① 参照→保存名の公開の口（コア）② 送信欄の候補の一覧（`order_send.go`・`app.js`）③ PDFの綴じ込み
  （`order_pdf.go`・`recover`）④ 25MB の上限と、図面の置き場の読み権限（通信箱のページを外注担当が読めるか）。

## 6. 聞くこと

1. **支給部品を必要部材表に出す意味**——お客様から支給される部品を「手配する」とは何か（お客様への催促？
   弊社から外注先へ支給する部品？）。発注書（紙）にするのか、別の知らせなのか。
2. **塗装の色の置き場**——外注加工の表に `表面`（色・鍍金・生地）の列を足して、発注明細の `表面` へ運ぶ形でよいか。
   塗装・鍍金は外注加工の表に書くのか、別の表（`塗装`）にするのか。
3. **外注加工の発注明細の品名**——部品（図面名称）にして、加工内容は別の列（`加工内容`）でよいか。品番は加工製品の
   `品番`、無ければ `図面番号` でよいか。
4. **設定の形**（§3 のスケッチ）でよいか。種類を発注の表の列（`種類`）として見せるか。
5. **図面の渡し方**（§4）——`資料` 列で決めておく形でよいか。顧客の図面をそのまま外注先へ渡してよいか。
6. **購入部品の `仕様`・外注加工の `支給`・`推奨業者`・行の `備考`** を紙に出すか（列にするか、落とすか）。

## 8. 調査（2026-09-28）——実物の発注書・ワンノート・ウェブ

⚠ 実在の社名・人名はここに書かない（公開リポジトリ）。

### 8.1 実物の発注書（デスクトップの見本・実物7枚）

- **7枚とも題は「発注書」**。Excel の様式が2つ——**材料用**（明細 `材質｜形状｜寸法｜単位｜数量｜単価｜金額`）と
  **製品用**（加工・塗装・鍍金の5枚・明細 `商品コード（＝図番）｜商品名｜［色］｜単位｜数量｜単価｜金額`）。
- **ヘッダは全部同じ**: 発注年月日（和暦）・発注書No.（欄はあるが**7枚とも空**）・宛先（社名＋御中）・前文「下記の通り、
  発注いたします。」・**差出人**（自社名＋部署・住所・担当・TEL・FAX）・**合計金額（税抜）**（上に大きく）・
  **希望納期**（日付は0枚——自由文「急ぎでお願いします」「納期わかりましたらお知らせください」か空）・
  **納品場所**（7枚とも自社）。印・支払条件・消費税は無い。
- **欄外**: 表の下の合計（税抜）と備考の枠。備考には**何に使うか（「装置名＋用」）**がほぼ毎回（7枚中6枚）、
  塗装は「持ち込み日は未定・決まったら連絡」、最後は「よろしくお願いします。」。
- **外注加工の紙に、加工の種類は書かれていない**——図番と業者で伝わる運用。**図面の添付の書き込みは0枚**。
- **塗装は色の列**（全行「緑」）と、**装置ごとの見出しの行**（商品コードの欄に「装置名＋用」だけの行）で束ねる。
  品名に「（マスキング有）」と作業の指示。**鍍金は色の列が空で、品名の下の続きの行に「（三価ユニクロ、タコメッキ）」**。
- **材料の紙は単価・金額が空**（値段は後で決まる）。**実物は0を空欄に見せる**（w-cms の紙は「0」「0 円」と刷る——§1.4）。
- w-cms の紙に無いもの: 前文・**納品場所**・上の合計欄・装置ごとの見出しの行。

### 8.2 ワンノートの運用（「板金部」805ページを読むだけで全件）

- **■塗装（2026-07）・■外注加工（2026-08）・■購入品（2026-08）は、この2か月で雛形に足された新しい節**。
  それより前は ■材料の表と自由文・■見積もり・まとめページに書かれていた。**雛形はいまも更新されている**。
- **■外注加工**の表は全部 `名称｜材質｜加工｜個数｜推奨業者｜備考`（値のあるページ22）:
  - **加工**: 溶断・レーザー切断・旋盤・鍍金・機械加工（マシニング）。
  - **名称**: 部品名・**図番＋枝番**・材料の記述（`t9板`）など、まちまち。
  - **材質**: 板厚まで入ることがある（`SS t12`）・表面の指定が混ざる（`鉄 メッキ`）。
  - **推奨業者**: 2社並べる・**自社**（自社で加工する）もある。
  - **備考**: ほとんどが「装置名称・図面名称」（どの製品のものか）。
  - 表の後ろの自由文は**価格の履歴**——`日付　見積　業者　［枝番］　ロットN　単価`。■見積もりの外注加工費と一致する。
  - **1つの製品に外注加工が複数ある例**（5行・3行・2行）——**番号は「製品の図番（または部品名）＋ハイフン＋連番の枝番」**で、
    自由文の価格の行もこの枝番で行を指している。
  - 自社で描いた**図面の印刷イメージ**が ■外注加工 の節に置かれている（ページに1枚）。業者ごとの**発注書 Excel の添付**が
    実質の発注履歴。加工用の DXF は ■データ に置かれている。
- **■塗装**（57ページ）は自由文の**単価の履歴**（`日付　業者　［見積］　［色／マスキング］　ロットN　単価`）。**色を書いた行は7行だけ**。
  **色と鍍金の種類がきちんと書かれている唯一の場所は、まとめページの客先の部品リストの `表面処理` 列**
  （`塗装(緑) 日塗工：番号(マンセル：値)`・`塗装（黒）半ツヤ`・`ユニクロメッキ（白）`・`生地品`）。
- **■購入品**は中身があるのが3ページだけで、購入部品の実際の記録は **■材料の表の行**（形状に「一種ナット」・寸法に「M10」・
  備考に仕入先）とまとめページに混ざっている。
- **■支給品は客先から支給される物**（鋳物・ナット付きパイプ・改造前の品など）。**価格も業者も無く、受け取りの状態だけ**
  （「引き取り済み」「入手済み」）。弊社から外注先へ材料を支給した記録は見つからない。
- 「注文書ひな形」ページで、業者が**機械加工・切断加工・鋼材・購入部品・塗装・メッキ・部品**の7つに分けられている。
- ⚠ OneNote は **32ビットの PowerShell** でしか COM を開けない（`C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`）。

### 8.3 ウェブ（テンプレート・法律）

- **下請法は 2026-01-01 から「取適法」**（製造委託等に係る中小受託事業者に対する代金の支払の遅延等の防止に関する法律）。
  旧「3条書面」は**「4条明示」**。**明示事項は12**——名称・委託日・給付の内容・納期・納入場所・**検査完了期日**・代金の額・
  **支払期日**（受領から60日以内・「納品後○日以内」は不可）・（一括決済・電子記録債権の事項）・**有償支給の品名・数量・対価・
  引渡期日・決済期日と方法**・未定事項の理由と予定期日。法4条で**支払方法**も。
  - **対象になるかは資本金・従業員数の組で決まる**（製造委託: 発注側 資本金1千万円超〜3億円 × 受ける側 1千万円以下、など／
    従業員300人超 × 300人以下）。**加工・塗装・めっきは製造委託**。規格品の購入は原則対象外だが、**寸法を指定した切断は委託に
    当たりうる**。
  - **メールでの交付に相手の承諾は要らなくなった**（求められたら書面）。受信と同時に紙に出る FAX は書面の扱い。
  - **取引の記録（受領日・検査の結果・変更の理由・支払額と日）を2年保存**——発注書の写しだけでは足りない。
  - 振込手数料を相手に負担させる文言・手形払は、対象の取引では不可。
- **フリーランス法**（2024-11）: 外注先が**従業員のいない個人（一人会社）**なら、**会社の規模に関係なく**明示義務がある。
- 公取委の書式例（製造委託）: 明細に品名・規格・数量（単位）・単価・金額、**原材料「支給なし／有償／無償」**の欄。
  品名の欄に「仕様書、図面、検査基準等を別に交付している場合は、そのことを付記する」。
- 種類ごとの項目の相場:
  - 塗装: **色（日塗工番号・マンセル・色見本）・艶（段階と言い方を明記）**・膜厚・マスキング・塗装方法・用途。
  - めっき: 種類（JIS記号、三価クロメートは括弧で補う）・ベーキング・マスキング。
  - 外注加工: **図番と版数**・加工内容・支給の有無・図面の渡し方。
  - 購入部品: メーカー・型番・仕様・同等品可否。
  - **支給を依頼する側の書類（支給願い）の定型は見つからない**——近いのは支給品受領書・受払簿（支給元・品名・規格・数量・
    必要日・受領日・受領数）。
  - **社内価格の社内発注書の定型も見つからない**（近いのは製造指示書）。

## 9. 加工製品ページの表の項目の提案（2026-09-28）

見本・ワンノート・ウェブの3つで**繰り返し出てきたもの**を採り、1つにしか出ないものは備考か後回しにする。
**★は新しく足す列**。

### 9.1 材料（いまのまま・足さない）

`材質｜形状｜寸法｜個数（1台あたり）｜備考｜区分`

- 実物の紙もワンノートもこの形。**定尺・切断の指定は寸法に書く**（ワンノート `*定尺（6000）`・紙の続きの行 `（〜品）`）。
- ミルシートの要否は、どこにも出てこない（ウェブだけ）→ 足さない。
- ⚠ ワンノートの ■材料 には**購入部品（ナット等）と切り板の外注（溶断・レーザー切り板）が混ざっている**——移すときに
  購入部品・外注加工へ仕分ける。

### 9.2 外注加工（塗装・鍍金もここへ）

`★番号｜名称｜加工内容｜材質｜★表面｜個数（1台あたり）｜支給｜推奨業者｜備考｜区分` ＋ **番号ごとの資料のブロック**

- **★番号**——1つの製品に外注加工が複数ありうる（利用者）。ワンノートは「**製品の図番（または部品名）＋ハイフン＋連番**」で
  振っていた（価格の行もこれで指す）。**振り方は別途相談**（利用者）——その日まで、この列は人が書く。
- **名称**——外注先へ渡す品物の名前（部品名）。紙の `品名` になる。
- **加工内容**——溶断・レーザー切断・曲げ・溶接・旋盤・機械加工・**塗装**・**鍍金**。実物の紙には書かれていない（図番と業者で
  伝わる）ので、紙に刷るかは設定で（初期値は刷る——外注先が複数の加工を受ける場合に要る）。
- **★表面**——**塗装の色・艶・鍍金の種類**（`緑`・`黒 半ツヤ`・`日塗工 番号`・`三価ユニクロ`・`生地`）。**塗装を外注加工の表へ
  まとめる**（利用者の希望）。マスキングの有無もここに書く（実物は品名の中・ワンノートは自由文）。紙の `表面`（旧 `色`）になる。
- **材質**——ワンノートで使われている（`SS t12`）。
- **支給**——`なし／有償／無償`（公取委の書式例の欄）。ワンノートでは弊社から外注先へ支給した記録は無いが、法の明示事項
  （有償支給）に関わるので列は残す。
- **推奨業者**——ワンノートでよく使われている（**自社**を書けば自社で加工）。紙には出さない（その業者あての紙なので）。
  ⚠ いまの加工製品テンプレートには無い列（登録には在る）→ テンプレートに足す。
- **資料**——利用者の案で、**列ではなく番号ごとの資料のブロック**（開閉できる・図面・写真・文書・顧客の図面も）へ。
  発注書を送るとき、その番号の資料を**メール・FAX・印刷に添える**。⚠ ブロックが番号で結ばれるので、番号の振り方と一緒に決める。

### 9.3 購入部品

`品名｜仕様｜個数（1台あたり）｜★推奨業者｜備考｜区分`

- **仕様**に**メーカー・型番・規格**（`M8`・`W1"*40`・`パイロット付`）。ウェブはメーカー・型番を分けるが、実物・ワンノートは
  1つの欄に書いている → 分けない。
- **★推奨業者**——ワンノートの ■購入品 は外注加工の表を流用して推奨業者を使っていた。紙には出さない。

### 9.4 支給部品（支給願い）

`品名｜仕様（客先の部品番号など）｜個数（1台あたり）｜備考｜区分`

- **客先から支給される物**（ワンノート）。**支給願い**として客先へ「発注」する（利用者）——宛先は加工製品の `客先`。
- **受け取ったこと**は、支給願いの行の `状態`（`納品済`＝受領）で記録する（ワンノートの「引き取り済み」「入手済み」）。
- 紙の題は **「支給願い」**（設定の種類ごとの題）。単価・金額は刷らない（価格が無い）。

### 9.5 加工製品ページではなく、発注書（紙）の側に要るもの

- **納品場所**（実物7枚とも自社・いまの紙に無い）→ 発注書テンプレートにタグ `納品場所`（初期値は自社）。
- **何に使うか（「装置名＋用」）**——実物の備考にほぼ毎回 → 発注部材表から作るとき、行の加工製品の `装置名称` から
  備考欄の下書きに入れる（人が消せる）。
- **塗装の紙の「装置ごとの見出しの行」** → 紙で装置ごとに束ねる（弊社品番から装置名称を引く）。
- **差出人のまとまり**（自社名・部署・住所・担当・TEL・FAX）——実物は毎回。w-cms は署名（連絡帳の担当者ページ）から刷る。
- **金額 0 を空欄に**（§1.4）。
- **法定の明示事項**（検査完了期日・支払期日・支払方法・有償支給の条件）——**東邦の取引が取適法・フリーランス法の対象に
  なるかで決まる**（§10 の問い）。

## 10. 聞くこと（2026-09-28・§9 の提案に対して）

1. §9 の各表の列でよいか（★の3つ——外注加工の `番号`・`表面`、購入部品の `推奨業者`——を足す）。
2. **外注加工の番号の振り方**（別途相談・ワンノートの「図番＋ハイフン＋連番」から始めるか）と、**番号ごとの資料のブロック**の形。
3. **東邦の資本金と従業員数**、**外注先に従業員のいない個人事業主がいるか**——取適法・フリーランス法の明示事項（検査完了期日・
   支払期日・支払方法など）を発注書に足す必要があるかが決まる。
4. 自社の他部門への発注（社内価格）は、発注書と同じ紙でよいか（題を「社内発注」などに変えるか）。

## 10a. 利用者の返事（2026-09-28 午後）

1. **★の列は足してよい**（外注加工の `番号`・`表面`、購入部品の `推奨業者`）→ ✅ 同日に足した（§11）。外注加工には `名称`・`材質` も。
2. **番号は連番でよい**（「ほかに良い方法があれば提案してください」）→ **提案: 加工製品ごとの連番（`1`・`2`…）を人が
   書き、紙には `弊社品番-番号`（`000235-1`）で刷る。消した番号は使い回さない。** ワンノートの「図番＋ハイフン＋連番」と
   同じ形で、**図番の代わりに弊社品番**を使う——図番は顧客が変える（改定で `_rev1` になる）が、弊社品番は変わらないので、
   外注先から番号で問い合わせを受けても引ける。⚠ **確認待ち**（違っていれば紙の刷り方を1か所変えるだけ）。
3. **資本金1000万円・従業員2人・外注先は企業だけ** → **取適法の発注側に当たらない**（製造委託で発注側になるのは資本金
   1千万円**超**か従業員300人超——1000万円ちょうどは「超」ではない）。**フリーランス法も、相手が企業なら当たらない**
   ——⚠ ただし**従業員のいない一人会社は「企業」でもフリーランス法の対象**です（§8.3）。法定の明示事項（検査完了期日・
   支払期日・支払方法など）は**いまは足さない**。⚠ **資本金・従業員数が変わったとき、一人会社や個人へ外注するときは
   見直すこと。**
4. **自社の他部門への発注は同じ紙でよい**（題も「発注書」のまま）。

利用者:「**履歴は替えなくて良いと思います。運用前に一度だけ履歴の精査と変更を行いましょう**」——公開リポジトリの
履歴の書き換え（実名の除去）は**いまはしない**。運用を始める前に1回だけ（作業引き継ぎの「決定はしたが着手は先」）。

## 11. 実装（2026-09-28）

§3 の案をそのまま入れた（利用者:「一度ご提案通りにやってみましょう。それを見ながら考えましょう」）。

- **設定 `extensions.toho.order_kinds`**——種類ごとに `kind`・`from`（加工製品ページの表のキャプション）・`key`（手配済みを
  数える鍵）・`display`（必要部材表に出す名前）・`columns`（発注の表の列 ← 元の表の列・`@タグ`・`@弊社品番`・`|` は
  「無ければ次」）・`title`（紙の題）。読み手は `ext/toho/order_kinds.go`。
  - 材料: 鍵 `材質・形状・寸法`。
  - 外注加工: 鍵 `番号・加工内容`／品番 `@品番|@図面番号`／品名 `名称|@図面名称`／加工内容・材質・表面・支給。
  - 購入部品・支給部品: 鍵 `品名・仕様`。支給部品は題 **「支給願い」**。
- **設定 `order_print_columns`**——紙に刷る列の並び（初期値: 番号・品番・品名・加工内容・材質・形状・寸法・表面・仕様・
  支給・単位・数量・単価・金額）。**推奨業者は運ばない・行の備考は刷らない**。全行が空の列は紙から落ちる（いまと同じ）。
- **発注の表（発注部材表・発注明細）に `種類`・`番号`・`加工内容`・`仕様`・`支給` の列**。手配済みの鍵は
  **種類＋鍵の列の値**（`orderRowKey`）——必要部材表・発注部材表・発注書で同じ関数。⚠ **種類の無い古い行**は、
  鍵の列のどれかに値がある最初の種類として読む（材料の行は材料・品名だけの行は購入部品）。
- **支給部品も必要部材表に出る**（09-27 は「出さない」だった）。
- **紙**: 題は取り消していない行の種類が全部同じ題を持つときだけその題（混ざれば「発注書」）・保存名も同じ題／
  外注加工の番号は `弊社品番-番号`／⚠ **単価が空なら金額も空、単価の無い行が1つでもあれば合計を刷らない**（§1.4 の
  食い違いを直した）／単価が1つも無い紙は金額の列ごと落とす。
- **テンプレート（職場のデータ）**: 加工製品の外注加工を `番号｜名称｜加工内容｜材質｜表面｜個数｜支給｜推奨業者｜資料｜
  備考｜区分`、購入部品に `推奨業者`。発注書の発注明細を発注の表の列の和集合に、タグに `納品場所`（初期値 `弊社`）。
- ⚠ **まだのもの**: 番号ごとの資料のブロック（§4・§6a）／装置名＋用 の備考の下書き・塗装の紙を装置で束ねる（§9.5）／
  送るたびのPDFの作り直し（§1.4 の2つ目）。
