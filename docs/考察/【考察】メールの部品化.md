# 【考察】メールの部品化

メールを書く欄・下書き・（これから）メールの表示と FAX を、**1つの部品**にする話の決定ログです。
現況は [作業引き継ぎ.md](../作業引き継ぎ.md)、経緯は [変更履歴.md](../変更履歴.md) 2026-09-30、
要求は [【要求】通信拡張.md](../拡張/通信/【要求】通信拡張.md) §3。

## 1. きっかけ（2026-09-30）

> 「メール表示、メール送信、メール編集などを部品化したら良いと思います。FAXなどもいずれ部品化したいです」
> 「メール編集は下書きのことです。今日着手します」——利用者

数えると、**メールを書く欄が2つあり、別々に作られていました**。送る口（`POST /api/mail/send`）は1つで、
控えが通信箱に残るところは共通でした。

| | 返信の欄 | 発注書の送信の欄 |
|---|---|---|
| 組み立てる場所 | 画面（`app.js`） | サーバー（東邦の拡張の鏡） |
| CC | あり | 無い |
| 署名 | 無い | あり（連絡帳の「メールの署名」） |
| 添付 | ページの📎から選ぶ | 発注書の PDF（送るときに作る）と資料のチェック |
| 送ったあと | 知らせ | 発注済みの印（画面が3段を順に呼ぶ） |

**同じことをする欄が、片方にしか無いものを持っていました。** 下書きはどちらにも無く、書きかけは
画面を閉じると消えていました。

## 2. 決めたこと

### 2.1 欄は1つ、違うのは「用件」

- **部品は `assets/mail-compose.js`（＋ `mail-compose.css`）**。`app.js` に頼らないので、エディタのページと
  メール一覧（`mails.html`）の両方から読む。
- **用件**（返信・新規・発注書）ごとに違うのは3つだけ——**初期値**（宛先・件名・署名入りの本文・添付の候補・注意）、
  **送る直前の仕事**（発注書なら PDF を作って添える）、**送れたあとの仕事**（発注済みにする）。
- **口は通信の拡張、中身は使う側の拡張**（`comm.RegisterSendPurpose`・開発方針 §0「口はこちら、言葉は拡張から」）。
  メールの拡張は発注書を知らず、東邦の拡張が用件「発注書」を登録する（`ext/toho/order_mail.go`）。
  返信・新規はメールの拡張が登録する（`ext/comm/mail/compose.go`）。
- ⚠ **「送れたのに後の仕事ができなかった」は、送れたことと一緒に言う**（`after_error`）——黙るともう一度送る
  （09-22 の発注書の送信と同じ規律。画面の3段がサーバーの1回に畳まれただけ）。

### 2.2 下書きは通信箱のページ

- 形は**送信の控えと同じテンプレート**（通信記録（送信メール））。送信日時・メッセージID・対応が無く、
  `下書き`（用件の名前）と `下書きの元`（用件の元のページ・参照）のタグを持つ。
- **家でも職場でも開ける**（ブラウザに憶えると、その端末でしか直せない）。**対応のタグが無いので未処理の一覧に並ぶ**
  ——書きかけを忘れない（一覧には「📝 下書き」の印）。メール一覧でもいちばん上に並ぶ。
- ⚠ **`返信元` は付けない**——送る前から「この記録への返信」に並ぶと、出していない返信が出したように見える。
- **送ったら、送った日の控えを新しく作り、下書きはごみ箱へ**（控えの置き場は送った月・下書きの月ではない）。
- ⚠ **書けない下書き・エディタで開いている下書きからは1通も送らない**——送ってから片付けられないと分かっても、
  出たメールは戻せない。⚠ **`下書き` のタグが無いページは、下書きとして書き換えない**（この口で任意のページを
  上書きさせない）。
- ⚠ `<pre>` の直後の改行は HTML として読むと1つ落ちる——空行で始まる本文（返信の初期値）が開き直すたびに
  詰まらないよう、保存のときに1つ補う。

### 2.3 署名は連絡帳の拡張へ

メールの署名は返信にも新しいメールにも要る**共通の道具**なので、読み方（節の中身を行にする）を東邦の拡張から
`ext/comm/contacts/signature.go` へ移した（開発方針 §0「共通に使えるものを拡張に閉じ込めない」）。
**ログイン名と同じ題の連絡帳の人のページ**の「メールの署名」を入れる（09-22 の差出人の初期値と同じ当て方）。
発注書の署名（紙に刷る差出人）は東邦の拡張に残る。

## 3. 変えていないこと

- **発注書は送る直前に PDF を作り直す**（09-22 のまま）。「表示中の最新のPDFを送る」（C4・09-24 決定）は、
  再送とキャンセルの仕事で扱う（[【要求】発注フォルダ](../拡張/東邦/【要求】発注フォルダ.md)「発注書の再送とキャンセル」）。
- 「FAXで送った」「手渡した」のボタン（人が押したことが事実）。

## 4. まだのもの

- **メールの表示の部品**——ヘッダ・本文・添付・前後の鎖を1つにし、通信記録のページでもメール一覧でも、
  受注ページのような別のページの中でも同じ見た目にする。**どこに埋めたいか**を利用者に聞いてから。
- **FAX**——送る欄の「送り先の道」を差し替える（宛先は FAX 番号・添付は PDF だけ）。用件（初期値と前後の仕事）は
  道に依らないので、そのまま使える。FAX サーバーの機械が整ってから（`ext/comm/fax`）。
- 下書きを捨てるボタン（いまはページを消す——🗑）。
