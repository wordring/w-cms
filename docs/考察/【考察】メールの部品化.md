# 【考察】メールの部品化

メールを書く欄・下書き・（これから）メールの表示と FAX を、**1つの部品**にする話の決定ログです。
「部品」は、いくつもの画面から同じように使える、画面と処理のまとまりのことです。

この文書の並びは、次のとおりです。

- **決めたこと**（§2）: メールを書く欄を1つにすること、下書きの持ち方、署名の置き場。
- **変えていないこと**（§3）
- **まだのもの**（§4）: メールの表示の部品、FAX、下書きを捨てるボタン。

現況は [作業引き継ぎ.md](../作業引き継ぎ.md)、経緯は [変更履歴.md](../変更履歴.md) 2026-09-30、
要求は [【要求】通信拡張.md](../拡張/通信/【要求】通信拡張.md) §3 にあります。

## 1. きっかけ（2026-09-30）

> 2026-09-30 利用者:「メール表示、メール送信、メール編集などを部品化したら良いと思います。FAXなどもいずれ部品化したいです」
> 「メール編集は下書きのことです。今日着手します」

数えてみると、**メールを書く欄が2つあり、別々に作られていました**。

共通だったのは、次の2つです。

- 送る口（`POST /api/mail/send`）は1つでした。「口」は、画面がサーバーへ仕事を頼むときの入口のことです。
- 送ったメールの控えは、どちらも通信箱に残りました。通信箱は、届いた通信と送った通信の記録を入れておくページです。

違っていたのは、次の所です。

| | 返信の欄 | 発注書の送信の欄 |
|---|---|---|
| 組み立てる場所 | 画面（`app.js`） | サーバー（東邦の拡張の鏡） |
| CC | あり | 無い |
| 署名 | 無い | あり（連絡帳の「メールの署名」） |
| 添付 | ページの📎から選ぶ | 発注書の PDF（送るときに作る）と資料のチェック |
| 送ったあと | 知らせ | 発注済みの印（画面が3段を順に呼ぶ） |

表の言葉を少し説明します。

- 「東邦の拡張」は、開発元の業務のための拡張です。
- 「鏡」は、ページを表示するときにサーバーが描き足す部分です。本文には保存されません。
- 「CC」は、写しを送る宛先です。
- 「連絡帳」は、連絡先の人や組織のページを入れておく置き場です。

**同じことをする欄が、片方にしか無いものを持っていました。**
下書きは、どちらにもありませんでした。書きかけは、画面を閉じると消えていました。

## 2. 決めたこと

### 2.1 欄は1つ、違うのは「用件」

- **部品は `assets/mail-compose.js` です**（見た目は `mail-compose.css`）。
  `app.js` に頼らないので、エディタのページとメール一覧（`mails.html`）の両方から読めます。
- **用件ごとに違うのは、3つだけです。** 用件は、返信・新規・発注書のことです。
  - **初期値**: 宛先・件名・署名入りの本文・添付の候補・注意
  - **送る直前の仕事**: 発注書なら、PDF を作って添えます
  - **送れたあとの仕事**: 発注済みにします
- **口は通信の拡張、中身は使う側の拡張が持ちます。**
  用件を登録する口は `comm.RegisterSendPurpose` です。
  開発方針 §0 の「口はこちら、言葉は拡張から」に当たります。
  - メールの拡張は、発注書を知りません。用件「発注書」は、東邦の拡張が登録します（`ext/toho/order_mail.go`）。
  - 返信・新規は、メールの拡張が登録します（`ext/comm/mail/compose.go`）。
  - その後: いまの用件は、返信・新規・部材発注書・見積書・部材見積依頼の5つです（2026-10-19 に確かめた）。
    用件「発注書」は、2026-10-15 の用語の変更で「部材発注書」になりました（`ext/toho/order_mail.go` の `OrderMailPurpose`）。
    見積書は `ext/toho/estimate_mail.go`、部材見積依頼は `ext/toho/rfq_pdf.go` が登録します。
- ⚠ **「送れたのに後の仕事ができなかった」は、送れたことと一緒に言います**（`after_error`）。
  黙っていると、人がもう一度送ってしまいます。
  09-22 の発注書の送信と同じ規律です。画面が3段に分けて呼んでいたものが、サーバーの1回に畳まれただけです。

### 2.2 下書きは通信箱のページ

- **形は、送信の控えと同じテンプレートです**（通信記録（送信メール））。
  - 送信日時・メッセージID・対応はありません。
    メッセージID は、メール1通ごとに付く番号です。対応は、記録の処理が済んだことを示す印です。
  - タグを2つ持ちます。`下書き`（用件の名前）と、`下書きの元`（用件の元のページ・参照）です。
- **家でも職場でも開けます。** ブラウザに憶えさせると、その端末でしか直せないからです。
- **対応のタグが無いので、未処理の一覧に並びます。** 書きかけを忘れません。
  一覧には「📝 下書き」の印が付きます。メール一覧でも、いちばん上に並びます。
  - その後（2026-10-19）: 未処理も `対応：未処理` と書くようになり、下書きにも `対応：未処理` を書きます
    （`ext/comm/mail/compose.go` の `draftRecordBody`）。未処理の一覧に並ぶのは同じです。
- ⚠ **`返信元` は付けません。**（いまの名前は `親ページID`。2026-10-09 に改めた。下書きには今も付けません。）
  送る前から「この記録への返信」に並ぶと、出していない返信が、出したように見えてしまいます。
- **送ったら、送った日の控えを新しく作り、下書きはごみ箱へ入れます。**
  控えの置き場は、送った月です。下書きの月ではありません。
- ⚠ **書けない下書きと、エディタで開いている下書きからは、1通も送りません。**
  送ってから「片付けられない」と分かっても、出たメールは戻せないからです。
  - その後（2026-10-12）: ブラウザは編集権を取らなくなりました。
    いま「開いている」と見なすのは、道具が `/api/lock` で握っているときだけです（`ext/comm/mail/reply.go` のコメント）。
- ⚠ **`下書き` のタグが無いページは、下書きとして書き換えません。**
  この口で、任意のページを上書きさせないためです。
- ⚠ `<pre>` の直後の改行は、HTML として読むと1つ落ちます。
  `<pre>` は、書かれた形のまま見せるための HTML の要素です。
  空行で始まる本文（返信の初期値）が、開き直すたびに詰まらないよう、保存のときに改行を1つ補います。

### 2.3 署名は連絡帳の拡張へ

メールの署名は、返信にも新しいメールにも要る**共通の道具**です。
そこで、署名の読み方（節の中身を行にする処理）を、東邦の拡張から連絡帳の拡張へ移しました。
開発方針 §0 の「共通に使えるものを拡張に閉じ込めない」に当たります。

- 入れるのは、**ログイン名と同じ題の連絡帳の人のページ**にある「メールの署名」です。
  09-22 の差出人の初期値と、同じ当て方です。
- 発注書の署名（紙に刷る差出人）は、東邦の拡張に残ります。
- 実装: `ext/comm/contacts/signature.go`

## 3. 変えていないこと

- **発注書は、送る直前に PDF を作り直します**（09-22 のまま）。
  「表示中の最新のPDFを送る」（C4・09-24 決定）は、再送とキャンセルの仕事で扱います
  （[【要求】発注フォルダ](../拡張/東邦/【要求】部材発注フォルダ.md)「発注書の再送とキャンセル」）。
  - その後（2026-10-14）: 部材発注書は、送る直前に作り直さず、ページに表示している PDF を添えるようにしました。
    まだ PDF が無いときだけ、送るときに作ります（`ext/toho/order_mail.go`。[【要求】通信拡張.md](../拡張/通信/【要求】通信拡張.md) §5a の「⚠ いま」）。
    見積書・部材見積依頼書は、いまも送る瞬間に作ります。
- 「FAXで送った」「手渡した」のボタン。人が押したことが、そのまま事実です。

## 4. まだのもの

- **メールの表示の部品**
  - ヘッダ・本文・添付・前後の鎖を、1つの部品にします。
    「前後の鎖」は、やりとりの前のメールと後のメールへのつながりのことです。
  - 通信記録のページでも、メール一覧でも、受注ページのような別のページの中でも、同じ見た目にします。
  - **どこに埋めたいか**を、利用者に聞いてから作ります。
- **FAX**
  - 送る欄の「送り先の道」を差し替えます。宛先は FAX 番号で、添付は PDF だけです。
  - 用件（初期値と前後の仕事）は道に依らないので、そのまま使えます。
  - FAX サーバーの機械が整ってから作ります（`ext/comm/fax`）。
- **下書きを捨てるボタン**。いまは、ページを消します（🗑）。
