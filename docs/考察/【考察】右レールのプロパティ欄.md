# 【考察】右レールのプロパティ欄

> 2026-10-02 に起こした。利用者が加工製品ページに Excel の表を貼り、「問題ありませんか？」と聞いたのが始まり。
> **コアの話**（エディタ・業務の語を持たない——開発方針 §0）。**未決**——§5 の「聞くこと」を利用者が決める。

## 1. 発端

> 「加工製品ページにExcelから表を貼り付けたら普通に表が保存されました。…問題ありませんか？」
> （筆者が「1行目が見出しでない・キャプションが無い・div と列の幅の情報が残る」と答え、貼ったときに整えるかを聞いたら）
> 「整えますが、一行目を見出しにするかなどは人が決めたいです。右のレールにプロパティー欄を作って、設定できるようにしては
> どうでしょう？表以外もです。検討してみてください」——利用者（2026-10-02）

## 2. いま（2026-10-02・事実）

**Excel の表を貼ると**（ブラウザの既定の貼り付け——`assets/app.js` の `paste` はファイル・画像と、タグの中の文字だけを横取りする）:

- 表が見えない `<div>` に包まれる。
- `<colgroup><col/>…</colgroup>`（Excel の列の幅の名残・幅の値はサニタイズで落ちる）が残る。
- **1行目も `<td>`**（見出し `<th>` にならない）。w-cms は見出しの表示文字を列の名前（鍵）に使うので、列の型・幅・折り返しの
  決まりも、索引での列の読み方も効かない。
- **キャプションが無い**ので DB（表の写し・🔎 表を探す・集計）に入らない（キャプションのある表だけが入る——【要求】タグと表）。

**要素の設定を変える道具**は、いまは**浮くもの**ばかり:

| 道具 | 出る所 | できること |
|---|---|---|
| 文字の浮くツールバー（`#w-context-toolbar`） | 選んだ文字の近く | 太字など |
| 表の行・列の浮くツールバー（`#w-table-toolbar`） | キャレットのある行 | ＋行・↑↓・✕行・＋列・←→・✕列・⚙ 列の設定（型——`#w-col-popover`） |
| 定義リストの浮くツールバー（`#w-dl-toolbar`） | 同上 | 項目の追加など |
| ファイル表示の配線（`button.fv-wire` → `#w-fv-popover`） | ファイル表示の札 | 参照を貼る |
| 「⋯」のメニュー（10-01） | ファイル・写真の札 | 形式に合った操作 |

**右レール**（`aside.rail-right`）は**ページの**ことだけ——ページ情報（ID・親・QR）・権限・版の履歴。幅 300px。
⚠ 1100px より狭い画面では**ドロワー**（右から引き出す・普段は隠れている）。

## 3. 案——右レールに「プロパティ」の欄

**キャレットのある要素（ブロック）の設定を、右レールの欄に出して変えられるようにする。** ページ情報の上（または下）に
1枚足す。表に限らず、見出し・段落・ファイル表示・タグ（名前：値）・見出しの節・画像など、**いま選んでいるもの**ごとに中身が変わる。

| 選んでいるもの | 欄に出すもの（案） |
|---|---|
| 表 | **1行目を見出しにする**（チェック）・**キャプション**（表の名前——入れると DB に入る、と添える）・列ごとの見出しと型（いまの ⚙ を移す）・行と列の数 |
| 見出し | 段（見出し1〜3）・節で包む（見出しの節にする）か |
| ファイル表示 | 参照（いまの配線の窓）・ファイル名・開閉と縦横比の既定 |
| タグ（名前：値） | 名前ごとの型（設定の語彙から・読むだけ） |
| 画像 | 幅・説明（alt） |
| 段落・その他 | 要素の種類だけ（変えるものが無ければ「設定はありません」） |

- **閲覧モード**では読むだけ（何が選ばれているか・表が DB に入っているか）にするか、出さないか（§5 問い1）。
- **貼り付けで勝手に決めないこと**を守る——1行目を見出しにする・キャプションを付けるは**人がこの欄で選ぶ**。

**貼ったときに機械が整えるもの**（利用者:「整えます」——人の判断が要らない形だけ）:

- 表だけを包む `<div>` を外す。
- `<colgroup>`・`<col>` を外す（w-cms は列の幅を本文に持たない）。
- ⚠ 1行目・キャプション・空の行と列には**触らない**（人が欄で決める）。
- どこで整えるか: **貼った瞬間（画面）**——人が整った形をすぐ見られる。サーバーのサニタイズで落とす案は、許可リスト
  （【一覧】語彙 §1.1・本文サニタイズ設計 §5.4）を変えることになり、既に保存された本文にも効くので重い。

## 4. 考えておくこと

- **浮くツールバーとの関係**——表の行・列の操作は、キャレットのある行のそばにあるほうが速い（遠い右レールまで手を動かさない）。
  **行・列の操作は浮くまま、設定（見出し行・キャプション・列の型）は欄へ**が筆者の案。
- **狭い画面**——右レールはドロワーで普段は隠れている。欄を使うにはドロワーを開く手間が1つ増える。スマホでは浮くパネル
  （`placeFloating`）のほうが使いやすいかもしれない。
- **キャレットが無いとき**（何も選んでいない）——欄は「ページ」の設定（いまのページ情報）を出す、という統一もできる。
- **保存の仕方**——欄で変えたものは本文の書き換え（`<td>`→`<th>`・`<caption>` を足す）なので、いつもの自動保存に乗る。
  クロームではなく本文を変えるので、エディタの保存の道（`triggerAutoSave`）を通すこと。
- **機械が描く表**（鏡・`.vocab-chrome`）は設定を変えられない（保存されない）——欄は「機械が描く表です」とだけ出す。

## 5. 聞くこと（返事待ち）

1. **出す場面**——編集モードだけ / 閲覧モードでも読むだけで出す。
2. **置き場所**——右レールのいちばん上（ページ情報の上）/ ページ情報の下 / 開閉できる欄。
3. **表で最初に出すもの**——1行目を見出しにする・キャプション・列の型（⚙ を移す）・ほかに要るもの。
4. **浮くツールバーとの分担**——行・列の操作は浮くまま・設定は欄へ（筆者の案）/ 全部を欄へ。
5. **表以外の順番**——見出し・ファイル表示・タグ・画像のどれから。
6. **貼り付けで整える2つ**（div を外す・colgroup を外す）は先に作ってよいか（欄を待たずに）。
