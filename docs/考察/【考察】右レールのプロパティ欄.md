## 2. いま（2026-10-02・事実）

### Excel の表を貼るとどうなるか

貼り付けは、ブラウザの既定の動きに任せています。
`assets/app.js` の `paste` が横取りするのは、ファイル・画像と、タグの中の文字だけです。

そのため、Excel の表を貼ると次のようになります。

- 表が、見えない `<div>` に包まれます。
- `<colgroup><col/>…</colgroup>` が残ります。これは Excel の列の幅の名残です。
  幅の値は、サニタイズ（本文から、許していないタグや属性を落とす処理）で落ちます。
- **1行目も `<td>` です**（見出しの `<th>` になりません）。
  w-cms は、見出しの表示文字を列の名前（鍵）に使います。
  そのため、列の型・幅・折り返しの決まりも、索引（検索や集計のための DB）での列の読み方も効きません。
- **キャプション（表の題）がありません。** そのため、DB に入りません（表の写し・🔎 表を探す・集計のどれにも入りません）。
  DB に入るのは、キャプションのある表だけです（【要求】タグと表）。

### 要素の設定を変える道具

要素の設定を変える道具は、いまは**浮くもの**ばかりです。
「浮くもの」は、本文の上に重ねて出る、小さな帯や窓のことです。

| 道具 | 出る所 | できること |
|---|---|---|
| 文字の浮くツールバー（`#w-context-toolbar`） | 選んだ文字の近く | 太字など |
| 表の行・列の浮くツールバー（`#w-table-toolbar`） | キャレットのある行 | ＋行・↑↓・✕行・＋列・←→・✕列・⚙ 列の設定（型——`#w-col-popover`） |
| 定義リストの浮くツールバー（`#w-dl-toolbar`） | 同上 | 項目の追加など |
| ファイル表示の配線（`button.fv-wire` → `#w-fv-popover`） | ファイル表示の札 | 参照を貼る |
| 「⋯」のメニュー（10-01） | ファイル・写真の札 | 形式に合った操作 |

「キャレット」は、文字を打つ位置の印のことです。

### 右レール

右レール（`aside.rail-right`）は、**ページの**ことだけを出しています。

- 出しているのは、ページ情報（ID・親・QR）・権限・版の履歴です。
- 幅は 300px です。
- 1100px より狭い画面では、**ドロワー**になります。右から引き出す形で、普段は隠れています。

## 3. 案——右レールに「プロパティ」の欄

**キャレットのある要素（ブロック）の設定を、右レールの欄に出して変えられるようにします。**

- ページ情報の上（または下）に、欄を1枚足します。
- 表に限りません。見出し・段落・ファイル表示・タグ（名前：値）・見出しの節・画像など、
  **いま選んでいるもの**ごとに中身が変わります。

| 選んでいるもの | 欄に出すもの（案） |
|---|---|
| 表 | **1行目を見出しにする**（チェック）・**キャプション**（表の名前——入れると DB に入る、と添える）・列ごとの見出しと型（いまの ⚙ を移す）・行と列の数 |
| 見出し | 段（見出し1〜3）・節で包む（見出しの節にする）か |
| ファイル表示 | 参照（いまの配線の窓）・ファイル名・開閉と縦横比の既定 |
| タグ（名前：値） | 名前ごとの型（設定の語彙から・読むだけ） |
| 画像 | 幅・説明（alt） |
| 段落・その他 | 要素の種類だけ（変えるものが無ければ「設定はありません」） |

この欄について、次の2つを添えます。

- 設定を変えられるのは、**書ける形**のときです。
  **閲覧モード**では、読むだけにするか、出さないかのどちらかです（§5 問い1）。
  読むだけにするなら、何が選ばれているか・表が DB に入っているかを見せます。
- **貼り付けで勝手に決めないこと**を守ります。
  1行目を見出しにする・キャプションを付ける、の2つは**人がこの欄で選びます**。

### 貼ったときに機械が整えるもの

利用者の「整えます」に当たる部分です。人の判断が要らない形だけを整えます。

- 表だけを包む `<div>` を外します。
- `<colgroup>`・`<col>` を外します（w-cms は、列の幅を本文に持ちません）。
- 1行目・キャプション・空の行と列には**触りません**（人が欄で決めます）。

どこで整えるかは、**貼った瞬間（画面）**です。人が、整った形をすぐ見られます。

サーバーのサニタイズで落とす案は、重くなります。
許可リスト（【一覧】語彙 §1.1・本文サニタイズ設計 §5.4）を変えることになり、既に保存された本文にも効くためです。

## 4. 考えておくこと

- **浮くツールバーとの関係**
  - 表の行・列の操作は、キャレットのある行のそばにあるほうが速いです（遠い右レールまで手を動かさずに済みます）。
  - 筆者の案は、**行・列の操作は浮くまま、設定（見出し行・キャプション・列の型）は欄へ**です。
- **狭い画面**
  - 右レールはドロワーで、普段は隠れています。欄を使うには、ドロワーを開く手間が1つ増えます。
  - スマホでは、浮くパネル（`placeFloating`）のほうが使いやすいかもしれません。
- **キャレットが無いとき**（何も選んでいないとき）
  - 欄は「ページ」の設定（いまのページ情報）を出す、という統一もできます。
- **保存の仕方**
  - 欄で変えたものは、本文の書き換えです（`<td>`→`<th>`・`<caption>` を足す）。だから、いつもの自動保存に乗ります。
  - クローム（画面の飾り付けで、保存されない部分）ではなく本文を変えます。
    エディタの保存の道（`triggerAutoSave`）を通すこと。
- **機械が描く表**（鏡・`.vocab-chrome`）
  - 「鏡」は、ページを表示するときにサーバーが描き足す部分です。保存されないので、設定を変えられません。
  - 欄には「機械が描く表です」とだけ出します。

## 5. 聞くこと（返事待ち）

利用者に決めてもらうことは、次の6つです。

1. **出す場面**: 書ける形のときだけにするか、閲覧モードでも読むだけで出すか。
   （はじめは「編集モードだけにするか」と書いていました。2026-10-12 に編集モードをやめたので、言い直しました。問いの中身は同じです。）
2. **置き場所**: 右レールのいちばん上（ページ情報の上）か、ページ情報の下か、開閉できる欄か。
3. **表で最初に出すもの**: 1行目を見出しにする・キャプション・列の型（⚙ を移す）。ほかに要るものがあるか。
4. **浮くツールバーとの分担**: 行・列の操作は浮くまま、設定は欄へ移すか（筆者の案）。それとも、全部を欄へ移すか。
5. **表以外の順番**: 見出し・ファイル表示・タグ・画像の、どれから作るか。
6. **貼り付けで整える2つ**（div を外す・colgroup を外す）は、欄を待たずに先に作ってよいか。
