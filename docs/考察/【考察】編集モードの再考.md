# 【考察】編集モードの再考

> 状態: **検討中**（2026-10-09 に起こした・まだ何も決めていない）。
> 正本の候補は [【要求】ページとエディタ.md](../【要求】ページとエディタ.md)。ロックの経緯は

## 1. 発端

メールのページの「対応: 未処理・済・不要」の札をきっかけに、利用者から2つの問いが出た。

> 「メールページには、「対応」未処理、済、不要というタグ風のものがあるのですが、これもタグそのものにしては」
> 「タグにはコンボボックスで候補を出す設定が無かったでしょうか？」——利用者（2026-10-09）

決まったことは2つ（【要求】通信拡張 §4 の下書き）:

- タグの値の候補を、編集モードで enum のタグ全部に出す。同じ日に作った（【要求】タグと表 §11）。
- `対応` のタグが無い記録に `対応：未処理` を書き足す。

未決は**値の替え方**。筆者は次の3つを挙げた。

- 閲覧モードでも押して替える。
- 編集モードだけで替える。
- いまの札も残す。

利用者の答えはこうだった。

> 「せっかくですから、編集モードについて再考察しましょう」——利用者（2026-10-09）

いまの札は閲覧モードで1回押せば替わり、編集権も要らない。札を本物のタグにすると、タグの値を替えるには編集モードに入ることになる。
問いは「対応」1つでは終わらない。**値を1つ替えるために、モードを替えて編集権を取るのが正しいのか**、という問いになる。

## 2. いまの形（2026-10-09 の実装・事実だけ）

**モードは2つ**です。閲覧が既定で、右上のトグルで編集へ入ります（`assets/app.js` の `onModeToggle`・`enterEditMode`・`applyMode`）。

- **編集に入ると**、ページ単位の編集権を取ります（`POST /api/lock`）。
  - 本文は最新に載せ直し、保持者として SSE をつなぎます。
  - 誰かが持っていれば 423 になり、「空き次第このまま自動で編集を開始します」と待ちます。
  - 待っている人が来ると、2分の猶予で持ち主から明け渡されます。持ち主の接続が切れていれば、すぐに明け渡されます。
  - 待つ人がいなければ、編集権に期限はありません（`internal/cms/editlock/lock.go`）。
- **編集から出ると**、書きかけの保存を流し切ってから編集権を返します。
- **保存**:
  - 1.5秒止まったときと、本文から出たときに保存します。
  - ブロック1つだけが変わったときは `/api/save-block`、それ以外は `/api/save` で全体を保存します。
  - どちらも編集権のしるし（トークン）が要ります。ロックの無いページはしるし無しでも通ります。
- **閲覧モードのまま本文を書く口が多くあります**（14種ほど）。たとえば次のものです。
  - 対応の札
  - 発注部材表・発注書を作る
  - 整理
  - 見積依頼書を作る
  - 連絡帳の登録
  - 図面の改定
  - 行の状態
  - 表に行を足す
  - メールの下書き

  関門はどれも「**誰かがエディタを開いていれば断る**」です（`editlock.RefuseWhileEditing`・`Locks.EditorOpen`）。
  ⚠ **自分が開いていても断ります**。そのため業務のボタンの多くは、閲覧モードでだけ押せます。
- **編集モードだけにあるもの**:
  - 書けること（contenteditable）
  - スラッシュメニュー
  - ブロックの ⠿・🗑・＋
  - 帯（B I U・¶ H1 H2 H3・＋・↶ ↷）
  - 選択肢のメニュー（表のセル・10-09 からタグの値も）
  - アンドゥ・リドゥ（編集モードのあいだだけ）
  - 子ページを作る・このページを削除
- **閲覧モードだけにあるもの**:
  - 表の並べ替え
  - 見出しで畳む
  - カルーセルを1枚ずつ見せる
  - 画像の拡大表示
  - 機械向けのタグを「▸ 詳細」へ畳む
  - ほかの人の書き込みの知らせ
  - 業務のボタンの多く（解析・整理・対応・返信・印刷 など）

  ⚠ **編集に入ると見た目が変わります**——並べ替えと畳みが外れ、カルーセルは枠になり、タグは全部出ます。
- ⚠ コードのコメントの食い違い（直していない）: `app.js` の `onModeToggle` の上のコメントには「status を10秒ポーリング」とありますが、
  実装は SSE です。

## 3. いまの形で起きていること

| | 何が起きるか | 例 |
|---|---|---|
| a | **値を1つ替えるのに、モードを替えて編集権を取る**——その手間を避けるために、場面ごとに専用の札やボタンを作ってきた（タグに似た別物が増える） | 対応の札・行の状態のボタン（発注明細）・「✓ 回答を記録」 |
| b | 業務のボタンは閲覧モードにしか無く、編集モードでは自分の編集権で断られる——**直してはボタンを押す作業で、モードを行き来する** | 発注部材表を直して「発注書を作る」 |
| c | 編集権は**ページに1人**——2人が同じページの別の場所を直せない（片方が待つ） | 受注フォルダ・発注のページ |
| d | **閲覧と編集で見た目が変わる**——並べ替えた表・畳んだ見出しが編集に入ると元に戻る | 長い加工製品ページ |
| e | スマホでは、帯とキーボードで書く場所が狭い（10-07 に帯を上へ移した） | — |

## 4. 案

### A. モードは残し、閲覧モードの「小さな書き込み」を型で一般化する（筆者の推し）

閲覧モードで、**選択肢の決まった値**（enum のタグ・表のセル。のちに bool・日付も）を押すと、選択肢が出て1回で替わる。

- サーバーには「1つの値を書く」口を1つ置く（コア・設定の語彙の選択肢に無い値は断る）。
- 関門は業務のボタンと同じ「誰かが開いていれば断る」。
- 値の変更は版に残す。
- **対応の札はこれに置き換わる**（`対応：未処理` を押すと3つ出る）。
  発注明細の状態・見積依頼明細の状態のような、場面ごとの札も同じ道に寄せられる。
- モードは「**文章と形を書く**」ためのものになる。値を替えるだけならモードに入らない。
- 良いところ:
  - 発端の問い（a）がいちばん小さい変更で片付く。
  - 業務の札の作り方が1つになる（語彙に選択肢を書けば、どのタグ・どの列でも押せる——コアと拡張の線にも合う）。
  - ロック・保存の仕組みは今のまま。
- 弱いところ:
  - b・c・d は残る。
  - 「閲覧モードでも書ける所がある」ので、何が押せるかを見た目で示す必要がある。
  - 1回押すたびに版が1つ増える。

### B. モードを無くす（いつでも書ける）

読んでいるページにそのまま書ける。打ち始めたときに編集権を取り、しばらく止まれば放す。

- 良いところ: a・b・d がまとめて消える（行き来が無い・見た目は1つ）。
- 弱いところ:
  - **読んでいるだけの人が誤って書き換える**——通信記録（届いたときのまま不変）・受注ページ（原本の写し）など、
    触ってほしくないページが多い。
  - 編集権を取るのが打ち始めなので、取れなかったとき（誰かが書いている）に、打った字をどうするかを決める必要がある。
  - 並べ替え・畳み・カルーセルと書くことの両立（並べ替えた表に書くと、本文のどの行か）。
  - スマホで読むたびにキーボードが出る。
  - 作り直しが大きい（編集権・保存・アンドゥの前提が全部変わる）。

### C. B に加えて、編集権をブロックごとにする

打っているブロックだけを握る。別の人は同じページの別のブロックを書ける。

- 下地はある——ブロックごとの保存（`/api/save-block`）と、変わったブロックだけを読み直す知らせ（10-07）。
- 良いところ: c まで消える。
- 弱いところ:
  - ブロックを足す・消す・並べ替えるといった形の変更は、ページの編集権が要る（2つの粒度が混ざる）。
  - 機械が本文を書く口（14種）の関門も、ブロックごとに考え直す必要がある。
  - 3案の中で最も大きい。

### 筆者の見立て

**A から始めるのがよい**と考えます。

- 発端（対応）を片付けつつ、業務の札をコアの仕組み1つに寄せられます。
- B・C へ進むときも、A の「1つの値を書く口」は使えます。B・C の弱いところ（誤って書き換える・形の変更）は、実際に困ってから
  測ったほうがよいと考えます。
- ただ、利用者がいちばん困っているのが b・c・d なら、話は B・C からです。

## 5. 聞くこと

1. **いちばん困っていることはどれか**——次の4つのうちどれでしょうか（§3）。
   - a: 値を1つ替えるのにモードを替える。
   - b: 直してからボタンを押すたびにモードを行き来する。
   - c: 2人が同じページを直せない。
   - d: 編集に入ると見た目が変わる。
2. **閲覧モードで押して替えてよいものの範囲**——次のどこまでにするか。
   - enum のタグだけ
   - 表のセルの enum も
   - 日付・数も（数は打つことになる）
3. **閲覧で書けてはいけないページ**があるか——通信記録（届いたまま不変）・受注ページの原本の写しなど。
   - 対応のように、通信記録にも「人の印」は書く。そのため、ページ単位ではなく**タグ・列ごと**に決める形もある。
4. **対応の札**——A なら、`対応：未処理` のタグの値を押すと3つ出る形に置き換えてよいか（札は無くす）。
5. B・C を考えるなら: 読んでいるだけで書ける状態をどう見分けるか（例: 字の上に乗ると枠が出る・長押し・ダブルクリック）。
