## 2. いまの形（2026-10-09 の実装・事実だけ）

この節は、2026-10-09 時点の形です。2026-10-12 に作り直したあとの形は、§7 にあります。

**モードは2つ**です。閲覧が既定で、右上のトグルで編集へ入ります（`assets/app.js` の `onModeToggle`・`enterEditMode`・`applyMode`）。

- **編集に入ると**、ページ単位の編集権を取ります（`POST /api/lock`）。
  - 本文は最新に載せ直し、保持者として SSE をつなぎます。
  - 誰かが持っていれば 423 になり、「空き次第このまま自動で編集を開始します」と待ちます。
  - 待っている人が来ると、2分の猶予で持ち主から明け渡されます。持ち主の接続が切れていれば、すぐに明け渡されます。
  - 待つ人がいなければ、編集権に期限はありません（`internal/cms/editlock/lock.go`）。
- **編集から出ると**、書きかけの保存を流し切ってから編集権を返します。
- **保存**:
  - 1.5秒止まったときと、本文から出たときに保存します。
  - ブロック1つだけが変わったときは `/api/save-block`、それ以外は `/api/save` で全体を保存します。
  - どちらも編集権のしるし（トークン）が要ります。ロックの無いページはしるし無しでも通ります。
- **閲覧モードのまま本文を書く API が多くあります**（14種ほど）。たとえば次のものです。
  - 対応の札
  - 発注部材表・発注書を作る
  - 整理
  - 見積依頼書を作る
  - 連絡帳の登録
  - 図面の改定
  - 行の状態
  - 表に行を足す
  - メールの下書き

  関門はどれも「**誰かがエディタを開いていれば断る**」です（`editlock.RefuseWhileEditing`・`Locks.EditorOpen`）。
  **自分が開いていても断ります**。そのため業務のボタンの多くは、閲覧モードでだけ押せます。
- **編集モードだけにあるもの**:
  - 書けること（contenteditable）
  - スラッシュメニュー
  - ブロックの ⠿・🗑・＋
  - 帯（B I U・¶ H1 H2 H3・＋・↶ ↷）
  - 選択肢のメニュー（表のセル・10-09 からタグの値も）
  - アンドゥ・リドゥ（編集モードのあいだだけ）
  - 子ページを作る・このページを削除
- **閲覧モードだけにあるもの**:
  - 表の並べ替え
  - 見出しで畳む
  - カルーセルを1枚ずつ見せる
  - 画像の拡大表示
  - 機械向けのタグを「▸ 詳細」へ畳む
  - ほかの人の書き込みの通知
  - 業務のボタンの多く（解析・整理・対応・返信・印刷 など）

  **編集に入ると見た目が変わります。** 並べ替えと畳みが外れ、カルーセルは枠になり、タグは全部出ます。
- コードのコメントの食い違い（直していない）: `app.js` の `onModeToggle` の上のコメントには「status を10秒ポーリング」とありますが、
  実装は SSE です。
  - → その後: このコメントは、2026-10-12 に編集モードをやめたとき（`e1d1831`）に消えました。

## 3. いまの形で起きていること

| | 何が起きるか | 例 |
|---|---|---|
| a | **値を1つ替えるのに、モードを替えて編集権を取る**——その手間を避けるために、場面ごとに専用の札やボタンを作ってきた（タグに似た別物が増える） | 対応の札・行の状態のボタン（発注明細）・「✓ 回答を記録」 |
| b | 業務のボタンは閲覧モードにしか無く、編集モードでは自分の編集権で断られる——**直してはボタンを押す作業で、モードを行き来する** | 発注部材表を直して「発注書を作る」 |
| c | 編集権は**ページに1人**——2人が同じページの別の場所を直せない（片方が待つ） | 受注フォルダ・発注のページ |
| d | **閲覧と編集で見た目が変わる**——並べ替えた表・畳んだ見出しが編集に入ると元に戻る | 長い加工製品ページ |
| e | スマホでは、帯とキーボードで書く場所が狭い（10-07 に帯を上へ移した） | — |

## 4. 案

### A. モードは残し、閲覧モードの「小さな書き込み」を型で一般化する（筆者の推し）

閲覧モードで、**選択肢の決まった値**を押すと、選択肢が出て、1回で替わります。
選択肢の決まった値とは、enum のタグ・表のセルのことです（のちに bool・日付も）。

- サーバーには、「1つの値を書く」API を1つ置きます（コアに置きます。設定の語彙の選択肢に無い値は断ります）。
- 関門は、業務のボタンと同じ「誰かが開いていれば断る」です。
- 値の変更は、版に残します。
- **対応の札はこれに置き換わります**（`対応：未処理` を押すと3つ出ます）。
  発注明細の状態・見積依頼明細の状態のような、場面ごとの札も、同じ道に寄せられます。
- モードは「**文章と形を書く**」ためのものになります。値を替えるだけなら、モードに入りません。
- 良いところ:
  - 発端の問い（a）が、いちばん小さい変更で片付きます。
  - 業務の札の作り方が1つになります。
    語彙に選択肢を書けば、どのタグ・どの列でも押せます。コアと拡張の線にも合います。
  - ロック・保存の仕組みは、今のままです。
- 弱いところ:
  - b・c・d は残ります。
  - 「閲覧モードでも書ける所がある」ので、何が押せるかを、見た目で示す必要があります。
  - 1回押すたびに、版が1つ増えます。

### B. モードを無くす（いつでも書ける）

読んでいるページに、そのまま書けます。打ち始めたときに編集権を取り、しばらく止まれば放します。

- 良いところ: a・b・d がまとめて消えます（行き来が無い・見た目は1つ）。
- 弱いところ:
  - **読んでいるだけの人が誤って書き換える**。
    通信記録（届いたときのまま不変）・受注ページ（原本の写し）など、触ってほしくないページが多くあります。
  - 編集権を取るのが、打ち始めです。
    取れなかったとき（誰かが書いている）に、打った字をどうするかを決める必要があります。
  - 並べ替え・畳み・カルーセルと、書くことの両立（並べ替えた表に書くと、本文のどの行か）。
  - スマホで、読むたびにキーボードが出ます。
  - 作り直しが大きくなります（編集権・保存・アンドゥの前提が、全部変わります）。

### C. B に加えて、編集権をブロックごとにする

打っているブロックだけを握ります。別の人は、同じページの別のブロックを書けます。

- 下地はあります。ブロックごとの保存（`/api/save-block`）と、変わったブロックだけを読み直す通知（10-07）です。
- 良いところ: c まで消えます。
- 弱いところ:
  - ブロックを足す・消す・並べ替えるといった形の変更は、ページの編集権が要ります（2つの粒度が混ざります）。
  - 機械が本文を書く API（14種）の関門も、ブロックごとに考え直す必要があります。
  - 3案の中で、最も大きい作り直しです。

### 筆者の見立て

**A から始めるのがよい**と考えます。

- 発端（対応）を片付けつつ、業務の札をコアの仕組み1つに寄せられます。
- B・C へ進むときも、A の「1つの値を書く API」は使えます。B・C の弱いところ（誤って書き換える・形の変更）は、実際に困ってから
  測ったほうがよいと考えます。
- ただ、利用者がいちばん困っているのが b・c・d なら、話は B・C からです。

## 5. 聞くこと

1. **いちばん困っていることはどれか**——次の4つのうちどれでしょうか（§3）。
   - a: 値を1つ替えるのにモードを替える。
   - b: 直してからボタンを押すたびにモードを行き来する。
   - c: 2人が同じページを直せない。
   - d: 編集に入ると見た目が変わる。
2. **閲覧モードで押して替えてよいものの範囲**——次のどこまでにするか。
   - enum のタグだけ
   - 表のセルの enum も
   - 日付・数も（数は打つことになる）
3. **閲覧で書けてはいけないページ**があるか——通信記録（届いたまま不変）・受注ページの原本の写しなど。
   - 対応のように、通信記録にも「人の印」は書く。そのため、ページ単位ではなく**タグ・列ごと**に決める形もある。
4. **対応の札**——A なら、`対応：未処理` のタグの値を押すと3つ出る形に置き換えてよいか（札は無くす）。
5. B・C を考えるなら: 読んでいるだけで書ける状態をどう見分けるか（例: 字の上に乗ると枠が出る・長押し・ダブルクリック）。

## 6. 決めたこと（2026-10-12 利用者）

> 2026-10-12 利用者:「排他のために編集モードを設けたが、今後は編集モードの代わりに、閲覧に邪魔なものを表示しない目的で、閲覧モードを設けることにします。そして、ブロック単位の保護に変更し、保護の内容は編集中の同ブロックを同時に編集したものが居たら、警告してマージできるように両方表示します。」

### 筆者の読み

- **モードの意味が入れ替わります。**
  - いまの編集モードは、「編集権を取る」ためのものです（排他）。
  - これからは、**ページはふだん書ける**形です。モードは**見た目だけ**になります。
  - 「閲覧モード」は、読むのに邪魔なもの（⠿ 🗑 ＋・帯・機械向けのタグなど）を出さないためのものです。
  - モードを替えても、編集権は取りません。
- **ページ単位の悲観ロック（編集権）をやめます。**
  - 守りは**ブロック単位**です。しかも、**先に握る形ではありません**。
  - 同じブロックを同時に書いた人がいたら、**警告し、両方の版を並べてマージできるようにします**（楽観的な守り）。
  - §4 の案C（ブロックごとの編集権）とも違います。握らないので、待つ人が出ません（§3 の c が消えます）。
- これで、§3 の a〜d は、次のようになる見込みです。
  - a: 値を替えるのに、モードを替えません（ふだん書けるので）。
  - b: 業務のボタンの「誰かが開いていれば断る」が、意味を失います（開いている＝書いている、ではなくなります）。
    関門の作り直しが要ります。
  - c: 2人が、同じページの別のブロックを同時に書けます。同じブロックだけが、警告とマージになります。
  - d: 見た目は、閲覧モードと書く形の2つのままです。並べ替え・畳みをどちらに置くかは詰めます。

### 下地（10-12 に確かめた事実）

- **ブロックごとの保存** `/api/save-block`（`internal/cms/handler_save.go`）は、`page_id`・`block_id`・`html`・`token` だけを送ります。
  - **どの版から書き始めたか（元の版）を送っていない**ので、いまは同時の書き込みを見分けられません。
  - 元の版（ブロックの中身の指紋など）を足し、サーバーで「いまのブロックが元の版のままか」を比べるのが、芯になります。
    「指紋」は、中身から計算する短い値です。中身が同じなら、同じ値になります。
- **ほかの人の書き込みの通知**（`internal/cms/page_events.go`・SSE・10-07）は、本文が変わると知らせます。
  画面は、**変わったブロックだけ**を差し替えます。
  - ぶつかったことを、書いている最中に知らせる道は、これに乗ります。
- **編集権を前提にした API**
  - 編集権の API（`internal/cms/editlock/`）があります。
  - そのほかに、「誰かが開いていれば断る」関門を使う API が、22 ファイルあります
    （`RefuseWhileEditing`・`Locks.EditorOpen`・`RequireEditLock`）。
    業務のボタン・権限・親の付け替え・添付・削除・版を戻す・整理などです。
  - `editlock` を使うファイルは、全部で 25 です。
  - どれも、考え直しが要ります。

### このあと聞くこと（1つずつ・答えで次が変わる順）

#### 問い1: ページを開いたときの形と、閲覧モードで字を打てるか

**問い**:

- 書ける形で開くか、閲覧モードで開くか（端末ごと・スマホは別か）。
- 閲覧モードは、読むだけ（打てない）か、飾りが消えるだけ（打てる）か。

→ ✅ **2026-10-12 決まった**（利用者:「お勧め通りで」）

- **閲覧モードは読むだけ（打てない）**です。
- 表の並べ替え・見出しで畳む・カルーセル・画像の拡大は、閲覧モードに置きます。
- 書ける形との切り替えに、編集権は要りません（一瞬で替わります）。
- **開いたときの形は、その端末に憶えます**（最後に使った形）。
- 初めて開くときは、パソコンは書ける形・スマホは閲覧モードです（読むたびにキーボードと帯が出ないようにするためです）。

#### 問い2: 誤って書き換えてほしくないページ

**問い**: 通信記録（届いたまま不変）・受注ページの原本の写しなど。
ふだん書ける形になると、読んでいるだけの人が触れてしまいます。

→ ✅ **2026-10-12 決まった**（利用者:「Aで良いです。その分、アンドゥ・リドゥが重要になると思う」）

- **何もしません**（閲覧モードで読めばよい・触っても戻せる）。
  利用者の言う「A」は、この「何もしない」案です。筆者が挙げた3つの案の1つ目でした（B・C は次の行です）。
- 置き場ごとに閲覧で開く（B）・ブロックごとに書けない（C）は、作りません。
- そのかわり、**戻す道が守りになります**。

筆者が書き留めたこと（10-12 に今の作りを見て）:

- **アンドゥ**
  - いまのアンドゥは、**ページ全体の写し**（上の段のブロックの並び）を積み、戻すときにそれへ差し替えます
    （`assets/app.js`「区切り（チェックポイント）」・`pushState`）。履歴は、編集モードのあいだだけです。
  - **ほかの人が同じページの別のブロックを書く形では、このままだと戻したときに相手の書き込みまで巻き戻す**ことになります。
  - アンドゥは、**自分の変更だけ**（自分が変えたブロックの前と後）を積む必要があります。
    戻すときに相手がそのブロックを書き換えていたら、ぶつかったときと同じく、両方を並べる形にします。
- **版**
  - 版の「この版に戻す」も、ページ全体を戻します。同じ理由で、相手の書き込みを消します。
  - 「このブロックだけ戻す」が要るかもしれません。

### 試験の約束（2026-10-12 利用者:「込み入ってるのでテストは十分にお願いします」）

作り直しは、次の試験が揃って緑になるまで「できた」と言いません。
「緑になる」は、試験が全部通ることです。

- **サーバーの合わせ方（Go）**
  - 書き始めたときの本文・自分の変更・相手の変更の組を表にして、全部の組み合わせを試します。
    - 違うブロックを変えた
    - 同じブロックを変えた（ぶつかる）
    - 表の違うセル・同じセル・行や列を足した消した
    - 足した・消した・動かした・並べ替えた の組み合わせ
    - 消したブロックを書いていた
  - 期待する結果（合わさる・両方を返す）を、1行ずつ書きます。

  - 人の保存と業務のボタン（`RewriteBody`）を、同じページへ同時に何十回も流します。
  - **どの書き込みも消えない**ことを確かめます（ページごとの書き込みのロック）。
- **画面（E2E）**
  - ブラウザを2つ（2人）立ち上げ、同じページで次を確かめます。

    - 同じブロックを書く（その場で警告・相手の版が上に出る・「これで決める」「相手の版にする」「自分の版にする」）

    - 閲覧モードでは打てない・開いたときの形を端末に憶える
- **変異試験**（コードをわざと壊して、試験が落ちるかを見ること）
