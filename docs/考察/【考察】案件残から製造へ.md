## 2. いまの形（2026-10-21）

- 案件残表（案件のトップ）の右の方に「製造」の欄があり、表の上に「🏭 選んだ行で製造開始」があります。
  押すと、今回作る数を直す欄が開き、「🏭 製造を始める」で**すぐに製造ページを作ります**（`/api/mfg/new`）。1つの製造は1社です。
- 案件残表の列は、装置名・弊社品番・品番・品名・残・数量・出荷済数量・**状態**・**材料発注**・**製造完了**・**納品書発行**・**請求書発行**・備考・まだ無いもの・案件・製造・納品 です（`ext/toho/backlog.go`）。
  製造完了・納品書発行・請求書発行は、もう鏡です（ほかの書類から数える。人は書かない）。状態と材料発注は、人が選ぶ印です。
- 「製造」の置き場には、臨時部材表・**必要部材表**・手配不要表・未発注の部材発注書・未送付の見積書・見積書を作る、が並んでいます。
- 二重に発注しない仕組みは、部材発注明細表の行の「案件」の列（どの案件のためか）と、製造ページの「手配済み」の引き算です。
  案件明細表の側には、どの書類で発注・納品したかを書いていません。

## 3. 新しい流れ（筆者の読み）

1. **案件残表**: 先頭の列にチェックボックス。表の下に「製造」ボタン。
   チェックして押すと、その行が「製造」に入ります（**製造待ち**）。案件残表では、それと分かる形で見せます（問い1）。
2. **「製造」の置き場**: 製造に入った案件（製造待ち）の表を出します。先頭の列にチェックボックス、表の下に「開始」ボタン。
   チェックして「開始」を押すと、選んだ案件が**製造のひとまとまり**になります（いまの製造ページ。問い3）。
3. **取り消し**: 開始した案件は、いつでも1つずつ取り消せます（問い4）。
4. **案件明細表に、書類の場所を書く**: 部材発注明細・納品明細などの行を、`ページID-ブロックID` の形で、案件明細表の行に書きます。
   取り消しても、どこで発注したかが残るので、もう一度製造に入れたときに二重に発注しません。
   部材発注書を作るときは、案件明細表のこの欄を見て、発注済みの部材を除きます。
5. **「製造」の置き場の必要部材表**はなくします。部材は、開始したまとまり（製造ページ）で集めます。

筆者が決めたこと（違えば直します）:

- 「案件」は、案件明細表の**行**のことと読みました（いまと同じく、行ごと・数ごとに製造へ入れる）。
- 書類の場所を書く列は、案件明細表の行に「部材発注」「納品書」の2つの列を足す形を考えています（請求書は納品書から辿れる）。
  1つの行に部材がいくつもあるので、1つのセルに `ページID-ブロックID` を「、」で並べます（参照の列。いまの `資料` の列と同じ書き方）。

## 4. 問い

1. 案件残表で「製造」を押した行は、どう見せるか。
   - 案A: 表に残し、打ち消し線を引く（残の数・案件残高には数える）。
   - 案B: 表から外し、表の下に「製造に入ったもの」として分けて並べる。
2. まとめる列（状態・材料発注・製造完了・納品書発行・請求書発行）を、どうするか。
   - 案A: 1つの「進み」の列にまとめ、自動で出す（製造待ち → 製造中 → 製造完了 → 納品済 → 請求済）。人は書かない。
   - 案B: 列を無くす。
3. 「開始」でできるまとまりは、いまの製造ページか。1つのまとまりに、客先の違う案件を入れてよいか。
4. 取り消した案件は、どこへ戻るか（「製造」の製造待ちの表か、案件残表か）。
   その製造ページで作った書類（部材発注書・納品書など）は、そのまま残してよいか。
5. 「製造」の置き場の臨時部材表・手配不要表も、要らなくなるか（どちらも必要部材表と組で使っていました）。

### §4 の答え（2026-10-21）

利用者は、問いの選択肢から選んで答えました。

1. 案件残表で製造に入った行は、**打ち消し線で残す**（残の数・案件残高には数える）。
2. 5つの列は、**「進み」の1列にまとめる**（製造待ち → 製造中 → 製造完了 → 納品済 → 請求済。自動で出し、人は書かない）。
3. 「開始」でできるまとまりは、**1社だけ**（いまの製造ページと同じ）。
4. 取り消した案件は、**製造待ちの表へ戻る**。
5. （臨時部材表・手配不要表は、まだ答えがありません。それまでは今のまま残し、必要部材表だけをなくします。）

あわせて、利用者がこう足しました。

> 2026-10-21 利用者:「製造フォルダの表に入った案件もキャンセルして案件フォルダに戻すことが出来ます。したがって各「案件明細表」にはこれまで発行した伝票の「ページID」や発注した部材の「ページID」が必要になります」

だから、行き来は次の3つの段になります。どの段からも、1つ前へ戻せます。

```
案件残表（案件）  ──「製造」──▶  製造待ちの表（「製造」）  ──「開始」──▶  製造ページ（1社のまとまり）
                 ◀─ 取り消し ─                          ◀─ 取り消し ─
```

戻しても、その行のために作った書類は残ります。だから、**案件明細表の行が、自分の書類の場所を持ちます**。

- 発行した伝票（納品書・請求書・見積書 など）の場所。
- 発注した部材（部材発注明細の行・部材見積依頼明細の行）の場所。
- 形は `ページID-ブロックID`（行の ID）です。1つのセルに、「、」で並べます。
- 部材発注書を作るときは、案件明細表のこの欄を見て、もう発注した部材を除きます（二重に発注しない）。

## 5. 作る順（筆者の案）

1. **案件残表**: 先頭にチェックボックス、表の下に「製造」ボタン。押した行は「製造」の製造待ちの表へ入り、案件残表では打ち消し線になる。5つの列を「進み」の1列に。
2. **製造待ちの表**（「製造」の置き場）: 先頭にチェックボックス、表の下に「開始」と「案件へ戻す」。「開始」で製造ページを作る（1社）。
3. **製造ページの取り消し**: 製造明細表の行ごとに「製造待ちへ戻す」。
4. **案件明細表に書類の場所**: 書類を作るたびに、その行の ID を案件明細表の行へ書く。部材発注書を作るときは、それを見て除く。
5. **必要部材表をなくす**（「製造」の置き場とテンプレートから。職場のデータは保存の口で、数える → 1枚 → 全部）。

## 6. 作ったもの（2026-10-21）

⚠ いま（`ext/toho/mfg_wait.go`・`ext/toho/backlog.go`）:

- **製造待ちの数は、案件明細表の行が持ちます**（列「製造待ち」・数）。別の表は持ちません。
  - 本文の表の先頭に、保存しないチェックの列を置くと、エディタの列の数え方とずれるおそれがあるためです。
    状態を案件明細の行に持たせると、製造待ちの表はサーバーが描くビューにでき、先頭にチェックを置けます。
  - 既にある案件ページ 52枚とテンプレート「案件ページ」には、道具で列を足しました（`デスクトップ\w-cms\道具\製造待ち_20261021\`・保存の口・版が残る）。
- **案件残表**:
  - 先頭の列は製造へ入れるチェックです（まだ製造に入っていない数がある行だけ・紙に出さない）。
  - 表の下に「🏭 製造」。押すと、選んだ行の、まだ製造に入っていない数（数量 − 製造ページに入れた数 − 製造待ち）を、案件明細の「製造待ち」へ書きます（`/api/mfg/wait`）。
  - 全部が製造に入った行（製造待ちか製造中）は、打ち消し線で残します（残の数・案件残高には数える）。
  - 状態・材料発注・製造完了・納品書発行・請求書発行の5列と「製造」の列は、**「進み」の1列**にまとめました。製造待ち N（「製造」へのリンク）・製造中（製造ページへのリンク）・製造完了・納品書・請求書を、あるものだけ並べます。何も無ければ「未着手」。人は書きません。
  - 人が付ける「完了」（もう案件残に出さない）は、案件ページの案件明細表の「状態」で付けます（案件残表からは付けられなくなりました）。
  - 古い「🏭 選んだ行で製造開始」は外しました（API `/api/mfg/new` は残っています）。
- **「製造」の置き場**: 製造待ちのビュー（印 `<section data-mirror="製造待ち">`）。製造待ちの行を客先ごとの表に並べます。
  - 先頭のチェックと「▶ 選んだ行で開始」で、製造ページを作ります（1社・`/api/mfg/start`）。製造待ちの欄は空に戻ります。
  - 「↩ 選んだ行を案件へ戻す」で、製造待ちの欄を空にします（`/api/mfg/unwait`）。
  - 職場の「製造」（/002025）とテンプレート「製造」に印を置き、最初の段落の案内を今の流れに替えました。
- **製造ページ**: 製造明細表の右に「取り消し」の列。「↩ 製造待ちへ」で、その行を製造明細から外し、数を案件明細の「製造待ち」へ戻します（`/api/mfg/back`）。
  - ⚠ この製造で納めた分がある行は、戻せません（ボタンも出しません）。戻すと、納めた分まで作り直すことになるためです。
  - 閉じた（記録へ移した）製造ページからは戻せません。
- **二重の発注**: 部材は、いまも案件ごとに引き算します（製造ページの「📦 この製造の部材を発注部材表へ」は、必要部材表と同じ「案件×加工製品」の残りを使う）。
  だから、取り消して別の製造で始め直しても、もう発注した部材は出てきません。
- 書けるかの確かめ: 製造待ちへ入れる・戻すは、その案件ページへの write を求めます。開始は「製造」への write も求めます（書類を作る API の直し・2026-10-21）。
- 見張りの試験: `ext/toho/mfg_wait_test.go`（わざと壊すと落ちることを3か所で確かめた）・E2E `e2e/verify-mfg-wait.js`（自分で作ったページの上で、①〜⑥を押して確かめた。古い `verify-mfg-new.js` は外した）。

## 7. 残り

- **作る順の4番**（案件明細表に書類の場所）: 筆者の案は、**保存する列ではなく、ほかの書類から数えて見せる欄（鏡）**にすることです。
  部材発注明細表の行は「案件」の列を、納品明細・請求明細の行は「案件」と品番を持っているので、案件明細の行ごとに、その書類の行を引けます。
  保存する列にすると、書類を消したり直したりしたときに、写しが古くなります。利用者の答えを待ちます。
- **作る順の5番**（必要部材表をなくす）: 臨時部材表の行は、必要部材表で選んで発注部材表へ入れるので、必要部材表をなくすと、臨時部材表から発注できなくなります。
  臨時部材表・手配不要表をどうするか（§4 の問い5）が決まってから、なくします。
