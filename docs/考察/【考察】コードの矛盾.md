# 【考察】コードの矛盾

> 2026-10-19 利用者:「終わったら、コードの矛盾を探して修正して下さい。全体を順にお願いします。朝までかかって大丈夫です」

2026-10-19 夜から 10-20 未明に、コード全体を10の分野に分けて読みました。
探したのは、コメントと振る舞いの食い違い、同じ規則の写しの食い違い、画面とサーバーの口の約束の食い違い、不具合になりうる形です。

途中で、利用者から「セッションのトークン使用量が上限に近づいているので、エージェントの数を絞ってください」と言われ、6つの分野は途中で切り上げました。
切り上げたのは、コアの前半・後半、認証と cmd と道具、東邦の解析と整理、東邦の見積、app.js の後半と管理画面です。この6つは、読み残しがあります。

## 1. 直したもの

コメントの食い違いは、各分野で直しました（振る舞いは変えていない）。

振る舞いの不具合は、次の10件を直しました。どれも番人の試験を足し、直す前の形に戻すと落ちることを確かめました。

1. 整理の図面改定・図面追加が、錠の外で読んだ合流先の本文から組んで書いていた。そのあいだのほかの人の保存が消えた（`revision.go`）。
2. 「装置のページへ」で図面を入れた装置のフォルダが加工製品と数えられ、その下の加工製品が整理の候補から消えていた（`product_list.go`）。職場では /001362 で起きていたはずです。
3. 客先＋品番で結ぶ候補に、旧版のページが入っていた（`product_customer.go`）。
4. 人が一度保存した（字下げされた）ページで、整理の書き戻しが黙って空振りし、社名のページの `連絡帳` のタグが整理のたびに増えていた（`filing.go`）。
5. 見積表の単価をテンプレートの式 `=ROUND(原価*(1+利益率/100))` で書くと、📌 で記録した直後なのに「⚠ 記録が計算表と合いません」と出た（`estimate.go`）。
6. 部材見積依頼書を作ったあとの片付けが、番号のずれた別の業者の見積依頼部材表を消すことがあった（`rfq_doc.go`）。
7. 請求済みの鍵に案件が入っておらず、同じ納品書の別の案件の同じ品番の行が、二度と請求書に出なかった（`invoice.go`）。
8. 一部の行だけ閉じた案件で、閉じた行のために買った分が在庫として別の案件に回っていた（`procure_ledger.go`）。
9. 必要部材表の納期を、畳まずに文字で比べて並べていた（`unordered.go`）。
10. 材料の最新単価で、部材発注日を畳まずに比べていた（`material_price.go`）。

## 2. 見つけたが、まだ直していないもの

重いものから並べます。「確かめた」は、係がコードを読んで確かめたものです。筆者はまだ自分では確かめ直していません。

### 2.1 データが消える・壊れるもの

- メールの下書きの保存（`ext/comm/mail/compose.go` の DraftSaveAPIHandler）は、送る欄の中身から本文を丸ごと組み直します。
  人が下書きのページに直に書いたもの（`対応` の値・足した段落）は、次に「📝 下書きに保存」を押すと消えます（確かめた）。
- 本文の ID の無いブロック（テンプレートから作ったページ）は、機械が書き換えると ID が変わります。
  そのブロックを書きかけていた人の保存が「相手が消した」のぶつかりになり、「残す」を選ぶと表が2つになります（確かめた・試験はまだ）。
- ページの属性のファイル（サイドカー）を書く口（並べ替え・付け替え・権限）は錠を取らず、`page.WriteSidecar` はフォルダを作り直します。
  削除と重なると、消したページが生き返ることがあります（確かめた・時間に左右される）。
- 2枚目の部材発注明細表の行のボタン（戻す・発注済にする）が、別の表の行に効きます（確かめた）。
- 手配不要表の「↩ 戻す」だけ、臨時部材表を同じページへ戻します。「製造」以外のページでは、戻した行が必要部材表に出ません（確かめた）。

### 2.2 守りの穴

- 本文の埋め込みの宛先の検査（`htmldoc/sanitize.go` の safeEmbedURL）を、スラッシュで始まらない相対の URL が通ります（いまは実害なし）。
- 前段のプロキシを信頼する決め方（`internal/auth/handlers.go` の isTrustedProxy）は、私設のアドレスを全部信頼します。LAN の端末が `X-Forwarded-For` で監査の接続元を偽れます。社外へ出す前に、信頼するアドレスを決める必要があります（利用者に決めてほしいこと）。
- 道具が残した編集ロックがあると、画面からの添付・削除・版の戻し・権限の変更が 409 で止まり続けます（`editlock.Locks.Validate`）。
- 部材見積依頼書を返事から作る口（RFQReplyMakeRFQAPIHandler）が、加工製品ページを読めるかを確かめていません。

### 2.3 数え方・見え方の食い違い

- 製造ページを記録へ移す条件が、まだ紙を作っていない請求書も「請求済み」と数えます（`mfg_close.go`）。
  発行した請求書だけにする直しは、既にある試験 `TestCloseFinishedMfgPagesOnInvoice` と合わなかったので戻しました。続きがあります。
- 製造ページの「納品」の欄が、見積の依頼の行にも出ます（押すと誤った断りになる）。
- 製造に入れられる数が、製造の外で納めた数（移行用の仮納品書など）を引きません。どう数えるかは利用者に確かめます。
- 閉じた製造ページが、途中のまま閉じても数を抱え続けます。
- 見積計算書のページで「📄 見積書に入れる」を開くと、客先が空になります（`estimate_doc.go`）。
- 返事の原本の候補に、読めない種類のファイル（xlsx）が出ます。手で書く返事ページを結ぶと、その表を明細へ写す道がありません。
- 同じロットに見積表が何枚もあるとき、赤字の警告はいちばん安い単価、製造ページの見積書は先に見つけた1枚を使います（利用者に確かめる）。
- 図面改定で、並べてある図面が全部旧版へ移ります（「あとから改定にする」は1枚ずつ）。意図かを利用者に確かめます。
- 「未分類へ戻す」（連絡先）と `addContactTags` の二重の確かめが、字下げのある本文で当たりません（`contacts_handler.go`）。
- メール一覧の「未処理」は、通信箱と違って向きで決めています（`assets/mails.js`）。
- パソコンから添えたファイルは 32MiB まで置けますが、送るときは合計 25MB で止まります。
- IMAP の取り込みだけ、大きさの上限がありません（利用者に決めてほしいこと）。
- `NormalizeCode` が全角のマイナス（U+2212）を畳みません（直したら DB の再構築が要る）。
- 式の表示の早道が、先頭の全角空白・NBSP を見落とします（`formulaCellRe`）。

### 2.4 画面の小さいもの

- 何も書いていないのに「未保存」と出ることがあります（MutationObserver が飾りだけの変化も拾う）。
- 管理画面が、ログインしていない人をログインへ送りません（`assets/admin.js`）。
- 製造ページの「📦」が、入らなかった行（skipped）を黙って捨てます。
- `assets/mails.js` が、断りの理由を `d.error` で読んでいます（サーバーは `message`）。
- ぶつかったときの相手の名前が出ません（`/api/sync` の応答に `by` が無い）。

### 2.5 道具

- `tools/templates.js` の export が `WCMS_DATA_DIR` を見ません。
- `tools/sample-data.js` が、置き場づくりの失敗（`success:false`）を見ません。
- 管理画面のグループの口が、失敗した追加も監査に残します。
