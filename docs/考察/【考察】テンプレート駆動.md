### 「テンプレート駆動」の意味

**「テンプレート駆動」の意味**は、利用者が 2026-09-27 に言い直しました。

> 人間が書き換えても機能して欲しいです。そのために、何かのタグを置くとそこが鏡になってほしいのです。

### ✅ B. テンプレート以下では鏡もボタンも働かない（2026-09-27 に実装）

**何が害になるのか**

- **見るだけの鏡は、描いても害はありません**。
  これは、利用者の問い「こう見えるとわかるだけで、何ら問題が無いように思う」への答えです。
- ⚠ **害があるのは、表示しているページへ書き込むボタン**です。次のボタンが当たります。

  1. 書いたもの（発注部材表・PDF）が、**そのテンプレートから作るページ全部へコピーされ**ます。

     エラーは出ません。発注漏れになります。

**どう止めたか**

- **描画**: `RenderComputedViews` は、テンプレート以下では鏡を描きません。
  - 鏡の印には、**名前だけの案内**を出します。
    「🪞 必要部材表——テンプレートの中では鏡を描きません（このテンプレートから作ったページで、ここに鏡が出ます）」
  - ほかの鏡（ファイル表示・表の足元のボタン）は、何もしません。
- **書き込み**: 東邦拡張の関門（`requireWritableIdle`）が、コアの `RefuseTemplateArea` で **409** を返します。
  409 は、「いまは受け付けられません」という断りの応答です。
  - 取りこぼしの受け皿として、コアの `RewriteBody` も `ErrTemplateArea` で断ります。
  - 呼び手は全部、業務のページを書く口です。
    テンプレートの中を書く正当な呼び手は無い、と 2026-09-27 に数えました。

### ✅ C. 「この位置に足す」を、人が置いた印・表の場所に従わせる（2026-09-27 に実装）

これは「最新の図面が上」という意味の規則で、位置の焼き込みではありません。

## 4a. D——機械が作るページもテンプレートを埋める（2026-09-27 夕・実装済み）

> 利用者:「Dの分についても、テンプレート駆動にしたいです」
> 「**テンプレートにはスラッシュメニューから表などの印を置き、コードはそれを埋めてはどうでしょう？問題になりそうなのは、繰り返しの場合だと思います**」
> 「**繰り返す数は、その場にならないとわからないからです**」

**形はテンプレート、値と数は機械**です。
テンプレートは「1つ分の形」を持ちます。機械は、その場で分かった数だけ繰り返します
（コアの `cms.PageDraft`・[page_template.go](../../internal/cms/page_template.go)）。

| 印（テンプレートに人が置くもの） | 機械がすること | 繰り返し |
|---|---|---|
| 題（h1） | 書き換える（題の完全一致が同一性の鍵なので、題は機械が決める） | — |
| 可変タグの `<dt>名前</dt>` | 名前で探して値を入れる。**値が空ならテンプレートの欄のまま** | 宛先が3人なら**同じ名前を3つに増やす** |
| キャプション付きの表（スラッシュメニューで挿す） | 見出しの行を「1行分の形」として、**見出しの言葉で列を合わせた**行を作る。見本の行は消す（0件なら残す） | 明細の数だけ行を作る |
| ファイル表示の印（`data-ref` が空のもの） | 配線する（原本PDF・図面） | — |
| **見出しの節**（`<section><h2>本文</h2>`）・畳める枠（`<details><summary>`） | 見出しを残して中身を入れ替える（メールの本文・添付の一覧・発注書の備考・読んだままの表） | 添付の数だけ段落を並べる |

### テンプレートに無いもの

**テンプレートに無いもの**をどうするかは、利用者が選びました。

- **機械が値を持つタグ・列がテンプレートに無ければ「足す」**。
  - タグは、可変タグの末尾に足します。列は、表の右端に足します。
  - 読み手（必要部材表・状態のボタン・重複検知のメッセージID）は、名前で探します。
    捨てると、機能が黙って壊れます。
  - 値が空なら、足しません。
- **中身を組むものの器は「見出しの節」**。
  - スラッシュメニューに「**見出しの節**」を足しました（見出しの言葉が名前になる）。
  - 受注ページの原本PDF・読んだままは、畳める枠の見出しも、同じ「名前の見える入れ物」として探します。
    09-21 に決めた「畳んでおく」（`<details>`）を崩さないためです。
- **値を入れる器（表・節）が無ければ作らずに断ります**（`cms.TemplateSlotError`・409）。
  - 位置の規則を、コードに戻さないためです。
  - 飾り（原本PDFの表示・読んだままの枠）は、無ければ出しません。

### テンプレートの題

**テンプレートの題**は、次の表のとおりです。
テンプレート置き場の下の葉で、置き場と同じ引き方をします。**無ければ作らない**のも同じです。

| 題 | 使うところ | 要る器 |
|---|---|---|
| 受注ページ | 発注書PDFの解析 | 表「受注明細」（原本PDFの印・「顧客の発注書（読んだまま）」の枠は任意） |
| 加工製品 | 図面PDFの解析 | 見出し「図面」の節・表「改訂明細」 |
| 発注書 | 発注部材表の「発注書ページを作る」 | 表「発注明細」・備考を書くなら見出し「備考」の節 |
| 通信記録（受信メール） | メールの取り込み | 見出し「添付ファイル」の節・本文があれば見出し「本文」の節 |
| 通信記録（送信メール） | 送信の控え | 見出し「本文」の節・添えたら「添付ファイル」の節 |
| 通信記録（手入力） | 「＋ 記録する」 | なし |
| 連絡帳の組織・連絡帳の人 | 連絡先の登録 | なし |

### 作るときの決まり

- **確かめるのは作る前**です。
  - 解析は、**Gemini に聞く前に**両方のテンプレートを引きます（有料の問い合わせを無駄にしない）。
  - 発注書は、「作成中」のページを作る前に確かめます。
  - **メールは送る前に**、控えを組めるかを確かめます。
    送ったあとで控えが作れないと、出た事実が残らないためです。
- **管理画面**に、「機械が作るページのテンプレート」の表を出します。
  登録（`cms.RegisterPageTemplate`）ごとに、在る／無い（2枚あるも）を出します。
- **スラッシュメニューに受注明細・発注明細・臨時部材表を出しました**（それまで `Hidden`）。
  テンプレートに人が置く印になったためです。

### 知らないと壊す所

- ⚠ **図面ブロックは見出し「図面」で探します**（`drawingBlockOf`）。
  - それまでは、`FirstBlockHTML` で「最初の節」を取っていました。
  - そのままだと、テンプレートで材料の節を図面より前に置いたとき、改定の合流が材料を運ぶところでした。
- ⚠ **写すときに定義リストと表の中の字下げを落とします**。
  - エディタが字下げして保存したテンプレートでも、`<dt>客先</dt><dd>` のように詰まった形になります。
  - 文字列で探す読み手が、空振りしないためです。
- ⚠ **改訂明細の1版目の行にブロックIDを振ります**。
  - テンプレートを写すと、ブロックIDは外れます。
  - 振らないと、改定の行を数える正規表現に数えられず、版がずれます。

### そのままのもの・残っていること

- **そのままのもの**: 改定の旧版（運んだ図面ブロックを並べるだけ）・年月の箱と整理の中間の箱（題だけ）。
- **残っていること**: **既存のページへ機械が挿す表**（新しい発注部材表・臨時部材表の骨組み）は、
  まだ登録の見出しから組んでいます。

- 職場のテンプレート: テンプレート／東邦／{受注ページ・加工製品・発注書}、テンプレート／通信／{通信記録（受信メール）・
  通信記録（送信メール）・通信記録（手入力）・連絡帳の組織・連絡帳の人}。
- 中身は、**それまでのコードが組んでいた形**を写しました。
