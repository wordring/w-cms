## 0. 何を決めたいか

利用者（2026-09-27）:

> 発注フォルダ、受注フォルダなどのフォルダになるページは必ず集計の鏡が付きますから、
> これらはテンプレートを使うことにしてはどうでしょう？ テンプレートに鏡を入れる
> スラッシュメニューは空のTableを入れるのでしょうか？ それによって今後の実装方針が
> 変わると思います

> 名前の見えない印 `<section data-type="unordered-items"></section>` は廃止して削除して欲しいです。
> 今後、テンプレート駆動型に変更していきたいのですが、可能でしょうか？
> コードに「この位置にこの鏡」と言ったことをハードコーディングするのではなく、テンプレートに、
> 「ここにこの鏡」と書き、コードのハードコーディングを減らしたいのです。

## 1. 答え——できます

**鏡は本文に「印」だけを置き、中身はページを開くたびにサーバーが描きます**（保存しません）。
スラッシュメニューが入れるのも**空の表ではなく、見出しだけの節** `<section><h2>必要部材表</h2></section>`
です。テンプレートは 2026-09-25 から**純粋なコピー**なので、テンプレートに印を書いておけば、
コピーしたページにもそのまま鏡が付きます。コード側に要るのは「どのテンプレートから作るか」だけです。

⚠ **鏡の中身（計算）はコードに残ります**——減らすのは「どのページのどこに何を置くか」（配置）で、
「何を計算するか」ではありません。

## 3. 1段目——名前の見えない鏡の印を廃止（2026-09-27・実装済み）

- 鏡（レジストリで `View: true` の形式）は、**見出しの印 `<section><h2>表示名</h2></section>` だけ**で
  名乗ります。`<section data-type="unordered-items"></section>` のような属性の印は**読みません**
  （`vocabTypeOf`・`hasViewMarker`）。中身を全部消して描き直す属性の印の流儀（`fillViewMarker`）も消し、
  いまは**前回描いたクロームだけ**を消します（見出しの下の人の書き込みは残る）。
- コードが印を書くときは **`cms.ViewMarkerHTML(形式名)`** を通します（表示名はレジストリから引く・
  置き場の雛形5か所をこれに替えた）。
- **対象外**: ファイル表示 `<section data-type="file-view" data-ref="…">`・可変タグ `<dl data-type="tags">`・
  file 容器・表の `data-type`（表は DBの日本語化 5段目の4 で別に消す）。どれも鏡ではありません。
- データは `tools/migrate-view-markers.js` で書き換えます（どれが鏡かは動いているサーバーの
  `/api/tag-schema` から引く）。**職場は 2026-09-27 に済み**（9ページ・11個）。⚠ **自宅はまだ**——
  流さないと、自宅の置き場の鏡が**エラーも出ずに消えます**（印は本文に残るので、流せば戻る）。
  両方で流し終えたら道具は消す。
- ⚠ **見出しが見えるようになって、鏡の中の題と二重に出ます**（例: 見出し「必要部材表」の下に
  「🧾 必要部材表（受注横断）」）。スラッシュメニューで入れた鏡は前からこの形でした。
  **案**: 鏡の中の題の行をやめ、件数など題に入っていた情報は説明の行へ移す（§5 の問い）。

## 4. これからの形（案）

- **A. 置き場は、同じ題のテンプレートから作る。** `テンプレート／発注` があればそれをコピーし、
  無ければ拡張の雛形（`RequiredPage.Body`）を使います。雛形は**新しい環境での初期値**になります。
  作る道2本（`CreateMissingRequiredPages` と `EnsureTopLevelBox`）も**同じ規則の1本**にします——
  いまの「作られた道で中身が違う」が消えます。題で引くのはコアの共通の規則にできます（業務語を
  持たない・§0）。
- **B. テンプレートの上では鏡を描かず、名前だけを出す**（コア）。⚠ **いまは描かれ、ボタンも押せます**
  ——鏡のボタンは表示しているページに書き込むので、`テンプレート／発注` の上で「発注部材表へ入れる」を
  押すと、**テンプレートに発注部材表ができ、以後に作る発注フォルダ全部へコピーされます**
  （拡張の鏡はどれもテンプレートを見分けていない・2026-09-27 に確かめた）。**A より先に要ります。**
- **C. 機械が作るページは「テンプレートをコピーして埋める」。** 埋める先は**タグの名前と表の
  キャプション**（見たままの規則・DBの日本語化と同じ手掛かり）。テンプレートに無いタグ・表は
  **末尾に足して知らせる**（黙って捨てると、人がテンプレートから消した表のデータが消える）。
  解析については [【考察】発注書から受注明細へ.md](【考察】発注書から受注明細へ.md) で合意済みの方向と同じ。
- **D. 「この位置に足す」は、テンプレートに置いた表・印を手掛かりにする。** 例: 臨時部材表は
  テンプレートに空で置く（いまも空で置く決まり）／発注部材表は最後の発注部材表の下（無ければ末尾）。
- **E. 年・月の箱と整理の中間の箱**も、テンプレートがあれば使う（無ければいまの見出しだけ）。

## 5. 未決（利用者に聞くこと）

1. **§4 の A〜E をこの方向で進めてよいか。** とくに B を A より先にしたい。
2. **テンプレートの名前の引き方**——置き場は題（`発注` → `テンプレート／発注`）で引けます。
   **題の決まっていないページ**（受注ページは題が発注書番号・発注書は仕入先）は、拡張がテンプレートの
   名前を渡す形になります（例:「受注ページ」「発注書」）。この名前を**設定で変えられるようにするか**。
3. **新しい環境のテンプレートを誰が作るか**——テンプレートは環境ごとのデータ（Git に入らない）。
   (a) 「足りない置き場を作る」が**雛形からテンプレートも作る** (b) 人が作る（無ければ雛形で作るだけ）。
   筆者は (b) を勧めます（自動で作ると、人が消したテンプレートがまた生えてくる）。
4. **鏡の中の題の行をやめてよいか**（§3 の二重表示）。
5. **ファイル表示 `<section data-type="file-view" data-ref="…">` も名前の見えない印です**——
   ページ1枚に図面の数だけ並ぶので、見出しを付けると目次が図面で埋まります。**このまま残すか**。
