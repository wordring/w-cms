# 【考察】同じ品番の加工製品ページ

同じ客先の中で、同じ品番の加工製品ページを2枚作らないための考察です。
要求の正本は [【要求】東邦拡張.md](../拡張/東邦/【要求】東邦拡張.md) §12 です。

## 1. 要求

> 2026-10-01 利用者:「とすると、二つの加工製品ページが同じ品番を持つのはマズいので、加工製品ページを作る前にチェックし、編集者に選択させる
> 必要があります」

> 2026-10-01 利用者:「つまり、会社が違えば同じ品番を許します。同じ会社内の同一品番は警告し、人間が対応します」

【要求】東邦拡張 §12 では、確かめる時点と、何を選ばせるかを、利用者と決めてから作ることになっていました。

## 2. 調べたこと（2026-10-19）

加工製品ページができる道は、次の3つです。

- **🤖解析**: 通信記録の子に、整理を待つページを作ります。品番の確かめはしません。
- **整理の「新規」**: 整理を待つページを `製造台帳／社名／（装置名称）` へ移し、加工製品ページとして置きます。
  同じ題のページが行き先にあれば、「図面改定」「図面追加」「新規」を選ばせていました。
  けれど、**題が違えば**、同じ客先に同じ品番のページがあっても、黙って置いていました。
- **「図面追加」**: 新しいページは作りません。同じ図面が在れば、2026-10-03 からダイアログで確かめています。

もう1つ、穴がありました。受注の行から加工製品ページを品番で引くとき、整理を待つページも数に入っていました。
そのため、同じ図面が2通目で届くと「同じ客先に2枚」になり、整理で片付けるまで受注の行が結ばれませんでした。

## 3. 聞いたことと答え（2026-10-19）

筆者は、次の2つを聞きました。

- 問い1: どの時点で確かめるか。
  - 案A（筆者の勧め）: 整理の「新規」のとき。🤖解析は今までどおり整理を待つページを作る。
    受注の行を結ぶときは、整理を済ませたページを先に見る（2通目の図面で結べなくなる穴を塞ぐ）。
  - 案B: 🤖解析のときも止める。ただし、解析の時点では客先を読み違えることがある。
- 問い2: ダイアログで何を選ばせるか。
  - 案A（筆者の勧め）: 既にあるページを並べて、「別の品物として作る」か「やめる」か。
    やめたら、整理の欄で「図面追加」「図面改定」「重複（取り込まない）」を選び直す。
  - 案B: ダイアログの中で4つから選び、そのまま進める。

✅ **利用者は、問い1・問い2とも案A を選びました**（2026-10-19）。

## 4. 作ったもの（2026-10-19）

**整理の「新規」で確かめる**

- 整理の「新規」で、同じ客先に、同じ品番の加工製品ページが既にあるとします。そのときは、何も動かさずに確かめを返します（`needs_confirm`・`confirm:"same_code"`）。
  - 同じ客先は、製造台帳の社名で見ます。
  - 同じ品番は、設定 `product_code_tags`＝図面番号・品番・部品番号のどれかで見ます。
  - 比べる相手は、整理を済ませたページ（製造台帳の下）だけです。旧版（`ページ種類：加工製品の旧版`）と、読めないページは除きます。
  - 番号は、表記をそろえて比べます。受注の行を結ぶときと同じ `pagesByAnyTag` を使います。
- 画面は、確かめのダイアログを出します。既にあるページ（ページ番号と題）と品番を見せて、「別の品物として作る」「やめる」を聞きます。
  - 作るなら、`confirm_same_code:true` を付けて送り直します。
  - これは、図面の確かめ（`confirm_revision`）・装置名の確かめ（`confirm_no_machine`）とは別の印です。
- 作ったことは、監査に残します（`file-drawing.same-code-accepted`）。

**受注の行は、整理を済ませたページを先に見る**

- 受注の行から加工製品ページを引くときの話です（`productPagesForCustomer`）。
  整理を済ませたページが1枚でもあれば、整理を待つページは数えません。
- 整理を待つページしか無ければ、いままでどおりそれに当たります。

**実装と見張りの試験**（見張りの試験は、後戻りを見つける試験です）

- 実装: `ext/toho/filing_same_code.go`（`sameCodeProducts`）・`ext/toho/filing.go`・`ext/toho/product_customer.go`（`isFiledProduct`）・`assets/app.js`（画面の部分は、2026-10-20 から `ext/toho/assets/toho.js` にあります）。
- 見張りの試験: `TestFileDrawingsAsksWhenSameCodeExists`・`TestProductLookupPrefersFiledPages`・E2E `verify-filing-same-code.js`。

## 5. まだのもの

- **いま既に、同じ客先の中で同じ品番を持つページ**は、そのままです。数えて利用者に見せるかは、未定です。
  受注の行が結べないときは、案件明細表の足元に ⚠ が出ます。
- 旧版の子ページを、受注の行を結ぶ候補から外す案は、まだです。
  作業引き継ぎの「返事待ち」にある「1つの図面に図面番号が2つ」の話です。
  - いまは、外してあります。2026-10-20 に、受注の行を結ぶ候補から、改定で子ページへ移った旧版を外しました（`productPagesForCustomer` の `isOldVersionPage`。[【考察】コードの矛盾.md](【考察】コードの矛盾.md) §1 の3）。
- ワンノートの製造の道具は、同じ図面番号なら作らずに、報告に出します。2026-09-28 からこの形で、変えていません。
