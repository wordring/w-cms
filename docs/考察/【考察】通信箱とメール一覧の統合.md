# 【考察】通信箱とメール一覧の統合

> 状態: **問いの答え待ち**（2026-10-29）。まだ何も作っていません。

## 1. 話の流れ（利用者の言葉）

【考察】コードの矛盾 §2.3 の「メール一覧の『未処理』は、通信箱と違って向きで決めています」について、利用者に聞きました。

> 2026-10-29 利用者:「メール一覧は通信箱に統合して、見え方を選択できるようにしたいです。メール一覧のような見え方も欲しいですが、未処理は通知と同じで良いのでは？」

## 2. いま

いま、通信の記録を見る画面は2つあります。

- **通信箱**（トップ直下のページ）。
  - いちばん上に「未処理」の表があります。人の印 `対応` が `未処理` の記録を、届いた順に並べます（`ext/comm/view_unhandled.go`）。
  - 向きでは決めません（2026-09-05 の決まり「未処理は人の印だけで決める」）。印の初めの値は、記録の作り方で決まります。
    - `未処理` から始まる: 届いたメール・届いた FAX・出た電話・手で書いた記録（メモ・かけた電話）・メールの下書き・送れなかった FAX。
    - `不要` から始まる: 送ったメール（w-cms から送ったもの・メールの読み込みが送信の箱から取り込んだもの）。
    - `済` から始まる: 送った FAX（送れなかったら、見張りが `未処理` に戻す）。
  - 「☎ 出ていない着信」の行も、この表に混ざります（`missed_call.go`）。
  - メール・FAX・電話・メモのどれも並びます。
- **メール一覧**（`/assets/ext/comm/pages/mails.html`。通信箱からのリンクで開く）。
  - メールだけを、返信の鎖（スレッド。`親ページID`）に束ねて並べます（`ext/comm/assets/pages/mails.js`）。
  - 件名・相手・向き・期間・未処理で絞れます。片付いたものも全部出ます。
  - ⚠ ここの「未処理」は、通信箱と決め方が違います。「受信か下書きで、`対応` が `済`・`不要` でないもの」です。
    ただ、送ったメールは `不要` から始まるので、ふだんは同じものが出ます。違うのは、人が送ったメールを `未処理` に戻したときだけです（通信箱には出て、メール一覧には出ない）。

スマホへの通知（`NotifyArrival`）は、記録が届いたときに出ます。届いたメール（自動の読み込み）・FAX・出た電話・送れなかった FAX です。
どれも `未処理` から始まる記録なので、通知が来たものは通信箱の作業待ちにも並びます。

## 3. 案（筆者）

1. **メール一覧のページをなくし、通信箱の中で見え方を選ぶ。**
   - 通信箱の一覧の上に「見え方」を置きます。「作業待ち」（いまの未処理の表）と「スレッド」（いまのメール一覧の形）です。
   - 選んだ見え方は、その端末のブラウザに憶えます（閲覧のスイッチと同じ）。
   - いまのメール一覧の住所は、通信箱の「スレッド」へ送ります（ブックマークが切れないように）。
2. **未処理の決め方を1つにする。** どちらの見え方でも、同じ決まりで未処理を決めます。決まりは問い1です。
3. **スレッドにも、FAX・電話・メモを入れる。** `親ページID` の鎖はチャネルを問わないので、メールへの返事に FAX が来たときも同じスレッドに並びます。絞り込みに「チャネル」を足します（問い2）。

## 4. 問い

- **問い1 未処理の決め方**。「通知と同じ」は、次のどちらの意味ですか。
  - A. 通信箱の作業待ちと同じ。人の印 `対応` が `未処理` のもの（向きは見ない）。通知が来たものは `未処理` から始まるので、片付けるまでここに並びます。
    手で書いた記録（メモ・かけた電話）とメールの下書きも並びます（通知は来ない）。
  - B. 通知が来るものだけ。届いた記録（受信のメール・FAX・出た電話・送れなかった FAX）で、`対応` が `未処理` のもの。
    メモ・かけた電話・下書きは、印が `未処理` でも未処理に出しません。
  - 筆者の勧めは A です。通信箱の決まり（2026-09-05）と同じで、作業待ちとスレッドの未処理がそろいます。
    B にするなら、通信箱の作業待ちも同じ決まりに変えるかを、あわせて決めます。
- **問い2 スレッドに FAX・電話・メモを入れるか**。勧めは「入れる」（チャネルで絞れる）です。
- **問い3 メール一覧のページをなくしてよいか**。勧めは「なくす」（古い住所は通信箱へ送る）です。
