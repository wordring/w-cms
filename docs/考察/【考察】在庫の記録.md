## 1. いまの形

在庫の数を書く所はありません。代わりに、部材の手配を数える帳簿（`ext/toho/procure_ledger.go`）が、買い過ぎた分を「在庫」とみなして、次の案件の手配に回しています（【要求】製造 §8.9）。

- **数えるもと**は、部材発注書の部材発注明細表の行の**数量**（発注した数）です。届いた数ではありません。
- 案件ごとに、その案件のために発注した数を、その案件の必要（案件の数 × 加工製品の部材の表の1台あたりの数）に当てます。
- 必要を超えた分は**余り（在庫）**として、ほかの開いている案件の必要へ、納期の早い順に1回だけ回ります。
  案件ページの手配状況では、その発注に「・在庫」と出ます。
- 手配不要表の余りは回しません（買っていないため）。備考が「追加」の行（作り直しのぶん）も回しません。
- 回す相手は、**同じ加工製品の**ほかの案件だけです。帳簿の鍵が「加工製品 ＋ 部材の鍵」だからです（`procKey`）。
  部材の鍵は、材料なら 材質・形状・寸法、購入部品・支給部品なら 品名・仕様、外注加工なら 番号・加工内容 です（設定の `order_kinds`）。
- 部材発注書で「📦 納品済」を押すと、その行の状態が「納品済」になり、全部届くと `納品日` に今日が入ります。届いた**数**は記録しません。
- 材料表には `単位` の列がありません。`個数` は「1台あたり何個（何枚）」として数えています。

**加工製品**

- 加工製品の在庫を書く所はありません。
- 製造ページの製造明細表の `数量` は、製造待ちから入れた案件の数です。人が多めに直すことはできますが、多く作った分は、どこにも在庫として残りません。
- 客先の注文に結び付かない製造は、自社案件（`ページ種類：自社案件`・`ext/toho/own_case.go`）で表せます。在庫のために作るときも、自社案件にできます。ただ、作った品物は在庫として残らず、製造ページを手で閉じて終わります。
- 納品書は、製造ページの納品作業からだけ作ります（2026-10-22 から）。だから、在庫にある品物を、製造を始めずに客先へ納める道がありません。

## 2. 足りないこと

### 2.1 届いた数

- 発注した数と違う数が届いても（多く届いた・定尺で丸めて届いた・欠品した）、記録する欄がありません。
- 部材発注明細表の `数量` を人が書き換えれば帳簿は追いつきますが、「発注した数」の記録が消えます。紙（送った部材発注書）とも合わなくなります。

### 2.2 同じ材料を使うほかの加工製品への回し方

- いまは同じ加工製品の案件にしか回りません。同じ板（材質・形状・寸法が同じ）を別の加工製品で使っても、余りは当たりません。
- 材料の鍵は、書いた文字をそろえて比べます（全角半角・空白など）。`t3.2*100*200` と `t3.2×100×200` のような書き方の揺れは、同じ材料と見なされないことがあります。

### 2.3 減らし方

- いまの在庫は、帳簿の中で毎回計算し直す「仮の数」です。
  - 余りは、開いている案件の必要に当たると減ります。ただし、実際に使ったか、捨てたか、別の用途に回したかは分かりません。
  - 当たる相手が無ければ、余りはいつまでも帳簿に残ります。棚の現物と合わせる道（棚卸し）がありません。
- 加工製品ページの表に在庫量を書く案（2026-10-01）は、書いた数が使っても減らないので、まだ入れていません（【要求】製造 §8.9 の未決）。

### 2.4 在庫の一覧

- いま何がいくつ在庫にあるかを、見る所がありません。手配状況の「・在庫」は、回った先で見えるだけです。

### 2.5 加工製品の在庫

- 多く作った品物も、在庫用に作った品物も、在庫の数として残りません（§1）。
- あとで客先から注文が来たとき、在庫から納めた記録（納品書）を作る道がありません。いまは、製造ページを作って納品作業から納品書を作るしかなく、作っていない製造の記録が残ります。
- 案件残表は、在庫があっても、その注文を「まだ製造していない」と見せます。

### 2.6 単位

- 材料を切った形（ブランク）で買うなら、`個数` は枚数で数えられます。
- 定尺（たとえば 4m の丸棒）で買って社内で切るなら、在庫は「本数」より「長さ」で数えたくなります。いまの表では書き分けられません。

## 3. 筆者の案

「在庫表」を1つ持ち、在庫の数を**書類から計算し、棚卸しで人が合わせる**形を勧めます。

### 3.1 届いた数（部材発注書）

- 部材発注明細表に列 `納品数`（届いた数）を足します。紙には刷りません。
- 「📦 納品済」を押すと、`納品数` が空なら `数量` を入れます。違う数が届いたら、人が `納品数` を直します。
- 帳簿は、`納品数` があればそれを、無ければ（まだ届いていない行は）`数量` を、手当てとして数えます。発注した数（`数量`）はそのまま残るので、紙とも合います。

### 3.2 在庫表（置き場「在庫」）

- トップ直下に置き場「在庫」を作り、本文に**在庫表**を1つ置きます。
  列は 種類・部材の鍵の列（材質・形状・寸法／品名・仕様）・数・単位・置き場所・棚卸し日・備考 です。
- 在庫表の数は、**人が棚卸しで書いた数**です（棚卸し日つき）。
- 画面には、その数に、棚卸し日のあとの入り（届いた数の余り）と出（在庫から使った数）を足し引きした**いまの数**を、鏡（表示のときにサーバーが足す列）で並べます。
- 鍵に加工製品は入れません。同じ材料なら、どの加工製品でも同じ在庫です（§2.2）。
  外注加工した部品（塗装済みの部品など）は、その加工製品にしか使えないので、鍵に加工製品を入れます（問い1）。

### 3.3 使うとき（製造ページの「🧾 部材作業」）

- 必要部材表に、在庫のいまの数を見せる列を足します。
- 必要部材表の下に「📦 在庫から使う」を足します。押すと、その行は手配不要表へ移り（理由は「在庫から」）、在庫の出として数えます。
- 自動では在庫から当てません。在庫の数は現物とずれることがあるので、人が棚を見て決めます（問い4）。

### 3.4 いまの「仮の在庫」

- 案件のために買った余りを、ほかの案件へ黙って回す今の仕組みは、在庫表ができたら外します。
  余りは在庫表の「入り」として見えるようになり、使うときは人が「📦 在庫から使う」で選びます。
- 外すと、今まで黙って当たっていた余りが当たらなくなり、必要部材表に部材が出てくることがあります。切り替えるときに、いまの余りを在庫表の棚卸しの数として書き写します（問い8）。

### 3.5 加工製品の在庫

- 在庫表に、加工製品の行も置きます。鍵は加工製品ページ（弊社品番）です。
- **入り**: 製造ページで、納品した数より多く作った分を在庫に入れます。製造明細表に列 `製造数`（実際に作った数）を足し、「✓ 製造完了」のときに `数量` を入れて、多く作ったら人が直します。製造ページを閉じるときに、`製造数` − 納めた数 が在庫に入ります。
  在庫のためだけに作るときは、自社案件で作ります（いまの形のまま）。自社案件の製造は、作った数が全部在庫に入ります。
- **出**: 案件残表で行を選んで「📦 在庫から納品」を押すと、在庫から、その注文の納品書を作ります（製造ページは作らない）。在庫の出として数えます。
  製造ページの納品作業で、在庫の分を足して納めることもできるようにします（一部を在庫から・残りを作る）。
- 加工製品ページに、その品物の在庫の数を見せます（「🧾 受注・見積の単価」の近く）。
- 案件残表では、在庫で足りる注文の行に「在庫 N」と出します。

### 3.6 作る順の案

1. 部材発注明細表の `納品数`（§3.1）。
2. 置き場「在庫」と在庫表、いまの数の鏡（§3.2）。
3. 必要部材表の在庫の列と「📦 在庫から使う」（§3.3）。
4. 仮の在庫を外し、いまの余りを在庫表へ書き写す（§3.4）。
5. 加工製品の在庫（§3.5）: 製造明細表の `製造数`・閉じるときの入り・「📦 在庫から納品」・加工製品ページと案件残表の在庫の数。
6. 在庫の一覧のビュー（在庫表そのものが一覧になるので、要るかは使ってから）。

## 6. 答えを受けた形

§3 の案を、答えに合わせて組み直しました。筆者が読み足した所には「（筆者の読み）」と書きます。

### 6.1 一度在庫に入れて、在庫から出す

- 届いたもの（部材発注書の「📦 納品済」）と作ったもの（製造の製造完了）は、**まず在庫表に入れます**。
- **同じときに、もう作業を始めている分を引きます**。部材なら、その部材を発注した製造のぶん。加工製品なら、その製造で納める案件のぶんです。
  残りが在庫として残ります。
- ほとんどの物は、入れた数と引いた数が同じなので、在庫は 0 になります。それでも、この形でよいと考えます（利用者の問い2への筆者の答え）。
  - 入れるのも引くのも機械が同じときに行うので、人の手間は増えません。
  - 一部を在庫から、残りを作って納めるとき（問い10の答え）も、同じ形のまま扱えます。
  - 通ったことは、在庫表の版と監査に残ります。
- 在庫表は「ただの表」です。人が棚卸しのたびに直してよく、機械は直された数から足し引きを続けます。

### 6.2 在庫表（トップ直下の置き場「在庫」）

- 在庫にするのは、材料・購入部品・支給部品・外注加工した部品・加工製品の全部です（問い1）。
- 同じものかどうかは、部材の鍵で決めます（いまの手配の数え方と同じ）。
  - 材料: 材質・形状・寸法。購入部品・支給部品: 品名・仕様。この3つは、どの加工製品でも同じ在庫です（問い5）。
  - 外注加工した部品: 弊社品番（その加工製品）と、番号・加工内容。
  - 加工製品: 弊社品番。
- 定尺の材料は「長さ*本数」で数えている（問い6）ので、寸法に長さを書き（例 `φ25*4000`）、在庫の数は本数で数える形にします（筆者の読み・§7 問い13）。
- 表は種類ごとに分けます（筆者の読み・§7 問い12）。1つにまとめると列が十を超え、欄（最大 666px）に入らないためです。

### 6.3 在庫の数を見せる所

- 製造ページの製造明細表（加工製品の在庫）と、発注部材表（部材の在庫）の、数量の横に「在庫数」の列を足します（問い4）。表示のときにサーバーが足す列（鏡）で、本文には書きません。
- 在庫を使うかどうかは、この列を見て人が決めます。機械は自動では当てません。使い方は、様子を見てから決めます。

### 6.4 加工製品

- 製造明細表に `製造数`（実際に作った数）を足します。「✓ 製造完了」のときに `数量` を入れ、多く作ったら人が直します（問い9）。
- 在庫のためだけに作るときは、自社案件で作ります。自社案件の製造には納める案件が無いので、作った数が全部在庫に残ります。
- 「📦 在庫から納品」は作りません（様子を見る・問い10）。

### 6.5 いまの仮の在庫

- 在庫表ができたら、「余りを次の案件へ黙って回す」仕組みを外します（問い8）。
- 外すときに、いまの余りを在庫表へ書き写します。

### 6.6 作る順

1. 置き場「在庫」と在庫表（種類ごと）・テンプレート。
2. 部材発注書の「📦 納品済」で、在庫に入れて、作業を始めた分を引く。
3. 製造明細表と発注部材表の「在庫数」の列。
4. 製造明細表の `製造数` と、製造完了で加工製品を在庫に入れて、納める分を引く。
5. 仮の在庫を外し、いまの余りを在庫表へ書き写す。
6. 様子を見てから: 在庫から使う操作・在庫から納品。
