# ユースケース：受注と進捗管理

このドキュメントでは、**w-cms** における顧客発注書（および弊社発注書）をベースとした、部品ごとの進捗管理ユースケースとカスタムタグの設計仕様を定義します。

---

## 1. 目的
受注の記録は、顧客から発注書が届いたタイミングで作成されます。顧客は一度の取引で複数枚の発注書を発行することがあるため、システムは1つの「受注記録ページ（ページIDを持つHTML）」の中に複数枚の発注書PDF（原本）と、それぞれに紐づく複数の部品（図面）情報を記録できるようにします。
また、部品ごとに製造・加工・納品の進捗ステータスを追跡可能にし、仮想的な進捗管理ダッシュボードを自動生成します。

---

## 2. タグ設計仕様

### 2.1. 1ページへの複数発注書の記録
1つのHTMLファイル内に、複数の `<m-file tag="顧客の発注書">` ブロックを自由に配置します。
各発注書は、それぞれ一意の `order-no` (発注書番号) 属性を持ちます。

### 2.2. 部品の発注書番号へのぶら下がり（ネスト）
発注書の中に記載されている部品は、HTML上で `<m-file>` の子ノードとして `<m-item>` タグをネスト記述します。
パーサーおよびデータベースはこの親子関係を読み取り、`client_order_items` の各行に親の `order_no` を記録して「発注書ナンバーにぶら下がる」リレーションを構築します。

```html
<!-- 顧客発注書1 (発注書番号: PO-A100) -->
<m-file src="attachments/PO-A100.pdf" 
        name="発注書_PO-A100.pdf" 
        tag="顧客の発注書" 
        order-no="PO-A100" 
        client-name="トーア" 
        ordered-at="2026-06-18">
    <!-- 部品が発注書番号 PO-A100 にぶら下がる -->
    <m-item item-id="SHAFT-01" item-name="シャフトA" price="8000" quantity="10" status="未着手"></m-item>
    <m-item item-id="SHAFT-02" item-name="シャフトB" price="12000" quantity="5" status="加工中"></m-item>
</m-file>

<!-- 顧客発注書2 (発注書番号: PO-A200、同じページに記録) -->
<m-file src="attachments/PO-A200.pdf" 
        name="発注書_PO-A200.pdf" 
        tag="顧客の発注書" 
        order-no="PO-A200" 
        client-name="トーア" 
        ordered-at="2026-06-18">
    <m-item item-id="GEAR-01" item-name="ギヤA" price="15000" quantity="2" status="検査中"></m-item>
</m-file>
```

---

## 3. 進捗ステータス管理

### 3.1. 部品ステータス (`status` 属性)
部品ごとに以下のステータス値を設定・更新できます。
*   `未着手` (初期状態)
*   `加工中`
*   `検査中`
*   `納品済`

### 3.2. 仮想進捗管理ページでの可視化
OneNote的なHTMLファイルを個別に編集して保存すると、データベース内のインデックス情報（`client_order_items` の各行の `status`）がリアルタイムに同期されます。
システム全体で提供される「仮想的な進捗管理ページ」では、このデータベースのインデックスを元に、以下のような進捗状況を俯瞰表示できます。

```
【受注進捗管理ボード】
----------------------------------------------------------------------
発注書番号: PO-A100 (顧客: トーア, 受注日: 2026-06-18, ページID: 00002)
 ├─ [未着手] シャフトA (SHAFT-01) × 10個
 └─ [加工中] シャフトB (SHAFT-02) × 5個

発注書番号: PO-A200 (顧客: トーア, 受注日: 2026-06-18, ページID: 00002)
 └─ [検査中] ギヤA (GEAR-01) × 2個
----------------------------------------------------------------------
```

これにより、ユーザーは各図面（部品）のページから進捗を更新するだけで、自動的に全体の発注書ベースの進捗ボードが最新に保たれるようになります。
また、部品単位でどの発注書に紐づいているかが一目で判別できます。
