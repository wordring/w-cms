# 【要求】w-cms とは

**何のためのソフトウェアか**の要求仕様です。

> **書くのは利用者**、**矛盾を指摘するのがエージェント**（開発方針 §2）。
> 本書は **2026-09-23 に [要件定義書.md](要件定義書.md) §1 から抜き出したもの**です
> ——⚠ **利用者が読んで直すための下書き**であって、まだ利用者の言葉になっていません。

⚠ **2種類のことが書いてあります。** （印なし）＝**要求**（利用者が直す）、
⚠ **いま**＝**実装の現状**（エージェントが直す）。
**なぜそうなったか**は `【考察】` が正本です。

---

## 1. 目的

**入力項目が固定された帳票システムを作らない。**

Notion のように**自由なブロックレイアウトで書いたページ＋PDF原本**から、
**見える文字（階層・ページ名・見出し・タグ）を手掛かりに**データベースが集計します。

- 「顧客管理画面」「製品管理画面」のような**固定のページ種別を持ちません**。
  すべてのページは**同じ構造のHTML**で、**役割は階層とページ名でだいたい決まります**。
- 集計に載せるかどうかは、**ブロック単位の印**で決まります。

## 2. 用途は2つ——**別サーバー・別ドメインの2インスタンス**

| インスタンス | 用途 | 主な利用者 | 中心の要求 |
|---|---|---|---|
| **業務** | 社内の業務システム | 認証済みの利用者だけ | 受発注・進捗・原価/利益の記録と集計 |
| **サイト** | 一般公開のウェブサイト | 匿名の訪問者＋編集者 | 公開ページの読み取り専用配信 |

- ⚠ **データは完全に独立**します。`data/master`・`cms.db`・`auth.db` はインスタンスごとに別で、
  **ページを共有しません**。したがって ⚠ **業務データが公開面へ出る事故は、権限設定ではなく
  構成そのもので防がれます**（業務ページと公開ページが同じ木に同居しない）。
- **ソフトウェアは同一**（同じ単一バイナリ）。⚠ **インスタンスごとに機能を分岐させる作りは
  持ちません**——差は**データと運用**で吸収します。
- **運用は2セット**になります（デプロイ・バックアップ・更新・初期管理者）。

## 3. 設置者は開発元に限らない

> 2026-08-26 ユーザー:「プラグインを様々な企業やサイト運営者が自分で設置することは要件に
> 含まれていますか？含まれていない場合、含めてください。**利用者は私のみではありません**」

- **語彙とプラグイン（計算を含む）は、設置した運用者が自分で追加できること。**
- ⚠ **開発元の業務語彙（受発注・部材など）は「同梱の既定セット」であって、コアの一部では
  ありません。** `-tags minimal` で外せます。

## 4. 業務の対象領域

- **製造・加工業（部品加工／材料調達）の受発注業務**。
- 用語は**視点に依らない役割語**で統一します（受注／発注・販売見積／購入見積）
  ——正本は [【一覧】用語集.md](【一覧】用語集.md) §1。
- **語彙は最終的に100種規模**を予定します。
  ⚠ **いま**は21形式（2026-09-22・コア5＋拡張16。カスタム要素は0）。
  ⚠ **「語彙を増やす／一覧を保守する／エディタから選ぶ」経路が、数十〜百のオーダーで
  破綻しないこと**が要求です（[【要求】表とDB.md](【要求】表とDB.md) の3層モデル）。
- ウェブサイトとしては、**公開ページが検索エンジンと一般の訪問者に晒される**ことを前提とします。

## 5. 利用者

| 利用者 | できること |
|---|---|
| 認証済みの利用者 | ページ権限（Unix風 read/write）の範囲で閲覧・編集 |
| グループ | ページの group クラス権限の単位（**フラット・入れ子なし**） |
| admin | root 相当。全権限バイパス・利用者/グループ管理・DB再構築・ロック強制解除 |
| 匿名の訪問者 | **実効公開ページだけ** read 専用 |

## 6. 公開範囲と脅威モデル

- ⚠ **どちらのインスタンスもインターネット公開を前提**とします。強固な認証・HTTPS・
  レート制限・CSRF 対策は**必須**です。
- **業務インスタンスは匿名に何も見せません。** 全ページ非公開（`public` を使わない運用）とし、
  匿名には**存在情報も返しません**（[【要求】権限.md](【要求】権限.md) の404統一）。
- **サイトインスタンスでは匿名アクセスが常時の主要動線**です。未認証で到達できる面
  （公開ページの本文・子ページ一覧・親リンク・添付配信）は、**既定非公開＋明示的な公開操作**という
  **フェイルクローズ**で守ります。⚠ **下書き（非公開ページ）の存在も匿名には漏らしません。**

## 7. 実装の制約（守ってほしいこと）

- **標準ライブラリ優先。** 外部パッケージの新規追加は**原則禁止・事前承認制**。
  ⚠ 承認済みの直接依存の一覧は [開発方針.md](開発方針.md) §1 が正本です。
- ⚠ **CGO 不要**でビルドできること（Windows でも C コンパイラなしで動く）。
- **フロントエンドはバニラJS・ビルド工程ゼロ・追加ライブラリなし。**
- **単一バイナリ**で配布・起動できること。
- ⚠ **実装量が語彙数に対して不変であること。** 型ごとの JavaScript を書かない、
  語彙を増やすたびにフロントの markup を手で足さない。
