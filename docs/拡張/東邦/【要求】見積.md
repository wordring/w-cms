## 1. 見積を記録する（←旧文書から下書き）

- **見積は2種類**——顧客へ出す見積＝**売上の予定**、業者から貰う見積＝**原価の予定**（ユースケース:72-111）。
  予定の売上・原価として【要求】受注 §5（原価と利益）へつながる。
- **あとから引けること**——「あの部品は前いくらで出したか」「同じ材料を3社に聞いたうちどこが安かったか」を、ページを
  またいで引き出す（**横断比較**）。利用者「見比べることはよくありますので、いずれその機能も必要になります」
  （2026-08-21・ユースケース:26・解体前 l.636——要件定義書は行き先を「`【要求】見積` の案」としていた）。
- 図面がある見積もりは、加工製品ページに入れて区分「見積もり」のタグを付ける（2026-09-29 利用者「見積についても、図面が
  あるなら加工製品に入れて、見積もりのタグを付けたいです」——【要求】東邦拡張 §9）。

⚠ **いま**: 見積の器（見積書のページ）も横断比較も未実装。在るのは、加工製品ページの `見積もり` の表（工程・数・単位・備考
——ワンノートから移した原価の内訳）と、区分「見積もり」のタグと、加工製品の一覧の絞り込みだけ。

## 2. 見積の器——決まったこと（←【考察】製造という軸 §7i・§7k・2026-09-22）

- **見積は器（見積書のページ）が要る**——理由は3つ: ①外に出る紙（見積書）がある ②受注の前にあるので、紐づける受注ページが
  まだ無い ③失注する——受注にならない見積が残るので、受注の下に置けない。
- **「見積DB」（専用の表）は要らない**——横断で読むのは索引の仕事。専用の表はドメイン表ゼロ（D-1）に逆行する。
- **発注明細と同じ表に「見積」の印で混ぜない**——状態の列に混ぜると、読み手すべてが「見積を外す」を覚えていなければならず、
  1か所忘れた日に見積が手配済みに化ける。相見積もりは1つの材料に複数社が並ぶので、混ぜると**買ってもいない会社の値段**が
  最新単価を上書きする。**形式を分け、列の宣言は共有する**（見積の明細も発注明細と同じ列で足りる）。
  利用者の問い（2026-09-22）:「見積もりの印をつければ見積も同じDBを使うことが出来ますが、そうするべきか否か」への筆者の答え。
- **価格の出所の順位**（混ぜて1つの数にせず、出所を必ず添える）——1. 発注明細（発注済・納品済）＝実際に買った値段 ＞
  2. 見積明細（貰った見積書）＝言われた値段・複数社が並ぶ ＞ 3. 発注明細（未発注）＝こちらが書いただけ・出さない ＞
  4. ワンノートの参考価格＝日付が無い・「最新単価」を名乗らせない。

⚠ **いま**: 最新単価の鏡が使っているのは1と4だけ（`ext/toho/material_price.go`）。
