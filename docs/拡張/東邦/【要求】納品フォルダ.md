> - 印の無い文は**要求**です（こうあってほしい、という決まり）。書くのは利用者で、
>   エージェント（AI）は矛盾を見つけたら指摘します（[開発方針.md](../../開発方針.md) §2）。

> - 「（案）」「（未決）」と付いた見出しは、まだ決まっていない所です。利用者が読んで決めます。
> - いつ・なぜその形になったかは、末尾の「この文書の経緯」と、`docs/考察/` フォルダの【考察】にあります。

利用者が読んで直すためのもので、まだ利用者の言葉になっていません。

## ⚠ まず確かめたいこと——「納品」は2つあります

> 利用者:「**納品書は納品フォルダの納品書ページから発行します**」

**発行する**ということは、弊社が出す紙の話です。
ところが、その少し前に伺った `納品日` は、部材発注書の話でした。
あちらは、仕入先が弊社へ納める側です。

| どちら向きか | 紙 | 誰が出すか | 対応するもの |
|---|---|---|---|
| **弊社 → 顧客** | **納品書** | **弊社が発行する**（本書） | 受注 |
| **仕入先 → 弊社** | 仕入先の納品書 | **相手が出す**（こちらは受け取るだけ） | 部材発注 |

**同じ「納品」でも、別のものです。** 利用者に決めていただきたいことが、2つあります。

**① 本書はどちらを扱うか。**

- 「発行します」とあるので、弊社が出す側だと読みました。
- 受け取る側も同じフォルダに入れるなら、`向き` で分けることになります。
  通信箱（メールなどの通信の記録を入れる置き場）が、`向き：受信／送信` で分けているのと同じ形です。

**② 部材発注書の `納品日`（＝仕入先から届いた日）はどこに書くか。**

- [【要求】製造.md](【要求】製造.md) §8.5 では、まだ決まっていません（未決です）。
  あちらでは、部材発注書ページを作るときに `納品日` のタグを空の欄で置き、届いた日を人が書きます。誰がいつ書くか（納品の記録から書くか）は決まっていません。
- 本書が弊社が出す側だけを扱うなら、あちらの置き場は、別に決める必要があります。

## 1. 置き場

置き場は **`記録／年／月／製造記録`** です。年月は、納品書ページを作った日のものです。
「置き場」は、その種類のページを入れておくページのことです（フォルダの役目をします）。

- 年月の決まりは、2026-10-16 に決めた記録の年月の決まりです（[【考察】全体の設計.md](../../考察/【考察】全体の設計.md) §4.1・§4.2）。
- 製造ページから作った納品書も、同じ置き場に入ります。製造ページの子にはしません。
  - どの製造の分かは、納品明細表の列「製造」（製造ページへの参照）で表します。
  - 製造ページの末尾の「この製造の書類」に並びます。
- 題は「【弊社】納品書　<客先>」です。
- `ページ種類` は `弊社納品書` です。

⚠ **いま**: 2026-10-19〜20 は、製造ページから作った納品書を製造ページの子に作っていました。その形の納品書も、製造ページの書類として見分けます（`ext/toho/mfg_docs.go`）。

**案件ページの下には、置けません。** 理由は、部材発注書と同じです。

- 1回の納品が、複数の受注にまたがることがあります。
- 分納（1つの受注を、何回かに分けて納めること）なら、1つの受注から、納品書が何枚も出ます。

## 2. なぜ器が要るのか

「器」は、そのことを記録しておくための、専用のページのことです。

器が要るかどうかの物差しは、利用者自身が出したものです
（[【考察】製造という軸.md](../../考察/【考察】製造という軸.md) §7i）。物差しは、次の2つの問いです。

- ①外に出る紙があるか
- ②1つの受注行に何度も起きるか

納品に当てはめると、次のようになります。

| 問い | 納品は |
|---|---|
| 外に出る紙があるか | ✓ **納品書**（2026-09-22 決定:「**納品書はこのシステムから出します**」） |
| 1つの受注行に何度も起きるか | ✓ **分納**（「一つの加工製品が**複数の納品に分かれる**場合もある」） |

**どちらも「はい」なので、器が要ります。**

これで、同じ形が5つ並びます。**見積・部材発注・納品・請求の紙が原本で、案件明細表は鏡**、という形です。
5つは、【考察】製造という軸 §7i の4つ（見積・製造・納品・発注）に、§7j の請求を足した数です。
製造には、外に出る紙がありません。製造の器を作るかは、まだ決まっていません（[【要求】製造.md](【要求】製造.md) §7）。
「鏡」は、ページを開くたびにサーバーが描き足す表示のことです。人が打つ欄ではありません。

⚠ **いま**（2026-10-19 から）: 製造の器として、製造ページがあります（トップ直下「製造」の下・1枚に1社）。2026-10-21 から、案件残表の「🏭 製造」で製造待ちへ入れ、「製造」の製造待ちの表の「▶ 選んだ行で開始」で1枚作ります（【考察】案件残から製造へ）。
決めたことは [【考察】製造ページ.md](../../考察/【考察】製造ページ.md) にあります。

## 3. ⚠ 案件明細表に足す列はゼロ

> 2026-09-22 利用者:「納品は**記録すべきことがあまりありません**」

そのとおりです。**記録するのは、紙のほう**だからです。

```
納品書ページ（記録／年／月／製造記録）   ← 紙が原本。いつ・何を・何個
      ↓ 索引から数える
案件明細表の `出荷済数量`        ← 累計だけ（鏡）。⚠ **人は打ちません**
```

図の「索引」は、保存のたびに、タグと表から作る検索用のデータベースのことです。

- 納品書ができたら、`出荷済数量` は**鏡に置き換わります**。印と事実を、二重に持たないためです。
- 分納だと、`納品日`・`納品数` は、1つのセルに入りません。
  これが、「案件ページの表に入れれば良いか」という当初の案を採らなかった理由です。

⚠ **いま**（2026-10-17 から）: `出荷済数量` は鏡です（`ext/toho/delivery_shipped.go`）。

- その行が載った納品書（`ページ種類：弊社納品書`）の数を足して、案件ページの欄と案件残表に出します。
- 発行済かどうかは見ません。未発行の納品書も数えます。
- 案件明細の行とは、納品明細の `案件`（案件ページ。2026-10-19 までの名前は `受注`）と `品番` で結びます。
  品番が空の行は、`品名` で結びます。
- 人が欄に書いた値は、読みません。
  - 書いてあれば、鏡に「欄に書いた N は使いません」と添えます。
  - 案件残表からも、書けなくしました。
- 2026-10-17 までに人が書いていた数（43枚・238行）は、**移行用の仮納品書**へ移しました。案件ページごとに1枚です。欄は空にしました。
  - 題は「【弊社】納品書（移行用の仮）　<客先>」です。
  - 置き場は、案件ページと同じ年月の `記録／年／月／製造記録` です。
  - 紙は作っていません（未発行のままです）。

  > 2026-10-17 利用者:「一点だけ確認です。人が書いた出荷済み数量はどこに保存するでしょうか？これも納品書ページを作って移行用の仮納品書だと書いておいてはどうでしょう？」

## 4. 納品書ページ（案）

**部材発注書ページと同じ作りにする**のが素直だと考えます。部材発注書ページは、すでに動いているためです。

### タグ（案）

タグは、ページに「名前：値」の形で付ける札のことです。「型」は、値の種類です。

| タグ | 型 | 備考 |
|---|---|---|
| 納品書番号 | code | **ページ番号そのもの**です（部材発注書と同じ。別に採番しません） |
| 客先 | text | 連絡帳にある組織または個人 |
| 納品日 | date | **実際に納品した日**です（予定は `納期`・確定した期日は `納品日`） |
| 納品担当 | ref | 連絡帳の担当者ページ |
| 納品場所 | text | |

⚠ **いま**:

- 上の5つに、`発行日` と `ページ種類` を足しています。
  `発行日` は date で、紙を作った日です。空なら未発行です。
- `客先` には、案件ページの `発注元` を写します。
- `納品担当` には、作った人の連絡帳のページが初めに入ります（2026-10-17 夜から）。
  作った人のページとは、ログイン名と同じ題で、署名のある人のページです。

### 納品明細（案）

⚠ **列は、案件明細表と、名前と型をそろえること。**
そろっていないと、ページをまたいだ検索（横断検索）が、片方を取りこぼします。
そろえる列は、`弊社品番`・`品番`・`品名`・`数量`・`単位` です。

| 列 | 型 | 備考 |
|---|---|---|
| 弊社品番 | ref | 加工製品ページ。**これが無いと、どの受注のぶんか辿れません** |
| 品番 | code | 顧客の言葉 |
| 品名 | text | |
| 数量 | number | **この回に納めた数**です（受注数ではありません） |
| 単位 | enum | |
| 備考 | text | |

**単価・金額を書くかは、未決です。**
実物の納品書を見てから決めるのが確実です（部材発注書は、実物7枚を読んで形が決まりました）。

⚠ **いま**:

- 表の名前は「納品明細表」です。
- 列は、弊社品番・案件・発注書番号・品番・品名・数量・単位・単価・備考 です（`ext/toho/delivery.go` の `deliveryItemColumns`）。
  - 案件（案件ページ。2026-10-19 までの名前は「受注」）と発注書番号は、どの注文のぶんかを辿るために足しました。
  - 品番・品名・単位・単価・発注書番号は、案件明細から機械が写します。
- 単価は載せます。決まっていない行は、空欄です（0 にしません）。
- 紙は、2026-10-15・16 に w-cms の外で作った納品書の形です。
  単価の決まっていない行があると、紙に小計・合計を刷りません。

## 5. ⚠ 分納をどう表すか（未決）

同じ加工製品を、2回に分けて納めるときの例です。

```
受注: ブラケット 20個
  → 納品書A  10個（9/25）
  → 納品書B  10個（10/2）
```

- 案件明細表の `出荷済数量` は、2枚を足して 20 になります（鏡）。
- 「あと何個か」は、引き算で出ます（`数量 − 出荷済数量`）。そのための欄は要りません。
- **利用者に決めていただきたいのは、納品書を作るときに、「残り」をどう見せるかです。**
  部材発注の「必要部材」と同じように、まだ納めていないものの一覧が要るはずです。

⚠ **いま**: まだ納めていないものの一覧は、案件残表です（残 = 数量 − 出荷済数量）。

- 残のある行を選んで、納品書を作ります。
- 今回納める数の欄には、初めに残りが入ります。
- 同じ行を何枚もの納品書に載せれば、分納になります。
