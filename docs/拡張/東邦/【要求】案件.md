# 【要求】案件

**案件**（前の名前は「受注」）の要求仕様です。
案件は、顧客の注文を受けて記録し、残を追い、売上と利益を見る業務です。
見積の依頼も、案件として並べます（[【考察】製造ページ.md](../../考察/【考察】製造ページ.md) §7 の答え）。
東邦拡張（コードは `ext/toho`）の業務の1つです。

⚠ **いま**: 2026-10-19 に、「受注」を「案件」に改名しました。

- 名前が変わったのは、トップ直下の「案件」・案件ページ・案件明細表・案件残表です。
- 「受注残高」は、名前を残しています。注文の残りの金額だからです。
- 客先の発注書から作った案件ページの題は、「【顧客】発注書 <発注書番号>」です。
  番号が読めなければ「【顧客】発注書（<発注元>）」、発注元も読めなければ「【顧客】発注書（番号不明）」です（`ext/toho/analyze_order_page.go` の `buildOrderPageHTML`）。

となりの業務は、別の【要求】にあります。

- 見積: [【要求】見積.md](【要求】見積.md)
- 製造と進捗: [【要求】製造.md](【要求】製造.md)
- 納品: [【要求】納品フォルダ.md](【要求】納品フォルダ.md)
- 部材の発注: [【要求】製造.md](【要求】製造.md) §8

## 1. 受注の取り込みと案件残（下書き）

出どころ: 【要求】東邦拡張 §11

> 2026-09-30 利用者:「顧客の発注番号は発注書が正本です」「一枚のPDFに複数の発注書が入っています。…返答も発注書ごとに配列のように」

> 受注ページにして良いと思います」「受注ページに受注残高を出したい。受注残の表に装置名も入れたい」
> 「このシステムでは弊社品番で識別できないとマズい」

- 案件ページの発注書番号は、**発注書に書かれた番号**です（メールの添付の名前ではありません）。
- 1つのPDFに発注書が何枚も入っていれば、発注書ごとに案件ページを作ること。
- Excel の注文リストも、はっきり受注と分かるものは、案件ページにすること。
- 案件ページに受注残高を出すこと。案件残の表に装置名を入れること。
- 1つの加工製品ページに、別の品物（左右違い・上下）を入れないこと。
  受注の行を、弊社品番で見分けるためです。弊社品番は、加工製品ページの番号です。

## 2. 案件ページの形（下書き）

旧文書から抜き出した下書きです。

- **案件ページは、顧客から発注書が届いたときに作ります。1つの発注書＝1ページです。**

  > 2026-09-18 利用者:「発注書は一ページ一発注書で
  > 問題ない」

  - 置き場は、`受注／年／月` です（年月は、発注日で決めます）。
  - 出どころ: ユースケース:117・121-127
- **原本PDFを持つのは、顧客の発注書だけです**（弊社の部材発注書には、持たせません）。
  - 原本PDFと、「読んだまま」の写しを、畳んで（折りたたんで）残します。
  - ヘッダはタグ、明細は表にします（部品ごとに1行です）。
    タグは、本文に「名前：値」の形で書く項目です。
  - 出どころ: ユースケース:46-52・解体前 l.274-277
- **機械の読みは、人が確かめます。**
  - 抽出の結果は検証されないので、内容の確認は人が行います。
  - 画面も「内容を確認してください」と告げます。
  - 出どころ: ユースケース:186

⚠ **いま**: 実装済みです。

- 案件ページは、テンプレート「案件ページ」を写して作ります。
  並びは、原本PDF のファイル表示 → 「顧客の発注書（読んだまま）」の枠 → `案件明細表`、です。
- 題の頭に【顧客】が付きます（`【顧客】発注書 <発注書番号>`。【顧客】は 2026-10-16 から、「発注書」は 2026-10-19 から。それまでは「受注」）。
- 置き場は `記録／年／月／依頼` です（2026-10-16 から）。整理で、ここへ収めます。
  - 年月は、**案件ページを作った日**で決めます（発注日ではありません）。
    上の本文の `受注／年／月`（発注日）とは違います。
  - トップ直下の「案件」は、案件残表などの作業面として残ります。作業面は、人が作業に使うページです。
  - それより前に収めた案件ページも、2026-10-16 に、同じ年月のまま `記録／年／月／依頼` へ移しました（職場の 52枚。古い年月のフォルダはごみ箱へ）。
- 検算は、サーバーのプログラム（Go）で計算して、✓／⚠ を足元に出します。
  機械の読みを、同じ機械に検算させないためです。

    - 探すのは、**受注の `発注元` と同じ客先の加工製品ページだけ**です。発注元の無い受注は、結びません。

    2件以上なら、結びません（同じ図番で、別の品物が実在するためです）。
  - 人が入れた値は、触りません。
  - 次のときは、結びません（次に開いたときに結びます）。

    - 道具（ワンノートの製造 など）が、その案件ページの編集権を握っているあいだ（`editlock.Locks.EditorOpen`）
  - 画面は、2026-10-12 から編集権を握りません。

  - 書くときは、ページごとの書き込みのロックを取ります（`cms.RewriteBody`）。

  - 結んだことは、監査（誰が何をしたかの記録）に残ります（`order-item.linked`）。
- **受注変更の記録の仕方**: 【考察】通信記録処理 §4.3 に、一案があるだけです。
