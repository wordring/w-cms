## 1. ZIP の展開（←【要求】添付 §8）

⚠ **メールの取り込みだけが ZIP を展開します。** 展開してよい根拠は
**受信原本（`.eml`）が ZIP を持っていること**なので、⚠ **人が手で落とした ZIP は展開しません。**

⚠ **いま**: 展開そのもの（上限3つ——1件の大きさ・件数・合計）はコアの `cms.ExpandZip` が
持ちます（[【要求】添付.md](../../【要求】添付.md) §8）。

> 「添付ファイルのPDFについて、ZIPの場合まとめて解析するオプションが欲しいです」——利用者（2026-09-30）

⚠ **いま**: 東邦の拡張が載っていれば、メールの ZIP の隣に「🤖 中のPDFをまとめて解析（N件）」が出ます。中のPDFを
中のパスの順に1つずつ解析し（1件ずつの「🤖 解析」と同じ）、最後に1つの知らせにまとめます。解析済みのものは飛ばします
（解析し直すのは1件ずつの「🤖 再解析」で）。どれがどの ZIP から出たかは添付の目録（`cms.ZipMembersOf`）が持ちます。

## 3. メールの部品——表示・送信・下書き（2026-09-30）

> 「メール表示、メール送信、メール編集などを部品化したら良いと思います。FAXなどもいずれ部品化したいです」
> 「メール編集は下書きのことです」——利用者（2026-09-30）

⚠ **いま**: 送る欄は1つの部品（`assets/mail-compose.js`）で、返信・新しいメール（メール一覧の「✉️ 新しいメール」）・
発注書の送信が同じ欄を使います。違うのは**用件**ごとの初期値と送る前後の仕事だけ（決定の経緯は
[【考察】メールの部品化.md](../../考察/【考察】メールの部品化.md)）。
⚠ **いま**: 「📝 下書きに保存」で通信箱にページができ、未処理の一覧とメール一覧に「📝 下書き」で並びます。
開くと送る欄が開いていて、直して保存し直すか、送れます（送ると送った日の控えができ、下書きはごみ箱へ）。
⚠ **いま**: 本文の初期値に、連絡帳の**ログイン名と同じ題の人**の「メールの署名」が入ります。署名は人のページの見出し
「メールの署名」（発注書・見積書の差出人は「発注書の署名」）の下に書きます——見出しの節でも、ふつうの見出し（見出し2など）でもよい
（2026-10-02 から。それまでは節の形しか読まず、見出し2で書いた署名が効かなかった）。⚠ ログイン名が人のページの題と違うと
（例: ログイン名 `a`）、メールの署名は入りません。

- メールの署名（と発注書・見積書の差出人の初期値）は、**ログイン名と同じ題の連絡帳の人のページ**から読む——**ログイン名を人の
  ページの題に合わせる**（2026-10-02 問いへの答え——人のページにタグで書く案・送る欄で選ぶ案は採らなかった）。
⚠ **いま**: メールの表示の部品と FAX はまだです。

## 4. 対応はメールのページで選ぶ（2026-09-30）

> 「そのメールへの対応が終わったかどうかは、受信フォルダではなく、メールページで選択したいです」——利用者（2026-09-30）

⚠ **いま**: 通信記録のページ（閲覧モード）の頭に「対応: 未処理・済・不要」があり、押すと付け替わります（`未処理` で
印が外れて未処理の一覧へ戻る）。通信箱の未処理の一覧の「済」「不要」も残っています。下書きには出しません。

## 5. ファイルの ID で添付を足す（2026-10-01）

> 「メール送信にファイル添付が無いです。PDFや画像の表示にIDが在ると思いますが、それをクリック程度で簡単にクリップボードへ
> コピーできると、ほかの場所にスラッシュメニューから貼りつけたり、メールに添付できるのでは」——利用者（2026-10-01）

⚠ **いま**: 送る欄の「📎 添付」の下に ID の欄があり、ファイル表示・写真の「🔗 ID」で写した ID を**貼った時点で**
（Enter・「添付に足す」でも）印付きで並びます。いくつでも（空白・「,」区切り）。同じファイルは1つにまとめ、
引けない ID（読めない・無い・ID の形でない）は理由を出して欄に残します。足した添付は下書きにも残り、送るときに渡ります。
w-cms の外のファイル（手元のディスク）を直に添える道はまだありません——先にどこかのページへ上げて ID で足します。

## 5a. 送るときに作るPDFも添付に並べる・宛先を連絡帳から選ぶ（2026-10-03 利用者の言葉から下書き）

> 「見積書ページのメール作成欄は見積書PDFも他と同じように表示し、ただし最初から添付に入っているようにするとわかりやすい」
> 「宛先は連絡帳から候補を取得してコンボボックスで出して欲しい」——利用者（2026-10-03）

⚠ **いま**:
- 見積書・発注書の送る欄の「📎 添付」のいちばん上に「御見積書 ○.pdf（送るときに作ります）」（発注書は「発注書 ○.pdf」）が
  **印つき**で並ぶ。PDF は送る瞬間に作る（いつも最新の明細で）——印を外せば作らずに送る（`ComposeDraft.Generated`・
  `skip_generated`）。下書きを開き直しても並ぶ。
- 宛先・CC の下に「連絡帳」の欄（打って絞れる候補の一覧）。候補は連絡帳の組織と人のメールアドレス（読めるものだけ・
  「名前（会社） <アドレス>」）。選ぶと「宛先へ」「CCへ」で選んだ欄の末尾にアドレスが足される（同じアドレスは足さない）。
  宛先の欄は今までどおり手でも書ける（`GET /api/contacts/addresses`・`ext/comm/contacts/address_book.go`）。

## 5b. パソコンのファイルを添える（2026-10-04 利用者の言葉から下書き）

> 「新しいメールを作成するときに、ローカルコンピュータから添付したいです。返信などの時も同様です」——利用者（2026-10-04）

- 新しいメールでも、返信などでも、送る欄から**手元のパソコンのファイル**を添えられる。

⚠ **いま**（`assets/mail-compose.js`・`POST /api/mail/attach`・`ext/comm/mail/compose_attach.go`）:
- 送る欄の「📎 添付」の下に「💻 パソコンから添付」（いくつでも選べる）。**送る欄へのドロップでも**足せる（本文へのドロップ＝
  ページの添付にはならない）。どの用件の送る欄にも出る（返信・新規・見積書・発注書・見積依頼書）。
- 置き場は**下書きのページ**——まだ下書きでなければ先に下書きを保存してから（通信箱の未処理に並ぶ）、そこへ添付として置き、
  印つきで並べ、下書きにも書き留める（開き直しても並ぶ）。送れる種類は ID で足す添付と同じ（PDF・画像・設定の
  `attachment_extensions`・`.eml`）。PDF の先頭・画像の種別と位置情報は添付の口と同じに確かめる。1つ `max_upload_mib` まで・
  送るときは合計 25MB まで（今までどおり）。
- 送ると、下書きはごみ箱へ行くので、**下書きに置いたファイルを送信の控えのページへ写し**、控えのリンクを写した先へ付け替える
  （w-cms の中のほかのファイルは今までどおり元のページを指す）。写せなかったら下書きを残し、送れたことと一緒に知らせる。

## 6. メールから作るページを選ぶ（2026-10-01 利用者の言葉から下書き）

> 「メールから作るボタンは「受注ページ作成」「加工製品ページ作成」「返信」ページのタイプは増える可能性があるので「受注ページ」
> 「加工製品ページ」をコンボボックスで選択して「作成」ボタンを押せばいいかも」——利用者（2026-10-01）

- メールの記録から作るページの種類は、選ぶ欄で選んで「作成」で作る（種類は増えていく）。

⚠ **いま**: 通信記録のページ（閲覧モード）に「作るページ [選ぶ] [作成]」が出ます。選べる種類は**拡張が登録します**
（`comm.RegisterRecordMaker`・`GET /api/record-makers`・`POST /api/record-make`——通信は種類の名前も作り方も知らない）。
東邦の拡張が載っていれば、受信のメールに「受注ページ」（🤖 本文を読む）と「加工製品ページ」（テンプレートから空のページを作って
編集モードで開く・Gemini は呼ばない）。送信の控え・下書きには出ません。書けない人には選ぶ欄を出さず、もう作ったページの印
（✓ 受注・✓ 加工製品）だけを出します。「✉️ 返信」はページを作らないので、選ぶ欄に入れず別のボタンのまま。
