# 【ユースケース】受注と進捗管理

このドキュメントでは、**w-cms** における顧客発注書（および弊社発注書）をベースとした、部品ごとの進捗管理ユースケースと語彙（`data-type` マーカー付き標準HTML）の設計仕様を定義します。

---

## 1. 目的
受注の記録は、顧客から発注書が届いたタイミングで作成されます。顧客は一度の取引で複数枚の発注書を発行することがあるため、システムは1つの「受注記録ページ（ページIDを持つHTML）」の中に複数枚の発注書PDF（原本）と、それぞれに紐づく複数の部品（図面）情報を記録できるようにします。
また、部品ごとに製造・加工・納品の進捗ステータスを追跡可能にし、仮想的な進捗管理ダッシュボードを自動生成します。

---

## 2. 語彙の設計仕様

### 2.1. 1ページへの複数発注書の記録
1つのHTMLファイル内に、複数の `<section data-type="client-order">` ブロックを自由に配置します。
各発注書は、それぞれ一意の発注書番号をヘッダ `<dl>` の `<dd>` に持ちます。

### 2.2. 部品の発注書番号へのぶら下がり（明細表）
発注書の中に記載されている部品は、業務文書ブロックの直下に置く明細表
`<table data-type="client-order-items">` の各行として記述します。
パーサーおよびデータベースはこの入れ子関係を読み取り、`client_order_items` の各行に親の `order_no` を記録して「発注書ナンバーにぶら下がる」リレーションを構築します。

PDF原本がある場合は、容器 `<section data-type="file" data-src="…">` で包みます
（`pdf_path` は祖先の容器の `data-src` から `ClosestFileSrc` で読まれます）。
容器は任意なので、ファイルの無い受注は業務文書ブロックだけを置けば構いません。

**値は属性ではなく要素の中身**にあります（`dd`／`td` のテキスト）。項目の鍵も `dt` の項目名・
`th` の見出しという**見える文字そのもの**です。これにより閲覧側はJavaScriptなしで読めます。

```html
<!-- 顧客発注書1 (発注書番号: PO-A100) -->
<section data-type="file" data-src="PO-A100.pdf">
    <p>📎 <a href="/data/master/00/000002/PO-A100.pdf">発注書_PO-A100.pdf</a></p>
    <section data-type="client-order">
        <dl>
            <dt>発注書番号</dt><dd>PO-A100</dd>
            <dt>発注元</dt><dd>トーア</dd>
            <dt>発注日</dt><dd>2026-06-18</dd>
        </dl>
        <!-- 部品が発注書番号 PO-A100 にぶら下がる -->
        <table data-type="client-order-items">
            <tbody>
                <tr><th>品番</th><th>品名</th><th>単価</th><th>数量</th><th>状態</th></tr>
                <tr><td>SHAFT-01</td><td>シャフトA</td><td>8000</td><td>10</td><td>未着手</td></tr>
                <tr><td>SHAFT-02</td><td>シャフトB</td><td>12000</td><td>5</td><td>加工中</td></tr>
            </tbody>
        </table>
    </section>
</section>

<!-- 顧客発注書2 (発注書番号: PO-A200、同じページに記録) -->
<section data-type="file" data-src="PO-A200.pdf">
    <p>📎 <a href="/data/master/00/000002/PO-A200.pdf">発注書_PO-A200.pdf</a></p>
    <section data-type="client-order">
        <dl>
            <dt>発注書番号</dt><dd>PO-A200</dd>
            <dt>発注元</dt><dd>トーア</dd>
            <dt>発注日</dt><dd>2026-06-18</dd>
        </dl>
        <table data-type="client-order-items">
            <tbody>
                <tr><th>品番</th><th>品名</th><th>単価</th><th>数量</th><th>状態</th></tr>
                <tr><td>GEAR-01</td><td>ギヤA</td><td>15000</td><td>2</td><td>検査中</td></tr>
            </tbody>
        </table>
    </section>
</section>
```

> **弊社発注書（仕入側）も同じ形**です。`data-type` が `our-order` ／ 明細が `our-order-items` に
> 変わり、ヘッダの `client-name` が `supplier-name`（発注先）になります。
> 状態の選択肢は `未納品` / `納品済` の2つです（[vocab.go](../internal/cms/vocab.go)）。

---

## 3. 進捗ステータス管理

### 3.1. 部品ステータス（明細表の `status` 列）
部品ごとに以下のステータス値を設定・更新できます（`<th>` の列のセル）。
*   `未着手` (初期状態)
*   `加工中`
*   `検査中`
*   `納品済`

選択肢は語彙レジストリ（[vocab.go](../internal/cms/vocab.go) の `client-order-items`）が持ち、
エディタは enum 列としてセルに選択肢メニュー（`#enum-menu`）を出します。
一覧に無い値も**拒否せず**保存し、型不一致として赤く印を付けるだけです。

### 3.2. 仮想進捗管理ページでの可視化（**構想・未実装**）
HTMLファイルを個別に編集して保存すると、データベース内のインデックス情報（`client_order_items` の各行の `status`）が同期されます（**ここまでは実装済み**）。
これを元に「仮想的な進捗管理ページ」で以下のような進捗状況を俯瞰表示する構想です。

```
【受注進捗管理ボード】
----------------------------------------------------------------------
発注書番号: PO-A100 (顧客: トーア, 受注日: 2026-06-18, ページID: 000002)
 ├─ [未着手] シャフトA (SHAFT-01) × 10個
 └─ [加工中] シャフトB (SHAFT-02) × 5個

発注書番号: PO-A200 (顧客: トーア, 受注日: 2026-06-18, ページID: 000002)
 └─ [検査中] ギヤA (GEAR-01) × 2個
----------------------------------------------------------------------
```

これにより、ユーザーは各図面（部品）のページから進捗を更新するだけで、自動的に全体の発注書ベースの進捗ボードが最新に保たれるようになります。
また、部品単位でどの発注書に紐づいているかが一目で判別できます。
