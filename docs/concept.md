# w-cms ソフトウェアコンセプト・設計仕様書

このドキュメントでは、**w-cms** の基本コンセプトである「HTMLファイルとデータベースの双方向連携」および、具体的なユースケース（部材価格の推移、製造プロセスの記録、写真付きマニュアル等）の仕様について定義します。

---

## 1. コア・コンセプト：双方向データ連携

w-cms は、単なる静的ファイルの保存システムではなく、**「HTMLファイル（ドキュメント）」と「関係性データベース（SQLite）」が双方向でデータをやり取りするシステム**です。

```mermaid
graph LR
    HTML[アップロードされたHTML<br>例: 発注書/納品書/作業日報] -- 1. 解析・登録 (Extract) --> DB[(SQLite DB)]
    DB -- 2. 過去の記録を呼び出し (Load) --> Page[部材詳細ページ/製造マニュアル]
```

### ① インプット（ファイルからDBへ）
アップロードされたHTML（発注書、納品書、作業日報など）の記述内容をパースし、データベースへ構造化データとして登録します。
*   **例**: 作業日報HTMLから「どの機械で、どんな加工を、何分行ったか」を自動抽出し、DBの製造ログテーブルにインサートします。

### ② アウトプット（DBからファイル・画面へ）
特定の詳細ページ（部材紹介や製造マニュアルなど）を表示・生成する際に、データベースから関連する過去の履歴データを動的に読み出して、ページ内にレンダリングします。
*   **例**: 特定の部材ページを開いた際、DBから過去の製造ログを集計して「平均加工時間」や「使用した機械」を表示し、見積もりの参考データを出力します。また、作業工程の写真と説明文を組み合わせた「製造マニュアル」を生成します。

---

## 2. 具体的なユースケース

### 2.1. 部材の価格推移管理
仕入れた部材の価格推移を自動でトラッキングし、仕入れ価格の変動を可視化します。
*   **インプット**: 発注書・納品書のHTMLをアップロード。
*   **処理**: HTML内の部材タグ（例: `<m-item name="ボルトA" price="120">`）から、価格と日付をDBへ保存。
*   **アウトプット**: 部材詳細ページで、過去の価格推移リストやグラフを表示。

### 2.2. 製造プロセスの記録と見積もり算出への活用【新規】
製造時の「設備・加工内容・所要時間」を記録し、将来の製品見積もり（コスト計算）の精度向上や自動化に役立てます。
*   **インプット**: 日々の「作業日報」や「製造記録」のHTMLをアップロード。
    *   例: `<m-process machine="旋盤A" method="荒削り" duration="35" item="シャフトB">` のような情報をHTMLに記載。
*   **処理**: 使用した機械、加工方法、かかった時間（分）をデータベースに保存。
*   **アウトプット**: 
    *   製品ページを開いた際に、「この製品を作るのに平均でどの機械を何分使い、どの加工が必要か」のデータを集計して表示。
    *   加工時間 × 機械・人件費レート から、自動で見積もり参考価格を算出。

### 2.3. 写真付き製造マニュアルとしての活用【新規】
製造現場での工程ごとの作業内容やコツを、写真付きの「製造マニュアル」としてWeb上で一元管理・共有します。
*   **インプット**: 各工程の写真（画像ファイル）を含んだHTMLをアップロード。
    *   画像ファイル自体は w-cms の物理ストレージ（`data/master/` 内の該当フォルダ）に保存。
*   **処理**: 画像の保存パスと、その工程の説明文・タグ（例: 「セット方法」「注意点」など）をデータベースにインデックス登録。
*   **アウトプット**: 
    *   部材名や製品名で検索すると、写真がステップ順に並んだ美しい「Web製造マニュアル」が自動構成されて表示される。
    *   自宅と会社の双方で、スマホやタブレットから最新のマニュアルをいつでも確認可能。

## 3. 実装に向けたデータモデル設計（案）

これらのユースケースを実現するために、今後拡張が想定されるデータベーステーブルの構造案です。

### ① `items` テーブル（部材マスタ）
*   `id` (TEXT, PRIMARY KEY): 部材・製品コード
*   `name` (TEXT): 部材・製品名
*   `spec` (TEXT): 仕様・規格

### ② `price_history` テーブル（価格履歴）
*   `id` (INTEGER, PRIMARY KEY AUTOINCREMENT)
*   `item_id` (TEXT, FOREIGN KEY): 部材ID
*   `price` (INTEGER): 単価
*   `source_page_id` (TEXT, FOREIGN KEY): 抽出元HTMLのページID
*   `recorded_at` (DATE): 発注日・納品日

### ③ `manufacturing_logs` テーブル（製造プロセスログ）【新規】
*   `id` (INTEGER, PRIMARY KEY AUTOINCREMENT)
*   `item_id` (TEXT, FOREIGN KEY): 対象の製品ID
*   `machine_name` (TEXT): 使用した機械（例: 「旋盤A」「マシニングセンタB」）
*   `process_method` (TEXT): 加工方法（例: 「外径削り」「穴あけ」）
*   `duration_minutes` (INTEGER): 加工時間（分）
*   `operator_name` (TEXT): 作業者名
*   `source_page_id` (TEXT, FOREIGN KEY): 抽出元の日報ページID
*   `recorded_at` (DATE): 作業日

### ④ `process_photos` テーブル（マニュアル用画像情報）【新規】
*   `id` (INTEGER, PRIMARY KEY AUTOINCREMENT)
*   `item_id` (TEXT, FOREIGN KEY): 製品ID
*   `step_number` (INTEGER): 工程順序 (例: 1, 2, 3...)
*   `image_path` (TEXT): 画像ファイルの物理保存パス (例: `data/master/xx/xxxxx/step1.jpg`)
*   `description` (TEXT): その工程の説明・注意点
*   `source_page_id` (TEXT, FOREIGN KEY): 抽出元のマニュアル元ファイルID

## 4. 今後の開発ロードマップ

1.  **HTML解析機能（parser.go）の拡張**:
    *   部材価格タグ、製造プロセス情報（機械・時間）、および画像タグ（`<img>`）をHTMLから抽出できるようにパーサーを強化。
2.  **データベース（sqlite.go）の拡張**:
    *   上記の `items`、`price_history`、`manufacturing_logs`、`process_photos` テーブルを初期化処理に追加。
3.  **データ同期ロジック（sync.go）の拡張**:
    *   HTMLアップロード時に、複数の異なるユースケースデータ（価格、日報ログ、マニュアル用画像）を判別し、それぞれ適切なテーブルへ保存・更新するロジックを実装。
4.  **UI/描画機能（handler.go / テンプレート）の拡張**:
    *   アップロード一覧画面の他に、「部材ごとの価格推移・見積算出画面」および「写真付き製造マニュアル表示画面」を新設。
