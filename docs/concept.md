# w-cms ソフトウェアコンセプト・設計仕様書

このドキュメントでは、**w-cms** の基本コンセプトである「ファイルベースのドキュメント管理と、データベースによる可変タグ・原価情報の双方向連携」の仕様について定義します。

---

## 1. コア・コンセプト：ファイルベース保存とDBインデックスの双方向連携

w-cms は、ドキュメントの本文データをデータベースに格納しません。**「ドキュメントの本体はすべてファイルシステム（ファイルベース）に保存し、検索・集計に必要な可変タグや取引データのみをデータベース（SQLite）にインデックス登録する」**という設計を採用します。

```mermaid
graph TD
    subgraph Editor [Notion風ブロックエディタ]
        E1[ドキュメント編集]
    end

    subgraph Storage [ファイルシステム (物理ストレージ)]
        F1["data/master/xx/xxxxx/document.json (エディタ用JSON)"]
        F2["data/master/xx/xxxxx/index.html (閲覧用HTML)"]
    end

    subgraph DB [SQLite データベース]
        T1["page_tags テーブル (可変属性名:値)"]
        T2["各種取引テーブル (価格/製造ログ等)"]
    end

    E1 -- 1. ファイル保存 (Save) --> F1
    E1 -- 2. 差分抽出・登録 (Index) --> DB
    DB -- 3. 動的データを反映 (Load) --> E1
    F1 -- 4. 編集時にロード --> E1
```

### ① ファイルベースの保存（ドキュメント本体）
Notion風エディタで編集されたドキュメントは、以下の2つのファイルとして物理ストレージに保存されます。
*   **`document.json`**: ブロックの構造やテキスト本文など、エディタが再読み込み・編集するために必要な生データ。
*   **`index.html`**: ブラウザで高速にプレビュー表示するためのレンダリング済みHTMLファイル。
*   *保存先フォルダの例*: `data/master/26/260603-103/`（IDに基づき自動分散）

### ② 可変タグと原価データのDB登録（インプット）
保存処理と同時に、エディタ内の「データブロック」から情報を抽出し、データベースへインデックス情報として登録します。
*   **可変タグ（キー・バリュー）**: 発注書や見積書内の「名前：値」のペア（例: `発注元: 株式会社トーアスポーツマシーン`）を `page_tags` テーブルに登録します。
*   **原価・取引データ**: 材料見積、外注見積、作業日報から抽出した数値データをそれぞれの専用テーブル（価格履歴、製造ログなど）に反映します。

### ③ DBからファイル・画面への動的反映（アウトプット）
ドキュメントを読み込む際、静的なコンテンツ（`document.json`の内容）の上に、データベースから動的ブロック（原価算出や価格推移など）のデータを取得してリアルタイムに重ね合わせて表示します。

## 2. 具体的なユースケースとブロック構成

### 2.1. 可変タグブロックによる自由な属性登録（各種書類から）
取引先によって異なるヘッダー項目（支払条件、希望納期、発注者など）を、データベースの設計変更なしで自由に登録・検索します。
*   **入力（ファイルへ保存 ＆ DBへインデックス）**:
    *   エディタ内の `「可変タグブロック」` で `[ 項目名 ] : [ 値 ]` を動的に追加・編集。
    *   ドキュメント全体は `document.json` に保存され、タグのペアのみが DB の `page_tags` テーブルへ保存されます。
*   **検索・出力**:
    *   DBの `page_tags` を検索して該当するドキュメントファイルを特定し、ファイルシステムから直接 `document.json` をロードしてエディタに表示します。

### 2.2. 材料コスト・外注加工費の推移（各種見積書から）
材料屋や加工業者から取得した見積書ファイルを保存し、原価データをDBでトラッキングします。
*   **保存**: 見積書ドキュメントファイルを物理保存し、中の `「材料/外注見積ブロック」` の数値のみを DB へ反映。
*   **出力**: 製品のWiki詳細ページに `「コスト推移ブロック」` を置くと、DBから過去の仕入価格の変動を引っ張ってきて動的表示します。

### 2.3. 顧客発注と原価・利益の動的算出（顧客発注書・各種見積書から）
お客様からの発注書ファイルを保存し、見積書データと突き合わせて製品ごとの利益率を算出します。
*   **保存**: 顧客発注書ファイルを物理保存し、受注金額・数量データを DB へ反映。
*   **出力**: 製品ページ内の `「原価・利益算出ブロック」` が、DBの「最新材料見積」＋「最新外注見積」＋「自社加工費」を自動集計し、販売単価と比較した粗利益率を表示します。

## 3. 実装に向けたデータモデル設計（案）

ドキュメント本体はファイルとして保存されるため、データベースは「ファイルへのポインタ（参照）」と「検索・集計用インデックス」に特化した構造になります。

### ① `pages` テーブル（ドキュメントのインデックス）
*   `id` (TEXT, PRIMARY KEY): ページID (例: `"260603-103"`)
*   `title` (TEXT): ページタイトル
*   `file_path` (TEXT): 物理ファイルの保存先パス (例: `"data/master/26/260603-103/"`)
*   `updated_at` (DATETIME): 更新日時

### ② `page_tags` テーブル（可変属性インデックス）【可変タグ式】
*   `page_id` (TEXT, FOREIGN KEY): `pages.id` に紐づく
*   `name` (TEXT): 属性の名前（キー） (例: `"発注元"`, `"希望納入日"`, `"支払条件"`, `"発注者"`)
*   `value` (TEXT): 属性の値 (例: `"株式会社トーアスポーツマシーン"`, `"2026-06-10"`, `"通常"`, `"紀平"`)

### ③ `client_orders` テーブル（顧客発注インデックス）
*   `id` (INTEGER, PRIMARY KEY AUTOINCREMENT)
*   `item_id` (TEXT): 製品ID（図面番号など）
*   `client_name` (TEXT): 取引先顧客名
*   `price` (INTEGER): 受注単価（売上）
*   `quantity` (INTEGER): 数量
*   `source_page_id` (TEXT, FOREIGN KEY): 抽出元ドキュメントのページID

### ④ `material_costs` テーブル（材料仕入見積インデックス）
*   `id` (INTEGER, PRIMARY KEY AUTOINCREMENT)
*   `material_name` (TEXT): 材料・部材名
*   `supplier_name` (TEXT): 材料屋名
*   `cost` (INTEGER): 材料単価（原価）
*   `source_page_id` (TEXT, FOREIGN KEY): 抽出元ドキュメントのページID

## 4. 今後の開発ロードマップ

1.  **エディタの保存・ロード機構の設計**:
    *   Notion風エディタのブロックデータを `document.json` としてファイルシステムに書き込み、再読み込みするフロント・バックエンド連携の実装。
2.  **データベース（sqlite.go）のインデックス化**:
    *   データベースはインデックス（`pages`、`page_tags`、取引データ等）のみを保持するようスキーマを調整。
3.  **可変タグ同期ロジック（sync.go）の実装**:
    *   `document.json` 保存時に、記述された可変タグブロックの情報をDBの `page_tags` に自動でUPSERTするロジックの実装。
4.  **動的ブロックとDB連携の実装**:
    *   ファイルからロードされたドキュメントを表示する際、動的反映ブロック（原価計算やグラフなど）がリアルタイムにDBから最新値をクエリして画面を更新する仕組みの構築。
