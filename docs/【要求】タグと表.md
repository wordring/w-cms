## 2. 形

```html
<dl data-type="tags">
  <dt>仕入先</dt><dd>みなと商店</dd>
  <dt>発注日</dt><dd>2026-09-23</dd>
  <dt>発注担当</dt><dd>000031-a1b2</dd>
</dl>
```

- **本文に書きます。** 本文が正本で、DBは派生です。
- **1ページに何枚でも**、**同じ名前を何個でも**置けます（`メールアドレス` が代表例——
  1つの連絡先ページに窓口・担当・共有アドレスが並びます）。
- ⚠ **`data-type="tags"` の無い素の `dl` は、索引に入りません**（2026-09-18 決定
  「素の定義リストは DBから外しましょう」）。見た目は同じなので、**書いたのに検索に
  掛からない**という気づきにくい形になります。
- ⚠ **参照として読むのも、このタグの中だけ**です。素の `dl` まで見ると、
  発注書番号 `250401-203` が「6桁-英数字」に当てはまって**参照に化けます**。

### 空欄の形

⚠ **サニタイズは空の `<dd>` に `<br>` を入れます**——`<dd><br/></dd>`。
`<dd>([^<]*)</dd>` だけで探すと**空欄を素通り**します（2026-09-11 に `客先` を3枚
取りこぼしました）。読み書きは `replaceFirstFieldValue` を通すこと（`<br>` も空と扱う）。

## 3. 型は**名前**で決まる

> 2026-09-06 ユーザー決定:「名前が『受信元』であれば値は『参照』」

⚠ **`data-type` で型を明示する案は採りませんでした。** コピペで型が落ち、
**100ページに同じ属性を書く**ことになるためです。

**正本は [config/settings.json](../config/settings.json) の `vocabulary`**:

```json
"vocabulary": {
  "単価":   { "type": "number" },
  "発注日": { "type": "date" },
  "受信元": { "type": "ref" },
  "状態":   { "type": "enum", "values": ["未着手", "加工中", "納品済"] }
}
```

- ⚠ **Goコードに既定値はありません。** 設定が壊れていると**起動を止めます**
  ——黙って既定値で上書きすると、運用者が足した語が消えるためです（仕様）。
- ⚠ **語を足したらDB再構築**（`POST /api/rebuild-db`。再起動は不要）。
  忘れると**索引に載らないまま**で、エラーは出ません。
- **設定はGit管理**なので、語を足せば `git pull` で全環境へ届きます。
- ⚠ **名前が型を決める＝システム全体でひとつ**です。`発注済` を `bool` にしたら、
  **どのページのどのタグも** `bool`。揺れないのが利点ですが、
  **場所によって意味を変えることはできません**。

### 型の一覧（9種）

| 型 | 何を表すか | 畳み方（`norm_value`） |
|---|---|---|
| `text` | 自由文 | 全角英数・半角カナ・直径記号を畳む。⚠ **長音には触らない** |
| `code` | 番号・記号（図面番号・品番・発注書番号） | `text` に加えて**空白・ハイフン類・長音・大小**も畳む |
| `number` | 数 | 数として格納（⚠ 文字列にしない。§5） |
| `date` | 日付 | ISO（`2026-09-23`） |
| `datetime` | 日時 | ISO |
| `enum` | 決まった選択肢 | `text` と同じ（2026-09-14 に畳んだ） |
| `image` | 画像 | — |
| `ref` | **他のページ／ブロックを指す**（`ページID-ブロックID`） | — |
| `email` | `名前 <アドレス>` | **アドレスだけ** |

⚠ **`text` と `code` の違いは畳む強さだけ**です。`レーザー` は `text` ならそのまま、
`code` なら `レ-ザ-` になります——**機械が書く名前に `NormalizeCode` を使わないこと**。

### 引き方

| 口 | 何で引くか |
|---|---|
| `PagesByTag` | **生の値**で完全一致 |
| `PagesByTagLoose` | **畳んだ値**で一致（大小・全角・区切りの揺れを越える） |

⚠ **2段にせず、呼ぶ側が選びます。** 畳んだ文字列だけを返す口（`NormalizeForLookup`）は
2026-09-15 に撤去しました——`norm_value` が宣言型を持たなくなった日から、
**文字列で引くと `number` のタグがエラーにならず0件**になるためです。

## 5. ⚠ `norm_value` は宣言型を持たない——型は**値**が持つ

> 2026-09-15 ユーザー:「norm_value は文字列、数値、時刻のような種類が考えられます」

SQLite は**宣言の無い列で、値ごとの格納クラスを保ちます**。`TEXT` と宣言すると
数まで文字列に化け、**`"8000" < "900"`** になります（実測）:

| 宣言 | 並び |
|---|---|
| `TEXT` | `12.5, 8000.0, 900.0, abc` ⚠ |
| **宣言なし** | `12.5, 900, 8000, abc` ✓ |

混ざっても平気なのは ①並びが格納クラスのグループ順で範囲が重ならない
②問いは必ず `name` で絞り、**名前が型を決める**ためです。

⚠ **代償は「型を取り違えると、エラーにならず0件」。** だから**束ねる形を
`tagNormBind` の1か所**に閉じ、**書き手（`insertVocabEntry`）と読み手
（`PagesByTagLoose`）が同じ関数を通ります**。
⚠ **範囲で引く口を足すときも、同じ関数を通すこと。**
⚠ 整数は整数の格納クラスへ（`REAL` だと `3` が `3.0` になります）。

番人は [page_tags_norm_type_test.go](../internal/cms/page_tags_norm_type_test.go)。

### ⚠ 畳めなかったタグは、並べると先頭・絞ると消える

`date` 型のタグに `未定` と書いた行は、`date` として畳めないので `norm_value` は **NULL** です
（生の値は正本として残る）。

| 書き方 | `未定` の行 |
|---|---|
| `ORDER BY norm_value` | **先頭に来る**（SQLite は NULL を最小として並べる） |
| `WHERE norm_value <= ?` | **黙って消える**（NULL の比較は偽） |

**正反対の振る舞いが同じ列から出ます。** ⚠ **日付で並べる・絞るビューを作るときは
`norm_value IS NOT NULL` を明示し、畳めなかった値を別枠で必ず見せること**——
黙って落とすと「納期が書いてあるのに一覧に出ない」になります。

## 6. 揺れを畳む

| 何を | どこで | 規則 |
|---|---|---|
| 全角英数・半角カナ | `NormalizeText` | NFKC |
| **直径記号** | 設定 `char_folding` | `Φ ϕ ⌀ Ø ø Ф ф` → `φ`。⚠ **NFKC では畳めません**（別系統の文字）。⚠ **足したらDB再構築** |
| 機械が書き起こす**名前** | `NormalizeNameForIngest` | 書く**時点**で NFKC（どの名前に掛けるかは拡張が決める） |
| 社名の法人格 | `cms.FoldCompanyName` | 設定 `company_forms` |

⚠ **機械が書く名前に `NormalizeCode` を使わないこと**——`レーザー` が `レ-ザ-` になります。
⚠ **メールの件名には掛けません**（届いたままが正本）。

拡張が名前を書くときの決まり（社名を書く口を揃えるなど）は、拡張の【要求】（[拡張/](拡張/)）に
書きます（2026-09-27 に移した・[開発方針 §0](開発方針.md)）。

## 7. 参照タグ（`ref`）

値は **`ページID-ブロックID`**（例 `000031-a1b2`）。

- **表示のとき**にリンクになります（`ref_render.go`。本文は書き換えません）。
- **宙ぶらりん**（指す先が無い）は**薄赤**で出ます。
- ⚠ **飛ぶ先は常に本文のブロック**（`#<data-id>`）です。添付そのものを指す経路はありません
  ——だから**添付の識別子もブロックIDと同じ4桁**（ファイル名＝URL＝`data-id` の3役）。
- ⚠ **指し先は「消えないもの」にすること。** 人が消せるブロックを指すと、消した日に
  宙ぶらりんになります（業務での当て方は拡張の【要求】）。
- ⚠ **型が `ref` であることが、リンクにする唯一の条件**です。値の形だけでは参照と番号を
  見分けません（2026-09-04 の事故の教訓）。⚠ 2026-09-21 に `資料` 列が `text` のままで
  **押して飛べなかった**のは、これを忘れていたためです。
- **表のセルも、列の型が `ref` ならリンクになります**（2026-09-20〜・`ref_render.go` の `linkRefCells`）。

## 8. 書くときの決まり

- **項目の鍵は見出しの表示文字**（`<dt>` の文字）。機械キーを本文へ書く属性はありません。
- ⚠ **見た目の印は本文に保存できません**——`class` はサニタイズで落ちます。
  宙ぶらりんの薄赤のように、**表示時に付ける鏡型**で作ります。
- ⚠ **機械が既存ページのタグを書き換えるときは関門が要ります**。`RewriteBody` は
  読んで・変えて・書くので、エディタが開いているとオートセーブと黙って上書きし合います。
  使うのは `editlock.RefuseWhileEditing`（1ページ）か `editlock.Locks.EditorOpen`（まとめ押し）。
  ⚠ `RequireEditLock` は**使えません**（一覧画面のボタンはトークンを持てず必ず409）。
- ⚠ **空欄の意味を決めつけないこと。** 出荷済み・単価の空は「まだ分からない」で、
  `0` を埋めると**人が入れた `0` と見分けが付きません**。
- ⚠ **`/api/load` の出力を `/api/save` へ書き戻さないこと。** `/api/load` は鏡を埋めて
  返し、落とすシリアライザは**ブラウザの `app.js`** です。外から書き戻すと鏡が本文に
  焼き込まれます（2026-09-21 に6枚焼きました）。いまは `cms.StripChrome` が
  **`Sanitize`／`SanitizeReport` の冒頭**で落とします——⚠ **順序がこの守りの全部**です
  （サニタイズは `class` を落とすので、後では印が残っていません）。

## 10. `bool` 型（2026-09-23 決定）

> ユーザー:「発注書ページに『発注済』というタグを足したい…**タグにチェックボックスを
> 使うことは可能ですか？**」「**data-typeがBOOLのタグはチェックボックスを出す**という
> 取り決めはどうですか？」「**BOOL型があると入力が楽です**」（2026-09-23・**足すことは決定**）

### できること・できないこと

⚠ **チェックボックスは本文に保存できません。** サニタイザが `input`・`button`・`select` を
**部分木ごと消します**（本文に偽のログインフォームを書ける穴を塞ぐため。
[本文サニタイズ設計.md](旧文書/本文サニタイズ設計.md)）。

**実体はこうなります**——既に3つ動いている形と同じです:

```
本文に入るもの … 「済」という文字だけ
画面に出るもの … チェックボックス（サーバーが表示のときに足す鏡）
押したとき     … 本文の文字を「済」⇄「空」に書き換える
```

⚠ **いま**: `bool` が無いので、拡張は**選択肢が1つしかない `enum`**（`済` だけ）で偽装し、
チェックボックスを画面側で手書きしています（拡張の【要求】）。`bool` があれば
**宣言がそのまま画面になり**、列を足したときに画面を直し忘れる形が構造的に消えます。

### ⚠ 決めるべきこと——チェックは2状態、データは3状態

```
はい  ／  いいえ  ／  まだ誰も見ていない
              ↑ 外したチェックボックスでは、この2つを見分けられません
```

| タグ | 外れたチェックの意味 | |
|---|---|---|
| `発注済`・`材料発注` | まだ出していない | 問題なし（同じ意味） |
| `検査合格` | ⚠ **不合格なのか、まだ検査していないのか** | 区別できない |

**提案する取り決め**:

> **`bool` は「印」である。** 値は `済` か**空**の2つで、**空は「まだ」**を意味する。
> ⚠ **「いいえ」を積極的に記録したいときは `bool` を使わず `enum`**（`合格`／`不合格`／空）。

### 足すのに要るもの

1. `internal/cms/vocab.go` の `validColumnTypes` に `bool` を1つ
   ——⚠ **ここを足さないと、設定に `bool` と書いた瞬間に起動が止まります**
2. `config/settings.json` の `vocabulary` に `"発注済": { "type": "bool" }`
3. ⚠ **DB再構築**
4. **タグの鏡**（`<dl>` の中にチェックボックスを出す）——⚠ **新しい経路です**。
   いまのチェックボックスは全部**計算ビューの中**にあり、**本文のタグの鏡**はまだ
   ありません。閲覧モードと編集モードの両方で押せる必要があります。

⚠ **`bool` を足すことと、「どのページにどのタグを持つか」は別の話**です。
行から数えれば分かることをタグで二重に持つと、**1行取り消したときにタグが嘘をつきます**
（業務での例は拡張の【要求】）。

## 11. ⚠ タグには「鏡」がありません（2026-09-23）

> ユーザー:「**ENUM型のタグは、リストで選択できますか？列挙する値は、設定できますか？**」

**答えは半分ずつです。**

| 問い | 答え |
|---|---|
| **値を設定できるか** | ✓ **できます**。`config/settings.json` に `{"type": "enum", "values": [...]}` |
| **リストで選べるか** | ⚠ **タグでは選べません**（**表のセルでは選べます**） |

```json
"在籍":   { "type": "enum", "values": ["在籍", "休職", "出向", "退社"] },
"移行中": { "type": "enum", "values": ["確認待ち"] }
```

### ⚠ いま、タグの値に起きること

- ✓ 値が `values` に**在れば** `tag-known`、**無ければ** `tag-unlisted` の印が付きます（色で示す）。
- ✗ ⚠ **候補のボタンは出ません。** 候補メニューは **`#w-editor-content table td`** に
  束ねられていて、**表のセルだけ**が対象です。
- ⚠ **空欄には印を付けません**——「まだ書いていない」は間違いではないからです。

**つまり、タグでは「打ち間違えたら色で分かる」だけ**です。

### ⚠ これは `enum` だけの話ではありません

**同じ `enum` 型なのに、表とタグで振る舞いが違います。**

| | 表のセル | タグの値 |
|---|---|---|
| `enum` の候補 | ✓ ボタンが出る | ⚠ **出ない**（色だけ） |
| `image` の「画像を選ぶ」 | ✓ 出る | ⚠ **出ない** |
| `bool` のチェックボックス（§10） | （足せる） | ⚠ **出ない** |
| `ref` のリンク | ✓ 出る | ✓ 出る |

⚠ **要求: タグの値にも、型に応じた入力補助を出すこと。**
表と同じ理屈です——**打つより選ぶほうが速く、速ければ揃います**。

⚠ **これを1つ作れば、`enum` の候補・`bool` のチェックボックス・`image` の選択が
まとめて片付きます。** いま3つとも同じ理由（**タグの鏡がない**）で出ていません。

### ⚠ 候補は縛りではありません

⚠ **採らずに手で打てること。** 揃うのは採ったときだけで、**手打ちは止められません**
——それでも意味があるのは**打つより選ぶほうが速い**からです。
`tag-unlisted` の印は「**間違い**」ではなく「**一覧に無い**」を意味します。

## 12. 3層モデル

**「語彙を増やす」と「計算を作る」を別の作業に分けるための形**です。

| 層 | 実体 | 変える人 | 担うもの |
|---|---|---|---|
| **① 語彙レジストリ** | **宣言データ** | 運用者（設定ファイル）／拡張（Go） | 形式の定義——名前・表示名・分類・アイコン・要素種別・**列**（機械キー・型・ラベル・許可値） |
| **② 汎用索引** | コアのコード（**1実装**） | — | 形式の解決できる表を `vocab_index` へ同期。検索・単純集計 |
| **③ 計算ビュー** | Goコード（**少数**） | 開発者 | 索引から読んで組み立てる（手配状況・未手配の一覧・受注残・参考単価） |

⚠ **追加コストに段差があるのが要点**です。記録・表示だけの語彙（100種の大半）は
**①の宣言1件**で済み、**開発者がボトルネックになりません**。Goコードが要るのは
**計算を伴う語彙だけ**（10個未満に保つ）。

⚠ **安全性は①に依存しません。** サニタイザの許可リストは**コードで固定**で、
`data-type` は**属性名だけ**を要素限定（`table`・`dl`・`section`・`th`）で許可し、
**値は不活性な文字列として検査しません**。レジストリは**編集支援と検証の語彙であって、
安全性の門ではありません**——この分離があるから、将来レジストリを実行時に編集できる
ようにしても危険な要素は増やせません。

## 13. 形式の解決——表が「自分が何か」を名乗る方法

**2通りあり、この順で1回だけ**解決します:

| 順 | 名乗り方 | 例 |
|---|---|---|
| ① | **`data-type` 属性**（古い本文） | `<table data-type="our-order-items">` |
| ② | **`<caption>`** | `<table><caption>発注明細</caption>` |

- ①が優先なので、**既存の本文は壊れません**。新しく書く表はキャプションで名乗ります。
- ⚠ **`<caption>` を足したのは 2026-09-20**（ユーザー:「表のうち、意味の分かるものに
  キャプションを付けましょう。**キャプションを頼りに集計できるようになるはず**です」）。
  「見た儘が全て」の原則どおりです。
- ⚠ **節の見出し（`<section><h2>材料</h2><table>…`）では名乗れません**——2026-09-29 にやめました（§1）。
  それまでは見出しでも名乗れ、**節の見出しと `<caption>` が重なると 2026-09-21 まで索引に
  二重に入っていました**（手配数も原価も倍）。

### ⚠ 表の写しにはキャプションだけで入る・集計の索引は登録された形式だけ

- **表の写し**（`data/tables.db`・2026-09-25〜）には、`<caption>` のある表なら**登録が無くても**入ります——
  キャプションがテーブルの名前、見出しが列の名前（🔎 表を探す・AI の口から引ける・
  [【考察】DBの日本語化.md](考察/【考察】DBの日本語化.md)）。
- **集計の索引**（`vocab_index`）には、**レジストリに載っている形式だけ**が入ります（2026-09-20 のユーザー決定——
  それまでは型が解決しない表も、形式名が空のまま入っていました）。⚠ **裏返すと、キャプションを付けただけでは
  集計の索引には入りません**——形式として登録して初めて、拡張の集計（手配・原価など）が読めます。

## 14. 行き先は `vocab_index`

- **索引の `field` は見出しの表示文字**（`品番`）で、**機械キー（`item-id`）ではありません**。
- **ヘッダと明細の対応づけは `block_no`**（ページの中の連番）。
- ⚠ **`section` の素の `dl`（業務ブロックのヘッダ）は 2026-09-18 から入りません。**
  ヘッダの値は**ページの可変タグ**へ移りました——素の `dl` に書いても検索に掛かりません。
- 読む口は [vocab_query.go](../internal/cms/vocab_query.go):

| 口 | 何を返すか |
|---|---|
| `VocabTableRowsOf(db, pageID, type)` | **1ページの**その形式の行 |
| `VocabRowsOfType(db, type)` | **全社の**その形式の行（⚠ スコープを越える集計はこちら） |
| `PagesByTag` / `PagesByTagLoose` | タグでページを引く |

⚠ **`RelatedPages`（深さ1）に頼れない集計があります。** 置き場の離れたページどうしは
直接つながらないので、**深さ1では黙って0件**になります——そういう集計は `VocabRowsOfType` で
**全社を読み**、鍵の列で束ねます（業務での例は拡張の【要求】）。

⚠ **読めないページは混ぜないこと。** 表には誰でも行を書けるので、絞らないと
**読めないページの値が引けてしまいます**。

## 15. 本文の走査は**配送係だけ**

本文HTMLを処理する経路は3つあり、**1つの走査**に寄せてあります
（[walk.go](../internal/cms/walk.go)・SAX over DOM）。

| 段 | いつ | 権能 | できること |
|---|---|---|---|
| **観察係** | 保存時 | 書き込みTx | 自分の索引テーブルへ洗い替え。⚠ **`Replace` はありません** |
| **鏡型** | 表示時 | 読み取り専用DB | `Replace`。表示専用のクローム（`.vocab-chrome`）を足す |
| ~~**種まき**~~ | ~~新規作成時~~ | — | ⚠ **いま**: **2026-09-25 に撤去**——テンプレートは純粋なコピーになった（[【考察】ページテンプレート.md](考察/【考察】ページテンプレート.md) §9） |

⚠ **観察係に `Replace` が無いのは行儀ではなく型の問題**です。同じ理由で鏡型には
書き込みTxを渡しません——**「派生→正本の逆流」がコンパイル時に不可能**になります
（2026-08-21 に一度踏みました）。

- ⚠ **`WalkElements` を自分で回す新しいコードは、たいてい設計を間違えています。**
  除外規則（`.vocab-chrome` の中を読まない・テンプレート領域を索引しない）は
  **配送係がそもそもイベントを発火しない**形になっていて、**規約ではなく観測できない事実**です。
- **鏡は引き金1つにつき1人**（重複は起動時に落とす）——「順番」に意味を持たせないため。
- ⚠ **観察係の `descend` は OR で畳まれます。** AND にすると明細が索引から消えます。

### 索引に載らないもの

- **テンプレート領域（ルート含む）** ——判定はサイドカー＋本文HTML（⚠ DBを見ると静かに壊れます）
- **拡張が「DBに入れない」と言ったページ**（コアの口 `cms.RegisterTablesExclusion`・
  どのページかは拡張の【要求】）

## 16. 列の宣言

```go
{Field: "item-name", Label: "品名", Type: cms.ColText},
{Field: "status",    Label: "状態", Type: cms.ColEnum, Enum: []string{"未発注", "発注済"}},
```

- **`Label` が索引の鍵**（見出しの表示文字）。`Field` は機械キーで、**本文には出ません**。
- ⚠ **見出し行は宣言から組むこと**（`headerRowHTML`）。手書きに戻すと、
  **列を足した日に足した列がどこからも読めません**——**エラーは出ません**。
- ⚠ **同じ意味の列は、形式を越えて名前と型を揃えること。** `品番` が片方 `code`・
  片方 `text` だと、**畳み方が違って突き合わせが静かに外れます**。
- ⚠ **列の宣言を共有するときは毎回作ること**（スライスを共有すると、片方の書き換えが
  もう片方に及びます——`orderItemColumns()` が関数なのはそのため）。
- ⚠ **パッケージ変数の初期化は `init()` より先に走ります。** `var x = labelOf(...)` は
  `RegisterVocab` の前に引いて**常に空**になり、比較が素通りして条件が逆になります。
  **レジストリから引くものは関数にすること。**

---

## 17. スキーマを変えるとき

- ⚠ **新しいテーブルを足しても自動再構築は走りません。** `ApplySchema` は空の表を作るだけ
  ——`page_tags` を足した日にタグ88行が古い表に取り残されました（画面は無言で空）。
  いまは `DriftedSchemaTables` が「**索引に中身があるのに表が無い**」もずれとして扱います。
  ⚠ `CREATE INDEX` を表と取り違えると、**起動のたびに再構築が走ります**。
- ⚠ **スキーマを変えたら、作り直しが `ApplySchema` より先。** 逆だと列を変えた表へ
  新しい索引を張ろうとして**起動が落ちます**（`no such column: name`）。
- **プラグインテーブルにマイグレーションはありません**——起動時に1度だけ自動再構築。
- ⚠ **一括置換で SQL を直すときは UNION を跨がないこと**（`page_tags` と `vocab_index` で
  列名が違います）。

## 18. 語彙モデルが満たすこと

- ⚠ **知らないものを消さない。** レジストリに登録していない `data-type`・キャプションも、
  **サニタイズは拒否しません**——語彙は増えるものだからです。表の写しにはキャプションで入り、
  集計の索引には登録された形式だけが入ります（§13）。
- ⚠ **見出しの改名を告知する。** 表は**自己記述**で、**列の鍵は見出しの表示文字ただ1つ**です。
  だから**見出しを変えると鍵が変わります**——⚠ **黙って変えさせないこと。**
- ⚠ **マーカーは `class` ではなく `data-*`。** サニタイザの `class` 全面拒否に**例外を作らない**
  ためです。⚠ **だから見た目の印は本文に保存できません**（表示時に付ける鏡で作ります）。
- ⚠ **レジストリを安全性の門にしない**（§12）。
- ⚠ **新しいカスタム要素（Web Components・`<m-*>`）は作らない。**
  ⚠ **いま**はカスタム要素0種（2026-08-20 に全廃）。
- ⚠ **写真・画像は語彙ではなく「内容」**です。標準HTML（`<img>`）だけで完結します
  （[【要求】添付.md](【要求】添付.md)）。
- **語彙の単一正本を1つのAPIで配る**——レジストリと拡張の宣言を合成して
  `GET /api/tag-schema` で返し、エディタと文書生成がそれを読みます。
  ⚠ **エディタ側に手書きの要素リストを置かないこと。**

## 19. レジストリの育て方

**段階を踏みます**（2026-08-16 決定）:

| 段 | どこに宣言があるか | 語彙を足すのに |
|---|---|---|
| **v1**（⚠ **いま**） | Goコード内の宣言テーブル＋`config/settings.json` | ⚠ **形式の追加には再ビルドが要る**（設定で足せるのは語→型の `vocabulary` と、表ごとの列の例外の `table_vocabulary` だけ——表の形式そのものは足せない）。⚠ ただしキャプションの付いた表は**登録なしで**表の写し（`data/tables.db`・2026-09-25〜）に入る——登録が要るのは `vocab_index` とそれを読む集計 |
| (b) | 管理コンソールで編集するDB | 再デプロイ不要 |
| (c) | **語彙定義ページ**（w-cms 自身のページで語彙を定義する） | 同上 |

⚠ **先にコード内で始めたのは、定義スキーマが固まる前にDB化すると移行が二度手間になるため**です。

- 識別子（`data-type` の値と機械キー）は **kebab-case**。
- ⚠ **識別子はレジストリ全体で一意**にすること。

**スキーマと本文**

- **スキーマは速さより柔軟性のために。** 縦持ちにして、形式が増えても DB のスキーマが変わらないようにする。利用者

- **本文に機械専用のID・キー・隠しメタデータを書かない。値は要素の中身に書き、属性には入れない**（コンセプト.md:95-96・102）。→ §8
- **挿入の経路が違っても出口は同じ**——同じ語彙・同じ保存時のサニタイズと検証・同じ編集ロックを通す。語彙の正本を迂回する
  経路を作らない（解体前 l.263-265）。→ §18
- **どの文字を同じとみなすかは業種の知識なので、コードに持たず設定に置く。** 利用者「材料や図面にΦという記号が多く出てきます。

- **金額は `¥8,000` のように書いても数値として読む**（`¥`・桁区切り・全角を吸収。通貨は独立の型にせず `number` に含める）
  （【ユースケース】受注から利益まで.md:53）。→ §3 の `number` の畳み方。⚠ いま: 実装済み（`cms.VocabNumber`）。
- **数量の空セルは 1 と読む**（手で書く表で「1個」を書かせないため）（【ユースケース】受注から利益まで.md:54・
  アーキテクチャとDBスキーマ.md:188-189）。→ §8 か §14。⚠ §8「空欄の意味を決めつけない」の例外になるので、並べて書くこと。
  ⚠ いま: 実装はコアの `cms.VocabQuantity`（機械キー `quantity` の意味をコアが知っている——業務の語として拡張へ出すかは要判断）。

**ページ間の参照**（→ §7）

- **参照は本文のタグで表し、DB に参照専用の表（`page_refs`）を持たない。** 利用者「page_refs は正本の座から降ろしてください。
  この方式にする理由は、AIが柔軟な操作をしてくれると信じているからです。必ずその時代が来るはずです。」（2026-08-30・
  アーキテクチャとDBスキーマ.md:637・661）
- **由来への参照は必須**——機械が作るページは、どこから来たかを参照タグで持つ（例 `受信元`）（同:656）。⚠ いま: 実装済み。
- **参照の値は所在地**（「URLのリンクみたいな感じ」）。業務番号を持たない相手も同じ形（ページ番号＋ブロックID）で指し、
  特別扱いを作らない（同:676-684・728）。
- **参照値は構文で読む**——ハイフン類の揺れは畳んでよいが、**先頭のゼロは畳まない**。ページIDは6桁ちょうどに限る
  （`123-45` のような図面番号が参照に化けないため）（同:696-701・751-753）。→ §3 の `ref` の畳み方も。⚠ いま: 実装済み（`parseRefValue`）。
- **参照はラベル一致にすぎず、DB は保証しない**——宙ぶらりんに加えて**多重ヒット**も起きうる（同:686-689）。
- **参照タグの名前は固定しない。** 利用者「参照タグの名前は、検索時に威力を発揮します。…どのような名前でも検索したら良いだけです」
  （2026-08-30・同:727）。⚠ いまの「型は名前で決まる」（設定の `vocabulary` で `ref` と宣言した名前だけがリンクになる）と
  すり合わせが要る。
- **宙ぶらりんの判定はページを読むたびに。** 利用者「先に参照を書いて、あとから参照元を作る場合もあるので、ページを読むたびに
  背景の更新が必要かもしれません」（2026-08-30・同:729-734）。⚠ いま: 表示のたびに判定する。見るのはページの有無までで、
  ブロックの有無は見ない。

**鏡（計算ビュー）と語彙**（→ §12・§15・§18）

- **鏡の印は名前の見える1つの要素**——`<section data-mirror="表示名"></section>`。利用者「もう少しわかりやすいシングルタグに
  出来ないでしょうか」「閉じタグがあっても良いです」「名前の見えない印は廃止して削除して欲しい」（2026-09-27）。挿した直後の
  空の印には、編集モードで「🪞 表示名（保存して読み直すと、ここに鏡が出ます）」を出す。登録されていない名前は描かず、保存時に
  告げ、編集モードで赤くする（エディタ仕様.md:88-98・アーキテクチャとDBスキーマ.md:347-355・コンセプト.md:89）。
  ⚠ いま: 実装済み。この文書に `data-mirror` の語がまだ無い。
- **鏡の中身（サーバーが埋めたもの）は編集モードでも編集できず、保存されない。** 印の節そのものと、中に人が書いたものは残る
  （エディタ仕様.md:99-102・485・アーキテクチャとDBスキーマ.md:364-368）。
- **鏡は自動更新しない**（更新は読み直し——描き方を Go と JS の2か所に持たないため）。**夜間バッチや定期の再集計は要らない**
  ——保存時の索引と表示時の鏡で足り、鏡の価値は速さではなく腐らないこと（アーキテクチャとDBスキーマ.md:373-377・
  パーサとプラグイン.md:118-127）。
- **エラーの方針**——索引（観察係）のエラーは保存を失敗させる（索引の欠けは黙って壊れる芽なので、書き手にその場で知らせる）。
  鏡のエラーはその鏡に理由を描いて続ける（ページ全体を道連れにしない・無言の空白を作らない）。同期のエラーは握り潰さない
  （2026-08-26・パーサとプラグイン.md:306-312）。
- **未知の形式・登録されていない鏡の印は、拒否せず保存の応答で告知する。** 告知は見落とせない配色（赤地・閉じるまで消えない）で、
  拒否ではない。利用者「OK。赤色背景などで告知してください」（2026-08-21・エディタ仕様.md:826-833・
  アーキテクチャとDBスキーマ.md:62-66・354-355）。
- **閲覧モードでは、機械に向けた値のタグ（`…アドレス`・`メッセージID` など）を「▸ 詳細（N件）」へ畳む**（見た目だけ・編集モード
  では畳まない）。利用者「利用者が、『名前：値』のタグは見た目のままにDBに入れられると信じるためには、実際にそうである必要が
  あります」（2026-09-03・エディタ仕様.md:70-75）。→ §2 か §8。⚠ いま: 実装済み。畳む語尾はコアの `app.js` に手書き
