# カスタムタグ一覧（現行・実装済み）

w-cms のページ本文（HTML）で使えるカスタムタグの**実装済み**リファレンス。各タグがどの属性を持ち、どのDBテーブルへ同期されるかをまとめる。
（背景・設計思想は [アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md)・[エディタ仕様.md](エディタ仕様.md)・[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md)、ユースケースは [【ユースケース】受注と進捗管理.md](【ユースケース】受注と進捗管理.md)・[【ユースケース】原価と利益.md](【ユースケース】原価と利益.md) を参照）

> 最終更新: 2026-06-27。**このファイルは現行実装の鏡**であり、タグ・属性を増減したら更新すること（出典: `assets/web-components.js` の `customElements.define`／`observedAttributes`、`internal/cms/plugin_*.go`、`assets/index.html` のスラッシュメニュー）。
> 設計中の未実装タグ（`<m-message>`・`<m-quote>`・`m-file tag="図面"`・納品レコード等）は本ファイルには載せない。[受信記録の取り込み（メール・FAX・電話のページ化）.md](【考察】受信記録の取り込み.md) を参照。

## 1. カスタム要素（6種）

| タグ | 役割 | 主な属性 | 同期先テーブル | スラッシュメニュー |
|---|---|---|---|---|
| `<m-tag>` | 可変タグ（名前:値のメタ情報） | `name`, `value` | `page_tags`（コア・`parser.go`） | 🏷️ 可変タグ |
| `<m-file>` | ファイル/PDFブロック（`tag` 属性で意味が決まる） | `src`, `name`, `tag`, `order-no`, `client-name`, `supplier-name`, `item-id`, `price`, `cost`, `quantity`, `ordered-at`, `estimated-at` | `tag` 依存（§2） | 📩 顧客の発注書 / 📤 自社の発注書 |
| `<m-item>` | 明細行（`m-file` の子。発注書番号にぶら下がる） | `item-id`, `item-name`, `price`, `cost`, `quantity`, `status` | `client_order_items` / `our_order_items` | （ツールバー「＋部品を追加」で挿入） |
| `<m-material>` | 部材定義（1部品あたりの必要部材） | `item-name`, `cost`, `supplier-name`, `quantity` | `part_materials` | 🔩 部材定義 |
| `<m-child-list>` | 子ページ一覧（表示専用・`/api/children`） | なし | —（表示のみ） | 📂 子ページ一覧 |
| `<m-required-materials>` | 手配状況リスト（集計表示・`/api/required-materials`） | `page-id` | —（集計表示のみ） | 📊 手配状況リスト |

補足：
- `observedAttributes`（再レンダリングを誘発する属性）は要素ごとに上記の一部。`m-file` の `item-id`・`estimated-at` は見積もりプラグインが読むが `observedAttributes` には含まれない（属性としては有効）。
- `<m-item>` はスラッシュメニューには無く、`<m-file tag="顧客の発注書">` 等のコンテキストツールバー「＋部品を追加」で子として挿入する（[エディタ仕様.md](エディタ仕様.md) 4章）。

## 2. `<m-file>` の `tag` 値（意味のサブタイプ）

`<m-file>` は `tag` 属性の値で挙動・同期先が変わる。

| `tag` の値 | 同期先テーブル | 子要素 | プラグイン |
|---|---|---|---|
| `顧客の発注書` | `client_orders`（ヘッダ） | `<m-item>` → `client_order_items` | [plugin_client_order.go](../internal/cms/plugin_client_order.go) |
| `弊社の発注書` | `our_orders`（ヘッダ） | `<m-item>` → `our_order_items` | [plugin_our_order.go](../internal/cms/plugin_our_order.go) |
| `弊社の見積もり` | `our_estimates` | なし | [plugin_estimates.go](../internal/cms/plugin_estimates.go) |
| `材料屋・加工業者の見積もり` | `supplier_estimates` | なし | [plugin_estimates.go](../internal/cms/plugin_estimates.go) |
| （未指定。既定表示は `未分類`） | 同期なし | — | ただのファイルカードとして表示のみ |

`tag` 別に表示色や編集フォームも切り替わる（`assets/web-components.js` の `MFile.render`）。

> **将来の再設計予定（未実装）**: 現状の `<m-file>` は「ファイル」と「業務文書の意味（発注書等）」を一要素に抱える過積載状態（`tag` 文字列で意味を切替＋業務属性 `order-no`/`client-name`/… を直持ち）。これを **`<m-file>` ＝純粋なファイル容器（`name`/`ext`/`size`/`modified-at` 等）＋ 中身に形式別の構造化タグ（`<m-order>` 等）** へ分離し、プラグインは中身要素を拾う方向で検討中。詳細は [【考察】受信記録の取り込み.md §4.5](【考察】受信記録の取り込み.md)。

## 3. `<m-tag name="...">` の既知の名前

`m-tag` の `name` は自由語で、基本はすべて `page_tags` に `(name, value)` として入る。特別扱いされる名前のみ以下：

| `name` | 用途 |
|---|---|
| `部品番号` | ページ全体に効き、`part_id` として同一ページ内の全 `<m-material>` 行に注入される（[plugin_materials.go](../internal/cms/plugin_materials.go)、ヘルパ `TagValue`） |
| `必須項目`, `状態` | 製品マスタページの規約（[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 7章。例: `状態=廃版` で新規発注の選択肢から除外しつつ過去参照は保持） |
| `発注元`, `希望納期`, `支払条件`, `自社担当` など | 自由メタ（既定テンプレートの記述例。すべて `page_tags` に入るだけ） |
| `親ページID` | **旧形式・取り込まない**。ページ属性はサイドカー `<id>.meta.json` が正本に移行済み（[エディタ仕様.md](エディタ仕様.md) 9章） |

## 4. タグ → テーブルの早見

| テーブル | 由来タグ | 担当 |
|---|---|---|
| `page_tags` | `<m-tag>` | コア（`parser.go`） |
| `client_orders` / `client_order_items` | `<m-file tag="顧客の発注書">` ＋ 子 `<m-item>` | `plugin_client_order.go` |
| `our_orders` / `our_order_items` | `<m-file tag="弊社の発注書">` ＋ 子 `<m-item>` | `plugin_our_order.go` |
| `our_estimates` | `<m-file tag="弊社の見積もり">` | `plugin_estimates.go` |
| `supplier_estimates` | `<m-file tag="材料屋・加工業者の見積もり">` | `plugin_estimates.go` |
| `part_materials` | `<m-material>`（＋ `<m-tag name="部品番号">`） | `plugin_materials.go` |

`<m-child-list>` と `<m-required-materials>` は表示専用で、固有テーブルを持たない（前者は子ページAPI、後者は集計APIを呼ぶ）。
