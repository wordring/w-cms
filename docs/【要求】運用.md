## 1. ⚠ 正本はファイル、DBは派生

正本は、おおもとの記録のことです。派生は、正本から作り直せる写しのことです。

- **`data/master/` が、唯一の正データです。**
- **`data/cms.db` は、検索・集計のための、使い捨てキャッシュです。**
  キャッシュは、速く引くために取っておく写しです。消しても、ファイルから作り直せます。

⚠ **いま**: 2026-09-25 から、`data/tables.db` も、同じく使い捨てです。
`data/tables.db` は、本文の表を、キャプション（表の題）の名前の表として写したものです。

> ⚠ **DB には、ファイルから再生成できないデータを、一切持たせないこと。**
> これは**不変条件**（いつでも成り立っていなければならない決まり）です。
> プラグインを足すときも、汎用索引にも、適用します。

- ⚠ **派生（DB）から正本（ファイル）へ書き戻さない。**
  壊れたときは、壊れたままのほうが気づけます。

  > 2026-08-21 利用者:「これは設計を変えます。サイドカーが読めない場合、運用者が手作業で修正します。自動で治すことはしません。データベースから正本への書き込みは集計など必要な場合に限られます。」

- **内容と属性を分けます。**
  - 本文 `<id>.html` が、内容です。
  - サイドカー `<id>.meta.json` が、属性です（owner・group・mode・public・parent_id・作成/更新情報）。
    サイドカーは、ページの属性を持つファイルのことです。
- ⚠ **認証情報 `data/auth.db` だけは、再生成できません。** DB 再構築の対象外です。
  認証情報は、利用者やパスワードなど、ログインのための情報です。
- **バックアップ対象は、`data/master/` 全体＋ `data/auth.db` です。**
  `cms.db` は対象外です（復元時に再生成します）。

⚠ **いま**: ファイルから作り直せないものは、`data/master/` と `data/auth.db` のほかにも、次の所にあります。

| 置き場 | 何か |
|---|---|
| `data/trash/` | 削除したページ（ごみ箱） |
| `data/tls/` | `-gencert` が作った証明書と鍵 |
| `data/mail/` | メールのサインインの記録（利用者ごと） |
| `data/_reset-<日時>/` | データの初期化の前に取った控え（§5） |
| `config/settings.json` | 設定ファイル（§3） |

置き場ごとの注意です。

- `data/trash/`: 削除は、ここへの移動です。画面から戻す道具は、まだありません。
- `data/tls/`: 作り直すと、各パソコンで信頼の設定をやり直します。
- `data/mail/`: メールの拡張が置きます。無くなると、サインインをやり直します。
- `data/_reset-<日時>/`: 初期化のボタンがあったころの控えです（ボタンは 2026-10-14 に外しました）。
- `config/settings.json`: Git で管理しています。

ほかの置き場です。

- 監査ログは、`data/auth.db` の中です（[【要求】権限.md](【要求】権限.md) §4）。
- 版（本文の版と、添付の `files/.versions/`）は、`data/master/` の中です。
- `data/tables.db` も、`cms.db` と同じく、対象外でかまいません（作り直せます）。

### 復元は「ファイルを戻して起動するだけ」

- **DB が空で、ファイル正本があれば、起動時に自動で再構築すること。**
- **DB 再構築（admin のみ）は冪等で、途中で失敗しても、再実行で回復すること。**
  冪等（べきとう）は、何度行っても結果が同じになることです。

## 2. 日時は ISO 8601

ISO 8601 は、日付と時刻の書き方の国際規格です。

> 2026-08-30 利用者:「時刻は ISO-8601とします。w-cms全域で使用しますが、**利用者がプラグインなどで別表記に対応するのを妨げるものではありません**」

- **日付のみは `YYYY-MM-DD` です**（ゼロ詰め。月と日を、いつも2桁で書きます）。
- **時刻付きは、`T` 区切りです**（日付と時刻のあいだに `T` を置きます）。
  ⚠ **空白区切りは、ISO 8601 ではありません。** SQL リテラルの流儀です。
  SQL リテラルは、データベースへの命令文の中に、値を直接書く書き方のことです。
- **ゼロ詰めの ISO は、文字列比較＝時系列順になります。**
  文字として比べた順が、そのまま時間の順になる、ということです。
  SQLite（w-cms が使うデータベース）の日付関数にも、そのまま通ります。
- **別表記（和暦・スラッシュ）は、入り口で受けて、ISO へ揃えるものです。内部表現としては使いません。**
  プラグインによる別表記の入出力は、運用者の自由です。

## 3. 設定

設定の置き場は、2つに分かれます。

**① 秘密情報と、インスタンス固有の値は、環境変数です。**

- 環境変数は、サーバーを起動するときに、外から渡す設定の値です。
  インスタンスは、動いている w-cms の1つ1つのことです。
- これらの値のために、アプリは設定ファイルを読まず、コマンドラインフラグ（起動の命令に付ける指定）も持ちません。
- **例外は `-gencert` だけです。**
  自己署名の証明書を `data/tls/` に作って終わる道具で、サーバーの動きは変えません。
  自己署名の証明書は、HTTPS のために、自分で作る証明書のことです。

**② ただし、「運用者が育てるもの」は、設定ファイル `config/settings.json` が正本です。**

- 育てるものは、語彙の辞書・添付の拡張子・アップロード上限などです。
- **Git管理の必須ファイルです。**
- ⚠ **Goコードに既定値はありません。無くても、壊れていても、起動を止めます。**
  黙って既定値で上書きすると、**運用者の語が消える**ためです。
  - 例外は1つだけです。アップロード上限の既定（32MiB）は、コードにあります（[【要求】添付.md](【要求】添付.md) §2）。
    「無ければ無制限」が、いちばん危ない既定だからです。
- ⚠ **秘密は、`config/settings.json` に入れません**（公開リポジトリに入るためです）。

### 環境変数（⚠ **コアの分はこの表が正本**。足すときは `WCMS_` 接頭辞で命名し、ここを更新する）

コアが読む環境変数は、この表が正本です。
足すときは、`WCMS_` で始まる名前を付けて、この表を更新します。

拡張が読む環境変数は、その拡張の【要求】（[拡張/](拡張/)）に書きます。

| 環境変数 | 意味 | 既定 | 状態 |
|---|---|---|---|
| `WCMS_ADMIN_USER` / `WCMS_ADMIN_PASSWORD` | 初期管理者（利用者が空のときだけ。作成後は外す） | なし | 実装済み |
| `WCMS_SECURE_COOKIES` | `0` で Secure Cookie を無効化（⚠ **ローカル検証専用・本番禁止**） | 有効 | 実装済み |
| `WCMS_BASE_URL` | サイトの基底URL。canonical と `sitemap.xml` の絶対URLに使う | リクエストから導出 | 実装済み |
| `WCMS_TLS_CERT` / `WCMS_TLS_KEY` | アプリ自身で TLS 終端。⚠ **両方そろうと待受は `:8443` だけ**。片方だけなら**書きかけとみなして起動を止める** | `:8080` の平文 | 実装済み |
| `WCMS_ADDR` | 待受アドレス。リバースプロキシと同居するならローカルへ束縛できる | `:8080` | 実装済み（下の「⚠ いま」） |
| `WCMS_DATA_DIR` | `data/` の場所 | `./data` | 実装済み（下の「⚠ いま」） |

⚠ **いま**:

- `WCMS_ADDR` を渡さないときは、TLS なら `:8443` で待ち受けます。渡せば、TLS のときもその値です。
- `WCMS_DATA_DIR` の下に、本文・DB・証明書（`-gencert`）・メールの保管が、全部入ります。
  添付のURL `/data/master/…` は、変わりません。
- コアは、表に無い `GEMINI_API_KEY`（AI の Gemini を呼ぶためのキー）も読みます（`internal/cms/gemini.go` の `GeminiGenerateBlobs`）。
  呼ぶのは、いまは東邦の拡張だけです（解析・部材見積依頼の返事を読む など）。無ければ、解析のボタンが設定を促すだけで、ほかは動きます。
  名前に `WCMS_` が付いていません。

表の言葉を説明します。

- 「Secure Cookie」は、HTTPS（暗号にした通信）のときだけ Cookie を送る設定です。
- 「基底URL」は、サイトのアドレスの、もとになる部分です。
- 「TLS 終端」は、通信の暗号を解く役目を、そこで受け持つことです。「平文」は、暗号にしていない通信です。
- 「待受」は、サーバーが接続を待つ場所（アドレスとポート）のことです。
  「ローカルへ束縛」は、同じ機械の中からの接続だけを受けるようにすることです。
- 「リバースプロキシ」は、w-cms の手前に置いて、外からの通信を受けて取り次ぐサーバーです。

**起動時に有効な設定を1行ログへ出すこと。**
環境変数方式は、「いま何が効いているか」が見えにくいためです。

⚠ **ただし、秘密の値は出しません**（キーの**有無**だけを出します）。

⚠ **いま**: 起動のときに、次のような1行を出します。

```
有効な設定: 待ち受け https://localhost:8443（TLS あり）・Secure Cookie あり・データ data/・設定 config/settings.json・Gemini のキー あり・メールのアプリ登録 あり・拡張 …
```

- 実装: `cmd/w-cms/startup_line.go`。
- 見張りの試験（決まりが破れていないかを確かめる試験）は、`TestEffectiveSettingsLineHidesSecrets` です。
  秘密の値が出ないことを確かめます。

## 4. デプロイ

- **実行ファイル1つと、横に置く `assets/`・`config/` で、配布・起動できること**（CGO 不要・クロスビルド可）。
  - CGO は、Go から C 言語のプログラムを呼ぶ仕組みです。これに頼らないので、C コンパイラなしで作れます。
  - クロスビルドは、別の OS 向けの実行ファイルを、手元の機械で作ることです。

  ⚠ **いま**: 拡張を入れて組んだときは、拡張の画面のファイル（`ext/<拡張>/assets/`）も、実行ファイルの横に置きます（2026-10-20 から）。
  サーバーは、このフォルダもディスクから読むためです（`internal/cms/ext_scripts.go`）。
  無いと、エラーは出ずに、その拡張のボタンなどの働きだけが出ません。
  要求の「`assets/`・`config/` で」とは食い違っています（[【要求】w-cmsとは.md](【要求】w-cmsとは.md) §5 も同じです）。
- **本番想定は、VPS（2 CPU / 2GB RAM / Linux・systemd）＋リバースプロキシです。**
  - VPS は、借りて使う、仮想のサーバーです。
  - systemd は、Linux で、サーバーのプログラムを起動して見張る仕組みです。
- **2インスタンス運用にします。**
  - 業務用とサイト用を、**別サーバー・別ドメイン**で動かします。
  - バックアップ・初期管理者・更新も、**インスタンスごと**に行います。
  - **Cookie・セッションは、ドメイン単位で、自然に分離されます。**

## 6. 公開ウェブサイトとしての要求

- **公開ページは、編集用の画面の部品（クローム）を含まない体裁で届くこと。**
  画面の部品は、本文のまわりにある、画面の飾り付け（ヘッダーや操作のボタンなど）のことです。本文ではないので、保存されません。
- **SEO・SNS共有に備えること。**
  SEO は、検索エンジンに見つけてもらいやすくすることです。用意するものは、次のとおりです。
  - ページごとの `<title>`（ページの題）
  - `description`（ページの説明文）
  - OGP（SNS に貼られたときに出る、題・説明・画像の指定）
  - 正規URL（canonical。そのページの正式なアドレス）
  - `sitemap.xml`（サイトのページの一覧を、検索エンジンへ渡すファイル）
  - `robots.txt`（検索エンジンの巡回プログラムへの注文を書くファイル）
- **レート制限**: 匿名アクセスは、不特定多数から来ます。レート制限は、リバースプロキシ側で受けます。
  レート制限は、短い時間に何度も来る要求を止める仕組みです。
- **エラー画面**: 404・403 が、**一般の訪問者にも意味の分かる体裁**であること。

### キャッシュ

キャッシュは、一度返した応答を、ブラウザや途中のサーバーが取っておいて、次に使い回すことです。

- **公開ページは、匿名向けに、キャッシュ可能な応答（`ETag` を含む）を返せること。**
  `ETag` は、応答の中身が変わったかどうかを見分けるための印です。
- ⚠ **非公開ページ・認証済みの応答をキャッシュさせないのは、絶対条件です。**
  - キャッシュさせてよいのは、匿名×実効公開のページの応答だけです（`Vary: Cookie`・ETag）。
  - 認証済みのページ・匿名の404・要認証のAPI・`/api/me` は、no-store です。
  - これが崩れると、共有のキャッシュが、他人の応答を配ります。
  - `Vary: Cookie` は、「Cookie が違えば、別の応答として扱うこと」という指示です。
    no-store は、「この応答を取っておかないこと」という指示です。
- **公開⇄非公開の切り替えが、外から見えるまでの許容遅延は、10分です。**
  非公開へ戻した側にも、10分効きます。即時に失効させる仕組みは、原理的に作れません。

  > 2026-08-21 利用者:「キャッシュにとって必要な時間を知りませんが、10分程度でどうでしょう？」

⚠ **いま**: 実装済みです。

- 匿名×実効公開のページ・`sitemap.xml`・`robots.txt` は、`public, max-age=600`＋`Vary: Cookie` で返します（`publicCacheSeconds`）。
- それ以外は、`no-store` です。
- 実装: `internal/cms/handler_view.go`（ページ）・`internal/cms/handler_sitemap.go`（`sitemap.xml`・`robots.txt`。`publicCacheSeconds` もここ）・`internal/auth/middleware.go`（要認証の `no-store`）。

### 程度を決めたもの

| 何 | 決めたこと |
|---|---|
| アクセシビリティ（画面読み上げ）・サイト内検索 | 「**出来る限りやる程度の要件とします**」（2026-08-21 利用者）。⚠ サイト内検索は**未実装** |
| 運用要件（アクセス記録・可用性目標・バックアップの RPO/RTO） | 「**定めるが、いまではない**」（2026-08-21 利用者） |

表の言葉を説明します。

- 「可用性」は、止まらずに使えることです。
- 「RPO」は、「どの時点までのデータを戻せればよいか」の目標です。
  「RTO」は、「どれだけの時間で復旧できればよいか」の目標です。
