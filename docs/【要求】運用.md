**設定・デプロイ・管理機能・公開サイト**の要求仕様です。

> **書くのは利用者**、**矛盾を指摘するのがエージェント**（開発方針 §2）。
> 本書は **2026-09-23 に [要件定義書.md](要件定義書.md) §2.7・§3・§4.3・§4.4 から
> 抜き出したもの**です——⚠ **利用者が読んで直すための下書き**です。

⚠ **2種類のことが書いてあります。** （印なし）＝**要求**（利用者が直す）、
⚠ **いま**＝**実装の現状**（エージェントが直す）。

## 1. ⚠ 正本はファイル、DBは派生

**`data/master/` が唯一の正データ**で、`data/cms.db` は**検索・集計のための使い捨てキャッシュ**です。

> ⚠ **DBにはファイルから再生成できないデータを一切持たせないこと。**
> これは**不変条件**で、プラグインを足すときも汎用索引にも適用します。

- 内容と属性を分けます——本文 `<id>.html` ＝内容、サイドカー `<id>.meta.json` ＝属性
  （owner・group・mode・public・parent_id・作成/更新情報）。
- ⚠ **認証情報 `data/auth.db` だけは再生成できません**——DB再構築の対象外です。
- **バックアップ対象は `data/master/` 全体＋ `data/auth.db`。**
  `cms.db` は対象外（復元時に再生成）。

### 復元は「ファイルを戻して起動するだけ」

- **DBが空でファイル正本があれば、起動時に自動で再構築**すること。
- **DB再構築**（admin のみ）は**冪等**で、途中で失敗しても再実行で回復すること。

## 2. 日時は ISO 8601

> 2026-08-30 ユーザー:「時刻は ISO-8601とします。w-cms全域で使用しますが、**利用者が
> プラグインなどで別表記に対応するのを妨げるものではありません**」

- 日付のみは `YYYY-MM-DD`（ゼロ詰め）、時刻付きは **`T` 区切り**
  （⚠ **空白区切りは ISO 8601 ではありません**——SQL リテラルの流儀）。
- ⚠ **ゼロ詰めISOは文字列比較＝時系列順**になり、SQLite の日付関数にもそのまま通ります。
- ⚠ **別表記（和暦・スラッシュ）は入り口で受けて ISO へ揃えるもの**で、
  **内部表現としては使いません。** プラグインによる別表記の入出力は運用者の自由。

## 3. 設定

**秘密情報とインスタンス固有の値は環境変数。**
アプリは設定ファイルを読まず、コマンドラインフラグも持ちません。

⚠ **ただし「運用者が育てるもの」は設定ファイル `config/settings.json`** が正本です
（語彙の辞書・添付の拡張子・アップロード上限など）。
**Git管理の必須ファイル**で、⚠ **Goコードに既定値はありません**
——**無くても壊れていても起動を止めます**（黙って既定値で上書きすると**運用者の語が消える**ため）。

⚠ **秘密は `config/settings.json` に入れません**（公開リポジトリに入るため）。

### 環境変数（⚠ **この表が正本**。足すときは `WCMS_` 接頭辞で命名し、ここを更新する）

| 環境変数 | 意味 | 既定 | 状態 |
|---|---|---|---|
| `WCMS_ADMIN_USER` / `WCMS_ADMIN_PASSWORD` | 初期管理者（利用者が空のときだけ。作成後は外す） | なし | 実装済み |
| `WCMS_SECURE_COOKIES` | `0` で Secure Cookie を無効化（⚠ **ローカル検証専用・本番禁止**） | 有効 | 実装済み |
| `GEMINI_API_KEY` | PDF明細抽出のAPIキー | なし | 実装済み（業界慣行名のため接頭辞の例外） |
| `WCMS_BASE_URL` | サイトの基底URL。canonical と `sitemap.xml` の絶対URLに使う | リクエストから導出 | 実装済み |
| `WCMS_TLS_CERT` / `WCMS_TLS_KEY` | アプリ自身で TLS 終端。⚠ **両方そろうと待受は `:8443` だけ**。片方だけなら**書きかけとみなして起動を止める** | `:8080` の平文 | 実装済み |
| `WCMS_DAV` | `1` で WebDAV を開く（⚠ **HTTPS が前提**） | 閉じる | 実装済み |
| `WCMS_DAV_ALLOW_FORWARDED` | `1` でプロキシ経由の WebDAV も通す。⚠ **既定は404で断る**（**WebDAV は社外へ出さない**） | 断る | 実装済み |
| `WCMS_MAIL_CLIENT_ID` / `WCMS_MAIL_TENANT_ID` | メールのアプリ登録。無いと「設定待ち」で起動 | なし | 実装済み |
| `WCMS_MAIL_IMAP_HOST` / `WCMS_MAIL_SMTP_HOST` | 接続先（メールサーバーの移設に備えて外へ出してある） | Office365 | 実装済み |
| `WCMS_ADDR` | 待受アドレス。リバースプロキシと同居するならローカルへ束縛できる | `:8080` | ⚠ **未実装** |
| `WCMS_DATA_DIR` | `data/` の場所 | `./data` | ⚠ **未実装** |

⚠ **起動時に有効な設定を1行ログへ出すこと**——環境変数方式は「いま何が効いているか」が
見えにくいためです。⚠ **ただし秘密の値は出しません**（キーの**有無**だけ）。

## 4. デプロイ

- **単一バイナリ**で配布・起動できること（クロスビルド可）。
- 本番想定は **VPS（2 CPU / 2GB RAM / Linux・systemd）＋リバースプロキシ**。
- **2インスタンス運用**——業務用とサイト用を**別サーバー・別ドメイン**で動かし、
  バックアップ・初期管理者・更新も**インスタンスごと**に行います。
  ⚠ **Cookie・セッションはドメイン単位で自然に分離**されます。

## 5. 管理機能

admin 向けの管理コンソールで:

- 利用者の作成・パスワード再設定・有効/無効化
- グループとメンバーの管理
- 監査ログの閲覧
- **DB再構築**
- ⚠ **いま**: 「置き場」（足りない箱をボタンで作る）と「データの初期化」も。
  ⚠ **初期化は消す前に控えを取るので取り消せます**——実際に1度助かりました。
  ⚠ **実運用に入る前に開発メニューは外すこと。**

## 6. 公開ウェブサイトとしての要求

- **公開ページは編集用クロームを含まない体裁**で届くこと。
- **SEO・SNS共有**——ページごとの `<title>`・`description`・OGP・正規URL（canonical）・
  `sitemap.xml`・`robots.txt`。
- **キャッシュ**——公開ページは匿名向けにキャッシュ可能な応答（`ETag` を含む）を返せること。
- **レート制限**——匿名アクセスは不特定多数から来ます。リバースプロキシ側で受けます。
- **エラー画面**——404・403 が**一般の訪問者にも意味の分かる体裁**であること。
