# 【一覧】語彙

w-cms のページ本文（HTML）で使える**語彙**のリファレンス（引くための一覧）です。
語彙とは、本文に書ける表やブロックの種類と、その名前のことです。種類の1つ1つを「形式」と呼びます。

この文書には、**何が書けるのか**と、**どの形式がどのDBテーブルへ入るのか**だけを書きます。

> **ほかの文書との分担**
>
> - **「いま何があるか」＝本ファイル**です。
>   正本は [internal/cms/vocab.go](../../internal/cms/vocab.go) の `vocabRegistry` です。
> - **「なぜその形か・いつ変わったか」は、ここには書きません。**
>   決定と理由は [【考察】語彙モデル.md](../考察/【考察】語彙モデル.md)（§9 決定ログ・§11）、
>   経緯は [変更履歴.md](../変更履歴.md) が正本です。
> - 安全性の規則は、[本文サニタイズ設計.md](../旧文書/本文サニタイズ設計.md) §5 にあります。
> - 計算プラグインの作り方は、[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md) にあります。

> **形式を決めるのは「見える言葉」です。**
>
> - `<section><h2>表示名</h2>…</section>` と書けば、**その見出しの言葉が形式を宣言**します（解決は `vocabTypeOf`）。
>   表では、`<caption>`（表の題）が同じ役目をします。
> - **`data-type` は機械の名前**です。
>   属性があれば属性が勝ちますが、**書かなくてよい**のが普通の形です。
> - **属性が必須なのは、可変タグ（`tags`）と、配線を属性に持つ形式**（`file-view`・`file`）だけです。
> - **鏡（計算ビュー）は、印 `<section data-mirror="表示名"></section>` で名乗ります。**
>   値は表示名です。`data-type` では名乗れません（2026-09-27 午後から。§2.3）。
>
> **形式の一覧に出てこないもの**
>
> - **未実装の形式は載せません**（設計中のものは、各 `【考察】`・`【要求】` にあります）。
> - **通信記録ページと参照は、新しい形式ではなく、可変タグで表します**（§4。参照の値は `ページID-ブロックID`）。

## 1. 本文の語彙は3つの層でできている

本文の語彙は、次の3つの層でできています。

- **①語彙レジストリ**: 使える形式の登録簿です。
- **②汎用索引**: 本文の表を読み取って入れておく、DB の索引です。
- **③計算プラグイン**: 索引を読んで、集計などの計算をするプログラムです。

**①語彙レジストリ／②汎用索引／③計算プラグインの3層モデルは、
[【考察】語彙モデル.md](../考察/【考察】語彙モデル.md) §4 が正本です。**
本ファイルが写すのは、①の中身（§2）と、それが②③のどこへ流れるか（§3）です。

運用上おさえるのは、次の2点です。

- **安全性の門はサニタイザだけで、レジストリは関与しません。**
  サニタイザは、保存の前に危険な HTML を取り除く処理です。
  - `data-type` の**値は検査されません**。だから、レジストリに無い値も保存を通ります。
    保存応答の `unknown_types` で告知するだけです（[【一覧】API.md](【一覧】API.md)）。
  - ただし、**②汎用索引には入りません**。
    2026-09-20 から、索引するのは登録された形式だけです（`vocab_index.go` の `OnElement`）。
  - キャプションのある表は、登録が無くても、表の写し（`data/tables.db`・2026-09-25〜）には入ります。
  - レジストリが担うのは、編集支援（スラッシュメニュー・挿入骨格・型検証）と、鍵・型を解決するための語彙だけです。
- **エディタは、語彙を手書きで持ちません。**
  - 要素リストも形式リストも、`GET /api/tag-schema` から受け取ります。
  - 応答は、`elements` / `void` / `block_id` / `vocab` / `vocabulary` / `table_vocabulary` / `column_types` / `extensions` / `sql_names` の9キーです。
    - `sql_names` は、表の名前・見出しの「SQL で引くとき気をつける所」を、編集画面で薄赤にするための事実です（2026-09-28）。
    - `extensions` は、載っている拡張の名簿です。画面が、拡張のボタンを出し分けるのに使います。
    - `column_types` は、`th[data-type]` に書ける列型の一覧です。
  - `assets/index.html` に手書きで残るスラッシュメニュー項目は、次の5つです。
    残りは、`populateSlashMenuVocab` がレジストリから生成します。
    - `h1`（見出し）
    - `p`（段落）
    - 見出しの節（`section`・2026-09-27）
    - 折りたたみ（`details`・2026-09-28）。題の言葉がブロックの名前になります。編集モードでは、中に「＋ ファイル」が出ます。
    - 画像（レジストリの形式ではなく、添付＋`<img>` の挿入操作です）

### 1.1 `data-*` マーカーの許可範囲

マーカーは、HTML の要素に付ける、`data-…` という形の印（属性）です。

**許可範囲（どの属性をどの要素へ許すか・値を検査するか）の正本は、
[本文サニタイズ設計.md](../旧文書/本文サニタイズ設計.md) §5.4 です**
（実装は [internal/cms/htmldoc/sanitize.go](../../internal/cms/htmldoc/sanitize.go)）。

本文の語彙マーカーは、次の**3つだけ**です。

- **`data-type`（型名）**
- **`data-src`（出所アドレス）**
- **`data-ref`（ファイル表示の配線・`section` 限定）**

`data-id`（保存の単位）と `id`（リンクの宛先）は、全要素共通の別枠です。
この2つを分ける理由は、[【考察】語彙モデル.md](../考察/【考察】語彙モデル.md) §9 にあります。

ここには、語彙側の固有事情だけを書きます。

- **`th[data-type]` だけは意味が違います。** 形式名ではなく、**列型**（その列の値の種類）を明示します。
  - 使えるのは**9つ**です（`validColumnTypes`・[vocab.go](../../internal/cms/vocab.go)）:
    `text` / `code` / `number` / `date` / `datetime` / `enum` / `image` / `ref` / `email`。
  - `datetime` は、時刻を含む日時です（`date` は日付だけ）。
  - `ref` は、他ページや、その中のブロックへの参照です。
  - `email` は、メールの相手です。値は `名前 <アドレス>` で、畳んだ値（表記をそろえた値）がアドレスだけになります。
  - この3つ（`datetime`・`ref`・`email`）は、**タグの型としても名前から決まります**（§4）。
- **列型の決定順序は、`th` の `data-type` 明示 > レジストリ宣言 > 見出し語の辞書 > `text` です。**
  - サーバーでは、`vocab_index.go` の `resolveColumnType` が決めます。
    エディタは、同じ辞書を `/api/tag-schema` の `vocabulary` で受け取ります。
    だから、索引と画面の判定が食い違いません。
  - **辞書の正本は、`config/settings.json` の `vocabulary` です。**
    1語につき `{"type": …, "values": [...]}` の1件で、型と選択肢を一緒に持ちます。
  - ⚠ **Goコードに既定値は無く、ファイルが唯一の正本です。**
    運用者がファイルへ足して、DB再構築すれば効きます。
- **鍵（フィールド名）は、見出しの表示文字ただ1つです**（`th` / `dt` のテキスト）。「見える文字がすべて」です。
  - ③計算形式では、その表示文字が、レジストリ宣言の**ラベル**に一致することで、機械キー（`Field`。§2.2）へ解決されます。
  - **機械キーを本文へ書き出す属性はありません。**

> **見出しを改名すると、その列は③計算プラグインに読まれなくなります**
> （部材手配計算などの、型付きテーブルへ入りません）。
> 黙って止まらないよう、解決できなくなった列は、保存応答の `unresolved_fields` で告知します
> （拒否はしません。[【一覧】API.md](【一覧】API.md)）。

### 2.1 形式の一覧

表の読み方は、次のとおりです。

- **形式を決めるのは「見出し・`<caption>` に書く言葉」**（第1列）です。
- **`data-type`（第2列）は機械の名前**です。
  レジストリの鍵・既存本文の互換のほか、`Hidden` の明細表のように**人が挿さないもの**を機械が書くときに使います。
- **分類「ビュー」（鏡）は、`data-type` では名乗れません。**

### 2.2 列と列型

**形式ごとの列の一覧は、ここには置きません。**

レジストリの `Columns`（列の宣言）が決めるのは、次の**2つだけ**です。**本文に何が書けるかではありません。**

1. **挿入の骨格**: スラッシュメニューから挿したとき、最初に並ぶ見出しです。
2. **③計算が読む鍵**: 見出しの表示文字が `Label` に一致したときに解決される、機械キー（`Field`）です。

**本文の鍵は、書いた人が見出しに書いた言葉です。**

- 宣言に無い列を足しても、索引には入ります。
- 宣言どおりの列でも、**見出しを改名すれば③計算からは外れます**（保存応答の `unresolved_fields`）。

**だから、宣言を写した表は「本文の現実」にはなりません。**

**いまの宣言を見たいときは、正本を見ます。**

- [internal/cms/vocab.go](../../internal/cms/vocab.go) の `vocabRegistry`
- 動いているサーバーなら、`GET /api/tag-schema` の `vocab`（拡張・設定から足した形式も入ります）

> **列についての決まり**
>
> - **`備考` の列だけが、画面で折り返します**（`app.js` の `WRAP_COLUMNS`）。
>   ほかの列は1行に保ち、表は自分の中で横スクロールします。
> - **`状態` の `完了` だけは、「もう受注残に出さない」の宣言です。**
>   `納品済` は、出したという事実です。残数があれば、まだ出ます。
> - `材料発注`・`納品書発行`・`請求書発行` は、人が付ける `済` の印です。
>   「材料発注が終わった」の事実は、手配状況リストの残要手配数 0 が答えです。
>   印と事実を、二重には持ちません（[【考察】製造という軸.md](../考察/【考察】製造という軸.md)）。

補足：

- **数値は、正規化して読みます。**
  `¥8,000` や全角の `８０００` は、`8000` として解釈されます（`NormalizeValue`）。
  正規化値は**併記**であり、生テキストが常に正本です。
- **`quantity` の空セルは 1** として扱います。手で書く表で、「1個」をいちいち書かせないためです。
- **型の不一致は、拒否せず、赤印で通知するだけです。**
  「自由な記述をシステムが認識する」というコンセプトを壊さないためです
  （[【考察】語彙モデル.md](../考察/【考察】語彙モデル.md) §5.1）。
- `date` 型は、`YYYY-MM-DD` へ正規化します（`YYYY/M/D`・`YYYY年M月D日` も受けます）。
- **`text` と `code` は、「畳む強さ」だけが違います。**
  「畳む」は、表記の揺れをそろえることです。
  見た目も入力補助も同じで、索引の併記値（`norm_value`）の作り方が変わります。
  - `text` は、軽く畳みます（全角英数→半角・半角カナ→全角・濁点の合成・前後の空白）。
    **長音 `ー` には触りません。** `ひかりレーザー` を壊さないためです。
  - `code` は、強く畳みます（軽い正規化＋空白の除去・ハイフン類/長音/`_`→`-`・英字は大文字）。
    図面番号・発注書番号のような**符牒**（決まった番号や記号）に付けます。
    **区切りの有無は畳みません。** `R520-M070` と `R520M070` は別扱いです。別の部品を1つにしないためです。

  引くときは、`PagesByTag`（生の完全一致）と `PagesByTagLoose`（畳んだ一致）を、**呼ぶ側が選びます**。
  正本は [【考察】テキストの正規化.md](../考察/【考察】テキストの正規化.md) です。
- **`enum` は、`text` と同じに畳みます。** 中の空白は畳みません（それは `code` だけです）。
  **正規化しない列型は、`image` だけ**です。
- **`image` 列の入力補助**は、2つあります。
  セルにキャレット（文字を打つ位置の印）を置くと出る「🖼 画像を選ぶ」ボタンと、セルへの画像ドロップです。
  どちらも `insertImageIntoCell` が受け持ち、`/api/upload-image` へ送って `<img>` を入れます
  （[【要求】添付.md](../【要求】添付.md)）。

### 2.3 形式の外形（HTMLの実例）

**いまの形**（1文書＝1ページ）

- ヘッダは、**ページの可変タグ**に書きます。
- 原本は、`<details>` で畳んだ**ファイル表示**と、「読んだまま」の写しで持ちます。
- 明細は、**`<caption>` で形式を名乗る表**です。

🤖 解析が受注ページに書く形が、これです
（[ext/toho/analyze_pdf.go](../../ext/toho/analyze_pdf.go) の `buildOrderPageHTML`）。
並びは、**原本（PDF）→ 読んだまま → 弊社の明細**です。確かさの順に並べています。

```html

  <dt>発注元</dt><dd>みなと商店</dd>
  <dt>発注日</dt><dd>2026-07-15</dd>
  <dt>納期</dt><dd>2026-08-20</dd>
  <dt>小計</dt><dd>80000</dd>
  <dt>消費税</dt><dd>8000</dd>
  <dt>合計金額</dt><dd>88000</dd>
  <dt>受信元</dt><dd>000042-c3p7</dd>
</dl>
<details><summary>顧客の発注書（PDF）</summary>
  <section data-type="file-view" data-ref="000042-c3p7"></section></details>
<details><summary>顧客の発注書（読んだまま）</summary><table>…</table></details>
<table>
  <caption>受注明細</caption>
  <tbody>
    <tr><th>弊社品番</th><th>品番</th><th>品名</th><th>数量</th><th>単位</th><th>単価</th><th>納期</th><th>出荷済み</th><th>備考</th><th>状態</th></tr>

  </tbody>

```

- 形式の解決は、①`data-type` ②節の機能見出し ③表の `<caption>` の順で、**1回だけ**行います。
  ただし、計算ビュー（`View: true`）の形式名を書いた `data-type` は、①では読みません。
  ②の見出しへ落ちます（2026-09-27・`vocabTypeOf`）。
- 検算の結果は、明細の `<tfoot>` に**鏡**で出ます。本文には書きません。
  検算するのは、`数量 × 単価 = 金額`／`Σ金額 = 小計`／`小計 + 消費税 = 合計` です。
- **登録された語彙だけが索引に入ります。** 名乗らない表は、`vocab_index` に載りません。

**表は `<caption>` で名乗ります**

- これが**挿入の既定**です（2026-09-27 から）。
  エディタの `buildVocabSkeleton` が、表の種類をこの形で挿します。
- **`<caption>` は、人のためのキャプション（表の題）でもあり、同時に形式の宣言**でもあります。
- **`data-type` は書きません**（機械が書く表と同じです）。

```html
<table>
  <caption>材料</caption>
  <tbody>
    <tr><th>材質</th><th>形状</th><th>寸法</th><th>個数</th></tr>
    <tr><td>SS400</td><td>板</td><td>t3.2*100*200</td><td>2</td></tr>
  </tbody>
</table>
```

- **表の写し（`data/tables.db`）は、キャプションのある表だけを読みます。**
  それが、全面的にキャプションへ移した理由です。

  > 2026-09-26 利用者:「全面的にキャプションに置き換える」

**機能見出し形**

機能見出し形は、`section` の**最初の見出しの言葉**で、形式を名乗る形です。
見出しの言葉がレジストリの表示名に一致すれば、それが形式です。

- **表については、もう挿しません**（2026-09-27 までは、これが挿入の既定でした）。
- **鏡も、2026-09-27 午後から挿しません**（下の「計算ビュー」の、`data-mirror` の印に替わりました）。
- 既定のビルドでは、スラッシュメニューがこの形で挿す形式は、もうありません
  （改訂履歴も、2026-09-27 から改訂明細の表だけです）。
- **読むのは続けます。**
- **古い本文の表は、まだこの形で残っていて、読み手は読み続けます**
  （5段目で移し替えます。職場の加工製品テンプレートの `材料` など）。

```html
<section><h2>必要部材表</h2></section>   <!-- 鏡の古い形（2026-09-27 午前だけ）: data-mirror へ移し終えるまで読むが、もう挿さない -->

<section>                                <!-- 古い表の形: 読むが、もう挿さない -->
  <h2>材料</h2>
  <table>…</table>
</section>
```

- ⚠ **見出しの言葉が形式を決めます。**
  改名すると、**別の形式（または形式なし）になります**。
  だから、保存の応答が `unresolved_fields` で告知します（拒否はしません）。
- **素の `table` は、明細として索引に入ります**（節が形式を持つときです。古い本文のための扱いです）。
  **素の `dl` は載りません。** ヘッダは、ページの**可変タグ**へ書きます。
- 見出し語がレジストリに無ければ、**静かにただのセクション**になります。
  告知はしません。普通の見出しへの誤検知を避けるためです。

**可変タグだけは属性が要ります**

**見出しで名乗る場所が無く、素の `dl` と見た目で区別が付かないため**です。

```html
<dl data-type="tags"><dt>発注元</dt><dd>みなと商店</dd><dt>部品番号</dt><dd>A100-B01-0051</dd></dl>
```

> ⚠ **古い本文には、`data-type` の形が残っています。**
>
> - **属性は読み続けるので、壊れません。**
>   **計算ビューの属性の印だけは例外**で、2026-09-27 から読みません（下の「計算ビュー」）。
> - ただし、中に**ヘッダを素の `dl` で持つ**ものは、**発注書番号・発注元・発注日が索引に入りません**。
>   **タグへ書き直すこと。**

**計算ビュー**（表示専用）

- 本文に保存されるのは、**鏡の印** `<section data-mirror="表示名"></section>` だけです
  （2026-09-27 午後から・値は鏡の表示名）。
- 中身は、`view_render.go` が、ページを返すたびに、印の末尾へ `<div class="vocab-chrome">` として埋めます。
- 消すのは、前回描いた `.vocab-chrome` だけです。だから、印の中に人が書いたものは残ります。
- 印に見出しが無いので、鏡の題は、鏡の中に1回だけ出ます。
- 仕組みは、[アーキテクチャとDBスキーマ.md](../旧文書/アーキテクチャとDBスキーマ.md) 4.4 にあります。

```html
<section data-mirror="子ページ一覧"></section>
<section data-mirror="手配状況リスト"></section>
```

- 鏡の印の形についての、利用者の言葉です。

  > 利用者:「『表と挿げ替えるためのタグ』はほぼ間違いなく鏡になりますから、ページを読むたびに更新が必要なもの。保存するHTMLにも記録されるはず。もう少しわかりやすいシングルタグに出来ないでしょうか」「hrは流石に意味が分からないので、閉じタグがあっても良いです」

  属性名は、定数 `cms.MirrorAttr` です。
  サニタイザは、`section` に限って通します。値は、不活性な（何も動かさない）文字列です。
- **登録されていない名前（打ち間違い・表の形式の名前）の印は、描きません。**
  保存の応答 `unknown_types` で告げ（`UnknownVocabTypes`）、編集モードでは印を薄赤にします（`.is-vocab-unknown`）。
- 挿した直後の空の印には、編集モードでだけ、
  「🪞 表示名（保存して読み直すと、ここに鏡が出ます）」の案内が出ます（CSS の `::before`・保存されません）。
- **2026-09-27 の午前だけ使った見出しの節（`<section><h2>子ページ一覧</h2></section>`）は、2026-09-28 に読むのをやめました。**
  両方の環境で `data-mirror` へ移し終えたので、`vocabTypeOf` の鏡の解決と、
  移し替えの道具 `tools/migrate-view-markers.js` を消しました。
- ⚠ **名前の見えない属性の印（`<section data-type="child-list"></section>` など）は、2026-09-27 に廃止しました。**
  **読まれず、鏡は描かれません**（`vocabTypeOf`・`hasViewMarker` が、計算ビューの `data-type` を見ません）。

  > 利用者:「名前の見えない印は廃止して削除して欲しい」

- **コードが印を書くときは、`cms.ViewMarkerHTML(形式名)` を通します。**
  - `<section data-mirror="表示名"></section>` を返します。
  - 表示名は、レジストリから引きます。
  - `View: true` でない形式を渡すと、panic（プログラムが止まる誤り）になります。
  - 置き場の雛形は、これで書いています。

**ファイル表示**（鏡型）

- 保存されるのは、**マーカー1つと短縮ファイル名の名札**です。
- 表示では、名札を消して、閉じられる枠 `<details class="file-view-fold" open>` を描きます（2026-09-27）。
- **配線は属性 `data-ref`** です。

```html
<section data-type="file-view" data-ref="010272-c3p7"></section>
```

- **中に参照タグを書いても、開きません**（`TestFileViewIgnoresInnerTags`）。
  旧い形のままの本文は、`data-ref` へ写すまで、「参照がありません」と出ます。
- 属性は、**`section` に限って**サニタイザが通します（`structuralElements`）。
  URLではないので、`safeEmbedURL` は通しません。
  URLを組むのは、サーバー側です。書く人が宛先を選べない、という性質は、値の検査ではなく、そこで守られます
  （[セキュリティ設計.md](../旧文書/セキュリティ設計.md) §4）。
- **列は持ちません**（中に書くものが無いためです）。
  - スラッシュメニューから挿さるのは、空の `<section data-type="file-view"></section>` です（`data-ref` は、まだありません）。
  - 参照は、編集モードの**配線の札**（`button.fv-wire`）→ プロパティ欄 `#w-fv-popover` で入れます
    （[エディタ仕様.md](../旧文書/エディタ仕様.md) §7.5）。
  - 札が出るのは、`data-type="file-view"` を持つブロックだけです。
    だから、**スラッシュメニューも属性形で挿します**（`usesHeadingForm` の例外）。
  - `tags`・`file` と同じ扱いで、理由も同じです。**配線を属性に持つ形式は、見出し形にしません。**

## 3. 形式 → テーブルの早見

**業務データが入る表は、2つだけ**です
（コアテーブルは `pages` と `page_perms`。[internal/database/sqlite.go](../../internal/database/sqlite.go)）。

**形式ごとの専用テーブルはありません。**
正本は [【考察】タグ表と業務ブロック表の分離.md](../考察/【考察】タグ表と業務ブロック表の分離.md) §8 です。

| テーブル | 由来する形式 | 担当 |
|---|---|---|
| **`page_tags`** | **可変タグだけ**です（`dl[data-type="tags"]`）。列は `page_id / seq / name / value / norm_value` の5つです。**主鍵は `(page_id, seq)`** です（`seq` は**ページ通し**の番号）。**`norm_value` だけ宣言型を持ちません。** 型を値に持たせ、`number` のタグが辞書順（`"8000" < "900"`）に並ぶのを防ぐためです。⚠ 束ねる形は、`tagNormBind` が1か所で決めます。**範囲で引く口を足すときも同じ関数を通す**こと | [vocab_index.go](../../internal/cms/vocab_index.go) |
| `vocab_index` | **登録された語彙の表**です。`table[data-type]` と、`<caption>` で名乗った `table` が入ります。加えて、形式を持つ `section`（`data-type` または機能見出し）の**素の `<table>`** も入ります（`data-type` を持たない表です。`section` の側から拾います）。**素の `<dl>` は載りません**（ヘッダはタグへ）。**登録されていない形式も載りません** | 〃 |

**振り分けは書き手1か所**です（`insertVocabEntry`）。だから、読む側は表を選ぶだけです。

`vocab_index` での区別は、`data_type` 列です。

- 明細は、表自身の `data-type`（または、`<caption>` の表示名から解決した形式名）で載ります。
- 素の表なら、包む形式の `Items` で載ります。
- どちらの場合も、同じ形式名で載ります（受注明細なら、どちらも `client-order-items`）。

読む側の入口は、[vocab_query.go](../../internal/cms/vocab_query.go) の4つです。

- `VocabTableRowsOf`・`VocabBlocksOf`（どちらも `vocab_index`）
- `PagesByTag`・`PagesByTagLoose`（どちらも `page_tags`。生の完全一致か、畳んだ一致かを、**呼ぶ側が選びます**）

③計算は、この索引だけを読みます（[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md) §8）。

## 4. 可変タグ（`dl[data-type="tags"]`）の既知の名前

`tags` の鍵（`dt` の表示文字）は、自由語（好きに書ける言葉）です。
すべて、**`page_tags`** に `(name, value, norm_value)` として入ります。

- **同じ名前を同一ページに複数置いてよい**です。
  担当者が2人、関連部品番号が複数、といった多値属性のためです。
- 多値は、**対の繰り返し**で表します。
  1つの `dt` に複数 `dd` は形式外ですが、来れば、鍵の繰り返しとして寛容に読みます。
- 単一値として読む用途は、`cms.TagValue` が先頭を採ります。

特別扱いされる名前だけを、以下に挙げます。

> **⚠ 機械が書く／引く名前は、生の文字列ではなく定数です。**
>
> - **人が本文に書く名前は自由語のまま**です。定数は、**コードが名指しするとき**のものです。
> - 「所有」は、その名前を持つパッケージです。
>   `comm` は `w-cms/ext/comm`、`contacts` は `w-cms/ext/comm/contacts`、`toho` は `w-cms/ext/toho` です。

## 5. 語彙の増やし方

**既定の増やし方は、「レジストリへ宣言を1件足す」です。**
カスタム要素（独自の HTML 要素）は作りません（§6）。

1. [internal/cms/vocab.go](../../internal/cms/vocab.go) の `vocabRegistry` へ、`VocabDef` を1件足します。
   `Type` は kebab-case（小文字をハイフンでつなぐ書き方）で、一意（ほかと重ならない名前）にします。
   `Element` は、`table` / `dl` / `section` のいずれかです。
2. 再起動すると、`GET /api/tag-schema` の `vocab` に現れ、**スラッシュメニューに自動で並びます**
   （`Hidden: true` なら並びません）。
   挿入骨格・列型の検証・②汎用索引への同期も、そのまま通ります。
3. 本ファイルの **§2.1 の一覧**を更新します。**手で写さず生成する**こと。
   1. リポジトリ直下に、使い捨ての `_vocabgen/main.go` を置きます。
   2. その中で、`_ "w-cms/ext/comm"`・`ext/comm/contacts`・`ext/comm/mail`・`ext/toho` を blank import します
      （使わなくても読み込ませる書き方です）。
   3. `cms.LoadSettings()` → `cms.VocabDefs()` を、§2.1 の行の形で印字します。
   4. 表を貼り替えてから、ディレクトリを消します。

   生成するときに気をつけることは、次のとおりです。

   - ⚠ **形式（表の種類）は、Go のコードでしか登録できません。**
     `settings.json` にあるのは、言葉→型の辞書（`vocabulary`）だけです。形式を足す口はありません。
     2026-09-25 に確かめて、訂正しました。それまでは「設定から足した形式も同じ口に出る」と書いていました。
   - **第1列は `Icon + DisplayName`**（見える言葉）で、`Type` は第2列です。
   - **`VocabDefs()` は `Type` の abc 順に返す**ので、並べ替えてから貼ること。
   - **列の一覧は作りません**（§2.2）。
4. **Goのコードは1行も書きません。**
   集計API・型付きテーブル・取り込み変換のいずれかが要るときだけ、③計算プラグインを追加します
   （[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md) 冒頭の振り分け）。

> **サニタイザは変更不要です。**
> `data-type` は許可済みの属性名で、**値は検査されません**。
> だから、新しい形式名を足しても、許可リストに触る必要はありません
> （`table` / `dl` / `section` / `th` を担い手にする限りです）。
> 新しい**要素**や**属性**が要る場合だけ、`structuralElements` を直します
> （[本文サニタイズ設計.md](../旧文書/本文サニタイズ設計.md) §5・§7）。

## 6. 本文はすべて標準HTML

**本文に、独自の要素は1つもありません。**
語彙は、**標準HTMLの担い手**（`table` / `dl` / `section` / `th`）に、
見出しの表示文字（と、例外だけ `data-type`）で意味を載せる形だけです。

これを見張る試験（番人）は、`vocabulary_test.go` の `TestNoCustomElementVocabulary` です。
`AllowedVocabulary()` に、ハイフンを含む要素名が現れたら落ちます。

許可リストに無い要素は、**アンラップされます**（要素は捨てられ、中身のテキストは残ります）。
だから、独自要素の混じった本文が入ってきても、文字は失われません。
