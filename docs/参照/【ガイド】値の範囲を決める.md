# 【ガイド】値の範囲を決める

この文書は、表やタグに書く値について、「この名前の値は、この範囲に入るはず」という決まりを足す手順です。
決まりから外れた値があると、画面がその値に色を付けて知らせます。

> 2026-10-22 利用者:「加工製品ページの部材の表の個数というより、個数の値が小数点の場合、警告として背景色を変えては？これを一般化して、名前と値が対応する場合に、ある名前の値の範囲を設定できるように出来ませんか」

> 2026-10-22 利用者:「語の値の範囲として、材質という名前に対して、SS400、SUS304と言った文字列の行列も許容できると良いです」

## 1. どんなことができるか

w-cms では、表の列の見出しやタグの名前（例: `個数`・`材質`）ごとに、値の決まりを書けます。

- **数の範囲**: 「個数は 0 以上の整数」のように、いちばん小さい数・いちばん大きい数・整数かどうかを決めます。
- **決まった値の並び**: 「材質は 鉄・SS400・SUS304 … のどれか」のように、書いてよい値を並べます。

決まりは、**書くことを止めるものではありません**。外れた値も、そのまま書けて、保存されます。
画面が「この値は決まりから外れています」と知らせるだけです。
書き間違い（`0.5` と書くつもりが無かった・`SS4OO` と打ち間違えた など）に、その場で気づくための仕組みです。

## 2. 画面での見え方

決まりから外れた値は、次のように見えます。

- 背景が**薄い橙色**になり、値の前に **⚠** が付きます。
- マウスを載せると、理由が出ます（例:「⚠ 個数: 整数ではありません（小数）」「⚠ 材質: 決まった値（鉄・SS400・…）にありません」）。

色と ⚠ は、表のセルにも、タグの値にも付きます。閲覧モードでも、書ける形でも出ます。
値を直すと、その場で消えます。色と ⚠ は画面に出すだけで、本文には保存されません。

決まった値の並びがある名前では、セルやタグの値に入ったときに出る**候補**も、その並びになります。
よく使う値が上に来ます。選べば、打ち間違えずに入れられます。

## 3. いま決めてあるもの

| 名前 | 決まり |
|---|---|
| `個数` | 0 以上の整数（小数と、0 より小さい数を知らせる） |
| `材質` | 鉄・SS400・SS・STKM13A・SGP・SPCC・SM490A・STKM・SUS304・STKM11A-EG・SK3 のどれか |

`材質` の並びは、2026-10-22 に職場で使われていた値から作りました。
材質と寸法を1つの欄に混ぜた値（`SS　t12` など）は、並びに入れていません。
材質に表面の仕上げや加工の言葉を足した値（`鉄生地`・`SS生地`・`鉄　メッキ`・`STKM13A（ビードカット）`）と、
材質ではない値（`セルスペーサー`）も、入れていません。これらの値は、いま ⚠ が付きます。

## 4. 決まりを足す・直す手順

決まりは、設定のファイル `config/settings.json` の `vocabulary`（語彙）に書きます。
語彙は、名前と、その値の型（数・日付・文字など）の対応の表です。

1. `config/settings.json` を開き、`"vocabulary"` の中の、その名前の行を探します（無ければ1行足します）。
2. 下の「書き方」のとおりに、決まりを書き足します。
3. 管理画面の「🔄 データベース再構築」を押します。これで設定が読み直されます（サーバーの再起動は要りません）。
4. 開いているページを読み直します（F5）。画面は、ページを開いたときに設定を受け取るためです。

設定のファイルは Git で管理しています。直したら、ほかの環境（家・職場）へも `git pull` で届けます。

⚠ **書き方を間違えると、サーバーが起動しません**（データベース再構築も止まります）。
黙って決まりを無視すると、効いていないことに気づけないためです。
止まったときは、出てきた文（どの名前の何が違うか）を見て直します。

## 5. 書き方

### 数の範囲（型が `number` の名前）

```json
"個数": { "type": "number", "integer": true, "min": 0 }
```

| 書くもの | 意味 |
|---|---|
| `"min": 0` | これより小さい数を知らせる |
| `"max": 100` | これより大きい数を知らせる |
| `"integer": true` | 小数を知らせる |

3つのうち、要るものだけを書きます。

### 決まった値の並び（型が `text` か `code` の名前）

```json
"材質": { "type": "text", "allowed": ["鉄", "SS400", "SUS304"] }
```

`allowed` に、書いてよい値を並べます。並べた順は、候補の並びの、同じ回数のときの順になります。

比べるときは、次の違いを同じとみなします。

- 全角と半角（`ＳＳ４００` と `SS400`）
- 大文字と小文字（`sus304` と `SUS304`）
- 型が `code` の名前では、さらに空白・ハイフン・長音・下線（`SUS 304` と `SUS-304` と `SUS304`）

### 書いてはいけないもの

次のように書くと、サーバーが起動を止めます。

- 数の範囲（`min`・`max`・`integer`）を、型が `number` でない名前に書く。
- `min` を `max` より大きくする。
- `allowed` を、型が `text`・`code` でない名前に書く（選択肢の型 `enum` には `values` を使う）。
- `allowed` に、空の値や、同じ値を2回書く。

### 表ごとに決まりを変えるとき

同じ名前でも、表によって決まりを変えたいときは、`"table_vocabulary"` に表の名前（キャプション）ごとに書きます。
表ごとの決まりがあれば、そちらが先に使われます。

```json
"table_vocabulary": {
  "材料表": { "個数": { "type": "number", "integer": true, "min": 0, "max": 100 } }
}
```

## 6. 選択肢（`enum`）との違い

型が `enum` の名前（例: `対応` の 未処理・済・不要）にも、値の並び（`values`）があります。
`enum` の並びに無い値は**薄い黄色**になりますが、これは警告ではありません。新しい言葉が育つ場所として、「見慣れない値です」と知らせるだけです。

この文書の決まり（`allowed`・`min`・`max`・`integer`）は、外れたら**警告（薄い橙と ⚠）**です。
「この値は間違いかもしれない」と知らせたいときに使います。

## 7. しくみの置き場所（開発者向け）

- 決まりを読むのはコアです（`internal/cms/vocab.go` の `VocabWord`、検査は `internal/cms/settings.go` の `validateVocabWord`）。
- 画面は `/api/tag-schema` の `vocabulary`・`table_vocabulary` で決まりを受け取り、`assets/app.js` の `outOfRangeReason` で確かめます（表のセルは `validateCell`、タグの値は `markTagVocabulary`）。見た目は `assets/app.css` の `.cell-out-of-range`・`.tag-out-of-range` です。
- 試験は `internal/cms/settings_test.go`（`TestSettingsVocabularyRange`・`TestSettingsVocabularyAllowed`）と、E2E の `e2e/verify-value-range.js` です。
