### 2b. 載っている拡張を「知らせる」

拡張が自分で名簿に名前を書きます（`cms.RegisterExtension(id, name)`・`internal/cms/extensions.go`）。

| ID | 名前 | 名前を書く場所 |
|---|---|---|
| `comm` | 通信 | `ext/comm/comm_routes.go` の `init` |
| `comm/contacts` | アドレス帳 | `ext/comm/contacts/plugin.go` の `init` |
| `comm/mail` | メール送受信・IMAP／SMTP | `ext/comm/mail/plugin.go` の `init` |
| `toho` | 東邦の業務 | `ext/toho/materials.go` の `init` |

名簿の使い道は4つです。

1. 起動ログの「拡張セット: …」の1行。
2. 起動ログの「有効な設定: …」の1行（`cmd/w-cms/startup_line.go`）。
3. 画面の出し分け（`/api/tag-schema` の `extensions`・空でも `[]`）。読むのは `assets/app.js` の `hasExtension(id)` で、拡張の JS は `window.wcms.hasExtension` を通します。
   `hasExtension` は**知らされていなければ true** を返します（取得に失敗したら全部出す。出ないより、押して断られるほうが原因に気づけます）。
   いま `hasExtension('…')` を呼ぶのは拡張の JS だけです（`toho.js` 2・`mail.js` 1）。コアの `app.js` は名指ししません。
4. **画面のファイルを配る範囲**（§2d）。ID がそのまま `ext/<ID>/assets/` の場所になります。

### 2d. 拡張の画面のファイル（`internal/cms/ext_scripts.go`・2026-10-20）

- 載っている拡張ごとに、`ext/<ID>/assets/` の `.js`・`.css`・`.html` を拾います（`discoverExtAssets`・起動して最初に使うとき1度だけ）。
- 直下のファイルは、編集用の画面の枠へ差し込みます。`.js` は `app.js` のあと、`.css` は `app.css` のあとです（`extScriptTags`・`extStyleTags`。順は URL の文字の順）。
- 1段下のフォルダ（例: `ext/comm/assets/pages/`）のファイルは、配るだけで枠へは差し込みません。メールの一覧は `/assets/ext/comm/pages/mails.html` です。

- ビルドで外した拡張は名簿に無いので、そのファイルも配られません。

派生についての決まりです。

- **`cms.db` は使い捨て**です。`data/master` から丸ごと作り直せます（`RebuildDatabase`）。
  - テーブルは `pages`・`page_perms`（コア）＋`vocab_index`・`page_tags`（`vocabIndexPlugin`）＋`material_dimensions`（`dimensionPlugin`・`ext/toho`）＋`rebuild_state`（再構築の進み具合の印・`sync.go`）の**6つ**です。
  - `Register` を通るプラグインは、既定のビルドで**6つ**です。コアの `vocabIndexPlugin` と、拡張の `commPlugin`・`contactsPlugin`・`mailPlugin`・`materialsPlugin`・`dimensionPlugin`。
    表を持つのは `vocabIndexPlugin` と `dimensionPlugin` だけです。
- **`data/tables.db`（表の写し）も使い捨て**です（`tables_db.go`）。
  - 保存のたびに `SyncIndex` が `syncCaptionTables` で、**キャプションのある表だけ**を写します。表の名前はキャプション、列の名前は見出しです（`TableName` で正規化）。式のセルは計算した値を入れます。
  - 全再構築で作り直し（`ResetTablesDB`）、版（`PRAGMA user_version`）が古ければ起動時に1度だけ作り直します（`tablesDBOutdated`）。
  - **表と列の名前を SQL に入れるのは `tables_db.go`・`tables_query.go`・`tables_report.go` の3つだけで、どれも `quoteIdent` を通します。**
  - 入れないページは、テンプレート領域と、拡張が `RegisterTablesExclusion` で断るページ（いまは `移行中` のタグを持つページ）です。
- **認可を読むのは、正本ではなく派生**です。`page.GetPerms`（`page_perms` を読む）も `page.EffectivePublic` も `cms.db` を読みます。
  ずれたら、認可は索引に従います。**派生から正本へは書き戻しません。** サイドカーが読めなければ `requireSidecar` がエラーを返し、
  本文の保存・親の付け替え・権限の変更が止まります。
- **`data/` の場所は `WCMS_DATA_DIR` で変えられます**（既定は `data`・2026-10-14・`internal/database/datadir.go`）。
  - `data/` の下を使う所は `database.DataPath` から引きます（本文 `page.MasterDir()`・ゴミ箱 `page.TrashDir()`・3つのDB・`-gencert` の `tls`・メールの保管 `mail`・候補の `autocomplete.json`）。
  - 環境変数を読むのは起動のとき1回だけです（`database.UseDataDirFromEnv`。呼ぶのは `cmd/w-cms/main.go` の冒頭と、道具 `tools/mail/fetch`・`tools/onenote/build`）。
  - この文書の `data/…` は、既定の場所で書いています。**添付の URL `/data/master/…` は URL の名前で、置き場所ではありません**（`page.DataFileHandler` が `MasterDir()` へ読み替えます）。
- **正本を書く道は `page.WriteFileAtomic`**（一時ファイル＋rename）です。**12ファイル・15箇所**です
  （`version.go` が3・`attachment_save.go` が2・`page/perms.go` の中の1と、10-19 の `autocomplete.go` を含む）。
  サーバー（`internal`・`ext`）で `os.WriteFile` が残るのは、ローカル編集の一時ファイル（`local_edit.go`。書いてから rename）の1つだけです。
- **本文を書く道は、1回の書き込みのあいだ `LockPageBody` を取ります**（2026-10-12・`body_lock.go`）。これを「書き込みのロック」と呼びます。
  - 取るのは書き込みのいちばん外側です。`SaveAPIHandler`・`SaveBlockAPIHandler`・`SyncAPIHandler`（`syncLocked`）・`rewritePageBody`（`RewriteBody`・`RewriteBodyUnlessHeld`・`SetPageH1` の芯）・

  - ほかに `ext/toho/order_pdf_sent.go` の `overwriteUnsentOrderPDF` が取ります。こちらは本文を書かず、「送っていない」と決めてから添付を上書きするまでのあいだ、
    「送った」の記録が割り込まないように取ります。合わせて**8ファイル・9箇所**です。
  - ロックは再入できません。取ったまま、同じページの本文を書く関数を呼ぶと止まります。
  - 削除もロックの中で行い、保存の側はロックの中でページが在るかを見ます（`writeBody` は、サイドカーが無ければ 404 で書かない・10-19）。
    それまでは、削除と保存が行き違うと、消したはずのページが本文だけで残りました。
- **重複の見分け・解析済み・弊社品番の結び・通信記録の親子に専用テーブルはありません。** 本文のタグ（`Message-ID`・`受信元`・`弊社品番`・`親ページID`）を
  `page_tags`／`vocab_index` から逆に引きます。
- **索引を SQL で直に読む拡張がある**ことを知っておいてください。コアのテーブル名（`page_tags` など）を SQL に書く所は、拡張に**21ファイル**あります
  （`ext/comm` 4・`ext/comm/contacts` 3・`ext/toho` 14）。
  `page_tags.norm_value` を条件に使うのは、いまも `vocab_query.go` の `PagesByTagLoose` だけです
  （読み出す列に使う所は、拡張に3つ。`comm/handler_replies.go`・`comm/view_unhandled.go`・`toho/filing_candidates.go`）。
- **`:memory:` のDBは接続ごとに別のDB**です。行を読みながら中で別のクエリを投げると、空の別のDBに当たり、絞り込みが静かに全部落ちます。
  読み切ってから返す関数（`cms.TagRowsNamed`・`cms.ChildPages`・`cms.VocabRowsOfType`・`cms.TagsOfPage`）を使います。
- **表示専用の画面の部品（`.vocab-chrome`）は、本文へ入る手前で落とします**（`cms.StripChrome`・`Sanitize`／`SanitizeReport` の冒頭）。
  **順序がこの守りの全部**です（サニタイズは `class` を落とすので、後では印がありません）。タグの飾り・記録の箱の中身も、この印を付けて描きます。
- **テンプレート領域は索引にも鏡にも載りません**（判定はサイドカーと本文で先祖をたどる `IsTemplateArea`。DBを見ない）。
  テンプレート以下では、鏡は名前だけの案内です。書き込みの API は `RefuseTemplateArea` で 409、取りこぼしは `rewritePageBody` が `ErrTemplateArea` で止めます。
  オートコンプリートの数え上げも、テンプレートの中は数えません。

## 5. 知っておくべき食い違いと注意点

- **編集ロック（`editlock`）は、道具のために残っています。** 画面は 2026-10-12 から `/api/lock` を呼びません（`assets/app.js` に `/api/save`・`/api/lock` の文字はありません）。
  残っているものと、いまの効き方は次のとおりです。
  - `/api/save`・`/api/save-block` は `gateSave` → `RequireLockToken` を通ります。**ロックが無ければ通す**決まりなので、道具が握っているときだけ効きます。
  - 添付の API（`openUpload`）・親の付け替え・削除・版を戻す・権限の変更は、`editlock.RequireEditLock` を通ります（**5ファイル・6箇所**）。画面はトークンを付けないので、道具が握っていなければ通ります。
  - 機械が既存のページを書き換えるときの関門は3つです。
    `editlock.RefuseWhileEditing`（**3ファイル・5箇所**）、`editlock.Locks.EditorOpen`（`editlock/handler.go` を含めて**11ファイル・11箇所**）、`cms.RewriteBodyUnlessHeld`（**7ファイル・9箇所**・10-20）。
    どれも**ロックを握っている人が居るときだけ**断ります。画面が握らなくなったので、ほぼ素通りです。
  - 人の書きかけとの重なりは、いまは `LockPageBody`（1回の書き込み）と `/api/sync` の指紋の比べで守ります。機械もほかの書き手の1人で、ぶつかれば画面が両方を並べます。
  - 版の区切りは、ロックを手放したとき（`editlock.OnRelease` → `RecordVersion(force)`）に加えて、`/api/version-checkpoint` でも打ちます。画面はこちらだけを使います。
- **`RequireAdmin` が2つあります。** `page.RequireAdmin` は `auth.RequireAdmin` への委譲で、実体は1つです。
- **保存のときに本文を読む係は2人**です（`vocabIndexPlugin`＝きっかけ `*`・`dimensionPlugin`＝`part-materials` と `our-order-items`）。
  だから、降りるかどうかの `descend` は **OR でまとめます**（AND にすると明細が索引から消えます）。
  `material_dimensions.block_no` は自分で数えた連番で、コアの `block_no` とは揃えていません（結合しない前提）。
- **鏡のきっかけは21**です（`RegisterMirror` を数えた値）。
  - コアは3つです。`*`（計算ビュー）・`file-view`・`tags`（タグの飾り・10-20）。
  - 東邦は18です。`drawing_mirror.go` が4つの部品の表（`part-materials`・`part-outsourcing`・`part-purchased`・`part-supplied`）を1つの繰り返しで登録します。
    ほかは `client-order-items`・`part-estimate`・`part-estimate-record`・`estimate-items`・`order-draft`・`our-order-link`・`our-order-items`・`rfq-needs`・`rfq-draft`・`rfq-items`・`procure-skip`・
    `delivery-items`・`invoice-items`・`mfg-items`（10-17〜19）です。
  - きっかけごとに担当は1人です。だからタグの並び（`tags`）の担当はコアが持ち、拡張の飾りは `RegisterTagDecorator` へ登録します。
- **同じ名前の定数が、意味を変えて2つあります。** `comm.RecordBoxTitle` は記録の箱の印の名前（`記録の箱`）、`toho.RecordBoxTitle` はトップ直下の置き場の名前（`記録`）です。
  東邦の `PurchaseOrderBoxTitle`（`部材発注`）と `EstimateBoxTitle`（`見積`）は、置き場が無くなったあとも、試験と古い本文のために定数だけが残っています。
- **記録の箱は、本文に印があるページにだけ出ます。** 印はテンプレート「通信記録（…）」が持ちます。コードは既にある記録へ印を書き足しません
  （職場の既存の記録には、2026-10-20 に道具で書き足しました。[作業引き継ぎ.md](../../作業引き継ぎ.md) の「職場で流したデータの道具」）。
- **記録から作るページの選択肢は、記録の箱の中にサーバーが描きます。** そのため `GET /api/record-makers` を呼ぶ画面はもうありません（ルートは残っています）。
  `POST /api/mail/import`（1回分の取り込み）と `POST /api/admin/autocomplete/survey`（候補を今すぐ数え直す・admin）も、画面から呼ぶ所はありません。
- **書類を作る東邦の API は、置き場への write を見ません。** `MfgNewAPIHandler`・`DeliveryNewAPIHandler`・`InvoiceNewAPIHandler`・`NewOurOrderAPIHandler` などは、
  `GateJSONPost` のあと、読める案件の行や表から本文を組み、`cms.EnsureTopLevelBox`／`recordFolderOr` → `newBuiltPage`（`cms.CreateChildPage`）で作ります。
  作ったページの権限は親から写します。ページを作る権利を置き場の write で絞る形ではありません（意図かは未確認）。
- **ファイル表示の「開ける形式」は、配信の側の決まりの帰結です。** `fileViewKinds`（`.pdf`・`.png`・`.jpg`・`.jpeg`・`.webp`・`.gif`・`.svg`・`.mp4`・`.m4a`・`.mp3`）に無い拡張子は、開くためのリンクを出すだけです。
- **添付の配信の入口が2つあります。** 旧い形 `/data/master/…`（`page.DataFileHandler`）と、きれいなURL `/<ページID>/<名前>`（`page.ServeCleanAttachment`）。どちらも `.json` は配りません。
  旧い形の URL の `/data/master` は名前だけで、`page.MasterDir()`（データの場所の下）へ読み替えて配ります。
- **索引の `pages.file_path` は、書くけれど本文を読むのには使いません。** データの場所を変えると古い場所を指すためです。
  本文は `page.BodyPath(id)` から読みます。`file_path` を SELECT するのは `ext/toho/filing_files.go`（`pagesShowing`）だけで、空かどうか（本文がまだ無いページを飛ばす）にしか使いません。
- **`section` に許す `data-*` は4つ**です（`data-type`・`data-src`・`data-ref`・`data-mirror`）。
- **プラグインのテーブルにマイグレーションはありません。** `ApplySchema` は `CREATE TABLE IF NOT EXISTS` です。起動時のずれの検出（`DriftedSchemaTables`）＋自動の再構築で対応します。
  コアのテーブルには手書きのマイグレーション（`database/sqlite.go` の `coreMigrations`）があります。表の写しは `PRAGMA user_version` で作り直します。
- **`WalkElements` を回すファイルは17**です（定義を除く・23箇所）。
  コアの `anchor.go`（2）・`attachment_ref.go`・`file_view.go`・`formula.go`・`parser.go`・`plugin.go`（3）・`ref_render.go`・`sanitize.go`・`shell_public.go`・`tables_db.go`・`view_render.go`・`vocab_notify.go`（3）と、
  拡張の `comm/record_text.go`（2）・`contacts/signature.go`・`mail/compose.go`・`toho/order_docs.go`・`toho/record_sections.go`。
  どれも索引のための走査ではありません（索引は本文を配る仕組み `walk.go` だけ）。
- **コアで dt/dd の対を読むのは `eachDLPair`** です（呼び手は `plugin.go`（2）・`ref_render.go`・`vocab_index.go`・`vocab_notify.go`）。自前で読む所は残っています。
  `page_template.go` の `tagDD` と、東邦の紙の読み手（`readOrderDoc`・`readDeliveryDoc`・`readInvoiceDoc` など）です。`eachDLPair` は非公開なので、拡張からは使えません。
- **節の中の素の表を拾う `eachPlainVocabTable` は、見出しで種類を決める読み方を廃した（09-29）あとも残っています。** 呼び手は `vocab_index.go`（`syncVocabSection`）と `vocab_notify.go` です。
  DBの日本語化 5段目の4で消す候補です（[【考察】DBの日本語化.md](../../考察/【考察】DBの日本語化.md)）。
- **`walkState.Ancestors` / `Closest` に本体の使い手がいません。** [【ガイド】プラグイン開発.md](../【ガイド】プラグイン開発.md) が指す公開APIなので残してあります。
- **本体に呼び手の無い公開関数**（メソッドを除く・値としての参照も数えた値）。
  - **試験にも無いもの3つ**: `cms.EnsureChildByTitle`（`page_lookup.go`）・`cms.VocabBlocksOf`（`vocab_query.go`）・`comm.SendPurposeNames`（`compose.go`）。
  - **試験だけが使うもの5つ**: `cms.FirstBlockHTML`・`cms.ViewMarkerHTML`・`cms.LoadSettingsFrom`・`cms.SetExtAssetRoot`（10-20）・`cms.CellChoiceCounts`（10-19）。
  - 消すか使うかは、利用者の判断です。
- **手配の集計が2本あります。** 古い `RequiredMaterials`（`/api/required-materials`・`RelatedPages` の範囲）と、新しい集計です。
  新しいほうは、手配状況（`ProcurementByProduct`）と必要部材表（`UnorderedItems`）が**同じ帳簿**（`procure_ledger.go` の `buildLedger`）を通します。
  古いほうの API を叩くのは E2E（`verify-template.js`）だけです。
- **社名を機械が書く所は、揃え方が2通りです。** 解析・案件の整理・加工製品の整理の候補・見積書・部材見積依頼の返事は `contacts.OrgNameForPage`（**7ファイル・9箇所**）、
  連絡帳の登録の初期値は `contactRowInitials`（候補が2つ以上なら空）です。
  1つでも生の名前を書くと、完全一致で結ぶ2つの木が黙って結ばれません（`linkPartner` → `PartnerByTitle`）。
- **改訂明細表を探す関数は `revisionTableAt` の1つ**です（属性でも caption でも）。`InsertRevisionRow` は `revision.go` にあり、呼び手は `revision.go` と `drawing_supersede.go` です。
- **`page_tags.norm_value` は宣言型を持ちません。** 束ねる形は `tagNormBind` 1か所です（書き手 `insertVocabEntry`・読み手 `PagesByTagLoose`）。
  この列を条件に使う裸の SQL を書かないでください（型を取り違えると、エラーにならず0件になります）。
- **ページIDを文字列にする所は `page.FormatID` を通します**（`page` の外から**79ファイル・188箇所**）。
- **`MatchDXFAttachments`（PDFとDXFの突き合わせ）は、試験から一度も呼ばれていません**（呼び手は解析の1か所だけ）。
- **メソッドを固定する見張りの試験の範囲です。**
  `method_guard_test.go` は `internal/cms`・`internal/auth`・`ext/comm` の3つにあります。
  `internal/cms` の `TestStateChangingHandlersRejectGET` は15件で、10-12 の API（`/api/sync`・`/api/version-checkpoint`・`/api/presence`）も入りました。
  `ext/toho` には、読むだけの API が POST を断ることを見る `read_only_method_test.go` があります。状態を変える東邦・アドレス帳・メールの API の GET を断る見張りはありません
  （多くは `GateJSONPost` を通すので POST 以外は 405 になりますが、固定する試験はありません）。
- **読んでから組んで書く API は、書くときにロックの中で組み直します。** 2026-10-14 の版で「ロックの外で読む」と書いた `drawing_supersede.go` は、10-19 に直りました
  （旧版ページを作ったあと、`RewriteBody` の中で読み直した本文から組む）。整理の図面の項目・発注元・製造完了のセル・案件明細のセルは `rebuildBody` を通します。
  `cms.RewriteBody` に渡す関数で、引数の本文を見ずに作り置きの本文を返すのは、作ったばかりのページへ書く `newBuiltPage` の1つだけです（`8fff53c` で数えた値）。
