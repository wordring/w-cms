名簿の使い道は4つです。

1. 起動ログの「拡張セット: …」の1行。

### 2c. 置き場と、機械が使うテンプレート

管理画面の「置き場」（`GET/POST /api/admin/pages`・admin）で、足りないものだけを作ります（起動時には作りません）。

### 2d. 拡張の画面のファイル（`internal/cms/ext_scripts.go`）

- 載っている拡張ごとに、`ext/<ID>/assets/` の `.js`・`.css`・`.html` を拾います（`discoverExtAssets`・起動して最初に使うとき1度だけ）。
- 直下のファイルは、編集用の画面の枠へ差し込みます。`.js` は `app.js` のあと、`.css` は `app.css` のあとです（`extScriptTags`・`extStyleTags`。順は URL の文字の順）。
- 1段下のフォルダ（例: `ext/comm/assets/pages/`）のファイルは、配るだけで枠へは差し込みません。
- 配るのは `GET /assets/ext/…` の `ExtScriptHandler`（認証不要・拾ったファイル以外は 404）。`.html` は `ServeStampedHTML`、ほかは `SetAssetCache` を通し、住所の版の印が合えば長く残させます（§2g）。
- ビルドで外した拡張は名簿に無いので、そのファイルも配られません。

派生についての決まりです。

- **`cms.db` は使い捨て**です。`data/master` から丸ごと作り直せます（`RebuildDatabase`）。
  - テーブルは `pages`・`page_perms`（コア）＋`vocab_index`・`page_tags`（`vocabIndexPlugin`）＋`page_links`（`pageLinksPlugin`）＋`material_dimensions`（`dimensionPlugin`・`ext/toho`）＋`rebuild_state`（再構築の進み具合の印・`sync.go`）の**7つ**です。
  - `Register` を通るプラグインは、既定のビルドで**7つ**です。コアの `vocabIndexPlugin`・`pageLinksPlugin` と、拡張の `commPlugin`・`contactsPlugin`・`mailPlugin`・`materialsPlugin`・`dimensionPlugin`。
    表を持つのは `vocabIndexPlugin`・`pageLinksPlugin`・`dimensionPlugin` の3つです。保存のときに本文を読む係（`Observer`）は `vocabIndexPlugin` と `dimensionPlugin` の2つで、
    `page_links` へは `SyncIndex` が `syncPageLinks` を直に呼んで書きます（同じトランザクション。本文を配る仕組みは印のある要素しか届けないため）。
- **`data/tables.db`（表の写し）も使い捨て**です（`tables_db.go`）。
  - 保存のたびに `SyncIndex` が `syncCaptionTables` で、**キャプションのある表だけ**を写します。式のセルは計算した値を入れます。
  - 全再構築で作り直し（`ResetTablesDB`）、版（`PRAGMA user_version`）が古ければ起動時に1度だけ作り直します（`tablesDBOutdated`）。
  - **表と列の名前を SQL に入れるのは `tables_db.go`・`tables_query.go`・`tables_report.go` の3つだけで、どれも `quoteIdent` を通します。**
  - 入れないページは、テンプレート領域と、拡張が `RegisterTablesExclusion` で断るページ（いまは `移行中` のタグを持つページ）です。
- **認可を読むのは、正本ではなく派生**です。`page.GetPerms`（`page_perms` を読む）も `page.EffectivePublic` も `cms.db` を読みます。
  ずれたら、認可は索引に従います。**派生から正本へは書き戻しません。**
- **`data/` の場所は `WCMS_DATA_DIR` で変えられます**（既定は `data`・`internal/database/datadir.go`）。
  - `data/` の下を使う所は `database.DataPath` から引きます（**11ファイル・13箇所**。本文・ゴミ箱・3つのDB・`-gencert` の `tls`・メールの保管・候補・FAX の仕事・出ていない着信・PDF の絵・表示用の写真・通知の鍵）。
  - 環境変数を読むのは起動のとき1回だけです（`database.UseDataDirFromEnv`。呼ぶのは `cmd/w-cms/main.go` の冒頭と、道具 `tools/mail/fetch`・`tools/onenote/build`）。
  - **添付の URL `/data/master/…` は URL の名前で、置き場所ではありません**（`page.DataFileHandler` が `MasterDir()` へ読み替えます）。
- **正本を書く道は `page.WriteFileAtomic`**（一時ファイル＋rename）です。**17ファイル・21箇所**です（`page/perms.go` の中の1を含む）。
  サーバー（`internal`・`ext`）で `os.WriteFile` を直に使うのは4か所で、どれも一時ファイルか、作り直せるもの・初めて作る鍵です
  （`local_edit.go` の一時ファイル・`pdf_clean.go` の作り直す前の写し・`pdf_pages.go` の描き終えた印・`webpush.go` の初めての送り手の鍵）。
- **本文を書く道は、1回の書き込みのあいだ `LockPageBody` を取ります**（`body_lock.go`）。これを「書き込みのロック」と呼びます。
  - 取るのは**8ファイル・10箇所**です。`handler_save.go`（2。`/api/save`・`/api/save-block`）・`handler_sync.go`（`syncLocked`）・`append_page.go`（`rewritePageBody`）・
    `handler_version.go`（`VersionCheckpointAPIHandler`）・`version.go`（2。`RevertToVersion` と、ロックを手放したときの版の区切り）・`handler_delete.go`（`moveToTrash`）・
    `ext/comm/intake.go`（`IntakeContext.UpdatePage`）・`ext/toho/order_pdf_sent.go`（`overwriteUnsentOrderPDF`。本文を書かず、添付を上書きするあいだ「送った」の記録を割り込ませない）。
  - ロックは再入できません。取ったまま、同じページの本文を書く関数を呼ぶと止まります。
  - 削除もロックの中で行い、保存の側はページが在るかを見ます（`writeBody` は、サイドカーが無ければ 404 で書かない）。
- **木の付け替えは `treeMu` で1つずつ通します**（`tree_lock.go`）。消す側は `beginDeleteIfChildless` で子を数えて印を付け、足す側（`/api/new-page`・`CreateChildPage`・親の付け替え）は `withLiveParent` で親が在って消されかけていないかを見ます。
  これが無いと、消すと決めてから移すまでのあいだに作られた子が、ごみ箱の親を指したまま残りました。
- **重複の見分け・解析済み・弊社品番の結び・通信記録の親子に専用テーブルはありません。** 本文のタグ（`Message-ID`・`受信元`・`弊社品番`・`親ページID`・`FAX` の仕事の番号）を
  `page_tags`／`vocab_index` から逆に引きます。同じ印の記録を2枚作らないよう、取り込みは印ごとの錠（`keylock`）の中で引きます。
- **索引を SQL で直に読む拡張がある**ことを知っておいてください。コアのテーブル名を SQL に書く所は、拡張に**24ファイル**あります
  （`ext/comm` 7・`ext/comm/contacts` 3・`ext/toho` 14。`FROM`・`JOIN`・`INTO`・`UPDATE` の直後に書かれた名前で数えた値）。
  `page_tags.norm_value` を条件に使うのは、いまも `vocab_query.go` の `PagesByTagLoose` だけです
  （読み出す列に使う所は、拡張に3つ。`comm/handler_replies.go`・`comm/view_unhandled.go`・`toho/filing_candidates.go`）。
- **`:memory:` のDBは接続ごとに別のDB**です。行を読みながら中で別のクエリを投げると、空の別のDBに当たり、絞り込みが静かに全部落ちます。
  読み切ってから返す関数（`cms.TagRowsNamed`・`cms.ChildPages`・`cms.VocabRowsOfType`・`cms.TagsOfPage`）を使います。
- **表示専用の画面の部品（`.vocab-chrome`）は、本文へ入る手前で落とします**（`cms.StripChrome`・`Sanitize`／`SanitizeReport` の冒頭）。
  同じ場所で、写真の住所の版の印も外します（`StripAttachmentVersions`）。**順序がこの守りの全部**です（サニタイズは `class` を落とすので、後では印がありません）。
- **テンプレート領域は索引にも鏡にも載りません**（判定はサイドカーと本文で先祖をたどる `IsTemplateArea`。DBを見ない）。
  テンプレート以下では、鏡は名前だけの案内です。書き込みの API は `RefuseTemplateArea` で 409、取りこぼしは `rewritePageBody` が `ErrTemplateArea` で止めます。
  リンクの索引・オートコンプリートの数え上げ・参照の引き（`PagesReferringTo`）も、テンプレートの中は数えません。
- **ログインしていない人に描く鏡は、`RegisterPublicMirror` で登録したものだけ**です（2026-10-26）。コアの3つ（計算ビューの器・ファイル表示・タグの飾り）がそうで、
  計算ビューの器も、拡張が `RegisterView` で足したビューは匿名には描きません（`publicViews` はコアが初めから持つビューだけ）。

- **編集ロック（`editlock`）は、道具のために残っています。** 画面は `/api/lock` を呼びません（`assets/app.js` に `/api/save`・`/api/lock` の文字はありません）。
  - `/api/save`・`/api/save-block` は `gateSave` → `RequireLockToken` を通ります。**ロックが無ければ通す**決まりなので、道具が握っているときだけ効きます。
  - 添付の API（`openUpload`）・親の付け替え・削除・版を戻す・権限の変更は、`editlock.RequireEditLock` を通ります（**5ファイル・6箇所**）。
  - 機械が既存のページを書き換えるときの関門は3つです。
    `editlock.RefuseWhileEditing`（**3ファイル・5箇所**）、`editlock.Locks.EditorOpen`（`editlock/handler.go` を含めて**11ファイル・11箇所**）、`cms.RewriteBodyUnlessHeld`（**7ファイル・8箇所**）。
    どれも**ロックを握っている人が居るときだけ**断ります。画面が握らないので、ほぼ素通りです。
  - 人の書きかけとの重なりは、`LockPageBody`（1回の書き込み）と `/api/sync` の指紋の比べで守ります。機械もほかの書き手の1人で、ぶつかれば画面が両方を並べます。
- **`RequireAdmin` が2つあります。** `page.RequireAdmin` は `auth.RequireAdmin` への委譲で、実体は1つです。
- **保存のときに本文を読む係は2人**です（`vocabIndexPlugin`＝きっかけ `*`・`dimensionPlugin`＝`part-materials` と `our-order-items`）。
  だから、降りるかどうかの `descend` は **OR でまとめます**（AND にすると明細が索引から消えます）。
  `pageLinksPlugin` は表を持つだけで、係ではありません（`SyncIndex` が直に書く）。
- **鏡のきっかけは24**です（`RegisterMirror`・`RegisterPublicMirror` を数えた値）。
  - コアは3つで、どれも `RegisterPublicMirror` です。`*`（計算ビュー）・`file-view`・`tags`（タグの飾り）。
  - 東邦は21です。`drawing_mirror.go` が4つの部品の表（`part-materials`・`part-outsourcing`・`part-purchased`・`part-supplied`）を1つの繰り返しで登録します。
    ほかは `client-order-items`・`part-estimate`・`part-estimate-record`・`estimate-items`・`order-draft`・`our-order-link`・`our-order-items`・`rfq-needs`・`rfq-draft`・`rfq-items`・
    `procure-skip`（`mfg_skip.go`）・`delivery-items`・`invoice-items`・`mfg-items`・`mfg-needs`・`mfg-delivery-draft` です。
  - きっかけごとに担当は1人です。だからタグの並び（`tags`）の担当はコアが持ち、拡張の飾りは `RegisterTagDecorator` へ登録します。
- **同じ名前の定数が、意味を変えて2つあります。** `comm.RecordBoxTitle` は記録の箱の印の名前（`記録の箱`）、`toho.RecordBoxTitle` はトップ直下の置き場の名前（`記録`）です。
  東邦の `PurchaseOrderBoxTitle`（`部材発注`）と `EstimateBoxTitle`（`見積`）は、置き場が無くなったあとも、試験と古い本文のために定数だけが残っています（`filing_order.go`）。
- **記録の箱は、本文に印があるページにだけ出ます。** 印はテンプレート「通信記録（…）」が持ちます。コードは既にある記録へ印を書き足しません。
- **画面から呼ぶ所の無い API があります**（`assets/` と `ext/*/assets/` の JS・HTML に住所の文字が無いもの）。
  - 道具・機械・E2E が呼ぶもの: `/api/save`・`/api/save-block`・`/api/lock` の筋（道具）・`/api/intake/eml`（`tools/mail/push`）・`/api/product-folder`（ワンノートの製造の道具）・
    `/api/machine/call`（`cmd/w-cms-phone`）・`/api/machine/fax`（`deploy/fax/` の台本）・`/api/local-edit/file`（`cmd/w-cms-edit`）・`/api/required-materials`（E2E の `verify-template.js`）・
    `/api/mfg/new`（E2E だけ。案件残表の「🏭 製造開始」は `/api/mfg/wait` で製造待ちへ入れ、製造ページは「▶ 開始」の `/api/mfg/start` が作る）・
    `/api/admin/autocomplete/survey`（候補を今すぐ数え直す。E2E の `verify-cell-choices.js`・`verify-tag-enum.js` が、暇を待たずに数えさせる）。
  - 管理者だけの移しの API（リポジトリの外の道具が使う）: `/api/rfq/import`・`/api/rfq/fill-names`・`/api/rfq/set-cells`・`/api/estimate/import`・`/api/table/append-rows`。
  - 画面からもう呼ばれなかった `/api/record-makers`・`/api/replies`・`/api/thread`・`/api/mail/import`・`/api/validate-parent` は、2026-10-30 に外しました。
    記録の箱の選ぶ欄・🧵・📨 は、サーバーが `RecordMakersOf`・`ThreadOf`・`RepliesTo` で描きます。
- **書類を作る東邦の API は、作る先への write を見ます。** `newBuiltPage` の頭の `requireWriteTo` です（ほかに `estimate_calc_doc.go`・`own_case.go`・`quote_case.go`・`mfg_wait.go`・`record_box.go` が同じ関数を呼びます）。
- **ファイル表示の「開ける形式」は、配信の側の決まりの帰結です。** `fileViewKinds` に無い拡張子は、開くためのリンクを出すだけです。
- **添付の配信の入口が2つあります。** 旧い形 `/data/master/…`（`page.DataFileHandler`）と、きれいなURL `/<ページID>/<名前>`（`page.ServeCleanAttachment`）。どちらも `.json` は配りません。
  きれいなURLには、表示用の写真（`?view=1`）と PDF の1ページの絵（`?pdfpage=`）の枝があります。
- **索引の `pages.file_path` は、書くけれど本文を読むのには使いません。** 本文は `page.BodyPath(id)` から読みます。`file_path` を SELECT するのは `ext/toho/filing_files.go`（`pagesShowing`）だけです。
- **`section` に許す `data-*` は4つ**です（`data-type`・`data-src`・`data-ref`・`data-mirror`）。
- **プラグインのテーブルにマイグレーションはありません。** `ApplySchema` は `CREATE TABLE IF NOT EXISTS` です。起動時のずれの検出（`DriftedSchemaTables`）＋自動の再構築で対応します。
  コアのテーブルには手書きのマイグレーション（`database/sqlite.go` の `coreMigrations`）があります。
- **`WalkElements` を回すファイルは18**です（定義を除く・24箇所）。
  コアの `plugin.go`（3）・`vocab_notify.go`（3）・`anchor.go`（2）・`attachment_ref.go`・`file_view.go`・`fixed_tag.go`・`formula.go`・`page_links.go`・`parser.go`・`ref_render.go`・`sanitize.go`・`shell_public.go`・`tables_db.go`・`view_render.go`と、
  拡張の `comm/record_text.go`（2）・`contacts/signature.go`・`mail/compose.go`・`toho/order_docs.go`。
  どれも索引のための走査ではありません（索引は本文を配る仕組み `walk.go` だけ。`page_links.go` は印の無い要素も拾うために自分で歩く）。
- **コアで dt/dd の対を読むのは `eachDLPair`** です（呼び手は `plugin.go`（2）・`fixed_tag.go`・`ref_render.go`・`vocab_index.go`・`vocab_notify.go`）。`eachDLPair` は非公開なので、拡張からは使えません。
- **節の中の素の表を拾う `eachPlainVocabTable` は、見出しで種類を決める読み方を廃した（09-29）あとも残っています。** 呼び手は `vocab_index.go` と `vocab_notify.go` です。
- **`walkState.Ancestors` / `Closest` に本体の使い手がいません。** [【ガイド】プラグイン開発.md](../【ガイド】プラグイン開発.md) が指す公開APIなので残してあります。
- **本体に呼び手の無い公開関数**（メソッドを除く・値としての参照も数えた値）。
  - **試験にも無いもの3つ**: `cms.EnsureChildByTitle`（`page_lookup.go`）・`cms.VocabBlocksOf`（`vocab_query.go`）・`comm.SendPurposeNames`（`compose.go`）。
    `comm.IntakeFile`・`toho.CountOrderDrafts` は、2026-10-30 に外しました。
  - **試験だけが使うもの6つ**: `auth.Authenticate`（本体は `AuthenticateFrom` を呼ぶ）・`cms.FirstBlockHTML`・`cms.ViewMarkerHTML`・`cms.LoadSettingsFrom`・`cms.SetExtAssetRoot`・`cms.CellChoiceCounts`。
  - 非公開の関数では、`toho` の `setOrderItemCell` が試験だけから呼ばれます（同じだった `billedKeys` は、2026-10-30 に外しました）。
  - 消すか使うかは、利用者の判断です。
- **手配の集計が2本あります。** 古い `RequiredMaterials`（`/api/required-materials`・`RelatedPages` の範囲）と、新しい集計です。
  新しいほうは、手配状況（`ProcurementByProduct`）・製造ページの部材（`UnorderedItems` → `mfgPartLines`）・在庫（`stock_in.go`）が**同じ帳簿**（`procure_ledger.go` の `buildLedger`・`openOrderRows`）を通します。
- **社名を機械が書く所は、揃え方が2通りです。** 解析・案件の整理・加工製品の整理の候補・見積書・部材見積依頼の返事・業者の納品書は `contacts.OrgNameForPage`（**9ファイル・11箇所**）、
  連絡帳の登録の初期値は `contactRowInitials`（候補が2つ以上なら空）です。
- **改訂明細表を探す関数は `revisionTableAt` の1つ**です。`InsertRevisionRow` の呼び手は `revision.go` と `drawing_supersede.go` です。
- **`page_tags.norm_value` は宣言型を持ちません。** 束ねる形は `tagNormBind` 1か所です（書き手 `insertVocabEntry`・読み手 `PagesByTagLoose`）。
  この列を条件に使う裸の SQL を書かないでください（型を取り違えると、エラーにならず0件になります）。
- **ページIDを文字列にする所は `page.FormatID` を通します**（`page` の外から**101ファイル・225箇所**）。
- **`MatchDXFAttachments`（PDFとDXFの突き合わせ）は、試験から一度も呼ばれていません**（呼び手は解析の1か所だけ）。
- **メソッドを固定する見張りの試験の範囲です。**
  `method_guard_test.go` は `internal/cms`・`internal/auth`・`ext/comm` の3つにあります。
  `internal/cms` の `TestStateChangingHandlersRejectGET` は15件です。`ext/toho` には、読むだけの API が POST を断ることを見る `read_only_method_test.go` があります。
  状態を変える東邦・アドレス帳・メールの API の GET を断る見張りはありません（多くは `GateJSONPost` を通すので POST 以外は 405 になりますが、固定する試験はありません）。
- **読んでから組んで書く API は、書くときにロックの中で組み直します。** 整理の図面の項目・発注元・製造完了のセル・案件明細のセル・製造待ちは `rebuildBody`（**5ファイル・6箇所**）を通します。
  `cms.RewriteBody` に渡す関数で、引数の本文を見ずに作り置きの本文を返すのは、作ったばかりのページへ書く `newBuiltPage` の1つです。
- **機械の書き換えは、版を3回まで記録します**（`rewritePageBody`）。書き換える前の中身を区切りの版にし、書いたあとの中身で版を切り、同じ中身でもう一度区切って閉じます（3回目は意図。コメントに理由があります）。
