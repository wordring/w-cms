- **`cms` は `ext/` を import しない。** 拡張は `init()` で自分をコアの登録表へ足すだけで、コアは拡張の存在を
  知りません。**コアが宣言する登録の口は11**（`grep '^func Register' internal/cms`）——`Register`（プラグイン）・
  `RegisterVocab`・`RegisterView`・`RegisterMirror`・`RegisterContactResolver`・`RegisterSettingsSection`・

  `RegisterUploadInterceptor`（アップロードの横取り・09-30 撤去）は**もうありません**。
  **業務の言葉がコアに要るときは、口をコアに作り、言葉は拡張から渡す**（開発方針 §0——例:
  `RegisterTablesExclusion` へ `移行中` のタグを渡すのは `ext/toho/material_price.go`）。

  > 通信の口はコアではなく `ext/comm` にあります——`RegisterIntake`（取り込み係・`intake.go`）・
  > `RegisterMailer`／`RegisterOwnAddresses`（メール・`mail.go`）・**`RegisterSendPurpose`**（送る欄の用件・
  > `compose.go`・09-30）・**`RegisterContactNamer`**（アドレス→連絡帳の名前・`contact_name.go`・09-30）・**`RegisterRecordMaker`**（記録から作るページの種類・`record_make.go`・10-01）。

| ID | 名前 | 名乗る場所 |
|---|---|---|

### 2c. 置き場と、機械が使うテンプレート（2026-09-27〜）

**置き場**（トップ直下の、名前で機能が決まるページ）は拡張が `cms.RegisterRequiredPage` で名乗り、管理画面の
「置き場」（`GET/POST /api/admin/pages`・admin）で足りないものだけを作ります（起動時には作らない）。
⚠ **本文は同じ題のテンプレートから写す**（`box_template.go` の `BoxTemplateID`）——テンプレートが無ければ作れない。

| 題 | 持ち主 | 名乗る場所 |
|---|---|---|
| `テンプレート` | コア | `internal/cms/template.go` の `init` |
| `通信箱` | `comm` | `ext/comm/intake.go` の `init` |
| `連絡帳` | `comm/contacts` | `ext/comm/contacts/contacts.go` の `init` |
| `取引先`・`受注`・`発注` | `toho` | `ext/toho/materials.go` の `init` |

同じ題は登録できません（`panic`）。トップ直下に同じ題の置き場を2枚作ることは保存の時点で 409
（`handler_save.go` の `refuseDuplicateBoxTitle`）。

**機械が作るページ**（解析・取り込み・送信の控え・手で作る記録・連絡先・発注書・加工製品の箱）は、テンプレート置き場に
在る**同じ題のページを写して**印（タグの名前・表のキャプション・見出しの節）を埋めます（`page_template.go` の
`DraftFromTemplate` → `PageDraft`）。テンプレートが無いか2枚あれば 409（`ErrNoPageTemplate`）。何が要るかは
拡張が `cms.RegisterPageTemplate` で名乗り、管理画面の「機械が作るページのテンプレート」に在る／無い／2枚あるが出る
（`PageTemplateStatuses`）。**9つ**:

| 題 | 持ち主（名乗る場所） |
|---|---|
| `通信記録（受信メール）`・`通信記録（手入力）` | `comm`（`intake.go`） |
| `通信記録（送信メール）` | `comm/mail`（`plugin.go`） |

派生に関する規律:

- **`cms.db` は使い捨て**。`data/master` から丸ごと作り直せます（`RebuildDatabase`）。テーブルは `pages`・`page_perms`
  （コア）＋ `vocab_index`・`page_tags`（観察係 `vocabIndexPlugin`）＋ `material_dimensions`（観察係 `dimensionPlugin`・
  `ext/toho`）＋ `rebuild_state`（再構築の進行印・`sync.go`）の**6つ**。`Register` を通るプラグインは既定のビルドで6つ——
  コアの `vocabIndexPlugin` と、拡張の `commPlugin`・`contactsPlugin`・`mailPlugin`・`materialsPlugin`・`dimensionPlugin`。
  表を持つのは `vocabIndexPlugin` と `dimensionPlugin` だけ。
- **`data/tables.db`（表の写し）も使い捨て**（2026-09-25・`tables_db.go`）。保存のたびに `SyncIndex` が
  `syncCaptionTables` で**キャプションのある表だけ**を写し、表の名前はキャプション・列の名前は見出し（`TableName` で
  正規化）。同じ名前の表は1つに入れて列を統合する。**全再構築で作り直し**（`ResetTablesDB`）、版（`PRAGMA
  user_version`）が古ければ起動時に1度だけ作り直す（`tablesDBOutdated`）。**表と列の名前を SQL に入れるのは
  `tables_db.go`・`tables_query.go`・`tables_report.go` の3つだけで、どれも `quoteIdent` を通す**。⚠ **入れないページ**——テンプレート領域と、拡張が `RegisterTablesExclusion` で断るページ
  （いまは `移行中` のタグを持つページ）。⚠ **移行のあいだは `vocab_index` にも書き続ける**（集計がそちらを読むため）。
- **⚠ 認可の読み口は正本ではなく派生**——`page.GetPerms`（`page_perms` を読む）も `page.EffectivePublic` も `cms.db`。
  **ずれたら認可は索引に従う**。**派生から正本へは書き戻さない**——サイドカーが読めなければ `requireSidecar` がエラーを
  返し、本文保存・親の付け替え・権限変更が**止まる**。
- **正本を書く経路は `page.WriteFileAtomic`**（一時ファイル＋rename）——**11ファイル・13箇所**（`version.go` が3）。
  サーバー（`internal`・`ext`）で `os.WriteFile` が残るのは、ローカル編集の一時ファイル（`local_edit.go`——書いてから
  rename）とデータの初期化の写し戻し（`reset_data.go`）の2つで、どちらも正本を直に上書きしない（ほかに常駐ヘルパーの
  `cmd/w-cms-edit` が手元の写しを書く）。
- **重複検知・解析済み・弊社品番の結びに専用テーブルは無い**——本文のタグ（`メッセージID`・`受信元`・`弊社品番`）を
  `page_tags`／`vocab_index` から逆に引く。
- **`:memory:` DBは接続ごとに別のDB**。行を読みながら中で別のクエリを投げると空の別DBに当たり、絞り込みが静かに
  全部落ちる。読み切ってから返す口（`cms.TagRowsNamed`・`cms.ChildPages`・`cms.VocabRowsOfType`・`cms.TagsOfPage`）を使う。
- **⚠ 表示専用クローム（`.vocab-chrome`）は本文へ入る手前で落とす**（`cms.StripChrome`・`Sanitize`／`SanitizeReport`
  の冒頭）。**順序がこの守りの全部**（サニタイズは `class` を落とすので、後では印が無い）。
- **テンプレート領域は索引にも鏡にも載らない**（判定はサイドカー＋本文で先祖を辿る `IsTemplateArea`——DBを見ない）。
  テンプレート以下では鏡は名前だけの案内、書き込みの口は `RefuseTemplateArea` で 409。

## 5. 既知のねじれ・注意点

- **`RequireAdmin` が2つある**——`page.RequireAdmin` は `auth.RequireAdmin` への委譲で、実体は1つ。
- **観察係は2人**（`vocabIndexPlugin`＝引き金 `*`・`dimensionPlugin`＝材料と発注明細）。だから `descend` は **OR で畳む**
  （AND にすると明細が索引から消える）。`material_dimensions.block_no` は自分で数えた連番
  （`ctx.Counter(dimensionTable+":"+dataType)`）で、コアの `block_no` とは**揃えていない**（結合しない前提）。
- **添付の配信口が2つある**——旧形 `/data/master/…`（`page.DataFileHandler`）ときれいなURL `/<ページID>/<名前>`
  （`page.ServeCleanAttachment`）。どちらも `.json` は配らない。
- **ファイル表示の「開ける形式」は配信側の帰結**——`fileViewKinds`（`.pdf`・`.png`・`.jpg`・`.jpeg`・`.webp`・`.gif`・
  `.svg`・`.mp4`・`.m4a`・`.mp3`）に無い拡張子は開く口（リンク）を出すだけ。
- **`section` に許す `data-*` は4つ**（`data-type`・`data-src`・`data-ref`・**`data-mirror`**）。
- **プラグインテーブルにマイグレーションは無い**——`ApplySchema` は `CREATE TABLE IF NOT EXISTS`。起動時のずれ検出
  （`DriftedSchemaTables`）＋自動再構築。コアテーブルには手書きのマイグレーション（`database/sqlite.go` の
  `coreMigrations`）。表の写しは `PRAGMA user_version` で作り直す。
- **`WalkElements` を回すファイルは14**（定義を除く）——コアの `anchor.go`（2）・`attachment_ref.go`・`file_view.go`・
  `parser.go`・`plugin.go`（3）・`ref_render.go`・`sanitize.go`・`shell_public.go`・`tables_db.go`・`view_render.go`・
  `vocab_notify.go`（3）と、拡張の `contacts/signature.go`・`mail/compose.go`（3）・`toho/order_docs.go`。
  いずれも索引の走査ではない（索引は配送係 `walk.go` だけ）。
- **コアで dt/dd の対を読むのは `eachDLPair`**（呼び手は `plugin.go`（2）・`ref_render.go`・`vocab_index.go`・
  `vocab_notify.go`）。⚠ **自前で読む所が2つ残っています**——`page_template.go` の `tagDD`（テンプレートの印の欄を
  名前で探して埋める）と、`ext/toho/order_pdf.go` の `readOrderDoc`（発注書の可変タグを紙へ）。`eachDLPair` は
  非公開なので拡張からは使えない。
- **節の中の素の表を拾う `eachPlainVocabTable` は、見出しで名乗る読み方を廃した（09-29）あとも残っている**——呼び手は
  `vocab_index.go`（`syncVocabSection`）と `vocab_notify.go`。DBの日本語化 5段目の4で消す候補
  （[【考察】DBの日本語化.md](../../考察/【考察】DBの日本語化.md)）。
- **`walkState.Ancestors` / `Closest` に使い手がいない**（`Ancestors` は `walk_test.go` だけ・`Closest` は0件）。文書
  （【ガイド】プラグイン開発）が指す公開APIなので残してある。
- **本体に呼び手の無い公開関数**（インターフェースの実装・`Ancestors`／`Closest` を除く）——**試験にも無いもの3つ**:
  `cms.EnsureChildByTitle`（`page_lookup.go`）・`cms.VocabBlocksOf`（`vocab_query.go`・`ext/toho/analyzed.go` のコメントにだけ
  名前が出る）・`comm.SendPurposeNames`（`compose.go`）。**試験だけが使うもの7つ**: `cms.WriteTag`・`cms.FirstBlockHTML`
  （`append_page.go`——機械が作るページがテンプレートの印を埋める形になって、タグを文字で組む口が空いた）・
  `cms.ViewMarkerHTML`・`cms.LoadSettingsFrom`（試験の設定の読み込み）・`cms.AttachmentVersions`（`webdav_write.go`）・
  `contacts.PartnerCandidates`・`toho.AllSent`（`order_status.go`）。消すか使うかは利用者の判断。
- **`Locks.Validate` を直に呼ぶのは `editlock/handler.go` の `RequireLockToken` だけ**。
- **既存ページの本文を機械が書き換える口には別の関門がある**——`editlock.RefuseWhileEditing`（1ページ）か
  `editlock.Locks.EditorOpen`（まとめ押し）。呼び手は拡張の12ファイル（`contacts_handler.go`（3）・`handler_handled.go`・
  `mail/compose.go`・`toho/backlog.go`・`filing.go`（2）・`filing_duplicate.go`・`filing_order.go`・`handler_gate.go`・
  `order_draft.go`・`order_mail.go`・`product_tree.go`・`temp_parts.go`（2））と `editlock/handler.go`。
  **自分が開いていても断る**／**保持者が居なくなったロックは無視する**。`RequireEditLock` は使えない
  （一覧画面のボタンはトークンを持てない）。
- **手配の集計が2本ある**——古い `RequiredMaterials`（`/api/required-materials`・`RelatedPages` のスコープ）と、新しい
  `ProcurementByProduct`（手配状況リストの描画・全社の発注明細を `弊社品番` で束ねる）。古いほうを叩くのは E2E
  （`verify-template.js`）だけ。
- **社名を機械が書く口は4つ、揃え方は2通り**——解析・受注の整理・加工製品の整理は `contacts.OrgNameForPage`、連絡帳の
  登録の初期値は `contactRowInitials`（同じ考えで、候補が2つ以上なら空）。1つでも生の名前を書くと、完全一致で結ぶ
  2つの木が黙って結ばれない（`linkPartner` → `PartnerByTitle`）。
- **改訂明細の表を探す口は `revisionTableAt` の1つ**（属性でも caption でも）——`InsertRevisionRow` は
  `analyze_pdf.go` に居て、呼び手は `revision.go` だけ（置き場と呼び手が別ファイル）。
- **`page_tags.norm_value` は宣言型を持たない**——束ねる形は `tagNormBind` 1か所（書き手 `insertVocabEntry`・読み手
  `PagesByTagLoose`）。**この列を述語に使う裸の SQL を書かないこと**（型を取り違えるとエラーにならず0件）。
- **ページIDを文字列にする所は `page.FormatID` を通す**（本体で33ファイル・54箇所）。
- **⚠ `MatchDXFAttachments`（PDFとDXFの突き合わせ）は試験から一度も呼ばれていない**（呼び手は解析の1か所だけ）。
- **`ext/toho` と `ext/comm/*` の下位パッケージにメソッド確認の番人が無い**——`method_guard_test.go` は
  `internal/cms`・`internal/auth`・`ext/comm` の3つにだけある。

## 7. 数え直す（この文書を疑うとき）

```bash
# 規模（ext/ と tools/ を必ず含めること）
find cmd internal ext -name '*.go' -not -name '*_test.go' | xargs wc -l | sort -rn | head -21
find cmd internal ext tools -name '*_test.go' | xargs cat | wc -l
grep -rh '^func Test' --include='*_test.go' cmd internal ext tools | wc -l
wc -l assets/*.js assets/*.css assets/*.html
ls e2e/verify-*.js | wc -l; ls e2e/probe-*.js | wc -l

# パッケージ依存の向き（ディレクトリごと）
for d in internal/cms ext/comm ext/comm/contacts ext/comm/mail ext/toho; do
  echo "$d → $(ls $d/*.go | grep -v _test.go | xargs grep -h '"w-cms/' | sed 's/.*"w-cms\/\([^"]*\)".*/\1/' | sort -u | tr '\n' ' ')"; done
# 拡張どうしの import（向きは必ず「拡張 → 通信」）
grep -rln '"w-cms/ext/' --include='*.go' ext | grep -v _test.go

# ビルドタグ（拡張のパッケージ側には無い＝取り付け口だけ）
grep -rn '^//go:build' --include='*.go' cmd ext internal

# ルート表（コアと、拡張が足す分）
grep -nE 'Handle(Func)?\(' cmd/w-cms/main.go
for d in ext/comm ext/comm/contacts ext/comm/mail ext/toho; do echo "$d $(ls $d/*.go | grep -v _test | xargs grep -h 'Pattern: *"' | wc -l)"; done

# コアが宣言する登録の口と、拡張からの登録
grep -rn '^func Register' --include='*.go' internal/cms | grep -v _test
grep -rn 'cms\.Register[A-Za-z]*(' --include='*.go' ext | grep -v _test

# 語彙の形式・ビュー・ルート・置き場の本数は、組ごとに実際に数えるのがいちばん確か
#   （`_measure/` に小さな main と ext_*.go の写しを置き、cms.VocabDefs() / cms.PluginRoutes() /
#    cms.ExtensionIDs() / cms.RequiredPages() を出す。`_` 始まりは `./...` に拾われない。終わったら消すこと）
go build ./... && go build -tags nomail ./... && go build -tags minimal ./...
```

**`gofmt -l` は判断材料にしないこと**——このリポジトリでは CRLF のため全ファイルが挙がります。
整形の確認は `go build` / `go vet` / `go test` で行います。
