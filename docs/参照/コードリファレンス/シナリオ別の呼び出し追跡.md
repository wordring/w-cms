# シナリオ別の呼び出し追跡

**対象コミット: `8fff53c`（2026-10-21。この時点のコードから作り直しました・[全体地図.md](全体地図.md) と同じ測定）**

主な操作について、呼び出しの連鎖を**実際に追える形**で並べます。関数名は実在するものだけを書きます。
分かれ道（403／404／409／423 になる条件）も添えます。個々の関数の説明は `go doc` が、呼び出し元の一覧は
[【一覧】関数リファレンス.md](【一覧】関数リファレンス.md) が持ちます。

> **連鎖の多くはパッケージをまたぎます。**
> 取り込み（§6）・メールの読み込み（§6b）・記録の箱と記録から作るページ（§7b）・メールを送る（§7d）・未処理（§8c）は `ext/comm`（と `ext/comm/mail`）です。
> 解析・整理・案件から部材発注・見積と部材見積依頼・製造と納品と請求（§7・§7c・§8e・§8f・§8i）は `ext/toho`、連絡帳（§8d）は `ext/comm/contacts` です。
> **向きを間違えないこと。** コアは拡張を呼びません。コアは**登録された関数を呼ぶ**だけで、そこに何が積まれているかを知りません。

> **2026-10-12 から、画面は編集権（ページ単位のロック）を取りません。** 画面の保存は §2 の `/api/sync` だけです。
> `/api/save`・`/api/lock` の筋（§2b）は、道具のために残っている道です。

すべての要求は、いちばん外側を通ります。

```
CSPProtect( … )                     … 全部の応答へ Content-Security-Policy（strict。'unsafe-inline' なし）
        └─ /     → CSRFProtect(root)
                    … GET/HEAD/OPTIONS 以外は Origin（無ければ Referer）とホストの一致を求める
                      → 別のオリジンなら 403、どちらのヘッダも無ければ 403
```

## 0. 起動

`cmd/w-cms/main.go` の `main()` です。

```

                                     証明書・DB・本文・メールの保管・候補のファイルは、どれもここから引く）
（-gencert なら自己署名の証明書を defaultCertDir()＝<データの場所>/tls に作って終わる。設定もDBも要らないので先に処理する）

  └ ずれがあれば cms.RebuildDatabase()   … 全テーブルを DROP して data/master から作り直す

cms.RebuildIfNeeded()              … ①中断した再構築のやり直し ②表の写しの版が古ければ作り直し
                                     ③空のDB＋ファイルありの復旧
database.InitAuthDB()              … data/auth.db を開き AuthTables

WCMS_TLS_CERT と WCMS_TLS_KEY が両方あるとき
  newCertReloader(cert, key)       … 証明書と鍵のファイルが替わったら、次の接続から読み直す（cert_reload.go・2026-10-19）
  srv.ListenAndServeTLS(listenAddr(true))   … WCMS_ADDR・無ければ :8443

> 設定はDBより先に読みます。この後の再構築が、語→型の推論の辞書を使うためです。
> `RebuildDatabase` も先頭で `LoadSettings` を読み直すので、辞書へ語を足しても **DB再構築**（§11）だけで効きます。

## 1. ページを開く（`GET /{id}`）

`RootHandler`（`handler_view.go`）です。**体裁は相手で分かれます。**

```
RootHandler
├ id が "" / "index.html"        → 302 /000000（クエリは保つ）
├ id == "000000" かつ pages に無い → 既定のHTMLとサイドカー（mode 302）を作って SyncIndex（初めの起動）
├ id に "/" を含む（/<6桁>/<名前>） → page.ServeCleanAttachment（§5 の[配信①]）
├ id に英数字とハイフン以外      → pageNotFound
├ 数にならない・pages に行が無い → pageNotFound
├ requirePageViewable
│   ログインした人 × page.GetPerms(…).CanRead が偽 → forbiddenPage（403・体裁つきのHTML）
│   匿名 × page.EffectivePublic が偽
│     └ トップページ(0) → 302 /login?next=…
│     └ それ以外        → notFoundWithLogin（404・戻り先つきのログインの導線）
├ os.ReadFile(page.BodyPath) 失敗 → pageNotFound
│
├ body = RenderAnchors( RenderReferenceLinks( RenderComputedViews( Sanitize(content) ) ) )
│         ↑ 描画のときだけ ↑ 描画のときだけ     ↑ 式のセルの結果 → 鏡型の段（walkMirror）
│                                                                       ↑ 二層目の防壁（冒頭で StripChrome）
├ 匿名 → servePublicPage（RenderPublicShell・public, max-age=600・Vary: Cookie・ETag・304。スクリプトは読み込まない）
└ ログインした人 → RenderPageShell(body, RenderBreadcrumb(…), title)・Cache-Control: no-store
                   画面の枠へ本文・パンくず・拡張の <script>／<link> を差し込む（extScriptTags・extStyleTags）
```

`RenderComputedViews` は、まず `renderFormulaCells` で表のセルの式（`=個数*単価`）に結果を添えます（`formula.go`）。
次に `hasViewMarker` で早道し、あれば `walkers.walkMirror` で要素を配ります。**ここが「拡張の画面がコアの描画に乗る」唯一の入口**です。

- 鏡は `<section data-mirror="表示名">` で示し、登録が無ければ `missingViewHTML` が理由を出します。テンプレート以下では、鏡は名前だけの案内です（`IsTemplateArea`）。
- タグの並び（`dl[data-type="tags"]`）は、飾りの登録された名前のタグがあるときだけ歩きます（`hasDecoratedTag`）。`decorateTags` が値の欄の末尾へ ☎ や「未分類へ戻す」を足します。
- 通信記録の `<section data-mirror="記録の箱">` には、`recordBoxHTML` が記録の箱を描きます（§7b）。
- 同じ段で表の鏡も走ります。たとえば次のものです。
  案件明細表の足元の検算と受注残高・出荷済数量・製造完了・発行の印・赤字の警告／材料表の最新単価／支給部品表の下の見積回答と受注・見積の単価／
  発注部材表の欄／部材発注明細表の行ごとのボタン／見積計算表と見積表／見積明細表・部材見積依頼明細表・納品明細表・請求明細表・製造明細表の足元／
  部材見積依頼の表の重複の印／手配不要表の戻す／ファイル表示。

`RenderReferenceLinks` は、可変タグ（`dl[data-type="tags"]`）の値を `parseRefValue` に掛け、`pageExists` でリンクか `ref-missing` かを決めます。
`email` 型の名前は `linkEmailDD`（解決係に尋ねる・無ければ素のテキスト）、`ref` 型と宣言されたタグ（`受信元`・`親ページID`・`連絡帳` など）はページIDだけの値をページへの参照として扱います。
表は、列の宣言が `ref` のセルだけ（`弊社品番`）をリンクにします。鏡が `<tfoot>` へ足した行は `inVocabChrome` で飛ばします。

**本文の取得の API（`GET /api/load?id=`）**は `LoadAPIHandler` です。

```
LoadAPIHandler
├ GET 以外は 405 → queryPageID（400）→ RequirePageReadOrPublic
├ pages に行が無い 404 → page.BodyPath の本文（索引の file_path は読まない）
├ RenderComputedViews(Sanitize) を text/plain＋nosniff で返す
└ view=1 のときだけ RenderAnchors(RenderReferenceLinks(…)) も通す
   （閲覧の画面がページの更新の知らせを受けて読み直すとき。開いたときと同じ描き方で比べるため・§3）
```

鏡は埋めて返すので、これを外から `/api/save` へ書き戻すと、鏡が本文に書き込まれてしまいます（`StripChrome` が守りますが、既に保存された鏡は落とせません）。

## 2. 書ける形で保存する（`POST /api/sync`）

`SyncAPIHandler`（`handler_sync.go`・2026-10-12）です。画面の保存は、これ1本です。

画面が送るもの（`SyncRequest`）は次のとおりです。

- `base` … 前の応答で受け取った並びと指紋（`{id, h}` の列）。指紋はサーバーが正本のファイルから計算したものだけを使います。
- `order` … いまの並び（上の段のブロックの ID）。
- `changes` … 変えた（足した）ブロック（`{id, base_h, base_html, html}`。足したブロックは `base_h` が空）。
- `full` … 全部のブロックの書き出しを返してほしい（書ける形に入るとき）。
- `tab` … このタブの印（自分の保存の知らせを受けないため）。

```
SyncAPIHandler
├ POST でない                    → 405
├ DecodeJSONBody（8MiB）         → 413 / 400
├ normalizedPageID               → 400
├ page.RequirePageWrite          → 401 / 403   ← 読むだけ（変えない）でも write が要る。書ける人だけが書ける形に入る
├ 変えたブロックを正本の形へ（ロックの外）
│   SanitizeReport(c.HTML) → storedFormOf（サニタイズ・最初の要素だけ・ID を揃える）。中身が無くなれば当てない
├ syncLocked（2026-10-20 にまとめた。ロックは defer で外す）
│   ├ LockPageBody(id)            ← ページごとの書き込みのロック
│   ├ os.ReadFile(page.BodyPath(id)) → 404
│   ├ splitStoredBlocks           … 本文を上の段のブロックに分ける（空白とコメントは捨てる）→ 500
│   ├ ensureStoredBlockIDs        … ID の無いブロックに中身から決まる ID を振る。振っただけでは書かない
│   ├ plan := planSync(current, req, mine, sanitized)   … 純粋な関数
│   │   消したブロック: 相手が変えていなければ消す。変えていれば残す（kept）
│   │   変えたブロック: いまの指紋が元の指紋のまま、または canonBlock で同じ → 当てる
│   │                  相手と同じに変えた → 相手の版のまま
│   │                  両方が変えた → mergeBlock3（表なら違うセルだけ合わせる）→ 合えば merged
│   │                  合わなければ ぶつかり（kind changed・本文は相手の版のまま）
│   │   相手が消したブロックを変えていた → ぶつかり（kind deleted）
│   │   足したブロック: 画面の並びで前にあるブロックの後ろへ
│   │   並び: 画面が並べ替えていれば画面の並び、そうでなければいまの並びを保つ
│   └ plan.dirty なら（本文が変わる）
│       ├ FillFileViewNames(user, Sanitize(finalBody))
│       ├ writeBody          … refuseDuplicateBoxTitle → 409 ／ サイドカーが無い（消されたページ）→ 404
│       │                      ／ page.BumpUpdatedAt → 500 ／ WriteFileAtomic → 500
│       ├ RecordVersion(id, user, finalBody, false)   … 失敗しても止めない
│       ├ syncBody → SyncIndex → 500
│       └ noteBlockWriters   … 変わったブロックを、この人が書いたと覚える
│      変わらなければ書かない（知らせも出ない。変わったところを読むだけにも使う）
├ 書いたなら auth.AuditRequest(r, "save", id) → notifyPageUpdatedFrom(id, user, tab, updatedAt)
├ 仕上がりのブロックごとに、画面へ渡す理由（why）を決める
│   full（書ける形に入るとき）・other（相手が変えた）・new（相手が足した）・kept・merged・sanitized
│   理由のあるブロックとぶつかりがあれば RenderComputedViews(r, idInt, finalBody) で描いて HTML を添える
│   ぶつかりには blockWriterOf で「誰が書いたか」を添える
└ 200 {success, page_id, updated_at, written, blocks:[{id,h,html?,why?}], conflicts, kept, kept_by?,
       unknown_types, unresolved_fields, stripped_ids}
```

画面の側（`assets/app.js`）の流れです。

```
保存の機会（1.5秒のデバウンスはやめた）
  ブロックを去る（focusout）・タブを隠す（visibilitychange）・ページを去る（pagehide）
  ・閲覧モードへ替える・業務のボタンの前（postJSON → window.wcmsFlushSave）・帯やメニューの操作とアンドゥのあと（saveNow）
     ↓
saveToServer → queueSync(false) → runSync（1本ずつ・syncChain）
  ├ captureAll           … まだ拾っていない自分の変更をアンドゥのコマンドにする
  ├ ensureBlockIds       … 上の段の ID を揃える（入れ子は変えたブロックの中だけ）
  ├ serializeBlocks      … 変わったブロックだけ changes に入れる
  │    サーバーの並びに無いブロックは、元が残っていても「足した」として中身ごと送る
  │    受け取りに行くとき（pull）は、キャレットのある書きかけのブロックを送らない（held）
  ├ fetch('/api/sync', {keepalive: タブを隠す・ページを去るとき})
  │    受け取りに行くだけ（pull で changes が空）のときは X-Wcms-Background: 1 を付ける（セッションを延ばさない）
  └ applySyncResult
       描き直すブロックは差し替える（相手の変更はアンドゥの記録へ写すだけ。adoptExternal）
       送ったあとにまた書いていたブロック → openConflict（黄色い枠・上が相手の版）
       相手が消したのに書いていたブロック → openConflict（「消す」「残す」）
       placeBlocks で仕上がりの並びにする

ぶつかりを決める（resolveConflict）
  「これで決める」「自分の版にする」 … 元を相手の版にしたまま、自分の版を送り直す
  「相手の版にする」               … 相手の版へ差し替える
  「消す」「残す」                 … 消す／足したブロックとして送り直す
```

> 相手の保存の知らせ（§3）を受けると、書ける形のタブは `pullFromServer`（`queueSync(true)`）で変わったブロックを受け取ります。
> 書いている最中のブロックを相手が書き換えていたら、そのブロックを去って送ったときに並べます（表の違うセルなら黙って合わさる）。

## 2b. 道具の保存（`/api/lock` → `/api/save` → `/api/unlock`）

ワンノートの製造の道具（`tools/onenote/build`）・テンプレートの取り込み（`tools/templates.js`）・E2E の `e2e/lib.js` が使う道です。画面は使いません。

```
[握る]   POST /api/lock?id=            LockAPIHandler（editlock/handler.go）
         ├ queryPageID → 400 ／ requireWriter（page.RequirePageWrite）→ 401 / 403
         ├ Locks.TryAcquire … 取れない → 423 {ok:false, holder, same_user, grace_remaining_sec}
         └ 200 {ok, token}（本文は返さない）
[保存]   POST /api/save               SaveAPIHandler（handler_save.go）  入力 {page_id, html, token}
         ├ POST でない → 405 ／ DecodeJSONBody → 413 / 400 ／ page_id が空 → 400
         ├ gateSave … normalizedPageID → 400 ／ page.RequirePageWrite → 401 / 403
         │            ／ editlock.RequireLockToken（JSON の token）→ 409（他者が保持中・トークン失効。ロックが無ければ通す）
         ├ SanitizeReport（冒頭で StripChrome）→ FillFileViewNames
         ├ LockPageBody の中で: writeBody（409 / 404 / 500）→ RecordVersion（止めない）→ syncBody（500）→ noteBlockWriters
         ├ auth.AuditRequest(r, "save", id) → notifyPageUpdated
         └ 200 saveEcho {success, page_id, updated_at, html, sanitized, unknown_types, unresolved_fields, stripped_ids}
         POST /api/save-block（SaveBlockAPIHandler）… 同じ gateSave。ロックの中で読んで ReplaceBlock（無い・重複は 409）→ writeBody → syncBody。版は作らない
[放す]   POST /api/unlock?id=&token=    UnlockAPIHandler → Locks.Release
         └ 保持者本人でトークンが合うときだけ editlock.OnRelease → RecordVersion(…, force=true)（版の区切り）
[強制]   POST /api/lock/force?id=       page.RequireAdmin → Locks.ForceRelease → Audit "lock.force"
[購読]   GET  /api/lock-events?id=&role=holder|waiter&token=   … SSE。presence はこの接続の有無
```

> **`/api/lock` を2回呼ばないこと。** 同じ利用者でも2回目でトークンがずれ、そのあとの削除・保存が 409 になります（`force → lock（1回）→ 使う` の順）。
> 道具が握っているあいだは、ロックを見る関門（添付・削除・親の付け替え・版を戻す・機械の書き換え）が、画面と機械の書き込みを 409 で断ります。

## 2c. 機械が本文を書き換える（`cms.RewriteBody` とその仲間）

`RewriteBody` → `rewritePageBody`（`append_page.go`）です。`RewriteBody` を呼ぶのは**18ファイル・22箇所**、`RewriteBodyUnlessHeld` を呼ぶのは**7ファイル・9箇所**です。

```
rewritePageBody(pageID, author, rewrite)
├ IsTemplateArea(pageID) → ErrTemplateArea（API ごとの RefuseTemplateArea の取りこぼしの受け皿）
├ defer LockPageBody(pageID)()
├ os.ReadFile(page.BodyPath)
├ safe := fillFileViewNamesAs(author, Sanitize(rewrite(current)))
├ noteBlockWriters（機械が変えたブロックは、押した人が書いたと覚える）
├ page.BumpUpdatedAt → page.WriteFileAtomic
├ RecordVersion(pageID, author, safe, false)
├ SyncIndex
└ （defer）notifyPageUpdated(pageID, author, updatedAt)

RewriteBodyUnlessHeld(pageID, author, rewrite)（2026-10-20）
├ editlock.Locks.EditorOpen(ページ) … 道具が握っていれば書かずに *HeldError{Holder}
└ そうでなければ rewritePageBody（上と同じ）

東邦の rebuildBody(pageID, author, body, build)（ext/toho/handler_gate.go・2026-10-19 夜）
├ build(body)   … ロックの外で読んだ本文で組んでみる。断られたら buildErr、変わらなければ書かない（版を足さない）
└ cms.RewriteBody(pageID, …, func(cur) { build(cur) })
                … ロックの中で読み直した本文から組み直して書く。組めなければ何も変えずに buildErr
```

- **ロックは書き込みのあいだだけ**です。人の書きかけとぶつかれば、画面が両方を並べます（機械もほかの書き手の1人）。
- それまでの関門（東邦の `requireWritableIdle`・`editlock.RefuseWhileEditing`・`Locks.EditorOpen`）は、呼び出しが残っています。断るのは、道具がロックを握っているときだけです。
- ロックを取ったまま、同じページの本文を書く関数を呼ばないこと（再入できないので止まります）。
- `RewriteBody` に渡す関数は、引数の本文（いまの本文）から組みます。作り置きの本文を返すのは、作ったばかりのページへ書く `newBuiltPage` の1つだけです。
- 既にあるページを、テンプレートと同じ道具で書き換えるときは `cms.EditBody(cur)` → `SetTag`・`ReplaceTag`・`Container` … → `HTML()` です（メールの下書きの `redraftBody`・10-20）。
  ブロックの ID と字下げの空白を残すので、ブロックへの参照と画面のブロックの突き合わせが壊れません。
- タグを足すときは `cms.AddPageTags(body, pairs)` です。ページのタグの並び（最初の節より前）の末尾へ足し、並びが無ければ h1 の直後に作ります。

## 4. ページを作る（`POST /api/new-page`）

```

├ POST 限定（GET は 405）

**機械が作るページは `cms.CreateChildPage`**（`page_folders.go`）です。`reserveNewPageID` → `Sanitize` → `WriteFileAtomic` → `GetPerms(親)` で継承して `EnsureSidecar` → `SyncIndex`。

## 7d. メールを送る（`GET /api/mail/compose` → `POST /api/mail/draft` → `POST /api/mail/send`・`ext/comm/mail`）

**送る欄は1つの部品で、用件が中身を持ちます。** 用件は「返信」「新規」（`ext/comm/mail`）と「部材発注書」「見積書」「部材見積依頼」（`ext/toho`）の5つです。
画面の欄は `ext/comm/mail/assets/mail-compose.js`（`window.wcmsMailCompose.open`）が共通で描きます。宛先・CC の候補は `GET /api/contacts/addresses`（§8d）です。

```

├ cms.GateJSONGet → 405 / 403
├ draft= … NormalizeID・page.CanView → 404 ／ draftOf（下書きのタグから宛先・件名・本文・添付を戻す）→ 404
│          用件の Defaults から、送る前の説明（SendNote）・送るときに作るファイル（Generated・その一言 GeneratedNote）だけ借りる
├ purpose= … comm.SendPurposeOf → 知らない用件は 400 ／ purposePage（元のページが要る用件は読めるか）→ 400 / 404
│            → 用件の Defaults(user, pageID)
└ 200 {success, draft, ready}

[下書き] POST /api/mail/draft  DraftSaveAPIHandler
├ GateJSONPost ／ DecodeJSONBody ／ 用件 → 400 ／ purposePage
├ draft_id あり → checkDraftWritable（PageIDOrFail・RequirePageWrite・下書きのページだけ・RefuseTemplateArea・RefuseWhileEditing → 409）
│               → RewriteBody(redraftBody)  … cms.EditBody(いまの本文) → ReplaceTag で、送る欄が持つものだけを入れ替える（10-20）
│                                              人が下書きのページに直に書き足したものは残る。組めなければ 409

│        → MailBoxPageID（無ければ 409）→ comm.CreateRecordPage（通信箱／年／月）

[パソコンから添付] POST /api/mail/attach（multipart: draft_id・file）  MailAttachAPIHandler（compose_attach.go）

├ draft_id あり → checkDraftWritable（送る前に確かめる）→ 409
├ 返信元があれば NormalizeID → 400 ／ page.CanView → 404
├ 控えのテンプレートを組めなければ 409（送らない）
├ 用件の Prepare（送るときに添えるファイル。見積書・部材見積依頼書は PDF を作って添える。部材発注書は表示中の PDF を添え、無いときだけ作る）

## 9. 版を取り出す・戻す

```
[一覧] GET /api/versions?id=      VersionsAPIHandler … queryPageID → page.RequirePageRead → ListVersions（新しい順）
[取得] GET /api/version?id=&v=    VersionAPIHandler  … queryPageID → page.RequirePageRead → ReadVersion（safeVersionID・8MiB）
                                   → RenderComputedViews(r, idInt, Sanitize(body)) を text/plain ＋ nosniff
[戻す] POST /api/revert           RevertAPIHandler
├ POST 限定 ／ DecodeJSONBody ／ normalizedPageID → 400 ／ page.RequirePageWrite → 401 / 403
├ editlock.RequireEditLock → 409（道具がロックを握っているときだけ）
├ RevertToVersion → 失敗は 400
│   ReadVersion → LockPageBody → いまの内容を RecordVersion(force) → Sanitize（いまの許可リストで）
│   → WriteFileAtomic → BumpUpdatedAt → SyncIndex → 戻した内容も RecordVersion(force) → notifyPageUpdated → noteBlockWriters
├ auth.AuditRequest(r, "revert", "<id> -> <版ID>")
└ 200 {success, page_id, version, html: RenderComputedViews(Sanitize(戻した本文))}
[区切り] POST /api/version-checkpoint?id=   … §3c
```

画面の側です。ページ丸ごと戻すときは `revertToVersion`（書ける形なら、戻したあと `loadForEditing` で元ごと受け取り直して `rebaseHistory`）。
**「このブロックだけ戻す」**（`openVersionBlocks` → `revertOneBlock`）はサーバーの API を持ちません。版を `GET /api/version` で読み、
いまと違うブロックを並べ、押したブロックを画面で差し替えて、ふつうの保存（§2 の `/api/sync`）で送ります（相手がそのブロックを書いていればぶつかります）。

`RecordVersion` の決まりです。中身のハッシュが最新の版と同じなら何もしない（区切りなら印 `Sealed` を付ける）／区切りでなく、同じ人で、最新の版が区切られておらず、
版IDから10分以内ならその版を置き換える／それ以外は新しい版を切る。**版の掃除はありません**（2026-09-23 に撤去）。

```

## 12. ログイン・ログアウト

```
[画面]   GET /login          auth.LoginPageHandler（認証不要）。?error=1 は「違います」、?error=wait は「しばらく待って」
[認証]   POST /api/login     auth.LoginAPIHandler（認証不要・CSRFProtect は通る）
         ├ loginSem（argon2id の同時実行を4件に制限）
         ├ Authenticate
         │   ├ isLockedOut … 続けて失敗した数に応じた待ち（backoffFor。1・2・4・8秒、5回で15分のロックアウト）
         │   │   待ちのあいだはパスワードを確かめずに断る（ErrLockedOut・数えない）。数えるのは打たれた利用者名ごと
         │   ├ 不在・無効・ハッシュ無しは decoyHash で時間を均してから失敗
         │   └ VerifyPassword 失敗 → recordFailure
         ├ 失敗 → auth.Audit(username, "login.fail", clientIP) → 302 /login?error=1（待ちなら error=wait）&next=…
         ├ CreateSession → setSessionCookie（HttpOnly・SameSite=Lax・Secure は WCMS_SECURE_COOKIES）
         ├ auth.Audit(user, "login", clientIP)
         └ 302 next（safeNextPath が同じサイトの絶対パスだけに絞る）
[破棄]   POST /api/logout    auth.LogoutAPIHandler（POST 限定）→ Audit "logout" → DeleteSession → 302 /login
[状態]   GET /api/me         auth.MeAPIHandler（OptionalAuth。未認証は 200 {authenticated:false}）
[残り]   GET  /api/session   auth.SessionAPIHandler（RequireAuth）… SessionRemaining → {expires_in, idle_ttl, warn_before}。寿命は延ばさない
         POST /api/session   … 告知の「続ける」。操作なので RequireAuth を通るときに延び、延びたあとの残りを返す
         切れていれば RequireAuth が 401（ここへは来ない）
```

セッションは**最後の操作から8時間**で切れます（`SessionIdleTTL`）。

```
RequireAuth / OptionalAuth → userFromRequest(w, r)
  └ resolveSession(token, isOperation(r))
       last_seen から8時間を過ぎていれば → 行を消して未認証
       操作で、前の記録から1分以上（sessionTouchEvery）→ last_seen・expires_at を今に → setSessionCookie で Cookie を出し直す
  isOperation が偽（延ばさない）… X-Wcms-Background: 1 の要求・/api/page-events・/api/lock-events・/api/presence・GET /api/session
```

画面の側は `assets/session.js` です（`index.html`・`admin.html`・`tables.html`・`ext/comm/assets/pages/mails.html`）。`GET /api/session` で残りを聞き、`warn_before`（5分）を切ったら画面の上に帯を出します。
「続ける」は `POST /api/session` です。切れたら（401）ログインへ移ります。ただし書きかけがあれば（`window.wcmsHasUnsaved`・`app.js`）移らずに帯で知らせ、ログインは別のタブで開きます。
`app.js` は、裏で自動に送る要求（受け取りだけの `/api/sync`・知らせを受けての `/api/load?view=1`）に `X-Wcms-Background: 1` を付けます。拡張の JS は `window.wcms.bgHeaders` を使います（メールの読み込みの見張りなど）。
接続元のアドレス（`clientIP`）は、前段がループバックか私設のアドレスのときだけ `X-Forwarded-For` を採ります。
