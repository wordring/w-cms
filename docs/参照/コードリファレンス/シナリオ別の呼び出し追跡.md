# シナリオ別の呼び出し追跡

**対象コミット: `609bb6ef`（2026-10-30。`c20d76b6` のコードから作り直し、`609bb6ef` までの変更を写しました・[全体地図.md](全体地図.md) と同じ測定）**

主な操作について、呼び出しの連鎖を**実際に追える形**で並べます。関数名は実在するものだけを書きます。
分かれ道（403／404／409／423 になる条件）も添えます。個々の関数の説明は `go doc` が、呼び出し元の一覧は
[【一覧】関数リファレンス.md](【一覧】関数リファレンス.md) が持ちます。

> **連鎖の多くはパッケージをまたぎます。**
> 取り込み（§6）・メールの読み込み（§6b）・機械の入口（§6c）・記録の箱（§7b）・メールを送る（§7d）・FAX と電話（§7e）・未処理（§8c）は `ext/comm`（と `ext/comm/mail`）です。
> 解析・整理・案件から部材発注・見積と部材見積依頼・製造と納品と請求（§7・§7c・§8e・§8f・§8i）は `ext/toho`、連絡帳（§8d）は `ext/comm/contacts` です。
> **向きを間違えないこと。** コアは拡張を呼びません。コアは**登録された関数を呼ぶ**だけで、そこに何が積まれているかを知りません。

> **画面は編集権（ページ単位のロック）を取りません。** 画面の保存は §2 の `/api/sync` だけです。
> `/api/save`・`/api/lock` の筋（§2b）は、道具のために残っている道です。

すべての要求は、いちばん外側を通ります。

```
CSPProtect( … )                     … 全部の応答へ Content-Security-Policy（strict。'unsafe-inline' なし）
        └─ /     → CSRFProtect(root)
                    … GET/HEAD/OPTIONS 以外は Origin（無ければ Referer）とホストの一致を求める
                      → 別のオリジンなら 403、どちらのヘッダも無ければ 403
                    … 前置き /api/machine/ と、業務サーバーの中の入口から来た要求は確かめない（ブラウザではないため）
```


## 1. ページを開く（`GET /{id}`）

`RootHandler`（`handler_view.go`）です。**体裁は相手で分かれます。**

```
RootHandler
├ id が "" / "index.html"        → 302 /000000（クエリは保つ）
├ id == "000000" で本文のファイルが無い → 既定のHTMLとサイドカー（mode 302）を作って SyncIndex（初めの起動）
├ id に "/" を含む（/<6桁>/<名前>）
│   ├ ?pdfpage= → ServePDFPage（PDF の1ページの絵・§5c）
│   ├ ?view=1   → ServePhotoView（表示用の写真・§5c）
│   └ それ以外  → page.ServeCleanAttachment（§5 の[配信①]）
├ ゼロ詰めの6桁でない（isCanonicalPageID）→ pageNotFound（/2240 や /02240 は開けない）
├ pages に行が無い → pageNotFound
├ requirePageViewable
│   ログインした人 × page.GetPerms(…).CanRead が偽 → forbiddenPage（403・体裁つきのHTML）
│   匿名 × page.EffectivePublic が偽 → トップページは 302 /login?next=…・それ以外は notFoundWithLogin（404）
├ os.ReadFile(page.BodyPath) 失敗 → pageNotFound
│
├ body = RenderAttachmentVersions( RenderAnchors( RenderReferenceLinks( RenderComputedViews( Sanitize(content) ) ) ) )
│         ↑ 写真の住所に版の印   ↑ 描画のときだけ ↑ 描画のときだけ   ↑ 式のセル → 鏡型の段   ↑ 二層目の防壁
├ 匿名 → servePublicPage（RenderPublicShell・public, max-age=600・Vary: Cookie・ETag・304。スクリプトは読み込まない）
└ ログインした人 → RenderPageShell(body, RenderBreadcrumb(…), title)
                   → 印 <!--WCMS_BOOT--> を bootDataHTML(r, id) で埋める（§14）・Cache-Control: no-store
```

`RenderComputedViews` は、まず `renderFormulaCells` で表のセルの式に結果を添えます。
次に `hasViewMarker` で早道し、あれば `walkers.walkMirror` で要素を配ります。**ここが「拡張の画面がコアの描画に乗る」唯一の入口**です。

- 鏡は `<section data-mirror="表示名">` で示し、登録が無ければ `missingViewHTML` が理由を出します。テンプレート以下では、鏡は名前だけの案内です。
- **匿名に描くのは `RegisterPublicMirror` の鏡だけ**です（計算ビューの器・ファイル表示・タグの飾り）。計算ビューの器も、拡張のビューは匿名には描きません（`publicViews`）。
- タグの並び（`dl[data-type="tags"]`）は、飾りの登録された名前のタグがあるときだけ歩きます（`hasDecoratedTag`）。
- 通信記録の `<section data-mirror="記録の箱">` には、`recordBoxHTML` が記録の箱を描きます（§7b）。
- ファイル表示は、PDF を絵にできれば絵を縦に並べ（`PDFPagesFor`・`pdfPagesHTML`）、間に合わなければ埋め込みで見せます。JPEG は表示用の写しの住所にします。

`RenderReferenceLinks` は、可変タグの値を `parseRefValue` に掛け、`pageExists` でリンクか `ref-missing` かを決めます。
表は、列の宣言が `ref` のセルだけ（`弊社品番`）をリンクにします。

**本文の取得の API（`GET /api/load?id=`）**は `LoadAPIHandler` です。

```
LoadAPIHandler
├ GET 以外は 405 → queryPageID（400）→ RequirePageReadOrPublic
├ pages に行が無い 404 → page.BodyPath の本文
├ RenderComputedViews(Sanitize)
├ view=1 のときだけ RenderAnchors(RenderReferenceLinks(…)) も通す（閲覧の画面の読み直し・§3）
├ RenderAttachmentVersions（書くための本文にも写真の版の印を添える。保存の手前で外れる）
└ text/plain＋nosniff で返す
```

鏡は埋めて返すので、これを外から `/api/save` へ書き戻すと、鏡が本文に書き込まれてしまいます（`StripChrome` が守りますが、既に保存された鏡は落とせません）。

## 2. 書ける形で保存する（`POST /api/sync`）

`SyncAPIHandler`（`handler_sync.go`）です。画面の保存は、これ1本です。

画面が送るもの（`SyncRequest`）は、`base`（前に受け取った並びと指紋）・`order`（いまの並び）・`changes`（変えた・足したブロック）・`full`（全部の書き出しが欲しい）・`tab`（このタブの印）・`checkpoint`（版を区切る）です。

```
SyncAPIHandler
├ POST でない → 405 ／ DecodeJSONBody（8MiB）→ 413 / 400 ／ normalizedPageID → 400
├ page.RequirePageWrite → 401 / 403   ← 読むだけでも write が要る
├ 変えたブロックを正本の形へ（ロックの外）… SanitizeReport(c.HTML) → storedFormOf
├ syncLocked（ロックは defer で外す）
│   ├ LockPageBody(id)
│   ├ os.ReadFile(page.BodyPath(id)) → 404
│   ├ splitStoredBlocks → 500 ／ ensureStoredBlockIDs（振っただけでは書かない）
│   ├ plan := planSync(current, req, mine, sanitized)   … 純粋な関数
│   │   消したブロック: 相手が変えていなければ消す。変えていれば残す（kept）
│   │   変えたブロック: いまの指紋が元のまま、または canonBlock で同じ → 当てる
│   │                  両方が変えた → mergeBlock3（表なら違うセルだけ合わせる）→ 合わなければぶつかり（changed）
│   │   相手が消したブロックを変えていた → ぶつかり（deleted）
│   └ 本文が変わるとき
│       ├ FillFileViewNames(user, Sanitize(finalBody))
│       ├ KeepFixedTags … 管理者でない人が、作るときに決めるタグを替えていたら元へ戻す（戻したらブロックを組み直す）
│       └ commitBody … writeBody（409 置き場の題の重複 / 404 消されたページ / 500）→ RecordVersion（止めない）
│                      → checkpoint なら RecordVersion(force) → syncBody → SyncIndex → noteBlockWriters
├ 書いたなら auth.AuditRequest(r, "save", id) → notifyPageUpdatedFrom(id, user, tab, updatedAt)
├ 理由（why）のあるブロックとぶつかりがあれば、RenderAttachmentVersions(RenderComputedViews(Sanitize(finalBody))) で描いて添える
│   ぶつかりには blockWriterOf で「誰が書いたか」を添える
└ 200 {success, page_id, updated_at, written, blocks, conflicts, kept, …}
```

画面の側（`assets/app.js`）の流れです。

```
保存の機会 … ブロックを去る・タブを隠す・ページを去る・閲覧モードへ替える・業務のボタンの前（postJSON → window.wcmsFlushSave）
     ↓
saveToServer → queueSync(false) → runSync（1本ずつ）
  ├ captureAll → ensureBlockIds → serializeBlocks（変わったブロックだけ）
  ├ fetch('/api/sync', {keepalive: タブを隠す・ページを去るとき})
  │    受け取りに行くだけのときは X-Wcms-Background: 1 を付ける（セッションを延ばさない）
  └ applySyncResult … 描き直すブロックは差し替える（adoptExternal）・ぶつかれば openConflict・placeBlocks で並べる
ぶつかりを決める（resolveConflict）…「これで決める」「自分の版にする」「相手の版にする」「消す」「残す」
```

## 2b. 道具の保存（`/api/lock` → `/api/save` → `/api/unlock`）

ワンノートの製造の道具・テンプレートの取り込み（`tools/templates.js`）・E2E の `e2e/lib.js` が使う道です。画面は使いません。

```
[握る]   POST /api/lock?id=            LockAPIHandler → requireWriter → Locks.TryAcquire（取れない → 423）→ 200 {ok, token}
[保存]   POST /api/save               SaveAPIHandler  入力 {page_id, html, token}
         ├ POST でない 405 ／ DecodeJSONBody 413 / 400 ／ page_id が空 400
         ├ gateSave … normalizedPageID 400 ／ page.RequirePageWrite 401 / 403 ／ editlock.RequireLockToken 409（ロックが無ければ通す）
         ├ SanitizeReport → FillFileViewNames
         ├ LockPageBody の中で: KeepFixedTags → commitBody
         └ auth.AuditRequest(r, "save", id) → notifyPageUpdated → 200 saveEcho
         POST /api/save-block（SaveBlockAPIHandler）… 同じ gateSave。ロックの中で読んで ReplaceBlock → KeepFixedTags → commitBody
[放す]   POST /api/unlock?id=&token=    UnlockAPIHandler → Locks.Release → editlock.OnRelease → RecordVersion(force)（版の区切り）
[強制]   POST /api/lock/force?id=       page.RequireAdmin → Locks.ForceRelease → Audit "lock.force"
[購読]   GET  /api/lock-events?id=&role=holder|waiter&token=   … SSE
```

> **`/api/lock` を2回呼ばないこと。** 同じ利用者でも2回目でトークンがずれ、そのあとの削除・保存が 409 になります（`force → lock（1回）→ 使う` の順）。

業務サーバーの中の入口（Unix ソケット）からも、同じ API を同じ形で呼べます。要求は決めた1人の利用者として扱われ、版と監査にその名前が残ります。

## 2c. 機械が本文を書き換える（`cms.RewriteBody` とその仲間）

`RewriteBody` → `rewritePageBody`（`append_page.go`）です。`RewriteBody` を呼ぶのは**23ファイル・29箇所**、`RewriteBodyUnlessHeld` を呼ぶのは**7ファイル・8箇所**です。

```
rewritePageBody(pageID, author, rewrite)
├ IsTemplateArea(pageID) → ErrTemplateArea
├ defer LockPageBody(pageID)()
├ os.ReadFile(page.BodyPath)
├ stampBlockIDs … ID の無いブロックに、画面が使う ID を先に入れてから rewrite へ渡す
├ safe := fillFileViewNamesAs(author, Sanitize(rewrite(…)))
├ noteBlockWriters（機械が変えたブロックは、押した人が書いたと覚える）
├ 変わるなら RecordVersion(前の中身, force) … 書き換える前の中身を区切りの版に残す
├ page.BumpUpdatedAt → page.WriteFileAtomic
├ RecordVersion(safe, force) → もう一度 RecordVersion(safe, force)（新しく切った版を閉じる）
├ SyncIndex
└ （defer）notifyPageUpdated(pageID, author, updatedAt)

RewriteBodyUnlessHeld … editlock.Locks.EditorOpen(ページ) なら書かずに *HeldError、そうでなければ上と同じ
東邦の rebuildBody(pageID, author, body, build) … ロックの外の本文で組んでみて、書くときはロックの中で読み直した本文から組み直す
東邦の newBuiltPage(parent, user, 名前, build) … requireWriteTo(parent) → CreateChildPage("<h1>作成中</h1>") → RewriteBody(番号を入れた本文)
```

- ロックを取ったまま、同じページの本文を書く関数を呼ばないこと（再入できないので止まります）。
- 既にあるページを、テンプレートと同じ道具で書き換えるときは `cms.EditBody(cur)` → `SetTag`・`ReplaceTag`・`Container` … → `HTML()` です。ブロックの ID と字下げの空白を残します。
- タグを足すときは `cms.AddPageTags(body, pairs)` です。

## 3. 書ける形と閲覧モード・ページの更新の通知・版の区切り

```
onModeToggle（トグルを押したときは rememberMode でこの端末に憶える）

│              → populateEditor → applyMode → rebaseHistory → validateTypedTables
```

`applyMode` の中で、閲覧モードでだけ働くもの（添付のクリック展開 `refreshAttachmentPreviews`・見出しで畳む `refreshHeadingFolds`・表の「⋯」`refreshTableMenus`・

### 3b. ページの更新の通知とキャレット（`page_events.go`）

```
[購読] GET /api/page-events?id=&tab=     PageEventsAPIHandler
       NormalizeID 400 ／ page.RequirePageRead 401 / 403 → 購読してから hello
       本文が書き換わると {type:"updated", by, updated_at, tab}（notifyPageUpdated／From）
       鏡のもとのデータが変わると {type:"views"}（NotifyViewsChanged）
       キャレットが動くと {type:"presence", …}
[キャレット] POST /api/presence {id, tab, block}   PresenceAPIHandler → 自分の購読だけ → publishPresence
[開いている人] GET /api/page-watchers?id=&tab=     PageWatchersAPIHandler
```

画面の側です（`openPageEvents`）。

- **書ける形**では、`updated` を受けると `pullFromServer`（§2 の `/api/sync`）で変わったブロックを受け取ります。
- **閲覧モード**では、`schedulePageCheck` → `checkPageUpdate` が `loadViewHTML(true)` で読み直し、前に読んだものとブロックごとに比べます（`planPageUpdate`）。
- `views` を受けると、`scheduleViewsRefresh` → `refreshViews` で鏡の中身だけを描き直します（本文・スクロール・左右の欄は動かさない。入力中の欄があるブロックは `typingIn` で飛ばす）。

## 10. 削除する（`GET /api/delete-check` → `POST /api/delete-page?id=`）

```
[画面] deletePage … GET /api/page-watchers（ほかに開いている人）→ GET /api/delete-check（消すと何が壊れるか）→ flushPendingSave
                    → POST /api/delete-page（確かめのダイアログで「それでも消す」を選べば force=1）

DeleteCheckAPIHandler（delete_impact.go）… 読めるか → DeleteImpactOf → {empty, lines, impact:{refs, hidden, tables}, children, can_force（管理者か）}

DeletePageAPIHandler（handler_delete.go）
├ POST 限定 ／ queryPageID 400 ／ id == "000000" → 400
├ page.RequirePageWrite → 401 / 403
├ removalRefusal(user, id, -1)（RegisterRemovalGuard。通信箱の受信・送信の記録は管理者だけ）→ 403
├ 親ページへの write が無い → 403（書けない置き場のページは消せない）
├ editlock.RequireEditLock → 409（道具がロックを握っているときだけ）
├ beginDeleteIfChildless（treeMu の中で子を数え、無ければ「消している」印）→ 子があれば 409（件数つき）
├ DeleteImpactOf … 指しているページ（PagesReferringTo: 参照のタグ・表のセル・page_links）と、索引に入った自分の表
│   どちらかがあり force=1 でない → 409（理由の行）／ force=1 でも管理者でない → 403
├ moveToTrash(id) … LockPageBody の中で data/trash へ（同じIDが既にあれば -2, -3…）・noteTrashed（番号を使い回さない）
├ PurgePageIndex(id) → editlock.Locks.ForceRelease
└ auth.AuditRequest(r, "delete-page", …（警告を承知で: …）) → 200 {success, page_id, trash_path}
```

- 保存の側（`writeBody`）は、サイドカーが無ければ 404 で書きません。
- 拡張が自分で片付ける道（`DeletePageToTrash`・`DeleteLeafPageToTrash`）は、消す前の確かめと `RegisterRemovalGuard` を通りません。整理の合流（`revision.go`）・重複の取り下げ（`filing_duplicate.go`）・
  空の製造ページ（`mfg_drop.go`。こちらは自分で `PagesReferringTo` を見る）・`.eml` の取り込みが途中で失敗したときの作りかけのページ（`intake_eml.go`）・送った下書き（`mail/reply.go`）が使います。
- **復元の画面はありません。** 戻すには、手で `data/master` へ移してDBを再構築します。

## 12. ログイン・ログアウト

```
[画面]   GET /login          auth.LoginPageHandler（認証不要）
[認証]   POST /api/login     auth.LoginAPIHandler（認証不要・CSRFProtect は通る）
         ├ loginSem（argon2id の同時実行を4件に制限）
         ├ AuthenticateFrom(名前, パスワード, 接続元)
         │   ├ ログインの名前ごとの錠（lockLoginName・internal/keylock）
         │   ├ 名前と接続元の組・接続元・名前の3つで数える（attemptKeysFor）。待ちのあいだはパスワードを確かめずに断る
         │   ├ 不在・無効・ハッシュ無しは decoyHash で時間を均してから失敗
         │   └ VerifyPassword 失敗 → recordFailure
         ├ 失敗 → Audit "login.fail" → 302 /login?error=1（待ちなら error=wait）
         ├ CreateSession → setSessionCookie（HttpOnly・SameSite=Lax・Secure は WCMS_SECURE_COOKIES）
         └ Audit "login" → 302 next（safeNextPath）
[破棄]   POST /api/logout    auth.LogoutAPIHandler → Audit "logout" → DeleteSession → 302 /login
[状態]   GET /api/me         auth.MeAPIHandler（OptionalAuth）
[残り]   GET  /api/session   SessionRemaining → {expires_in, idle_ttl, warn_before}（延ばさない）／ POST は「続ける」
```

セッションは**最後の操作から8時間**で切れます（`SessionIdleTTL`）。`RequireAuth`／`OptionalAuth` → `userFromRequest` → `resolveSession(token, isOperation(r))` です。
業務サーバーの中の入口から来た要求は、セッションを使わず `localSocketUser` で利用者を引きます（無効にした利用者なら 401）。

画面の側は `assets/session.js` です（`index.html`・`admin.html`・`tables.html`）。最初の答えは殻に埋めた `#w-boot-data` から使います。
接続元のアドレスは、前段が `WCMS_TRUSTED_PROXIES` に書いたアドレス（とループバック）のときだけ `X-Forwarded-For` を採ります。

## 14. 画面の起動の順

```

├ <head>  boot.js … 同期のスクリプト。レールの開閉を描く前に決める

├ <head>  app.css → <!--WCMS_EXT_STYLES-->（comm.css・contacts.css・mail-compose.css・mail.css・toho.css）→ session.css
├ <body>  …本文はサーバーが合成済み
└ </body> の前 app.js → <!--WCMS_EXT_SCRIPTS--> → session.js → push.js … どれも defer なし。書いてある順に同期で実行
             app.js … window.wcms を凍らせて渡す（version 4）。最初の問い合わせは bootFetch が埋めた答えを1回だけ使う
             拡張の JS（URL の文字の順）: comm/comm-threads.js → comm/comm.js → comm/contacts/contacts.js
                   → comm/mail/mail-compose.js（window.wcmsMailCompose）→ comm/mail/mail.js → toho/toho.js
             session.js … セッションの残りを聞き始める
             push.js … 帯に「🔔」（この端末で通知を受けるか）
             window.onload（app.js）:
             ├ await Promise.all([loadMe(), loadTagSchema()])
             ├ syncRailToggleButtons / initHeadroom / 開いたときの形をトグルに入れる / adoptViewSource
             ├ initBlocks / buildToc / setupEditorEvents / setupAutoSave / setupHistoryHooks / setupSaveOnLeave / setupPresence / setupArrowNavigation
             ├ 匿名なら applyMode / loadPageMeta / loadChildNav して終わる
             └ onModeToggle()（§3a）→ loadPageMeta / loadPerms / loadChildNav / openPageEvents
```

- 画面のファイルの住所には、殻を返すときに `?v=<版の印>` が添えられます（`StampAssetURLs`）。印が合えば、ブラウザは1年たずねずに使います。
- 拡張の JS が登録している飾りは、`onChrome` が9つ、`onFileMenu` が2つです（[【一覧】関数リファレンス §8g](【一覧】関数リファレンス.md)）。

> `boot.js`・`app.js`・拡張の JS・`session.js`・`push.js` は、どれも `defer` を持ちません。`<head>` の同期のスクリプトが先、`</body>` の前が後、という**書いてある順**どおりに実行されます。
