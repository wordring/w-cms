ミドルウェア（`cmd/w-cms/main.go` を読んだ結果）です。

```
CSPProtect(
            └─ CSRFProtect( root )
                          ├─ /assets/      … 認証不要（Cache-Control: no-cache・ディレクトリの一覧なし）
                          ├─ /assets/ext/  … 認証不要（拡張の画面のファイル・ExtScriptHandler・2026-10-20）
                          ├─ /login, /api/login, /api/tag-schema … 認証不要
                          ├─ /sitemap.xml, /robots.txt          … 認証不要
                          ├─ /api/local-edit/file … ログインの外・鍵だけ（常駐ヘルパーは Origin を付けて CSRF を通す）
                          ├─ OptionalAuth … /api/load, /data/, /api/me, /api/children,
                          │                 /api/page-meta, /api/qr, /api/zip-list, / (RootHandler)
                          └─ RequireAuth(protected) … 上記以外の /api/（コアの44本＋プラグインが
                                                       足す88本。コアの1本は定数で書く /api/session）
```

- `CSRFProtect` は GET/HEAD/OPTIONS を確かめません。**状態を変える API は、ハンドラの側でメソッドを絞ること。**
  固定しているのは `internal/cms/method_guard_test.go`（`TestStateChangingHandlersRejectGET` の15件＋`TestPagePermsHandlerChecksAuthFirst`）・
  `ext/comm/method_guard_test.go`・`internal/auth/method_guard_test.go` です。**ハンドラを直に呼んで 405 を期待します。**
  東邦は、読むだけの API が POST を断ることを `ext/toho/read_only_method_test.go` が見ます。
  `cmd/w-cms/route_guard_test.go` では足りません。`buildHandler()` へ流すので `RequireAuth` が先に 401 を返し、ハンドラ自身のメソッドの確かめが走らないためです。
- `RequireAuth` と `OptionalAuth` は同じ `userFromRequest(w, r)` でセッションを解決します。`RequireAuth` は入口で `Cache-Control: no-store` を一律に付けます（`TestAuthenticatedAPIsAreNotCacheable`）。
- **セッションは「最後の操作から8時間」で切れます**（`internal/auth/session.go`）。`userFromRequest` → `resolveSession(token, isOperation(r))` です。
  - 利用者の操作なら `last_seen` を今にし（前の記録から1分以上経ったときだけ書く・`sessionTouchEvery`）、そのとき Cookie も出し直します（`setSessionCookie`）。
  - 延ばさないのは、`X-Wcms-Background: 1` の印（`BackgroundHeader`）の付いた要求・`passivePaths`（`/api/page-events`・`/api/lock-events`・`/api/presence`）・`GET /api/session` です。
  - 失効は `last_seen` だけで決めます（`expires_at` は写し）。残りを返す API は `SessionAPIHandler`（`handlers.go`・GET は延ばさない／POST は「続ける」で延ばす・`expires_in`・`idle_ttl`・`warn_before`）で、`SessionRemaining` を通します。
  - 延ばさずに引く `ResolveSession` の本体の呼び手は、`handlers.go` の `LogoutAPIHandler`（監査に名前を残すため）の1つです。
- CSP の配線は `TestCSPIsWired`（`route_guard_test.go`）、ポリシーの文字列は `internal/auth/csp_test.go` の `TestCSPPolicyIsStrict` が固定します。

## 9. 数え方（同じ結果を出す手順）

```bash
# 呼び出し元（試験・コメント・宣言の行を除く）
grep -rn --include='*.go' -E '(^|[^A-Za-z0-9_])SyncIndex\(' internal cmd ext tools \
  | grep -v '_test.go' | grep -vE ':[0-9]+:\s*//' | grep -vE ':[0-9]+:func (\([^)]*\) )?SyncIndex\('

# 本体に呼び手の無い公開関数（呼び出しでも値でも、宣言・コメント・試験を除いて0件のもの）
for f in $(find internal ext -name '*.go' -not -name '*_test.go'); do
  grep -oE '^func [A-Z][A-Za-z0-9_]*\(' "$f" | sed -E 's/^func //; s/\($//' | while read id; do
    n=$(grep -rn --include='*.go' -E "(^|[^A-Za-z0-9_])$id([^A-Za-z0-9_]|$)" internal cmd ext tools | grep -v _test.go \
        | grep -vE ':[0-9]+:\s*//' | grep -vE ":[0-9]+:func (\([^)]*\) )?$id\(" | wc -l)
    [ "$n" = 0 ] && echo "$f $id"; done; done

# 公開APIの一覧
go doc ./internal/cms
go doc ./ext/comm
go doc ./ext/toho
```

> この版の数は、上と同じ規則（識別子の境界で当たる・コメントの行と行末のコメントを除く・宣言の行を除く・試験を除く）を node で書いた道具で、
> 全部の Go のファイルを1回読んで数えました。`grep` の1回ずつより速く、数は同じ規則です。

**数え違いに気をつけること**（このプロジェクトで実際に踏んだもの）です。

- **メソッド名**: `Name` / `Schema` / `Tables` / `Triggers` / `OnElement` / `OnFile` / `Extensions` は複数の型が実装するので、「最初に宣言したファイルへの依存」に見えます。
- **同じ名前の別の関数・フィールド**:
  - `SaveAttachment` は `cms.SaveAttachment` と `IntakeContext.SaveAttachment` の2つです。
  - `SignatureOf` は `contacts.SignatureOf` と東邦の包みの2つです。
  - `templateBody` はコアと `tools/onenote/build` の2つ、`setAttr` はコアと `ext/toho` の2つ、`machineOf` は `backlog_machine.go`（メソッド）と `unordered.go` の2つです。
  - `RecordBoxTitle` は `comm`（`記録の箱`）と `toho`（`記録`）で意味が違います。
  - `PageTitle` は、東邦の構造体のフィールド `PageTitle` にも当たります。
  - `TagValue(` は `PageTagValue(` にも当たります。`Sanitize(` は `htmldoc` の `Sanitizer.Sanitize` にも当たります。
- **同じ名前の関数**: `RequireAdmin` は `auth` と `page` の両方にあります（`page` は委譲）。`ensureChildByTitle`（連絡帳・小文字）と `EnsureChildByTitle`（コア）は別物です。
- **同じパッケージの中の呼び出し**: `auth.RequireAdmin(` で数えると、`auth` 自身の呼び出しが漏れます。`page.*` も同じです。
- **括弧なしの参照**: ルート表の `Handler:`、`RegisterView(…, xxxViewHTML)`、`RegisterMirror(…, MirrorHandlerFunc(f))`、`RegisterTagDecorator(名前, f)`、
  送る欄の用件の `Defaults: orderMailDefaults`、記録から作るページの `Make: makeOrderFromMail`、記録の箱の節の `Render: filingSlotHTML`、
  試験が差し替える変数（`var judgeOrderPDF = judgeOrderPDFWithGemini`・`var sendMail = comm.SendMail`・`importBatch = ImportMessages`・`fixRecordTags = comm.FixRecordTags`）は `名前(` では当たりません。
  **呼び手ゼロに見えても、値で渡されていることがあります。**
- **コメントの中の言及**: 件数だけ見て内訳を見ないと外します。
- **語彙やルートの本数**: 数え上げより、小さな `main` を書いて `cms.VocabDefs()` / `cms.PluginRoutes()` / `cms.ExtensionIDs()` / `cms.RequiredPages()` を印字するほうが確かです（ビルドタグの組ごとに数えられます）。
