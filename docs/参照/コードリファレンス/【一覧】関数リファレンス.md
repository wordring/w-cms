**対象コミット: `c60d187`（2026-10-01 作り直し・[全体地図.md](全体地図.md) と同じ測定）＋同日の「受注の行は受注フォルダを開いたときに結ぶ」を反映**

主要な関数と**その呼び出し元**の対応表です。呼び出し元は `grep` の実測で、
テスト（`*_test.go`）・コメント内の言及・宣言行は除いています。**`ext/` と `tools/` も数えます**。
ファイル名は `internal/cms/` と `ext/` を省いて書きます（`toho/filing.go` は `ext/toho/filing.go`）。
括弧の数字はそのファイルの中の箇所数です。

> **各関数の説明は `go doc` が持ちます。** ここは「誰から呼ばれるか」＝
> 変更したときに何が壊れうるかの地図です。
>
> ```bash
> go doc ./internal/cms SyncIndex      # 1関数の説明
> go doc -all ./internal/cms/page      # そのパッケージの全公開API
> go doc -src ./internal/cms Sanitize  # 実装も見る
> ```

> ⚠ **`internal/cms/page` への呼び出しは「パッケージの外から `page.` 付きで呼ぶ箇所」を
> 数えています。** パッケージの中（`page/perms.go` など）からの呼び出しは、その旨を
> 添えて別に書いています——`page.` を付けないので同じ grep では当たりません。

                          │                 /api/page-meta, /api/qr, /api/zip-list, / (RootHandler)
                          └─ RequireAuth(protected) … 上記以外の /api/（コアの35本＋プラグインが
                                                       足す33本）
```

- `CSRFProtect` は GET/HEAD/OPTIONS を検証しません。**状態を変える経路は
  ハンドラ側でメソッドを絞ること**。固定しているのは
  `internal/cms/method_guard_test.go`（`TestStateChangingHandlersRejectGET` の**12件**＋
  `TestPagePermsHandlerChecksAuthFirst`）・`ext/comm/method_guard_test.go`
  （`TestCommStateChangingHandlersRejectGET` 3件＋`TestJSONReadHandlersRejectNonGET` 2件）・
  `internal/auth/method_guard_test.go`（`TestLogoutRejectsGET`）。**ハンドラを直接呼んで 405 を期待します**。
  ⚠ **`cmd/w-cms/route_guard_test.go` では足りません**——`buildHandler()` へ流すので `RequireAuth` が
  先に 401 を返し、**ハンドラ自身のメソッド確認が一度も走らない**。
  ⚠ **`ext/toho`・`ext/comm/contacts`・`ext/comm/mail` には同じ番人がありません**（東邦の口は `GateJSONPost` を
  通すので POST 以外は 405 になるが、それを固定する試験は無い）。
- `RequireAuth` と `OptionalAuth` は同じ `userFromRequest` でセッションを解決します。`RequireAuth` は
  入口で `Cache-Control: no-store` を一律に付けます（`TestAuthenticatedAPIsAreNotCacheable`）。
- CSP の配線は `TestCSPIsWired`（`route_guard_test.go`）、ポリシー文字列は
  `internal/auth/csp_test.go` の `TestCSPPolicyIsStrict` が固定します。

## 9. 数え方（再現手順）

```bash
# 呼び出し元（テスト・コメント・宣言行を除く）
grep -rn --include='*.go' -E '(^|[^A-Za-z0-9_])SyncIndex\(' internal cmd ext tools \
  | grep -v '_test.go' | grep -vE ':[0-9]+:\s*//' | grep -vE ':[0-9]+:func (\([^)]*\) )?SyncIndex\('

# 本体に呼び手の無い公開関数（呼び出しでも値でも、宣言・コメント・試験を除いて0件のもの）
for f in $(find internal ext -name '*.go' -not -name '*_test.go'); do
  grep -oE '^func (\([^)]*\) )?[A-Z][A-Za-z0-9_]*\(' "$f" | sed -E 's/^func (\([^)]*\) )?//; s/\($//' | while read id; do
    n=$(grep -rn --include='*.go' -E "(^|[^A-Za-z0-9_])$id([^A-Za-z0-9_]|$)" internal cmd ext tools | grep -v _test.go \
        | grep -vE ':[0-9]+:\s*//' | grep -vE ":[0-9]+:func (\([^)]*\) )?$id\(" | wc -l)
    [ "$n" = 0 ] && echo "$f $id"; done; done

# 公開APIの一覧
go doc ./internal/cms
go doc ./ext/comm
go doc ./ext/toho
```

**偽陽性に注意**（このプロジェクトで実際に踏んだもの）:

- **メソッド名**——`Name` / `Schema` / `Tables` / `Triggers` / `OnElement` / `OnFile` /
  `Extensions` は複数の型が実装するので、「最初に宣言したファイルへの依存」に見えます。
- **同名の別関数**——`SaveAttachment` は `cms.SaveAttachment` と `IntakeContext.SaveAttachment`、
  `SignatureOf` は `contacts.SignatureOf` と東邦の包み、`machineOf` は `backlog_machine.go`（メソッド）と
  `unordered.go` の2つ。`TagValue(` は `dlTagValue(`・`PageTagValue(` にも当たります。`Sanitize(` は
  `htmldoc` の `Sanitizer.Sanitize` にも当たります。
- **同名関数**——`RequireAdmin` は `auth` と `page` の両方にあります（`page` は委譲）。
  `ensureChildByTitle`（連絡帳・小文字）と `EnsureChildByTitle`（コア）も別物です。
- **同一パッケージ内の呼び出し**——`auth.RequireAdmin(` で grep すると `auth` 自身の
  6箇所が漏れます。`page.*` も同じで、`page` パッケージ内からの呼び出しは `page.` が付きません。
- **括弧なしの参照**——ルート表の `Handler:`、`RegisterView(…, xxxViewHTML)`、`RegisterMirror(…, MirrorHandlerFunc(f))`、
  送る欄の用件の `Defaults: orderMailDefaults`、試験が差し替える変数（`var judgeOrderPDF = judgeOrderPDFWithGemini`・
  `var sendMail = comm.SendMail`）は `名前(` では当たりません——**呼び手ゼロに見えても値で渡されている**ことがあります。
- **コメント内の言及**——件数だけ見て内訳を見ないと外します。
- **語彙やルートの本数**——grep より、**小さな `main` を書いて `cms.VocabDefs()` /
  `cms.PluginRoutes()` / `cms.ExtensionIDs()` / `cms.RequiredPages()` を印字する**ほうが
  確かです（ビルドタグの組ごとに数えられます）。
