ミドルウェア（`cmd/w-cms/main.go` の実測）です。

```
CSPProtect( outer )
            ├─ /dav/  … CSRFProtect の外側（WebDAV。PROPFIND に Origin が付かないため。
            │            守れるのは Cookie を使う口だけなので、HTTP Basic のここには効かない）
            └─ CSRFProtect( root )
                          ├─ /assets/     … 認証不要（Cache-Control: no-cache・ディレクトリの一覧なし）
                          ├─ /login, /api/login, /api/tag-schema … 認証不要
                          ├─ /sitemap.xml, /robots.txt          … 認証不要
                          ├─ /api/local-edit/file … ログインの外・鍵だけ（常駐ヘルパーは Origin を付けて CSRF を通す）
                          ├─ OptionalAuth … /api/load, /data/, /api/me, /api/children,
                          │                 /api/page-meta, /api/qr, /api/zip-list, / (RootHandler)
                          └─ RequireAuth(protected) … 上記以外の /api/（コアの42本＋プラグインが
                                                       足す75本）
```

- `CSRFProtect` は GET/HEAD/OPTIONS を確かめません。**状態を変える口は、ハンドラの側でメソッドを絞ること。**
  固定しているのは `internal/cms/method_guard_test.go`（`TestStateChangingHandlersRejectGET` の12件＋`TestPagePermsHandlerChecksAuthFirst`）・
  `ext/comm/method_guard_test.go`・`internal/auth/method_guard_test.go` です。**ハンドラを直に呼んで 405 を期待します。**
  `cmd/w-cms/route_guard_test.go` では足りません——`buildHandler()` へ流すので `RequireAuth` が先に 401 を返し、ハンドラ自身のメソッドの確かめが走らないためです。
  10-12 の口（`/api/sync`・`/api/version-checkpoint`・`/api/presence`）は、上の12件に入っていません。
- `RequireAuth` と `OptionalAuth` は同じ `userFromRequest` でセッションを解決します。`RequireAuth` は入口で `Cache-Control: no-store` を一律に付けます（`TestAuthenticatedAPIsAreNotCacheable`）。
- CSP の配線は `TestCSPIsWired`（`route_guard_test.go`）、ポリシーの文字列は `internal/auth/csp_test.go` の `TestCSPPolicyIsStrict` が固定します。

## 9. 数え方（再現の手順）

```bash
# 呼び出し元（試験・コメント・宣言の行を除く）
grep -rn --include='*.go' -E '(^|[^A-Za-z0-9_])SyncIndex\(' internal cmd ext tools \
  | grep -v '_test.go' | grep -vE ':[0-9]+:\s*//' | grep -vE ':[0-9]+:func (\([^)]*\) )?SyncIndex\('

# 本体に呼び手の無い公開関数（呼び出しでも値でも、宣言・コメント・試験を除いて0件のもの）
for f in $(find internal ext -name '*.go' -not -name '*_test.go'); do
  grep -oE '^func [A-Z][A-Za-z0-9_]*\(' "$f" | sed -E 's/^func //; s/\($//' | while read id; do
    n=$(grep -rn --include='*.go' -E "(^|[^A-Za-z0-9_])$id([^A-Za-z0-9_]|$)" internal cmd ext tools | grep -v _test.go \
        | grep -vE ':[0-9]+:\s*//' | grep -vE ":[0-9]+:func (\([^)]*\) )?$id\(" | wc -l)
    [ "$n" = 0 ] && echo "$f $id"; done; done

# 公開APIの一覧
go doc ./internal/cms
go doc ./ext/comm
go doc ./ext/toho
```

**偽陽性に気をつけること**（このプロジェクトで実際に踏んだもの）です。

- **メソッド名**——`Name` / `Schema` / `Tables` / `Triggers` / `OnElement` / `OnFile` / `Extensions` は複数の型が実装するので、「最初に宣言したファイルへの依存」に見えます。
- **同じ名前の別の関数**——`SaveAttachment` は `cms.SaveAttachment` と `IntakeContext.SaveAttachment`、`SignatureOf` は `contacts.SignatureOf` と東邦の包み、
  `machineOf` は `backlog_machine.go`（メソッド）と `unordered.go` の2つ、`templateBody` はコアと `tools/onenote/build` の2つ、`setAttr` はコアと `ext/toho` の2つです。
  `TagValue(` は `PageTagValue(` にも当たります。`Sanitize(` は `htmldoc` の `Sanitizer.Sanitize` にも当たります。
- **同じ名前の関数**——`RequireAdmin` は `auth` と `page` の両方にあります（`page` は委譲）。`ensureChildByTitle`（連絡帳・小文字）と `EnsureChildByTitle`（コア）は別物です。
- **同じパッケージの中の呼び出し**——`auth.RequireAdmin(` で grep すると `auth` 自身の6箇所が漏れます。`page.*` も同じです。
- **括弧なしの参照**——ルート表の `Handler:`、`RegisterView(…, xxxViewHTML)`、`RegisterMirror(…, MirrorHandlerFunc(f))`、送る欄の用件の `Defaults: orderMailDefaults`、
  記録から作るページの `Make: makeOrderFromMail`、紙の `paperKind{build: buildOrderPDF}`、試験が差し替える変数（`var judgeOrderPDF = judgeOrderPDFWithGemini`・
  `var sendMail = comm.SendMail`・`importBatch = ImportMessages`・`fixRecordTags = comm.FixRecordTags`）は `名前(` では当たりません。**呼び手ゼロに見えても、値で渡されていることがあります。**
- **コメントの中の言及**——件数だけ見て内訳を見ないと外します。
- **語彙やルートの本数**——grep より、小さな `main` を書いて `cms.VocabDefs()` / `cms.PluginRoutes()` / `cms.ExtensionIDs()` / `cms.RequiredPages()` を印字するほうが確かです（ビルドタグの組ごとに数えられます）。
