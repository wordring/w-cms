# 【一覧】用語集

w-cms で使う用語の正本（いちばん正しいとする元の一覧）です。
利用者と開発者が、同じ言葉で話すために使います。

**業務の用語**（受注／部材発注・納品・部材…）と、**画面の用語**（レール・画面の部品・ブロック…）の両方を、ここに集めます。
設計・実装・ドキュメント・コミットメッセージ、そして会話で、**用語を統一**するために使ってください。

この文書は、3つの節でできています。

- **§1 業務の用語**: 「何を扱っているか」を指す言葉です。受発注・ものづくり・納品・通信記録を扱います。
- **§2 画面の用語**: 「どこの話をしているか」を指す言葉です。
  「左のパネル」「サイドバー」「メニュー」のような、曖昧な指し方を避けるために用意しました。
  実装は [assets/index.html](../../assets/index.html)、挙動の詳細は [エディタ仕様.md](../旧文書/エディタ仕様.md) §9 が正本です。
- **§3 基盤の用語**: 両者にまたがる土台の言葉です（ページ・正本性・語彙・計算ビュー）。
- **§4 言い換えた言葉と別名**: 文書を読みやすく直したときに言い換えた言葉と、もとの言葉の対応です。古い文書に出てくる言葉（口・番人・錠・クローム など）は、ここで引けます。

> **本文で使える形式（`data-type`）の一覧**は、[【一覧】語彙.md](【一覧】語彙.md) が正本です。
> 形式とは、表やブロックの種類のことです。【一覧】語彙は、語彙レジストリ（使える形式の登録簿）の写しです。
> ここには、個々の形式は載せません。
>
> 2026-08-21 に、「画面構成と用語.md」を本ファイルの §2 へ統合しました。
> 用語の正本が業務用と画面用の2冊に分かれていて、どちらを引けばよいか分からなかったためです。

表の中には、`<table data-type="…">` のような HTML の書き方や、プログラムの中の名前も出てきます。
これらは開発者のための手掛かりです。言葉の意味を知りたいだけなら、「意味」や「説明」の欄を読めば足ります。

## 1. 業務の用語

この節の用語は、次の方針で決めています。

- **「発注書」という言葉だけでは、誰の立場で言うかによって意味が変わり、曖昧です。**
  たとえば顧客が出す発注書は、こちらから見れば、受け取る側の書類です。
  そこで、立場に依らない**役割語**（役割で呼ぶ言葉）で呼びます。
- **受け取る側と出す側の対は、`受注` ／ `部材発注` と呼びます**（2026-06-27 に `受注` ／ `発注` と決め、2026-10-15 に出す側を `部材発注` と改めました）。
  標準的で、曖昧さの無い言葉です。
  `注文` という案もありました。実在の「注文書」に根ざした言葉ですが、`受注` の教科書的な対義語である `発注` を選びました。
- **見積の2種は、`見積` ／ `部材見積依頼` と呼びます**（2026-10-02 に `見積` ／ `見積依頼` と改め、2026-10-15 に `部材見積依頼` と改めました）。
  - `見積` は弊社が顧客へ出すもの、`部材見積依頼` は弊社が業者へ出すものです。

    > 利用者:「弊社の見積もりを見積もり、業者への見積依頼の場合、見積依頼と明確に言葉を分けます」

  - 書類（見積書・部材見積依頼書）は、トップ直下の「記録」の `記録／年／月／依頼`・`記録／年／月／製造記録` に入ります（下の「記録」）。
    製造ページから作った書類は、その製造ページの子になります。
  - 置き場は、もとはトップ直下の「見積」と「部材見積依頼」に分かれていました
    （[【要求】見積.md](../拡張/東邦/【要求】見積.md)・[【要求】部材見積依頼.md](../拡張/東邦/【要求】部材見積依頼.md)）。
    2026-10-16 から、この2つは作業面（ビューと表の置き場）になりました。
    2026-10-19 に、この2つと「部材発注」の置き場をなくしました。作業面は、トップ直下の「製造」へ移しました
    （[【考察】製造ページ.md](../考察/【考察】製造ページ.md) §8.8・§8.9）。
  - それまでは、取引の性質で **`販売見積` ／ `購入見積`** と呼んでいました（2026-06-27 決定）。
    `売上/原価見積` という案は、「原価見積＝社内原価積算」と紛れるので避けました。
- **弊社から業者への側だけに「部材」を付けます**（2026-10-15）。

  > 2026-10-15 利用者:「用語の変更を行います。影響範囲は広範囲にわたり、エディタ内外の表示、文書の表記等を含みます。「発注」を「部材発注」、「見積依頼」を「部材見積依頼」に変更します。」

  - 置き場・ページ・表・タグの名前が変わりました（`部材発注`・`部材発注書`・`部材発注明細`・`部材発注書番号`・`部材発注日`・`部材発注担当`、
    `部材見積依頼`・`部材見積依頼書`・`部材見積依頼明細`・`部材見積依頼番号`・`部材見積依頼日`・`部材見積依頼担当`・`部材見積依頼の返事` など）。
  - **客先の側の言葉は、そのままです**。案件ページの `発注書番号`・`発注日`・`発注元`、「顧客の発注書」、客先からの見積依頼、
    「受発注」という一般の言い方には、「部材」を付けません。
  - **そのままの名前**: 部材表（`発注部材表`・`見積依頼部材表`・`見積依頼必要部材表`・`臨時部材表`・`必要部材表`）、
    状態の値（`未発注`・`発注済`・`納品済`・`取消`・`未回答`・`回答あり`・`辞退`）、案件明細表の列 `材料発注`、動詞の「発注する」。
  - **業者に渡す紙（PDF）とメールは、いまの言葉のまま**です。紙の題は「発注書」「支給願い」「見積依頼書」、紙に刷る項目名は
    「発注書番号」「発注日」です（タグの名前の頭の「部材」を、刷るときに外します）。PDF のファイル名と、メールの件名・本文も同じです。
- **表の「実装・状態」欄の読み方**:
  **実装済み** とある語は、いまのコードに対応するものがあります。
  **設計中** とある語は、[【考察】通信記録処理.md](../考察/【考察】通信記録処理.md) などで検討中で、まだ実装していません。

```
見積         ─(確定)→ 受注      （顧客と・売上側）
部材見積依頼 ─(確定)→ 部材発注  （仕入先と・原価側）
```

### 2.3 本文の中の用語

本文（`#w-editor-content`）の中の要素には、エディタが、画面の上でだけ枠（ラッパー）を被せます。

表に出てくる「キャレット」は、文字を打つ位置の印（点滅する縦棒）のことです。

| 呼び名 | DOM | 説明 |
|---|---|---|
| **ブロック** | `.editor-block` | 本文の最小単位です。見出し・段落・表・業務文書ブロックの、それぞれを包みます |
| └ **ブロック操作** | `.block-controls`・`.add-btn` | ブロックの左脇に出る、ドラッグハンドル `⠿`（つかんで動かす印）と、削除 `🗑` です（`.block-controls`）。「＋」（`.add-btn`）は `.block-controls` の外にあり、ブロックの**下端の境界の中央**に出ます（2026-08-31）。どちらも、書ける形（§2.4）で、マウスを載せたとき（ホバー時）に出ます。節や折りたたみの中の要素には、同じ3つを並べた小さな帯（`#w-inner-controls`）が出ます |
| └ **ブロック本体** | `.block-content` | 実際の要素（`<h1>`・`<p>`・`<section data-type="file">` 等）を入れる器です |
| **スラッシュメニュー** | `#w-slash-menu` | 書ける形の段落で `/`（全角の `／` でも）を打つと出る、挿入のメニューです（続けて打つ文字で絞り込めます）。コンテキストツールバーの「＋」からも開きます。項目の出どころは3つです。①**手書きは7項目**（[assets/index.html](../../assets/index.html)。H1・H2・H3 の見出し、P 段落、§ 見出しの節、▸ 折りたたみ、📎 画像・ファイル）。②JS が足す、汎用の「表」「定義リスト」（骨組みの下書き）。③残りは、語彙レジストリから動的に生成します（既定のビルドで、43形式のうち `Hidden` の10形式を除く33項目。2026-10-21 にレジストリの宣言を数えました。2026-10-19 は42形式・32項目、2026-10-14 は37形式・30項目でした）。挿す形は3つです。表の形式は、`<caption>` を持つ表です。計算ビューは、鏡の印 `<section data-mirror>` です。それ以外（可変タグ・ファイル表示・カルーセル）は、`data-type` を付けた要素です。見出しの節で挿す形（機能見出し形）は、2026-09-29 にやめました。分類「基本」の項目は、決まった順に並びます。ほかの分類は、使った回数の多い順です |
| **テンプレートメニュー** | `#w-template-menu` | 「＋ 子ページを作成」で出る、小さなメニューです。先頭が「空のページ」です。その下に、`/api/templates` から得たテンプレートのツリーが並びます（枝＝分類の見出し、葉＝テンプレート。[【考察】ページテンプレート.md](../考察/【考察】ページテンプレート.md)） |
| **コンテキストツールバー** | `#w-context-toolbar` | 書ける形でブロックにキャレットを置くと出る、小さな帯です。ボタンは左から、↶ ↷（元に戻す・やり直す）、B I U 🔗（文字の装飾とリンク）、📎（画像・ファイルを足す）、¶ H1 H2 H3（ブロックの種類を替える）、＋（下にブロックを足す）です。パソコンでは、2026-10-19 から、本文のすぐ上の**固定の帯**（`#w-fixed-bar`）に、表ツールバー・dlツールバーと一緒に並びます（スクロールしても上に留まります。キャレットの場所に合わない組は、薄くなって押せません。`initFixedBar`）。それまでは、キャレットのある行のすぐ上に浮いていました。タッチ端末では、画面の**上の端**に全幅の1列で出ます（ドック `.is-docked`。2026-10-07 に下の端から移しました） |
| **表ツールバー** | `#w-table-toolbar` | 本文中の表のセルにキャレットがあると出る、行・列の操作です（＋行/↑/↓/✕行・＋列/←/→/✕列/⚙）。`data-type` の有無を問いません（計算ビューの中は除きます）。パソコンでは、2026-10-19 から本文の上の固定の帯に並びます（コンテキストツールバーと同じ） |
| **dlツールバー** | `#w-dl-toolbar` | 本文中の `dl`（定義リスト。名前と値の並び）の項目にキャレットがあると出る、項目の操作です（＋項目/＋値/↑/↓/✕項目）。`data-type` の有無を問いません |
| **列設定ポップオーバ** | `#w-col-popover` | 表ツールバーの ⚙ で開きます。列型の明示（`th` の `data-type`）をする欄で、属性の側を編集する入口です |
| **リンクのプロパティ欄** | `#w-link-popover` | キャレットがリンクの上にあると出ます。宛先の入力欄と、「リンクを外す」があります。ダイアログは出しません（[エディタ仕様.md](../旧文書/エディタ仕様.md) §3.2） |
| **ファイル表示の欄** | `#w-fv-popover` | ファイル表示（`<section data-type="file-view">`）の札を押すと開きます。どのファイルを開くかの参照（`data-ref`。`ページID-添付ID`）を書く欄です。リンクのプロパティ欄と同じ形です |
| **選択肢メニュー** | `#w-enum-menu` | 書ける形で、enum 列（決まった選択肢から選ぶ列）のセルにキャレットがあると出る、選択肢の一覧です。enum の可変タグの値にも出ます（2026-10-09）。選択肢の正本は、設定 `config/settings.json` の語彙です。image 列（画像の列）では「🖼 画像を選ぶ」が出ます。何度も入力された定型的な値があれば、表のセルとタグの値にオートコンプリートの候補が出て、打った字で絞れます（2026-10-19）。それまでの候補の出どころ `Suggest` は、外しました。どれも縛りではなく、手で打つこともできます |
| **トースト** | `#w-toast-host` の子 | 画面の隅に出る、一時的な通知です（保存の失敗・操作の結果・モードの切り替え・ほかの人がページを更新した知らせ など）。ボタンを持つこともあります（「変わったところを読み込む」）。ふだんの保存の状態（「未保存」「保存中...」）は、トーストではなく、ヘッダーの `#w-save-status` に出ます |
| **形式の枠** | `body[edit-mode] … [data-type]` | 書ける形だけに出る、破線の枠です（CSS の `body[edit-mode]` は、書ける形のことです。属性の名前は昔のままです）。「**w-cms がこの要素を見る**」ことを示します。枠が出るのは、`data-type` を持つ形式ブロックと、ファイル容器です。`<caption>` を持つ表は `data-type` を持たないので、枠は出ません。かわりに、表の名前（caption）が薄い青になります。計算ビューの印 `<section data-mirror>` は `data-type` を持たないので、枠も薄青も出ません。かわりに、既知の名前なら鏡の中身が見えます。挿した直後の空の印なら、案内「🪞 表示名（保存して読み直すと…）」が見えます。登録されていない名前なら、薄赤になります。ページタイトルになる最初の `h1` にも、同じ枠が出ます（実行時クラス `is-page-title`。属性にしないのは、位置で決まるためです） |
| **認識の背景色** | `.vocab-word`・`dl[data-type="tags"] dt`・`.cell-known` ／ `.is-vocab-unknown`・`.cell-invalid` | 書ける形では、背景色の3値で見分けます（薄い青＝機械が読む／薄い赤＝未定義・型不一致／無印＝素の本文）。`.vocab-word` は、登録された表の名前（`<caption>`）に付きます（2026-09-29 までは、節の見出しの言葉に付けていました）。正本は [エディタ仕様.md](../旧文書/エディタ仕様.md) §3.2 です |
| **語彙クローム**（画面の部品の印） | `.vocab-chrome` | 本文の中に**混ざって見えるが保存されない**DOM（画面の部品）です。用途は3つです。①計算ビューと鏡の中身（サーバー事前描画が埋めます。業務のボタンもここに入ります）。②エンハンサが付ける付帯UI（PDFプレビュー・ドロップゾーン など）。③閲覧モードの添付の札（📎リンク横の「▶ 表示」「▶ 中身」「🔗 参照」と、展開したプレビュー・目録。拡張は `window.wcms.onAttachment` で札を足せます）。本文の直下へ飾り付けを足すコードは、必ず `.vocab-chrome` を付けます。付けないと、本文として保存されます |

`.editor-block` と `.block-content` は、**エディタが挿す枠であって本文ではありません**。
保存するときに、シリアライザ（画面の内容を保存用の HTML に直す処理）が、これらを剥がします
（[エディタ仕様.md](../旧文書/エディタ仕様.md) 6.1.1）。

`.vocab-chrome` も同じです。シリアライザが読み飛ばすので、正本HTMLには入りません。
計算ビューなら、本文に残るのは、鏡の印 `<section data-mirror="子ページ一覧"></section>` 等と、印の中に人が書いたものだけです。

**本文DOMを走査する新しいコードは、`.vocab-chrome` を除外したか必ず確かめること。**
本文の `class` は、サニタイザ（保存の前に危険な HTML を取り除く処理）が必ず落とします。
だから、この判定が誤って当たること（誤爆）はありません。

### 2.4 表示モードによる差

| モード | 条件 | 見え方 |
|---|---|---|
| **書ける形** | `body[edit-mode]`（スイッチ「閲覧」がオフ） | ページを開くと、最初から書けます（書く権限のある人が、パソコンで開いたときの既定です）。本文が `contenteditable` になり、ブロック操作・ツールバー・スラッシュメニューが使えます。画面は、編集権（ページ単位のロック）を取りません。保存は `POST /api/sync` で、ブロック単位です。保存するのは、ブロックを去る・タブを隠す・ページを去るときです。同じブロックを2人が同時に書くと、そのブロックの上に枠が出て、両方の版が並びます。違うブロックは、黙って合わさります。業務のボタン（鏡のボタン）も押せます。押す前に、書きかけを保存します |
| **閲覧モード** | `body` に `edit-mode` が無い（スイッチ「閲覧」がオン） | 読むだけです。本文は打てません。ブロック操作・ツールバー・スラッシュメニューは出ません。閲覧モードだけの働きは、表の並べ替え・見出しで畳む・カルーセル・画像の拡大・機械向けのタグを畳む・添付のクリック展開・表の印刷です。スマホは、初めは閲覧モードです。書く権限の無い人は、いつも閲覧モードです（スイッチも出ません） |
| **編集モード** | （2026-10-12 までの呼び名） | 2026-10-12 までは、ページ単位で編集権（編集ロック）を取ってから書く形でした。1人だけが書けました。同日にやめて、いまの「書ける形」になりました。CSS と JavaScript の `edit-mode` という属性の名前は、昔のまま残っています。古い文書と変更履歴に出てくる「編集モード」は、この形のことです |
| **匿名** | `body.public`（[assets/public.html](../../assets/public.html)） | 未ログインで実効公開ページを見ている状態です。サーバーが、編集用の殻ではなく、**公開専用ビュー**を返します（`RenderPublicShell`）。レールも書き込み系のUIも JavaScript も、配りません。編集用の殻の CSS にある `body.anonymous` は、その前の方式の名残です（殻が匿名に届いたときの備えとして残っています） |

どちらの形で開くかは、スイッチ「閲覧」を押した形を、その端末に憶えます（ブラウザの `localStorage` の `wcms.mode`）。
決定の経緯は [【考察】編集モードの再考.md](../考察/【考察】編集モードの再考.md) §6〜§8、要求は [【要求】ページとエディタ.md](../【要求】ページとエディタ.md) §3 にあります。

編集ロックの API（`/api/lock`・`/api/unlock`・`/api/lock/force`・`/api/save`・`/api/save-block`）は、道具のために残っています（ワンノートの製造・テンプレートの取り込み・E2E）。画面は使いません。

**計算ビューは、どのモードでも同じ**です。

- 中身は、サーバーがページを返すときに埋めます。
  だから、閲覧モードでも匿名でも、JavaScript なしで表が見えます（[view_render.go](../../internal/cms/view_render.go)）。
- 書ける形でも、中身は `contenteditable`（その場で書き換えられる状態）になりません。エディタの持ち物ではないためです。
- そのぶん、**書いている最中の変化は自動では反映されません**。
  子ページを作っても、子ページ一覧のビューに現れるのは、再読み込みのあとです。
  描画ロジックを Go と JS の2箇所に持たないための割り切りです。

## 3. 基盤の用語（業務と画面にまたがる土台）

| 用語 | 意味 | 出典 |
|---|---|---|
| **ページ** | w-cms の文書の単位です。親子の木構造（階層）を成します。1つのページは、本文HTML（内容）＋サイドカー（属性）でできています。通信記録・文書・案件（参照ハブ）等も、すべてページです。 | [アーキテクチャ §1-2](../旧文書/アーキテクチャとDBスキーマ.md) |
| **ページID** | ページを1つに決める識別子です。**6桁ゼロ埋めの数値文字列**です（例: `000001`、トップページは `000000`）。`pages.id`（`INTEGER PRIMARY KEY`）の採番値を、桁埋めしたものです。URLパス（`/000001`）や、保存フォルダ `data/master/{先頭2桁}/{id}/` の基底になります。 | [アーキテクチャ §6](../旧文書/アーキテクチャとDBスキーマ.md) |
| **正本性** | `data/master` のファイル群が、唯一の正データである、という決まりです。DB（`cms.db`）は、再生成可能な派生インデックス（ファイルから作り直せる索引）です。 | [アーキテクチャ §8](../旧文書/アーキテクチャとDBスキーマ.md) |
| **受信原本** | 受信したまま、改変せずに残す証跡です（生 `.eml`／スキャン元）。`.eml` は、添付を内包する完全アーカイブです。 | [通信記録メモ §9.1](../考察/【考察】通信記録処理.md) |
| **自己完結性** | 各文書ページが、業務用の実ファイルを自分のフォルダに所有し、単体で意味を保てることです。 | [通信記録メモ §9.1](../考察/【考察】通信記録処理.md) |
| **サイドカー** | ページの属性（親ID・所有/権限・作成/更新情報）を持つファイル `<id>.meta.json` です（正本）。本文HTMLは「内容」です。 | [アーキテクチャ §2](../旧文書/アーキテクチャとDBスキーマ.md)・[エディタ仕様 §9](../旧文書/エディタ仕様.md) |
| **版管理（リビジョン）** | 多くの取引から参照される定義（部品仕様・図面）の改訂方式です。**旧版を消さず保持・新版を追加・現行を状態フラグでマーク**します。参照する側は、使った版を固定（ピン）します。受注のような「その場編集（現在状態）」とは区別します。過去の取引を、さかのぼって変えないためです。いまの実装では、図面の改定（古い図面は旧版の子ページへ。改訂履歴に行を足します）と、構成部品の表の `区分`（現行／廃版）が、これに当たります。⚠ 下の「版」（ページの本文の履歴）とは、別の言葉です。 | [通信記録メモ §4.6](../考察/【考察】通信記録処理.md)・[アーキテクチャ §7](../旧文書/アーキテクチャとDBスキーマ.md) |
| **版**（版の履歴） | **ページの本文HTMLの履歴**です。保存の区切りごとに、本文の写しを残します（`data/master/…/versions/`）。右レールの「版の履歴」カードに並びます。書ける形で、「この版に戻す」と、ブロックごとに見て「このブロックだけ戻す」ができます。対象は本文だけです。戻しても、権限・所有者・親は変わりません。版は消しません（2026-09-23 の決定）。 | [【要求】ページとエディタ.md](../【要求】ページとエディタ.md) §4・[version.go](../../internal/cms/version.go) |

## 4. 言い換えた言葉と別名（2026-10-21）

2026-10-21 に、文書を人になじみやすい言葉へ書き直しました。

> 2026-10-21 利用者:「終わったら、すべての文書を検査して、矛盾を修正し、人間にとってなじみやすい言葉に書き換えてください」

書き直しの前の文書・変更履歴・【考察】・コードのコメントには、もとの言葉が残っています。
もとの言葉で引いたときは、この節で今の言い方を見てください。

### 4.1 そのまま使う言葉

次の言葉は、利用者が使う言葉なので、言い換えません。

| 言葉 | 意味 |
|---|---|
| **鏡** | 表示するときにサーバーが埋める、保存されない部分です。本文には鏡の印だけを保存します（§3「ビューマーカー」） |
| **帯** | 画面の上や下に横長に並ぶ、ボタンの列です（例: コンテキストツールバー・パソコンの固定の帯 `#w-fixed-bar`。§2.3） |
| **置き場** | 名前で役目が決まる、トップ直下のページです（通信箱・連絡帳・製造台帳・案件・製造・記録・テンプレート）。テンプレートを写して作ります |
| **印** | 本文に書いておく目印です。w-cms はそれを見て働きます（例: 鏡の印 `<section data-mirror="…">`・タグ・表のキャプション） |
| **正本** | いちばん正しいとする元のものです（例: ページの正本は `data/master` のファイル。§3「正本性」） |
| **写し** | 正本から作った複製です（例: 表の写し `data/tables.db`。§3） |
| **札** | 添付やファイルの横に出る、小さなボタンです（例: 「▶ 表示」「🔗 参照」「⋯」） |

### 4.2 言い換えた言葉（もとの言葉は別名）

| 今の言い方 | もとの言葉（別名） | 意味 |
|---|---|---|
| **API**・**入口** | 口（API の入口） | サーバーが外から受け付ける所です（例: 「保存の口」は「保存の API」） |
| **登録の仕組み** | 口（登録する所） | 拡張が `init()` から部品を差し込む関数です（例: 「鏡を載せる口」は「鏡を登録する仕組み」。`cms.Register…`・`comm.Register…`。[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md) §9） |
| **見張りの試験** | 番人 | 後戻り（直したはずの不具合や決まりが崩れること）を見つける試験です（例: コアと拡張の境の `internal/boundary`） |
| **ロック**（書き込みのロック） | 錠（書き込みの錠） | 1つのページの本文を、同時に2つの所から書かないための仕組みです（`cms.LockPageBody`）。§2.4 の「編集ロック」とは別のものです |
| **画面の部品** | クローム | 本文ではない飾りです。保存されません（§2.2・§2.3 の「語彙クローム」） |
| **画面の枠** | 殻 | 本文を囲む画面の枠組みです（§2.2） |
| **本文を配る仕組み** | 配送係 | コアが本文を1回だけ歩いて、要素を受け持ちのプラグインへ届ける仕組みです（`internal/cms/walk.go`） |
| **保存のときに本文を読む係** | 観察係 | 本文を読んで、自分のテーブルを作り直すプラグインです（`Observer`） |
| **試験が実は何も見張っていなかったこと** | 空振り | 試験が緑でも、壊したときに落ちない状態です |
| **わざと壊して、試験が落ちるかを見ること** | 変異（変異試験） | 試験が本当に見張っているかを確かめるやり方です |
| **任せた別のエージェント** | 下請け | エージェントが仕事を任せた、別のエージェントです |
| **〜として扱われる**・**〜を示す** | 名乗る（表が種類を名乗る） | 例: 「キャプションで名乗る表」は「キャプションで形式を示す表」 |
| **きっかけ** | 引き金 | 処理を呼び出す元になるものです（例: 観察係が受け持つ形式名 `Triggers()`） |
| **表記をそろえる** | 畳む（表記の揺れ） | 全角半角・空白・記号などの書き方の違いをそろえることです（正規化）。画面で「畳む」（折りたたむ）は、そのままの意味で使います |
| **本文に書き込んでしまう** | 焼く・焼き込む | 表示のときだけの部分（鏡など）が、本文として保存されてしまうことです |
