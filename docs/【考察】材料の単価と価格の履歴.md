# 【考察】材料の単価と価格の履歴

> 2026-09-21。ユーザーの問い:「材料の表形式を考察しましょう。現在は**単価やロットが
> 入っている**のですが、これは**検索して最新情報をひくべきもの**で、本来はここに
> あるべきものではありません。しかしながら、**ワンノートには検索して表示する機能が
> 無いので、参考価格を書いていました**。今後はどうあるべきでしょう？そして、
> **購入記録が無いので古い表の単価も消したくありません**」

## 1. 「単価」は3つの別物が同じ言葉になっている

これが問いの核心です。**1つの列名が、性質の違う3つの数を受けています。**

| 何 | 性質 | 日付 | 相手 | 置き場 |
|---|---|---|---|---|
| **いくらで買ったか** | 事実 | ある | ある | 発注明細（`our-order-items`） |
| **いくらで見たか** | 判断（**凍結すべき**） | 見積の日 | 無い | 見積もり |
| **いくらで買えそうか** | 予測 | — | — | **引いて出すもの。本文に書かない** |

ワンノートの `単価（ロット1）みなと` は**3つ目を1つ目の形で書いたもの**でした。
⚠ **書いた瞬間から古くなり、直す人は現れません**——何年前の値か誰にも分からない、
というのが実データの現状です。

そして `■見積もり` の表には既に `材料 840 円` の行があります。
**材料表の単価列は、その840円を出すための下書き**でした。

## 2. いまの土台は、既に半分そうなっている

| 表 | 材質 | 形状 | 寸法 | 単価 |
|---|---|---|---|---|
| `part-materials`（材料） | ✓ | ✓ | ✓ | **無い** |
| `our-order-items`（発注明細） | ✓ | ✓ | ✓ | **ある** |

**材料表に単価が無いのは偶然ではありません。** そして
[materials.go](../ext/subcon/materials.go) の `materialNameOf` が
**`材質＋形状＋寸法` を材料の鍵**として既に使っています（`RequiredMaterials` の集計）。

**繋ぐ鍵は、もう両方の表にあります。** 足りないのは引いて出す側（③計算）だけです。

## 3. 決めたこと（2026-09-21・ユーザー）

| 決めたこと | なぜ |
|---|---|
| **新しい材料表に単価を書かない** | 変わるもの（価格）と変わらないもの（仕様）を同じ行に置くと、行ごと古くなる |
| **参考単価は鏡で出す**——材料表の右に「最新単価・時点・仕入先」の列を足す | ⚠ **本文には書かない**（書けば古くなる）。鏡なら開くたびに引き直す |
| **移植した古い単価はそのまま列として残す** | ⚠ **購入記録がまだ無いので、これが唯一の価格記録**。消すと戻せない |

⚠ **3つ目が成り立つのは、可変列が索引に入るからです。** 実測で `000072` の
`単価（ロット）`・`単価（ロット1）みなと`・`単価（ロット1）たちばな` は
`vocab_index` に `part-materials` の列として載っています。
**残すことと、引けることは両立しています**——消す必要がそもそもありません。

## 4. 出所に順位を付け、4段目に「最新」を名乗らせない

**これが「消さない」と「古い値に騙されない」を両立させる仕掛けです。**

| 順 | 出所 | 日付 | 相手 | 画面での名乗り |
|---|---|---|---|---|
| 1 | **発注明細**（買った） | ある | ある | **最新単価** |
| 2 | 相見積もり（聞いた） | ある | ある | 見積単価 |
| 3 | 見積もりの材料費（使った） | ページの日 | 無い | その時の前提 |
| 4 | **ワンノートの参考価格** | **無い** | 列名にだけ | **参考（日付不明）** |

⚠ **4は決して「最新単価」の欄に出しません。** 日付の無い数字は、**古いほど危ない**
——「あるのに古い」は「無い」より悪い結果を生みます（その値で見積もって受注すると、
損が出るまで誰も気づかない）。

⚠ **引けなかったことを黙らないこと。** 「単価が出ない」と「そんな材料は買ったことが
ない」は**別**です。空欄にせず、**引けなかったと書く**。

## 5. ⚠ 罠

- **鍵が揺れます。** `鉄STPG370EG` と `鉄`、`t3.4*定尺` と `t3.2`——どれも自由文です。
  `text` 型の畳み込み（大小・全角）では届きません。**機械は候補を出すところまで、
  決めるのは人**（図面の重複判定と同じ結論）。
- **⚠ 材料表に `単位` がありません。** `個数 2` が2本なのか2枚なのかは、`寸法` の
  `定尺` から読むしかない。発注明細には `単位` があります。
  **掛け算（個数 × 単価 = 材料費）をさせるなら、先に単位を埋める必要があります。**
  ⚠ いまは**掛けずに単価だけ見せる**のが安全です。
- **購入記録は、まだ自動では貯まりません。** 発注明細は**発注書ページを作れば**
  貯まりますが、そのページを作る機能は未実装（未決 #12）。
  ⚠ **「今後は引ける」は、発注書を w-cms で出し始めてからの話**です。
  **PDF発行が入った（2026-09-21）ので、器はできています。**
- **同じ材料が複数の加工製品ページに散ります。** 単価を各ページに書くと
  **同じ事実がN箇所**になり、⚠ **直す人は現れません**。ワンノートの実例がそれです。

## 6. 未決

- **相見積もり（順位2）の置き場。** ワンノートの `単価（ロット1）みなと`・`たちばな` は
  「買う前に聞いた値段」で、**相手と日付を持てる器**が要ります。
  ⚠ ユーザー判断で**後回し**（2026-09-21）。`外注加工` の `推奨業者` と同じ形の問いです。
- **見積もりの材料費を、材料表から自動で積むか。** いまは人が `材料 840 円` と
  書いています。⚠ 単位の問題（上）が片付くまでは自動化できません。
- **「最新」の定義。** いちばん新しい発注か、同じ仕入先のいちばん新しい発注か。
  ⚠ 仕入先で値段が違うので、**1つに決めず並べる**ほうが実務に合うかもしれません。

## 7. 着手の順番

1. **鏡の列**（`材料` 表の右に 最新単価・時点・仕入先）。⚠ **引けなければ「引けない」と書く**
2. 発注書ページを作る機能（未決 #12）——**これが入って初めて記録が貯まります**
3. 価格推移（行を押すと履歴）——2の記録が溜まってから
4. 相見積もりの器——ユーザーが必要と判断したとき
