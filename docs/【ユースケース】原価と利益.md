# 【ユースケース】原価と利益

このドキュメントでは、**w-cms** における原価および利益（売上・粗利）の算出ロジックと、それに使用する語彙（`data-type` マーカー付き標準HTML）の設計仕様を定義します。

---

## 1. 目的
見積書（売上予定）、発注書（売上確定）、仕入先への見積・発注書（原価）をHTMLドキュメント内で適切に表現し、データベースがそれら非同期に登録される各種データを `item_id`（製品コード/図面番号）で名寄せして、リアルタイムな原価・利益管理を行えるようにします。

---

## 2. 語彙の設計仕様

いずれも**値は属性ではなく要素の中身**（`dd`／`td` のテキスト）に置きます。項目の鍵も
`dt` の項目名・`th` の見出しという**見える文字そのもの**です。PDF原本を伴う場合は容器
`<section data-type="file" data-src="…">` で包みます（容器は任意）。

### 2.1. 弊社の見積もり (`our_estimates`)
顧客に対して提示した見積金額（売上予定）を記録します。見積は明細を持たないフラットな1件なので `<dl>` です。
```html
<section data-type="file" data-src="EST-2026-001.pdf">
    <p>📎 <a href="/data/master/00/000002/EST-2026-001.pdf">見積書_EST-2026-001.pdf</a></p>
    <dl data-type="our-estimate">
        <dt>品番</dt><dd>SHAFT-01</dd>
        <dt>顧客</dt><dd>トーア</dd>
        <dt>見積金額</dt><dd>10000</dd>
        <dt>見積日</dt><dd>2026-06-15</dd>
    </dl>
</section>
```

### 2.2. 顧客の発注書 (`client_orders` / `client_order_items`)
顧客から受領した正式な発注金額（売上確定）を記録します。1枚の発注書に複数部品が載るため、ヘッダ `<dl>` ＋明細 `<table>` の構造をとります。
```html
<section data-type="file" data-src="PO-1001.pdf">
    <p>📎 <a href="/data/master/00/000002/PO-1001.pdf">発注書_PO-1001.pdf</a></p>
    <section data-type="client-order">
        <dl>
            <dt>発注書番号</dt><dd>PO-1001</dd>
            <dt>発注元</dt><dd>トーア</dd>
            <dt>発注日</dt><dd>2026-06-18</dd>
        </dl>
        <table data-type="client-order-items">
            <tbody>
                <tr><th>品番</th><th>品名</th><th>単価</th><th>数量</th><th>状態</th></tr>
                <tr><td>SHAFT-01</td><td>シャフトA</td><td>8000</td><td>10</td><td>未着手</td></tr>
            </tbody>
        </table>
    </section>
</section>
```

### 2.3. 材料屋・加工業者の見積もり (`supplier_estimates`)
外注や材料発注にあたり、業者から受領した見積もり（原価予定）を記録します。
```html
<section data-type="file" data-src="SUP-EST-501.pdf">
    <p>📎 <a href="/data/master/00/000002/SUP-EST-501.pdf">材料見積_SUP-EST-501.pdf</a></p>
    <dl data-type="supplier-estimate">
        <dt>部材名</dt><dd>特殊鋼材</dd>
        <dt>仕入先</dt><dd>東邦金属工業</dd>
        <dt>見積金額</dt><dd>2500</dd>
        <dt>見積日</dt><dd>2026-06-16</dd>
    </dl>
</section>
```

### 2.4. 弊社の発注書 (`our_orders` / `our_order_items`)
材料購入や外注加工のために、弊社が発行した注文（確定原価）を記録します。こちらもヘッダ＋明細の構造です。
```html
<section data-type="file" data-src="PO-OUR-001.pdf">
    <p>📎 <a href="/data/master/00/000002/PO-OUR-001.pdf">注文書_PO-OUR-001.pdf</a></p>
    <section data-type="our-order">
        <dl>
            <dt>発注書番号</dt><dd>PO-OUR-001</dd>
            <dt>発注先</dt><dd>東邦金属工業</dd>
            <dt>発注日</dt><dd>2026-06-18</dd>
        </dl>
        <table data-type="our-order-items">
            <tbody>
                <tr><th>品名</th><th>単価</th><th>数量</th><th>状態</th></tr>
                <tr><td>特殊鋼材</td><td>2300</td><td>10</td><td>未納品</td></tr>
            </tbody>
        </table>
    </section>
</section>
```

> 金額は `¥8,000` のような表記で書いても、同期時に数値へ正規化されます（`¥`・桁区切りを吸収）。
> 数量の空セルは 1 として扱います。

---

## 3. 集計ロジック (粗利計算)

データベースは、`item_id`（または `item_name`）をキーとして、同一案件/部品ごとの売上高と原価高を紐づけて算出します。

### 3.1. 売上（収入）の算出
1.  **確定売上**: `client_order_items` の `price * quantity` の合計。
2.  **予定売上**: 顧客からの発注書がまだない場合、`our_estimates` の `price` を売上予定（数量1と仮定、または見積情報）として参照します。

### 3.2. 原価（支出）の算出
1.  **確定原価**: `our_order_items` の `cost * quantity` の合計。
2.  **予定原価**: 弊社からの発注書がまだない場合、`supplier_estimates` の `cost` を原価予定として参照します。

### 3.3. 利益計算
$$利益 (粗利) = 売上 - 原価$$
$$利益率 = \frac{利益}{売上} \times 100\%$$

> [!NOTE]
> 上記の集計ロジックは設計上の仕様であり、**未実装**です。本文のパース・DB同期（`our_estimates`, `supplier_estimates`, `client_order_items`, `our_order_items` への抽出）は実装済みですが、これらを `item_id` で名寄せして利益率を算出する集計と、それを画面に表示するビューはまだ存在しません。
>
> 実装時の形は**先行する部材手配集計（`required-materials`）に倣います**——語彙レジストリ（[vocab.go](../internal/cms/vocab.go)）へ `View: true` の形式を1件足し、本文には空のマーカー `<section data-type="…">` だけを保存して、中身は**サーバー事前描画**（[view_render.go](../internal/cms/view_render.go)・[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) §4.4）で埋めます。集計SQL自体は同書「3. 部材手配計算APIの仕様」と同様に計算プラグイン側へ置きます。
