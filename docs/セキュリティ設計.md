**この文書は「線引き」と「判定の手順」だけを持ちます。** 仕組みの詳細はそれぞれの正本が
持っていて、ここから指します——同じことを2か所に書くと、片方が必ず古くなるためです。

| サニタイズ二層・許可リスト・URL規則・CSPの文字列 | [本文サニタイズ設計.md](本文サニタイズ設計.md) |

ここが引き受けるのは、**上の文書のどれにも収まらない問い**です:

- 本文に書いた文字は、ブラウザに何をさせられるのか（＝信頼境界）

- マーカー方式は `<embed>` を許すのと同じではないのか（§4）

## 1. 誰から何を守るのか

w-cms は**社内の業務システム**で、利用者は全員が認証済みです。だから守る相手は
「見知らぬ攻撃者」だけではありません。

| 相手 | 何を持っているか | 何を防ぐか |
|---|---|---|
| **本文を書ける人**（＝全利用者） | 任意のHTML文字列を保存できる | 書いた文字が、**他の利用者のブラウザで勝手に動く**こと |
| **外から届くもの**（メール・添付・PDF・FAX） | 中身は誰も検めていない | 取り込んだ時点で**本文の一部として動く**こと |
| **匿名の訪問者**（公開ページ） | 読むだけ | 読めないはずのものが見えること・存在が漏れること |

**いちばん大きいのは1行目です。** 攻撃者を想定しなくても、**コピペ1回で事故が起きます**
——ワンノートや Web から貼った内容に何が混ざっているかは、貼った本人も知りません。

> **実際に起きたこと**（2026-08-21）: 本文へ `<img src="/api/logout">` を1つ保存すると、
> そのページを開いた**全員が無音でログアウト**しました。誰も攻撃していません。
> 埋め込みの宛先を制限していなかった、というだけです。

### 不変条件

**本文に書ける文字は、「表示」以上の力を持ってはいけません。**

具体的には、本文の文字だけでは次のどれも起こせません:

- スクリプトを走らせる
- 外部へ通信する（画像1枚の取得も含む）
- アプリの口（`/api/…`）を叩く
- 画面を覆う・入力欄を偽装する
- 他人の権限で何かを読む

## 2. 三枚重ね（どれか1枚が破れても止まる）

| 層 | 何をするか | 破れたときに何が残るか | 正本 |
|---|---|---|---|
| **① サニタイズ** | 危ない要素を部分木ごと削除、属性を許可リストで絞る、埋め込み先URLを限る | ②③ | [本文サニタイズ設計.md](本文サニタイズ設計.md) §5 |
| **② 配信ヘッダ** | 添付の `Content-Type`・`Content-Disposition: attachment`・SVGへの sandbox | ①③ | 同 §5／`internal/cms/page/perms.go` |
| **③ CSP** | `script-src 'self'` ほか。インラインの `script`/`style`/`on*=` を禁じる | ①② | 同 §6 |

**①は入口と出口の両方に掛かります**（保存時と描画時）。保存経路を通っていない本文
——手で置いたファイル・バックアップからの復元・取り込みAPIが直接書いたページ——にも
効かせるためです。

⚠ **CSP は strict 運用中**（`'unsafe-inline'` なし）。インラインの `<script>`・`<style>`・
`style=` 属性・`on*=` は**書けません**。スクリプトとスタイルは `/assets/` の外部ファイルへ、
イベントは `addEventListener`、動的スタイルは `element.style.x = y` で当てます。

## 3. 「これを画面に出したい」と言われたときの判定手順

**この節がこの文書の主目的**です。同じ問いが繰り返し出るので、答えを1か所に置きます。

### 手順

1. **その形式は、ブラウザが素で描けるか。**
   描けないもの（CAD・Excel・Word）は、外部の描画ライブラリを連れてこない限り出せません
   ——そして連れてくることは[開発方針 §1](開発方針.md) が原則禁止しています。
   **ここで止まるなら、それが答えです。**

2. **その要素は本文に書けるか**（[本文サニタイズ設計.md](本文サニタイズ設計.md) §5 の許可リスト）。

   | 形式 | 要素 | 本文に書けるか |
   |---|---|---|
   | png / jpg / webp / gif / **svg** | `<img src>` | ✅ |
   | mp4 など | `<video src controls>` | ✅ |
   | 音声 | `<audio src controls>` | ✅ |
   | **pdf** | `<embed>` / `<object>` / `<iframe>` | ❌ **3つとも禁止** |

   書けるなら、**それで終わりです**——マーカーも新しい仕組みも要りません。

3. **書けないなら、マーカー方式**（§4）。本文には印だけを置き、**中身は機械が組みます**。

4. **宛先は必ず機械が決めること。** 書いた人が決めてよいのは「どれを指すか」までで、
   URLそのものを書かせてはいけません（§4 の表）。

5. **配信の口の認可を確かめること。** 出す先が添付なら、その配信口が読み手の権限を
   見ているか（`page.RequirePageReadOrPublic`）。

### 判定の実例（2026-09-14）

「部品ページに図面PDFを出したい」に対して、この手順を通した結果:

- 手順1 … PDFはブラウザが描ける ✅
- 手順2 … `<embed>` は禁止 ❌ → 手順3へ
- 手順3 … `section[data-type="file-view"]` のマーカーを新設
- 手順4 … URLは参照の値（`ページID-添付ID`）から機械が組む
- 手順5 … 配信は既存の認可付きの口を通る

**ついでに分かったこと**: マーカーが要るのは**PDFだけ**でした。画像・SVG・動画・音声は
本文にそのまま書けます。**「PDFを出す仕組み」を作る前に、この表を見ること。**

## 4. マーカー方式は、`<embed>` を許すのと同じではない

**この問いは繰り返し出ます**（2026-09-14 ユーザー:「結局のところ embed と同じなので
セキュリティ上問題でしょうか？」）。答えは**違う**で、理由は1つです。

> **`<embed>` が危ないのは要素そのものではなく、`src` を書いた人が決めることです。**

| | `<embed>` を本文に許す | マーカー＋機械が組む |
|---|---|---|
| `src` を決めるのは | **書いた人の文字列** | **機械**（参照から導き、形を検査する） |
| 指せる先 | 何でも（`/api/logout`・外部・`javascript:` …） | `/<6桁>/<英数字>.<拡張子>` だけ |
| 認可 | URLを直接書ける | 同じ配信口を通る——**読めないページのファイルは出ない** |
| 攻撃者が得るもの | 任意リソースの自動取得・プラグイン起動 | **何も増えない**（自分が読めるファイルを、自分のページに出せるだけ） |

書いた人が選べるのは**ページIDと添付IDだけ**で、しかもその2つは**自分に読めるページの
ものでなければ何も出ません**。2026-08-21 の `/api/logout` 事故が起きたのは、
まさに「宛先を書いた人が決められた」からでした。ここはその力が機械の手に戻っています。

### だから守るべき規律

- **リンクから埋め込みを導出するときは、形を必ず検査すること。**
  リンク（`a[href]`）はサニタイザが宛先を制限していません——押さないと何も起きないためです。
  そのhrefを `src` に流すと、制限していない値が埋め込みの宛先になります。
  正規表現で「きれいなURL」の形を確かめてから使います。
- **サニタイズの後にHTMLを足す関数は、自前でエスケープの責任を負うこと**
  （`RenderComputedViews`・`RenderAnchors`・`RenderPageShell`・`RenderReferenceLinks`・
  `renderFileView`）。ここの規律が破れると保存型XSSになります。
- **DOM生成は `createElement` ＋ `textContent`。** `innerHTML` へ文字列を入れないこと
  ——`escapeAttr` 頼みの保存型XSSが実際に発火した過去があります。

## 5. 外から届くものの扱い

| もの | 扱い |
|---|---|
| **画像** | 保存前にEXIFを落とす（JPEGは再符号化するので画素は元と厳密には一致しない） |
| **SVG** | 入口で「整形式のXMLでルートが svg」を検査。守りの本体は**配信側**（`attachment` ＋ sandbox CSP）——本文からの `<img>` 表示はこのヘッダを無視するので影響なし |
| **PDF** | インライン配信（クリック展開が前提）。**中身の危険は埋め込み方によらず同じ**なので、開くかどうかの判断を人に残す（自動では開かない） |
| **ZIP** | 目録を読むだけで**展開しない**（ZIP爆弾対策）。中の1件を取り出す解析だけ上限つき |
| **由来の分からないもの** | `application/octet-stream` ＋ `attachment`（表示させずダウンロードさせる） |
| **`.json`** | **添付として受けません**。置き場は分離済みで構造上は無害ですが、正本と同じ拡張子を添付に混ぜる運用そのものを断ちます |

**通信箱の下の添付は「届いた事実の証拠」**なので読み取り専用です（WebDAV からも書けません）。
置き場所が扱いを決めます。

## 6. 秘密の置き場

- **`config/settings.json` は公開リポジトリに入ります。** 秘密を書けば公開されます。
- 鍵・トークンは環境変数（`~/OneDrive/デスクトップ/w-cms.env`・**リポジトリ外**）。
  **書くのは人**——値をチャットやログへ出すと、そこに残ります。
- **リフレッシュトークンは `data/mail/<利用者>.json`。** ログにも応答にも出しません。
- ⚠ **ファイルの権限指定（0600）は Windows では効きません**（実測 666）。
  本番機で守っているのはOSのアカウント分離です。
- **Gemini は有料枠の鍵で運用する**——無料枠は入力データが製品改善に使われます。
  コードからは判定できず、**運用側で守るしかありません**。
