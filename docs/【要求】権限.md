# 【要求】権限

**認証・認可・公開・監査**の要求仕様です。

> **書くのは利用者**、**矛盾を指摘するのがエージェント**（開発方針 §2）。
> 本書は **2026-09-23 に [要件定義書.md](要件定義書.md) の §2.3・§4.1 から抜き出したもの**です
> ——⚠ **利用者が読んで直すための下書き**です。

⚠ **2種類のことが書いてあります。** （印なし）＝**要求**（利用者が直す）、
⚠ **いま**＝**実装の現状**（エージェントが直す）。
**なぜそうしたか**は [認証認可設計.md](認証認可設計.md) が正本。

---

## 1. 認証

- **アプリ単体で管理**します（SSOへ委譲しない）。⚠ 将来の委譲（MFA・SSO/OIDC）は
  接合点だけ予約してあります。
- パスワードは **argon2id** でハッシュ。
- **総当たり対策**（バックオフ／ロックアウト）と、**利用者の列挙対策**
  （⚠ **存在しない利用者でも同じ計算量を消費する**）を備えること。
- セッションは **256bit トークン**（DB側はハッシュ保存）、Cookie は
  `HttpOnly`/`Secure`/`SameSite=Lax`。
- **「最後の操作から8時間」で失効**すること（アイドル基準へ一本化）。
  ⚠ **失効の数分前に画面で告知すること**——⚠ **いま**は未実装（2026-08-21 決定）。
- **初期管理者**は環境変数で、**利用者が空のときだけ**作ること。

⚠ **パスワード変更で既存セッションは切りません**（ユーザー:「書きかけが保存できないほうが
困ります」）。締め出しは「利用停止」が受け持ちます。

## 2. 認可——ページ単位の Unix 風モデル

- **read/write の2ビット × owner/group/other の3クラス**（mode は `"330"` のような3桁文字列）。
- **子ページの作成には親ページの write を要求**します（ディレクトリ書き込み相当）。
- chmod/chgrp は **owner または admin**、chown は **admin のみ**。

### ⚠ 権限の正本はサイドカー

権限の正本は **`<id>.meta.json`** で、**書き込めるのは権限変更の口とページ新規作成だけ**です。

⚠ **本文保存の口は権限に一切触れないこと**——**自己認可の構造的な防止**です
（本文を保存する操作で自分の権限を書き換えられてはいけません）。

⚠ **いま**: 認可の**読み口はサイドカーではなく `cms.db`（派生）**です。
ずれたら認可は索引に従います。⚠ **派生から正本へは書き戻しません**
（サイドカーが読めなければ止まる）。

## 3. 匿名公開

- **mode と独立した `public` フラグ**で制御します。
- **実効公開＝自分の public ∧ 全先祖の public**（パスゲート）。
  ⚠ **ルート `000000` の非公開化が、サイト全体のキルスイッチ**になること。
- **新しいページの `public` は常に false**（フェイルクローズ）。
- 匿名は **read 専用**。
- ⚠ **匿名には「読めない」と「存在しない」を区別させない**
  （[【要求】ページとエディタ.md](【要求】ページとエディタ.md) §1）。
- 戻り先は**同一サイト内の絶対パスだけ**に絞ること。

## 4. 監査

**書き込み・権限変更を記録し、admin が閲覧できること。**

**認証イベント（ログインの成功・失敗・ログアウト）も記録対象**です。

> 2026-08-21 ユーザー:「**誰が事務所の外から入ってきたか知る必要があると思います。**」

- 「どこから」を満たすため、認証イベントには**接続元アドレス**も残します。
- ⚠ **詐称できないようにすること。** 本番はリバースプロキシの背後なので `X-Forwarded-For` を
  見ますが、⚠ **前段がプロキシ（ループバック／私設アドレス）のときだけ採用し、
  末尾＝直近のプロキシが足した値**を使います。
- 記録するもの: 本文の保存・権限変更・**ページの新規作成**・**添付の保存と上書き**
  （⚠ **上書きは別の名前で記録します**——添付の上書きは復元できないため）・**索引の全再構築**。

⚠ **監査ログで「5年遡れること」は満たせません**（[【要求】ページとエディタ.md](【要求】ページとエディタ.md) §4）。

## 5. 本文の安全

### サニタイズは二層

**保存時＋描画時**の許可リスト方式で、**サニタイザは冪等**であること
（`Sanitize(Sanitize(x)) == Sanitize(x)`）。

⚠ **保存時は除去結果をエディタへエコーバックして利用者に通知すること**
——黙って消すと、書いたものが消えたことに気づけません。

### 「タグは寛容・属性は厳格」

| | 方針 |
|---|---|
| **要素** | 構造HTML（h1〜h6・リスト・ルビ・表・`details`・`video`/`audio`）は**広く許可** |
| | `script`/`style`/`iframe`/`form` 系は**部分木ごと削除** |
| **属性** | `on*`・`style`・`id`・`class` は**常に拒否**（例外は `data-id`・`data-type`・`data-ref`） |

⚠ **`input`・`button`・`select` も削除対象**です（入力欄の偽装）
——**本文に偽のログインフォームを書ける穴**を塞ぐため。
⚠ **だからチェックボックスは本文に書けません**（[【要求】タグ.md](【要求】タグ.md) §10）。

⚠ **`data-type` は属性名だけを要素限定で許可し、値は検査しません。**
**レジストリは編集支援と検証の語彙であって、安全性の門ではありません**
——この分離があるから、将来レジストリを実行時に編集できるようにしても危険な要素は増えません。

### URLの規則

| どこ | 許す形 |
|---|---|
| リンク（`href`・`cite`） | 相対・http・https・mailto・tel |
| **埋め込み**（`img src` 等） | ⚠ **`/data/` 配下ときれいなURLに限る** |

⚠ **リンクは制限していないので、クロームがリンクから埋め込みを導出するときは形を必ず検査すること。**

### そのほか

- **CSP を全レスポンスへ付与**すること。⚠ **いま**は **strict 版**（`'unsafe-inline'` なし）で、
  インラインの `script`/`style`/`on*=` は**書けません**。
- **CSRF は Origin/Referer とリクエストホストの一致検証**（GET/HEAD/OPTIONS 以外）。
  ⚠ **ヘッダが無ければ拒否**（フェイルクローズ）。
- ⚠ **フロントのDOM生成は `createElement`＋`textContent`。**
  **値を文字列連結して `innerHTML` へ入れないこと**——`escapeAttr` 頼みの保存型XSSが
  **実際に発火した過去があります**。
- ⚠ **サニタイズ後にHTMLを足す関数は、自前でエスケープ責任を負います**
  （`RenderComputedViews`・`RenderAnchors`・`RenderPageShell`・`RenderReferenceLinks`）。
  **破れると保存型XSS**です。
- **本番は TLS/HTTPS 必須**（リバースプロキシで終端）。
  ⚠ **Secure Cookie の無効化は、ローカル検証のときだけ。**
