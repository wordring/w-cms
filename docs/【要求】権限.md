# 【要求】権限

**認証・認可・公開・監査**の要求仕様です。

- **認証**は、誰がログインしているかを確かめることです。
- **認可**は、その人に何を許すかを決めることです。
- **公開**は、ログインしていない人にページを見せることです。
- **監査**は、誰が何をしたかを記録して、あとで確かめられるようにすることです。

> **この文書の読み方**
>
> - 印の無い文は**要求**です（こうあってほしい、という決まり）。書くのは利用者で、
>   エージェント（AI）は矛盾を見つけたら指摘します（[開発方針.md](開発方針.md) §2）。
> - 「⚠ **いま**」で始まる段落は**実装の現状**です。こちらはエージェントが実装に合わせて直します。
> - 末尾の「下書き」は、エージェントが旧文書から抜き出して置いたものです。
>   利用者が読んで、直したり採ったりします。
> - **なぜそうしたか**は、[認証認可設計.md](旧文書/認証認可設計.md) が正本です。
>   この文書の言い回しが変わった経緯は、末尾の「この文書の経緯」にまとめました。

この文書は、2026-09-23 に [要件定義書.md](旧文書/要件定義書.md) の §2.3・§4.1 から抜き出して作りました。

## 1. 認証

- **認証は、アプリ単体で管理します。** SSO へは委譲しません。
  SSO は、1つのログインを、いくつものシステムで使い回す仕組みです。
- 将来の委譲（MFA・SSO/OIDC）は、接合点だけ予約してあります。
  - MFA は、パスワードのほかに、もう1つの確かめを足す仕組みです（多要素認証）。
  - OIDC は、SSO の方式の1つです。
  - 接合点は、あとからつなぐための場所のことです。

### パスワード

- **パスワードは、argon2id でハッシュします。**
  ハッシュは、元に戻せない形に変えて保存することです。
  argon2id は、そのための方式の1つです。総当たりで破るのに手間がかかるように作られています。
- **パスワードを変更しても、既存のセッションは切りません。**
  セッションは、ログインしてからログアウトするまでの、つながりのことです。

  > 利用者:「書きかけが保存できないほうが困ります」

  締め出しは、「利用停止」が受け持ちます。

### 総当たりと列挙への備え

- **総当たり対策**（バックオフ／ロックアウト）を備えること。
  - 総当たりは、パスワードを片っ端から試す攻撃です。
  - バックオフは、失敗するたびに、次を試せるまでの待ちを延ばすことです。
  - ロックアウトは、しばらくのあいだ、ログインを受け付けなくすることです。
- **利用者の列挙対策**を備えること。
  - 列挙は、どの利用者名が実在するかを、外から探り当てることです。
  - ⚠ **存在しない利用者でも、同じ計算量を消費すること。**
    かかる時間の違いで、利用者の有無を見分けられないようにします。

⚠ **いま**:

- 続けて失敗するたびに、次を試せるまでの待ちが倍になります（1・2・4・8秒）。
- 待ちのあいだは、パスワードを確かめずに断ります（失敗には数えません）。
  ログイン画面は「しばらく待って」と言います。
- 5回続けて失敗すると、15分のロックアウトになります。
- 数えるのは、打たれた利用者名ごとです（存在しない名前も同じです）。
  だから、待ちから利用者の有無は分かりません。
- 実装: `internal/auth/users.go` の `backoffFor`・`isLockedOut`。

### セッション

- **セッションは、256bit トークンで見分けます**（DB の側には、ハッシュにして保存します）。
  トークンは、その人であることを示す、でたらめな長い合い言葉です。
- **Cookie は `HttpOnly`/`Secure`/`SameSite=Lax` にします。**
  Cookie は、ブラウザがトークンを覚えておく入れ物です。3つの指定の意味は、次のとおりです。
  - `HttpOnly`: ページの中のスクリプトから読めなくします。
  - `Secure`: HTTPS（暗号にした通信）のときだけ送ります。
  - `SameSite=Lax`: ほかのサイトから出された要求には、原則として付けません。
- **「最後の操作から8時間」で失効すること**（アイドル基準へ一本化）。
  アイドルは、操作の無い時間のことです。失効の基準を、これ1つにそろえます。
- **失効の数分前に、画面で告知すること。**

⚠ **いま**: 上の2つとも、2026-10-14 に作りました。

- **最後の操作から8時間で切れます。** ログインからの絶対期限と、30分のアイドルは、ありません（`internal/auth/session.go` の `SessionIdleTTL`）。
- 操作で寿命が延びます。操作とは、利用者の要求に当たるもの（ページを開く・保存・業務のボタン など）です。
- 画面が裏で自動に送る要求では、延びません。
  ページの更新の知らせの購読（`/api/page-events`）・キャレットの知らせ（`/api/presence`）・残り時間を見る `GET /api/session`・
  印 `X-Wcms-Background` の付いた要求（知らせを受けての読み直し・メールの読み込みの様子の見張り など）です。
- 最後の操作の記録は、前の記録から1分以上たった操作のときだけ書き直します。Cookie もそのときに出し直すので、
  Cookie の寿命はいつも「最後の操作から8時間」です。失効は、最大で1分早まります。
- 告知は、失効の**5分前**です（「数分」の値は未決なので、5分にしました。`SessionWarnBefore`）。
  画面の上に帯が出て、「続ける」を押すと延びます。切れると、ログインの画面へ移ります。
  書きかけがあるときは移らずに、帯で知らせます（`assets/session.js`。エディタ・管理・表を探す・メール一覧の画面）。

### 初期管理者

- **初期管理者は、環境変数で渡し、利用者が空のときだけ作ること。**
  初期管理者は、最初の管理者のことです。
  環境変数は、サーバーを起動するときに、外から渡す設定の値です。

## 2. 認可——ページ単位の Unix 風モデル

ページごとに、誰が読めて、誰が書けるかを決めます。
形は、Unix（サーバーでよく使われる OS）のファイルの権限に似せています。

- **read/write の2ビット × owner/group/other の3クラス**で決めます。
  - read は読む権限、write は書く権限です。
  - owner は所有者、group はグループ、other はそれ以外の人です。
  - この組み合わせを mode と呼びます。mode は、`"330"` のような3桁の文字列です。
- **子ページの作成には、親ページの write を要求します。**
  Unix で、ディレクトリ（フォルダ）への書き込みに当たります。
- **権限を変えられる人は、次のとおりです。**
  - chmod（mode を変える）・chgrp（グループを変える）は、**owner または admin**
  - chown（所有者を変える）は、**admin のみ**

### ⚠ 権限の正本はサイドカー

サイドカーは、ページの属性を持つファイルです。
権限の正本（おおもとの記録）は、このサイドカー **`<id>.meta.json`** です。

- **サイドカーに書き込めるのは、権限変更の口と、ページ新規作成だけです。**
- ⚠ **本文保存の口は、権限に一切触れないこと。**
  本文を保存する操作で、自分の権限を書き換えられてはいけません。
  これを、仕組みの形で防ぎます（**自己認可の構造的な防止**）。

⚠ **いま**:

- 認可の**読み口は、サイドカーではなく `cms.db`（派生）**です。
  `cms.db` は、ファイルから作った、検索用の写しです（索引）。
- ずれたら、認可は索引に従います。
- ⚠ **派生から正本へは、書き戻しません。**
  サイドカーが読めなければ、止まります（要求は [【要求】運用.md](【要求】運用.md) §1）。

## 3. 匿名公開

匿名は、ログインしていない訪問者のことです。

- **公開は、mode と独立した `public` フラグで制御します。**
  フラグは、オンかオフかの印です。
- **実効公開＝自分の public ∧ 全先祖の public**（パスゲート）。
  - そのページ自身と、親をたどった先のページのすべてが公開のときだけ、実際に公開されます。
  - 途中に1つでも非公開のページがあれば、そこが門になって、その下は見えません。
- ⚠ **ルート `000000` の非公開化が、サイト全体のキルスイッチになること。**
  キルスイッチは、全体を一度に止めるスイッチです。
- **新しいページの `public` は、常に false です**（非公開で始まります）。
  迷ったら閉じる側に倒す考え方（フェイルクローズ）です。
- **匿名は read 専用です**（読むことだけができます）。
- ⚠ **匿名には、「読めない」と「存在しない」を区別させないこと**
  （[【要求】ページとエディタ.md](【要求】ページとエディタ.md) §1）。
- **戻り先は、同一サイト内の絶対パスだけに絞ること。**
  戻り先は、ログインのあとに戻るアドレスのことです。
  絶対パスは、`/` で始まる、サイトの中の住所です。ほかのサイトのアドレスは、戻り先にできません。

## 4. 監査

- **書き込み・権限変更を記録し、admin が閲覧できること。**
- **認証イベント（ログインの成功・失敗・ログアウト）も、記録対象です。**

> 2026-08-21 利用者:「**誰が事務所の外から入ってきたか知る必要があると思います。**」

### 接続元アドレス

- 「どこから」を満たすため、認証イベントには、**接続元アドレス**も残します。
  接続元アドレスは、どこから接続してきたかを示す、ネットワークの住所（IP アドレス）です。
- ⚠ **詐称できないようにすること。**
  - 本番は、リバースプロキシの背後で動きます。
    リバースプロキシは、w-cms の手前に置いて、外からの通信を受けて取り次ぐサーバーです。
  - そのため、接続元は `X-Forwarded-For` を見ます。
    これは、プロキシが「元の接続元はここです」と書き添える、通信の付属の情報（ヘッダ）です。
  - ただし、**前段がプロキシ（ループバック／私設アドレス）のときだけ採用し、末尾の値を使います**。
    末尾は、直近のプロキシが足した値です。
  - 前段は、w-cms に直接つないできた相手のことです。
    ループバックは、同じ機械の中からの接続です。私設アドレスは、社内などの閉じたネットワークのアドレスです。

### 記録するもの

- 本文の保存
- 権限変更
- **ページの新規作成**
- **添付の保存と上書き**
  （⚠ **上書きは別の名前で記録します**。添付の上書きは復元できないためです）
- **索引の全再構築**

⚠ **監査ログは、帳票の保持（5年・7年・最大10年）の代わりになりません**（[【要求】ページとエディタ.md](【要求】ページとエディタ.md) §4）。

⚠ **いま**: コードは、上の一覧より多くを記録しています。コアが記録するものは、次のとおりです。

| 何を | 記録の名前 |
|---|---|
| 認証（接続元アドレスつき） | `login`・`login.fail`・`logout` |
| 本文の保存 | `save`（画面の保存 `/api/sync` も、この名前です）・`save-block` |
| 権限変更 | `chmod`・`chgrp`・`chown`・`publish`・`unpublish`（公開の切り替え） |
| ページ | `new-page`・`delete-page`・`set-parent`（親の付け替え）・`reorder`（並べ替え）・`revert`（版の書き戻し）・`required-page.create`（置き場を作る）・`intake.folder`（機械がフォルダのページを作る）・`tag.rename`（タグの値の置き換え） |
| 添付 | `attach`・`attach.overwrite`（上書き）・`attach.meta-failed`・`local-edit.start`・`local-edit.write`・`local-edit.touch-failed` |
| 利用者とグループの管理 | `user.create`・`user.password`・`user.enable`・`user.disable`・`group.create`・`group.add`・`group.remove` |
| 管理の操作 | `rebuild-db`（索引の全再構築）・`data.reset`（データの初期化）・`lock.force`（ロックの強制解除） |

- 拡張も、自分の操作を同じ監査ログに記録します（メールの送信・解析・整理・部材発注書 など）。
- 監査ログを消す仕組みは、ありません。置き場は `data/auth.db` です。
- 管理の画面に出るのは、新しい順に200件までです。
- 実装: `internal/auth/admin.go` の `Audit`・`AuditRequest`・`RecentAudit`。

## 5. 本文の安全

### サニタイズは二層

サニタイズは、本文の HTML から、危ない部分を取り除くことです。取り除く仕組みを、サニタイザと呼びます。

- **保存時＋描画時の二層で行うこと。** 描画時は、画面に出すときのことです。
- **許可リスト方式にすること。**
  許可リスト方式は、「許すもの」を並べておいて、そこに無いものは通さないやり方です。
- **サニタイザは冪等であること**（`Sanitize(Sanitize(x)) == Sanitize(x)`）。
  冪等（べきとう）は、何度かけても結果が変わらないことです。
- ⚠ **保存時は、除去結果をエディタへエコーバックして、利用者に通知すること。**
  エコーバックは、取り除いたあとの結果を、送り返すことです。
  黙って消すと、書いたものが消えたことに気づけません。

### 「タグは寛容・属性は厳格」

HTML は、要素（タグ）と、要素に付ける属性でできています。
要素は広く許し、属性は厳しく絞ります。

| | 方針 |
|---|---|
| **要素** | 構造HTML（h1〜h6・リスト・ルビ・表・`details`・`video`/`audio`）は**広く許可** |
| | `script`/`style`/`iframe`/`form` 系は**部分木ごと削除** |
| **属性** | `on*`・`style`・`class` は**常に拒否**。`data-*` は、決まったものだけを許す（`data-id`・`data-type`・`data-ref`・`data-src`・`data-mirror`） |
| | **`id` は書ける**（ページ内のリンクのため）。ただし**殻が独占する接頭辞 `w-` は剥がす**——殻の部品と同じ名前にならないので、殻の乗っ取り（`getElementById`・CSS・`window` の名前）が起きない |

表の言葉を説明します。

- 「部分木ごと削除」は、その要素を、中身ごと取り除くことです。
- 「殻」は、本文のまわりにある、画面の部品（ヘッダーやレールなど）のことです。
- 「殻の乗っ取り」は、本文の要素が、殻の部品と同じ名前を名乗って、殻の部品になりすますことです。

表のほかに、次の決まりがあります。

- **`input`・`button`・`select` も、削除対象です**（入力欄の偽装）。
  **本文に偽のログインフォームを書ける穴**を塞ぐためです。
- ⚠ **だから、チェックボックスは本文に書けません**（[【要求】タグと表.md](【要求】タグと表.md) §10）。
- **`data-type` は、属性名だけを、要素限定で許可します。値は検査しません。**
  要素限定は、決まった要素にだけ許すことです。
- **レジストリは、編集支援と検証の語彙です。安全性の門ではありません。**
  レジストリは、語彙の登録簿のことです。
  この分離があるから、将来、レジストリを実行時に（サーバーを動かしたまま）編集できるようにしても、危険な要素は増えません。

### URLの規則

| どこ | 許す形 |
|---|---|
| リンク（`href`・`cite`） | 相対・http・https・mailto・tel |
| **埋め込み**（`img src` 等） | ⚠ **`/data/` 配下ときれいなURLに限る** |

リンクは、押すと移る先です。埋め込みは、画像のように、ページを開いただけで読み込まれるものです。

⚠ **リンクは制限していないので、クロームがリンクから埋め込みを導出するときは、形を必ず検査すること。**
クロームは、保存しない、画面の飾り付けのことです。導出は、リンクをもとに埋め込みを作り出すことです。

### そのほか

#### CSP

CSP（Content-Security-Policy）は、「このページでは何を動かし、何を読み込んでよいか」を、サーバーがブラウザに伝える仕組みです。

- **CSP を、全レスポンス（すべての応答）へ付与すること。**
- **CSP は strict であること。**
  strict は、`'unsafe-inline'` なしの、厳しい版です。
  インライン（ページの中に直接書いたもの）の `script`/`style`/`on*=` を許しません。

⚠ **いま**: 後戻りは、`internal/auth/csp_test.go` が見張ります。

#### CSRF

CSRF は、ほかのサイトから、ログイン中の人に勝手な操作をさせる攻撃です。

- **CSRF は、Origin/Referer とリクエストホストの一致検証で防ぐこと**（GET/HEAD/OPTIONS 以外）。
  - Origin と Referer は、「この要求は、どのサイトのページから出たか」を、ブラウザが添える情報（ヘッダ）です。
  - リクエストホストは、要求の宛先のサイトです。この2つが一致することを確かめます。
  - GET/HEAD/OPTIONS は、要求の種類の名前です。この3つは、検証の対象から外します。
- **ヘッダが無ければ、拒否すること**（フェイルクローズ。迷ったら閉じる側に倒す考え方です）。

#### HTML を組み立てるとき

保存型 XSS は、保存された文書に仕込まれたスクリプトが、それを開いたほかの人の画面で動く攻撃です。
次の2つは、それを防ぐ決まりです。

- ⚠ **フロントの DOM 生成は、`createElement`＋`textContent` で行うこと。**
  **値を文字列連結して `innerHTML` へ入れないこと。**
  - フロントは、ブラウザで動く画面の側のことです。DOM は、ブラウザが持っている、ページの部品の組み立てです。
  - `escapeAttr` 頼みの保存型 XSS が、**実際に発火した過去があります**。
- ⚠ **サニタイズ後に HTML を足すもの（殻・公開ページの殻・鏡・拡張の鏡）は、自前でエスケープ責任を負います。**
  **破れると、保存型 XSS です。**
  - エスケープは、`<` などの記号を、HTML として働かない文字に置き換えることです。
  - 鏡は、本文には印だけを置いて、中身はサーバーが表示のたびに描く部分のことです。

  ⚠ **いま**:

  - 殻は、`RenderPageShell`・`RenderPublicShell` です。
  - 本文の後処理は、`RenderComputedViews`・`RenderAnchors`・`RenderReferenceLinks` です。
    `RenderComputedViews` は、鏡の配送です。拡張の鏡も、ここから呼ばれます。

#### HTTPS

- **本番は、TLS/HTTPS が必須です**（リバースプロキシで終端）。
  TLS/HTTPS は、通信を暗号にする仕組みです。終端は、暗号を解く役目を、そこで受け持つことです。
- ⚠ **Secure Cookie の無効化は、ローカル検証のときだけです。**

### 本文の安全（入れる場所の案: §5）

15. **本文に書ける文字は、「表示」以上の力を持ちません**（不変条件）。
    不変条件は、いつでも成り立っていなければならない決まりです。次のどれも、起こせないこと。
    - スクリプト
    - 外部への通信（画像1枚も含みます）
    - アプリの口を叩く
    - 画面を覆う
    - 入力欄を偽装する
    - 他人の権限で読む

    いちばん大きな相手は、「本文を書ける全利用者」です（コピペ1回で事故になります）。
    - 出どころ: セキュリティ設計.md:21-33・39-49
    - 入れる場所の案: §5 の冒頭

16. **三枚重ね。**
    サニタイズ・配信ヘッダ・CSP は、独立した層です。どれか1枚が破れても、止まること。
    - サニタイズは、CSP の代わりになりません（偽のログイン欄・`dialog`・`id` の乗っ取りは、CSP では止まりません）。逆も同じです。
    - 本文に `style=` を通す例外を作りません（作れば、`style-src` を緩めることになります）。
    - 出どころ: セキュリティ設計.md:53-63・本文サニタイズ設計.md:3-10・36-39・65-70・381-385

17. **保存と描画のほかに、本文の取得（`/api/load`）と、版の取り出し・書き戻しも、サニタイズを通します。無検査で正本へ書く入口を作りません。**
    発端は、`id="w-…"` で殻の要素を乗っ取れたことです。
    - 出どころ: 本文サニタイズ設計.md:45-63・セキュリティ設計.md:190（2026-08-20）

    - 入れる場所の案: CSRF の行
    - ⚠ いま: 実装済みです（`method_guard_test.go`・`route_guard_test.go`）。

20. **未知の要素は、アンラップします。**
    アンラップは、要素は捨て、子と文字は残すことです。知らないタグで、本文が消えません。
