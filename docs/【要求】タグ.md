# 【要求】タグ

**可変タグ**——本文に書く `<dl data-type="tags">` の「名前：値」——の要求仕様です。

> **書くのは利用者**、**矛盾を指摘するのがエージェント**（開発方針 §2）。
> 本書は **2026-09-23 に、散らばっていた6つの文書からエージェントが抜き出したもの**です
> ——⚠ **利用者が読んで直すための下書き**であって、まだ利用者の言葉になっていません。
>
> **タグは w-cms の土台です。** 業務データの大半はここに入り（索引の84%）、
> 横断検索・計算ビュー・参照リンクはすべてタグを起点にします。
> ⚠ **それなのに 2026-09-23 まで、まとまった文書がありませんでした**——
> 【考察】語彙モデル・アーキテクチャ §9・【考察】タグ表と業務ブロック表の分離・
> 【考察】テキストの正規化・【一覧】語彙 §4・作業引き継ぎの罠 に散っていて、
> **どれが現行でどれが経緯か**が読む人に分かりませんでした。

## この文書の読み方

⚠ **2種類のことが書いてあります。混ぜないでください。**

| 印 | 何か | 直す人 |
|---|---|---|
| （印なし） | **要求**——こうあってほしい・こういう決まりにする | **利用者** |
| ⚠ **いま** | **現状**——実装がいまこうなっている（事実） | エージェント |

**要求を変えたら、実装が追随します。** ⚠ **現状のほうを勝手に要求として読まないこと**
——「いまこうだから、こうあるべき」ではありません。

**なぜそうなったか**（決定の経緯）は 【考察】 が正本です。本書には**結論だけ**書きます。

## 1. 形

```html
<dl data-type="tags">
  <dt>仕入先</dt><dd>みなと商店</dd>
  <dt>発注日</dt><dd>2026-09-23</dd>
  <dt>発注担当</dt><dd>000031-a1b2</dd>
</dl>
```

- **本文に書きます。** 本文が正本で、DBは派生です。
- **1ページに何枚でも**、**同じ名前を何個でも**置けます（`メールアドレス` が代表例——
  1つの連絡先ページに窓口・担当・共有アドレスが並びます）。
- ⚠ **`data-type="tags"` の無い素の `dl` は、索引に入りません**（2026-09-18 決定
  「素の定義リストは DBから外しましょう」）。見た目は同じなので、**書いたのに検索に
  掛からない**という気づきにくい形になります。
- ⚠ **参照として読むのも、このタグの中だけ**です。素の `dl` まで見ると、
  発注書番号 `250401-203` が「6桁-英数字」に当てはまって**参照に化けます**。

### 空欄の形

⚠ **サニタイズは空の `<dd>` に `<br>` を入れます**——`<dd><br/></dd>`。
`<dd>([^<]*)</dd>` だけで探すと**空欄を素通り**します（2026-09-11 に `客先` を3枚
取りこぼしました）。読み書きは `replaceFirstFieldValue` を通すこと（`<br>` も空と扱う）。

## 2. 型は**名前**で決まる

> 2026-09-06 ユーザー決定:「名前が『受信元』であれば値は『参照』」

⚠ **`data-type` で型を明示する案は採りませんでした。** コピペで型が落ち、
**100ページに同じ属性を書く**ことになるためです。

**正本は [config/settings.json](../config/settings.json) の `vocabulary`**:

```json
"vocabulary": {
  "単価":   { "type": "number" },
  "発注日": { "type": "date" },
  "受信元": { "type": "ref" },
  "状態":   { "type": "enum", "values": ["未着手", "加工中", "納品済"] }
}
```

- ⚠ **Goコードに既定値はありません。** 設定が壊れていると**起動を止めます**
  ——黙って既定値で上書きすると、運用者が足した語が消えるためです（仕様）。
- ⚠ **語を足したらDB再構築**（`POST /api/rebuild-db`。再起動は不要）。
  忘れると**索引に載らないまま**で、エラーは出ません。
- **設定はGit管理**なので、語を足せば `git pull` で全環境へ届きます。
- ⚠ **名前が型を決める＝システム全体でひとつ**です。`発注済` を `bool` にしたら、
  **どのページのどのタグも** `bool`。揺れないのが利点ですが、
  **場所によって意味を変えることはできません**。

### 型の一覧（9種）

| 型 | 何を表すか | 畳み方（`norm_value`） |
|---|---|---|
| `text` | 自由文 | 全角英数・半角カナ・直径記号を畳む。⚠ **長音には触らない** |
| `code` | 番号・記号（図面番号・品番・発注書番号） | `text` に加えて**空白・ハイフン類・長音・大小**も畳む |
| `number` | 数 | 数として格納（⚠ 文字列にしない。§4） |
| `date` | 日付 | ISO（`2026-09-23`） |
| `datetime` | 日時 | ISO |
| `enum` | 決まった選択肢 | `text` と同じ（2026-09-14 に畳んだ） |
| `image` | 画像 | — |
| `ref` | **他のページ／ブロックを指す**（`ページID-ブロックID`） | — |
| `email` | `名前 <アドレス>` | **アドレスだけ** |

⚠ **`text` と `code` の違いは畳む強さだけ**です。`レーザー` は `text` ならそのまま、
`code` なら `レ-ザ-` になります——**機械が書く名前に `NormalizeCode` を使わないこと**。

### 引き方

| 口 | 何で引くか |
|---|---|
| `PagesByTag` | **生の値**で完全一致 |
| `PagesByTagLoose` | **畳んだ値**で一致（大小・全角・区切りの揺れを越える） |

⚠ **2段にせず、呼ぶ側が選びます。** 畳んだ文字列だけを返す口（`NormalizeForLookup`）は
2026-09-15 に撤去しました——`norm_value` が宣言型を持たなくなった日から、
**文字列で引くと `number` のタグがエラーにならず0件**になるためです。

## 4. ⚠ `norm_value` は宣言型を持たない——型は**値**が持つ

> 2026-09-15 ユーザー:「norm_value は文字列、数値、時刻のような種類が考えられます」

SQLite は**宣言の無い列で、値ごとの格納クラスを保ちます**。`TEXT` と宣言すると
数まで文字列に化け、**`"8000" < "900"`** になります（実測）:

| 宣言 | 並び |
|---|---|
| `TEXT` | `12.5, 8000.0, 900.0, abc` ⚠ |
| **宣言なし** | `12.5, 900, 8000, abc` ✓ |

混ざっても平気なのは ①並びが格納クラスのグループ順で範囲が重ならない
②問いは必ず `name` で絞り、**名前が型を決める**ためです。

⚠ **代償は「型を取り違えると、エラーにならず0件」。** だから**束ねる形を
`tagNormBind` の1か所**に閉じ、**書き手（`insertVocabEntry`）と読み手
（`PagesByTagLoose`）が同じ関数を通ります**。
⚠ **範囲で引く口を足すときも、同じ関数を通すこと。**
⚠ 整数は整数の格納クラスへ（`REAL` だと `3` が `3.0` になります）。

番人は [page_tags_norm_type_test.go](../internal/cms/page_tags_norm_type_test.go)。

### ⚠ 畳めなかったタグは、並べると先頭・絞ると消える

`最短納期` は `date` として畳めないので `norm_value` は **NULL** です（生の値は正本として残る）。

| 書き方 | `最短納期` の行 |
|---|---|
| `ORDER BY norm_value` | **先頭に来る**（SQLite は NULL を最小として並べる） |
| `WHERE norm_value <= ?` | **黙って消える**（NULL の比較は偽） |

**正反対の振る舞いが同じ列から出ます。** ⚠ **納期・受注残のビューを作るときは
`norm_value IS NOT NULL` を明示し、畳めなかった値を別枠で必ず見せること**——
黙って落とすと「納期が書いてあるのに一覧に出ない」になります。

## 5. 揺れを畳む

| 何を | どこで | 規則 |
|---|---|---|
| 全角英数・半角カナ | `NormalizeText` | NFKC |
| **直径記号** | 設定 `char_folding` | `Φ ϕ ⌀ Ø ø Ф ф` → `φ`。⚠ **NFKC では畳めません**（別系統の文字）。⚠ **足したらDB再構築** |
| 機械が書き起こす**名前** | `NormalizeNameForIngest` | 書く**時点**で NFKC（顧客名・装置名称・図面名称・図面番号・発注書番号・品名など） |
| 社名の法人格 | `cms.FoldCompanyName`＋`contacts.OrgNameForPage` | 設定 `company_forms` |

⚠ **機械が書く名前に `NormalizeCode` を使わないこと**——`レーザー` が `レ-ザ-` になります。
⚠ **メールの件名には掛けません**（届いたままが正本）。

⚠ **社名を書く口は4つあり、揃っていないと意味がありません**——解析が書く `発注元`・`客先`／
受注の整理／加工製品の整理／連絡帳の登録の初期値。1つでも生の名前を書くと
`株式会社○○` のページが生まれ、**完全一致で結ぶ2つの木が黙って結ばれません**。

## 6. 参照タグ（`ref`）

値は **`ページID-ブロックID`**（例 `000031-a1b2`）。

- **表示のとき**にリンクになります（`ref_render.go`。本文は書き換えません）。
- **宙ぶらりん**（指す先が無い）は**薄赤**で出ます。
- ⚠ **飛ぶ先は常に本文のブロック**（`#<data-id>`）です。添付そのものを指す経路はありません
  ——だから**添付の識別子もブロックIDと同じ4桁**（ファイル名＝URL＝`data-id` の3役）。
- ⚠ **指し先は「消えないもの」にすること。** 図面ブロックは人が消せるので、
  社内コードは**改訂履歴の行や構成部品の行**を指します。
- ⚠ **型が `ref` であることが、リンクにする唯一の条件**です。値の形だけでは参照と番号を
  見分けません（2026-09-04 の事故の教訓）。⚠ 2026-09-21 に `資料` 列が `text` のままで
  **押して飛べなかった**のは、これを忘れていたためです。
- ⚠ **表のセルの参照は、まだリンクになりません**（`ref_render.go` はタグの `dl` だけ）。

## 7. 書くときの決まり

- **項目の鍵は見出しの表示文字**（`<dt>` の文字）。機械キーを本文へ書く属性はありません。
- ⚠ **見た目の印は本文に保存できません**——`class` はサニタイズで落ちます。
  宙ぶらりんの薄赤のように、**表示時に付ける鏡型**で作ります。
- ⚠ **機械が既存ページのタグを書き換えるときは関門が要ります**。`RewriteBody` は
  読んで・変えて・書くので、エディタが開いているとオートセーブと黙って上書きし合います。
  使うのは `editlock.RefuseWhileEditing`（1ページ）か `editlock.Locks.EditorOpen`（まとめ押し）。
  ⚠ `RequireEditLock` は**使えません**（一覧画面のボタンはトークンを持てず必ず409）。
- ⚠ **空欄の意味を決めつけないこと。** 出荷済み・単価の空は「まだ分からない」で、
  `0` を埋めると**人が入れた `0` と見分けが付きません**。
- ⚠ **`/api/load` の出力を `/api/save` へ書き戻さないこと。** `/api/load` は鏡を埋めて
  返し、落とすシリアライザは**ブラウザの `app.js`** です。外から書き戻すと鏡が本文に
  焼き込まれます（2026-09-21 に6枚焼きました）。いまは `cms.StripChrome` が
  **`Sanitize`／`SanitizeReport` の冒頭**で落とします——⚠ **順序がこの守りの全部**です
  （サニタイズは `class` を落とすので、後では印が残っていません）。

## 10. `bool` 型（2026-09-23 決定）

> ユーザー:「発注書ページに『発注済』というタグを足したい…**タグにチェックボックスを
> 使うことは可能ですか？**」「**data-typeがBOOLのタグはチェックボックスを出す**という
> 取り決めはどうですか？」「**BOOL型があると入力が楽です**」（2026-09-23・**足すことは決定**）

### できること・できないこと

⚠ **チェックボックスは本文に保存できません。** サニタイザが `input`・`button`・`select` を
**部分木ごと消します**（本文に偽のログインフォームを書ける穴を塞ぐため。
[本文サニタイズ設計.md](本文サニタイズ設計.md)）。

**実体はこうなります**——既に3つ動いている形と同じです:

```
本文に入るもの … 「済」という文字だけ
画面に出るもの … チェックボックス（サーバーが表示のときに足す鏡）
押したとき     … 本文の文字を「済」⇄「空」に書き換える
```

⚠ **いまは `enum` で偽装しています**——`材料発注`・`納品書発行`・`請求書発行` は
**選択肢が1つしかない `enum`**（`済` だけ）で、チェックボックスは画面側で
**フィールド名を3回手書き**しています（`checkFieldHTML`）。`bool` があれば
**宣言がそのまま画面になり**、列を足したときに画面を直し忘れる形が構造的に消えます。

### ⚠ 決めるべきこと——チェックは2状態、データは3状態

```
はい  ／  いいえ  ／  まだ誰も見ていない
              ↑ 外したチェックボックスでは、この2つを見分けられません
```

| タグ | 外れたチェックの意味 | |
|---|---|---|
| `発注済`・`材料発注` | まだ出していない | 問題なし（同じ意味） |
| `検査合格` | ⚠ **不合格なのか、まだ検査していないのか** | 区別できない |

**提案する取り決め**:

> **`bool` は「印」である。** 値は `済` か**空**の2つで、**空は「まだ」**を意味する。
> ⚠ **「いいえ」を積極的に記録したいときは `bool` を使わず `enum`**（`合格`／`不合格`／空）。

### 足すのに要るもの

1. `internal/cms/vocab.go` の `validColumnTypes` に `bool` を1つ
   ——⚠ **ここを足さないと、設定に `bool` と書いた瞬間に起動が止まります**
2. `config/settings.json` の `vocabulary` に `"発注済": { "type": "bool" }`
3. ⚠ **DB再構築**
4. **タグの鏡**（`<dl>` の中にチェックボックスを出す）——⚠ **新しい経路です**。
   いまのチェックボックスは全部**計算ビューの中**にあり、**本文のタグの鏡**はまだ
   ありません。閲覧モードと編集モードの両方で押せる必要があります。

⚠ **`bool` を足すことと、「発注書ページに `発注済` タグを持つか」は別の話**です。
行から数えれば分かることをタグで二重に持つと、**1行取り消したときにタグが嘘をつきます**
（[【要求】発注フォルダ.md](【要求】発注フォルダ.md) の「発注済の印」）。

## 11. ⚠ タグには「鏡」がありません（2026-09-23）

> ユーザー:「**ENUM型のタグは、リストで選択できますか？列挙する値は、設定できますか？**」

**答えは半分ずつです。**

| 問い | 答え |
|---|---|
| **値を設定できるか** | ✓ **できます**。`config/settings.json` に `{"type": "enum", "values": [...]}` |
| **リストで選べるか** | ⚠ **タグでは選べません**（**表のセルでは選べます**） |

```json
"在籍":   { "type": "enum", "values": ["在籍", "休職", "出向", "退社"] },
"移行中": { "type": "enum", "values": ["確認待ち"] }
```

### ⚠ いま、タグの値に起きること

- ✓ 値が `values` に**在れば** `tag-known`、**無ければ** `tag-unlisted` の印が付きます（色で示す）。
- ✗ ⚠ **候補のボタンは出ません。** 候補メニューは **`#w-editor-content table td`** に
  束ねられていて、**表のセルだけ**が対象です。
- ⚠ **空欄には印を付けません**——「まだ書いていない」は間違いではないからです。

**つまり、タグでは「打ち間違えたら色で分かる」だけ**です。

### ⚠ これは `enum` だけの話ではありません

**同じ `enum` 型なのに、表とタグで振る舞いが違います。**

| | 表のセル | タグの値 |
|---|---|---|
| `enum` の候補 | ✓ ボタンが出る | ⚠ **出ない**（色だけ） |
| `image` の「画像を選ぶ」 | ✓ 出る | ⚠ **出ない** |
| `bool` のチェックボックス（§10） | （足せる） | ⚠ **出ない** |
| `ref` のリンク | ✓ 出る | ✓ 出る |

⚠ **要求: タグの値にも、型に応じた入力補助を出すこと。**
表と同じ理屈です——**打つより選ぶほうが速く、速ければ揃います**。

⚠ **これを1つ作れば、`enum` の候補・`bool` のチェックボックス・`image` の選択が
まとめて片付きます。** いま3つとも同じ理由（**タグの鏡がない**）で出ていません。

### ⚠ 候補は縛りではありません

⚠ **採らずに手で打てること。** 揃うのは採ったときだけで、**手打ちは止められません**
——それでも意味があるのは**打つより選ぶほうが速い**からです。
`tag-unlisted` の印は「**間違い**」ではなく「**一覧に無い**」を意味します。
