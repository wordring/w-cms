# 用語集

w-cms の業務ドメインで使う中核語彙を定義する。設計・実装・ドキュメント・コミットメッセージで**用語を統一**するための正本。

> 方針メモ:
> - **「発注書」という裸の語は視点で意味が変わり曖昧**（顧客が出す発注書＝こちらは受け取る側）。視点に依らない**役割語**で呼ぶ。
> - 受け取る側／出す側の対は、標準的で曖昧のない **`受注` ／ `発注`** を採用する（`注文` 案は実在の「注文書」に根ざすが、`受注` の教科書的対義語である `発注` を選んだ。2026-06-27 決定）。
> - 見積の2種は、取引の性質で **`販売見積` ／ `購入見積`** とする（`売上/原価見積` 案は「原価見積＝社内原価積算」と紛れるため避けた。2026-06-27 決定）。
> - 「状態」欄が **実装済み** の語は現行コードに対応がある。**設計中** の語は [メール取り込み（emlのページ化）.md](メール取り込み（emlのページ化）.md) 等で検討中で未実装。

---

## 1. 受発注・取引の中核

| 用語 | 意味 | 実装・状態 |
|---|---|---|
| **受注** | **顧客から届いた発注書**（こちらが受け取る側）。売上側。 | 実装済み：`client_orders` ／ `<m-file tag="顧客の発注書">`（呼称は順次 `受注` へ統一） |
| **発注** | **加工業者・材料屋へ送る発注書**（こちらが出す側）。仕入側。 | 実装済み：`our_orders` ／ `<m-file tag="弊社の発注書">`（呼称は順次 `発注` へ統一） |
| **同時受注** | **同時に届いた複数の受注の束**（1通のメール／同日受信などの塊）。複数の受注を束ねる**参照ハブ**の一種。 | 設計中（[受信記録メモ §4.3](メール取り込み（emlのページ化）.md) のグルーピング軸の一つ） |
| **案件** | 受注・発注・部材・見積を突き合わせる**業務単位（ジョブ）**。「1文書＝1ページ」採用後は、文書ページを `<m-quote>` で束ねる**参照ハブページ**として表す。 | 設計中（[受信記録メモ §2.5](メール取り込み（emlのページ化）.md)）。現行は `page_id` 単位の集計 |
| **販売見積** | 弊社が顧客へ提示する見積（売上予定）。確定すると**受注**になる。 | 実装済み：`our_estimates` ／ `<m-file tag="弊社の見積もり">`（呼称は順次 `販売見積` へ統一） |
| **購入見積** | 仕入先（材料屋・加工業者）が弊社へ提示する見積（原価予定）。確定すると**発注**になる。 | 実装済み：`supplier_estimates` ／ `<m-file tag="材料屋・加工業者の見積もり">`（呼称は順次 `購入見積` へ統一） |

**受発注の2×2（予定→確定）**:

| 段階 | 売上側（顧客と） | 原価側（仕入先と） |
|---|---|---|
| 予定（見積） | **販売見積** | **購入見積** |
| 確定（発注書類） | **受注** | **発注** |

```
販売見積 ─(確定)→ 受注      （顧客と・売上側）
購入見積 ─(確定)→ 発注      （仕入先と・原価側）
```

## 2. ものづくりの対象

| 用語 | 意味 | 実装・状態 |
|---|---|---|
| **部品** | 製造・加工の対象。`item_id`（製品コード／図面番号）で識別。 | 実装済み：`<m-item item-id="...">`、`<m-tag name="部品番号">`（[原価と利益 §1](ユースケース_原価と利益.md)） |
| **図面** | 部品の仕様図（PDF/画像/DWG等）。部品とは**多対多**（1図面で1部品／1部品が複数図面）。 | 設計中（[受信記録メモ §4.2](メール取り込み（emlのページ化）.md)）。現状は資料添付 |
| **部材** | 1部品あたりに必要な材料。 | 実装済み：`part_materials` ／ `<m-material>` |

## 3. 納品・進捗

| 用語 | 意味 | 実装・状態 |
|---|---|---|
| **納品** | 受注に対して品物を納めるイベント（◯月◯日に N 個）。 | 設計中（[受信記録メモ §4.3](メール取り込み（emlのページ化）.md)） |
| **分納** | 1つの受注を**複数回に分けて納品**すること。充足は `受注数 − Σ納品済数 = 残` で集計。 | 設計中 |
| **進捗（status）** | 部品ごとの状態。現行は単一enum（未着手/加工中/検査中/納品済）。分納対応で数量ベース化を検討。 | 実装済み（enum）：`<m-item status="...">`。数量ベース化は設計中 |

## 4. 受信記録まわり（設計中）

| 用語 | 意味 |
|---|---|
| **受信記録** | メール・FAX・電話で外部から届いた受信の記録（`<m-message channel="email/fax/phone">`）。 |
| **受信箱（intake）ページ** | 取り込みの着地ページ。ここへ `.eml` 等をドロップ／フォーム入力し、未確認ページが生える（[§3.2](メール取り込み（emlのページ化）.md)）。 |
| **文書ページ** | 1発注書／1図面／1見積など**1文書＝1ページ**の原本＋構造化データ（[§2.5](メール取り込み（emlのページ化）.md)）。 |
| **参照ハブ（案件／同時受注 等）ページ** | 文書ページを `<m-quote>` で引用して束ね、集計する側のページ（[§2.5・§4.4](メール取り込み（emlのページ化）.md)）。 |

## 5. 基盤概念（既存・参照）

| 用語 | 意味 | 出典 |
|---|---|---|
| **正本性** | `data/master` のファイル群が唯一の正データ。DB（`cms.db`）は再生成可能な派生インデックス。 | [アーキテクチャ §8](アーキテクチャとDBスキーマ.md) |
| **受信原本** | 受信したまま改変しない証跡（生 `.eml`／スキャン元）。`.eml` は添付を内包する完全アーカイブ。 | [受信記録メモ §9.1](メール取り込み（emlのページ化）.md) |
| **自己完結性** | 各文書ページが業務用の実ファイルを自分のフォルダに所有し、単体で意味が保てること。 | [受信記録メモ §9.1](メール取り込み（emlのページ化）.md) |
| **サイドカー** | ページの属性（親ID・所有/権限・作成/更新情報）を持つ `<id>.meta.json`（正本）。本文HTMLは「内容」。 | [アーキテクチャ §2](アーキテクチャとDBスキーマ.md)・[エディタ仕様 §9](エディタ仕様.md) |
| **プラグイン** | 1ユースケース＝1ファイル（`internal/cms/plugin_*.go`）。タグ→テーブルの同期を自己登録する。 | [プラグイン開発ガイド.md](プラグイン開発ガイド.md) |

> 既存ドキュメント・コード（`client_orders`／`顧客の発注書` 等）の呼称は、[受信記録メモ §2.5・§4.5](メール取り込み（emlのページ化）.md) の実装時にこの用語へ揃える。タグ値・テーブル名のリネームはその段階でまとめて行う。
