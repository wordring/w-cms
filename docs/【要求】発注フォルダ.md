# 【要求】発注フォルダ

## 発注フォルダページの項目
- 必要部材
- 未発注の発注書
- 発注部材表

各項目には見出しを付けて、ハッキリとセクションを分けましょう。

### 必要部材
DBから受注残を調べて、受注残部品の弊社品番と一致するページIDに基づき、部材DBから必要部材を集積します。
その必要部材を表にして表示します。

| 選 | 納期 | 客先 | 装置 | 弊社品番 | 購入品 | 残 | 参考単価 |
|--|--|--|--|--|--|--|--|
||2026-10-15|みなと商店|オールラウンド|000080|鉄 FB t4.5*75*1090|2|860円|

- 選のセルにはチェックボックスが入ります。

表の下には、発注部材表を作るため項があります。
チェックした部材をどの表に入れるか設定するためのリストボックスと発注部材表に入れるボタンがあります。
リストボックスには、新しく作る「新規」とN番目の発注部材表に追加することを示す「N番目に追加」という項目があります。
「N番目に追加」は既存の発注部材表の数だけ項目が出来ます。
ボタンを押すと「新規」なら発注部材表ができ、「N番目に追加」ならN番目の発注部材表にチェックした部材が追加されます。
発注部材表に入った部材は必要部材表から消えます。

### 未発注の発注書

ここには未だ発注されていない発注書ページへのリンクを表示します。
DBを検索して「発注済」タグがFALSEの発注書ページが該当します。
作業者はここを見て残りの作業を進めます。
発注書ページを削除するとリンクも消えます。

### タグ

タグは次のとおりです。

| タグ | 型 | 実装 | 備考 |
|---|---|---|---|

| 発注日 | date | あり | 発注書を送信した日付 |
| 発注担当 | ref | あり | 連絡帳の担当者ページ。 |
| 希望納期 | date |  |  |

### 納品日と納期は別のもの（2026-09-23 ユーザー）

> 「**納品日は実際に納品される日、納期は顧客から提示される予定**です。」

| 語 | 何を表すか | 性質 |
|---|---|---|
| **納期** | **予定**——顧客から提示されるもの | 約束。**守る側の目標** |
| **納品日** | **事実**——実際に納品される日 | 起きたこと |

⚠ **予定と事実を同じ欄に書かないこと。** 混ぜると、**遅れたのか予定どおりだったのか**が
後から分かりません。

⚠ **決めていただきたいことが3つ残ります。**

**① `納品日` の置き場がありません。** 上の表から外れているので、**どこに書くか**が未定です。
⚠ **ページのタグには置けません——分納があります**
（ユーザー:「一つの加工製品が**複数の納品に分かれる**場合もある」）。1枚の発注書に
納品日が**何個も**付きます。

| 候補 | |
|---|---|
| **発注明細の行** | 行ごとに1つ。⚠ **同じ行が2回に分かれると、まだ足りません** |
| **納品書ページ**（`納品／年／月`） | ⚠ **紙が原本、明細は鏡**——見積・発注・請求と**同じ形**になります |

⚠ **筆者は納品書ページを推します**——「**紙のページが原本、明細は鏡**」は、既に4回
採ってきた形だからです（[【考察】製造という軸.md](【考察】製造という軸.md) §7i）。

**② `希望納期` が `date` だと、実物の書き方が入りません。** 実物7枚の「希望納期」欄は
**自由文**でした——「急ぎでお願いします」「納期わかりましたらお知らせください。」。
⚠ **日付型に入れられません。** 別の欄（自由文）を足すか、備考へ寄せるかの判断が要ります。
⚠ **`date` のまま自由文を書くと、索引では畳めず NULL になり、
「並べると先頭・絞ると消える」**という形になります（[【要求】タグ.md](【要求】タグ.md) §4）。

**③ ⚠ `発注日` を「送信した日付」にすると、置き場とずれます。**
⚠ **いまは発注書ページを作ったときに書き、`発注／年／月` の年月もその日付で決まります**
——**9月に作って10月に送ると、10月の発注書が9月のフォルダに入ります**。
**送った日に書き換えて、置き場も動かす**のか、**作った日（`作成日`）と送った日
（`発注日`）を分ける**のかを決めてください。

### 発注明細

部材の種類によって発注明細に必要な項目は変わりますが、表はすべての項目の集合となります。
PDFを作成するときに空の項目を消すことで、部材の種類にあった発注書PDFが作成されます。

| 列 | 型 | 材料 | 加工 | 塗装 | 鍍金 |
|---|---|:--:|:--:|:--:|:--:|
| 弊社品番 | ref | ○ | ○ | ○ | ○ |
| 品番 | code | | ○ | ○ | ○ |
| 品名 | text | | ○ | ○ | ○ |
| 材質 | text | ○ | | | |
| 形状 | text | ○ | | | |
| 寸法 | text | ○ | | | |
| 表面 | text | | | ○ | ○ |
| 数量 | number | ○ | ○ | ○ | ○ |
| 単位 | enum | ○ | ○ | ○ | ○ |
| 単価 | number | ○ | ○ | ○ | ○ |
| 備考 | text | ○ | ○ | ○ | ○ |
| 状態 | enum | ○ | ○ | ○ | ○ |

- **材料の行に `品名` は書きません**。材料に単独の名前は無く、**材質・形状・寸法の3つで決まります**
  ——書くと同じことが紙の上で2回言われ、直すときに食い違います。⚠ **購入部品は逆**で、
  **品名が同一性そのもの**なので残します。
- **`弊社品番` は紙に出しません**。相手には意味が無く、**こちらが問い合わせを受けたときに引く番号**です。
- **`表面`** には色（`緑`、`半ツヤ黒`）・鍍金（`三価ユニクロ、タコメッキ`）・`生地` が入ります。
- **単価を書かない発注書があります**（実物の材料2枚は単価も合計も空欄）。
  ⚠ **`0` とは別**です——紙の `0` は「0円で発注した」の意味なので、**空欄のまま**にします。

### 発注済の印

**印は発注書の行ごと**に付きます（`状態` の列）。値は4つ:

| 値 | 意味 | 手配済みに数える | 買った値段に数える |
|---|---|:--:|:--:|
| 未発注 | 紙はできたが、まだ出していない | ○ | |
| 発注済 | 出した（メール・FAX・手渡し） | ○ | ○ |
| 納品済 | 届いた | ○ | ○ |
| 取消 | 取り消した | | |

- **ページの印にしないのは、1枚の紙の中でも行ごとに事情が違うから**です
  ——1品だけ取り消す、1品だけ先に納まる。
- **取り消すと、その部材は必要部材の表へ戻ります**（手配済みに数えないため）。
- 取消の重さは2通り。**発注前は単純に取り消し**、**発注後は相手の了解が要る**ので画面が確かめます。
### ページの `発注済` をどうするか（2026-09-23）

> ユーザー:「ページに発注済みタグを持つと**検索が楽になる**と思いますが、
> **発注後でも発注を取り消す場合がある**ので、その場合どうするかです。」

⚠ **困りごとは正確です。** 人が手で打つタグにすると:

```
タグ「発注済」を付ける  →  あとで1行だけ取り消す
                              ↓
                    行は「取消」、タグは「発注済」のまま
                    ⚠ タグが嘘をつく。しかも誰も気づかない
```

**筆者の案: ⚠ 本文には書かず、索引にだけ「導いたタグ」として入れる。**

| | どこに在るか | 誰が書くか | 取り消したら |
|---|---|---|---|
| 行の `状態` | **本文**（正本） | 人・機械 | 変わる |
| ページの `発注済` | ⚠ **索引だけ**（`page_tags`） | ⚠ **保存のたび機械が数え直す** | **自動で変わる** |

- **検索は楽になります**——タグなので `PagesByTag` で引けます。
- ⚠ **嘘をつけません。** 本文が変われば保存時に必ず数え直され、DB再構築でも同じ値が出ます。
- ⚠ **「DBにはファイルから再生成できないデータを持たせない」に違反しません**
  ——**本文から計算できる**ので、再構築で復元できます
  （[【要求】運用.md](【要求】運用.md) §1）。
- ⚠ **人は打てません。** 打てると二重持ちに戻るので、**編集画面には出しません**。

⚠ **「未発注の発注書」の節で、既に `bool` を選んでおられます**——
「DBを検索して**『発注済』タグがFALSE**の発注書ページが該当します」。
**それでよければ、値は `bool`（真／偽）です。**

⚠ **残るのは、`bool` では表せない2つをどう扱うかです:**

| 紙の状態 | `発注済` は？ |
|---|---|
| 全部まだ出していない | **偽** ✓ |
| 全部出した | **真** ✓ |
| ⚠ **一部だけ出した** | ⚠ **真か偽か**——偽にすると「未発注の発注書」に**出したものが並びます** |
| ⚠ **全部取り消した** | ⚠ **真でも偽でもありません**——偽にすると、**もう用のない紙が作業一覧に残り続けます** |

⚠ **「一部だけ出した」は実際に起こります**——行ごとに印を付けられる作りにしたからです
（1品だけ先に納まる・1品だけ取り消す）。

**3値にすれば両方とも表せます**（`未発注` / `一部発注済` / `発注済`、取消だけの紙は `取消`）。
⚠ **ただし `bool` ではなくなります。** どちらを採るか決めてください。

## 発注書（紙・PDF）

**PDFを発行できることは必須**です。発注書はPDFで送付し、**保存します**。

保持年限は**設置した先で変わります**（2026-09-23 ユーザー:「個人が5年、法人が7年です。
**企業が過去に問題を起こしていた場合、最大10年**です」）——正本は
[【要求】ページとエディタ.md](【要求】ページとエディタ.md) §4。
⚠ **この会社は法人なので 7年**です。
⚠ **2026-09-23 に「5年で消す」をやめました**——既定では**消しません**。消すのは設定 `version_retention_years` に正の数を書いたときだけです。
（⚠ ただし**発注書のPDFは添付なので消えません**。消える恐れがあるのは本文の版です。）

実物7枚（`w-cms用見本`）と、いま w-cms が出す紙を比べて出た差です。

| | 実物 | いまの w-cms |
|---|---|---|
| 差出人ブロック（社名・部署・住所・担当・TEL・FAX） | 右上にある | `発注担当` の署名から出す。⚠ **連絡帳に署名が無いと空** |
| 合計金額（税抜） | **表の上と下の2箇所** | ⚠ **下だけ** |
| 希望納期 | **自由文**（「急ぎでお願いします」「納期わかりましたらお知らせください。」） | ⚠ `納期` は**日付型**なので、**この書き方が入りません** |
| 納品場所 | 全7枚にある | ⚠ **書いていません** |
| 明細のグループ見出し行 | **装置名だけの行**（`装置A用`・`共通台座用`）が明細に挟まる | ⚠ **ありません** |
| 「下記の通り、発注いたします。」 | ある | ⚠ ありません |
| 発注書No. | **全7枚とも空欄** | ページ番号が入る |

⚠ **字はFAXで読める大きさにします。** G3 FAX の標準モードは**縦 98dpi しかなく**、
9pt の和文は画数の多い漢字（`鋼`・`鍍`・`厚`）が塗り潰れます。
いまは**中身を測って、入る中でいちばん大きい字**（最大12pt）で組み、入らなければ
**字を下げる前に折り返し**ます。⚠ **実機のFAXではまだ確かめていません。**

## 発注書を送る

発注書ページで**送信方法を選んで**送ります。

| 方法 | 送り方 | 発注済みの印 |
|---|---|---|
| メール | 宛先・件名・本文を確かめて送信（PDFを添付） | **自動**（送信の成功がその事実） |
| FAX | ⚠ **FAXサーバーはまだありません**——当面は人が送って、押します | **人が押す** |
| 手渡し・郵送 | 印刷して渡す | **人が押す** |

- 宛先は `仕入先` の題で連絡帳を引いた**候補**です。⚠ **当たらないことが正常**
  （新しい仕入先の1通目）なので、そのときは黙らずにそう言って、人が打ちます。
- メールの控えは**通信箱**に残ります。
- ⚠ **将来要件: 作ったPDFをワンタッチで業者へFAXする。** FAX＋APサーバー用の機械は
  2026-09-17 に購入済み（モデムは未購入）。同じ機械にモデムを繋ぎ、通信記録とも接続します。
