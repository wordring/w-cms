# 【要求】添付

**ページにファイルを添えること**の要求仕様です。

> **書くのは利用者**、**矛盾を指摘するのがエージェント**（開発方針 §2）。
> 本書は **2026-09-23 に [要件定義書.md](旧文書/要件定義書.md) の §2.6 から抜き出したもの**です
> ——⚠ **利用者が読んで直すための下書き**です。

⚠ **2種類のことが書いてあります。** （印なし）＝**要求**（利用者が直す）、
⚠ **いま**＝**実装の現状**（エージェントが直す）。

---

## 1. 何を添えられるか

| 種類 | 入口 | 配信 |
|---|---|---|
| **PDF** | ドロップ／ファイル選択 | **インライン表示** |
| **画像**（png・jpeg・webp・gif・svg） | ドロップ／選択／**カメラ撮影** | **インライン表示**（⚠ SVGは別扱い・§3） |
| **その他**（CAD・Office・ZIP など） | 本文へのドロップ | **ダウンロード扱い** |

⚠ **いま**（2026-09-30）: 入口は3つで、どれも同じ処理を通ります——**書式の帯の 🖼（画像だけ）・📎（何でも）**、
スラッシュメニューの「🖼 画像」「📎 ファイル」、本文へのドロップ。入る場所は**キャレット（落とした所）のすぐ後ろ**で、
節・折りたたみの中なら中のまま。**画像は本文の中の絵**（`<img>`）、**それ以外（PDF・CAD・Office など）はファイル表示**
（PDF は開く枠・描けない形式は開く案内）で入ります（利用者:「イメージと添付ファイルは扱いが違って当然ですね」）。
写真はマウスを載せると右上に 📝（ローカルのアプリで編集）が出ます。節と折りたたみの末尾の「＋ ファイル」は
2026-09-30 にやめました（本文に見えるのに消せなかった）。

- 許す拡張子は**設定**で決めます（運用者が増やせる）。⚠ `.json` は書けません。
- ⚠ **添付は `files/` サブフォルダに置き、正本2ファイルと同居させないこと**
  ——**添付の名前が正本を上書きする穴が構造的に無くなります**。

## 2. 入口で守ること

- **リクエスト上限**（既定32MiB・設定で変えられる）
- **中身を見る**——PDF は先頭 `%PDF-`、ラスタ画像は**マジックナンバー**
  （⚠ **拡張子だけを信じないこと**）
- **ファイル名の正規化**——パス要素や制御文字を拒否、本文・サイドカーと同名を拒否
- ⚠ **名前の検査は全アップロード口が同じ関数を通ること。**
  ⚠ **外部へ送る側（AIへの送信など）も同じ関門を通すこと**——
  **置く側は守られ、送る側だけ素通し**という非対称が過去に実際にありました。

### ⚠ EXIF は保存時にサーバーで除去する

カメラ写真には**撮影位置（GPS）・撮影日時・機材**が埋まっていて、公開サイトに載ると
**撮影者の所在が漏れます**。

⚠ **除去はアップロード経路の一律処理**にすること——**公開時に選別する方式にしない**
（フェイルクローズ）。

⚠ **回転情報を捨てるなら、画素の向きを補正してから保存**すること（表示が横倒しにならない）。

⚠ **帰結**: 撮影日時・撮影場所を**業務データとして使う設計にはできません**。
必要ならアップロード受付時刻をサーバーが記録するか、利用者が表の `date` 列へ入力します。

## 3. SVG は「不活性な画像」として許す

SVG は**スクリプトを内包できる文書形式**です。中身の完全なサニタイズは行わず、
**埋め込み方と配信の二層で無害化**します。

| 層 | 何をするか |
|---|---|
| ① 埋め込み | 本文からの表示は **`<img src="x.svg">` 経由のみ**。⚠ **画像コンテキストではブラウザ仕様としてスクリプトが実行されません**。インライン `<svg>` はサニタイザが部分木ごと削除 |
| ② 配信 | `Content-Type: image/svg+xml` ＋ `Content-Disposition: attachment`（**直接開くと描画せずダウンロード**）＋このレスポンス限定の `Content-Security-Policy: sandbox; default-src 'none'` |
| ③ 入口 | well-formed XML でルートが `<svg>` か検査し、`<script>`・`<foreignObject>`・`on*=`・`javascript:` を含むものを拒否 |

⚠ **安全性の本体は②の配信側**で、③は多層防御の網です。
⚠ **代償として SVG 内の対話性は動きません**（ロゴ・図版の用途を想定）。

## 4. 配信

⚠ **静的配信ではなく、ページの read 権限を要求する保護ハンドラ**にすること。

- `nosniff` を付ける
- **許可種別以外はダウンロード扱い**
- ⚠ **本文とサイドカーは配信しない**

⚠ **「描ける形式」の表は、配信側の帰結であって独立した判断ではありません。**
配信が `inline` で返す形式（PDF・ラスタ画像・SVG）だけが、その場に描けます
——それ以外は「描ける」と宣言しても**ブラウザは描きません**。

## 5. 本文から開く

**`<section data-type="file-view" data-ref="ページID-添付ID">`** と書くと、
**サーバーがその添付を開く枠を足します**（鏡）。

- ⚠ **本文に在るのはマーカー1つだけ**です。中身はページを返すたびに描き、
  `.vocab-chrome` に包むので**保存されません**。
- ⚠ **`<embed>` を本文に書かせない**のがこの形の要点です。危ないのは要素そのものではなく
  **`src` を書いた人が宛先を決めること**——本文へ `<img src="/api/logout">` を1つ保存すると
  **全員が無音でログアウト**した、という事故が実際にありました。
  マーカー方式なら**書く人が選べるのはページIDと添付IDだけ**で、URLは機械が組みます。
- **PDF以外も開きます**（画像・動画・音声）。表に無い形式は**開く口（リンク）**を出します
  ——⚠ **「見つかりません」と言って黙るのは嘘**でした。ファイルは在るのですから。

## 6. 版と目録

- ⚠ **添付に版はありません。** 上書きすると前のものは戻せません
  （⚠ だから監査では**上書きを別の名前で記録**します）。
- ⚠ **WebDAV 経由の上書きだけは版が残ります**（`files/.versions/`）。
- **目録 `files/meta.json`** に、届いたときの名前・保存日時・利用者・大きさ・SHA-256・由来を
  残します。⚠ **本文のリンク文字は表示名、目録は届いた事実**——**正本は2つになりません**。

## 7. 未決・将来

| # | 何か |
|---|---|
| 1 | **保存した画像の編集**（回転・切り抜き・注記）。⚠ **添付に版が無い**ので、**別ファイル保存＝原本残置**が本命 |
| 2 | **SVG編集アプリ**——SVGが「閲覧する画像」から「編集対象の文書」になった時点で、**編集器の語彙への許可リストサニタイズ**へ拡張する。⚠ **「任意のSVGの完全な保全」は目標にしない** |
| 3 | **添付へのコンテキストメニュー**（OCR・編集）と **ZIP内ファイルの個別取り出し** |
| 4 | ⚠ **描けない形式のリンクに `download` 属性が無く、押すと保存名で落ちます**（画面には目録の表示名が出るのに）。足せば `.rpcd`・DXF・Excel・ZIP が一斉に正しい名前で落ちます |

## 8. ZIP の展開

⚠ **ZIP を展開するのは、受信原本が ZIP を持っている取り込みの経路だけ**です（どの経路かは
拡張の【要求】）。⚠ **人が手で落とした ZIP は展開しません。**

⚠ **展開の口を別の経路へ足すときは、同じ根拠が立つかを先に確かめること。**
上限は3つ（1件の大きさ・件数・合計）——ZIP爆弾対策です。
