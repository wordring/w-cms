# 【一覧】語彙

w-cms のページ本文（HTML）で使える**語彙**の実装済みリファレンス。何が書けるのか、どの形式がどのDBテーブルへ同期されるのかをまとめる。

> **分担**——**「いま何があるか」＝本ファイル**（形式の一覧・列・同期先。定義の実体は
> [internal/cms/vocab.go](../internal/cms/vocab.go) の `vocabRegistry`）。
> **「なぜその形か」＝[【考察】語彙モデル.md](【考察】語彙モデル.md)**（3層モデル・設計判断・決定ログ）。
> 安全性の規則は [本文サニタイズ設計.md](本文サニタイズ設計.md) §5、計算プラグインの作り方は
> [【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md)、ユースケースは
> [【ユースケース】受注から利益まで.md](【ユースケース】受注から利益まで.md)。

> **このファイルは現行実装の鏡（手書き）**。`vocabRegistry` を増減したら本ファイルも更新すること。
> **カスタム要素（`<m-*>`）は全廃済み**（2026-08-20）。新しい語彙はレジストリへ宣言1件を足す（§5）。
> 設計中の未実装形式（納品レコード等）は本ファイルには載せない
> （[【考察】通信記録処理.md](【考察】通信記録処理.md) を参照）。通信記録ページと参照は新しい形式では
> なく**可変タグ**で表す（§4。参照の値は `ページID-ブロックID`・D-4）。

> **形式を決めるのは「見える言葉」です**（D-2・2026-08-30 決定／08-31 実装）。
> `<section><h2>表示名</h2>…</section>` と書けば、**その見出しの言葉が形式を宣言**します
> （解決は `vocabTypeOf`。表は `<caption>` が同じ役目）。エディタのスラッシュメニューも
> この形で挿し、本ファイルの表も**第1列が見える言葉**です。
> ⚠ **`data-type` は機械が数えるための副**（[コンセプト.md](コンセプト.md) §1②・2026-08-25）
> ——属性があれば属性が勝ちますが、**書かなくてよい**のが普通の形です。
> ⚠ **例外は可変タグ（`tags`）と、配線を属性に持つ形式**（`file-view` 等）——
> こちらは**属性が必須**です（§4・§2.3）。経緯は
> [【考察】語彙モデル.md](【考察】語彙モデル.md) §11。

## 1. 本文の語彙は3つの層でできている

**①語彙レジストリ／②汎用索引／③計算プラグインの3層モデルは
[【考察】語彙モデル.md](【考察】語彙モデル.md) §4 が正本**。本ファイルが写すのは①の中身（§2）と、
それが②③のどこへ流れるか（§3）。運用上おさえるのは次の2点。

- **安全性の門はサニタイザだけで、レジストリは関与しない**。`data-type` の**値は検査されない**ので、
  レジストリに無い値も保存を通り、②汎用索引にも載る（保存応答の `unknown_types` で告知するだけ。
  [【一覧】API.md](【一覧】API.md)）。レジストリが担うのは編集支援（スラッシュメニュー・挿入骨格・
  型検証）と、鍵・型を解決するための語彙だけ。
- **エディタは語彙を手書きで持たない**。要素リストも形式リストも `GET /api/tag-schema` から受け取る
  （応答は `elements` / `void` / `block_id` / `vocab` / `vocabulary` / `column_types` / `extensions` の7キー。
  `extensions` は載っている拡張の名簿で、画面が拡張のボタンを出し分けるのに使う——2026-09-15 追加。
  最後の `column_types` は `th[data-type]` に書ける列型の一覧で、**2026-09-14 に足した**
  ——それまでエディタが手書きで持っており、`datetime`・`ref`・`email` を足した日から
  **3つ古いまま**だった）。
  `assets/index.html` に手書きで残るスラッシュメニュー項目は `h1`（見出し）・`p`（段落）・画像（レジストリの
  形式ではなく添付＋`<img>` の挿入操作）の3つだけで、残りは `populateSlashMenuVocab` がレジストリから生成する。

### 1.1 `data-*` マーカーの許可範囲

**許可範囲（どの属性をどの要素へ許すか・値を検査するか）の正本は
[本文サニタイズ設計.md](本文サニタイズ設計.md) §5.4**（実装は
[internal/cms/htmldoc/sanitize.go](../internal/cms/htmldoc/sanitize.go)）。本文の語彙マーカーは
**`data-type`（型名）・`data-src`（出所アドレス）・`data-ref`（ファイル表示の配線・
2026-09-15 に追加。`section` 限定）の3つだけ**で、`data-id`（保存の単位）と
`id`（リンクの宛先）は全要素共通の別枠（この2つを分ける理由は
[【考察】語彙モデル.md](【考察】語彙モデル.md) §9）。語彙側の固有事情だけをここに書く。

- **`th[data-type]` だけは意味が違う**——形式名ではなく**列型**を明示する。使えるのは
  **9つ**（`validColumnTypes`・[vocab.go](../internal/cms/vocab.go)）: `text` / `code` /
  `number` / `date` / `datetime` / `enum` / `image` / `ref` / `email`。
  あとから足した3つ——`datetime`（時刻を含む日時。`date` は日付だけ）・`ref`（他ページや
  その中のブロックへの参照）・`email`（メールの相手。値は `名前 <アドレス>` で、
  畳んだ値がアドレスだけ）——は、**タグの型としても名前から決まります**（§4）。
- **列型の決定順序は `th` の `data-type` 明示 > レジストリ宣言 > 見出し語の辞書 > `text`**
  （サーバーは `vocab_index.go` の `resolveColumnType`、エディタは同じ辞書を `/api/tag-schema` の
  `vocabulary` で受け取るので、索引と画面の判定が食い違わない）。
  **辞書の正本は `config/settings.json` の `vocabulary`**（1語につき `{"type": …, "values": [...]}` の
  1件で、型と選択肢を一緒に持つ——2026-09-14 に `type_inference` と `tag_enums` の2つを畳んだ。
  **Goコードに既定値は無く、ファイルが唯一の正本**（2026-09-07）。運用者がファイルへ足して
  DB再構築すれば効く——2026-08-30）。
- **鍵（フィールド名）は見出しの表示文字**（`th` / `dt` のテキスト）ただ1つ。「見える文字がすべて」。
  ③計算形式では、その表示文字がレジストリ宣言の**ラベル**に一致することで機械キー
  （`Field`。§2.2）へ解決される。機械キーを本文へ書き出す `data-field` は 2026-08-20 に撤去した。

> **見出しを改名すると、その列は③計算プラグインに読まれなくなる**（部材手配計算などの
> 型付きテーブルへ入らない）。黙って止まらないよう、解決できなくなった列は保存応答の
> `unresolved_fields` で告知する（拒否はしない。[【一覧】API.md](【一覧】API.md)）。

### 2.2 列（`table` では見出し行の列、`dl` では項目。`section` は列を持たず `Items` の表が持つ）

**機械キー**はレジストリ内部の識別子で、本文には現れない（③計算プラグインが読む鍵）。
欄が「—」の形式は機械キーを持たず、見出しの表示文字がそのまま鍵になる。

補足：

- **数値は正規化して読む**。`¥8,000` や全角の `８０００` は `8000` として解釈される
  （`NormalizeValue`）。正規化値は**併記**であり、生テキストが常に正本。
- **`quantity` の空セルは 1** として扱う（手で書く表で「1個」をいちいち書かせないため）。
- **型の不一致は拒否せず赤印で通知するだけ**。「自由な記述をシステムが認識する」というコンセプトを
  壊さないため（[【考察】語彙モデル.md](【考察】語彙モデル.md) §5.1）。
- `date` 型は `YYYY-MM-DD` へ正規化する（`YYYY/M/D`・`YYYY年M月D日` も受ける）。
- **`text` と `code` は「畳む強さ」だけが違う**（2026-09-04・案2）。見た目も入力補助も同じで、
  索引の併記値（`norm_value`）の作り方が変わる:
  - `text` …… 軽く畳む（全角英数→半角・半角カナ→全角・濁点の合成・前後の空白）。
    **長音 `ー` には触らない**——`ひかりレーザー` を壊さないため。
  - `code` …… 強く畳む（軽い正規化＋空白の除去・ハイフン類/長音/`_`→`-`・英字は大文字）。
    図面番号・発注書番号のような**符牒**に付ける。**区切りの有無は畳まない**
    （`R520-M070` と `R520M070` は別扱い——別の部品を1つにしないため）。

  引くときは `PagesByTag`（生の完全一致）と `PagesByTagLoose`（畳んだ一致）を**呼ぶ側が選ぶ**。
  正本は [【考察】テキストの正規化.md](【考察】テキストの正規化.md)。
- **`enum` は `text` と同じに畳む**（2026-09-14）。それまでの不変条件は「enum は正規化しない」
  だったが、`在籍` のように「選択肢だけあって型が無い」ため text 扱いだった語が enum になると、
  **畳んだ値が黙って空になる**（索引の後退）ので改めた。中の空白は畳まない（それは `code` だけ）。
  正規化しない列型は `image` だけ。
- **`image` 列の入力補助**は、セルにキャレットを置くと出る「🖼 画像を選ぶ」ボタンと、セルへの画像ドロップ
  （どちらも `insertImageIntoCell`。`/api/upload-image` へ送って `<img>` を入れる。[【要求】添付.md](【要求】添付.md)）。

### 2.3 形式の外形（HTMLの実例）

**いまの形（2026-09-18 以降・1文書＝1ページ）**。ヘッダは**ページの可変タグ**、原本は `<details>` で
畳んだ**ファイル表示**と「読んだまま」の写し、明細は **`<caption>` で形式を名乗る表**。
🤖 解析が受注ページに書く形がこれです（[ext/subcon/analyze_pdf.go](../ext/subcon/analyze_pdf.go) の
`buildOrderPageHTML`）。並びは**原本（PDF）→ 読んだまま → 弊社の明細**＝確かさの順。

```html
<h1>250715-304 みなと商店</h1>
<dl data-type="tags">
  <dt>発注書番号</dt><dd>250715-304</dd>
  <dt>発注元</dt><dd>みなと商店</dd>
  <dt>発注日</dt><dd>2026-07-15</dd>
  <dt>納期</dt><dd>2026-08-20</dd>
  <dt>小計</dt><dd>80000</dd>
  <dt>消費税</dt><dd>8000</dd>
  <dt>合計金額</dt><dd>88000</dd>
  <dt>受信元</dt><dd>000042-c3p7</dd>
</dl>
<details><summary>顧客の発注書（PDF）</summary>
  <section data-type="file-view" data-ref="000042-c3p7"></section></details>
<details><summary>顧客の発注書（読んだまま）</summary><table>…</table></details>
<table data-type="client-order-items">
  <caption>受注明細</caption>
  <tbody>
    <tr><th>弊社品番</th><th>品番</th><th>品名</th><th>数量</th><th>単位</th><th>単価</th><th>納期</th><th>出荷済み</th><th>備考</th><th>状態</th></tr>
    <tr><td>000077</td><td>A100-B01-0051</td><td>留めブラケット</td><td>10</td><td>個</td><td>8000</td><td>2026-08-20</td><td></td><td></td><td>未着手</td></tr>
  </tbody>
</table>
```

- 形式の解決は ①`data-type` ②節の機能見出し ③表の `<caption>` の順で**1回だけ**（⚠ 節の見出しと
  caption が重なると索引が二重に入っていた・2026-09-21 修正）。
- 検算（`数量 × 単価 = 金額`／`Σ金額 = 小計`／`小計 + 消費税 = 合計`）の結果は明細の `<tfoot>` に
  **鏡**で出ます——本文には書きません。
- **登録された語彙だけが索引に入ります**（2026-09-20）。名乗らない表は `vocab_index` に載りません。

**機能見出し形**（D-2・2026-08-31 以降の**挿入の既定**。エディタの `buildVocabSkeleton` が
この形で挿します）。⚠ **`data-type` を書きません**——`section` の**最初の見出しの言葉**が
レジストリの表示名に一致すれば、それが形式です。

```html
<section>
  <h2>検査記録</h2>
  <table>
    <tbody>
      <tr><th>品番</th><th>判定</th><th>検査写真</th><th>検査日</th></tr>
      <tr><td>A100-B01-0051</td><td>合格</td><td></td><td>2026-08-17</td></tr>
    </tbody>
  </table>
</section>
```

- ⚠ **見出しの言葉が形式を決めます。** 改名すると**別の形式（または形式なし）になります**
  ——だから保存の応答が `unresolved_fields` で告知します（拒否はしません）。
- **素の `table` は明細として索引に入ります**（節が形式を持つとき）。
  ⚠ **素の `dl` は載りません**（2026-09-18）——ヘッダはページの**可変タグ**へ。
- 見出し語がレジストリに無ければ、**静かにただのセクション**です（告知なし
  ——普通の見出しへの誤検知を避けるため）。

**表だけを単独で置くとき**は `<caption>` で名乗ります（2026-09-20）。
⚠ **`<caption>` は人のためのキャプションでもあり、同時に形式の宣言**です。

```html
<table>
  <caption>材料</caption>
  <tbody>
    <tr><th>材質</th><th>形状</th><th>寸法</th><th>個数</th></tr>
    <tr><td>SS400</td><td>板</td><td>t3.2*100*200</td><td>2</td></tr>
  </tbody>
</table>
```

**可変タグだけは属性が要ります**（⚠ **見出しで名乗る場所が無く、素の `dl` と
見た目で区別が付かないため**）。

```html
<dl data-type="tags"><dt>発注元</dt><dd>みなと商店</dd><dt>部品番号</dt><dd>A100-B01-0051</dd></dl>
```

> ⚠ **古い本文には `data-type` の形が残っています**（2026-09-18 より前のもの）。
> **属性は読み続けるので壊れません**が、中に**ヘッダを素の `dl` で持つ**ものは
> **発注書番号・発注元・発注日が索引に入りません**——**タグへ書き直すこと**。
> ⚠ **`section data-type="file"` でPDFを包む形と、`client-order`／`our-order`／
> `our-estimate`／`supplier-estimate`／`drawing` の5形式は、レジストリから消えています。**

**計算ビュー**（表示専用）。本文に保存されるのは空のマーカーだけで、中身は
`view_render.go` がページを返すたびに `<div class="vocab-chrome">` として埋める
（仕組みは [アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 4.4）。

```html
<section data-type="child-list"></section>
<section data-type="required-materials"></section>
```

**ファイル表示**（鏡型。保存されるのは**マーカー1つだけ**で、枠はサーバーが**その下へ足す**
——計算ビューと違って中身を消さない）。**配線は属性 `data-ref`**（2026-09-15。それまでは
中に参照タグを1つ書かせ「最初の `dl` の最初の参照」を読んでいた）。

```html
<section data-type="file-view" data-ref="010272-c3p7"></section>
```

- **中に参照タグを書いても開かない**（`TestFileViewIgnoresInnerTags`）。旧い形のままの
  本文は、`data-ref` へ写すまで「参照がありません」と出る。
- 属性へ移した理由は3つ（[file_view.go](../internal/cms/file_view.go) 冒頭が正本）:
  ①解析が書く本文では、図面ブロックの `受信元`（＝届いた記録）と表示先の指定が
  **同じ値で2行**並んでいた ②タグの名前に意味が無く（`受信元` でも `あ` でも動く）
  読む人が配線を見分けられない ③「最初の1つ」なので2つ書くと2つ目が黙って無視される。
- 属性は**`section` に限って**サニタイザが通す（`structuralElements`。URLではないので
  `safeEmbedURL` は通さない——URLを組むのはサーバー側で、書く人が宛先を選べない性質は
  値の検査ではなくそこで守られる。[セキュリティ設計.md](セキュリティ設計.md) §4）。
- **列は持たない**（中に書くものが無いため）。スラッシュメニューから挿さるのは
  見出し形の `<section><h2>ファイル表示</h2></section>` だけで、参照は編集モードの
  **配線の札**（`button.fv-wire`）→ プロパティ欄 `#w-fv-popover` で入れる
  （[エディタ仕様.md](エディタ仕様.md) §7.5）。
  札が出るのは `data-type="file-view"` を持つブロックだけなので、**スラッシュメニューも
  属性形で挿します**（`usesHeadingForm` の例外。`tags`・`file` と同じ扱いで、理由も同じ
  ——**配線を属性に持つ形式は見出し形にしない**）。

## 3. 形式 → テーブルの早見

**テーブルは1つだけです**。D-1（硬いドメイン表の全廃・2026-08-31）で、形式ごとの
専用テーブル8つと所有プラグイン4本を削除しました。

**索引は2つの表です**（2026-09-13 ユーザー決定。それまでは `vocab_index` 1本でした）。

| テーブル | 由来する形式 | 担当 |
|---|---|---|
| **`page_tags`** | **可変タグだけ**（`dl[data-type="tags"]`）。列は `page_id / seq / name / value / norm_value` の5つで、**主鍵は `(page_id, seq)`**（`seq` は**ページ通し**の番号）。**`norm_value` だけ宣言型を持ちません**——型を値に持たせ、`number` のタグが辞書順（`"8000" < "900"`）に並ぶのを防ぐため（2026-09-15。束ねる形は `tagNormBind` が1か所で決める） | [vocab_index.go](../internal/cms/vocab_index.go) |
| `vocab_index` | **登録された語彙の表**——`table[data-type]`・`<caption>` で名乗った `table` に加え、形式を持つ `section`（`data-type` または機能見出し）の**素の `<table>`**（`data-type` を持たない。`section` の側から拾う）。⚠ **素の `<dl>` は 2026-09-18 から載らない**（ヘッダはタグへ）。**登録されていない形式は載らない**（2026-09-20——それまでは空の形式名で入っていた） | 〃 |

**振り分けは書き手1か所**（`insertVocabEntry`）なので、読む側は表を選ぶだけです——
分けた理由は「読む側で `data_type='tags'` を足す」規律が守られなかったことで、正本は
[【考察】タグ表と業務ブロック表の分離.md](【考察】タグ表と業務ブロック表の分離.md) §8。

`vocab_index` での区別は `data_type` 列です——明細は表自身の `data-type`（または `<caption>` の
表示名から解決した形式名）、素の表なら包む形式の `Items`（どちらも `client-order-items`）で載ります。
読む側の入口は [vocab_query.go](../internal/cms/vocab_query.go) の4つ——`VocabTableRowsOf`・
`VocabBlocksOf`（どちらも `vocab_index`）と `PagesByTag`・`PagesByTagLoose`（どちらも
`page_tags`。生の完全一致か、畳んだ一致かを**呼ぶ側が選ぶ**）。③計算（部材手配計算）は
この索引だけを読みます（[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md) §8）。

`file`・`file-view` と **View** の9形式（`child-list`・`required-materials`・`order-backlog`・
`unordered-items`・`material-search`・`unlinked-customers`・`unhandled-intake`・`unknown-contacts`）は
索引にも載りません（配線だけの容器・表示専用）。⚠ **移行中のページ**（`移行中` タグ・§4）は
索引には入りますが、**表引き（③計算）からは外れます**（在ることで止める・2026-09-21）。

**コアテーブルは `pages` と `page_perms` だけ**で、業務データは上の2つの索引に載ります
（[internal/database/sqlite.go](../internal/database/sqlite.go)）。

受発注のPDFパスは形式自身ではなく**祖先のファイル容器** `section[data-type="file"]` の
`data-src` にあります。**索引はしません**（配線＝属性であって表示される値ではなく、
読む者もいなかったため。D-1・2026-08-31）——本文には残るので情報は失われません。

## 4. 可変タグ（`dl[data-type="tags"]`）の既知の名前

## 5. 語彙の増やし方

**既定の増やし方は「レジストリへ宣言を1件足す」**。カスタム要素は作らない（§6）。

1. [internal/cms/vocab.go](../internal/cms/vocab.go) の `vocabRegistry` へ `VocabDef` を1件足す
   （`Type` は kebab-case・一意、`Element` は `table` / `dl` / `section` のいずれか）。
2. 再起動すると `GET /api/tag-schema` の `vocab` に現れ、**スラッシュメニューに自動で並ぶ**
   （`Hidden: true` なら並ばない）。挿入骨格・列型の検証・②汎用索引への同期もそのまま通る。
3. 本ファイル §2 の表を更新する——**手で写さず生成する**（2026-09-22 の手順: リポジトリ直下に
   使い捨ての `_vocabgen/main.go` を置き、`_ "w-cms/ext/comm"`・`ext/comm/contacts`・`ext/comm/mail`・
   `ext/subcon` を blank import して `cms.LoadSettings()` → `cms.VocabDefs()` を §2.1／§2.2 の行の形で
   印字し、貼り替えてからディレクトリを消す。設定の `settings.json` から足した形式も同じ口に出る）。
   ⚠ **第1列は `Icon + DisplayName`**（見える言葉）で、`Type` は第2列です——
   `VocabDefs()` は `Type` の abc 順に返すので、**§2.1 の並びに合わせて並べ替えてから貼ること**。
4. **Goのコードは1行も書かない**。集計API・型付きテーブル・取り込み変換のいずれかが要るときだけ
   ③計算プラグインを追加する（[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md) 冒頭の振り分け）。

> **サニタイザは変更不要**。`data-type` は許可済みの属性名で、**値は検査されない**ので、
> 新しい形式名を足しても許可リストに触る必要はない（`table` / `dl` / `section` / `th` を担い手にする限り）。
> 新しい**要素**や**属性**が要る場合だけ `structuralElements` を直す
> （[本文サニタイズ設計.md](本文サニタイズ設計.md) §5・§7）。

> **手書きの写経は件数が増えれば破綻する**。正本がレジストリという1テーブルへ集約されたので当面は
> 本ファイルが鏡でよいが、`vocab` からの自動生成は引き続き課題
> （[要件定義書.md](要件定義書.md)（移動先の案内）「語彙一覧の生成化」。経緯は [変更履歴.md](変更履歴.md)）。

## 6. 本文はすべて標準HTML

**本文に独自の要素は1つも無い**（到達は 2026-08-20）。語彙は**標準HTMLの担い手**
（`table` / `dl` / `section` / `th`）に `data-type` と**見出しの表示文字**で意味を載せる形だけです。
これは `vocabulary_test.go` の `TestNoCustomElementVocabulary` が固定していて、
`AllowedVocabulary()` にハイフンを含む要素名が現れたら落ちます。

許可リストに無い要素は**アンラップされます**（要素は捨てられ、中身のテキストは残る）。
つまり、どこかから独自要素の混じった本文が入ってきても、文字は失われません。

表示されない配線だった参照（`受信元`・`前版`）も、**見える名前：値の参照タグ**
（`<dt>受信元</dt><dd>000002-12</dd>`。値は `ページID-ブロックID`・D-4）で決着しました——
見える形のまま保存し、描画時にリンクへ合成します（§4・
[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) §9.1〜9.3）。
集計を参照で辿る「参照追従JOIN」（[【考察】通信記録処理.md](【考察】通信記録処理.md) §2.5）は未着手。

> **なぜこの形にしたか**——決定と理由の正本は [【考察】語彙モデル.md](【考察】語彙モデル.md) §9 の決定ログ、
> 移行の経緯（何がどう置き換わったか）は [変更履歴アーカイブ.md](変更履歴アーカイブ.md) 2026-08-17〜2026-08-20。
