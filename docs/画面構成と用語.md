# 画面構成と用語

画面の各部分の**呼び名と範囲**を定めます。会話・Issue・コミットメッセージで画面上の位置を指すとき、
ここの用語を使ってください。実装は [assets/index.html](../assets/index.html)、
挙動の詳細は [エディタ仕様.md](エディタ仕様.md) §9 が正本です。

> この文書は「どこの話をしているか」を一意にするためのものです。
> 「左のパネル」「サイドバー」「メニュー」のような曖昧な指し方を避けるために用意しました。

---

## 1. 全体レイアウト

```
┌─────────────────────────────────────────────────────────────────┐
│ ヘッダー  .header                                                │  ← クローム
│  タイトル領域 .title-area        モード切替 / ⚙管理 / ログアウト  │
├──────────┬──────────┬───────────────────────┬──────────────────┤
│          │          │                       │                  │
│ 左レール │ 目次レール│      文書             │   右レール       │
│ .rail    │ .rail    │   .doc-column         │   .rail          │
│ -left    │ -toc     │                       │   -right         │
│          │          │  ┌─────────────────┐  │                  │
│ ┌──────┐ │ ┌──────┐ │  │ #editor-content │  │  ┌────────────┐  │
│ │子ページ│ │ │ 目次 │ │  │  （本文＝正本） │  │  │ ページ情報 │  │
│ └──────┘ │ └──────┘ │  └─────────────────┘  │  └────────────┘  │
│          │          │  ┌─────────────────┐  │  ┌────────────┐  │
│ ＋子ページ│          │  │ HTMLプレビュー   │  │  │ 🔒 権限    │  │
│  を作成  │          │  │ #html-preview   │  │  └────────────┘  │
│          │          │  └─────────────────┘  │                  │
├──────────┴──────────┴───────────────────────┴──────────────────┤
│ フッター帯  .site-footer                                         │
└─────────────────────────────────────────────────────────────────┘
   ↑つまみ .rail-toggle                              つまみ↑
```

作業領域 `.work-area` は **flex の4カラム**（左レール｜目次レール｜文書｜右レール）です。
`@media (max-width: 760px)` では文書を1カラム全幅にし、レールは**ドロワー**になります。

## 2. 用語一覧

| 呼び名 | DOM | 範囲・役割 | 本文に保存 |
|---|---|---|---|
| **ヘッダー** | `<header class="header">` | 画面最上部の帯。ページ名、編集モードのスイッチ、⚙管理、ログアウト。スクロールで隠れる（headroom） | ✗ |
| **作業領域** | `.work-area` | ヘッダーとフッターに挟まれた本体。レールと文書を並べる器 | — |
| **レール** | `<aside class="rail …">` | 文書の左右に立つ縦長のパネルの**総称**。4本ではなく**3本**（左・目次・右） | ✗ |
| └ **左レール** | `.rail-left` | **ページ階層**に対する情報と操作。親ページへのリンク、子ページカード、「＋ 子ページを作成」 | ✗ |
| └ **目次レール** | `.rail-toc` | 本文の見出し（`h1`〜`h6`）から生成した目次 | ✗ |
| └ **右レール** | `.rail-right` | **このページ**に対する情報と操作。ページ情報カード、権限カード | ✗ |
| **カード** | `<section class="rail-card">` | レールの中の1区画。`<details>` で折りたためる。見出しは `<summary>` | ✗ |
| **つまみ** | `.rail-toggle` | 各レール脇に固定された開閉ボタン。レールを閉じても残る（`.rail-toggle-group` に束ねる） | ✗ |
| **文書** | `.doc-column` | 中央のカラム。本文とHTMLプレビューを縦に並べる | — |
| └ **本文** | `#editor-content` | **ページの内容そのもの**。ここだけがファイルへ保存される | **✓** |
| └ **HTMLプレビュー** | `#html-preview` | 保存される正本HTMLをそのまま映す読み取り専用テキストエリア | ✗ |
| **フッター帯** | `<footer class="site-footer">` | 画面最下部の帯。現状は「w-cms」の仮表示のみ | ✗ |
| **ドロワー** | （`.rail` の狭幅時の姿） | 狭い画面でレールが文書に重なって出入りする形態 | ✗ |

**クローム**＝本文以外のUI全般（ヘッダー・レール・カード・つまみ・フッター帯）を指す総称。
「クロームは保存されない」が本プロジェクトの一貫した原則です。

## 3. 本文の中の用語

本文（`#editor-content`）の中は、エディタが動的にラッパーを被せます。

| 呼び名 | DOM | 説明 |
|---|---|---|
| **ブロック** | `.editor-block` | 本文の最小単位。見出し・段落・表・業務文書ブロックそれぞれを包む |
| └ **ブロック操作** | `.block-controls` | ブロック左脇の「＋」とドラッグハンドル `⠿`。編集モードでホバー時に出る |
| └ **ブロック本体** | `.block-content` | 実際の要素（`<h1>`・`<p>`・`<section data-type="file">` 等）を入れる器 |
| **スラッシュメニュー** | `#slash-menu` | 空の段落で `/` を打つと出る挿入メニュー。**手書きは2項目のみ**（H1 見出し・P 段落）で、残りは語彙レジストリから動的生成（`Hidden` の明細表2形式を除く10項目） |
| **コンテキストツールバー** | `#context-toolbar` | ブロックにフォーカスすると上に浮く小さなバー（B/I/U、明細追加） |
| **表ツールバー** | `#table-toolbar` | `data-type` 付きの表のセルにキャレットがあると出る行・列操作（＋行/↑/↓/✕行・＋列/←/→/✕列/⚙） |
| **dlツールバー** | `#dl-toolbar` | `<dl data-type>` の項目にキャレットがあると出る項目操作（＋項目/＋値/↑/↓/✕項目） |
| **列設定ポップオーバ** | `#col-popover` | 表ツールバーの ⚙ で開く。列型の明示（`th` の `data-type`）＝属性側の編集口 |
| **選択肢メニュー** | `#enum-menu` | enum 列のセルにキャレットがあると出る、レジストリ宣言の選択肢一覧 |
| **トースト** | `#toast-host` の子 | 画面隅に出る一時的な通知（保存結果・ロック状態など） |
| **形式の枠** | `body[edit-mode] … [data-type]` | 編集モードだけに出る破線の枠。「**w-cms がこの要素を見る**」ことを示す（形式ブロック・ファイル容器・計算ビュー）。ページタイトルになる最初の `h1` にも同じ枠が出る（実行時クラス `is-page-title`。属性にしないのは位置で決まるため） |
| **語彙クローム** | `.vocab-chrome` | 本文の中に**混ざって見えるが保存されない**DOM。①計算ビューの中身（サーバー事前描画が埋める）②エンハンサが付ける付帯UI（PDFプレビュー・ドロップゾーン・AI明細解析ボタン）の2用途 |

`.editor-block` と `.block-content` は**エディタが挿す枠であって本文ではありません**。
保存時のシリアライザはこれらを剥がします（[エディタ仕様.md](エディタ仕様.md) 6.1.1）。
`.vocab-chrome` も同様に、シリアライザが読み飛ばすので正本HTMLには入りません
（本文に残るのは空のマーカー `<section data-type="child-list">` 等だけ）。

## 4. 表示モードによる差

| モード | 条件 | 見え方 |
|---|---|---|
| **閲覧モード** | 既定 | 本文は読み取り専用。ブロック操作・スラッシュメニューは出ない |
| **編集モード** | `body[edit-mode]` | 編集ロックを取得済み。本文が `contenteditable` になり、クロームの操作系が有効 |
| **匿名** | `body.anonymous` | 未ログインで実効公開ページを見ている状態。右レールと書き込み系UIはCSSごと隠れる |

**計算ビューはどのモードでも同じ**です。中身はサーバーがページを返すときに埋めるので、
閲覧モード・匿名でもJavaScriptなしで表が見えます（[view_render.go](../internal/cms/view_render.go)）。
編集モードでも中身は `contenteditable` になりません（エディタの持ち物ではないため）。
そのぶん**編集中の変化は自動反映されません**——子ページを作っても、子ページ一覧のビューに
現れるのは再読み込み後です（描画ロジックをGoとJSの2箇所に持たないための割り切り）。

## 5. スクリーンショットについて

本ファイルは現状**図（ASCIIレイアウト）と表**で構成しています。実画面のスクリーンショットに
吹き出し・枠の注釈を重ねた図を追加すると、より直感的になります（未着手）。
追加する場合は `docs/images/` を作ってそこへ置き、本文から相対リンクしてください。
