### その前のセッション: 「エディタ内変更操作のロック共有」など（`origin/main` 反映済み）

**「エディタ内の変更操作を編集ロックで直列化する共通化」「権限カードの編集モード限定」「busyトーストの改善」**を実装し
`origin/main` へプッシュ済み（コミット `2526992`/`f764855`/`23f59df`、その前に `f496b54`/`8b48ec3`、`23f59df` 以前に
`69b9d28` 系）。確定仕様は [エディタ仕様.md](エディタ仕様.md) 9.2・10章、[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 4.3、
経緯は [同時編集の競合対策（検討中）.md](同時編集の競合対策（検討中）.md) §9 決定ログ。

- **共通ゲート `RequireEditLock(w, r, id)`**（`internal/cms/lock_handler.go`）を新設。`X-Lock-Token` ヘッダ（無ければ
  `token` クエリ）を保存と同じ `pageLocks.Validate` で検証し、他者保持/失効なら **409**、ロック無しは許可（保存と
  同一規約）。`PagePermsHandler`(POST)・`PageChownHandler`・`SetParentAPIHandler` に適用。
  **今後エディタ内に増える操作（画像/PDF等のリソース保存・削除など）も同じゲートに乗せられる**のが狙い
  （管理画面＝ユーザー/グループ操作はページ単位でないため対象外、と整理済み）。
- **フロント共通ラッパ `lockedFetch(url, opts)`**: ロックトークンを `X-Lock-Token` に自動同梱し、409 を
  `handleLockLost`（退避＋閲覧復帰＋再読込）に集約。`savePerms`/`chownPage`/`applyParent` を移行。
  汎用CSSクラス **`.edit-only`/`.view-only`** を追加（`body[edit-mode]` で表示切替、将来の操作はクラス付与だけでよい）。
- **権限カード（右パネル）を編集モード限定に**: 従来は編集モードと無関係に常時 chmod/chgrp/chown 可能だったのを、
  親ページID編集と同じ方針に揃え、編集モードでのみ操作可能にした（`refreshPermsEditable()`）。
- **busyトーストの改善**: 「再試行」ボタン（手動）を撤去し「待機をやめる」（自動取得＋キャンセル）に変更。
  「編集を待っている人がいます」トーストは編集権喪失時に自動で消し、「編集権が他の人に移りました」トーストは
  10秒で自動消去するようにした。
- **テスト**: `TestEditLockVerification`（他者ロック中の chmod/chown/set-parent が409、保持者は成功）を追加。
  `go test ./...` 全パス。
- **検証**: 実サーバー（プレビュー）で誤トークン→409・正トークン→200・ロック無し→200・権限カードの
  表示切替（閲覧=読み取り専用／編集=操作可）をブラウザ実機で確認、コンソールエラー無し。

### その前のセッション: 「同時編集の競合対策 Phase 2（プッシュ通知＝SSE）」（`origin/main` 反映済み）

ポーリングを全廃し SSE へ移行。

- **SSE**: `GET /api/lock-events?id=&role=holder|waiter&token=`（`text/event-stream`）を新設。**presence は SSE 接続の有無で判定**（保持者切断で即明け渡し、待機者切断で猶予キャンセル）。`GET /api/lock-status`（ポーリング）は廃止。`POST /api/lock`（取得）・`/api/unlock`・`/api/lock/force` は維持。
- サーバー: `lock.go` を接続ベース presence ＋ broadcast へ刷新。猶予満了は `StartLockReaper`（1秒ティッカー、`main` から起動）で評価。`lock_test.go` を新APIへ書き換え。
- フロント: ポーリング関数を撤去し `EventSource`（`openHolderEvents`/`openWaiterEvents`/`closeLockEvents`）へ置換。`available` で待機者が自動入室、`lost` で保持者が閲覧復帰＋本文自動再読込（`reloadContent`）。ヘッダーの「編集権の移行まで約N分」表示は撤去（トーストと重複）。
- 検証: 単体テスト＋プレビュー実機で「A保持→B待機→A解放→**Bが available で自動入室**」「保持者の**強制明け渡し→lost→閲覧復帰＋本文再読込**」を確認（コンソールエラー無し）。さらに **異なる2ユーザー（admin / 新規bob）の2セッション実機検証も完了（2026-06-22）**: 一時dirで実サーバーを起動し別Cookieの2セッションで `POST /api/lock`・SSE `/api/lock-events`・`/api/unlock`・`/api/lock/force` を curl 駆動し、`holding`／`waiter`(grace 120s)／`busy`(holder=admin・same_user非true)／競合中取得の **423**／解放後の `available`／待機者の昇格取得／**presenceベース明け渡し**（保持者SSE切断＝接続猶予10秒経過後に reaper が `available`）／強制解除 **204** を全て確認。2分の猶予満了経路は `lock_test.go` が時間差し替えで担保。

直前の Phase 1（悲観ロック・純HTTP・採番原子化＝`reserveNewPageID`・WAL/busy_timeout 堅牢化）は本Phase 2の土台。保持者識別は「エディタ個体＝トークン」単位（同一ユーザー別タブも競合）、保存は `SaveAPIHandler` がトークン検証（他者保持/失効は409）。

### その前のセッション: 「ページ属性のサイドカー化」と「独立サイドパネル（Plan B）」（`origin/main` 反映済み）

- UNIXに倣い、ページの**属性**（親ページID・作成日時・作成者・更新日時・権限）を本文HTMLではなく
  **サイドカー `<id>.meta.json`（正本）**に保存。HTML本体は純粋な「内容」になった。
- 直前に入れていた `<m-page-info>`（HTML埋め込み方式）は撤去。ページ情報の表示・編集は、文書から
  分離した**独立サイドパネル `<aside class="rail">`**（クローム）へ集約。画面は2カラムグリッド＋
  コンテナクエリで狭いとき1カラムに畳む。
- 親ページIDの変更は `POST /api/set-parent`、属性取得は `GET /api/page-meta` を新設。保存API・新規作成APIは
  HTMLを内容のみ扱う形に簡素化（改竄復元ロジックが不要に）。
- 構造体 `PagePerms` → `PageMeta` に改名（別コミット）。一覧用の旧 `PageMeta` は `PageSummary`。
- さらに**左サイドパネル（子ページナビ、`/api/children`）**を追加して3ペイン化。左右レールは
  ページ操作バーのトグルで開閉でき、状態は **`localStorage`（`wcms.rails`）** に保存（全ページ共有・FOUC防止は
  `<head>` のインラインscript）。既定テンプレートからは本文の `<m-child-list>` を除去（コンポーネント自体は残置）。
- 左ナビの**親ページリンクを最上部**（カードの外）へ移動。重複していた**ヘッダーの「🔒 権限」ボタンを廃止**
  （権限は右パネルに常設のため）。

確定仕様は [エディタ仕様.md](エディタ仕様.md) 9章・[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 2・4・8章、

## 開発環境の再現（自宅などで再開する手順）

```bash
# 1. 最新を取得
git pull

# 2. 依存取得
go mod tidy

# 3. 初回のみ管理者を作成して起動（ローカルHTTP検証なので Secure Cookie 無効）
#    ローカル開発の管理者は user=admin / password=Admin に統一する（環境間で揃える）。
WCMS_ADMIN_USER=admin WCMS_ADMIN_PASSWORD='Admin' WCMS_SECURE_COOKIES=0 \
  go run cmd/w-cms/main.go
# 2回目以降は環境変数なしで go run cmd/w-cms/main.go
# → http://localhost:8080 （/login にリダイレクト。admin / Admin でログイン）

# 4. テスト
go test ./...
```

注意:
- **ローカル開発のログイン**: `admin` / `Admin`（このパスワードは**ローカル検証専用**。本番では使わないこと）。
- `data/`（`cms.db` と `master/`、`auth.db`）は `.gitignore` 対象でコミットされない。**環境ごとに独立**するため、
  別環境（自宅など）では初回起動時に上記の環境変数で管理者が新規作成される。`auth.db` は同期されないので、
  「家でログインできない」は data/ が無い＝初回の管理者未作成か、別パスワードで作成済みのいずれか。
- **既存 `data/auth.db` のパスワードを忘れた／揃えたいとき**は、サーバーを止めてから以下で再設定できる（admin を `Admin` に）:
  ```bash
  # 一時パッケージで internal/auth.SetPassword を呼ぶ（ルートに別の package main があるためサブdirで実行）
  mkdir -p _resetpw && cat > _resetpw/main.go <<'GO'
  package main
  import ("fmt"; "w-cms/internal/auth"; "w-cms/internal/database")
  func main(){ database.InitAuthDB(); defer database.AuthDB.Close()
    if err:=auth.SetPassword("admin","Admin"); err!=nil { fmt.Println(err); return }
    fmt.Println("admin のパスワードを Admin に再設定しました") }
  GO
  go run ./_resetpw && rm -rf _resetpw
  ```
- ローカル実行・プレビュー用に `.claude/launch.json`（`go run` 起動設定）を用意済み。
  プレビュー（http://localhost）でCookieが付くよう **`env: { "WCMS_SECURE_COOKIES": "0" }`** を設定してある。

## 残課題・次の作業候補（任意）

1. **`<aside>` サイドパネルの本レイアウト作り込み**: 現状はカードを縦に並べた素直な構成。表示の磨き込み
   （アイコン・余白・折りたたみ既定状態など）は後追いで可能。
2. **既存データの移行**: 旧 `<m-page-info>` 方式で作られたHTML（属性がHTML内にある）が実環境に存在する場合、
   サイドカーへ移す一度きりの移行が要る。本リポジトリの `data/` はローカル限定のため通常は不要。
   ローカル検証で作った旧テストページ（`000001` 等）が気になる場合は管理コンソールの「DB再構築」で整理可能。
3. **CSS変数のさらなる移行**: トップレベルとサイドパネルはトークン化済み。スラッシュメニュー・ブロック操作・
   スイッチ等のウィジェット内部配色は据え置き。段階的に移行可能。
4. **`updated_at` の表記ゆれ**: サイドカー由来は RFC3339、フォールバックは SQLite の `CURRENT_TIMESTAMP`。
   表示は `formatDateTime` が吸収するが、必要なら保存時に正規化を検討。
5. **同時編集の競合対策（Phase 1+2＋エディタ内操作の直列化まで実装完了・運用中。一部の設計判断のみ未決）**:
   旧来の last-write-wins による lost update は悲観ロック＋SSEで解消済み。さらに権限変更・所有者変更・
   親付け替えも本文保存と同じロックで直列化済み（共通ゲート `RequireEditLock`／フロント `lockedFetch`）。
   経緯メモは [同時編集の競合対策（検討中）.md](同時編集の競合対策（検討中）.md) §9 決定ログに集約。
   **残る未決**（§8「今後の再検討候補」参照）: 複数待機者の順序（FIFO 等）、任意の安全TTL、ロック多重化時の
   共有ストア化、将来の CRDT 化。いずれも現状の単一プロセス・揮発的ロックで運用上の支障は出ていない。
   将来エディタ内に画像/PDF等のリソース操作が増える際は、UIに `.edit-only`、送信に `lockedFetch`、
   サーバーに `RequireEditLock` を通すだけで同じロックに乗せられる（[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 4.3参照）。
