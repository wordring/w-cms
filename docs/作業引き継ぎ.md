## 直近のセッションでやったこと（完了済み・`origin/main` 反映済み）

**「匿名公開（ログイン不要の閲覧）」**を設計合意のうえ実装し、`origin/main` へプッシュ済み
（コミット `9ffc035` バックエンド＋テスト、`9b10823` フロント、`4c49176` ドキュメント）。
仕様の正本は [認証認可設計.md](認証認可設計.md) §10。

- **モデル**: mode（owner/group/other）は3桁のまま、ページごとに独立フラグ `public`（既定 false）を追加。
  匿名は read 専用（write 禁止）。4桁modeにしない理由は §10.1 参照。
- **パスゲート**: 実効公開 = 自分の public ∧ **先祖すべての public ∧ ルート(000000)の public** の AND
  （`EffectivePublic`。`internal/cms/perms.go`）。ルートを鎖に含む＝サイト全体のキルスイッチ。
  フラグは非破壊・可逆（親を非公開にしても子のフラグは書き換えない）。
- **認可**: `RequirePageReadOrPublic`（匿名でも実効公開なら read 可）を `/api/load`・`/data/` に適用。
  公開操作は `POST /api/page-perms` の `public`（owner/admin、編集ロック必須）。公開時は親が実効公開かを
  検証し不可なら 403（`parentIsPublishable`）。GET は `public`/`effective_public`/`can_publish`/`can_write` を返す。
- **ルーティング**: `OptionalAuth`（`internal/auth/middleware.go`）を新設し、ページ殻・`/api/load`・`/data/`・
  `/api/me` を匿名許容に。それ以外は従来どおり `RequireAuth`。`/api/me` は未認証で `{authenticated:false}`。
- **子作成の継承**: `group`/`mode` を親から継承（setgid 相当・常時オン）、`owner`=作成者、`public`=常に false。
- **フロント**（`assets/index.html`）: 匿名（`body.anonymous`）は編集クローム（レール・編集スイッチ・
  ログアウト/管理・HTMLソース・ヒント）を隠した**読み取り専用ビュー**＋「ログイン」導線。権限カードに
  **🌐 公開トグル**（owner/admin のみ・編集モード中のみ操作・実効状態をヒント表示）。`can_write` で
  編集権の無いユーザーから編集スイッチを隠す。
- 実機検証済み（匿名×非公開→401／公開後→200、公開トグルUI、親非公開での公開→403＋日本語メッセージ、
  キルスイッチ、group継承、匿名ビューのクローム非表示）。`go test ./...` 全パス（新規テスト3本追加）。

その前までのセッションでは、フッター帯追加（`5702c19`）、親なしページ作成のトップページ限定（`c1b5950`/`900412e`）、
ページ操作バー廃止とレール役割の明確化（`1519572` ほか）を実装・プッシュ済み。

## 現在の状態

- ブランチ `main`。`origin/main` まで全て反映済み（未コミット・未プッシュの変更なし）。`go test ./...` 全パス。
- 編集ロックは、本文保存に加え**権限変更・所有者変更・親付け替え・公開切替**まで `RequireEditLock`/`lockedFetch` で直列化済み。権限カードは編集モード限定。
- 親ページの扱い: 親なし（トップレベル）にできるのはトップページ（`000000`、初回起動時に自動生成）のみ。
- **匿名公開**: ページごとの `public` フラグ＋パスゲート（実効公開＝先祖すべての AND、ルート含む）で運用中。
  公開できるのは owner/admin。既定は非公開（フェイルクローズ）。仕様は [認証認可設計.md](認証認可設計.md) §10。
- ページ最下部に `.site-footer` 帯（仮表示「w-cms」）を追加済み。将来はリンクを並べる想定（未実装）。
- 注意: 当セッションのローカル検証で作った検証ページ（`000006` 等）が `data/` に残っている場合あり。
  git管理外のローカル限定なので影響なし。気になれば管理コンソールの「DB再構築」で整理可。

## 開発環境の再現（自宅などで再開する手順）

```bash
# 1. 最新を取得
git pull

# 2. 依存取得
go mod tidy

# 3. 初回のみ管理者を作成して起動（ローカルHTTP検証なので Secure Cookie 無効）
#    ローカル開発の管理者は user=admin / password=Admin に統一する（環境間で揃える）。
WCMS_ADMIN_USER=admin WCMS_ADMIN_PASSWORD='Admin' WCMS_SECURE_COOKIES=0 \
  go run cmd/w-cms/main.go
# 2回目以降は環境変数なしで go run cmd/w-cms/main.go
# → http://localhost:8080 （/login にリダイレクト。admin / Admin でログイン）

# 4. テスト
go test ./...
```

注意:
- **ローカル開発のログイン**: `admin` / `Admin`（このパスワードは**ローカル検証専用**。本番では使わないこと）。
- `data/`（`cms.db` と `master/`、`auth.db`）は `.gitignore` 対象でコミットされない。**環境ごとに独立**するため、
  別環境（自宅など）では初回起動時に上記の環境変数で管理者が新規作成される。`auth.db` は同期されないので、
  「家でログインできない」は data/ が無い＝初回の管理者未作成か、別パスワードで作成済みのいずれか。
- **既存 `data/auth.db` のパスワードを忘れた／揃えたいとき**は、サーバーを止めてから以下で再設定できる（admin を `Admin` に）:
  ```bash
  # 一時パッケージで internal/auth.SetPassword を呼ぶ（ルートに別の package main があるためサブdirで実行）
  mkdir -p _resetpw && cat > _resetpw/main.go <<'GO'
  package main
  import ("fmt"; "w-cms/internal/auth"; "w-cms/internal/database")
  func main(){ database.InitAuthDB(); defer database.AuthDB.Close()
    if err:=auth.SetPassword("admin","Admin"); err!=nil { fmt.Println(err); return }
    fmt.Println("admin のパスワードを Admin に再設定しました") }
  GO
  go run ./_resetpw && rm -rf _resetpw
  ```
- ローカル実行・プレビュー用に `.claude/launch.json`（`go run` 起動設定）を用意済み。
  プレビュー（http://localhost）でCookieが付くよう **`env: { "WCMS_SECURE_COOKIES": "0" }`** を設定してある。

## 残課題・次の作業候補（任意）

0. **画面構成の用語を画面画像つきで可視化**（ユーザー要望・予定）: ヘッダー／レール（左右の
   サイドパネル）／ドロワー／文書（doc-column）／カード等の**呼び名と範囲**を、実際のスクリーンショットに
   注釈（吹き出し・枠）を重ねた図で示すドキュメントを用意する。置き場所は `docs/`（例: `画面構成と用語.md`）。
   既存の用語定義は [エディタ仕様.md](エディタ仕様.md) 9.1（3ペイン表）にあるので、それと突き合わせて図示する。
1. **`<aside>` サイドパネルの本レイアウト作り込み**: 現状はカードを縦に並べた素直な構成。表示の磨き込み
   （アイコン・余白・折りたたみ既定状態など）は後追いで可能。
2. **既存データの移行**: 旧 `<m-page-info>` 方式で作られたHTML（属性がHTML内にある）が実環境に存在する場合、
   サイドカーへ移す一度きりの移行が要る。本リポジトリの `data/` はローカル限定のため通常は不要。
   ローカル検証で作った旧テストページ（`000001` 等）が気になる場合は管理コンソールの「DB再構築」で整理可能。
3. **CSS変数のさらなる移行**: トップレベルとサイドパネルはトークン化済み。スラッシュメニュー・ブロック操作・
   スイッチ等のウィジェット内部配色は据え置き。段階的に移行可能。
4. **`updated_at` の表記ゆれ**: サイドカー由来は RFC3339、フォールバックは SQLite の `CURRENT_TIMESTAMP`。
   表示は `formatDateTime` が吸収するが、必要なら保存時に正規化を検討。
5. **同時編集の競合対策（Phase 1+2＋エディタ内操作の直列化まで実装完了・運用中。一部の設計判断のみ未決）**:
   旧来の last-write-wins による lost update は悲観ロック＋SSEで解消済み。さらに権限変更・所有者変更・
   親付け替えも本文保存と同じロックで直列化済み（共通ゲート `RequireEditLock`／フロント `lockedFetch`）。
   経緯メモは [同時編集の競合対策（検討中）.md](同時編集の競合対策（検討中）.md) §9 決定ログに集約。
   **残る未決**（§8「今後の再検討候補」参照）: 複数待機者の順序（FIFO 等）、任意の安全TTL、ロック多重化時の
   共有ストア化、将来の CRDT 化。いずれも現状の単一プロセス・揮発的ロックで運用上の支障は出ていない。
   将来エディタ内に画像/PDF等のリソース操作が増える際は、UIに `.edit-only`、送信に `lockedFetch`、
   サーバーに `RequireEditLock` を通すだけで同じロックに乗せられる（[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 4.3参照）。
6. **フッター帯（`.site-footer`）へのリンク追加**: 現状は仮表示「w-cms」のみ。よくあるウェブサイトのように
   利用規約・お問い合わせ等のリンクを並べる想定（ユーザー予告・未着手）。
7. **匿名公開の磨き込み（任意）**: 現状の匿名ビューは本文の読み取り専用表示まで。次の改善余地がある。
   - **公開ページの子ナビ・パンくず**: `/api/children`・`/api/page-meta` は要認証のままで、匿名ビューでは
     辿れない（公開された子だけを匿名に見せるなら、実効公開を条件にこれらを `OptionalAuth` 化する設計判断が要る）。
   - **公開ページ専用レンダリング**: いまは編集用テンプレートをCSSでクローム非表示にしている。SEO・OGP・
     キャッシュ等を本格対応するなら、軽量な公開専用ビューを別に用意する案もある。
   - 既定トップページ本文に残る「右上のスイッチで編集モード…」は匿名には不適。公開運用時は本文を整える。
