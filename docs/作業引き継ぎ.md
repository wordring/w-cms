### 前半：許可タグ・属性の拡張

本文で扱えるHTMLの語彙を広げ、**エディタとサニタイザを1つの宣言から導く**構造にした。
経緯は [【考察】許可タグと属性.md](【考察】許可タグと属性.md)、決定の正本は
[本文サニタイズ設計.md](本文サニタイズ設計.md) §5、まとめは
[変更履歴.md](変更履歴.md)（2026-08-04 の節）。

- **語彙の一元化**: `GET /api/tag-schema` が構造HTMLとカスタム要素の**両方**を返すようにし
  （`elements` / `void` / `block_id`）、エディタは手書きの `TEXT_BLOCK_TAGS` を捨てて
  DOMを辿る汎用シリアライザ（`serializeBlock` / `serializeNode`）に置き換えた。
  以後は `structuralElements` を直すだけでエディタが追随する。
- **許可リストの拡張**: `h1`〜`h6`・`dl`/`dt`/`dd`・ルビ・`section` 等・`details`/`summary`・
  `ins`/`del`・表の一族・`video`/`audio` などを追加（方針「タグは寛容・属性は厳格」）。
- **URL規則を2種類に分離**: リンク（`href`・`cite`）は外部可、埋め込み（`src`・`srcset`・`poster`）は
  **相対のみ**。あわせて**プロトコル相対URL `//host/…` が素通りしていた穴を塞いだ**。
- **`document.execCommand` を廃止**: Range 操作で常に `<strong>`/`<em>`/`<u>` を出す
  `toggleInlineFormat` に置き換え、`tidyInline` で空要素・入れ子・隣接・入れ子順序を正規化。

**着手前に判明していた要点**: サニタイザが許可していても、エディタのシリアライザが知らない
要素は**保存時に黙って捨てられる**（`h4`・`ul`・`table` が「画面に出るのに消える」状態だった）。
許可リストを広げる前に語彙の一元化が必要、という順序がこのセッションの肝。

**検証方法のメモ**: エディタ側のロジックは、`assets/index.html` から関数を名前で抜き出して
ハーネスHTMLを生成し、実ブラウザで動かして確認した（本体をコピペしないので実装と乖離しない）。
サーバー側はGoのテストで、**エディタの出力が無変更でサニタイザを通ること**まで含めて固定した。

- **カスタムタグはすべてプラグインが所有する**。`Plugin` の必須メソッド `Tags()` が語彙の唯一の
  正本で、サニタイズ許可リストと `/api/tag-schema`（エディタのシリアライザ）はそこから導かれる。
  コア（`sanitize.go`・`parser.go`）は `<m-*>` を一切知らず、コアテーブルは `pages`・`page_perms`
  だけ（`page_tags` も `plugin_page_tags.go` へ移設済み）。正本は
  [【一覧】カスタムタグ.md](【一覧】カスタムタグ.md) §1 と [【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md) §2。
- **`<m-file>` は純粋なファイル容器**（`src`/`name`/`ext`）。業務上の意味は中身の要素
  （`m-client-order`/`m-supplier-order`/`m-our-estimate`/`m-supplier-estimate`）が持ち、
  `tag` 文字列による分岐は全廃した。PDFのパスは `ClosestAttr` で容器から拾う。
  値を属性から中身へ移す転換（`m-field`/`m-table`）は §2.5 と合流させる予定で**未着手**。
- **`go test -race` が使える**（gcc 導入済み）。PATH に WinLibs の
  `~/AppData/Local/Microsoft/WinGet/Packages/BrechtSanders.WinLibs.POSIX.UCRT_*/mingw64/bin` を
  足し `CGO_ENABLED=1 go test -race ./...`。通常ビルドは Pure Go を保つため `CGO_ENABLED=0` のまま。
- **ページはサーバー合成方式**。`RootHandler` が `assets/index.html` の
  `<!--WCMS_CONTENT-->` へ本文を、`<title>` へページ名を埋め込んだ完成HTMLを返す
  （[shell.go](../internal/cms/shell.go) `RenderPageShell`）。初期表示で `/api/load` は叩かない
  （同APIは編集ロック起点の載せ替え専用として現存）。認可・404も画面側の作法でサーバーが返す
  （権限無し=403、匿名×非公開=`/login` へ302、不存在=404）。
- **本文で扱えるHTMLの語彙は「サーバーの1箇所」が正本**。`internal/cms/sanitize.go` の
  `structuralElements`（構造HTML）と各プラグインの `Tags()`（カスタム要素）を合成した結果が
  `GET /api/tag-schema`（`elements` / `void` / `block_id`）として返り、**エディタのシリアライザは
  それに従う**。エディタ側に手書きの要素リストは無い。方針は「**タグは寛容・属性は厳格**」で、
  `h1`〜`h6`・`dl`/`dt`/`dd`・ルビ・`section` 等・`details`・表の一族・`video`/`audio` まで許可。
  URLは**リンク（`href`・`cite`）が外部可／埋め込み（`src` 等）は相対のみ**。正本は
  [本文サニタイズ設計.md](本文サニタイズ設計.md) §5、経緯は [【考察】許可タグと属性.md](【考察】許可タグと属性.md)。
- **インライン装飾（太字・斜体・下線）は `document.execCommand` を使わない**。Range を直接
  操作して常に `<strong>`/`<em>`/`<u>` を出し、`tidyInline` が空要素・入れ子・隣接・入れ子順序を
  正規化する（[エディタ仕様.md](エディタ仕様.md) 4.1）。`Ctrl+B`/`I`/`U` も横取りする。
- **本文サニタイズは保存時・描画時の二層で実施済み**（許可リスト方式。
  [internal/cms/sanitize.go](../internal/cms/sanitize.go)、正本は
  [本文サニタイズ設計.md](本文サニタイズ設計.md)）。保存時はサニタイズ結果をエディタへ返し、
  除去が起きたブロックだけ差し替えて通知する（エコーバック方式）。
  無検査で正本へ書き込めた未使用の `/upload` は削除済み。
- **CSP（Content-Security-Policy）は中間版を全レスポンスへ付与済み**（`auth.CSPProtect`。
  `default-src 'self'; object-src 'self'; base-uri 'self'; frame-ancestors 'self'` は目標strictと同値、
  `script-src`/`style-src` のみ暫定で `'unsafe-inline'`）。strict 版（`'unsafe-inline'` なし）への
  格上げは前提リファクタ待ち。正本は [【考察】CSP強化.md](【考察】CSP強化.md)。
- **⚠ フロントでテンプレートへ値を差すときは必ず `escapeAttr` を通すこと**
  （[web-components.js](../assets/web-components.js) 冒頭）。テンプレートは文字列置換＋`innerHTML`
  なので、素通しすると値がHTMLとして解釈される。**サニタイザでもCSPでも止まらない**——
  `value` 等はURL属性でないので中身を検査されず、`'unsafe-inline'` はインラインイベントハンドラを
  許すため。2026-08-04 に実際に発火する保存型XSSとして修正済み。`escapeAttr` は
  二重引用符の属性値と本文テキストの両方で安全なので、迷ったらこちらを使う。

  ```bash
  # 既存ユーザーなら SetPassword、未作成なら CreateUser を使う。
  mkdir -p _resetpw && cat > _resetpw/main.go <<'GO'
  package main
  import ("fmt"; "w-cms/internal/auth"; "w-cms/internal/database")
  func main(){ database.InitAuthDB(); defer database.AuthDB.Close()
    if err := auth.SetPassword("a", "a"); err != nil {
      if err2 := auth.CreateUser("a", "a", true, ""); err2 != nil { fmt.Println(err, err2); return }
    }
    fmt.Println("ローカル管理者 a / a を用意しました") }
  GO
  go run ./_resetpw && rm -rf _resetpw
  ```
- ローカル実行・プレビュー用に `.claude/launch.json`（`go run` 起動設定）を用意済み。
  プレビュー（http://localhost）でCookieが付くよう **`env: { "WCMS_SECURE_COOKIES": "0" }`** を設定してある。

     ならない（`.` や `/` は `Atoi` を通らない）が、正本の名前が揺れる。ゼロ詰め6桁へ正規化すべき。
   - **`/assets/` にキャッシュ制御が無い**: ブラウザのヒューリスティックキャッシュが効くため、
     デプロイ後に古いフロント（`web-components.js`・テンプレート）が残りうる。検証時は
     ハードリロードが要る。長期的にはハッシュ付きURLか `Cache-Control` の指定を検討。
2. **既存データの移行**: 旧 `<m-page-info>` 方式で作られたHTML（属性がHTML内にある）が実環境に存在する場合、
   サイドカーへ移す一度きりの移行が要る。本リポジトリの `data/` はローカル限定のため通常は不要。
   ローカル検証で作った旧テストページ（`000001` 等）が気になる場合は管理コンソールの「DB再構築」で整理可能。
3. **CSS変数のさらなる移行**: トップレベルとサイドパネルはトークン化済み。スラッシュメニュー・ブロック操作・
   スイッチ等のウィジェット内部配色は据え置き。段階的に移行可能。
4. **`updated_at` の表記ゆれ**: サイドカー由来は RFC3339、フォールバックは SQLite の `CURRENT_TIMESTAMP`。
   表示は `formatDateTime` が吸収するが、必要なら保存時に正規化を検討。
5. **同時編集の競合対策（Phase 1+2＋エディタ内操作の直列化まで実装完了・運用中。一部の設計判断のみ未決）**:
   旧来の last-write-wins による lost update は悲観ロック＋SSEで解消済み。さらに権限変更・所有者変更・
   親付け替えも本文保存と同じロックで直列化済み（共通ゲート `RequireEditLock`／フロント `lockedFetch`）。
   経緯メモは [【考察】同時編集の競合対策.md](【考察】同時編集の競合対策.md) §9 決定ログに集約。
   **残る未決**（§8「今後の再検討候補」参照）: 複数待機者の順序（FIFO 等）、任意の安全TTL、ロック多重化時の
   共有ストア化、将来の CRDT 化。いずれも現状の単一プロセス・揮発的ロックで運用上の支障は出ていない。
   将来エディタ内に画像/PDF等のリソース操作が増える際は、UIに `.edit-only`、送信に `lockedFetch`、
   サーバーに `RequireEditLock` を通すだけで同じロックに乗せられる（[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 4.3参照）。
6. **フッター帯（`.site-footer`）へのリンク追加**: 現状は仮表示「w-cms」のみ。よくあるウェブサイトのように
   利用規約・お問い合わせ等のリンクを並べる想定（ユーザー予告・未着手）。
7. **匿名公開の磨き込み（~~任意~~ → 2026-08-16 に必須化。上の★へ移動）**: 一般公開のウェブサイトとしても
   使う前提になったため、以下は「任意の磨き込み」ではなく要件
   （[要件定義書.md](要件定義書.md) §4.4）。現状の匿名ビューは本文の読み取り専用表示＋子ナビ＋
   親ページへのリンク＋目次まで実装済み。
   - **子ナビ・パンくず（親への遡り）は実装済み**: `/api/children`・`/api/page-meta` を `OptionalAuth` 化し、
     匿名には実効公開（`EffectivePublic`）の子・親情報だけを絞って返す（[handler.go](../internal/cms/handler.go)
     `ChildPagesAPIHandler`・`PageMetaAPIHandler`）。フロントは左レールの子ページ一覧・親ページへのリンクを
     匿名にも表示（右レール・子ページ作成ボタン等の書き込み系は引き続き非表示。`body.anonymous` のCSS、
     [index.html](../assets/index.html)）。
