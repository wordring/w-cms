## いまここ: 語彙モデルへの移行が完了した

2026-08-16 に決めた「カスタム要素をやめ、マーカー付き標準HTMLへ移る」計画
（[【考察】語彙モデル.md](【考察】語彙モデル.md) §8.4）が、縦切り第1〜4段と最終掃除まで
**すべて完了**しました。到達点:

- **カスタム要素は0種**。本文は構造HTML＋`data-*` マーカーだけで、形式（`data-type`）の
  宣言は①語彙レジストリ [vocab.go](../internal/cms/vocab.go)（12形式）にデータとして載る。
  **新しい語彙はここへ1件足すのが既定**——エディタの挿入メニュー・索引・型検証まで自動で揃う。
  カスタム要素は**二度と作らない**（2026-08-17 決定）。
- **プラグインは計算ユースケースだけ**を持つ（`Name`/`Schema`/`Tables`/`Sync`＋任意の
  `RouteProvider`）。語彙宣言の機構（`Tags()`・`PluginTags()`・注入）は撤去済み。
- **計算ビュー**（子ページ一覧・手配集計）は空のマーカーを保存し、中身は
  [view_render.go](../internal/cms/view_render.go) が**サーバー事前描画**で埋める
  （`.vocab-chrome`＝保存されないクローム）。**閲覧はゼロJS**で完結する。
- **CSP は strict**（`'unsafe-inline'` なし）。インラインの script/style と `on*=` は
  リポジトリ全体でゼロ。後戻りは [csp_test.go](../internal/auth/csp_test.go) が検出。
- 両環境（職場・自宅）の実データは変換済みで、**一括変換ツールは撤去済み**。
  未変換の旧要素が後から出てきた場合はサニタイズでアンラップされる（テキストは残る）。
- **本文のマーカーは `data-type`（型名）と `data-src`（配線）の2つだけ**。同日に
  `data-field`（機械キー）を撤去し、**項目の鍵は見出し（`th`／`dt`）の表示文字ただ1つ**に
  なった。③計算プラグインが読む機械キーはレジストリ宣言（`Label`→`Field`）が解決する。
  改名で解決できなくなった列は保存時に `unresolved_fields` で告知される（拒否はしない）。
  あわせて **「w-cms がその要素を見て何かするなら `data-type` を付ける。何もしないなら
  付けない」** を規約として決定（[【考察】語彙モデル.md](【考察】語彙モデル.md) §9）。

詳細は [変更履歴.md](変更履歴.md) の 2026-08-19〜2026-08-20 の各節。文書もこの到達点へ
全面追随済み（2026-08-20。カスタムタグ一覧は [【一覧】語彙.md](【一覧】語彙.md) へ改名・作り替え）。

## 覚えておくこと（実装の勘所）

- **項目の鍵は見出しの表示文字**（`th`／`dt`）。機械キーを本文へ書く属性は無い。
  **見出しを改名すると③計算に読まれなくなる**が、保存時に告知が出る（黙って壊れない）。
- **新しい語彙はレジストリへ1件**。プラグインを書くのは計算が要るときだけ
  （[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md)）。カスタム要素は作らない。
- **インラインの script/style は書けない**（CSP strict）。スクリプト/スタイルは `/assets/` の
  外部ファイルへ、イベントは `addEventListener`、動的スタイルは `element.style.x = y`。
- **DOM生成は `createElement`＋`textContent`**。文字列を組み立てて `innerHTML` へ入れない
  （かつて `escapeAttr` 頼みで保存型XSSが実際に発火した。その機構ごと廃止済み）。
- **エディタのクロームは `.vocab-chrome`**（または本文DOM外）。シリアライザが保存しない。
- **本文の取得口は `GET /api/load` の1つ**。計算ビューのSSRを通るのはこの経路だけなので、
  本文を読む新しい経路を足すときは注意（`/api/lock` に生HTMLを同梱していて退行した実例あり）。
- **E2E は実バグを何度も見つけている**。`assets/` を変更したら `node --check` と
  verify-stage2/3/4 を回す（正本は `%OneDrive%\tools\wcms-e2e\`。落とし穴は同 README）。
- **ローカル検証のログインは `a` / `a`**。CSRF対策で `Origin` ヘッダ必須。

## 開発環境の再現（自宅などで再開する手順）

```bash
# 1. 最新を取得
git pull

# 2. 依存取得
go mod tidy

# 3. 初回のみ管理者を作成して起動（ローカルHTTP検証なので Secure Cookie 無効）
#    ローカル開発の管理者は user=a / password=a に統一する（環境間で揃えるため。2026-07-04 決定）。
WCMS_ADMIN_USER=a WCMS_ADMIN_PASSWORD='a' WCMS_SECURE_COOKIES=0 \
  go run cmd/w-cms/main.go
# 2回目以降は環境変数なしで go run cmd/w-cms/main.go
# → http://localhost:8080 （/login にリダイレクト。a / a でログイン）

# 4. テスト
go test ./...
```

注意:
- **ローカル開発のログイン**: `a` / `a`（**ローカル検証専用**。本番では使わないこと）。
  古い環境には `admin` / `Admin` で作られた `auth.db` が残っている場合がある（2026-07-04 に `a`/`a` へ変更）。
  入れないときは下の再設定手順で揃える。
- `data/`（`cms.db` と `master/`、`auth.db`）は `.gitignore` 対象でコミットされない。**環境ごとに独立**するため、
  別環境（自宅など）では初回起動時に上記の環境変数で管理者が新規作成される。`auth.db` は同期されないので、
  「家でログインできない」は data/ が無い＝初回の管理者未作成か、別の認証情報で作成済みのいずれか。
- **既存 `data/auth.db` の認証情報を忘れた／揃えたいとき**は、サーバーを止めてから以下で揃えられる:
  ```bash
  # 一時パッケージで internal/auth を呼ぶ（ルートに別の package main があるためサブdirで実行）
  # 既存ユーザーなら SetPassword、未作成なら CreateUser を使う。
  mkdir -p _resetpw && cat > _resetpw/main.go <<'GO'
  package main
  import ("fmt"; "w-cms/internal/auth"; "w-cms/internal/database")
  func main(){ database.InitAuthDB(); defer database.AuthDB.Close()
    if err := auth.SetPassword("a", "a"); err != nil {
      if err2 := auth.CreateUser("a", "a", true, ""); err2 != nil { fmt.Println(err, err2); return }
    }
    fmt.Println("ローカル管理者 a / a を用意しました") }
  GO
  go run ./_resetpw && rm -rf _resetpw
  ```
- ローカル実行・プレビュー用に `.claude/launch.json`（`go run` 起動設定）を用意済み。
  プレビュー（http://localhost）でCookieが付くよう **`env: { "WCMS_SECURE_COOKIES": "0" }`** を設定してある。
