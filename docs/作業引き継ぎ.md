### 決定はしたが、着手はもっと先

- **メール周りの残り**（`ext/mailgraph/`）:
    - **`SMTP.Send` はアプリ登録に無くてよい**（2026-09-03 に確認）。Entra の
      「所属する組織で使用している API」に **Office 365 Exchange Online が出てこない**
      ——App ID `00000002-0000-0ff1-ce00-000000000000` で検索しても出ない。おそらく
      Microsoft が新しいポータルで Exchange の委任許可を隠している。
      **実害は無い**——動的同意で足りるため。利用者は初回サインインで同意画面を通り、
      それ以降は黙って動く（「各自が自分のメールボックスについて同意する」という
      形なので筋も素直）。全員ぶんを一度で済ませたくなったら、そのとき考える。
    - **添付つきの返信**——`OutgoingMail` は添付を運べるが、返信のUIから付ける口が無い。
      SMTP なので上限は約35MB（Graph の3MiBではない）。
    - **自動取り込み**——いまは人が押したときだけ（§3 人間ゲート型）。実測1.2通/日
      なので当面これで足りる。
    - **トークンのファイル権限**——0600 を指定しているが **Windows では効かない**
      （実測 666）。本番機ではOSのアクセス制御が実質の守り。デプロイ手順に書くこと。
- **未処理の受信の運用**——過去分472通が全部「未処理」になっている。作業待ちの列と
  しては読めないので、**古い分をまとめて「対応：不要」にする手段**が要るかもしれない

- **表のセルの参照がリンクにならない**——外注加工の `資料` に添付への参照を書けるが

### 現状維持と決まったもの（作業なし・蒸し返さないこと）
- **製造部品ページの階層は「顧客名／装置名称／図面名称」**（ワンノートの形をそのまま）。
  **顧客名ページはトップ直下**（受信箱・テンプレートと同階層）。2026-09-03 ユーザー決定。
- **置き場所は解析では決めない**——ユーザー:「人間が見てもなにを言っているのか判断に
  困る場合も結構多いです。**なぜなら顧客は適当だからです**」（2026-09-03）。
  機械にも人にも「いま」決められないなら、**決めさせない作りにする**。
  解析は部品ページを通信記録ページの子として作り、読めたもの（図面番号・図面名称・
  装置名称・客先）をタグに入れるところまで。**受信箱がそのまま「まだ分からないものの
  置き場」**になる。整理は分かったとき（たいてい後続のメールや電話）に別操作で。
  一度は「解析が階層を自動で作る」で実装しかけたが、この一言で取り止めた。
- **見積だけ・試作は装置名称から新しく作ることがある**（`【試作】装置名称` の形）。
  ユーザー:「これは、**メールの内容から判断するしかありません**」「人間の判断も
  必要かもしれません」（2026-09-03）。**機械には決められない**——整理の操作で
  人が名前を打つ前提にする。
- **同じ部品のページが既にあれば、その図面は改定図面**（2026-09-03 ユーザー）。
  顧客名／装置名称の下では図面名称が一意なので、**ページが在ること自体が改定の合図**。
  記録の仕方はユーザー決定:「既存ページの図面の項目の**先頭に配置**してはどうでしょう？
  既存の図面は古いとわかるように**赤枠**で囲み、**ユーザーの判断で消します**。
  （古い図面は旧版に残っています）」。**「新しいものが上」という並びそのものが最新を
  表す**ので、状態を別に持たなくてよい。赤枠は**表示時に付ける**こと——`class` は
  サニタイズで落ちるので保存できない（`ref-missing` の薄赤と同じ作り）。
- **DXFは2種類あり、取り込み口を通るのは片方だけ**——ユーザー:「弊社は加工業者ですから
  CADからCAMへ移すためだけにDXFを作っています」「ごく少数の部品について、お客様から
  DXFの図面を頂きます。**メールに添付されてやってくるDXFは殆どこのタイプです**」
  （2026-09-03）。実データ911件で裏づけ済み:

  | | 同名PDFあり | 同名PDFなし | 正体 |
  |---|---|---|---|
  | **表題欄あり** | 4 | 7 | **お客様の図面**（メールで届く＝取り込み口を通る） |
  | 表題欄なし | 4 | 896 | 自社のCAM用（**取り込み口を通らない**） |

  **「911件中11件しか取れない」と読んではいけない**——分母に自社のCAM用を入れた誤り
  （一度この誤りで「表題欄の作り込みは打ち止め」と判断しかけた）。取り込み口から見える
  分母は11件で、そのうち**10件が取れている**。表題欄読み取りは主経路の機能。
- **DXF解析の目的は「身元の特定」ではなく「PDFとの突き合わせ」**——ユーザー:「主役が
  メール添付のPDFであるのは間違いないです。**PDFにプラスしてDXFがある場合が大部分**です。
  そのため、DXFの図面名称と図面番号をPDFと付き合わせて**同じ部品の図面と認識するために
  解析が必要**」（2026-09-03）。1通のメールにPDFが複数・DXFが複数入るときに、
  どのDXFがどの部品のものかを決めるのが仕事。
  突き合わせに使える手掛かりは強い順に:
    1. **DXFの表題欄の図面番号**（`dxf.go`・Gemini不要・無料・決定的）
    2. **ファイル名の完全一致**——PDFとDXFが同居する12組のうち**8組は同名**だった
       （`P200-911-03A-カーブマシーン(φ410…）` が .pdf と .dxf で同名）。
       図面番号の形をしている必要は無い（`レーザー　APW300 ジャッカー用板` でも対になる）
    3. 図面名称（**重複しうる**ので最後の手段）
  **未実装**。PDF側の図面番号はGeminiの解析結果から採る。
- **図面番号でページを自動的に束ねない**——ユーザー:「図面名称は重複する場合があり、
  一般に図面番号で識別します。残念ながら別の製品の図面番号が一致してしまう場合もあり、
  その場合には、社内で識別番号を割り当てるしかありません」（2026-09-03）。
  同一性を担うのは常にページIDで、図面番号は**探すためのタグ**。衝突したら複数出るので
  人が選ぶ。w-cms はページごとに6桁を必ず振っているので「社内で識別番号を割り当てる」は
  構造としては既に満たされている。

- **テンプレート置き場は h1（ページ名）で決まる。これは仕様**——「機能が名前で変わるのは目論見
  通りです。表示されている言葉が機能を表します」。受け入れたリスク（改名すると配下が
  ②索引・③計算から出入りし告知は出ない）の正本は
  [【考察】ページテンプレート.md](【考察】ページテンプレート.md) §9。**受信箱も同じ型**。
- **集計の見せ分けは残し、欠けたことは知らせない**（C案）——読めないページ由来の行は黙って落ちる
  （全員 admin か同一グループなら発動しません）。
- **パスワード変更で既存セッションは切らない**——「書きかけが保存できないほうが困ります」。

## 覚えておくこと（知らないと必ず踏む罠）

- **Graph と Exchange は別のリソース。1回のトークン要求に混ぜられない**
  （`AADSTS70011`）。サインインは Graph の権限で行い、SMTP のトークンは同じ
  リフレッシュトークンから別途取り直す（`accessTokenFor`・保管はスコープごと）。
  取り違えると「認証は通るのに送れない」という分かりにくい失敗になる。
- **Graph の `sendMail` は `In-Reply-To` を立てられない**（独自ヘッダ＝`x-` 始まり
  のみ。実物で `InvalidInternetMessageHeader` を確認）。だから送信は SMTP。
- **SMTP で投函したメールは Outlook の「送信済みアイテム」に残らない**
  （Exchange Online の仕様）。控えは w-cms の送信箱が担う——承知のうえの選択。
- **新しい権限は動的同意で足せる**。アプリ登録に無くても、その権限を要求して
  デバイスコードでサインインし直せばその場で同意画面が出る（`AADSTS65001` が
  出たらこれ）。ただし同意はその利用者ぶんだけ。

- **`:memory:` DBは接続ごとに別のDB**。行を読みながら中で別のクエリを投げると
  カーソルが接続を握ったままなので**空の別DBに当たり、絞り込みが静かに全部落ちる**
  （2026-09-03 に本番コードで踏んだ。`view_unhandled.go` は先に読み切ってから絞る形）。
  テストも `visibleChildren`・`page.CanView` を通るならファイルDBを使うこと。
- **受信箱・送信箱・テンプレート置き場は h1（ページ名）で決まる**。送信箱が無いと
  返信は送信できても控えが残らない（送信の成否はそのまま返り、記録の失敗は別に伝わる）。
- **子ページの並びは「並び順キー → 題 → ID」**（`sortChildren`）。キーの正本は
  サイドカーの `sort_key`。**キーが空でも題で並ぶ**ので年・月フォルダは何もしなくても
  正しい。ドラッグ並べ替えはその親の子を全部振り直す（`ReorderKey`）。
- **社内コードは「ページ番号-ブロックID」**。指し先は**消えないもの**にすること
  ——図面ブロックは人が消せる決まりなので、改訂履歴の行や構成部品の行を指す。

設計書に書いてあることはリンク先が正本です。ここに残すのは**知らずに書くと壊れるもの**だけ。

> **コードの現状を知りたいときは `go doc` から**（各パッケージの冒頭コメントに正本性・
> 3層モデル・回覧機構・最小権限の要点）。横断的な話——依存の向き・呼び出しの連鎖——は
> [コードリファレンス/](コードリファレンス/README.md) の3本。**古くなったら直さず、
> スキル /code-reference で作り直すこと**。

- **語→型の推論辞書はもう Goコードではない**。正本は `data/settings.json` の `type_inference`。
  **設定ファイルが壊れていると起動が止まる**（黙って既定値で上書きすると運用者の語が消えるため
  ——仕様）。語を足したら**DB再構築で効く**（再起動は不要）。
- **殻の `id` は接頭辞 `w-` を独占する**。本文の `id` は自由だが、接頭辞つきは剥がされる。
- **本文の取得口は `GET /api/load` の1つ**。計算ビューのSSRを通るのはこの経路だけ。
  この経路もサニタイズを通す。一方**アンカー合成（`RenderAnchors`）と参照リンク
  （`RenderReferenceLinks`）は通さない**——合成HTMLが本文として保存されてしまうため、
  ページ描画だけに掛ける。
- **エディタのクロームは `.vocab-chrome`**（または本文DOM外）。シリアライザが保存しない。
  本文DOMを走査する新しいコードは除外を必ず確かめる（Goテストが固定するのはアンカー合成だけ）。
- **認可の読み口はサイドカー（正本）ではなく `cms.db`（派生）**——ズレたら認可は索引に従う。
- **派生（DB）から正本（サイドカー）へは書き戻さない**。サイドカーが読めなければ止まる
  （運用者が手作業で直す、が決定）。
- **匿名には「読めない」と「存在しない」を区別させない**（どちらも404。例外はトップだけ）。
  戻り先は `safeNextPath` が同一サイト内の絶対パスだけに絞る。
- **サニタイズ後にHTMLを足す関数**（`RenderComputedViews`・`RenderAnchors`・`RenderPageShell`・
  `RenderReferenceLinks`）は自前でエスケープ責任を負う。規律が破れると保存型XSS。
- **DOM生成は `createElement`＋`textContent`**。`innerHTML` へ文字列を入れない
  （`escapeAttr` 頼みの保存型XSSが実際に発火した過去がある）。
- **本文の埋め込み（`<img src>` 等）の宛先は `/data/` 配下ときれいなURLに限る**。
  リンク（`a[href]`）は制限していないので、**クロームがリンクから埋め込みを導出するときは
  形（きれいなURLの正規表現）を必ず検査する**（app.js `refreshAttachmentPreviews` が手本）。
  状態を変える経路はメソッドを絞る（`route_guard_test.go` が固定）。
- **`csp_test.go` はポリシー文字列しか見ていない**。配線の固定は `TestCSPIsWired`。
- **ルート表は `buildHandler()`**（`cmd/w-cms/main.go`）。
- **プラグインテーブルにマイグレーションは無い**。スキーマを変えたら起動時に1度だけ
  自動再構築が走る（`DriftedSchemaTables`）。
- **`visibleChildren` を使うテストは `:memory:` DBでは動かない**——ファイルDBを使う
  （`setupTemplateAPITest` が手本）。
- **テンプレート領域（ルート含む）は③計算に載らない**。判定の先祖辿りは
  **サイドカー＋本文HTML**——DBを見ると静かに壊れる。
- **項目の鍵は見出しの表示文字**（`th`／`dt`）。機械キーを本文へ書く属性は無い。
  改名すると③計算に読まれなくなるが、保存時に告知は出る。
- **業務データの行き先は `vocab_index` だけ**（D-1）。③計算は
  [vocab_query.go](../internal/cms/vocab_query.go) を通して読む——**索引の `field` は
  見出しの表示文字**（`品番`）で、機械キー（`item-id`）ではない。
- **業務文書ブロックのヘッダ（素の `dl`）は `section` の側から拾っている**
  （`syncVocabSectionHeader`）。ここを外すと発注元・発注日が索引から黙って消える
  （`TestSectionHeaderIsIndexed` が固定）。ヘッダと明細の対応づけは `block_no`。
- **新しい語彙はレジストリへ1件**（`internal/cms/vocab.go`）。**カスタム要素は作らない**。
  プラグインは計算が要るときだけ（[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md)）。
- **取り込み係・解析はコアの回覧と共通の芯に乗る**——受信箱への到着はコアが拡張子で
  取り込み係へ回すだけ（`intake.go`）。ページ作成の芯は `createChildPageOf`、
  重複検知の分担は「鍵の取り出しは取り込み係（`SourceRefFinder`）・照合はコア
  （`ExistingIntakePage`・索引の逆引き）」。専用テーブルは無い。
- **インラインの script/style・`on*=` は書けない**（CSP strict・[開発方針.md](開発方針.md) §4）。
- **Gemini は有料枠のキーで運用する**——無料枠では入力データが製品改善に使われるため、
  「学習に使用されない」前提は課金が有効なキーであることが条件。コードからは判定できず、
  **運用側で守るしかない**（[【ガイド】デプロイ・運用.md](【ガイド】デプロイ・運用.md)）。
  キーの値はチャット・ログ・リポジトリに残さない（環境変数 `GEMINI_API_KEY`）。
- **ページ削除は `data/trash` への移動**（物理削除ではない）。トップと子持ちは不可・
  編集ロックが要る。**復元UIは未実装**——手で `data/master` へ戻してDB再構築。
- **E2E は実バグを何度も見つけている**。`assets/` を変更したら `node --check` と `e2e/` を回す
  （毎回回してよい・ユーザー承認済み）。`node` が PATH に無いことがある
  （`C:\Program Files\nodejs` を足す）。
- **ローカル検証のログインは `a` / `a`**。CSRF対策で `Origin` ヘッダ必須。
- **添付の保存先は `files/` サブフォルダ**。正本と同居しないので名前衝突の上書きは
  構造的に不可能。名前の検査 `safeAttachmentName` は全アップロード口が共有する。
- **画像は保存前に EXIF を落とす**（JPEG は再符号化——画素は元と厳密には一致しない）。
  原本をそのまま保つ用途（証跡）が出たら設計を見直す。
- **SVG の安全性は配信側が本体**（`attachment`＋sandbox CSP）。配信ヘッダを外すと
  同一オリジンで動く。**PDF はインライン配信**（クリック展開が前提）——ZIPは目録読みだけで
  展開しない（ZIP爆弾対策。中の1件を取り出す解析だけ上限つきで読む）。
- **本文の走査はコアの配送係だけ**（`walk.go`）。`WalkElements` を自分で回す新しいコードは
  たいてい設計を間違えている。
- **観察係の `descend` は OR で畳まれる**。AND にすると明細が索引から消える
  （`TestObserversSeeNestedItemsTable` が固定）。
- **版は本文HTMLだけ**。リバートで権限・所有者・親は巻き戻らない——この線引きが安全の要。
- **スラッシュメニューの項目は絞り込みのたびに作り直す**。click / mouseenter は作るたびに配線。

## 現在の状態（環境）

- **E2E は10本**（stage2〜version の9本＋verify-preview 16項目）。
  `cd e2e && npm install && npx playwright install chromium` で使える。`go test ./...` 全通過。
  **⚠ E2E を流すとトップ直下に定型名のページが積もる**——掃除は定型名で選んで削除APIへ。
  ただし**本物のテンプレート木も「テンプレート」という名前**なので、中身と更新時刻で
  見分けること（一度巻き込んで復元した実績あり）。
  **一式を続けて流すと、たまに1本だけ落ちる**（原因は前のスクリプトの編集ロック残り。
  同じ形の落ち方をしたら、まず再実行して切り分ける）。
- `data/` は `.gitignore` 対象で環境ごとに独立。**両環境とも一掃済み**
  （自宅 2026-09-02＝3枚／職場 2026-09-04＝6枚。トップ・テンプレート木・受信箱・送信箱）。
  掃除のときエディタでデータファイルを開いていると `data/master` を動かせない
  （Permission denied。PowerShell の `Move-Item` なら通る）。
- **一掃のやり方**（2026-09-04・職場）: サーバーを止め、残すページ以外の
  `data/master/*/*` を消し、`data/trash` を空にし、`data/cms.db*` を消してから起動する。
  **派生索引は起動時に `data/master` から作り直されます**
  （ログに「空のDBとHTMLファイルを検出」と出れば正常）。**`data/mail/` は消さないこと**
  ——サインインのリフレッシュトークンで、消すとデバイスコードからやり直しになります。
- **`data/trash` は普段は消さないこと**——削除したページの唯一の写しで、復元UIが未実装のため
  手で戻す以外にありません（要らないと判断したときだけ空にする）。
- **スキーマ変更を含む版で初めて起動する環境では、起動時に自動再構築が1度走る**
  （ログに「テーブル定義の変更を検出しました」と出れば正常・無害）。
- **`go test -race` が使える**（gcc 導入済み）。PATH に WinLibs の
  `~/AppData/Local/Microsoft/WinGet/Packages/BrechtSanders.WinLibs.POSIX.UCRT_*/mingw64/bin` を
  足し `CGO_ENABLED=1 go test -race ./...`。通常ビルドは Pure Go を保つため `CGO_ENABLED=0` のまま。
- **Gemini の実測は職場マシンで済み**（ユーザー環境変数 `GEMINI_API_KEY`・有料枠）。
  スマホからの実機確認も済み（LAN内 `http://<IP>:8080`・`WCMS_SECURE_COOKIES=0` 必須・
  平文Cookieなので本番の値では絶対にやらない）。

## 開発環境の再現（自宅などで再開する手順）

```bash
git pull && go mod tidy

# 初回のみ管理者を作成して起動（ローカルHTTP検証なので Secure Cookie 無効）。
# ローカル開発の管理者は user=a / password=a に統一する（環境間で揃えるため。2026-07-04 決定）。
WCMS_ADMIN_USER=a WCMS_ADMIN_PASSWORD='a' WCMS_SECURE_COOKIES=0 go run cmd/w-cms/main.go
# 2回目以降は環境変数なしで go run cmd/w-cms/main.go
# → http://localhost:8080 （/login にリダイレクト。a / a でログイン）

go test ./...
```

注意:

- **ローカル開発のログイン**: `a` / `a`（**ローカル検証専用**。本番では使わないこと）。
- `data/` はコミットされないため、別環境では初回起動時に上記の環境変数で管理者が作られます。
  **「家でログインできない」は、初回の管理者未作成か別の認証情報**。
- **既存 `data/auth.db` の認証情報を忘れた／揃えたいとき**は、サーバーを止めてから以下で揃う:
  ```bash
  # 一時パッケージで internal/auth を呼ぶ（ルートに別の package main があるためサブdirで実行）。
  mkdir -p _resetpw && cat > _resetpw/main.go <<'GO'
  package main
  import ("fmt"; "w-cms/internal/auth"; "w-cms/internal/database")
  func main(){ database.InitAuthDB(); defer database.AuthDB.Close()
    if err := auth.SetPassword("a", "a"); err != nil {
      if err2 := auth.CreateUser("a", "a", true, ""); err2 != nil { fmt.Println(err, err2); return }
    }
    fmt.Println("ローカル管理者 a / a を用意しました") }
  GO
  go run ./_resetpw && rm -rf _resetpw
  ```
- ローカル実行・プレビュー用に `.claude/launch.json`（`go run` 起動設定）を用意済み
  （プレビューでCookieが付くよう `WCMS_SECURE_COOKIES=0` 設定済み）。
- 取り込み・解析を試すには、トップ直下に「受信箱」ページを作り（名前が機能）、
  `GEMINI_API_KEY` を設定して起動する（無ければ解析ボタンが設定を促すだけで、他は全部動く）。
