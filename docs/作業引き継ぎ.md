  よって増殖する」）。対象は顧客名・装置名称・図面名称・図面番号・発注書番号
  （`NormalizeNameForIngest`）。**長音には触らない**——`NormalizeCode` を使うと `レーザー` が
  `レ-ザ-` になる。**メールの件名には掛けない**（届いたままが正本）。
  正本は [【考察】テキストの正規化.md](【考察】テキストの正規化.md) §3a。
- **テンプレート置き場・通信箱は h1（ページ名）で決まる。これは仕様**——「機能が名前で
  変わるのは目論見通りです。表示されている言葉が機能を表します」。受け入れたリスクの正本は
  [【考察】ページテンプレート.md](【考察】ページテンプレート.md) §9。
- **集計の見せ分けは残し、欠けたことは知らせない**（C案）——読めないページ由来の行は黙って落ちる。
- **パスワード変更で既存セッションは切らない**（「書きかけが保存できないほうが困ります」）。
  締め出しは「利用停止」が既に効く。
- **添付ファイルの配信にキャッシュ抑止は足さない**——共用PCも個人IDでログインする前提。
- **PDF解析は自動では走らない**（「自動ではなくボタンのclickなどで解析が始まると良い」09-01）。
  Gemini の呼び出しは常に人の操作の直後だけ（人間ゲート型）。

**拡張の切り方**

- **アドレス帳は `ext/contacts`**（09-15 移設・案B）。**拡張どうしの import が解禁**——
  `ext/sheetmetal` → `ext/contacts` が最初の1本。
  ⚠ **`ext/contacts` にビルドタグは付けない**。付けると「板金は入れたがアドレス帳は外した」
  という組み合わせが作れてしまい、整理が取引先ページを作れずに黙って壊れる。**依存は import で
  表す**。`cmd/w-cms/ext_contacts.go` は**起動ログに名前を出すためだけ**の1枚（`loadedExtensions`
  が `package main` の変数なので拡張から名乗れない）——**消しても機能は消えない**。
  **コアとの境目はフック3つ**——`RegisterVocab`・`RegisterView`・**`RegisterContactResolver`**
  （アドレス→連絡先ページ。`ref_render.go` が `ContactPageForAddress` を名指ししていたのを
  裏返した）。**どれも任意**で、積まなければ `email` 型のタグは素のテキストで出る——
  `-tags minimal` の実行ファイルに `取引先`・`未登録の連絡先`・`仕入先`・`api/contacts` は
  **1つも入っていない**（実測）。
  ⚠ **`ext/contacts` の試験はファイルDB**（`setup_test.go`）——`visibleChildren`・`page.CanView`
  を通るので `:memory:` では静かに空を返す。`ext/sheetmetal` がインメモリなのは、あちらが
  その経路を通らないから。
- **メール送受信は IMAP／SMTP**（どちらも OAuth2 の XOAUTH2・**外部依存ゼロ**・IMAP は必要な
  5コマンドだけ自前）。**Microsoft Graph は 09-05 に完全撤去**——メールサーバーをレンタルへ移す
  ことが決まり、Graph のままだと受信を丸ごと書き直すことになるため。**パスワードは w-cms を
  通らない**（デバイスコードフロー・預かるのはリフレッシュトークンだけ・`data/mail/<利用者>.json`）。
  正本は `ext/mail/`、口はコアの `internal/cms/mail.go`（Mailer）。`-tags nomail` で外せる。
  **SMTP の同意は南さん個人ぶん**。他の利用者は初回サインインで同意画面を通る。
  ⚠ **移設の継ぎ目**——接続先は環境変数（`WCMS_MAIL_IMAP_HOST` 既定 `outlook.office365.com:993`・
  `WCMS_MAIL_SMTP_HOST` 既定 `smtp.office365.com:587`）。**書き換わるのは接続先と認証方式だけ**
  ——パスワード認証（`AUTHENTICATE PLAIN`）は**移設先が決まってから**足す。`ext/mail/auth.go` は
  M365 のあいだだけの持ち物。

**通信箱**

- **受信も送信もトップ直下の「通信箱」1つ**（09-05 統合）。年／月フォルダに時系列。
  **向きは `向き：受信/送信` のタグ**で、`チャネル`（メール／FAX／電話）とは**直交する別の軸**
  （「送信 × FAX」が要る）。記録は動かさない——作業は一覧で行い、完了は `対応：不要` のタグ。
- **未処理の作業面は通信箱のページに載る**——1行1件・矢印＋チャネルの記号（`→☎` `←✉` `📠` `📝`）・
  📎の数・「不要」を1クリック・チェックして**まとめて片付け**（`/api/intake/handled`）。
- **通信以外の案件も通信箱に入る**（「自分が使う作業台の製造などは、どことも通信しません」）。
  タグを1つも書かずに通信箱の下へページを作れば作業待ちに並ぶ。
- **手で記録を作れる**——「＋ 記録する」でチャネルと向きを選び、できたページへファイルを落とす。
- **⚠ PDF・DXF の自動取り込みは 09-05 に取り止め**（「通信箱のPDF、DXF取り込みはやめましょう。
  メモに添付するようにしましょう」）——落ちてきた PDF を機械が `チャネル：FAX` と決めつけていた。
  **取り込み係が居るのは `.eml` だけ**。**FAXサーバーを繋ぐときは機械専用の口を作ること**。
- **電話をかけられる**——`電話番号` タグのあるページに `☎ …へかける`＋「記録を作る」チェック。
  `tel:` なのでソフトフォンがあれば動く。
- **⚠ 未処理は「人の印」だけで決まる**（09-05 に2度改めた）。向きでも子ページの有無でも決めない
  ——「かけた電話で受注することもある」「一つのメールに複数の案件が含まれることもある」。
- **取り込みで生まれたページには家が要る**——未処理一覧は通信箱の子孫を全部拾う
  （`isDescendantOf` は深さ無制限）ので、受注ページに置き場が無かったころはメール1通が
  2行にも3行にもなった。新しく「解析が作るページ」を足すときは**同時に行き先を決めること**。

**部品・取引先の木**

- **製造部品ページの階層は「顧客名／装置名称／図面名称」**（ワンノートの形）。**顧客名ページは
  「取引先」の下**（09-05「トップページの直接の子が個人名や社名はちょっと具合が悪い」）。
- **相手のページは1枚・箱も1枚**。アドレス帳が作る相手ページと部品階層の顧客名ページは
  **同じページ**。箱を `顧客` `仕入先` で割らないのは「顧客であり、仕入れ先である場合も
  あります」——役割は `取引` タグ。**`取引先` ページは無ければ自動で作られる**
  （[ext/contacts/contacts.go](../ext/contacts/contacts.go) の `EnsurePartnerBox`）。
- **装置名称の上に「段」**（`取引先／社名／段／装置名称／図面名称`。09-05「旧型、現行、試作などが
  あったほうが探しやすい」）。既定は現行・旧型・試作（`machine_stages`・**先頭が整理の初期値**）。
  **段は人が毎回選ぶ**。`【試作】装置名称` という題の付け方は不要になった。
- **窓口の人は `取引先／社名／担当者／名前`**（`ContactPersonBoxTitle`）——社名ページの子には
  装置名称が並ぶので、人を直接ぶら下げると埋もれる。**人のページを作る操作は未実装**
  （その人に添付や記録を紐づけたくなったときに作る）。
- **顧客名の推奨値は「既にある取引先ページの題」**（09-06「社名の揺れは、エイリアスの表かAIで
  なくせませんか？」）。鎖は `部品ページ → 受信元 → 通信記録 → 差出人アドレス → 取引先ページ →
  その題` で**全部が完全一致**——エイリアスの表もAIも要らない。完全一致がドメインより先
  （自社の工場長だけ別プロバイダ、が実データにある）。`取引：自社` は推奨値にしない。
- **2つ目のドメインは既存の相手へ足せる**（アドレス帳の「既にある相手へ足す…」）。
- **受注ページは `受注／年／月`**（09-06）。顧客の下へは置かない——**受注は複数の装置に
  またがる**。年月は**発注日**。移すのは 📁 整理の操作。正本は
  [filing_order.go](../ext/sheetmetal/filing_order.go)。
- **置き場所は解析では決めない**（「人間が見てもなにを言っているのか判断に困る場合も結構多い
  です。**なぜなら顧客は適当だからです**」09-03）。解析は部品ページを通信記録の子として作り、
  読めたものをタグに入れるところまで。**通信箱がそのまま「まだ分からないものの置き場」**。
  整理は分かったときに別操作で。
- **整理で直した値は図面ブロックと索引にも入る**（09-11「検索するときに困るからです」）。
- **見積だけ・試作は装置名称から新しく作ることがある**（段の「試作」に入れる。「メールの内容から
  判断するしかありません」——機械には決められない）。
- **同じ部品のページが既にあれば、その図面は改定図面**（09-03）。**旧版の図面は最新版の
  子ページ**（09-06「旧版を最も新しい版の子にしてはどうでしょう」）——部品ページに載るのは
  最新の図面1つだけで、古い図面の赤枠は要らなくなった。正本は `mergeAsRevision`
  （[filing.go](../ext/sheetmetal/filing.go)）。
- **解析済みの印は保存していない**——解析が書いた `受信元` の逆引き（`/api/analyzed`）。
  間違った解析をゴミ箱へ入れれば印も消え、押し直せる。
- **ファイルは「ファイル表示」のマーカーで開く**（09-14 に作り直し）。
  `<section data-type="file-view">` の中に参照を1つ書くと、**サーバーが**その添付を開く枠を足す
  （`internal/cms/file_view.go`・鏡型）。**タグの名前は書く人が決める**（コアは名前を知らない）。
  ⚠ クライアントで組むのはやめた——`RenderReferenceLinks` は `/api/load` を通らず、編集モードを
  出入りすると図面が黙って消えていた。鏡は両方の経路で走り、**公開ページ（匿名・ゼロJS）でも出る**。
  ⚠ 旧実装は `<section><h2>図面</h2>` という**板金の語彙でコアが分岐**していた（消えた）。
  `<embed>` を本文に書かせない理由は [セキュリティ設計.md](セキュリティ設計.md) §4。
- **DXFは2種類あり、取り込み口を通るのは片方だけ**（「弊社は加工業者ですからCADからCAMへ
  移すためだけにDXFを作っています」「メールに添付されてやってくるDXFは殆ど〔お客様の図面〕」）。
  実データ911件:

  | | 同名PDFあり | 同名PDFなし | 正体 |
  |---|---|---|---|
  | **表題欄あり** | 4 | 7 | **お客様の図面**（取り込み口を通る） |
  | 表題欄なし | 4 | 896 | 自社のCAM用（**取り込み口を通らない**） |

  **「911件中11件しか取れない」と読んではいけない**——分母に自社のCAM用を入れた誤り。取り込み口
  から見える分母は11件で**10件が取れている**。
- **DXF解析の目的は「身元の特定」ではなく「PDFとの突き合わせ」**（「PDFにプラスしてDXFがある
  場合が大部分です」）。手掛かりは強い順に ①DXFの表題欄の図面番号（`dxf.go`・Gemini不要）
  ②**ファイル名の完全一致**（同居12組のうち8組は同名）③図面名称（重複しうる）。**未実装**。
- **図面番号でページを自動的に束ねない**（「別の製品の図面番号が一致してしまう場合もあり…
  社内で識別番号を割り当てるしかありません」）。同一性は常にページID、図面番号は探すためのタグ。
  w-cms は6桁を必ず振るので「社内で識別番号」は構造として既に満たされている。

**HTTPS と WebDAV**（09-07 に一式実装・両環境とも導入済み）

- **HTTPS**: `go run ./cmd/w-cms -gencert` で自己署名を `data/tls/` に作り、`WCMS_TLS_CERT` と
  `WCMS_TLS_KEY` を置くと **:8443**（両方そろわないと起動を止める——片方だけは書きかけ）。
  各PCで1度だけ `Import-Certificate`（管理者PowerShell・**1行で貼る**）。
  ⚠ `-gencert` を走らせるたびに別の証明書ができる——**信頼させたものとサーバーが出している
  ものの指紋が一致しているか**を確かめること（1度食い違わせた。照合は `Get-PfxCertificate` の
  Thumbprint と、サーバーの証明書の SHA256 を突き合わせる）。
  ⚠ TLS の環境変数を置くと **:8443 だけ**になる——古い E2E は :8080 を見る（「環境」）。
- **WebDAV**（`WCMS_DAV=1`・**既定は閉じる**・`x/net/webdav` は既存依存）: エクスプローラで `Z:` に
  割り当て、**実物のCADで DXF を開けた**（SHA256 一致・シーク読み可）。**HTTPS が前提**——
  `BasicAuthLevel=1` が平文の Basic を送らせない（エラー67・認証失敗として報告されない）。
  **ページの木をそのまま見せる**（`Z:\取引先\社名\現行\装置\部品\図面.dxf`）。見せないものは
  設定 `webdav_hidden`（コアが `通信箱` を名前で特別扱いしない）。題はフォルダ名へ付け替える
  （`:`→`：`・重複はページIDを添える）——⚠ **規則を変えると割り当て済みのパスが全部変わる**
  （`safeFolderName`）。
  **上書きできる**——前の中身が版になる（`files/.versions/<名前>/<時刻>.<拡張子>`・一覧には
  出ない）。ページの更新時刻も進み、監査に `dav.write`。**新しいファイルは作れない**。
  消す・作る・動かす（`DELETE`・`MKCOL`・`MOVE`・`COPY`・`PROPPATCH`）は通さない。`LOCK` は通す。
  書ける範囲は設定 `webdav_readonly`（祖先まで効く）——**編集の対象は自社のファイルだけ**、
  通信箱の下の添付は「届いた事実の証拠」。
  `.rpcd` は **RootPro CAD** の形式（Radan は誤記）。試験は31バイトの偽物なので**実物での確認は未了**。
  正本は [【考察】添付をローカルアプリで編集する.md](【考察】添付をローカルアプリで編集する.md)。

> 回覧機構・最小権限の要点）。横断的な話——依存の向き・呼び出しの連鎖——は

**道具**

- **サーバーは `taskkill //IM main.exe` では止まらない**（09-07 に半時間溶かした）。実行ファイルは
  **`w-cms.exe`**。止め損なうと古いプロセスがポートを掴んだままで、**直したはずのコードが
  効かない**ように見える。PIDで止める:
  ```powershell
  Get-NetTCPConnection -LocalPort 8443 -State Listen | ForEach-Object {
    Stop-Process -Id $_.OwningProcess -Force }
  ```
- **`gofmt -w` を glob で走らせると無関係なファイルまで書き換わる**（全角の桁幅で位置揃えが
  直し直される）。名指しすること。`gofmt -l` は CRLF のため全ファイルが挙がるので判断材料にしない。
- **`sed -i` は CRLF を LF に変える**（09-15）。git の `autocrlf` が正規化するので内容の差分は
  ゼロになり実害は無いが、`git status` に触っていないファイルが並ぶ。**本当の差分は
  `git diff --numstat` で見る**（行末だけの変更は行数が出ない）。
- **deadcode の結果を鵜呑みにしない**（09-07・09-15 に2度）。試験だけが使う公開API・設計上の対で
  残している口・意図して残した土台（`deleteToken`）が全部「未到達」に出る。**1件ずつ呼び手と
  コメントを読んでから消す**。
- **Goの到達率（カバレッジ）はパッケージごと**（09-14 に誤読）。`go test ./internal/cms/page -cover`
  の 13.9% はそのパッケージ自身の試験ぶんだけ。`-coverpkg=./...` で測ると `CanView` 等は 100%。
  **低い数字を見て「試験が無い」と読まないこと。**
- **API を外から叩くときの作法**（09-11 に順に踏んだ）: ログインは**フォーム形式**
  （`--data-urlencode 'username=a'`・JSONだと `error=1` で302）／`/api/load?id=` は**生のHTML**／
  **`/api/lock/force` はロックが無いと 204（本文なし）**——JSONとして読むと落ちる／
  **別の口から握ったロックは同じ利用者でも `/api/lock` で取り直せず、`/api/unlock` でも外れない**
  （`Locks.Release` は保持者名とトークンの両方一致が要る。`ok:false, same_user:true` が返る。
  admin の `/api/lock/force` を通す）／
  Python の `subprocess` から curl を呼ぶと `/tmp` が MSYS のパス変換を通らない（`$TEMP` の実パス）。
- **`:memory:` DBは接続ごとに別のDB**。行を読みながら中で別のクエリを投げると**空の別DBに当たり、
  絞り込みが静かに全部落ちる**（09-03 に本番で踏んだ。`view_unhandled.go` は先に読み切ってから絞る）。
  `visibleChildren`・`page.CanView` を通る試験は**ファイルDB**——コアは `newTestFileDB`
  （`testsetup_test.go`）、拡張は自前の `setup_test.go`。
- **E2E は実バグを何度も見つけている**。`assets/` を変更したら `node --check` と `e2e/` を回す
  （毎回回してよい・ユーザー承認済み）。`node` が PATH に無いことがある（`C:\Program Files\nodejs`）。
- **ローカル検証のログインは `a` / `a`**。CSRF対策で `Origin` ヘッダ必須。
- **QRの検証ツールは開発機に pip で入れている**（`opencv-python-headless`・`qrcode`）。製品の依存では
  ない。`tools/qr_verify.py` を走らせるときだけ。

**索引・スキーマ**

- **⚠ 新しいテーブルを足しても自動再構築は走らない**（09-13）。`ApplySchema` は空の表を作るだけ
  ——`page_tags` を足した日にタグ88行が古い表に取り残された（画面は無言で空）。いまは
  `DriftedSchemaTables` が「索引に中身があるのに表が無い」もずれとして扱う。
  ⚠ `CREATE INDEX` を表と取り違えて起動のたびに再構築が走る二次災害も出した（`createdTableName`）。
- **⚠ スキーマを変えたら、作り直しが `ApplySchema` より先**。逆だと列を変えた表へ新しい索引を
  張ろうとして起動が落ちる（`no such column: name`）。
- **⚠ 主鍵を付けると隠れていた重複が出る**（試験側で2件——同じページ番号へ洗わず書き足し／
  タグの番号を `dl` ごとに 0 へ戻していた）。
- **⚠ 一括置換で SQL を直すときは UNION を跨がない**——`page_tags` を含む文字列をまとめて置換したら
  `vocab_index` 側の列名まで書き換わった。表ごとに列名が違うので、混ざる場所は手で直す。
- **プラグインテーブルにマイグレーションは無い**。スキーマを変えたら起動時に1度だけ自動再構築。
- **業務ブロックの行き先は `vocab_index`、タグは `page_tags`**（09-13 分離）。③計算は
  [vocab_query.go](../internal/cms/vocab_query.go) を通して読む——**索引の `field` は見出しの
  表示文字**（`品番`）で、機械キー（`item-id`）ではない。
- **業務文書ブロックのヘッダ（素の `dl`）は `section` の側から拾っている**（`syncVocabSection`・
  `eachPlainVocabChild`）。外すと発注元・発注日が索引から黙って消える（`TestSectionHeaderIsIndexed`）。
  ヘッダと明細の対応づけは `block_no`。
- **`text` と `code` は畳む強さだけが違う**。`code`（図面番号・発注書番号）は空白・ハイフン類・
  長音・大小まで畳み、`text` は**長音に触らない**。引くのは `PagesByTag`（生）と
  `PagesByTagLoose`（畳んだ一致）で、**2段にせず呼ぶ側が選ぶ**。
  ⚠ **`NormalizeForLookup`（畳んだ文字列だけ返す口）は 09-15 に撤去した**——`norm_value` に
  宣言型が無くなった日から、文字列で引くと number のタグが**エラーにならず0件**になる。
  09-14 に「設計判断を1日で捨てない」と残したが、捨てたのは判断ではなく古くなった実装。
- **語→型の推論辞書はコードではない**。正本は `config/settings.json` の `vocabulary`。
  **壊れていると起動が止まる**（黙って既定値で上書きすると運用者の語が消える——仕様）。
  語を足したら**DB再構築で効く**。
- **観察係の `descend` は OR で畳まれる**。AND にすると明細が索引から消える
  （`TestObserversSeeNestedItemsTable`）。
- **本文の走査はコアの配送係だけ**（`walk.go`）。`WalkElements` を自分で回す新しいコードは
  たいてい設計を間違えている。
- **テンプレート領域（ルート含む）は③計算に載らない**。判定の先祖辿りは**サイドカー＋本文HTML**
  ——DBを見ると静かに壊れる。
- **③計算の集計スコープは `cms.RelatedPages`**（自ページ＋参照で直接つながるページ・深さ1・両向き）。
  `block_no` はページの中の連番なので、**スコープが広がったあとはページごとに閉じて突き合わせる**。

**本文・参照**

- **⚠ 本文の空欄は `<dd><br/></dd>`**（サニタイズが入れる）。`<dd>([^<]*)</dd>` だけで探すと
  **空欄を素通りする**（09-11 に `客先` を3枚取りこぼした。`replaceFirstFieldValue` は `<br>` も空と扱う）。
- **項目の鍵は見出しの表示文字**（`th`／`dt`）。機械キーを本文へ書く属性は無い。
- **参照タグと読むのは可変タグ（`dl[data-type="tags"]`）の中だけ**。素の `dl` まで見ると
  **発注書番号が参照に化ける**（`250401-203` は「6桁-英数字」に当てはまる）。桁を絞るだけでは足りない。
- **参照が飛ぶ先は常に本文のブロック**（`#<data-id>`）。添付そのものを指す経路は無い——だから
  **添付の識別子もブロックIDと同じ4桁**（ファイル名＝URL＝`data-id` の3役は不変。既存の8桁は
  そのまま）。一意にすべき範囲は `files/` の中と本文の `data-id`。
- **社内コードは「ページ番号-ブロックID」**。指し先は**消えないもの**にすること（図面ブロックは
  人が消せるので、改訂履歴の行や構成部品の行を指す）。
- **本文の取得口は `GET /api/load` の1つ**（サニタイズを通す）。**アンカー合成
  （`RenderAnchors`）と参照リンク（`RenderReferenceLinks`）は通さない**——合成HTMLが本文として
  保存されてしまうため、ページ描画だけに掛ける。
- **エディタのクロームは `.vocab-chrome`**（または本文DOM外）。シリアライザが保存しない。
- **見た目の印は本文に保存できない**——`class` はサニタイズで落ちる。宙ぶらりんの参照の薄赤
  （`ref-missing`）のように、**表示時に付ける鏡型**で作る。
- **殻の `id` は接頭辞 `w-` を独占する**。本文の `id` は自由だが、接頭辞つきは剥がされる。
- **子ページの並びは「並び順キー → 題 → ID」**（`sortChildren`）。キーの正本はサイドカーの
  `sort_key`。ドラッグ並べ替えはその親の子を全部振り直す（`ReorderKey`）。
- **版は本文HTMLだけ**。リバートで権限・所有者・親は巻き戻らない——この線引きが安全の要。
- **スラッシュメニューの項目は絞り込みのたびに作り直す**。click / mouseenter は作るたびに配線。

**機械が書くとき**

- **⚠ 機械が既存ページの本文を書き換えるときは関門が要る**（09-14）。`RewriteBody` /
  `SetPageH1` は読んで・変えて・書くので、エディタが開いているとオートセーブと黙って上書きし合う。
  `RequireEditLock` は**使えない**（一覧画面のボタンはトークンを持てず必ず409）。使うのは
  `editlock.RefuseWhileEditing`（1ページ）か `editlock.Locks.EditorOpen`（まとめ押し・1件ずつ飛ばす）。
  **自分が開いていても断る**／**保持者が居なくなったロックは無視する**。正本は
  [【考察】同時編集の競合対策.md](【考察】同時編集の競合対策.md) §9。
- **機械が作るページは行き止まりにしない**（09-11）。計算ビューは**本文にブロックを置いて初めて
  描かれる**——`取引先` が見出しだけで、アドレス帳が100通のあいだ誰にも見られていなかった。
- **取り込み係・解析はコアの回覧と共通の芯に乗る**——ページ作成の芯は `CreateChildPage`、
  重複検知の分担は「鍵の取り出しは取り込み係（`SourceRefFinder`）・照合はコア
  （`ExistingIntakePage`）」。専用テーブルは無い。
- **新しい語彙はレジストリへ1件**——コアの器は `internal/cms/vocab.go`、業務の語彙は拡張が
  `RegisterVocab` で持ち込む。**カスタム要素は作らない**
  （[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md)）。
- **ページ削除は `data/trash` への移動**。トップと子持ちは不可・編集ロックが要る。
  **復元UIは未実装**——手で `data/master` へ戻してDB再構築。

**安全**

- **インラインの script/style・`on*=` は書けない**（CSP strict・[開発方針.md](開発方針.md) §4）。
  `csp_test.go` はポリシー文字列しか見ていない——配線の固定は `TestCSPIsWired`。
- **DOM生成は `createElement`＋`textContent`**。`innerHTML` へ文字列を入れない
  （`escapeAttr` 頼みの保存型XSSが実際に発火した過去がある）。
- **サニタイズ後にHTMLを足す関数**（`RenderComputedViews`・`RenderAnchors`・`RenderPageShell`・
  `RenderReferenceLinks`）は自前でエスケープ責任を負う。破れると保存型XSS。
- **本文の埋め込み（`<img src>` 等）の宛先は `/data/` 配下ときれいなURLに限る**。リンクは制限して
  いないので、**クロームがリンクから埋め込みを導出するときは形を必ず検査する**
  （`refreshAttachmentPreviews` が手本）。状態を変える経路はメソッドを絞る（`route_guard_test.go`）。
- **認可の読み口はサイドカー（正本）ではなく `cms.db`（派生）**——ズレたら認可は索引に従う。
  **派生から正本へは書き戻さない**（サイドカーが読めなければ止まる）。
- **匿名には「読めない」と「存在しない」を区別させない**（どちらも404。例外はトップだけ）。
  戻り先は `safeNextPath` が同一サイト内の絶対パスだけに絞る。
- **添付の保存先は `files/` サブフォルダ**——名前衝突の上書きは構造的に不可能。名前の検査
  `SafeAttachmentName` は全アップロード口が共有する。**画像は保存前に EXIF を落とす**
  （JPEG は再符号化）。**SVG の安全性は配信側が本体**（`attachment`＋sandbox CSP）。**PDF は
  インライン配信**、ZIPは目録読みだけで展開しない（ZIP爆弾対策）。
- **Gemini は有料枠のキーで運用する**——無料枠では入力データが製品改善に使われる。コードからは
  判定できず**運用側で守るしかない**。キーの値はチャット・ログ・リポジトリに残さない。
- **ルート表は `buildHandler()`**（`cmd/w-cms/main.go`）。拡張の口は各プラグインの `Routes()`。

**メール**

- **IMAP と SMTP は同じリソース**（Exchange Online）なので**トークンは1つ**（Graph 時代の
  `AADSTS70011` の罠は IMAP 化で消えた）。
- **SMTP で投函したメールは Outlook の「送信済みアイテム」に残らない**（仕様）。控えは通信箱。
- **新しい権限は動的同意で足せる**（`AADSTS65001` が出たらサインインし直す）。同意はその利用者ぶんだけ。
- **⚠ `AADSTS65001` は `invalid_grant` の形で返ってくる**。「失効した」とみなしてトークンを捨てると
  **権限を増やした日にサインインが消える**（09-05 に実際に消した）。**保管は自動で捨てないこと**
  ——`ext/mail/store.go` の `deleteToken` は将来のサインアウトの土台で、**自動では呼ばない**。
- **既読にしない。** IMAP は `EXAMINE`＋`BODY.PEEK[]`。**IMAP のリテラル**は行単位で読むと崩れる
  （`fetch` が先にサイズを読む）。

**WebDAV・QR**

- **`x/net/webdav` の `handlePut` は `OpenFile` のエラーを「存在しない」以外すべて 404 に潰す**
  ——書き込みの断りは `DavHandler` 側で返す（`refuseDavPut`）。判定は `OpenFile` にも残す
  （ハンドラ＝体裁の層、FS＝安全の層）。
- **⚠ QRは「他所のライブラリと同じ絵」にならない**（09-10 に半日溶かした）。segno・qrcode・w-cms は
  3つとも違う絵を出し、どれも読める（詰め草とマスク選択の差で、どちらも結果に影響しない）。
  **絵の一致を正しさの尺度にしない**——`python tools/qr_verify.py` が OpenCV で復号して確かめる
  （固定データを `-update-qr` で更新したら**必ず走らせる**）。**QRの壊れ方は静か**——誤り訂正を
  数バイト間違えても絵は出て、読み取り機が黙って諦めるだけ。
