- 親ページIDの入力導線を、文書先頭の `<m-page-info>` パネル1か所に集約（旧ヘッダーの簡易表示は廃止）。

## 開発環境の再現（自宅などで再開する手順）

```bash
# 1. 最新を取得
git pull

# 2. 依存取得
go mod tidy

# 3. 初回のみ管理者を作成して起動（ローカルHTTP検証なので Secure Cookie 無効）
WCMS_ADMIN_USER=admin WCMS_ADMIN_PASSWORD='DevPassw0rd!' WCMS_SECURE_COOKIES=0 \
  go run cmd/w-cms/main.go
# 2回目以降は環境変数なしで go run cmd/w-cms/main.go
# → http://localhost:8080 （/login にリダイレクト。上の管理者でログイン）

# 4. テスト
go test ./...
```

注意: `data/`（`cms.db` と `master/`、`auth.db`）は `.gitignore` 対象でコミットされない。別環境では初回起動で再生成され、管理者作成が必要。**前回の検証で作ったテストページ（`000001`/`000002`）はこの環境のローカルデータにのみ存在**し、リポジトリには含まれない（`000001` はcurl検証時のマルチバイト化けで親タグ名が壊れているが、別環境では再生成されないので無関係。気になれば管理コンソールの「DB再構築」で整理可能）。

## 残課題・次の作業候補（任意）

設計上「後回し」と合意済みの項目や、保守的にとどめた箇所が残っています。

1. **`<m-page-info>` の本レイアウト実装**: 現状は項目を並べただけの**仮レイアウト**。表示の作り込み（テンプレート `assets/templates/m-page-info-view.html` / `-edit.html`）は後回しと確定済み。
2. **CSS変数のさらなる移行**: トップレベルのレイアウトは `:root` のデザイントークン化済みだが、スラッシュメニュー・ブロック操作・スイッチ等の**ウィジェット内部配色とインラインstyle**は過剰なリファクタを避けて据え置き。段階的に移行可能。
3. **`updated_at` のフォーマット統一**: 新規・保存経由は RFC3339、未保存同期のフォールバックは SQLite の `CURRENT_TIMESTAMP`（`YYYY-MM-DD HH:MM:SS`）。表示は `MPageInfo.formatDateTime` が吸収するが、必要なら保存時に正規化を検討。
