## 直近のセッションでやったこと（完了済み）

**「同時編集の競合対策 Phase 1（悲観ロック・純HTTP）」を実装完了**しました（`origin/main` へプッシュ済み。最新は `642f6bc`）。
詳細は [変更履歴.md](変更履歴.md)「同時編集の競合対策 Phase 1」、確定仕様は [エディタ仕様.md](エディタ仕様.md) 10章・[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 4.3。

- 堅牢化: DSNの `_pragma` で WAL＋busy_timeout＋foreign_keys を全接続に適用（シナリオD）。採番を
  `reserveNewPageID` の `INSERT` 自動採番に統一し `GenerateNextID`(MAX+1) を廃止（シナリオE）。
- ロック基盤 `internal/cms/lock.go`（プロセス内 mutex map・競合トリガー方式・2分猶予・遅延評価）と
  `lock_handler.go`（`/api/lock`・`/api/lock-status`・`/api/unlock`・`/api/lock/force`）。`SaveAPIHandler` が
  トークン検証（他者保持/失効は409、ロック無しは許可）。
- **ロックの保持者は「エディタ個体＝トークン」単位**で識別（`fix: feeffb3`）。同じユーザーが別タブで
  同じページを開いても競合（423 busy）として検知する。busy 応答の `same_user` でトーストを出し分け。
- フロント（`assets/index.html`）: 編集モード＝ロック取得＋最新版再ロード、busy時の10秒空き待ち、保持中の
  status 10秒ポーリング、`lost`/409 の退避、`pagehide` の sendBeacon 解放、トースト通知エリア、ヘッダー sticky。
- 検証: ロックの単体テスト＋実機（Claude in Chrome）で「取得→status polling→save(token)→強制解除でlost→
  トースト＋閲覧モード切替」、および「**同一ユーザー2タブで2つ目が競合トースト＋閲覧モード復帰**」を確認。
  **異なる2ユーザーの busy 経路は単体テストのみ**（2セッション実機検証は未実施）。

### その前のセッション: 「ページ属性のサイドカー化」と「独立サイドパネル（Plan B）」（`origin/main` 反映済み）

- UNIXに倣い、ページの**属性**（親ページID・作成日時・作成者・更新日時・権限）を本文HTMLではなく
  **サイドカー `<id>.meta.json`（正本）**に保存。HTML本体は純粋な「内容」になった。
- 直前に入れていた `<m-page-info>`（HTML埋め込み方式）は撤去。ページ情報の表示・編集は、文書から
  分離した**独立サイドパネル `<aside class="rail">`**（クローム）へ集約。画面は2カラムグリッド＋
  コンテナクエリで狭いとき1カラムに畳む。
- 親ページIDの変更は `POST /api/set-parent`、属性取得は `GET /api/page-meta` を新設。保存API・新規作成APIは
  HTMLを内容のみ扱う形に簡素化（改竄復元ロジックが不要に）。
- 構造体 `PagePerms` → `PageMeta` に改名（別コミット）。一覧用の旧 `PageMeta` は `PageSummary`。
- さらに**左サイドパネル（子ページナビ、`/api/children`）**を追加して3ペイン化。左右レールは
  ページ操作バーのトグルで開閉でき、状態は **`localStorage`（`wcms.rails`）** に保存（全ページ共有・FOUC防止は
  `<head>` のインラインscript）。既定テンプレートからは本文の `<m-child-list>` を除去（コンポーネント自体は残置）。
- 左ナビの**親ページリンクを最上部**（カードの外）へ移動。重複していた**ヘッダーの「🔒 権限」ボタンを廃止**
  （権限は右パネルに常設のため）。

確定仕様は [エディタ仕様.md](エディタ仕様.md) 9章・[アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md) 2・4・8章、
経緯は [変更履歴.md](変更履歴.md) を参照。

## 開発環境の再現（自宅などで再開する手順）

```bash
# 1. 最新を取得
git pull

# 2. 依存取得
go mod tidy

# 3. 初回のみ管理者を作成して起動（ローカルHTTP検証なので Secure Cookie 無効）
WCMS_ADMIN_USER=admin WCMS_ADMIN_PASSWORD='DevPassw0rd!' WCMS_SECURE_COOKIES=0 \
  go run cmd/w-cms/main.go
# 2回目以降は環境変数なしで go run cmd/w-cms/main.go
# → http://localhost:8080 （/login にリダイレクト。上の管理者でログイン）

# 4. テスト
go test ./...
```

注意:
- `data/`（`cms.db` と `master/`、`auth.db`）は `.gitignore` 対象でコミットされない。別環境では初回起動で
  再生成され、管理者作成が必要。
- ローカル実行・プレビュー用に `.claude/launch.json`（`go run` 起動設定）を追加済み。

## 残課題・次の作業候補（任意）

1. **`<aside>` サイドパネルの本レイアウト作り込み**: 現状はカードを縦に並べた素直な構成。表示の磨き込み
   （アイコン・余白・折りたたみ既定状態など）は後追いで可能。
2. **既存データの移行**: 旧 `<m-page-info>` 方式で作られたHTML（属性がHTML内にある）が実環境に存在する場合、
   サイドカーへ移す一度きりの移行が要る。本リポジトリの `data/` はローカル限定のため通常は不要。
   ローカル検証で作った旧テストページ（`000001` 等）が気になる場合は管理コンソールの「DB再構築」で整理可能。
3. **CSS変数のさらなる移行**: トップレベルとサイドパネルはトークン化済み。スラッシュメニュー・ブロック操作・
   スイッチ等のウィジェット内部配色は据え置き。段階的に移行可能。
4. **`updated_at` の表記ゆれ**: サイドカー由来は RFC3339、フォールバックは SQLite の `CURRENT_TIMESTAMP`。
   表示は `formatDateTime` が吸収するが、必要なら保存時に正規化を検討。
5. **同時編集の競合対策（設計議論が進行中・未実装）**: 現状は last-write-wins で同ページ同時編集の
   lost update を防げない。検討メモ [同時編集の競合対策（検討中）.md](同時編集の競合対策（検討中）.md) に
   現状分析・方式・未決事項・決定ログを集約（議論で随時書き換え、最終的に仕様化したら本メモへ反映予定）。
   **これまでの合意（2026-06-21）**:
   - **悲観ロック（ページ単位）＋競合トリガー方式**: 無競合なら無期限、**他者の編集要求から2分の猶予**で
     明け渡す。編集モード移行でロック取得＋最新版ロード、保存はロックトークン検証、ロックはプロセス内
     mutex 付き map（揮発的・単一プロセス前提）。
   - **アプリ内通知エリア（トースト/スナックバー）**を新設し、ロック取得失敗（編集者へ同期トースト＝Phase 1）
     や「編集待機中」（保持者へプッシュ＝Phase 2）を表示。
   - **リアルタイム通知**は一方向中心のため **SSE を第一候補**（純 net/http）。**WebSocket が必要なら外部
     ライブラリ追加を許容**（開発方針 §1 への条件付き例外。採用確定時に承認リストへ明記）。
   - **編集モード切替トグルを画面内に常時表示**する要件（ヘッダー sticky か フローティング）。
   - 補助の堅牢化（採番の原子化＝`GenerateNextID` の MAX+1 廃止、原子的書き込み、DBのWAL/busy_timeout）は
     ロックと独立に効くため別途。
   - **残る未決**: 要求者の離脱検知（猶予キャンセル）、複数待機者の順序（FIFO 等）、任意の安全TTL。
   - **進捗**: **Phase 1（悲観ロック・純HTTP）は実装完了**（本セッション。上の「直近のセッション」参照）。
     残るは **Phase 2（即時通知＝SSE/WebSocket）** と軽微な競合 B・C。**異なる2ユーザー**の busy 経路の
     2セッション実機検証は未実施（同一ユーザー2タブの競合は実機確認済み）。
