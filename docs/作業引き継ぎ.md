## 次にやること（優先度順）

各項目は「**何を・なぜ・正本はどこか**」だけです。着手時は正本を読み直すこと
（調査済みの実装詳細は意図的に削っています——古い詳細はむしろ有害なので）。

**黙って壊れる／データが欠けるもの**

1. **起動時の索引再構築が途中で止まる穴を塞ぐ**——強制終了や停電で中断すると、次回は
   何事もなく起動するのに取り込めなかったページが「ありません」のままになり、記録も
   残りません（実測で再現）。決定は**①始めた印を残す ②途中なら次回必ずやり直す ③終わったら
   件数と所要時間を記録に残す**。**方式そのもの（ファイルから作り直す）は維持**（「1日以内で
   終わるなら」が条件）。実測値と決着は [【考察】設計総点検.md](【考察】設計総点検.md) §6。
2. **サイドカーが読めないときは自動で治さない**（設計変更）——ユーザー判断:「サイドカーが
   読めない場合、運用者が手作業で修正します。**自動で治すことはしません**。データベースから
   正本への書き込みは集計など必要な場合に限られます」。`bd7ee98` は索引から親を拾い直して
   書き戻す形で塞いだので**方向が逆**です。読めなければ運用者へ知らせて止める形へ寄せ直すこと
   （原則の正本は [アーキテクチャとDBスキーマ.md](アーキテクチャとDBスキーマ.md)）。
3. **匿名応答を404へ統一し、あわせてログイン後に元のページへ戻す**——方針は
   [要件定義書.md](要件定義書.md) §2.1 のとおりですが、**動機は「列挙対策」ではありません**——
   ユーザー回答は「（数と番号が数えられるのは）気にしません」「（権限が無いときは）ありませんと
   出るほうが良いです」。狙いは**権限の無い書類を開いた社員が迷わないこと**。**404統一だけ先に
   入れるとアドレス共有がかえって不便になる**ので、戻り先の復元と同時に。

**決定済みで小さいもの**

4. **記録の取りこぼしを埋める**——ページの新規作成・添付の保存と上書き・索引の全再構築が監査
   記録に残っていません（[要件定義書.md](要件定義書.md) の未達分）。加えてユーザー判断「誰が事務所の
   外から入ってきたか知る必要がある」により、**ログインの成功・失敗とログアウトも記録対象**。
   一方「5年遡れること」は監査記録ではなく**版管理で満たす**方針です（11番）。
5. **自動集計の表を触れなくする**（a案「そもそもボタンが出ず、触れない」）——手配状況リストと
   子ページ一覧は開くたびにサーバーが作り直す表なのに、編集モードで行・列の操作ができてしまい、
   入れた内容は保存されず再読込で黙って消えます（実測で再現）。ユーザーの但し書き:「今はまだ
   ページの構成がサンプルに過ぎません。サンプルとしてa案でお願いします」。

   保存時に告知が出るようになりましたが、他と同じ控えめなトーストです。ユーザー要望は
   「**赤色背景など**で告知してください」。
7. **公開ページのちらつきを消す**——未ログインで公開ページを開くと、ログアウトボタン・編集

   だけ）。原因は隠す手順が `/api/me` の応答後にあること。ユーザー:「治しておいてください」。

## 覚えておくこと（知らないと必ず踏む罠）

設計書に書いてあることはリンク先が正本です。ここに残すのは**知らずに書くと壊れるもの**だけ。

- **殻の `id` は接頭辞 `w-` を独占する**（`w-editor-content` 等）。本文の `id` は自由に書けるが、
  接頭辞つきは剥がされる。殻へ接頭辞なしの id を足すと `shell_id_test.go` が落ちる。
- **本文の取得口は `GET /api/load` の1つ**。計算ビューのSSRを通るのはこの経路だけなので、
  本文を読む新しい経路を足すときは注意（`/api/lock` に生HTMLを同梱していて退行した実例あり）。
  **この経路もサニタイズを通す**（素通しだと殻の要素を乗っ取られる）。一方**アンカー合成
  （`RenderAnchors`）は通さない**——合成 id が本文として保存されてしまう。
- **エディタのクロームは `.vocab-chrome`**（または本文DOM外）。シリアライザが保存しない。
  **本文DOMを走査する新しいコードは除外したか必ず確かめること**——除外は保存・目次・タイトルの印・
  安全化の比較・アンカー合成の数箇所だけで、**Goテストが固定しているのはアンカー合成だけ**
  （保存側は JS で E2E のみ）。本文の `class` はサニタイザが落とすので、この判定は誤爆しない。
- **認可の読み口はサイドカー（正本）ではなく `cms.db`（派生）**。`GetPerms` も `EffectivePublic` も
  DB を読む——**ズレたら認可は索引に従う**ので、`parent_id` の喪失は公開範囲の問題になる。
- **サニタイズ後にHTMLを足す関数が3つある**（`RenderComputedViews`・`RenderAnchors`・
  `RenderPageShell`）。それぞれ自前でエスケープ責任を負っており、規律が破れると保存型XSS。
- **DOM生成は `createElement`＋`textContent`**。文字列を組み立てて `innerHTML` へ入れない
  （かつて `escapeAttr` 頼みで保存型XSSが実際に発火し、その機構ごと廃止した）。
- **サニタイザは相対URLの `<img src>` を通す**。`/api/` への GET が状態を変えると保存型CSRF に
  なるので、**状態を変える経路は必ずメソッドを絞る**（`route_guard_test.go` が固定）。
- **`csp_test.go` はポリシー文字列しか見ていない**（`CSPProtect` を外しても通る）。配線の固定は `cmd/w-cms/route_guard_test.go` の `TestCSPIsWired`。
- **ルート表は `buildHandler()`**（`cmd/w-cms/main.go`）。main から切り出したのはテストのため。
- **プラグインテーブルにマイグレーションは無い**。`ApplySchema` は `CREATE TABLE IF NOT EXISTS`
  を流すだけなので、**列を足すと既存DBでは保存だけが 500 になる**。起動時のずれ検出＋自動再構築
  （`DriftedSchemaTables`）が入ったので、以後スキーマを変えたら**起動時に1度だけ再構築が走る**。
- **`visibleChildren` を使うテストは `:memory:` DBでは動かない**——行を回しながら1件ずつ
  `page.GetPerms` を引く形で、入れ子のクエリが別接続＝別の空DBを見て権限がフェイルクローズし、
  子が1件も見えなくなる。**ファイルDBを使うこと**（`setupTemplateAPITest` が手本）。本番はファイル。
- **テンプレート領域（ルート含む）は③計算テーブルへ載らない**（載せると仮の発注書が集計に出る）。
  除外は「プラグインを飛ばす」ではなく `SyncIndex` へ空の本文を渡す形なので、フォルダへ出し入れ
  しても古い行は残らない。判定の先祖辿りは**サイドカー＋本文HTML**——DBを見ると静かに壊れる。
- **項目の鍵は見出しの表示文字**（`th`／`dt`）。機械キーを本文へ書く属性は無い。改名すると③計算に読まれなくなるが、保存時に告知は出る（黙っては壊れない）。
- **新しい語彙はレジストリへ1件**（`internal/cms/vocab.go`）。**カスタム要素は作らない**（理由は
  [【考察】語彙モデル.md](【考察】語彙モデル.md) §9）。プラグインは計算が要るときだけ書く
  （[【ガイド】プラグイン開発.md](【ガイド】プラグイン開発.md)）。
- **インラインの script/style・`on*=` は書けない**（CSP strict）。詳細は [開発方針.md](開発方針.md) §4。
- **Gemini（明細AI解析）は有料枠のキーで運用する**——**無料枠では入力データが製品改善に使われる**
  ため、ユーザーの前提「学習に使用されないという条件で使用しています」は**課金が有効なキーである
  ことが条件**。コードは `GEMINI_API_KEY` を渡すだけで枠を判定できず、**運用側で守るしかない
  必須条件**です（[【ガイド】デプロイ・運用.md](【ガイド】デプロイ・運用.md)）。
- **ページ削除は `data/trash` への移動**（物理削除ではない）。トップページと子持ちページは不可で、
  編集ロックが要る。**復元UIは未実装**——戻すには手で `data/master` へ移してDB再構築する。
- **E2E は実バグを何度も見つけている**。`assets/` を変更したら `node --check` と `e2e/` の
  スクリプトを回す（ユーザー承認済み——毎回回してよい）。`node` が PATH に無いことがある
  （`C:\Program Files\nodejs` を足す）。
- **ローカル検証のログインは `a` / `a`**。CSRF対策で `Origin` ヘッダ必須。

## 開発環境の再現（自宅などで再開する手順）

```bash
git pull && go mod tidy

# 初回のみ管理者を作成して起動（ローカルHTTP検証なので Secure Cookie 無効）。
# ローカル開発の管理者は user=a / password=a に統一する（環境間で揃えるため。2026-07-04 決定）。
WCMS_ADMIN_USER=a WCMS_ADMIN_PASSWORD='a' WCMS_SECURE_COOKIES=0 go run cmd/w-cms/main.go
# 2回目以降は環境変数なしで go run cmd/w-cms/main.go
# → http://localhost:8080 （/login にリダイレクト。a / a でログイン）

go test ./...
```

注意:

- **ローカル開発のログイン**: `a` / `a`（**ローカル検証専用**。本番では使わないこと）。
  古い環境には `admin` / `Admin` で作られた `auth.db` が残っている場合がある（2026-07-04 に変更）。
- `data/`（`cms.db` と `master/`、`auth.db`）はコミットされないため、別環境では初回起動時に上記の
  環境変数で管理者が作られます。**「家でログインできない」は、初回の管理者未作成か別の認証情報**。
- **既存 `data/auth.db` の認証情報を忘れた／揃えたいとき**は、サーバーを止めてから以下で揃う:
  ```bash
  # 一時パッケージで internal/auth を呼ぶ（ルートに別の package main があるためサブdirで実行）。
  # 既存ユーザーなら SetPassword、未作成なら CreateUser を使う。
  mkdir -p _resetpw && cat > _resetpw/main.go <<'GO'
  package main
  import ("fmt"; "w-cms/internal/auth"; "w-cms/internal/database")
  func main(){ database.InitAuthDB(); defer database.AuthDB.Close()
    if err := auth.SetPassword("a", "a"); err != nil {
      if err2 := auth.CreateUser("a", "a", true, ""); err2 != nil { fmt.Println(err, err2); return }
    }
    fmt.Println("ローカル管理者 a / a を用意しました") }
  GO
  go run ./_resetpw && rm -rf _resetpw
  ```
- ローカル実行・プレビュー用に `.claude/launch.json`（`go run` 起動設定）を用意済み。
  プレビュー（http://localhost）でCookieが付くよう **`env: { "WCMS_SECURE_COOKIES": "0" }`** を設定してある。
