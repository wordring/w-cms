# 実装計画：ドキュメントの充実化（再現性確保）

これまでに実装された最新のアーキテクチャやUI機能（Notion風エディタ、部材手配のBOM管理など）を第三者や将来の開発者が完全に再現・理解できるよう、ドキュメントを大幅に更新・拡充します。

## 1. ドキュメントの構成

既存の `docs/コンセプト.md` がコンセプトと設計仕様を兼ねていますが、情報量が多くなってきたため、以下のように役割を分割・整理します。

1.  **`README.md`**: 概要、技術スタック、起動方法の最新化。
2.  **`docs/コンセプト.md`**: システムの思想（ファイルベース＋タグ同期）と全体図。
3.  **[新規] `docs/アーキテクチャとDBスキーマ.md`**: データベースのスキーマ構造（`pages`, `client_orders` と明細の1:N関係、`part_materials` など）および、Web ComponentsとGoバックエンドの同期・パースの仕組みの解説。
4.  **[新規] `docs/エディタ仕様.md`**: 今回追加したNotion風エディタ（ブロックラッパー、ドラッグ＆ドロップ、スラッシュメニュー、コンテキストツールバー）の詳細なDOM構造とイベント仕様。

## 2. 変更予定の詳細

### ① `README.md` の更新
*   Notionライクなブロックエディタ機能を「特徴」として追加。
*   最新のプロジェクト構造（`test.html`, `web-components.js` などのアセット）の記述を追加。

### ② `docs/コンセプト.md` のリファクタリング
*   「自由なファイルベース保存とタグによる意味付け」というコアコンセプトは残しつつ、古いDBスキーマの記述やロードマップの一部を削除し、純粋な「設計思想・要件ドキュメント」へと洗練させます。

### ③ `docs/アーキテクチャとDBスキーマ.md` の新規作成
*   **バックエンド構造**: `sync.go`, `parser.go`, `handler.go` の役割。
*   **データベーススキーマ**: `sqlite.go` に基づく最新のテーブル定義。特に発注書ヘッダ（`client_orders`）と明細（`client_order_items`）の 1:N 関係や、新設された `part_materials` について解説します。
*   **API仕様**: 手配計算API (`/api/required-materials`) などのI/O仕様。

### ④ `docs/エディタ仕様.md` の新規作成
*   **フロントエンド（Web Components と Editor）**:
    *   `<m-file>`, `<m-item>`, `<m-material>` のマークアップ仕様とレンダリングの仕組み。
    *   **ブロックエディタの仕組み**: `.editor-block` で要素をラップする理由。
    *   **Drag & Drop**: HTML5 ドラッグAPIを用いた並び替えの実装。
    *   **Slash Command (`/`)**: フローティングメニューの起動・選択機構。
    *   **Context Toolbar**: 選択ブロックに応じたアクション（`＋ 部品を追加`）の動的表示と、`stopPropagation()` によるイベント制御。
