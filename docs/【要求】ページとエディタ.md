# 【要求】ページとエディタ

**ページの持ち方**と**本文の書き方**（エディタ）の要求仕様です。

> **この文書の読み方**
>
> - 印の無い文は**要求**です（こうあってほしい、という決まり）。書くのは利用者で、
>   エージェント（AI）は矛盾を見つけたら指摘します（[開発方針.md](開発方針.md) §2）。
> - 「⚠ **いま**」で始まる段落は**実装の現状**です。こちらはエージェントが実装に合わせて直します。
> - 「（下書き）」と付いた小見出しは、利用者の言葉をもとにエージェントが置いた下書きです。
>   利用者が読んで、直したり採ったりします。
> - いつ・なぜその形になったかは、末尾の「この文書の経緯」と、`考察/` フォルダの【考察】にあります。

この文書は、2026-09-23 に [要件定義書.md](旧文書/要件定義書.md) の §2.1・§2.2・§2.4 から抜き出して作りました。

## 1. ページ

- **ページ ID は6桁の連番です**（足りない桁は 0 で埋めます。例: `000123`）。
  番号は DB の `INSERT` の自動採番で決まります。同時に作っても、同じ番号にはなりません。
- **ページは必ず親を持ちます。** 親が無いのはトップページ `000000` だけです。管理者（admin）でも例外はありません。
- **子ページの作成は、1回の要求で終わること。**
  番号を取る → ファイルを作る → DB に入れる → 編集画面へ移る、までを1回で済ませます。
- **親の付け替えは専用の API で行い、次の3つを確かめること。**
  - 新しい親が実在する
  - 自分自身や自分の子孫を親にしない（循環の防止）
  - 新しい親に書く権限がある

⚠ **いま**: 保存先は `data/master/{ID の先頭2桁}/{ID}/` です。

- 本文は `<id>.html`、属性のファイル（サイドカー）は `<id>.meta.json` です。この2つが正本です。
- 添付は `files/` サブフォルダに入れます。正本の2ファイルと同じ場所に置かないので、
  添付の名前で正本を上書きしてしまう穴が、構造として無くなります。

### 初期表示はサーバー合成

サーバーは、画面の枠（殻。本文を埋め込む外側の HTML）に本文と題を埋め込んだ、**完成した HTML** を返します。

- 開いたときに画面がチラつかないこと。
- JavaScript を実行しないクローラ（検索エンジンなどの巡回プログラム）でも、本文が読めること。

⚠ **いま**: 閲覧は JavaScript なしで完結します（2026-08-20 から）。
最後まで画面の側で描いていた計算ビュー（子ページ一覧・手配集計）も、サーバーが先に描いて返します。

### 応答の決まり

| 誰が | どうなる |
|---|---|
| ログインした利用者で、読む権限が無い | **403**（読めません） |
| ログインした利用者で、ページが存在しない | **404**（ありません） |
| **ログインしていない人（匿名）** | 読めないページと存在しないページを**区別しません**（どちらも 404） |

匿名で 404 にそろえる狙いは、**権限の無いアドレスを開いた社員が迷わないこと**です。
ページの数を数えられるのを防ぐため（列挙対策）ではありません。

> 2026-08-16 利用者:「（数が数えられるのは）気にしません」「（権限が無いときは）ありませんと出るほうが良いです」

- 404 の画面には、**ログインへのリンク**を付けます。リンクは戻り先を覚えていて、ログインしたその足で目的のページへ着きます。
  これが無いと、社員どうしでアドレスを教え合っても、行き止まりになります。
- 画面も API も、**匿名で通れるすべての道で同じ応答にそろえること**。
- 例外はトップ経由（`/` → `/000000`）だけです。入口が失われないよう、`/login` へ案内してかまいません。

## 2. エディタ

**Notion のようなブロックエディタ**を提供します。
本文は、見出し・段落・表などの「ブロック」が縦に並んだものです。

ページの開き方には、そのまま字を打てる「**書ける形**」と、読むだけの「**閲覧モード**」の2つがあります。
右上のスイッチで切り替えます（決まりは §3「ブロック単位の保護」にあります）。

- ドラッグ&ドロップで、ブロックを並べ替えられること。
  - ⚠ いま（2026-10-27）: 動かしているあいだ、ポインタが画面の上の端（固定の帯の下から 70 px）か下の端（70 px）に入ると、端に近いほど速くページを送ります。画面の外へも動かせます（`assets/app.js` の `setupDragAutoScroll`）。

    > 2026-10-27 利用者:「ブロックを移動するとき、画面に表示されている範囲外に移動させることが出来ません。可能にする方法はありませんか？」
- スラッシュメニュー（`/` を打つと出る一覧）で、ブロックを挿せること。
- ブロックごとのツールバー（書式などの帯）があること。

  見出しは H3 まで。よく使う「ファイル表示」は基本の分類に置きます。
  PDF などのファイルは、画像と同じく、ドロップ・貼り付け・「📎 画像・ファイル」でどこへでも入れられるので、
  ファイル専用の項目はメニューに置きません。

  > 2026-10-01 利用者:「スラッシュメニューが増えすぎて使いにくいです。見出しはH3程度まで必要と思います。ファイル表示は
  > 基本グループに入れると便利です。『ファイル（PDF）』は画像のドロップと同様に、どこでも可能なようにして、スラッシュメニュー
  > から消してはどうでしょう？」

- **見出し1〜3は並べ、その下に段落など。タグもよく使うので、上の方に置くこと。**

  > 2026-10-01 利用者:「スラッシュメニューは見出し1－3は
  > 並んでいて欲しいですね。その下に段落などでしょうか。タグも良く使うのでメニューの上の方に出ていて欲しいです」

⚠ **いま**（2026-10-01）:

- 「基本」の分類は**決まった並び**です（使った回数では並べ替えません）。
  並びは、見出し1・見出し2・見出し3・段落・🏷️ 可変タグ・📎 画像・ファイル・📄 ファイル表示・🎠 カルーセル・表・定義リスト・見出しの節・折りたたみ。
  カルーセルは、2026-10-07 に足しました（下の「カルーセルと画像の拡大表示」）。
- ほかの分類は、これまでどおり、使った回数の多い順です。
- 可変タグは、いちばん下の「メタ」の分類から「基本」へ移しました。
- 「ファイル（PDF）」（古い file 容器）はメニューから外しました。すでに本文にある容器は、今も読めます。
- ファイルのドロップは前からどこでもできます。画像は絵として、それ以外はファイル表示として入ります。
- 実装: `assets/app.js` の `slashBasicOrder`・`insertFilesAfter`。

### 節や折りたたみの中の要素を動かす

> 利用者:「最終的には節の中のPDFを節の外にも動かせるようにしたい」

⚠ **いま**（2026-09-29）:

- 節（見出しの節）や折りたたみの**中の要素**（段落・表・埋め込みの PDF など）にも、
  いちばん上の段のブロックと同じ ⠿（動かす）・🗑（消す）・＋（下に足す）が出ます。
  指している要素の左に浮かぶ帯です。
- 中の要素は、節や折りたたみの外へも、中へも動かせます。
- 節の最初の見出しと、折りたたみの題は、入れ物の名前です。中の要素としては動かしません
  （節ごと動かすときは、上の段の ⠿・🗑 を使います）。
- 表の種類は表そのもの（キャプション。古い本文では `data-type` の属性）で決まり、節の見出しでは決まりません。
  だから、動かしても読まれ方は変わりません。

### ⚠ ブロック挿入UIは100種規模に耐えること

全部の種類を並べただけの固定のリストでは、選べなくなります。
**絞り込みの入力・分類・よく使う順**などで、目的の形式にたどり着けること。

- **選択肢と、挿される骨組みは、語彙のレジストリ（登録簿）から作ること。**
  語彙を増やすたびに画面を手で足す運用にしません
  （[【要求】タグと表.md](【要求】タグと表.md) の3層モデル）。
- 形式を選ぶと、列の宣言から、**見出しの行の付いた骨組み**を機械的に作って挿します。

### 汎用表エディタ

`data-type` の付いた表・定義リストを編集できること。
できることは、セルの直接編集、行の追加・削除・並べ替え、列の設定、**列の型に応じた入力の手助け**です。

**型の数が増えても変わらない、汎用の実装にすること。型ごとの JavaScript は書きません。**

- 列の型は、原則として**見出しの言葉から推し量ります**（`金額`→数値、`数量`→数値）。
  通貨は独立の型にせず、数値に含めます。
  その辞書はレジストリの一部です（[【要求】タグと表.md](【要求】タグと表.md) §3）。
- `th data-type` での明示と、形式のレジストリの宣言は、見出しからの推し量りより**優先**します。
- **型に合わない入力は、知らせるだけで、拒否しません**（背景の色など）。
- **機械の属性が、見出しからの推し量りより優先されている所は、書ける形のときに背景を目立たせること。**
  「見えている文字が、型としては使われていない」ことを利用者に示すためです。
  型が合わないことの通知（赤）とは別の色にします。閲覧モードのときと公開ページには出しません。

⚠ **いま**:

- 編集できるのは、`data-type` の付いた表だけではありません。
  キャプションで種類を示す表（[【要求】タグと表.md](【要求】タグと表.md) §13）も、同じ道具で編集できます。
  表の形を見分けるのは、`assets/app.js` の `tableDefOf` です。
- 列の型は9つで、通貨の型はありません。`金額` は `number` です（`config/settings.json` の `vocabulary`）。
- パソコンでは、行・列の操作は、本文の上に固定した1本に入ります（下の「パソコンでの帯の位置」）。
  このあとの4つは、指で触る端末での出方です。
- 行・列の操作（と定義リストの項目の操作）はツールバーで、キャレット（文字を打つ位置の印）のある行の横に出ます。
- **左端のつまみ（⠿）でドラッグすると、ツールバーはその画面の位置に留まります。**
  スクロールしても、別の行へ移っても、ページを開き直しても留まります（見る人ごとに、ブラウザへ覚えます）。
- つまみをダブルクリックすると、元の「行に付いて回る」出し方へ戻ります。
- 狭い画面では2段に折り返し、画面の中に寄せます。

> ドラッグして位置変更ができるようにしてください」

> ExcelのオートSUMのように総計を出したいのです。」
>
> 2026-10-15 利用者:「オートSUMはコアの機能、ロットごとに表を分けるのは東邦拡張の機能だと思います」
>
> 2026-10-15 利用者:「SUMは必要ないです。
> 列の見出し以外全部の合計もあったほうがよいと思います。」

⚠ **いま**:

- **式の書き方**
  - `=`（全角の `＝` でも）で始まるセルが式です。
  - 列は見出しの言葉で指します（全角と半角・空白の違いは吸収します）。同じ行のその列のセルになります。
  - 行は、行の先頭の列の言葉で指します（例: `=交通費+宿泊費`）。同じ列のその行のセルになります。
  - 名前は、列を先に探し、次に行を探します。
    列にも行にもある名前は、エラーにします。そのときは `列「単価」`・`行「単価」` と書き分けます。
  - 使えるのは、四則（`+ - * / × ÷`。全角でも）と括弧と数です。関数は「合計」と `ROUND` の2つです。
    `SUM` は受けません。
- **`ROUND`**
  - `ROUND(式)` は、式の値を整数に四捨五入します。大文字と小文字は問いません。
  - 0.5 は、0 から遠い方へ丸めます。表計算ソフトの ROUND と同じです。
  - 桁の引数は受けません。
    `,` は数の桁区切り（`1,000`）と読むので、`ROUND(x, 0)` と区別できないためです。
  - 中の式が空なら、結果も空です。中のエラーは、そのまま出します。

  > 2026-10-19 利用者:「式の結果に円未満が出ますが、ROUNDという関数を用意しては？」「出来るだけハードコーディングを無くしたいです」

- **合計**
  - 書き方は4つです。
    - `=合計()`: 自分の列の、見出しの行と自分を除いた全部。
    - `=合計(上)`: 自分の列の、自分より上の全部。
    - `=合計(価格)`: 名前が列なら、その列の全部（自分は除く）。名前が行なら、その行の先頭の列を除いた全部。
    - `=合計(交通費:宿泊費)`（例）: 両端が行なら、自分の列のその範囲です。両端が列なら、自分の行のその範囲です（`：` でも）。
  - 合計は、空のセルを飛ばします。全部が空なら、結果も空です。数でないセルがあれば、エラーにします。
- **そのほかの書き方**
  - 見出しに括弧や空白のある列は、`「単価（ロット1）」` のように囲みます。
  - ほかの式も指せます。式がぐるぐる回る（循環する）ときは、理由を出します。
    同じ列に `=合計()` を2つ置くと、互いを足そうとして循環します。
  - 空のセルを指したら、結果も空です（エラーにしません。空欄は「まだ分からない」の意味です）。
- **計算する場所**
  - 本文に入るのは**式だけ**です。計算は**サーバーの1か所**（`internal/cms/formula.go`）で行います。
  - 閲覧の表示と、DB（索引・表の写し）に入る値は、同じ関数を通ります
    （[【要求】タグと表.md](【要求】タグと表.md) §14）。
- **見え方**
  - 閲覧モードでは結果を見せます。計算できなければ、赤い背景に赤の太字で「⚠ エラー: 理由」と出します。マウスを載せると式が見えます。
  - 書ける形では式のまま見せます（式の印は青い字、前回エラーだった式は赤）。
  - 書ける形から閲覧モードへ戻ると、本文を読み直して計算し直します。
  - 並べ替えは、計算した値で行います。
- ⚠ **拡張が本文の表を直に読む所は、式の文字のまま読みます**（例: 拡張が作る紙〔PDF〕・検算・集計の表）。
  業務の表の列に式を書くなら、その読み手も直すこと。
  式の結果を読む関数は `cms.FormulaTableValues` です。拡張でいま使っているのは、`ext/toho/estimate.go` の `tableValues` の1か所だけです。

#### 複数のセルを貼る（下書き）

#### 表のセルを矩形で選ぶ（下書き）

> 2026-10-04 利用者:「表のセルの選択ですが、ドラッグ矩形の範囲にあるセルを選択するように出来ますか？」

⚠ **いま**:

- 表の中でドラッグして**別のセルへ入ると**、文字の選択をやめて、セルの矩形を選びます。
  同じセルの中のドラッグは、文字の選択のままです。
- Shift を押しながらセルを押すと、前に押したセルからの矩形を選びます。
- 閲覧モードでも書ける形でも選べます（鏡の表も選べます）。
- 選んだセルでできること:
  - コピー（Ctrl+C）。タブ区切りの文字と表の HTML で写します。見出しは `th` のままです。
  - 書ける形では、消す（Delete・Backspace）・切り取り（Ctrl+X）・貼り付け（Ctrl+V）。
- 写すのは、見えている文字です（閲覧モードの式は結果、書ける形では式、入力欄は値）。
- 消す・書くのは本文のセルだけです（鏡・結合・画像のセルには触りません）。
- 選んだ印は保存されません。ほかの所を押すか、Esc かほかのキーを押すと外れます。
- 実装: `assets/app.js`「表のセルを矩形で選ぶ」。

### 表を見る（閲覧モード）（下書き）

- **表を印刷できること。**

### ブロックの種類を替える・スラッシュを打たずに（下書き）

> 2026-10-07 利用者:「既存の文字列ブロックを見出しに変えたり段落に変えたりしたい」
>
> 2026-10-07 利用者:「スラッシュを入力するのは、日本語環境ではめんどう」

⚠ **いま**:

- 書ける形でブロックを触ると出る帯（B・I・U・🔗・📎）に、「¶ H1 H2 H3」と「＋」があります。
- **¶・H1〜H3 は、キャレットのある文字のブロック（段落・見出し）の種類を替えます。**
  - 中身・ブロック ID・キャレットの位置はそのままです。
  - 節や折りたたみの中の段落と見出しにも効きます。表やリストの中では押せません。
  - いまの種類のボタンには青い印が付きます。
  - アンドゥで戻せます（Ctrl+Z）。

- ⚠ 日本語入力の / キーが出す「・」では開きません。
  「・項目」のような箇条書き（例）で Enter を押したときに、表に化けてしまうためです。

#### パソコンでの帯の位置

> 2026-10-07 利用者（PC とスマホの両方で）:「帯が出ません」「一番下では出ます。ブロックを追加する丸に+も一番下しか出ません」

> 2026-10-12 利用者:「ブロックエディタのメニューが編集の邪魔をすることがあります。テーブルの編集では、列の見出しを見ながら書くことが多いからです。いっそのこと、普通のアプリケーションのように。メニューを上部に固定してしまってはどうでしょう？」

⚠ **いま**:

- パソコン（指で触らない端末）の帯は、**本文のすぐ上に固定した1本**の中にあります。
- この1本に並ぶのは、次の3つです。
  - 文字の帯（↶ ↷・B I U・🔗・📎・¶ H1 H2 H3・＋）
  - 表の行と列の帯
  - タグの項目の帯
- 1本は、本文の流れの中で場所を取ります。だから、本文に重なりません（表の列の見出しを隠しません）。
- スクロールしても、上に留まります。ヘッダーが出ているときは、その下に留まります。
- キャレットの場所に合う組だけが押せます。合わない組は、薄くなって押せません。
  隠さないのは、隠すと表に入るたびに1本の高さが変わり、本文がずれるためです。
- 選択肢・スラッシュのメニューは、選ぶものなので、いままでどおりキャレットの近くに出ます。
- スマホ・タブレット（指で触る端末）は、いままでどおり画面の上の端のドックです。
  表の帯をつまんで動かせるのも、指で触る端末だけです。
- 丸い ＋ はブロックの下の端に出るので、背の高いブロックでは見える所に来ません。
  節の中の要素は、指すと左に出る ⠿・🗑・＋ の ＋ か、帯の「＋」で足します。
- 実装: `assets/app.js` の `initFixedBar`・`fixedBars`（`app.css` の `#w-fixed-bar`）。

### 矢印キーでブロックを渡る（下書き）

> 2026-10-12 午後 利用者:「テーブルのセルを矢印キーで移動していくと、最後のセルの次に移ったあとキャレットが無くなり移動できなくなります。ほかにもそういう
> 要素があります」

⚠ **いま**（2026-10-12 午後）:

- 原因は、ブロックごとに書ける欄が分かれていることでした。ブラウザは、欄の端を越えてキャレットを動かせません。
  表の最後のセルの → と最後の行の ↓ は欄の外へ抜けてキャレットが消え、
  段落・箇条書き・タグ・節・折りたたみの端では動きませんでした。
- いまは、まずブラウザに動かしてもらい、欄の外へ抜けた・動かなかったときだけ直します。
  - 同じ欄の中に次の場所があれば、そこへ移ります（表とタグでは、↑ ↓ は同じ列の上・下のセルへ）。
  - 無ければ、次のブロックの頭（→ ↓）か、前のブロックの終わり（← ↑）へ移ります。
- 表の鏡の列（最新単価）と、閉じた折りたたみの中（見えない所）は飛ばします。
- いちばん最後・最初のブロックでは、欄の中に残ります。
- ⚠ 直していないこと: 開いた折りたたみの中身で ← を押すと、見出しへ飛びます（ブラウザのふるまいです）。
- 実装: `assets/app.js` の `setupArrowNavigation`。E2E は `verify-arrow-keys.js`。

### ⚠ レジストリが無くても既存文書の編集が壊れないこと

レジストリが要るのは、**新しく挿すとき**と、**入力の手助け・検証**だけです。
**すでにあるブロックの編集には要りません。**

表の鍵と型は、**見出しの行が運びます**。
だから、文書そのものが持っている情報だけで、編集が成り立ちます
（「正本はファイルで、それだけで自立している」という決まりの、表での姿です）。

### オートセーブ

- **保存は、ブロックを去るときと、ページを去るときに限ること。** 細かい通信を抑えます。

  > 2026-10-12 昼 利用者:「保存は、ブロックを去る時とページを去る時に限定して、細かい通信を抑制してはどうでしょう？
  > 一文字打っただけで競合を検出しマージしろと言われても困ります」

  あわせて、「長く止まったら保存する」保険の保存は置かない、タブを隠したら保存する、と決まりました
  （[【考察】編集モードの再考.md](考察/【考察】編集モードの再考.md) §8）。
- **変更が無ければ、何も送らないこと。**
- **保存の状況（未保存／保存中／保存済）を、いつも表示すること。**

⚠ **いま**（2026-10-12 昼）:

- 打っているあいだは、「未保存」の印が出るだけです。
- 保存するのは、次のときです。
  - ブロックを去るとき（別のブロックへ移る・本文の外を押す。表は、表ごとを1つと数えます）
  - タブを隠すとき・ページを去るとき
  - 閲覧モードへ替えるとき
  - 業務のボタンを押す前
  - 操作（帯・メニュー・⠿ 🗑 ＋・改行・ドラッグ）と、アンドゥ・リドゥのあと
- ほかの人の保存を受け取りに行くときも、自分が書いている最中のブロックは送りません。
- ⚠ **保険の保存が無いので、ブロックを去らないうちにパソコンやブラウザが落ちると、そのブロックの書きかけは消えます。**
- 「保存してから何かする」道筋は、必ず保存が終わるのを待ってから進みます（`await flushPendingSave()`。中で `saveToServer()` を呼びます）。
  鏡のボタン（`postJSON`）も、押す前に同じ関数を呼びます（`window.wcmsFlushSave`）。
- 実装: `assets/app.js` の `triggerAutoSave`・`setupSaveOnLeave`・`runSync` の held。

>

> 使った実装はどうでしょう？」「一文字ずつコマンドを収集し、同じコマンドが来たら結合して圧縮していくのは、ブラウザでは処理が
> 追いつきませんか？」「日本語入力で壊れやすいのであれば、日本語文字列が確定したときにコマンドとして収集すればよいのでは？」

⚠ **いま**（2026-10-12 昼に、コマンドの形へ作り直しました）:

- **履歴は「コマンド」の列です**（上限は300）。
  1つのコマンドは、変わったブロックの前と後・並びの前と後・キャレット・名前を持ちます。
- **打った文字は、1打鍵ごとにコマンドにします。**
  同じブロックで続けて打った、同じ種類（打つ・消す）のコマンドは、1つにまとめます。
  キャレットが飛ぶ・1秒止まる・種類が替わる、のどれかで、次のコマンドになります。
- **日本語は、変換を確定したときに1つのコマンドにします**（変換の最中は、ブラウザに任せます）。
- **帯・メニュー・ブロックの ⠿ 🗑 ＋ などの操作は、押したボタンの名前で1つのコマンドにします。**
  ↶ の説明に「元に戻す：見出し2にする」のように出ます。
- どちらでもない変更も、操作の前と、打つのが止まったときに、「変更」として拾います。
- **戻すときは、そのコマンドが変えたブロックだけを戻します。**
  - 戻そうとしたブロックを相手が書き換えていたら、黙って戻さずに、両方を並べて聞きます。
  - 相手が書き換えたブロックは消しません。
  - 変わっていないブロックはそのままです（ファイル表示の枠・鏡の中身・開いた PDF が残ります）。
- Ctrl+Z・Ctrl+Y は、**本文の外にフォーカスがあっても**効きます
  （本文の外の入力欄にいるときは、その欄のアンドゥになります）。
- 帯の頭に ↶ ↷ があります（スマホには Ctrl+Z が無いためです）。押せないときは薄くなります。
- 履歴は、閲覧モードと書ける形を行き来しても残ります。
  同じタブなら、ページを読み直しても残ります（ブラウザのタブごとの保管 `sessionStorage` に、新しいものから100件まで。入りきらなければ減らします）。
  タブを閉じると消えます。
- 実装: `assets/app.js`「編集中のアンドゥ・リドゥ（コマンド）」。E2E は `verify-undo-commands.js`。

#### 文字の飾り・語彙・カスタム要素

- 文字の飾り（太字など）は、`document.execCommand` を使わず、**自前の Range 操作**で実装すること。
  出力は、いつも `<strong>`/`<em>`/`<u>` にそろえます。
- **エディタが扱える語彙（要素・属性）は、サーバーの1か所が正本です。** エディタは `GET /api/tag-schema` で受け取ります。
  エディタの側に、手書きの要素のリストを置きません。
  「許可されている要素が、保存のときに黙って消える」不具合を繰り返さないためです。
- **新しいカスタム要素は作りません。**
  ページの中に直接書く `script`・`style`・`on*=` も書けません
  （CSP strict という安全の設定のためです。[開発方針.md](開発方針.md) §4）。

### 画面

画面は**3列**です。左のレール（目次と階層）・文書・右のレール（ページの情報・権限）で、その上下にヘッダーとフッターの帯があります。
狭い画面（幅 760px 以下）では、レールを**ドロワー**（引き出しのように出し入れする形）にすること。

- **保存されるのは本文だけ**です。画面の飾り付け（クローム）は保存しません。
- **画面の枠（殻）の `id` は、接頭辞 `w-` を独り占めします。** 本文の側に `w-` の付いた `id` があれば、剥がされます。

## 3. 同時編集

何人かが同じページを同時に開いて書いても、**誰かの書き込みが黙って消えないこと**（lost update を起こさないこと）。

### ブロック単位の保護（下書き）

> 2026-10-12 利用者:「排他のために編集モードを設けたが、今後は編集モードの代わりに、閲覧に邪魔なものを表示しない目的で、閲覧モードを設けることに
> します。そして、ブロック単位の保護に変更し、保護の内容は編集中の同ブロックを同時に編集したものが居たら、警告してマージできるように
> 両方表示します。」

細かい形は、8つの問いを1つずつ聞いて決めました
（[【考察】編集モードの再考.md](考察/【考察】編集モードの再考.md) §6。どれも、エージェントの勧めを利用者が選んだものです）。

- **閲覧モードは読むだけ**（字は打てません）。
  - 表の並べ替え・見出しで畳む・カルーセル・画像の拡大は、閲覧モードのものです。
  - 書ける形との切り替えに、編集権は要りません（すぐ替わります）。
  - 開いたときの形は、その端末に憶えます。初めて開くときは、パソコンは書ける形、スマホは閲覧モードです。
- **誤って書き換えてほしくないページにも、特別な守りは置きません。**
  そのかわり、戻す道（アンドゥと版）を強くします。
- **同じブロックを2人が書いたら、両方を並べて、人が合わせます。**
  - 相手の版を上に、読むだけの形で出します。下の自分の版を直して、「これで決める」を押します。
    「相手の版にする」「自分の版にする」も選べます。
  - **表は、違うセルの変更なら、黙って合わせます。**
    同じセルを違う値にしたときと、行や列を足した・消したときだけ、並べます。
- **並べる時機は、自分がそのブロックを去って、保存を送ったときです。**
  書いている最中には並べません
  （オートセーブの節の利用者の言葉「一文字打っただけで競合を検出しマージしろと言われても困ります」から）。
  早めの通知は、黄色の背景で出します（下の「ほかの人のいるブロック」）。
- **業務のボタンも、ほかの書き手の1人として扱います。**
  いつでも動き、人の書きかけとぶつかれば、同じ形で並べます。
  自分が押すボタンは、書きかけを保存してから動きます。
- **自分が書いているブロックを相手が消したら、書きかけを残して、「消す」「残す」を聞きます。**
  これは、その場ですぐ聞きます。相手が動かした・足した・並べ替えたときは、自然に合わせます。
- **ほかの人が開いているページを消すときは、確かめのダイアログに「○○さんが開いています」と出します。**
- **アンドゥは自分の変更だけを戻します。** 版からは「このブロックだけ戻す」ができます。
- **試験を厚くします。**

  > 2026-10-12 利用者:「込み入ってるのでテストは十分にお願いします」（【考察】§6「試験の約束」）

⚠ **いま**（2026-10-12 に作りました。[【考察】編集モードの再考.md](考察/【考察】編集モードの再考.md) §7）:

- 画面は編集権を取りません。保存は `POST /api/sync` だけです。
- サーバーは、ページごとの書き込みのロック（1回の書き込みのあいだだけの鍵）の中で、
  元の指紋（サーバーが前に渡した、ブロックの中身の印）と比べて、ブロック単位で当てます。
- ぶつかったら、ブロックの上に枠（相手の版・読むだけ）と、
  「これで決める」「相手の版にする」「自分の版にする」が出ます。
  消されたときは「消す（相手に合わせる）」「残す」が出ます。表の違うセルは黙って合わせます。
- 書ける形でも、ほかの人の書き込みの通知を受けて、その場で受け取ります。
  ただし、自分が書いている最中のブロックは、去って送るまで待ちます。
- 閲覧モードは読むだけです。開いたときの形は端末に憶えます（`localStorage` の `wcms.mode`）。
- 版は「ブロックごとに見る」→「このブロックだけ戻す」。
- ページを消すときは、開いている人の名前を出します（`GET /api/page-watchers`）。
- 実装: `internal/cms/handler_sync.go`・`block_sync.go`・`body_lock.go`。

### ほかの人のいるブロック（下書き）

> 2026-10-12 昼 利用者:「他人が同じブロックにキャレットを置いている、あるいはすでに文字を打ち込んでいるような場合は、早期に警告して欲しいです」
>
> 2026-10-12 昼 利用者:「置いただけで背景色を黄色系の彩度の低い色にしては？説明が多すぎるのでシンプルに」（表は「表ごと」）

⚠ **いま**（2026-10-12 昼）:

- 書ける形のタブは、キャレットのあるブロック（いちばん上の段）が変わるたびに、サーバーへ知らせます（`POST /api/presence`）。
- 同じページを開いているほかのタブでは、そのブロックの背景が**彩度の低い黄色**になります。
  - 文字の説明は出しません。名前は、マウスを載せると出ます。
  - 黄色になるのは、書ける形のときだけです。
  - 表は、表ごと黄色になります（セルを移っても、表のままです）。
- キャレットを置いただけで出します。
- 閲覧モードへ替える・タブを隠す・タブを閉じる、で消えます。
- 実装: `assets/app.js` の `renderPresence`・`updatePresence`、`internal/cms/page_events.go` の `PresenceAPIHandler`。

### ほかの人の書き込みを知らせる（下書き）

> 2026-10-07 利用者:「誰かが書き込むと、同じページを見ているほかの人に再読み込み通知が送られて、編集されたブロックだけ再読み込みできますか？」

⚠ **いま**:

- **閲覧モードで開いているタブ**には、そのページの本文が書き換わると、通知が出ます。
  - 文は「○○がこのページを更新しました（N か所）」です。
    自分の別のタブや、自分の押したボタンで変わったときは、「あなたの操作で」と出ます。
  - 「変わったところを読み込む」を押すと、**変わったブロックだけ**を差し替えて、しばらく薄い黄色で示します。
    変わっていないブロックはそのままです（畳んだ見出し・開いた PDF・並べ替え・鏡の絞り込みが残ります）。
  - 入力中の欄があるブロックは差し替えずに、そう伝えます（入力を終えて、もう一度押します）。
- **書ける形で開いているタブ**には、通知の札は出ません。変わったブロックを、その場で受け取ります（上の節）。
- 知らせるのは、本文を書く API です（エディタの保存・機械の書き換え・版を戻す）。
- 書く人が打ち続けているあいだは待ちます（長くても、最初の書き込みから約10秒）。
  読み直して、変わったところが無ければ、何も出しません。
- スマホのスリープなどで通信が切れていたあいだの書き込みは、つなぎ直したときに気づきます。
- 通知が出ないもの:
  - 添付の上書き（ローカル編集）。本文は変わらないためです。
  - ほかのページが変わったせいで、鏡の中身だけが変わったとき。
  - ログインしていない閲覧（公開ページ）。
- 実装: `internal/cms/page_events.go`（`/api/page-events`）・`assets/app.js`「ページの更新の通知」。

### 道具のために残っているページ単位のロック

2026-10-12 まで、同時編集は「**ページ単位の悲観ロック＋SSE**」で守っていました。
1人がページの編集権を握り、ほかの人は空くまで待つ形です。
画面はもうこの形を使いませんが、**編集権の API（`/api/lock` 一式）と `/api/save`・`/api/save-block` は、道具のために残してあります**
（ワンノートの移行の道具・テンプレートの取り込み・E2E）。

残っているロックの決まりは、次のとおりです。

- 編集権を握っている人は、エディタの個体ごとのしるし（トークン）で見分けます。同じ利用者の別のタブも、別の個体です。
- ほかの人が握っていれば **423** を返します。
- 待つ人がいなければ、期限はありません。待つ人が現れたら、**2分の猶予**で強制的に明け渡します。
- admin は**強制解除**できます（監査の記録が残ります）。
- ロックは、**動いているプロセスの中だけの状態でかまいません**（再起動で消えてもよい）。

⚠ **いま**:

- 業務のボタンには、「誰かが開いていれば断る」関門が残っています
  （`editlock.RefuseWhileEditing`・`editlock.Locks.EditorOpen`）。
  ブラウザはもう握らないので、道具が一瞬握るとき以外は、素通りします。
- 道具が握ったロックの持ち主かどうかは、`RequireEditLock` が確かめます（添付・権限・削除などの API）。
- それまでは、本文の保存だけでなく、権限の変更・所有者の変更・親の付け替え・公開の切り替え・
  **添付のアップロード**・**ページの削除**も、同じロックで順番に通していました
  （2026-08-21 まで、他人が編集中のページへ第三者が添付を足せていたためです）。
  いまは、ページごとの書き込みのロックと、違いだけを送る保存（`/api/sync`）が、その守りを引き継いでいます。

## 4. 版

- **保存した本文の版を残し、戻せること**（リビジョン／リバート）。
- **版の対象は、本文の HTML だけです。** 権限・所有者・親は巻き戻りません。
  この線引きが安全の要です。版を戻して権限まで戻ってしまうと、権限の決まりを版で回り込めてしまいます。

### 帳票の保持年限

> 2026-09-23 利用者:「帳票の保持期限は**企業が過去に問題を起こしていた場合、最大10年**です。
> **個人が5年、法人が7年**です。」

| 誰が使うか | 保持年限 |
|---|---|
| 個人 | **5年** |
| 法人 | **7年** |
| 法人（過去に問題を起こしている） | **最大10年** |

**年限は1つには決められないので、設定で持ちます。**
w-cms は、開発元でない企業も設置するソフトウェアです
（[【要求】w-cmsとは.md](【要求】w-cmsとは.md) §1「特定用途向けに拡張できる」）。
設置した先が個人か法人か、過去に何があったかは、w-cms には分かりません。

⚠ **いま**: **版は消しません。** 消す仕組みそのものがありません。

- 2026-09-23 に、版を消す仕組みごと取り除きました。

  > 2026-09-23 利用者:「**消す機構も持たないで良いです。もしも消す必要が出来たら、エージェントで消します**」

- 消さない理由は、間違えたときの被害が釣り合わないからです。

  | 間違い | 何が起きるか |
  |---|---|
  | 年限が短すぎた | **保持の義務を破ります。しかも、消えた版は戻りません** |
  | 年限が長すぎた | ディスクを使うだけです（gzip で縮めると小さい） |

- あとから年限を延ばしても、すでに消えた版は戻りません。
  だから、初日から安全な側に倒しておき、運用する人が自分の事情に合わせて短くする、という向きが正しいと考えます。
- 経緯は [【考察】アンドゥ・リドゥ.md](考察/【考察】アンドゥ・リドゥ.md) §4・§5 にあります。

### 保持の決まり

- **保持は、全ページ一律にします。**
  帳票だけに絞るには「どれが帳票か」の判定が要ります。その判定がずれると、保持の義務のほうが破れてしまいます。
- 年限で切るときは、うるう年で目減りしないよう、**1年を366日で数え、端数は必ず長い側へ**倒すこと。
- **添付には、版の消去はかかりません**（添付には版がありません。[【要求】添付.md](【要求】添付.md) §6）。
  消える恐れがあるのは、本文の版だけです。

**監査ログでは、保持の代わりになりません。**
実際に測ると、監査の記録 587件のうち 529件（90%）が編集中の自動保存でした。
管理の画面の「最近200件」は、約4時間分しか遡れていませんでした。
