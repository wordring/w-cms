## 1. なぜ考えたか

インライン装飾（太字・斜体・下線）を**保存できるようにする**にあたり、許可リストが実際に効いてくる。着手前は
B/I/U ボタンが押せて画面上も変わるが、エディタのシリアライザが `innerText` しか出さないため**保存されず、
再描画で消えていた**（＝ボタンが事実上機能していなかった）。同時に現行の許可リストを棚卸ししたところ
**4件の不整合**（§3・いずれも実証済み）が見つかったので、装飾対応と合わせて整理した。

## 2. 判断の物差し

既存の設計原則から、5つの基準を導いた。**以後、許可リストを増減するときはこの5つで説明できること。**

| # | 基準 | 由来 |
|---|---|---|
| **A** | **自己説明的か**——正本HTMLを読んだ人に意味が伝わるか。意味も属性も持たない入れ子はノイズ | [コンセプト.md](コンセプト.md)「HTMLが正本」「grep/diffが効く」 |
| **B** | **役割は属性・見える値は中身**か | [【考察】語彙モデル.md](【考察】語彙モデル.md) §2 |
| **C** | **安全か**——実行・外部通信・UI乗っ取りの経路にならないか | [本文サニタイズ設計.md](本文サニタイズ設計.md) |
| **D** | **往復で安定するか**——シリアライズ⇄サニタイズが冪等か。同じ見た目に2表現があると差分判定が揺れる | ブロック単位保存・アンドゥのスナップショット比較が壊れるため |
| **E** | **語彙の役割分担に沿うか**——業務の意味づけは `data-*` マーカー付き標準HTMLが担い、同じ役割を素のHTMLと二重に持たない | [【考察】語彙モデル.md](【考察】語彙モデル.md) §3（検討当時は「カスタム要素の領域と重複しない」。担い手が標準HTML側へ移り、2026-08-20 にカスタム要素は0種になった） |

**Dは今回とくに重い。** 「変更が無ければ保存しない」判定とアンドゥのスナップショット比較は、
どちらもシリアライズ結果の文字列一致に依存している。表現が揺れると無駄な保存や誤ったアンドゥを招く。

## 3. 棚卸しで見つかった不整合（実証済み → すべて解消）

| # | 問題 | 基準 | 実証 | 決着 |
|---|---|---|---|---|
| ① | **プロトコル相対URL `//evil.example/x` が通る** | C | `<img src="//evil.example/beacon.png">` が素通り。`safeURL` がスキーム空を「相対」と判定するため | **修正**（`isRelativeURL` が拒否） |
| ② | **`h4`〜`h6` が三者で食い違う** | D | 目次は h1〜h6 を拾い、サニタイザも通すが、**エディタの `TEXT_BLOCK_TAGS` が h1〜h3 のみ**。貼り付けた h4 は目次に出るのに次の保存で消える | **修正**（下記） |
| ③ | **`div`/`span` が意味も属性も無いまま残る** | A | `<div><span>x</span></div>` がそのまま通る。`class`/`id`/`style` は落とすので残っても情報量ゼロ | **残す**と決定（§5） |
| ④ | **`b`/`i` と `strong`/`em` が二重に許可** | D | 同じ見た目に2表現。エディタが片方を出し、貼り付けがもう片方を持ち込むと差分が揺れる | **両方残す**と決定（§5） |

①は**外部への情報漏れ**（閲覧者のIPと閲覧時刻が第三者に渡るトラッキングビーコン）になりうる。CSP
`default-src 'self'` が実行時にブロックするが、二層防御の趣旨からは許可リストでも弾くべき、と判断した。

**②の直し方に一般則がある。** 手書きの `TEXT_BLOCK_TAGS` を廃し、「**宣言は1つ、エディタとサニタイザが
両方それに従う**」形（`GET /api/tag-schema`）へ寄せた。宣言元は
[htmldoc/sanitize.go](../internal/cms/htmldoc/sanitize.go) の1箇所で、そこを直せばエディタが追随する
——**手書きの要素リストをエディタ側に置かない**（[本文サニタイズ設計.md](本文サニタイズ設計.md) §7）。
インライン装飾も `document.execCommand` をやめ、Range を直接操作して常に `<strong>`/`<em>`/`<u>` を出す実装へ
置き換えた（[エディタ仕様.md](エディタ仕様.md) 4.1）。

## 4. 決定（2026-08-04）

**タグは寛容・属性は厳格**——要素は危険でなければ許可し、属性は必要なものだけ許可する。理由と、どの要素・
属性がどちらに落ちたかは [本文サニタイズ設計.md](本文サニタイズ設計.md) §5.0〜§5.5 が正本。

## 5. 採らなかった提案とその理由

- **`span` のアンラップ** → **不採用**。「危険が無い限り残す」方針を採ったため。情報量ゼロという指摘
  （基準A）は妥当だが、**貼り付けた内容の構造を保つ利益**を優先した。`div` も同じ理由で残す——落とすと
  ブロック境界が消えて行が繋がる実害がある。
- **`b`→`strong`・`i`→`em` の正規化** → **不採用**。同じ方針による。なお正規化しなくても**往復の安定性
  （基準D）は保たれる**——シリアライザがDOMの内容を忠実に出力する限り、表現が2種類あっても文字列は一意に
  定まるため。正規化は表現統一の「あったら良い」であって、正しさの要件ではなかった。
- **`title` をグローバル属性にする** → **不採用**。情報が hover に隠れて自己説明性を損なう（基準A）ので
  `a`/`img` 以外へは広げない。**`lang` `dir` `aria-*` `role`** → **見送り**（現状用途が無い。必要になってから）。
- **`dl`/`dt`/`dd` の不採用案** → **覆した**。検討時は「名前:値はカスタム要素の領域」（当時の基準E）として
  落とす案だったが、「タグは寛容」の方針で採用。**現在はむしろ `<dl data-type>` が名前:値語彙の第一候補**
  （[【考察】語彙モデル.md](【考察】語彙モデル.md) §5.3）。基準Eの担い手が入れ替わると、同じ基準から逆の
  結論が出る例。
- **役割の分け方**: 打ち消し線 `s` は**純粋な視覚表現**として使い、ページの「取消」状態は名前:値のページメタが
  表す（基準E）。素の `<table>` は貼り付けた資料、業務明細は `data-type` を付けた表——**同じ標準要素を
  マーカーの有無で見分ける**。

## 6. 残る検討事項

スラッシュメニューに `h2`/`h3`・リスト・素の表を出すか。**2026-08-21 時点でも未対応**——手書き項目は `h1` と
`p` の2つだけで、他は貼り付けか手動でしか作れない。レジストリ側の形式は `/api/tag-schema` の `vocab` から
動的生成されるようになったので、残るのは素の要素の項目追加と、絞り込み・分類による到達性（正本は
[エディタ仕様.md](エディタ仕様.md) §3）。なお検討時の「追加候補」は**すべて採用済み**（`sub` `sup` `mark`
`caption` `th[scope]` `tel:`）。以後の増減は §2 の物差しで判断する。
