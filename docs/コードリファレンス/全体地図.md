# 全体地図

対象コミット `4eb3514`（2026-08-17・htmldoc 切り出しまで反映）。数値は実測。

## 30秒で掴む

- **単一バイナリのGoサーバー**（`cmd/w-cms`）が、ポート 8080 で HTTP を受ける。外部サービスは
  PDF解析の Gemini のみ（任意）。
- **ページの正本はファイル**。本文は `data/master/<先頭2桁>/<id>/<id>.html`、属性（所有者・権限・
  親・作成/更新）は同じフォルダの `<id>.meta.json`（サイドカー）。
- **SQLite は使い捨ての索引**。`data/cms.db` はファイルから再生成できる（`RebuildDatabase`）。
  再生成できない情報（ユーザー・セッション・監査ログ）だけが `data/auth.db` にある。
- **画面はサーバー合成**。`GET /{id}` が `assets/index.html`（殻）に本文を埋めた完成HTMLを返す。
- **フロントはバニラJS＋Web Components**。ビルド工程なし。`assets/app.js` がエディタ本体。
- **同時編集はページ単位の悲観ロック**。プロセス内メモリ＋SSE。

## レイヤと依存（Goパッケージ）

```
cmd/w-cms/main.go            ルーティングと起動
        │
        ▼
internal/cms                 HTTPハンドラ層＋プラグイン実装
   │   handler_save/view/tree/meta・perms_admin・pdf_handler
   │   shell・sync・parser・sanitize（語彙の合成）・block
   │   plugin.go（レジストリ）＋ plugin_*.go（実装7本）
   │
   ├──▶ internal/cms/htmldoc   サニタイズの実装（純粋なHTML部品・語彙は注入）
   │
   ├──▶ internal/cms/editlock   編集ロック（状態＋HTTP/SSE）
   │        │
   │        ▼
   └──────▶ internal/cms/page   保存パス・サイドカー・認可・添付配信
                 │
                 ▼
            internal/auth        セッション・CSRF・CSP・ユーザー/グループ
                 │
                 ▼
            internal/database    SQLite接続とコアテーブル定義
```

**逆流はありません**（`page` はハンドラを知らない、`editlock` は `cms` を知らない、
`htmldoc` はプラグインを知らない）。

## データの正本性（この設計の背骨）

| データ | 正本 | 派生 |
|---|---|---|
| ページ本文 | `data/master/.../<id>.html` | `pages.title`（見出しから抽出） |
| ページ属性（所有者・権限・親・作成/更新） | `<id>.meta.json`（サイドカー） | `pages.parent_id` ほか・`page_perms` |
| カスタム要素由来の業務データ | 本文HTML | 各プラグインのテーブル |
| ユーザー・セッション・監査ログ | `data/auth.db` | **なし（再生成不可・要バックアップ）** |
| 本文で使える語彙 | `htmldoc/sanitize.go` の `structuralElements` ＋ 各プラグインの `Tags()` | `GET /api/tag-schema` |

`data/cms.db` は消しても `data/master` から再生成できる（起動時に空を検出すれば自動再構築）。

## 覚えておくべき不変条件

1. **サニタイズは二層**。保存時（`SanitizeReport`）と描画時（`Sanitize`）。片方だけにしない。
2. **語彙は1箇所**。エディタのシリアライザは `/api/tag-schema` に従う。手書きの要素リストを
   フロントに置かない（置くと「画面に出るのに保存で消える」が再発する）。
3. **添付は `.pdf` のみ**。ページのフォルダには本文とサイドカーが同居しているため、
   任意の名前・種類を書けると権限昇格と保存型XSSになる（2026-08-05 に実際に塞いだ）。
4. **フロントでテンプレートに値を差すときは `escapeAttr`**。サニタイザでもCSPでも止まらない。
5. **カスタム要素は Light DOM**。Shadow DOM に描くと保存時のDOM走査から外れる。
6. **`page` は上位（ハンドラ・ロック）を知らない**。逆向きの import を足さない。

## 既知のねじれ

- ~~**`cms` パッケージ内の循環**~~ **解消済み（2026-08-17）**: サニタイザを
  [internal/cms/htmldoc](../../internal/cms/htmldoc/sanitize.go) へ切り出し、カスタム要素の
  語彙は `htmldoc.New([]TagSpec)` の引数として**注入**する形に反転した。`htmldoc` の import は
  `x/net/html` と標準ライブラリのみで、`PluginTags()` を呼ぶのは cms 側の合成ラッパ
  （[sanitize.go:34](../../internal/cms/sanitize.go)）1箇所。
- **暗黙の初期化順序**: 語彙は `sync.Once` で初回利用時にキャッシュされる。「全プラグインの
  `init()` 登録 → 最初のサニタイズ」という順序が型で表現されていない。
- **ページIDの正規化漏れ**: 権限判定は `strconv.Atoi` を通すが、ファイルパスには受け取った
  文字列をそのまま使う（`"0012"` でも通る）。トラバーサルにはならないが正本の名前が揺れる。
