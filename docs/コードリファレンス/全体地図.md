`docs/コードリファレンス/` は**実装の現状を写した文書群**です。設計の「なぜ」は各設計書が持ち、
ここは「いま何がどうなっているか」だけを扱います。

> **`go doc` が第一の窓口です。** 各パッケージには冒頭コメントを置いてあるので、
> まずそちらを読んでください——本ファイルはパッケージを**横断する**話（依存の向き・
> 正本性・ねじれ）を担当します。
>
> ```bash
> go doc ./internal/cms          # パッケージの概説＋公開APIの一覧
> go doc ./internal/cms Observer # 特定の型・関数の詳説
> go doc -all ./internal/cms/page  # そのパッケージの全公開APIをコメントごと
> ```

> ## ⚠ この文書群は一度畳まれています（2026-08-21）
>
> 手書きの「現状の写像」は実装と同じ速度で陳腐化し、**行数主張30件中16件が誤り・
> 一部は内容が逆**という状態になりました——読んだ人が正しい実装をバグと誤認しかねない、

>
> - **説明の本体は `go doc`（＝コードの中）へ置く。** パッケージの冒頭コメントは
>   コードと同じファイルにあるので、実装を変える人の目に入ります。この文書群が担うのは

>   コードが正しく、文書が古いのです。
> - **古くなったら直すのではなく作り直す**（スキル `/code-reference`）。

## 2. パッケージと依存の向き

`go list -f '{{join .Imports "\n"}}'` の実測。**循環はありません。**

```
cmd/w-cms
  └→ ext/mailgraph, ext/sheetmetal（ext_*.go のブランク import だけ）
  └→ internal/auth, internal/cms, internal/cms/editlock, internal/cms/page, internal/database

ext/mailgraph          →  internal/auth, internal/cms, internal/cms/page, internal/database
ext/sheetmetal         →  internal/auth, internal/cms, internal/cms/page, internal/database

internal/cms
  └→ internal/auth, internal/cms/editlock, internal/cms/htmldoc, internal/cms/page, internal/database

internal/cms/editlock  →  internal/auth, internal/cms/page
internal/cms/page      →  internal/auth, internal/database
internal/auth          →  internal/database
internal/cms/htmldoc   →  （w-cms の依存なし）
internal/database      →  （w-cms の依存なし）
```

**守るべき向きが3つ**あります。

- **`cms` は `ext/` を import しない。** 拡張は `init()` で自分をコアの登録表へ
  足すだけで、コアは拡張の存在を知りません（`Register`・`RegisterVocab`・
  `RegisterIntake`・`RegisterView`・`RegisterMailer`）。**コアが口（interface）を宣言し、
  拡張が実装を差し込み、使う側はコアに尋ねる**——`cms.Mailer` がその形の見本です
  （`mail.go` が口、`ext/mailgraph` が実装、返信の記録はコアの `SendMail` を呼ぶ）。
  取り込むかどうかは `cmd/w-cms/ext_*.go` のビルドタグ（`!minimal` / `!nomail`）が決めます。

- **`htmldoc` は誰も import しない。** 本文の語彙（許可要素・属性）の唯一の正本で、
  アプリのドメイン（レジストリ・プラグイン）を知りません。**`htmldoc` から `cms` を
  import しないこと。**
- **`editlock` は `cms` を import しない。** 版のチェックポイントを打つために
  「ロックを手放した」という出来事だけが必要なので、関数変数 `editlock.OnRelease` で
  受けます（設定するのは `cms/version.go` の `init`）。これで一方向のままになります。

外部の直接依存は6つ（`go.mod` の実測）: `modernc.org/sqlite`・`golang.org/x/crypto`・
`golang.org/x/net`・`golang.org/x/text`（`intake_eml.go`・`zip_list.go`・`normalize_text.go`
が直接利用）・`github.com/google/generative-ai-go`・`google.golang.org/api`。
[../開発方針.md](../開発方針.md) §1 の一覧と一致しています。

> **メール送受信は外部依存を1つも増やしていません**（2026-09-03）。受信は Graph の
> REST（`net/http`＋`encoding/json`）、送信は SMTP＋XOAUTH2（`net/smtp`・`mime`・
> `mime/multipart`・`crypto/tls`）——すべて標準ライブラリです。当初「IMAPライブラリを
> 承認する」と決めましたが、実物のメールヘッダから Exchange Online と判明し、
> どのみち OAuth2 が要るため自前の HTTP/SMTP に落ち着きました。

## 3. 何が正本か（不変条件）

**この節がこの文書群のいちばんの価値です。** 破ると静かに壊れる約束が並びます。

| 対象 | 正本 | 派生 | 破ったときに起きること |
|---|---|---|---|
| ページの**内容** | `data/master/<先頭2桁>/<id>/<id>.html` | `pages.title`・`vocab_index` | — |
| ページの**属性**（所有者・グループ・mode・公開・親・作成/更新） | サイドカー `<id>.meta.json` | `pages.parent_id` 等・`page_perms` | 派生から正本へ書き戻すと、欠損が派生の内容で埋まって「見た目は健全なのに中身が違う」状態になる |
| **添付** | `<id>/files/<生成ID>.<拡張子>`（2026-08-31 以前の添付はページフォルダ直下に残る） | — | 生成IDは保存名＝URL＝リンクブロックの `data-id` の3役（`GeneratedAttachmentID`）。参照 `ページID-ID` がブロックにも添付にも届くのはこの一致のおかげ |
| **本人確認**（利用者・グループ・セッション・監査記録） | `data/auth.db` | — | **ファイルから再生成できない**。`data/master` とは別に必ずバックアップ |
| 本文の**語彙**（許可要素・属性） | `htmldoc` の `structuralElements` | `/api/tag-schema` の応答 | エディタとサーバーで許可がずれ、保存のたびに値が消える |
| **形式**の宣言（`data-type` と機能見出しの意味） | `vocab.go` の `vocabRegistry` | スラッシュメニュー・挿入骨格・型推論・鏡型/種まきの担当判定 | 表示名（`DisplayName`）を変えると、その言葉を見出しに持つ既存セクションが形式なしになる（告知は出ない） |
| **設定**（語→型の推論辞書・添付上限・汎用添付の拡張子） | `data/settings.json`（`settings.go`） | `/api/tag-schema` の `type_inference`・②索引の型解決 | 在るのに読めない・不正なら**起動を止める**——既定値で黙って上書きすると運用者が足した語が消えるため |
| 版 | `versions/<版ID>.html.gz` ＋ `.json` | — | 対象は本文HTMLだけ。リバートで権限・親は巻き戻らない |
| **業務データ** | 本文の見える文字（`th`／`dt` の表示文字が鍵） | `vocab_index`（**唯一の行き先**・D-1） | ドメイン表は無い。③計算（部材手配）は `vocab_query.go` 経由で索引を読む |
| **ページ間の参照** | 本文の「名前：値」タグ（値は `ページID-ブロックID`） | `vocab_index` の1行 | 参照専用テーブル（`page_refs`）は**無い**・D-4。描画（`ref_render.go`）と集計スコープ（`ref_scope.go`）が**同じ文法**（`parseRefValue`）を使う——別に持つと「画面ではリンクなのに集計に乗らない」食い違いが出る |
| **メールの資格情報** | `data/mail/<利用者>.json`（リフレッシュトークンだけ） | — | アクセストークンは記憶の中だけ。**ログにも応答にも出さない**。権限は 0600 を指定するが **Windows では効かない**（実測 666）ので、本番機はOSのアクセス制御が実質の守り |

派生に関する規律:

- **`cms.db` は使い捨て**。`data/master` から丸ごと作り直せます（`RebuildDatabase`）。
  ファイルから再生成できない値をここへ持たせてはいけません。テーブルは
  `pages`・`page_perms`（コア）＋ `vocab_index`（観察係）＋ `rebuild_state`（再構築の進行印・
  `dropAllTables` の対象外）の4つだけです。
- **⚠ 認可の読み口は正本ではなく派生**——`page.GetPerms` も `page.EffectivePublic` も
  `cms.db` を読みます。**ずれたら認可は索引に従う**ので、`parent_id` の喪失は
  そのまま公開範囲の問題になります。
- **派生（DB）から正本（サイドカー）へは書き戻さない**（2026-08-21 決定）。
  サイドカーが読めなければ `requireSidecar` がエラーを返し、本文保存・親の付け替え・
  権限変更が**止まります**（運用者が手で直す）。
- **正本を書く経路は `page.WriteFileAtomic`**（一時ファイル＋rename）。本文・サイドカー・
  添付・版・設定・メールのトークンの書き込み**12ファイル・17箇所**がこれを通ります
  （`os.WriteFile` は残っていません）。
- **重複検知に専用テーブルは無い**——取り込み済みかは、通信記録ページの可変タグ
  `メッセージID` を `vocab_index` から逆引き（`PagesByTag`）して決めます。
- **`:memory:` DBは接続ごとに別のDB**。行を読みながら中で別のクエリを投げると
  カーソルが接続を握ったままなので**空の別DBに当たり、絞り込みが静かに全部落ちます**
  （2026-09-03 に本番コードで踏んだ）。`view_unhandled.go` と `ref_scope.go` は
  **先に読み切ってから絞る**形にしてあります。

## 5. 既知のねじれ・注意点

- **`RequireAdmin` が2つある**——`auth.RequireAdmin`（`admin_handlers.go` から6箇所）と
  `page.RequireAdmin`（`editlock/handler.go`・`handler_meta.go`・`perms_admin.go` から）。
  同名で同じ意味ですが、パッケージが違うだけです。
- **添付の配信口が2つある**——旧形 `/data/master/…`（`page.DataFileHandler`・互換）と
  きれいなURL `/<ページID>/<名前>`（`RootHandler` → `page.ServeCleanAttachment`・`files/` だけを読む）。
  応答ヘッダの規律は `setAttachmentHeaders` を共有。埋め込み（`<img src>`）のサニタイザ許可も
  両方の形（`htmldoc.safeEmbedURL`）。
- **`Sanitize` は薄い委譲**——`cms.Sanitize` は `htmldoc` の `Sanitizer` を呼ぶだけ。
  許可リストを直すときは `htmldoc/sanitize.go` を見ます。
- **プラグインテーブルにマイグレーションが無い**——`ApplySchema` は
  `CREATE TABLE IF NOT EXISTS` を流すだけ。起動時のずれ検出（`DriftedSchemaTables`）＋
  自動再構築が入っているので、**スキーマを変えたら起動時に1度だけ再構築が走ります**。
- **コアテーブルには手書きのマイグレーションがある**——`database/sqlite.go` の
  `coreMigrations`（`ALTER TABLE ... ADD COLUMN`。重複列のエラーは無視）。
- **観察係は1人だけ**（`vocabIndexPlugin`）。拡張の `materialsPlugin`・`mailPlugin` も
  `Register` を通りますが `Observer` を実装しておらず（`Schema`/`Tables` は nil）、
  `RouteProvider` としてAPIを足すだけです。**業務データの行き先は `vocab_index` 1本**（D-1）。
- **`WalkElements` を回すファイルは7つ**（grep の実測・定義と再帰呼び出しを除く）——
  `anchor.go`・`parser.go`・`plugin.go`（`TagValue`）・`ref_render.go`・`sanitize.go`
  （`ShellPrefixedIDs`）・`shell_public.go`（`ExtractDescription`）・`vocab_notify.go`。
  いずれも索引・計算のための走査ではありません。本文を走査する新しいコードを書いたら、
  たいてい配送係（`walk.go`）を使うべき場面です。
- **dt/dd の対を読む処理は `eachDLPair`（`vocab_index.go`）の1つだけ**——呼び手は5ファイル
  （`plugin.go`・`ref_render.go`・`template_new.go`・`vocab_index.go`・`vocab_notify.go`）。
  入れ子 `section` へ降りるかは引数 `skipSection` で分かれます。
- **section の素の中身を拾う切り分けは `eachPlainVocabChild` の1つだけ**——索引・種まき・
  改名告知の3者が共有。ここが割れると「索引には載るのに告知されない」ずれが生まれます。
- **`walkState.Ancestors` / `Closest` に使い手がいない**（テスト以外の呼び出し0件・
  2026-09-04 も再確認）。ファイル容器（`data-type="file"`）を親から拾う用途で作られ、
  容器の廃止（2026-08-31）で空いたまま残っています。
- **`Locks.Validate` を直に呼ぶのは保存の2口だけ**（`SaveAPIHandler`・`SaveBlockAPIHandler`。
  トークンは JSON 本文の `token`）。他の変更操作は `editlock.RequireEditLock`
  （ヘッダ `X-Lock-Token` か `token` クエリ）を通ります。
- **編集ロックを要求しない書き込みがある**——取り込み（`serveIntake`）・🤖 解析
  （`AnalyzeAttachmentAPIHandler`）・整理の実行（`FileDrawingsAPIHandler`）・
  メール取り込み（`MailImportAPIHandler`）・返信（`MailSendAPIHandler`）。
  いずれも**人が編集中の本文を奪わない**（子ページを作る・別ページへ足す）ので、
  `RequirePageWrite` だけで通します。**整理の併合だけは既存ページの本文を書き換える**
  ので、ここは今後ロックを要るようにするかもしれません（未決）。
- **参照の文法を持つ場所は2つ、規則は1つ**——描画（`ref_render.go` の `parseRefValue`）と
  集計スコープ（`ref_scope.go`）。後者が前者を呼びます。**別々に持たせないこと**
  ——「画面ではリンクなのに集計には乗らない」という食い違いが生まれます。
- **正規化の規則も1つに寄せてある**——`cms.NormalizeCode` を拡張の
  `normalizeDrawingNo`（PDFとDXFの突き合わせ）が呼びます。索引の `norm_value` と
  突き合わせが同じ規則で畳まれる、という保証がこれです。
