# コードリファレンス

**実装がいま何をしているか**を、実際のコードから機械的に洗い出してまとめた文書群です。
設計の「なぜ」は各設計書（[アーキテクチャとDBスキーマ.md](../アーキテクチャとDBスキーマ.md) や
[認証認可設計.md](../認証認可設計.md) など）が正本で、こちらは**現状の写像**に徹します。

> 最終更新: 2026-08-17 ／ 対象コミット: `085d7f3`（語彙モデルの縦切り第1段まで反映）
> 更新方法: **`/code-reference` スキル**（[.claude/skills/code-reference/SKILL.md](../../.claude/skills/code-reference/SKILL.md)）。
> 測り方の手順と、この環境固有の落とし穴（PowerShellのエンコーディング等）もそこに書いてあります。

## この文書群の約束

- **推測を書かない。** 行番号・関数名・回数は実際のファイルから取る。確認していないことは
  「未確認」と明記する。
- **設計の意図は書かない。** 「なぜそうしたか」は設計書と [変更履歴.md](../変更履歴.md) の役割。
  ここは「いま何がどうなっているか」だけを書く。
- **古くなったら消す。** 実装と食い違った記述は、直すか消す。残しておくと**コードより有害**になる
  （読む人が確かめずに信じるため）。

## AIエージェントが読む場合

この文書群は人間向けであると同時に、**コードベースに不慣れな状態で作業を始めるAIエージェント**にも
有効です。ただし使い方に条件があります。

- **使ってよい**: 「どのファイルを開けばよいか」の当たり付け、呼び出しの連鎖の把握、
  用語と不変条件（何が正本か・どちらの向きに依存しているか）の確認。
- **鵜呑みにしない**: 変更を加える前に、対象箇所は**必ず実ファイルを読んで確認する**。
  この文書は生成時点のスナップショットであり、コードの方が常に正しい。
- **数える作業は必ず機械にやらせる**: 「◯箇所ある」「◯行」は grep やスクリプトで数え直す。
  目視の見積もりは外れる（実際に外した記録が [変更履歴.md](../変更履歴.md) にある）。
