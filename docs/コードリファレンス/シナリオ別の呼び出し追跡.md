# シナリオ別の呼び出し追跡

**対象コミット: `1b783f8`（2026-09-22 測り直し。コードは `0278690`＝[全体地図.md](全体地図.md) の測定時から不変）**

主な操作について、**実際に追える形**で呼び出しの連鎖を並べます。関数名は実在するものだけ、
分岐（403／404／409／423 になる条件）も併記します。個々の関数の説明は `go doc` が、
呼び出し元の一覧は [【一覧】関数リファレンス.md](【一覧】関数リファレンス.md) が持ちます。

> ⚠ **連鎖の多くはパッケージをまたぎます。** 取り込み（§6）・未処理（§8c）・返信（§7d）は
> `ext/comm`、解析・整理・発注（§7・§7b・§8e）は `ext/subcon`、連絡帳（§8d）は
> `ext/comm/contacts` です。**向きを間違えないこと**——コアは拡張を呼びません。コアは
> **フック（登録された関数）を呼ぶ**だけで、そこに何が積まれているかを知りません。

すべてのリクエストは最外周を通ります:

```
CSPProtect( outer )                 … 全応答へ Content-Security-Policy（strict。'unsafe-inline' なし）
  outer ├─ /dav/  → DavHandler      … **CSRFProtect の外側**（WebDAV の PROPFIND に
  │                                    Origin が付かないため。Cookie を使わない口なので
  │                                    CSRF の守りはもともと効かない）
        └─ /     → CSRFProtect(root)
                    … GET/HEAD/OPTIONS 以外は Origin（無ければ Referer）とホストの一致を要求
                      → 別オリジンなら 403、どちらのヘッダも無ければ 403
```

## 0. 起動

`cmd/w-cms/main.go` の `main()`:

```
（-gencert なら自己署名証明書を作って終了。設定もDBも要らないので最初に処理する）

cms.LoadSettings()                 … config/settings.json を読む（**DBより先**。**無くても**
                                     読めなくても不正でも log.Fatal＝Goコードに既定値は無い）
                                     validate → parseSections（拡張の節）→ applySections
                                     （**設定由来の形式 vocab_formats をレジストリの末尾へ**
                                      SetSettingsVocabFormats・拡張の apply）
database.InitDB()                  … data/cms.db を開き CoreTables＋coreMigrations
cms.DriftedSchemaTables(DB)        … プラグインのテーブル定義のずれを**先に**見る
  └ ずれがあれば cms.RebuildDatabase()   … 全テーブルDROP→data/master から再構築
cms.ApplySchema(DB)                … CREATE TABLE IF NOT EXISTS を流す（vocab_index・page_tags・
                                     **material_dimensions** と、その索引）。**再構築より後**（下）
cms.RebuildIfNeeded()              … 中断した再構築のやり直し／空DB＋ファイルありの復旧
database.InitAuthDB()              … data/auth.db を開き AuthTables（cms.db と同じ openSQLite）
auth.BootstrapAdmin()              … users が空のときだけ初期管理者
editlock.StartLockReaper()         … 猶予満了を定期評価する goroutine
buildHandler()                     … ルート表（テストのために切り出してある）
cms.Extensions()                   … 載っている拡張を起動ログへ（「拡張セット: …」）
http.ListenAndServeTLS(":8443", …) … WCMS_TLS_CERT と WCMS_TLS_KEY が**両方**あるとき
http.ListenAndServe(":8080", …)    … 無いとき（片方だけなら log.Fatal＝書きかけの設定）
```

> **ずれの検出は `ApplySchema` より前**でなければ意味がありません。
> ⚠ **作り直しも `ApplySchema` より前**です（2026-09-13 に順序を入れ替えた）。逆だと
> **列を変えた表へ新しい索引を張ろうとして起動が落ちます**。
> ⚠ **表を足しただけでは中身は入りません**——`ApplySchema` は `CREATE TABLE IF NOT EXISTS`
> を流すだけ。それを拾うのが `DriftedSchemaTables` の「索引に中身があるのに表が無い」判定で、
> `material_dimensions` が足された環境もこの道で1度だけ再構築が走ります。

> **設定はDBより先**です——この後の再構築が語→型の推論辞書を使うため。
> `RebuildDatabase` も先頭で `LoadSettings` を読み直すので、辞書へ語を足しても
> `vocab_formats` へ形式を足しても **DB再構築**（§11）だけで反映されます（再起動は不要）。
> ⚠ 読み直しのたびに `RegisterVocab` を呼ぶと二重登録で落ちるので、設定由来のぶんは
> **末尾に固めて入れ替えます**（`settingsVocabCount`）。

## 1. ページを開く（`GET /{id}`）

`RootHandler`（`handler_view.go`）。**体裁は相手で分かれます。**

```
RootHandler
├ id が "" / "index.html"        → 302 /000000（クエリは保つ）
├ id == "000000" かつ pages に無い → 既定HTMLとサイドカー（mode 302）を作って SyncIndex（初回起動）
├ id に "/" を含む（/<6桁>/<名前>） → page.ServeCleanAttachment（§5の[配信①]）
│                                   （先頭が6桁のIDでなければ pageNotFound）
├ id に英数字ハイフン以外        → pageNotFound
├ strconv.Atoi 失敗             → pageNotFound
├ pages に行が無い              → pageNotFound
├ requirePageViewable ─────────────────────────────────────────┐
│   認証済み × page.GetPerms(…).CanRead が偽 → forbiddenPage（403・体裁つきHTML）
│   匿名 × page.EffectivePublic が偽
│     └ トップページ(0) → 302 /login?next=…
│     └ それ以外        → notFoundWithLogin（404・戻り先つきログイン導線）
├ os.ReadFile 失敗              → pageNotFound
│
├ body = RenderAnchors( RenderReferenceLinks( RenderComputedViews( Sanitize(content) ) ) )
│         ↑ 描画時だけ    ↑ 描画時だけ            ↑ 鏡型の段（walkMirror）  ↑ 二層目の防壁
│                                                                        （冒頭で StripChrome）
├ 匿名 → servePublicPage
│         RenderPublicShell(body, PageSEO{Title, ExtractDescription(body), CanonicalURL})
│         Cache-Control: public, max-age=600 ＋ Vary: Cookie ＋ ETag
│         If-None-Match 一致 → 304（本文を送らない）
└ 認証済み → RenderPageShell(body, title)
             Cache-Control: no-store
```

`RenderComputedViews` は `hasViewMarker`（レジストリの `View: true` **または鏡の付いた形式**の
`data-type` か表示名が本文に現れるか）で早道し、あれば `walkers.walkMirror` で要素を配ります。
**ここが「拡張の画面がコアの描画に乗る」唯一の口**で、`unhandled-intake`（`ext/comm`）・
`unknown-contacts`（`ext/comm/contacts`）・`required-materials`／`material-search`／
`unordered-items`／`order-backlog`／`unlinked-customers`（`ext/subcon`）は `RegisterView` で
自分から名乗っています。**登録が無ければ `missingViewHTML` が理由を出します**。
同じ段で表の鏡も走ります——受注明細の足元に検算（`renderOrderChecksum`）、材料の表に
廃版の印と参考単価の列（`markObsoleteRows` → `renderMaterialPrices`）、
ファイル表示（`renderFileView`）。どれも `DropChrome` で前回の分を落としてから描き直します。

`RenderReferenceLinks` は `<dl` も `<table` も無ければ早道、あれば:

- **可変タグ**（`dl[data-type="tags"]`・クロームの中は除く）——値を `parseRefValue`
  （`^[0-9]{6}[-‐−－ーｰ][0-9A-Za-z]+$`）に掛け、`pageExists` でリンク（`/<ページID>#<ブロックID>`）
  か `ref-missing` かを決めます。**`email` 型の名前は `linkEmailDD`**（`RegisterContactResolver`
  で預かった解決係＝`ContactPageForAddress(nil, …)` に尋ね、**解決係が無ければ素のテキストのまま**）。
  形が合わなくても **`ref` 型と宣言されたタグ**（`受信元`・`返信元`・`連絡帳`）ならページID
  だけの値をページ全体への参照として扱います（`parsePageRef`）。
- **表**（`linkRefCells`・2026-09-20）——**列の宣言が `ref` のセルだけ**（`弊社品番`）を
  リンクにします。空欄は触らない（人が後から結ぶ）。⚠ **鏡が `<tfoot>` へ足した行は
  `inVocabChrome` で飛ばします**——`RenderReferenceLinks` は `RenderComputedViews` の**後**に
  走るので、鏡の描いた行を本文として読んでしまい、検算の「合っています」が薄赤になった前科。

**匿名の404は「読めない」と「存在しない」を区別しません**（例外はトップページだけ）。
404画面は `/login?next=…` を持ち、`safeNextPath` が同一サイト内の絶対パスだけに絞ります。

**本文API（`GET /api/load?id=`）**は `LoadAPIHandler`——GET 以外は405 → `queryPageID`
（空も不正も「ページIDが不正です」の400）→ `RequirePageReadOrPublic` →
`pages.file_path` → `RenderComputedViews(Sanitize)` を `text/plain`＋`nosniff` で返す。
**アンカー合成と参照リンクは通しません**。⚠ **鏡は埋めて返します**——これを外から
`/api/save` へ書き戻すと鏡が本文に焼き付きます。いまは `StripChrome` が守りますが、
**既に保存された鏡は落とせません**（印が無い）。

## 2. 保存する（`POST /api/save`）

`SaveAPIHandler`（`handler_save.go`）。**順序に意味があります。**

```
SaveAPIHandler
├ メソッドが POST でない        → 405
├ DecodeJSONBody（8MiB上限）    → 413 / 400
├ page_id が空                 → 400（新規は /api/new-page を通す）
├ gateSave
│   ├ normalizedPageID         → 400
│   ├ page.RequirePageWrite    → 401 / 403
│   └ editlock.RequireLockToken（JSON の token）→ 409（他者が保持中／トークン失効。無ければ許可）
├ SanitizeReport(req.HTML)     → safeHTML, sanitized
│   └ 冒頭で StripChrome（.vocab-chrome を根こそぎ落とす。落としたら sanitized=true）
├ writeBody
│   ├ refuseDuplicateBoxTitle  → **409**（トップ直下で、題が置き場の名簿に在り、同じ題が既に別に在る）
│   ├ page.BumpUpdatedAt       → 500（**サイドカーが読めなければここで止まる**）
│   └ page.WriteFileAtomic(page.BodyPath(id)) → 500
├ RecordVersion(id, user, safeHTML, force=false)   … 失敗しても**保存は止めない**
├ syncBody → SyncIndex(id, safeHTML)      → 500
├ auth.AuditRequest(r, "save", id)
└ 200 saveEcho {success, page_id, updated_at, html, sanitized, unknown_types, unresolved_fields, stripped_ids}
```

`SyncIndex`（`sync.go`）の中身:

```
html.Parse → PageTitle（タイトル）
page.ReadSidecar（親・作成情報・更新日時。読めなければ parent_id は**現状維持**）
tx = DB.Begin()
  pages を upsert
  page.SyncPageMeta      … サイドカー → page_perms（upsertPerms）
  各 Observer.OnPageStart … vocab_index・page_tags・material_dimensions の当該ページ分を DELETE
  IsTemplateArea(id) が偽なら walkers.walkObserve(ctx, root)
    └ 引き金（vocabTypeOf）に当たった要素だけを担当へ配る（.vocab-chrome の中は歩かない）
       vocabIndexPlugin.OnElement（引き金 *）
         section → syncVocabSection … **登録された見出しの節だけ**。素の table を索引
                                       （素の dl は 2026-09-18 から拾わない。caption で名乗る表も
                                        配送係が別に届けるので飛ばす——飛ばさないと二重）
         table   → syncVocabTable   … **登録された形式だけ**。見出し行の th が鍵
         dl      → syncVocabDL      … 直前の dt が鍵
         （振り分けは insertVocabEntry ——可変タグ（dl[data-type="tags"]）は page_tags、
           それ以外は vocab_index。block_no は形式ごとの文書順連番＝ctx.Counter）
       dimensionPlugin.OnElement（引き金 part-materials / our-order-items・ext/subcon）
         table   → indexTable … `寸法` の列を ParseDimension で分解して material_dimensions へ
         section → 節の中の**素の表**だけ（cms.VocabTypeOf が空のもの）を同じく
         降りるかは OR で畳む（dimensionPlugin は表なら false、vocabIndexPlugin は常に true）
  PageFinisher を実装する Observer があれば OnPageEnd（いまは無い）
tx.Commit()
```

> **テンプレート領域は「要素イベントを1つも発火しない」だけ**で除外されます。
> `OnPageStart`（DELETE）は呼ぶので、普通のページをテンプレートフォルダへ移すと
> 古い行が消えます。判定 `IsTemplateArea` は**サイドカーと本文HTMLで先祖を辿ります**
> （DBを見ない）。
>
> ⚠ **登録されていない形式の表は索引に入りません**（2026-09-20）。受注ページの
> 「顧客の発注書（読んだまま）」は形式を登録していないので、弊社の明細と二重計上になりません。
> 運用者が自分の表を索引に入れる道は設定の `vocab_formats`。

**ブロック保存（`POST /api/save-block`）は版を作りません。** 同じ `gateSave` を通し、
`ReplaceBlock` で本文をマージしてから `writeBody`・`syncBody`（`RecordVersion` は呼ばない。
対象が無い／重複なら 409 でクライアントが全文保存へ落ちる）。最終状態はロック解放時の
チェックポイント（§3）が拾います。

**機械が本文を書き換える口（`RewriteBody` → `rewritePageBody`）も同じ作法**——
`Sanitize`（冒頭で `StripChrome`）→ `BumpUpdatedAt` → `WriteFileAtomic` → `RecordVersion` →
`SyncIndex`。呼ぶのは連絡帳（2。`contacts.go` の `addContactTags`・`contacts_handler.go` の unfile）・整理（`filing.go` 2・`filing_order.go`）・改定の合流
（`revision.go` 2）・弊社品番の結び（`link_item.go` 2）・受注残の書き戻し（`order_edit.go`）・
発注書の作成（`our_order_new.go`）・「対応」の印（`handler_handled.go`）。
**ロックは呼ぶ側が見ます**（§5 の関門）。

## 3. 編集モードへ入る／抜ける

```
[入る] POST /api/lock?id=
  LockAPIHandler（editlock/handler.go）
  ├ queryPageID → 400
  ├ requireWriter（page.RequirePageWrite）→ 401 / 403
  ├ Locks.TryAcquire
  │   取れない → 423 Locked {ok:false, holder, same_user, grace_remaining_sec}
  └ 200 {ok, token}   ※**本文は返さない**
  → フロント（acquireLock）が GET /api/load を読んで populateEditor

[購読] GET /api/lock-events?id=&role=holder|waiter&token=   … SSE。presence の実体はこの接続の有無

[抜ける] POST /api/unlock?id=&token=（タブ離脱時は navigator.sendBeacon からも）
  UnlockAPIHandler → Locks.Release
                      └ 保持者本人でトークン一致のときだけ editlock.OnRelease を呼ぶ
                         └ cms/version.go の init が RecordVersion(…, force=true)
                            （中身が最新の版と同じなら何もしない）

[強制] POST /api/lock/force?id=   … page.RequireAdmin → Locks.ForceRelease → Audit "lock.force"
```

**猶予は競合トリガー方式**——誰も待っていなければ無期限、待機者が現れてから2分で明け渡します
（`lockGraceDuration`）。取得直後に SSE が繋がるまでの猶予は10秒（`holderConnectGrace`）。

> ⚠ **閲覧モードへ戻るときは、送っていない自動保存を先に流します**。自動保存は1.5秒の
> デバウンスなので、`onModeToggle` が保存を待たずに `releaseLock()` を呼ぶと**最後の入力が
> 黙って消えます**。「保存してから何かする」経路を足すときは `await saveToServer()` を通すこと。
> ⚠ **`/api/lock` を2回呼ばないこと**——同じ利用者でも2回目でトークンがずれ、そのあとの
> 削除・保存が 409 になります（`force → lock（1回）→ 使う` の順で）。

## 4. ページを作る（`POST /api/new-page`）

```
NewPageAPIHandler（handler_tree.go）
├ POST 限定（GET は 405）
├ parent が空            → 400（親なしにできるのはトップページだけ）
├ page.RequirePageWrite(parent) → 401 / 403
├ loadTemplateBody（template.go）… template= があれば**採番の前に**検証して読む
│    NormalizeID → RequirePageRead → IsUnderTemplateRoot → isLeafPage → Sanitize
├ reserveNewPageID       … pages への INSERT で原子的に採番
├ html = 既定文 or FreshenTemplateBody(templateBody, newID)
│                           └ 種まきの段（walkSeed）。空欄を列型の既定値で埋める
│                             （date は今日。⚠ 発注書番号の自動採番 `PO-…` は 2026-09-21 に撤去
│                              ——受注ページの番号はお客様のもの）
├ page.WriteFileAtomic(page.BodyPath(新ID))
├ page.EnsureSidecar     … owner=作成者・group/mode は親の GetPerms から継承・public は常に false
├ SyncIndex
├ auth.Audit(user, "new-page", "<新ID> under <親>[ (template <id>)]")
└ 302 /{新ID}?edit=true
```

取り込み・解析・整理・置き場・発注書が使う `cms.CreateChildPage`（`page_folders.go`）は
同じ芯を関数にしたもの——`reserveNewPageID` → `Sanitize` → `WriteFileAtomic` →
`GetPerms(親)` で継承して `EnsureSidecar` → `SyncIndex`。監査は呼び手が録ります。

> ⚠ **置き場の題はトップ直下に1枚だけ**（2026-09-21）。`/api/new-page` は題を持たない
> （既定文）ので、止まるのは**保存のとき**（§2 の `refuseDuplicateBoxTitle`）です。
> 「通信箱」という題のページをトップ直下にもう1枚作って保存すると 409 で断られます。

## 5. 添付する（3つの口）と配る（2つの口）

```

**ここが「コアが拡張を名指ししない」形の見本です。** コアは受け口に尋ねるだけで、

```

         │       │       … cms.SaveAttachmentFrom（目録の由来 "mail"）。置けなければ取り込まない
         │       ├ saveMailAttachments（2026-09-17）:
         │       │     添付ごとに cms.AttachmentExtAccepted（許可リスト）→ cms.GuardUploadContent
         │       │     → ctx.SaveAttachment（由来 "mail:<原本の保存名>"）
         │       │     → <p data-id="<生成ID>">📎 <a href="/<ID>/<生成ID>.<ext>" download="元名">…</a></p>
         │       │     .zip なら cms.ExpandZip → 中身ごとに同じ検査と保存（由来 "zip:<ZIP>/<中のパス>"）
         │       │     → <p …>📎 <a …>↳ <中のパス></a></p>（リンク文字はフォルダを含む・保存名はファイル名だけ）
         │       │     通らなかったものは保存せず <p>📎 名前（理由）…</p> を残す（原本の中にある）
         │       ├ 本文を組む: h1 ＋ <dl data-type="tags">（cms.WriteTag で 差出人・宛先・受信日時・
         │       │             メッセージID・返信元メッセージID・チャネル・向き・添付数…）
         │       │             ＋ comm.PlainTextBlockHTML(text/plain) ＋ 添付のブロック ＋ 📧 受信原本
         │       └ ctx.UpdatePage(pageID, 本文)      … cms.Sanitize → WriteFileAtomic → cms.SyncIndex

- **編集ロックは要求しません**——通信箱の本文は変わらず、子ページが増えるだけ。
- `SaveAttachment` / `UpdatePage` は**この取り込みで作ったページ**にしか効きません（`isCreated`）。
- 通信箱の権限（group/mode）が子ページへ継承されます。
- ここで PDF の解釈は**しません**（人間ゲート型。§7）。
- **PDF専用の口（`/api/upload-pdf`）も同じ受け口を通ります**が、取り込み係が居るのは
  `.eml` だけなので**素通りして普通の添付**になります。
- **`-tags minimal` の組では受け口が空**なので、`.eml` を通信箱へ落としても**ただの添付**に
  なります。

└ 200 {success, page_id, trash_path}
```

芯は `DeletePageToTrash`——整理の合流（`revision.go`）も同じ芯で仮のページを片付けます。
**復元UIはありません。** 戻すには手で `data/master` へ移してDB再構築します。

## 11. DB再構築（`POST /api/rebuild-db`）

```
RebuildDBAPIHandler（handler_meta.go）
├ POST 限定
├ page.RequireAdmin → 401 / 403
├ RebuildDatabase（sync.go）                          → 500
│   ├ LoadSettings                … 辞書・vocab_formats・拡張の節を読み直す（再起動なしで効く）
│   ├ markRebuildStarted          … rebuild_state に「始めた印」
│   ├ dropAllTables               … sqlite_master の全テーブル（rebuild_state を除く）を DROP
│   ├ database.CreateCoreTables ＋ ApplySchema
│   ├ resyncAllPages              … data/master を歩き、versions/ を飛ばして .html ごとに SyncIndex
│   └ markRebuildFinished(件数, ミリ秒)
├ lastRebuildResult → auth.AuditRequest(r, "rebuild-db", "<件数>ページ / <ms>ミリ秒")
└ 200 {success, pages, duration_ms}
```

起動時の `RebuildIfNeeded` は、`data/master` に .html があるとき、**印が残っている
（前回が途中で止まった）なら pages が空でなくてもやり直し**、そうでなければ pages が
空のときだけ再構築します。データの初期化（§8f）も最後にこれを呼びます。

⚠ **ファイルが無いときだけは止めません**（読み込み済みの設定のまま続ける）。

## 12. ログイン・ログアウト

```
[画面]   GET /login          auth.LoginPageHandler（認証不要）
[認証]   POST /api/login     auth.LoginAPIHandler（認証不要・CSRFProtect は通る）
         ├ loginSem（argon2id の同時実行を4件に制限）
         ├ Authenticate
         │   ├ isLockedOut … 5回連続失敗で15分（login_attempts）
         │   ├ 不在・無効化・ハッシュ無しは decoyHash で時間を均してから失敗
         │   └ VerifyPassword 失敗 → recordFailure
         ├ 失敗 → auth.Audit(username, "login.fail", clientIP)
         │         302 /login?error=1&next=…
         ├ CreateSession → setSessionCookie（HttpOnly・SameSite=Lax・Secure は WCMS_SECURE_COOKIES）
         ├ auth.Audit(user, "login", clientIP)
         └ 302 next（safeNextPath が同一サイト内の絶対パスだけに絞る）
[破棄]   POST /api/logout    auth.LogoutAPIHandler（POST 限定）
         ├ ResolveSession でユーザー名を得てから auth.Audit(user, "logout", clientIP)
         └ DeleteSession → clearSessionCookie → 302 /login
[状態]   GET /api/me         auth.MeAPIHandler（OptionalAuth。未認証は 200 {authenticated:false}）
```

`RequireAuth` と `OptionalAuth` は同じ `userFromRequest`（Cookie → `ResolveSession` →
`LookupUser`）で利用者を解決します。**接続元アドレス**（`clientIP`）は、前段がループバック／
私設アドレスのときだけ `X-Forwarded-For` を採ります（`IsFromTrustedProxy`）。

## 13. クローラ（`GET /sitemap.xml` / `GET /robots.txt`）

```
SitemapHandler … publicPages()（全ページを回して page.EffectivePublic で絞る）
                 → <urlset> ＋ public, max-age=600 ＋ Vary: Cookie

RobotsHandler  … database.DB == nil または page.EffectivePublic(0) が偽
                 → "Disallow: /"（サイトが閉じている＝業務インスタンス）
                 → それ以外は /api/ と /login を閉じ、Sitemap: 行を出す
```

絶対URLの基底は `WCMS_BASE_URL` を最優先し、無ければリクエストから組み立てます
（`X-Forwarded-Proto`/`-Host` は前段がプロキシのときだけ採用）。

## 14. フロント側の起動順

```
index.html
├ <head>  boot.js（11行目）… **同期**スクリプト。レールの開閉を描画前に確定（FOUC防止）
├ <head>  app.css（13行目）
├ <body>  …本文はサーバーが合成済み（#w-editor-content に埋まった状態で届く）
└ </body> 直前 app.js（285行目）… defer なし。DOMが揃ってから同期実行
             bindChromeActions()  … クロームのボタン配線（addEventListener。on*= は無い）
             window.onload:
             ├ await Promise.all([loadMe(), loadTagSchema()])
             │    ↑ **語彙と「載っている拡張」は保存やクロームが走る前に必要**
             │      loadTagSchema が elements / void / vocab / vocabulary / column_types /
             │      **extensions** を受け取る（extensions が配列でなければ loadedExtensions=null
             │      ＝出し分けをしない）
             ├ initBlocks / buildToc / setupEditorEvents / setupAutoSave
             ├ 匿名なら applyMode / loadPageMeta / loadChildNav して終了
             └ onModeToggle（?edit ならロック取得→/api/load）→ loadPageMeta / loadPerms /
               loadChildNav / loadVersions
```

`applyMode` は閲覧モードで `refreshAttachmentPreviews` を呼び、編集モードでは
添付クロームを外して `decorateFileViews`（ファイル表示の配線の札）を出します。
サーバーが描いた作業面への配線（`wireUnhandledActions`・`wireContactRegister`・
`wireBacklogEditing`・`wireUnorderedOrder`・`wireMaterialSearch`）は**押す相手がサーバーの
クロームなので出し分けが要りません**——拡張が無ければ何も見つけずに帰ります。
`validateTypedTables` は本文の表のセルに型と折り返しの印を付けますが、**鏡のセルは
`isServerOwned` で飛ばします**（クロームの断り文の幅で列が決まった前科）。
スラッシュメニューの挿入骨格は `buildVocabSkeleton`——`usesHeadingForm(def)` なら
`<section><h2>表示名</h2>…</section>`（`data-type` を書かない）。
⚠ **`file-view` は `usesHeadingForm` の例外**（`tags`・`file` と同じ）。

> `boot.js` も `app.js` も `defer` を持ちません。`<head>` の同期スクリプトが先、
> `</body>` 直前が後、という**書いてある順**どおりに実行されます。
