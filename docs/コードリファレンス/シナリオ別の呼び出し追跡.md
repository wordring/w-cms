# シナリオ別の呼び出し追跡

**対象コミット: `46b0942`（2026-09-04 測り直し）**

主な操作について、**実際に追える形**で呼び出しの連鎖を並べます。関数名は実在するものだけ、
分岐（403／404／409／423 になる条件）も併記します。個々の関数の説明は `go doc` が、
呼び出し元の一覧は [【一覧】関数リファレンス.md](【一覧】関数リファレンス.md) が持ちます。

すべてのリクエストは最外周の2つを通ります:

```
CSPProtect  … 全応答へ Content-Security-Policy（strict。'unsafe-inline' なし）
CSRFProtect … GET/HEAD/OPTIONS 以外は Origin（無ければ Referer）とホストの一致を要求
              → 別オリジンなら 403、どちらのヘッダも無ければ 403
```

## 0. 起動

`cmd/w-cms/main.go` の `main()`:

```
cms.LoadSettings()                 … data/settings.json を読む（**DBより先**。無ければ
                                     既定値で作成、在るのに読めない・不正なら log.Fatal）
database.InitDB()                  … data/cms.db を開き CoreTables＋coreMigrations
cms.DriftedSchemaTables(DB)        … プラグインのテーブル定義のずれを**先に**見る
cms.ApplySchema(DB)                … CREATE TABLE IF NOT EXISTS を流す（vocab_index＋索引4本）
  └ ずれがあれば cms.RebuildDatabase()   … 全テーブルDROP→data/master から再構築
cms.RebuildIfNeeded()              … 中断した再構築のやり直し／空DB＋ファイルありの復旧
database.InitAuthDB()              … data/auth.db を開き AuthTables
auth.BootstrapAdmin()              … users が空のときだけ初期管理者
editlock.StartLockReaper()         … 猶予満了を定期評価する goroutine
buildHandler()                     … ルート表（テストのために切り出してある）
http.ListenAndServe(":8080", …)
```

> **ずれの検出は `ApplySchema` より前**でなければ意味がありません（流したあとでは
> 「宣言どおりのテーブルが在る」ように見えてしまう）。

> **設定はDBより先**です——この後の再構築が語→型の推論辞書を使うため。
> `RebuildDatabase` も先頭で `LoadSettings` を読み直すので、辞書へ語を
> 足したら **DB再構築**（11章）だけで反映されます（再起動は不要）。

登録は `init()` で済んでいます（`main()` より前）。**コアの分**——`vocabIndexPlugin`（観察係）・
鏡型と計算ビューの器（`view_render.go`）・種まき（`template_new.go`）・`emlIntake` と
`fileIntake`（取り込み係）・`editlock.OnRelease`（`version.go`）。**拡張の分**——
`cmd/w-cms/ext_*.go` のブランク import が引き金で、`ext/sheetmetal` が語彙14形式・
計算プラグイン・計算ビュー・鏡型・`.dxf` の取り込み係・ルート4本を、`ext/mailgraph` が
`Mailer` の実装とルート4本を足します。

> **何が入っているかは起動ログに出ます**（「拡張セット: …」の行）。ビルドタグの付け外しは
> 目に見えないので、**タグを忘れたビルドは受注ページ生成も部材計算も無いまま普通に起動します**
> ——気づくのは「発注書を解析しても何も起きない」ときです。
>
> ```
> 拡張セット: mailgraph（メール送受信・Microsoft Graph）, sheetmetal（板金部の既定セット）
> メール送受信: 有効（Microsoft Graph）   ← WCMS_MAIL_CLIENT_ID / _TENANT_ID があるとき
> メール送受信: 設定待ち（… が未設定）    ← 無いとき（他は全部動く）
> ```

## 1. ページを開く（`GET /{id}`）

`RootHandler`（`handler_view.go`）。**体裁は相手で分かれます。**

```
RootHandler
├ id が "" / "index.html"        → 302 /000000（クエリは保つ）
├ id == "000000" かつ pages に無い → 既定HTMLとサイドカー（mode 302）を作って SyncIndex（初回起動）
├ id に "/" を含む（/<6桁>/<名前>） → page.ServeCleanAttachment（5章の[配信②]）
│                                   （先頭が6桁のIDでなければ pageNotFound）
├ id に英数字ハイフン以外        → pageNotFound
├ strconv.Atoi 失敗             → pageNotFound
├ pages に行が無い              → pageNotFound
├ requirePageViewable ─────────────────────────────────────────┐
│   認証済み × page.GetPerms(…).CanRead が偽 → forbiddenPage（403・体裁つきHTML）
│   匿名 × page.EffectivePublic が偽
│     └ トップページ(0) → 302 /login?next=…
│     └ それ以外        → notFoundWithLogin（404・戻り先つきログイン導線）
├ os.ReadFile 失敗              → pageNotFound
│
├ body = RenderAnchors( RenderReferenceLinks( RenderComputedViews( Sanitize(content) ) ) )
│         ↑ 描画時だけ    ↑ 描画時だけ            ↑ 鏡型の段（walkMirror）  ↑ 二層目の防壁
│
├ 匿名 → servePublicPage
│         RenderPublicShell(body, PageSEO{Title, ExtractDescription(body), CanonicalURL})
│         Cache-Control: public, max-age=600 ＋ Vary: Cookie ＋ ETag
│         If-None-Match 一致 → 304（本文を送らない）
└ 認証済み → RenderPageShell(body, title)
             Cache-Control: no-store
```

`RenderComputedViews` は `hasViewMarker`（レジストリの `View: true` の `data-type` か
表示名が本文に現れるか）で早道し、あれば `walkers.walkMirror` で section を配ります。
`RenderReferenceLinks` は `<dl` が無ければ早道、あれば `eachDLPair` で値を `parseRefValue`
（`^[0-9]{6}[-‐−－ーｰ][0-9A-Za-z]+$`）に掛け、`pageExists`（`pages` の件数）で
リンク（`/<ページID>#<ブロックID>`）か `ref-missing` かを決めます。

**匿名の404は「読めない」と「存在しない」を区別しません**（例外はトップページだけ）。
404画面は `/login?next=…` を持ち、`safeNextPath` が同一サイト内の絶対パスだけに絞ります。

`pageNotFound` は相手で分かれます——匿名は `notFoundWithLogin`、認証済みは素の `http.NotFound`。

**本文API（`GET /api/load?id=`）**は `LoadAPIHandler`——`RequirePageReadOrPublic` →
`pages.file_path` → `RenderComputedViews(Sanitize)` を `text/plain`＋`nosniff` で返す。
**アンカー合成と参照リンクは通しません**（エディタが本文として保存してしまうため）。

## 2. 保存する（`POST /api/save`）

`SaveAPIHandler`（`handler_save.go`）。**順序に意味があります。**

```
SaveAPIHandler
├ メソッドが POST でない        → 405
├ DecodeJSONBody（8MiB上限）    → 413 / 400
├ page_id が空                 → 400（新規は /api/new-page を通す）
├ page.NormalizeID             → 400
├ page.RequirePageWrite        → 401 / 403
├ editlock.Locks.Validate      → 409（他者が保持中／トークン失効。ロックが無ければ許可）
├ page.BumpUpdatedAt           → 500（**サイドカーが読めなければここで止まる**）
├ SanitizeReport(req.HTML)     → safeHTML, sanitized
├ page.WriteFileAtomic(<id>.html) → 500
├ RecordVersion(id, user, safeHTML, force=false)   … 失敗しても**保存は止めない**
├ SyncIndex(id, safeHTML)      → 500
├ auth.Audit(user, "save", id)
└ 200 {success, page_id, updated_at, html, sanitized, unknown_types, unresolved_fields, stripped_ids}
```

`SyncIndex`（`sync.go`）の中身:

```
html.Parse → PageTitle（タイトル）
page.ReadSidecar（親・作成情報・更新日時。読めなければ parent_id は**現状維持**）
tx = DB.Begin()
  pages を upsert
  page.SyncPageMeta      … サイドカー → page_perms
  各 Observer.OnPageStart … vocab_index の当該ページ分を DELETE（＝洗い替えの前半）
  IsTemplateArea(id) が偽なら walkers.walkObserve(ctx, root)
    └ 引き金（vocabTypeOf）に当たった要素だけを担当へ配る（.vocab-chrome の中は歩かない）
       vocabIndexPlugin.OnElement
         section → syncVocabSection … 素の dl（ヘッダ）と素の table（Items 宣言があれば明細）を索引
         table   → syncVocabTable   … 見出し行の th が鍵。型は th の data-type > レジストリ > 推論辞書 > text
         dl      → syncVocabDL      … 直前の dt が鍵
         （block_no は形式ごとの文書順連番＝ctx.Counter）
  PageFinisher を実装する Observer があれば OnPageEnd（いまは無い）
tx.Commit()
```

> **テンプレート領域は「要素イベントを1つも発火しない」だけ**で除外されます。
> `OnPageStart`（DELETE）は呼ぶので、普通のページをテンプレートフォルダへ移すと
> 古い行が消えます。判定 `IsTemplateArea` は**サイドカーと本文HTMLで先祖を辿ります**
> （DBを見ない——再構築中は先祖が未同期でありうるため）。

**ブロック保存（`POST /api/save-block`）は版を作りません。** `ReplaceBlock` で本文を
マージしてから書き、`RecordVersion` は呼びません（対象が無い／重複なら 409 でクライアントが
全文保存へ落ちる）。最終状態はロック解放時のチェックポイント（3章）が拾います。

## 3. 編集モードへ入る／抜ける

```
[入る] POST /api/lock?id=
  LockAPIHandler（editlock/handler.go）
  ├ page.NormalizeID → 400
  ├ page.RequirePageWrite → 401 / 403
  ├ Locks.TryAcquire
  │   取れない → 423 Locked {ok:false, holder, same_user, grace_remaining_sec}
  └ 200 {ok, token}   ※**本文は返さない**
  → フロント（acquireLock）が GET /api/load を読んで populateEditor

[購読] GET /api/lock-events?id=&role=holder|waiter&token=   … SSE。presence の実体はこの接続の有無

[抜ける] POST /api/unlock?id=&token=（タブ離脱時は navigator.sendBeacon からも）
  UnlockAPIHandler → Locks.Release
                      └ 保持者本人でトークン一致のときだけ editlock.OnRelease を呼ぶ
                         └ cms/version.go の init が RecordVersion(…, force=true)
                            （中身が最新の版と同じなら何もしない）

[強制] POST /api/lock/force?id=   … page.RequireAdmin → Locks.ForceRelease → Audit "lock.force"
```

**猶予は競合トリガー方式**——誰も待っていなければ無期限、待機者が現れてから2分で明け渡します
（`lockGraceDuration`）。取得直後に SSE が繋がるまでの猶予は10秒（`holderConnectGrace`）。

## 4. ページを作る（`POST /api/new-page`）

```
NewPageAPIHandler（handler_tree.go）
├ POST 限定（GET は 405）
├ parent が空            → 400（親なしにできるのはトップページだけ）
├ page.RequirePageWrite(parent) → 401 / 403
├ loadTemplateBody（template.go）… template= があれば**採番の前に**検証して読む
│    NormalizeID → RequirePageRead → IsUnderTemplateRoot → isLeafPage → Sanitize
├ reserveNewPageID       … pages への INSERT で原子的に採番
├ html = 既定文 or FreshenTemplateBody(templateBody, newID)
│                           └ 種まきの段（walkSeed）。空欄を列型の既定値で埋め、
│                             order-no 列は PO-<新ID>（2件目以降 -2, -3…）
├ page.WriteFileAtomic(<新ID>.html)
├ page.EnsureSidecar     … owner=作成者・group/mode は親の GetPerms から継承・public は常に false
├ SyncIndex
├ auth.Audit(user, "new-page", "<新ID> under <親>[ (template <id>)]")
└ 302 /{新ID}?edit=true
```

取り込みと解析が使う `CreateChildPage`（`intake.go`）は同じ芯を関数にしたもの——
`reserveNewPageID` → `Sanitize` → `WriteFileAtomic` → `GetPerms(親)` で継承して `EnsureSidecar`
→ `SyncIndex`。監査は呼び手が録ります（`intake.create`／`analyze-pdf`）。

## 5. 添付する（3つの口）と配る（2つの口）

```
[汎用]  POST /api/upload-file   UploadFileHandler（upload_file.go）  フォーム名 file
[PDF]   POST /api/upload-pdf    UploadPDFHandler（pdf_handler.go）   フォーム名 pdf_file
[画像]  POST /api/upload-image  UploadImageHandler（upload_image.go） フォーム名 image_file

共通の順序:
├ POST 限定（GET は 405）
├ http.MaxBytesReader（MaxUploadBytes＝設定 max_upload_mib・既定32MiB）
├ page.NormalizeID → 400
├ page.RequirePageWrite → 401 / 403
├ [汎用のみ] 対象が受信箱（InboxPageID）なら serveIntake へ（6章）。担当が居なければ続行
├ editlock.RequireEditLock → 409
├ 名前の検査 SafeAttachmentName（ページの本文・サイドカーと同名は拒否）
│   汎用 … 拡張子は GenericAttachmentExts（設定・既定14種）。.pdf と画像は 400（専用口へ）
│   PDF  … .pdf のみ（attachmentFileName）
│   画像 … png/jpg/jpeg/webp/gif/svg（allowedImageExts）。HEIC/AVIF/TIFF/BMP は**形式ごとの理由**で 400
├ 中身の検査
│   汎用 … **しない**（安全の本体は配信側のヘッダ）
│   PDF  … 先頭が %PDF-
│   画像 … SniffImageKind ＋ 拡張子との一致 ＋ SVG は ValidateSVG、その後 StripImageMetadata
├ page.AttachmentDir（files/）に page.GeneratedAttachmentID で保存名を決める
│   （<生成ID>.<拡張子>。元の名前はURLに出ない）
├ os.Stat で上書きかを判定 → page.WriteFileAtomic
├ auth.Audit(user, "attach" | "attach.overwrite", "<id>/<保存名>")
└ 200 {file_name, id, href|src …}   … href/src は page.AttachmentURLFor ＝ /<ページID>/<保存名>

[配信①] GET /<ページID>/<名前>            RootHandler → page.ServeCleanAttachment（**新しい形**）
├ 名前に / \ を含む・空・ドット始まり → 404
├ page.RequirePageReadOrPublic → 匿名は404／認証済み×権限なしは403
├ files/<名前> が無い → 404（**直下は見ない**）
└ setAttachmentHeaders → http.ServeFile

[配信②] GET /data/master/<先頭2桁>/<id>/<名前>   page.DataFileHandler（**旧形・互換**）
├ path.Clean（.. の解決）
├ page.RequirePageReadOrPublic
├ <id>.html / <id>.meta.json は配らない（404）
└ setAttachmentHeaders → http.ServeFile

setAttachmentHeaders（両口で共有）: X-Content-Type-Options: nosniff ＋
    .pdf                     … application/pdf（インライン）
    .svg                     … image/svg+xml ＋ attachment ＋ この応答限定の sandbox CSP
    .png/.jpg/.jpeg/.webp/.gif … 実際の種別でインライン
    それ以外                 … application/octet-stream ＋ attachment
```

**ZIP の目録**（`GET /api/zip-list?page_id=&file=`・`OptionalAuth`）: `RequirePageReadOrPublic` →
`SafeAttachmentName`（.zip のみ）→ `page.AttachmentPath` → `listZipEntries`（セントラルディレクトリ
だけ・最大500件・`DecodeZipName` で Shift_JIS 名を復号）。**展開はしません。**

閲覧モードのフロント（`refreshAttachmentPreviews`）は `a[href]` のうち
`/<6桁>/<base36>.(pdf|zip)` の形だけに「▶ 表示／▶ 中身」と、PDF には「🤖 解析」
（`makeAnalyzeButton`）を挿します（クロームは `.vocab-chrome`）。

## 6. 受信箱へ `.eml` をドロップする（`POST /api/upload-file` → 取り込み係）

```
UploadFileHandler（5章の共通順序で RequirePageWrite まで）
└ InboxPageID() == page_id なら serveIntake（upload_file.go）
   ├ FormFile "file" が無い → false（通常の添付経路へ戻る）
   ├ intakeHandlerFor(拡張子) が nil → false（担当なし＝ただの添付）
   ├ 中身を読む → 500
   ├ **重複検知**（担当が SourceRefFinder を実装しているときだけ）
   │   emlIntake.SourceRef … mail.ReadMessage → Message-ID → (名前 "メッセージID", 値)
   │   ExistingIntakePage(名前, 値) … PagesByTag（vocab_index の data_type='tags' を逆引き）
   │     既存あり → auth.Audit(uploader, "intake.duplicate", …)
   │                200 {success, intake, duplicate:true, title, page_id（読める相手にだけ）}
   ├ ctx = IntakeContext{InboxID, Uploader}
   ├ emlIntake.OnFile(ctx, 元名, 中身)      → 失敗は 400「取り込めませんでした: …」
   │   ├ mail.ReadMessage → 件名・差出人・宛先・受信日時（ローカル時刻の RFC3339）
   │   ├ collectParts … multipart を再帰展開、text/* は charset から UTF-8 へ（x/text）
   │   ├ ctx.CreatePage("<h1>件名</h1>")   … CreateChildPage(受信箱, uploader, …)
   │   │                                     ＋ Audit "intake.create"（先にIDが要る）
   │   ├ 本文を組む: h1 ＋ <dl data-type="tags">（差出人・宛先・受信日時・メッセージID）
   │   │             ＋ text/plain の段落 ＋ 添付ごとに ctx.SaveAttachment
   │   │               （GeneratedAttachmentID・files/・Audit "attach"）
   │   │               → <p data-id="<生成ID>">📎 <a href="/<ID>/<生成ID>.<ext>" download="元名">…</a></p>
   │   └ ctx.UpdatePage(pageID, 本文)      … Sanitize → WriteFileAtomic → SyncIndex
   └ 200 {success, intake:true, page_id, title}
```

- **編集ロックは要求しません**——受信箱の本文は変わらず、子ページが増えるだけ。
- `SaveAttachment` / `UpdatePage` は**この取り込みで作ったページ**にしか効きません
  （`isCreated`）。既存ページを改変する口にはなっていません。
- 受信箱の権限（group/mode）が子ページへ継承されます——「受信物を誰が読めるか」は
  受信箱の設定で決まります。
- ここで PDF の解釈は**しません**（人間ゲート型。次章）。

## 7. 🤖 解析（`POST /api/analyze-attachment`・`ext/sheetmetal`）

```
AnalyzeAttachmentAPIHandler（ext/sheetmetal/analyze_pdf.go）  入力 {page_id, file, entry?}
├ POST 限定 → 405（JSON の cms.JSONFail）
├ cms.DecodeJSONBody → 413 / 400
├ page.NormalizeID → 400
├ page.RequirePageWrite → 401 / 403（**編集ロックは要らない**——子ページを作るだけ）
├ cms.SafeAttachmentName（.pdf / .zip）→ 400
├ loadPDFForAnalysis
│   page.AttachmentPath で実体を探す → 無ければ 400
│   .pdf … そのまま読む
│   .zip … entry（目録の表示名・cms.DecodeZipName で照合）の1件だけを
│          cms.MaxUploadBytes 上限つきで取り出す（申告サイズも実読みも打ち切る）
├ judgeOrderPDF(pdf)   … 変数。既定は judgeOrderPDFWithGemini
│   └ cms.GeminiGenerate(プロンプト, PDF) → cms.StripJSONFence
│      → JSON {is_client_order, doc_type, drawing_no, drawing_name, machine_name,
│              order_no, customer, order_date, items}
│   GEMINI_API_KEY 無し → 200 {success:false, message:"…設定してから起動し直して…"}
│   その他の失敗       → 200 {success:false, message:"解析に失敗しました: …"}
│
├─ **図面の枝**（doc_type=="drawing"）
│   ├ MatchDXFAttachments(pageID, 図面番号)  … 同じページのDXF添付（ZIP内も）と突き合わせ。
│   │                                          畳み方は cms.NormalizeCode（索引と同じ規則）
│   ├ cms.CreateChildPage(…, buildPartPageHTML(…)) → 500
│   │   本文: <h1>図面名称</h1>
│   │         <section><h2>図面</h2> … 📎原本リンク＋タグ（受信元・元ファイル・対応DXF）
│   │         <section><h2>改訂履歴</h2><table>（新しい版が先頭）
│   │         <section><h2>材料/外注加工/購入部品/支給部品</h2>（構成部品4表）
│   ├ Audit "analyze-drawing"
│   └ 200 {success, is_client_order:false, doc_type:"drawing", page_id, title, matched_dxf}
│
├─ **発注書ではない枝** → 200 {success:true, is_client_order:false}
│                          （**生成しないのも正常な結果**——押した問いに「違う」と答える）
│
└─ **発注書の枝**
    ├ cms.CreateChildPage(page_id, 操作者, buildOrderPageHTML(…)) → 500
    │   本文: <h1>受注 <番号></h1>
    │         <section><h2>顧客の発注書</h2><dl>発注書番号・発注元・発注日</dl>
    │                  <table>品番・品名・単価・数量・状態(未着手)</table></section>
    │         <dl data-type="tags">受信元: <元ページID>-<添付ID>[, 元ファイル: <ZIP内パス>]</dl>
    │   **日付と数値は cms.CanonicalForIngest で正規形にして書く**（D-3。読めなければ生のまま）
    ├ Audit "analyze-pdf"
    └ 200 {success, is_client_order:true, page_id, title}
```

生成されたページは**機能見出し形**なので、保存時の索引では `vocabTypeOf` が
`<h2>顧客の発注書</h2>` をレジストリの表示名で引き、`syncVocabSection` がヘッダ dl を
`client-order`、素の表を `client-order-items`（`Items` 宣言）として `vocab_index` へ載せます。
`受信元` の値は参照タグの文法に一致するので、表示時に `RenderReferenceLinks` が
`/<元ページID>#<添付ID>` へのリンクにします。

**置き場所はここでは決めません**（2026-09-03 ユーザー決定「人間が見てもなにを言っているのか
判断に困る場合も結構多いです。なぜなら顧客は適当だからです」）。作られた部品ページは
通信記録ページの子のままで、**受信箱がそのまま「まだ分からないものの置き場」**になります。
顧客名／装置名称／図面名称へ移すのは、次章の「整理」という**別の操作**です。

## 7b. 整理（`GET /api/filing-proposal` → `POST /api/file-drawings`・`ext/sheetmetal`）

**提案は何も作りません。** ページが生まれるのは実行のときだけ——「実行ボタンを押してから
ページ作成です」（ユーザー）。

```
FilingProposalAPIHandler（GET・filing.go）  入力 ?page_id=
├ page.CanView（読めない相手には404。匿名の404統一と同じ規律）
├ 子ページのうち図面ブロックを持つものを集める（drawingChildrenOf → cms.VocabBlocksOf(…, "drawing")）
└ 200 {proposals:[{page_id, title, 顧客名, 装置名称, 図面名称, reason}]}
                    ↑ 読めたタグから埋めた**推奨値**。人がこの欄を書き直す

FileDrawingsAPIHandler（POST・filing.go）  入力 {rows:[{page_id, customer, machine_name, drawing_name}]}
├ ログインだけ確認（403）——**対象ごとの write は行の処理の中で** canWritePage が見る
│  （HTTPは返さず、その行の outcome に載る。1行の権限不足で全体を止めない）
├ ensureChildPage(トップ, 顧客名) → ensureChildPage(顧客名, 装置名称)   … 無ければ作る
├ findChildByTitle(装置名称, 図面名称)  … **完全一致だけ**
│   ├ 無い   → movePage（親の付け替え）                          … outcome "moved"
│   └ 在る   → mergeAsRevision（**改訂**として既存ページへ併合）  … outcome "revision"
│              図面ブロックを先頭へ差し込む（cms.InsertAfterH1）＋改訂履歴に1行
│              ブロックIDが衝突したら振り直す（reassignBlockIDIfTaken）
└ 200 {results:[{page_id, outcome, message}]}
```

- **同じ部品のページが既にあれば、その図面は改訂図面**（2026-09-03 ユーザー決定）。
  顧客名／装置名称の下では図面名称が一意なので、**ページが在ること自体が改訂の合図**です。
- 古い図面の**赤枠は表示時に付けます**（`drawing_mirror.go` の鏡型）——`class` は
  サニタイズで落ちるので保存できません（`ref-missing` の薄赤と同じ作り）。

## 7c. メールを取り込む（`POST /api/mail/import`・`ext/mailgraph`）

**受信は Microsoft Graph、送信は SMTP。** 分かれているのは Graph の `sendMail` が
`In-Reply-To` を立てられないためです（実物で `InvalidInternetMessageHeader` を確認）。

```
MailImportAPIHandler（import.go）  入力 {folder?, max?, since?}
├ POST 限定 → 405 ／ 未ログイン → 403
├ ImportMessages（10分のタイムアウト）
│   ├ accessTokenFor(Graph のスコープ)  … 保管済みリフレッシュトークンから取り直す
│   │   未サインイン → cms.ErrMailNotSignedIn → 200 {success:false}
│   ├ ListMessages … **一覧の上限（5000）と取り込みの上限（50）は別**
│   │                （混ぜると「押しても進まない」になる。2026-09-03 に踏んだ）
│   ├ **古い順に並べ替える**（スレッドの親が先に着く）
│   └ 1通ずつ:
│       ├ cms.ExistingIntakePage("メッセージID", internetMessageId)
│       │     既存 → duplicate++（**ダウンロードの前に弾く**）
│       ├ FetchRawMIME … /messages/{id}/$value（生MIME）
│       └ cms.IntakeFile(受信箱, 利用者, "<件名>.eml", 生MIME)
│             → コアの取り込み係（6章とまったく同じ道）
└ 200 {success, summary:{listed, imported, duplicate, failed, titles}}
```

**取り込みの中身はコアの仕事**です（`emlIntake`）。拡張がするのは「取ってきて、
コアの口へ渡す」ところまで——だから人が `.eml` をドロップしたときと**同じページ**ができます。

## 7d. 返信する（`POST /api/mail/send`・`ext/mailgraph`）

```
MailSendAPIHandler（reply.go）  入力 {to, cc, subject, body, source_page_id?}
├ POST 限定 → 405 ／ 未ログイン → 403
├ cms.DecodeJSONBody → 413 / 400
├ 宛先が空 / 本文が空 → 400
├ 返信元が指定されていれば page.CanView → 404
│   **読めない記録には返信させません**（宛先や件名を引き写す口になるため）
│
├ 1. 送る … SendAndReturnID → sendViaSMTP
│      ├ accessTokenFor(SMTP のスコープ)  … **Graph とは別のリソース**
│      │   （混ぜると AADSTS70011。取り違えると「認証は通るのに送れない」）
│      ├ buildMIME … 件名は RFC 2047・本文と添付は base64 76桁折り
│      │   **In-Reply-To ＋ References に返信元のメッセージID**（SMTP にした理由）
│      └ smtp.office365.com:587 → STARTTLS → XOAUTH2 → DATA
│      失敗 → 200 {success:false, message}（記録は作らない。出ていないので）
├ Audit "mail.send"
│
└ 2. 記録する … recordSentMail（送信箱／年／月へ CreateRecordPage）
       失敗しても **200 {success:true, sent:true, record_error:"…"}**
       ——送ったものは取り消せないので、出た事実を隠さない
```

- **SMTP で投函したメールは Outlook の「送信済みアイテム」に残りません**
  （Exchange Online の仕様）。控えは w-cms の**送信箱**が担います——承知のうえの選択。
- 記録には `返信元` タグ（値は返信元のページID）が入るので、元の記録の側からは
  `/api/replies`（`PagesByTag`）で**逆引きして覗けます**。

## 9. 版を取り出す／戻す

```
[一覧] GET /api/versions?id=      VersionsAPIHandler
  NormalizeID → page.RequirePageRead → ListVersions（新しい順。本文の無い版は飛ばす）

[取得] GET /api/version?id=&v=    VersionAPIHandler
  NormalizeID → page.RequirePageRead → ReadVersion
    ├ safeVersionID … 時刻由来の形（20060102T150405Z）しか受け付けない（/ \ . は不可）→ 404
    └ gzip を 8MiB 上限で展開
  → RenderComputedViews(Sanitize(body)) を text/plain ＋ nosniff で返す

[戻す] POST /api/revert           RevertAPIHandler
├ POST 限定
├ DecodeJSONBody {page_id, version}
├ page.NormalizeID → 400
├ page.RequirePageWrite → 401 / 403
├ editlock.RequireEditLock → 409
├ RevertToVersion(id, version, author)          → 失敗は 400
│   ├ ReadVersion
│   ├ **いまの内容を RecordVersion(force=true)**（リバート自体を取り消せる）
│   ├ Sanitize（過去の版も**いまの許可リスト**で濾す）
│   ├ page.WriteFileAtomic → page.BumpUpdatedAt → SyncIndex
│   └ 戻した内容も RecordVersion(force=true)
├ auth.Audit(user, "revert", "<id> -> <版ID>")
└ 200 {success, page_id, version, html: RenderComputedViews(Sanitize(戻した本文))}
```

**サイドカーは触りません**——権限・所有者・親は現状のままです。

`RecordVersion` の規則: 中身のハッシュが最新の版と同じなら何もしない／`force=false` で
同じ編集者かつ最新の版IDから10分以内なら**その版を置き換える**／それ以外は新しい版を切り、
`PruneVersions` で5年（366日×5）を超えた版を落とす。

## 11. DB再構築（`POST /api/rebuild-db`）

```
RebuildDBAPIHandler（handler_meta.go）
├ POST 限定
├ page.RequireAdmin → 401 / 403
├ RebuildDatabase（sync.go）                          → 500
│   ├ LoadSettings                … 語→型の推論辞書を読み直す（再起動なしで効く）
│   ├ markRebuildStarted          … rebuild_state に「始めた印」（finished_at = NULL）
│   ├ dropAllTables               … sqlite_master の全テーブル（rebuild_state を除く）を DROP
│   ├ database.CreateCoreTables ＋ ApplySchema
│   ├ resyncAllPages              … data/master を歩き、versions/ を飛ばして .html ごとに SyncIndex
│   │                               （個々の失敗は握り潰して続行・件数を数える）
│   └ markRebuildFinished(件数, ミリ秒)
├ lastRebuildResult → auth.Audit(user, "rebuild-db", "<件数>ページ / <ms>ミリ秒")
└ 200 {success, pages, duration_ms}
```

起動時の `RebuildIfNeeded` は、`data/master` に .html があるとき、**印が残っている
（前回が途中で止まった）なら pages が空でなくてもやり直し**、そうでなければ pages が
空のときだけ再構築します。スキーマのずれ（`DriftedSchemaTables`）は0章で先に処理されます。

```
[画面]   GET /login          auth.LoginPageHandler（認証不要）
[認証]   POST /api/login     auth.LoginAPIHandler（認証不要・CSRFProtect は通る）

## 14. フロント側の起動順

```
index.html
├ <head>  boot.js（11行目）… **同期**スクリプト。レールの開閉を描画前に確定（FOUC防止）
├ <head>  app.css
├ <body>  …本文はサーバーが合成済み（#w-editor-content に埋まった状態で届く）
└ </body> 直前 app.js（269行目）… defer なし。DOMが揃ってから同期実行
             bindChromeActions()  … クロームのボタン配線（addEventListener。on*= は無い）
             window.onload:
             ├ await Promise.all([loadMe(), loadTagSchema()])（語彙は保存が走る前に必要）
             ├ initBlocks / buildToc / setupEditorEvents / setupAutoSave
             ├ 匿名なら applyMode / loadPageMeta / loadChildNav して終了
             └ onModeToggle（?edit ならロック取得→/api/load）→ loadPageMeta / loadPerms /
               loadChildNav / loadVersions
```

`applyMode` は閲覧モードで `refreshAttachmentPreviews` を呼び、編集モードでは
添付クロームを外します。コンテキストツールバーは `pointer: coarse` の端末で
`is-docked`（画面下のドック）になり、`positionDockedToolbar` が `visualViewport` の
下端へ合わせます。スラッシュメニューの挿入骨格は `buildVocabSkeleton`——
`usesHeadingForm(def)` なら `<section><h2>表示名</h2>…素の中身…</section>`
（`data-type` を書かない）を生成します。

> `boot.js` も `app.js` も `defer` を持ちません。`<head>` の同期スクリプトが先、
> `</body>` 直前が後、という**書いてある順**どおりに実行されます。
