ミドルウェア（`cmd/w-cms/main.go` の実測）:

```
CSPProtect( CSRFProtect( root ) )
                          ├─ /assets/     … 認証不要（Cache-Control: no-cache）
                          ├─ /login, /api/login, /api/tag-schema … 認証不要
                          ├─ /sitemap.xml, /robots.txt          … 認証不要
                          ├─ OptionalAuth … /api/load, /data/, /api/me,
                          │                 /api/children, /api/page-meta, /  (RootHandler)
                          └─ RequireAuth(protected) … 上記以外の /api/
```

- `CSRFProtect` は GET/HEAD/OPTIONS を検証しません。**状態を変える経路は
  ハンドラ側でメソッドを絞ること**（`route_guard_test.go` が固定）。
- `RequireAuth` は入口で `Cache-Control: no-store` を一律に付けます
  （API ごとに付けるとどれか1本が漏れるため）。

**偽陽性に注意**（このプロジェクトで実際に踏んだもの）:

- **メソッド名**——`Name` / `Schema` / `Tables` / `Triggers` / `OnElement` は全プラグインが
  実装するので、「最初に宣言したファイルへの依存」に見えます。
- **同名関数**——`RequireAdmin` は `auth` と `page` の両方にあります。`page.` の有無で分けること。
- **同一パッケージ内の呼び出し**——`auth.Audit(` で grep すると `auth` 自身の
  9箇所（ログイン・ログアウト・管理API）が漏れます。
- **コメント内の言及**——件数だけ見て内訳を見ないと外します。
