## 9. 数え方（再現手順）

```bash
# 呼び出し元（テスト・コメント・宣言行を除く）
grep -rn --include='*.go' -F 'SyncIndex(' internal cmd ext \
  | grep -v '_test.go' | grep -vE ':[0-9]+:\s*//' | grep -vE ':[0-9]+:func (\([^)]*\) )?SyncIndex\('

# 公開APIの一覧
go doc ./internal/cms
go doc ./ext/comm
```

**偽陽性に注意**（このプロジェクトで実際に踏んだもの）:

- **メソッド名**——`Name` / `Schema` / `Tables` / `Triggers` / `OnElement` / `OnFile` /
  `Extensions` は複数の型が実装するので、「最初に宣言したファイルへの依存」に見えます
  （`Extensions` は `cms.Extensions()` と `IntakeHandler.Extensions()` の2つ）。
- **同名の別関数**——`SaveAttachment` は `cms.SaveAttachment`（添付3経路の芯）と
  `IntakeContext.SaveAttachment`（取り込み係の口）の2つ。`TagValue(` は `dlTagValue(` にも当たります。
- **同名関数**——`RequireAdmin` は `auth` と `page` の両方にあります。`page.` の有無で分けること。
- **同一パッケージ内の呼び出し**——`auth.RequireAdmin(` で grep すると `auth` 自身の
  6箇所が漏れます。`page.*` も同じで、`page` パッケージ内からの呼び出しは `page.` が付きません。
- **括弧なしの参照**——`page.DataFileHandler` は `main.go` で `http.HandlerFunc(...)` に
  渡されるだけなので `DataFileHandler(` では当たりません。
- **コメント内の言及**——件数だけ見て内訳を見ないと外します。
- **語彙やルートの本数**——grep より、**小さな `main` を書いて `cms.VocabDefs()` /
  `cms.PluginRoutes()` / `cms.ExtensionIDs()` を印字する**ほうが確かです（ビルドタグの
  組ごとに数えられます）。
