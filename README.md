# w-cms (Content Management System)

Go言語で構築された、簡易的なファイル統合型のコンテンツ管理システム（CMS）です。

アップロードされたHTMLファイルを、ファイルシステム（物理ストレージ）へ効率的に分散配置して保存し、同時にHTML内のメタデータやコンテンツ構造を解析してSQLiteデータベースにインデックス情報として登録・同期します。

---

## 🚀 特徴

1. **物理ストレージと仮想階層（Path）の分離**
   - 物理ファイルは、自動生成されるIDをベースに自動でディレクトリ分散（例: `/data/master/00/00A1B/index.html`）して格納されます。これにより、同一フォルダへのファイル集中を防ぎます。
   - 一方で、ユーザーがサイト上で整理するための「仮想階層」は、HTML内の `path` 属性（例: `<m-page path="/製品/自社開発">`）から読み取り、データベース側で柔軟に管理・表示されます。

2. **CGO不要のPure Go SQLite**
   - Windows環境などでもCコンパイラなしで動作するPure Go実装のSQLiteドライバ (`modernc.org/sqlite`) を採用しています。

3. **セマンティックなHTML解析**
   - HTML内の `<m-page>` というカスタムタグからメタデータ（タイプやパス）を抽出し、さらに `h1`タグをタイトル、最初の `p`タグを要約として自動で収集・同期します。

## 📂 プロジェクト構成

```text
w-cms/
├── cmd/
│   └── w-cms/
│       └── main.go         # アプリケーション起動とルーティングの設定
├── internal/
│   ├── database/
│   │   └── sqlite.go       # データベース（SQLite）の初期化と接続管理
│   └── cms/
│       ├── handler.go      # HTTPハンドラ（アップロード処理・一覧描画）
│       ├── parser.go       # HTML解析とメタデータ抽出
│       ├── storage.go      # IDの自動採番（Base-36）と保存ディレクトリの決定
│       ├── sync.go         # データベースへのメタデータ同期（UPSERT）
│       └── storage_test.go # ID採番やファイルパス決定ロジックの単体テスト
├── data/                   # 起動時に自動生成されるデータ保存先
│   ├── cms.db              # SQLiteデータベースファイル
│   └── master/             # HTMLの物理ファイルが階層化されて保存されるディレクトリ
└── go.mod / go.sum         # go.mod依存関係
```

## 🛠 動作方法

### 1. 依存関係のセットアップ
Goがインストールされている環境で、プロジェクトルートにて依存パッケージをダウンロードします。

```bash
go mod tidy
```

### 2. アプリケーションの起動
以下のコマンドでサーバーを起動します。

```bash
go run cmd/w-cms/main.go
```
起動すると、`http://localhost:8080` でWebサーバーが立ち上がります。

### 3. テストの実行
ID採番ロジックや保存パス生成ロジックのテストを実行します。

```bash
go test ./internal/cms -v
```
