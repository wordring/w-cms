# w-cms

**文書を書くと、そのまま検索や集計に使えるデータになる**、小さな事業者のための文書・業務システムです。
Go 言語で書かれています。

- ワンノートのように、ブロックを並べて文書を書きます。書いたものは自動で保存されます。
- 「名前:値」のタグと、題（キャプション）の付いた表は、保存したときにデータベースへ入ります。
  文書に書いた言葉が、そのままテーブルの名前や列の名前になります。
- 正本は文書（HTML のファイル）です。データベースは文書から作り直せます。
- 案件・部材発注・見積・メールなどの業務の機能は、「拡張」として足します。

くわしい目的は [【要求】w-cmsとは.md](docs/【要求】w-cmsとは.md) にあります。

## 🚀 特徴

1. **ブロックエディタ**
   - 見出し・段落・表などの「ブロック」を並べて書きます。ドラッグ&ドロップで並べ替えられます。
   - `/` を打つと出るメニューから、見出し・表・タグ・ファイル表示などを挿せます。
   - 保存される形は素の HTML です。読むだけなら JavaScript は要りません。
2. **書いた言葉がそのままデータになる**
   - タグ（`<dl data-type="tags">` の「名前:値」）と、キャプションの付いた表が、保存のたびにデータベースへ入ります。
   - 言葉の型（数・日付・選択肢 など）は、設定の語彙（`config/settings.json`）で決めます。
   - 表の種類を足すときは、語彙の登録簿（レジストリ）に宣言を1件足します。エディタのメニュー・索引・型の確かめまで揃います。
3. **文書が正本、データベースは派生**
   - 本文は `data/master/` の下に、ページ ID ごとのフォルダで保存します。
   - ページの親子関係・所有者・権限は、本文の隣の属性のファイル（サイドカー `<id>.meta.json`）が正本です。
   - 索引のデータベース（`data/cms.db`）が壊れても、文書から作り直せます。
4. **何人かで同時に書ける**
   - ページを握って待たせる方式ではありません。別のブロックなら、同時に書けます。
   - 同じブロックを同時に書いたときは、両方を並べて、人が合わせます。表は、違うセルなら自動で合わせます。
5. **版と、元に戻す道**
   - 保存した本文の版が残り、戻せます。ブロック1つだけを戻すこともできます。
   - アンドゥ・リドゥは、自分の変更だけを戻します。
6. **認証と、ページごとの権限**
   - パスワードは argon2id で守り、セッション・CSRF 対策・CSP を重ねています。
   - ページごとに「読む・書く」を、所有者・グループ・それ以外に分けて決めます（Unix のファイルの権限に似た形）。
   - はっきり公開の操作をしたページだけが、ログインしていない人に見えます。
7. **外に頼るものを絞る**
   - データベースは、C コンパイラの要らない SQLite（`modernc.org/sqlite`）です。Windows でもそのままビルドできます。
   - 画面は素の JavaScript だけで、ビルドの工程はありません。
8. **拡張**
   - `ext/comm`（通信）: メールの取り込みと送信・通信箱・連絡帳。
   - `ext/toho`（東邦の業務）: 案件・製造・部材発注・加工製品・見積・部材見積依頼・納品書・請求書 など。
   - 拡張は、`ext/` の下のフォルダ1つで完結します。Go のパッケージと、画面のファイル（`assets/` の JS・CSS・HTML）が入っています。
   - 拡張のフォルダを足したり外したりしたら、`go generate ./cmd/w-cms` を流してから組み立てます。取り付けのファイル（`cmd/w-cms/ext_*_gen.go`）が作り直されます。
   - 拡張は、ビルドのときに外せます。`-tags minimal` で全部、`-tags nomail` でメールだけが外れます。
   - コア（`internal/` と `assets/` 直下）は業務の言葉を知りません。この境は、試験 `internal/boundary` が見張ります（[開発方針.md](docs/開発方針.md) §0）。

## 🛠 動かし方

### 1. 依存するパッケージを取る

Go が入っている環境で、リポジトリの根で実行します。

```bash
go mod tidy
```

### 2. 起動する

**初回だけ**、最初の管理者を環境変数で渡して起動します。

```bash
# 手元で試すとき（HTTP）は、Secure Cookie を無効にします
WCMS_ADMIN_USER=admin WCMS_ADMIN_PASSWORD='強いパスワード' WCMS_SECURE_COOKIES=0 \
  go run ./cmd/w-cms
```

2回目からは、環境変数なしの `go run ./cmd/w-cms` で起動できます（管理者は `data/auth.db` に保存されています）。

`http://localhost:8080` で立ち上がります。ブラウザで開くとログイン画面（`/login`）へ移るので、上で決めた管理者でログインしてください。

> ⚠ `go run cmd/w-cms/main.go` のように、ファイルを名指しして起動しないでください。拡張が1つも載りません。

> インターネットに公開する本番では、HTTPS が必須です。`WCMS_SECURE_COOKIES` は設定しないでください（既定で Secure が有効です）。
> 手順は [【ガイド】デプロイ・運用.md](docs/参照/【ガイド】デプロイ・運用.md) にあります。

よく使う設定は次のとおりです。

| 設定 | 意味 |
|---|---|
| `WCMS_ADDR` | 待ち受けるアドレス。渡さなければ `:8080`、HTTPS のときは `:8443` です |
| `WCMS_DATA_DIR` | データを置く場所。既定は `data` です |
| `WCMS_TLS_CERT`・`WCMS_TLS_KEY` | HTTPS の証明書と鍵。両方そろえて渡します。自己署名の証明書は `go run ./cmd/w-cms -gencert` で `data/tls/` に作れます |

### 3. 試験を流す

```bash
go test ./...
```

画面をブラウザで確かめる試験（Playwright）は `e2e/` にあります。

## 📂 フォルダの構成

| 場所 | 中身 |
|---|---|
| `cmd/w-cms/` | サーバーの入口。ルートの表（`main.go` の `buildHandler()`）と、拡張を取り付ける `ext_*_gen.go`（`go generate ./cmd/w-cms` で作るファイル） |
| `cmd/w-cms-edit/` | 添付ファイルを、パソコンのアプリで開いて編集するための常駐ヘルパー（Windows 用） |
| `cmd/list-models/` | Gemini のモデルの一覧を引く、補助のコマンド |
| `internal/cms/` | コア。ページ・保存・タグと表・版・鏡（表示するときにサーバーが埋める、保存されない部分）など |
| `internal/auth/` | 認証・セッション・CSRF と CSP・管理の API |
| `internal/database/` | データベースの初期化と、データの場所 |
| `internal/extgen/` | 拡張の取り付けのファイルを作る仕組み（`go generate` から呼ばれます） |
| `internal/boundary/` | コアと拡張の境を見張る試験と、業務の言葉の表（`rules.json`） |
| `ext/comm/` | 通信の拡張。`contacts/` は連絡帳、`mail/` はメールの送受信 |
| `ext/toho/` | 東邦の業務の拡張 |
| `ext/<拡張>/assets/` | 拡張の画面のファイル。`/assets/ext/<拡張>/…` として配ります |
| `assets/` | コアの画面のファイル（HTML・JavaScript・CSS）。サーバーが毎回ディスクから読みます |
| `config/settings.json` | 設定（語彙など）。Git で管理します。秘密は入れません |
| `docs/` | 文書（下の「文書の案内」） |
| `e2e/` | ブラウザで確かめる試験 |
| `tools/` | 道具（テンプレートの出し入れ・ワンノートからの移行・メールの取り込み・拡張の取り付けのファイルづくり・文書の書き直しの確かめ など） |
| `data/` | 動かすと作られるデータ。Git には入れません |

`data/` の中身は次のとおりです。

| 場所 | 中身 |
|---|---|
| `data/master/` | 本文と属性のファイル（**正本**）・添付・版 |
| `data/cms.db` | 索引（派生。`master/` から作り直せます） |
| `data/tables.db` | 表の写し（派生） |
| `data/auth.db` | 利用者とセッション・監査ログ（**作り直せません。バックアップが要ります**） |
| `data/trash/` | 削除したページの移動先 |
| `data/tls/` | `-gencert` が作った証明書と鍵 |
| `data/mail/` | メールのサインインの記録（メールの拡張が置きます） |
| `data/autocomplete.json` | オートコンプリートの候補（派生。暇なときに数え直します） |

コードの中身を知りたいときは、まず `go doc` を見てください。
各パッケージの冒頭のコメントに、何が正本か・全体の形などの要点があります。

```bash
go doc ./internal/cms              # コアの概説と、公開している関数の一覧
go doc ./internal/cms Observer     # 型や関数を1つだけ
go doc -all ./internal/cms/page    # そのパッケージの全部
```
